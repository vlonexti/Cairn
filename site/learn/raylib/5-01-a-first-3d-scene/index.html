A First 3D Scene

lesson 5.011 of 5 in milestone 55 min1 practice task

raylib draws 3D as easily as 2D. This lesson sets up a Camera3D, explains 3D coordinates and perspective, draws cubes, spheres, planes and a grid, loads and draws models, and introduces the vectors and matrices that move things in 3D.

Three axes

3D adds a third axis. raylib uses a right-handed, y-up system:

Axis Points
x Right
y Up (not down, as on the 2D screen)
z Towards the viewer

Positions are Vector3 { x, y, z }, in whatever unit you choose; most games use 1 unit = 1 metre, which makes gravity 9.81 and a person about 1.8 tall.

The camera

A 3D camera is defined by where it is, what it looks at and which way is up:

C++
Camera3D camera{};
camera.position = { 6.0f, 4.0f, 6.0f };     // where the eye is
camera.target = { 0.0f, 0.5f, 0.0f };       // the point it looks at
camera.up = { 0.0f, 1.0f, 0.0f };           // which way is up
camera.fovy = 45.0f;                        // vertical field of view, in degrees
camera.projection = CAMERA_PERSPECTIVE;     // or CAMERA_ORTHOGRAPHIC

Perspective makes far things smaller, like a real eye; the field of view is how wide the view is (45-70° is typical). Orthographic keeps sizes constant regardless of distance, which suits strategy and isometric games; then fovy is the height of the view in world units.

Drawing

C++
BeginDrawing();
ClearBackground(RAYWHITE);
BeginMode3D(camera);
    DrawPlane({ 0, 0, 0 }, { 20, 20 }, LIGHTGRAY);          // a floor
    DrawCube({ 0, 0.5f, 0 }, 1, 1, 1, RED);                 // centre and size
    DrawCubeWires({ 0, 0.5f, 0 }, 1, 1, 1, MAROON);
    DrawSphere({ 2, 1, 0 }, 0.5f, BLUE);
    DrawCylinder({ -2, 0, 0 }, 0.3f, 0.3f, 1.5f, 16, GREEN);
    DrawGrid(20, 1.0f);                                     // a helpful reference grid
EndMode3D();
DrawFPS(10, 10);                                            // 2D on top, as usual
EndDrawing();

Note that 3D shapes are placed by their centre: a 1 × 1 × 1 cube standing on the floor has its centre at y = 0.5.

Models

Real objects come from 3D files. raylib loads glTF (.glb/.gltf, the best choice), OBJ, IQM, VOX and M3D:

C++
Model tree = LoadModel("assets/tree.glb");                  // meshes, materials and textures
DrawModel(tree, { 3, 0, -2 }, 1.0f, WHITE);                 // position, uniform scale, tint
DrawModelEx(tree, pos, { 0, 1, 0 }, angleDegrees, { 1, 1, 1 }, WHITE);   // rotated around an axis
UnloadModel(tree);

glTF files can also contain animations: LoadModelAnimations and UpdateModelAnimation play them. Free models in this format are available from sites such as Kenney and Quaternius.

Vectors in 3D

raymath.h has everything for Vector3: Vector3Add, Vector3Subtract, Vector3Scale, Vector3Length, Vector3Normalize, Vector3DotProduct and Vector3CrossProduct.

  • The dot product a · b = |a||b| cos θ measures how much two directions agree: 1 for the same direction (when normalised), 0 for perpendicular, -1 for opposite. It answers "is the enemy in front of me?".
  • The cross product a × b is a vector perpendicular to both. From a "forward" direction and "up", forward × up gives "right", which is how cameras find their sideways direction.

Matrices

Objects are placed with a transform: scale, then rotate, then translate. raylib represents it as a 4 × 4 Matrix (MatrixScale, MatrixRotateY, MatrixTranslate, combined with MatrixMultiply). DrawModelEx builds it for you; you need matrices yourself for things like a sword attached to a hand, where the child's transform is multiplied by the parent's.

Lighting

The shapes above are drawn with flat colours, without light. Lighting needs a shader (lesson 5.04); raylib's examples include a basic lighting shader (shaders_basic_lighting) that most projects start from.
