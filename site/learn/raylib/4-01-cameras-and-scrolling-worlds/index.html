Cameras and Scrolling Worlds

lesson 4.011 of 5 in milestone 45 min1 practice task

A world bigger than the screen needs a camera. This lesson uses raylib's Camera2D - target, offset, zoom and rotation - converts between screen and world coordinates, and makes the camera follow the player smoothly with a dead zone, look-ahead, limits at the level's edges and screen shake.

World and screen coordinates

So far everything was drawn in screen coordinates. A level 5000 pixels wide does not fit, so objects get world coordinates, and a camera decides which part of the world is on screen.

C++
Camera2D camera{};
camera.target = player.pos;                                       // the world point the camera looks at
camera.offset = { GetScreenWidth() / 2.0f, GetScreenHeight() / 2.0f };  // where that point appears on screen
camera.rotation = 0.0f;
camera.zoom = 1.0f;

BeginDrawing();
ClearBackground(SKYBLUE);
BeginMode2D(camera);
    drawWorld();                 // in world coordinates
EndMode2D();
drawInterface();                 // in screen coordinates, on top
EndDrawing();

Everything between BeginMode2D and EndMode2D is transformed: a world point p appears on screen at (p - target) * zoom + offset (plus rotation). Putting offset at the screen's centre keeps the target in the middle.

Converting

The mouse is in screen coordinates; to click on the world, convert:

C++
const Vector2 mouseWorld = GetScreenToWorld2D(GetMousePosition(), camera);
const Vector2 labelPos = GetWorldToScreen2D(enemy.pos, camera);   // e.g. a name above an enemy in the interface

Following the player

camera.target = player.pos works, but the camera jerks with every small movement. Better cameras:

  • Smoothing: move the target part of the way towards the player each frame. Like friction in lesson 1.04, make it independent of the frame rate: target += (player - target) * (1 - pow(0.001f, dt)).
  • Dead zone: the camera does not move while the player stays inside a box around the screen's centre; it moves only enough to keep the player in the box. Small movements no longer shake the view.
  • Look-ahead: aim a little ahead of the player in the direction they are moving or facing, so they see more of what is coming.
  • Platformer vertical rule: many platformers only move the camera vertically when the player lands, so jumps do not bounce the view.

Staying inside the level

The camera should not show the void beyond the level's edges. After moving it, clamp the target so the visible area stays inside the level:

C++
const float halfW = GetScreenWidth() / 2.0f / camera.zoom;
const float halfH = GetScreenHeight() / 2.0f / camera.zoom;
camera.target.x = std::clamp(camera.target.x, halfW, levelWidth - halfW);
camera.target.y = std::clamp(camera.target.y, halfH, levelHeight - halfH);

If the level is smaller than the screen, centre it instead (the clamp range would be empty).

Zoom

Zooming around the mouse, as in the ImGui course's level editor, keeps the point under the mouse fixed: convert the mouse to world coordinates, change the zoom, and set offset to the mouse and target to that world point.

Screen shake

A short shake on a hit or explosion makes it feel powerful. Keep a trauma value between 0 and 1 that events add to and that decays over time; offset the camera by a random amount proportional to trauma²:

C++
trauma = std::max(0.0f, trauma - dt * 1.5f);
const float shake = trauma * trauma;
camera.offset = { centre.x + shake * 12 * randomMinus1To1(), centre.y + shake * 12 * randomMinus1To1() };

Squaring makes small trauma barely visible and large trauma strong. Always provide an option to turn shake off: some players get motion sickness.

Parallax

Background layers that move slower than the world make a cheap illusion of depth: draw a far layer with a camera whose target is target * 0.2, a nearer one with * 0.5, then the world at * 1.
