Render Textures and Post-Processing

lesson 5.055 of 5 in milestone 55 min1 practice task

Drawing into a texture instead of the screen opens up a lot - pixel-perfect scaling, minimaps, split screens, and post-processing effects applied to the whole frame such as vignettes, colour grading, blur and scanlines.

Drawing into a texture

A render texture is a texture you can draw into, like an off-screen window:

C++
RenderTexture2D target = LoadRenderTexture(320, 180);

// each frame:
BeginTextureMode(target);
    ClearBackground(BLACK);
    drawWorld();                         // everything goes into the texture
EndTextureMode();

BeginDrawing();
    ClearBackground(BLACK);
    // draw the texture to the screen; the source height is NEGATIVE because OpenGL textures are upside down
    DrawTexturePro(target.texture, { 0, 0, 320, -180 }, letterboxRect, { 0, 0 }, 0, WHITE);
EndDrawing();

UnloadRenderTexture(target);

The negative source height is the one thing everyone forgets: without it, the whole picture is upside down.

Pixel-perfect scaling

This is the clean way to make a pixel-art game: draw everything at the native resolution (320 × 180) into a render texture with point filtering, then draw that texture scaled up by a whole number, centred, with black bars (the letterbox from practice 2.01). Every pixel is the same size whatever the window size, and the mouse is mapped back with the inverse of the same scale and offset.

Other uses

Use How
Minimap Draw the level from above with a second camera into a small texture, show it in a corner
Split screen One render texture per player, each with its own camera, side by side
Mirrors, security cameras Draw the scene from another camera into a texture used on an object
Caching Draw something expensive once (a big static background) and reuse the texture

Post-processing

Post-processing is a shader applied to the whole finished frame: draw the world into a render texture, then draw that texture to the screen inside BeginShaderMode. The fragment shader sees every pixel of the frame:

C++
// vignette.fs: darken towards the edges
#version 330
in vec2 fragTexCoord;
uniform sampler2D texture0;
out vec4 finalColor;
void main()
{
    vec3 c = texture(texture0, fragTexCoord).rgb;
    float d = distance(fragTexCoord, vec2(0.5));      // 0 in the centre, about 0.7 in the corners
    c *= smoothstep(0.8, 0.3, d);                     // fade from 1 to 0 between 0.3 and 0.8
    finalColor = vec4(c, 1.0);
}

Common effects:

  • Vignette (above): focuses the eye on the centre.
  • Colour grading: adjust brightness, contrast and saturation, or tint the whole frame for mood (blue at night, red when low on health).
  • Grey scale: dot(c, vec3(0.299, 0.587, 0.114)) gives the perceived brightness, used for a "game over" or flashback look.
  • Blur: average neighbouring pixels; done in two passes (horizontal, then vertical) for speed, often to put a menu over a blurred game.
  • Scanlines and curvature: an old CRT look.
  • Bloom: blur only the bright parts and add them back, so lights glow.

raylib's examples include a dozen post-processing shaders (shaders_postprocessing) to start from.

Keep it optional

Post-processing costs a full-screen pass per effect, and some effects (blur, shake, flashing) bother some players. Give each strong effect a setting, and keep the interface outside the effect by drawing it after the post-processed frame.
