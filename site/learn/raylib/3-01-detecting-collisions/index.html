Detecting Collisions

lesson 3.011 of 5 in milestone 35 min1 practice task

The collision tests 2D games are built on - point in rectangle, rectangle against rectangle, circle against circle and circle against rectangle - how each one works, raylib's functions for them, and choosing the right shape for each object.

Shapes stand in for sprites

Testing every pixel of two sprites against each other is slow and rarely what you want. Games give each object a simple collision shape, usually a little smaller than its picture so near misses feel fair:

Shape Good for
Axis-aligned rectangle (AABB) Characters, tiles, platforms, pickups
Circle Balls, bullets, round enemies, anything that rotates
Point The mouse, a bullet's tip

"Axis-aligned" means the rectangle is not rotated: its sides are parallel to x and y. That makes every test a few comparisons.

Point in rectangle

C++
bool pointInRect(Vector2 p, Rectangle r)
{
    return p.x >= r.x && p.x < r.x + r.width && p.y >= r.y && p.y < r.y + r.height;
}

raylib: CheckCollisionPointRec(p, r). There is also CheckCollisionPointCircle and CheckCollisionPointTriangle.

Rectangle against rectangle

Two rectangles overlap unless one is completely to the left, right, above or below the other:

C++
bool rectsOverlap(Rectangle a, Rectangle b)
{
    return a.x < b.x + b.width && b.x < a.x + a.width &&
           a.y < b.y + b.height && b.y < a.y + a.height;
}

raylib: CheckCollisionRecs(a, b), and GetCollisionRec(a, b) returns the overlapping rectangle itself, whose width and height lesson 3.02 uses to push objects apart.

Use < rather than <= so that rectangles that only touch (one's right edge exactly at the other's left edge) do not count as overlapping. A character standing exactly on top of a floor tile should not be "inside" it.

Circle against circle

Two circles overlap when the distance between their centres is less than the sum of the radii. Compare squared distances to avoid the square root:

C++
bool circlesOverlap(Vector2 a, float ra, Vector2 b, float rb)
{
    const float dx = b.x - a.x, dy = b.y - a.y, r = ra + rb;
    return dx * dx + dy * dy < r * r;
}

raylib: CheckCollisionCircles(a, ra, b, rb).

Circle against rectangle

Find the point of the rectangle closest to the circle's centre by clamping the centre to the rectangle on each axis; the shapes overlap when that point is inside the circle:

C++
bool circleRect(Vector2 c, float r, Rectangle rect)
{
    const float nx = std::clamp(c.x, rect.x, rect.x + rect.width);
    const float ny = std::clamp(c.y, rect.y, rect.y + rect.height);
    const float dx = c.x - nx, dy = c.y - ny;
    return dx * dx + dy * dy < r * r;
}

If the centre is inside the rectangle, the closest point is the centre itself and the distance is 0. raylib: CheckCollisionCircleRec(c, r, rect). The two projects so far used this test.

Lines and rays

CheckCollisionLines(a1, a2, b1, b2, &point) tests two line segments and gives the crossing point: useful for lasers, line of sight, and fast bullets (lesson 3.02). The maths behind it is a pair of cross products, which the practice writes.

Who collides with whom

Not everything needs to test against everything. Write down the pairs that matter: player with enemies, player with pickups, player's bullets with enemies, enemies' bullets with the player, everything with walls. Many games give each object a layer and a mask (bit flags) and test a pair only if one's mask contains the other's layer.
