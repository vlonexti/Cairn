Resolving Collisions

lesson 3.022 of 5 in milestone 35 min1 practice task

Knowing two things overlap is half the job; the other half is deciding what happens. This lesson pushes objects apart along the shortest way out, moves one axis at a time so characters slide along walls, and stops fast objects from tunnelling through thin walls.

Detection and response

When the player walks into a wall, the overlap test says "yes". The response decides what happens: stop, slide along it, bounce, take damage. For solid things the response is to separate the objects so they no longer overlap.

The shortest way out

For two overlapping rectangles, the overlap is itself a rectangle (GetCollisionRec). Push the moving object out along the axis where the overlap is smaller: that is the shortest way out, called the minimum translation vector.

C++
void pushOut(Rectangle& mover, Rectangle wall)
{
    const Rectangle o = GetCollisionRec(mover, wall);
    if (o.width == 0 || o.height == 0) return;
    if (o.width < o.height)
        mover.x += (mover.x < wall.x) ? -o.width : o.width;      // out left or right
    else
        mover.y += (mover.y < wall.y) ? -o.height : o.height;    // out up or down
}

The brick breaker of milestone 2 used this idea for the ball. It has one weakness: at a corner, when the overlap is nearly square, it can pick the wrong axis, and a character walking along a floor made of tiles can "catch" on the seam between two tiles.

One axis at a time

The fix used by almost every 2D platformer is to move and resolve each axis separately:

C++
// 1. Move horizontally, then resolve horizontally only.
player.x += vel.x * dt;
for (const Rectangle& wall : walls)
    if (CheckCollisionRecs(player, wall))
    {
        if (vel.x > 0) player.x = wall.x - player.width;   // hit a wall on the right
        else if (vel.x < 0) player.x = wall.x + wall.width;
        vel.x = 0;
    }

// 2. Then vertically.
player.y += vel.y * dt;
onGround = false;
for (const Rectangle& wall : walls)
    if (CheckCollisionRecs(player, wall))
    {
        if (vel.y > 0) { player.y = wall.y - player.height; onGround = true; }   // landed
        else if (vel.y < 0) player.y = wall.y + wall.height;                     // bumped the head
        vel.y = 0;
    }

Because each step only moved along one axis, the direction of that movement says exactly which side was hit. The player slides along walls naturally: blocked on x, still free on y. And "landed on something" falls out for free as onGround.

Tunnelling

A bullet moving 1200 pixels a second moves 20 pixels a frame at 60 FPS. A wall 8 pixels thick can be completely between two frames' positions, so the overlap test never sees it: the bullet tunnels through.

Fixes, from simplest:

  1. Clamp the frame time (lesson 1.04) and keep walls at least as thick as anything moves in a frame.
  2. Sub-steps: split a big movement into several small ones, each no longer than the smallest object.
  3. Sweep: test the path, not just the end point. For a small bullet, test the segment from the old position to the new one against each wall (CheckCollisionLines against its edges), and take the nearest hit. For a moving box, the swept AABB test computes the time t between 0 and 1 at which it first touches the other box.

Bouncing and sliding

With the normal of the surface (the direction it faces, such as (0, -1) for a floor), other responses are one line each:

Response Velocity
Stop v = 0
Slide Remove the part along the normal: v -= dot(v, n) * n
Bounce Reflect: v -= 2 * dot(v, n) * n, times a bounciness below 1
