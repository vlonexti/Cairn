Keyboard, Mouse and Gamepad Input

lesson 1.055 of 5 in milestone 15 min1 practice task

Reading every kind of input raylib supports - keys held and pressed, typed characters, the mouse and its wheel, and gamepads with their sticks and dead zones - and mapping them to game actions so players can rebind them.

Down, pressed, released

Function True when
IsKeyDown(KEY_SPACE) The key is held this frame
IsKeyPressed(KEY_SPACE) The key went down since the last frame (once per press)
IsKeyReleased(KEY_SPACE) The key went up since the last frame
IsKeyUp(KEY_SPACE) The key is not held
IsKeyPressedRepeat(KEY_LEFT) The key's auto-repeat fired, as in a text box

Use Down for continuous actions (moving, accelerating) and Pressed for one-off actions (jumping, shooting once, opening a menu). Using IsKeyDown for a menu choice moves the selection every frame the key is held, which is 60 items a second.

Keys are named KEY_A ... KEY_Z, KEY_ZERO ... KEY_NINE, KEY_LEFT, KEY_ENTER, KEY_LEFT_SHIFT and so on, by their position on a US keyboard. For typed text (names, chat) use GetCharPressed(), which returns Unicode characters one by one in a loop, respecting the keyboard layout and Shift:

C++
for (int c = GetCharPressed(); c != 0; c = GetCharPressed())
    if (c >= 32 && c < 127 && name.size() < 12) name += static_cast<char>(c);
if (IsKeyPressed(KEY_BACKSPACE) && !name.empty()) name.pop_back();

The mouse

Function Gives
GetMousePosition() A Vector2 in window pixels
GetMouseDelta() How far it moved since the last frame
IsMouseButtonPressed(MOUSE_BUTTON_LEFT) Click, once (also Down, Released)
GetMouseWheelMove() Wheel movement this frame, positive away from you
SetMouseCursor(MOUSE_CURSOR_POINTING_HAND) Changes the cursor shape
DisableCursor() / EnableCursor() Hides and locks the cursor, for 3D cameras

A button is a rectangle plus a click test: CheckCollisionPointRec(GetMousePosition(), rect) && IsMouseButtonPressed(MOUSE_BUTTON_LEFT).

Gamepads

raylib numbers gamepads from 0 and uses positional button names so code works for Xbox and PlayStation pads alike:

C++
if (IsGamepadAvailable(0))
{
    const float lx = GetGamepadAxisMovement(0, GAMEPAD_AXIS_LEFT_X);    // -1 .. 1
    const float ly = GetGamepadAxisMovement(0, GAMEPAD_AXIS_LEFT_Y);
    if (IsGamepadButtonPressed(0, GAMEPAD_BUTTON_RIGHT_FACE_DOWN)) jump();   // A on Xbox, Cross on PlayStation
}

Dead zones

A stick at rest rarely reads exactly 0; it drifts by a few hundredths, which would make the character creep. Apply a dead zone: treat small values as zero, and rescale the rest so movement still starts smoothly from zero.

C++
float deadZone(float v, float dz)
{
    if (std::fabs(v) < dz) return 0.0f;
    return (v - std::copysign(dz, v)) / (1.0f - dz);    // dz..1 becomes 0..1
}

A better version uses the stick's length (a radial dead zone) so diagonal movement is not cut off differently from straight movement; the practice builds both pieces.

Actions, not keys

Game code should not ask "is W down?" but "is the player moving up?". Map actions to any number of inputs:

C++
enum class Action { Left, Right, Jump, Pause };
struct Binding { Action action; int key; int gamepadButton; };

bool actionPressed(Action a, const std::vector<Binding>& bindings)
{
    for (const auto& b : bindings)
        if (b.action == a && (IsKeyPressed(b.key) || IsGamepadButtonPressed(0, b.gamepadButton))) return true;
    return false;
}

Now a settings screen can change the bindings, and the game code never changes.
