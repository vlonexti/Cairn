Spatial Grids for Many Objects

lesson 3.055 of 5 in milestone 35 min1 practice task

Testing every object against every other is n squared - fine for 50 objects, hopeless for 5000. A uniform grid puts each object in the cells it touches and only tests objects that share a cell. This lesson builds one, rebuilds it every frame, and avoids testing pairs twice.

Every pair is too many

With n objects there are n(n-1)/2 pairs. For 100 objects that is 4950 tests a frame: no problem. For 5000 bullets and enemies it is 12.5 million, many times the frame budget. Most of those pairs are on opposite sides of the screen and could never touch.

The idea of broad phase collision is to cheaply find the pairs that might touch, and only run the real test (the narrow phase) on them.

A uniform grid

Divide the world into square cells, a bit bigger than a typical object. Each cell keeps a list of the objects that overlap it:

C++
struct Grid
{
    float cellSize;
    int cols, rows;
    std::vector<std::vector<int>> cells;          // object indices per cell

    int cellX(float x) const { return std::clamp(static_cast<int>(std::floor(x / cellSize)), 0, cols - 1); }
    int cellY(float y) const { return std::clamp(static_cast<int>(std::floor(y / cellSize)), 0, rows - 1); }

    void insert(int id, Rectangle r)
    {
        for (int cy = cellY(r.y); cy <= cellY(r.y + r.height); ++cy)
            for (int cx = cellX(r.x); cx <= cellX(r.x + r.width); ++cx)
                cells[cy * cols + cx].push_back(id);
    }
};

An object overlapping a cell boundary is put in every cell it touches, so neighbours across a boundary still meet in some cell.

Using it

Each frame:

  1. Clear the cells (keep the vectors' memory; just clear() each).
  2. Insert every object.
  3. For each cell, test each pair of objects in that cell.

Two objects that share several cells would be tested several times, once in each. Avoid duplicates by testing a pair only when a < b and recording tested pairs in a set, or, faster, only in the cell that contains the top-left corner of their overlap.

For a query ("which enemies are within the explosion?"), look only in the cells the query area covers, and collect each object once.

Choosing the cell size

  • Too small: big objects are in many cells, and inserting costs more than it saves.
  • Too large: many objects per cell, back towards n squared.
  • A cell about twice the size of a typical object is a good start. Measure with a profiler and adjust.

Other structures

Structure Good when
Uniform grid Objects of similar size spread over a bounded world: most 2D games
Spatial hash The same, but the world is unbounded: cells are keys in a hash map
Quadtree Sizes vary a lot, or objects cluster in a few places
Sort and sweep Objects mostly spread along one axis, as in side-scrollers

Static and moving things

Walls and tiles never move, so do not put them in the per-frame grid: a tile map is already a grid (lesson 4.02), and you can look up the tiles under an object directly from its position. Only moving objects need inserting every frame.
