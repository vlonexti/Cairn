The Game Loop

lesson 1.022 of 5 in milestone 15 min1 practice task

Every game is a loop that reads input, updates the world and draws it, many times a second. This lesson takes raylib's loop apart - what BeginDrawing and EndDrawing do, why the screen is cleared every frame, and how to keep update and drawing apart.

Input, update, draw

A film shows 24 still pictures a second; a game makes its pictures as it goes. Each picture is a frame, and each frame the game does three things:

flowchart LR
    I[Read input] --> U[Update the world] --> D[Draw the world] --> I
  1. Input: which keys are down, where the mouse is.
  2. Update: move things, check collisions, change scores and timers.
  3. Draw: show the world as it is now.

At 60 frames per second that happens every 16.7 ms. The game's state lives in variables that survive from frame to frame; the loop changes them a little each time.

C++
#include "raylib.h"

int main()
{
    InitWindow(800, 450, "Moving square");
    SetTargetFPS(60);

    float x = 100.0f;                          // state: survives between frames

    while (!WindowShouldClose())
    {
        // Input and update
        if (IsKeyDown(KEY_RIGHT)) x += 4.0f;
        if (IsKeyDown(KEY_LEFT))  x -= 4.0f;

        // Draw
        BeginDrawing();
        ClearBackground(RAYWHITE);
        DrawRectangle(static_cast<int>(x), 200, 50, 50, MAROON);
        EndDrawing();
    }
    CloseWindow();
}

What the raylib calls do

Call Does
InitWindow(w, h, title) Opens the window and creates the OpenGL context: call it before anything that loads or draws
SetTargetFPS(60) Makes EndDrawing wait so frames come no faster than 60 a second
WindowShouldClose() True once Esc or the close button was pressed
BeginDrawing() Starts the frame's drawing
ClearBackground(c) Fills the whole frame with one colour
EndDrawing() Shows the finished frame (swaps buffers), waits for the target frame rate, and polls input for the next frame
CloseWindow() Closes the window and frees the context

Note the last point about EndDrawing: raylib reads the keyboard and mouse there, so IsKeyPressed reports what happened since the previous frame.

Why clear every frame?

The game draws into a back buffer while the screen shows the front buffer; EndDrawing swaps them. The back buffer still holds an old frame, so without ClearBackground the new frame is drawn over old pictures and moving things leave trails. Clear first, then draw everything that should be visible, back to front: later drawing covers earlier drawing.

Keep update and draw apart

It is tempting to move things inside the drawing code. Keep them apart instead:

C++
struct Game { float x{ 100 }; int score{ 0 }; };

void update(Game& g) { if (IsKeyDown(KEY_RIGHT)) g.x += 4.0f; }
void draw(const Game& g) { DrawRectangle(static_cast<int>(g.x), 200, 50, 50, MAROON); }

while (!WindowShouldClose())
{
    update(game);
    BeginDrawing(); ClearBackground(RAYWHITE); draw(game); EndDrawing();
}

draw takes the game by const&: it can look but not change. This split pays off again and again: you can pause by skipping update, run the update twice as fast for testing, or test update without a window at all, which is exactly what the practice on this site does.
