Tile Maps and Levels

lesson 4.022 of 5 in milestone 45 min1 practice task

Most 2D levels are grids of tiles. This lesson stores a tile map, draws only the visible part from a tile sheet, loads levels from text files, places objects such as the player's start and enemies from the same file, and picks wall tiles automatically from their neighbours.

A grid of numbers

A tile map is a 2D grid where each cell holds a tile number: 0 for empty, 1 for grass, 2 for stone and so on. A 200 × 30 level is only 6000 small numbers, and collision is a direct lookup (the platformer of milestone 3 used exactly this).

C++
struct TileMap
{
    int width, height, tileSize;
    std::vector<int> tiles;                     // row by row

    int at(int x, int y) const { return (x < 0 || y < 0 || x >= width || y >= height) ? 0 : tiles[y * width + x]; }
};

A flat std::vector indexed with y * width + x is faster and simpler than a vector of vectors.

Drawing from a tile sheet

Tile pictures come from one texture, a tile sheet, like a sprite sheet. Tile n is the n-th cell (lesson 2.02's frameRect). Draw only the tiles the camera can see, as the ImGui level editor did:

C++
const Vector2 tl = GetScreenToWorld2D({ 0, 0 }, camera);
const Vector2 br = GetScreenToWorld2D({ (float)GetScreenWidth(), (float)GetScreenHeight() }, camera);
const int x0 = std::max(0, (int)std::floor(tl.x / map.tileSize)), x1 = std::min(map.width - 1, (int)std::floor(br.x / map.tileSize));
const int y0 = std::max(0, (int)std::floor(tl.y / map.tileSize)), y1 = std::min(map.height - 1, (int)std::floor(br.y / map.tileSize));
for (int y = y0; y <= y1; ++y)
    for (int x = x0; x <= x1; ++x)
        if (const int t = map.at(x, y); t != 0)
            DrawTextureRec(sheet, frameRect(t, sheetColumns, 16, 16), { (float)x * 16, (float)y * 16 }, WHITE);

At high zoom, thin lines can appear between tiles because of rounding. Draw at whole-pixel positions, use point filtering, and give the tile sheet a 1-pixel border around each tile (extrusion) if it still happens.

Levels from text files

A text file is the easiest level format to make and to change:

Output
# level 1
size 40 12
legend # stone, = grass, ~ water, P player, E enemy, C coin
.......................................
..............C.C.C....................
...P...........====.........E..........
==========.......................======
##########~~~~~~~~~~~~~~~~~~~~~~#######

Load it line by line: header lines first, then the grid. Letters for objects (P, E, C) are not tiles: when loading, record their positions in lists (player start, enemy spawns, coins) and put an empty tile in the map. One file then describes both the terrain and what is in it.

For bigger projects, the free Tiled editor saves maps as JSON or XML with layers and object lists; the loader is longer but the idea is the same.

Several layers

Real levels have layers: a background layer drawn behind the player, the solid layer for collision, a decoration layer in front. Each is its own grid of the same size. Only the solid layer is used for collision.

Auto-tiling

Choosing the right edge and corner pieces for every wall by hand is tedious. Auto-tiling chooses them: for each solid cell, look at its four neighbours and build a 4-bit number, one bit per side:

Output
bit 0: solid above   bit 1: solid right   bit 2: solid below   bit 3: solid left

The number (0 to 15) picks one of 16 tile pictures: 0 is a lone block, 15 is a solid interior, 5 (above and below) is a vertical column piece, and so on. Paint just "solid" in the level file and the loader draws proper edges. Using all eight neighbours (for inner corners) gives 47 or 256 variations with the same idea.
