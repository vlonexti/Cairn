Picking and 3D Collision

lesson 5.033 of 5 in milestone 55 min1 practice task

Clicking on things in 3D, shooting, line of sight and camera collision all ask one question - what does this ray hit first? This lesson turns the mouse into a ray, tests rays against planes, spheres and boxes, and adds sphere and box collision for moving objects.

Rays

A ray is a start point and a direction: Ray { Vector3 position; Vector3 direction; }. Points along it are position + direction * t for t >= 0. Every "what is in this direction?" question is a ray test:

Question Ray from Direction
What did the player click? The camera Through the mouse position
What does the gun hit? The muzzle or the eye The aim
Can the enemy see the player? The enemy's eyes Towards the player (with the distance as a limit)
Is the floor below me? The feet Straight down

The mouse as a ray

C++
const Ray ray = GetScreenToWorldRay(GetMousePosition(), camera);     // raylib 5 (older: GetMouseRay)
const RayCollision hit = GetRayCollisionBox(ray, crateBox);
if (hit.hit) { /* hit.point, hit.normal, hit.distance */ }

raylib has GetRayCollisionSphere, GetRayCollisionBox, GetRayCollisionMesh (exact, per triangle, slower), GetRayCollisionTriangle and GetRayCollisionQuad. To pick among many objects, test them all and keep the hit with the smallest distance.

Ray against a plane

The ground plane y = h is hit where position.y + direction.y * t = h:

C++
if (direction.y != 0) { t = (h - position.y) / direction.y; if (t >= 0) hit = position + direction * t; }

That is how strategy games turn a click into a point on the ground to move units to.

Ray against a sphere

Substitute the ray into the sphere equation |p - centre|² = r² and solve the quadratic in t. With m = position - centre and a normalised direction d: b = m · d, c = m · m - r²; if c > 0 and b > 0 the ray starts outside and points away (no hit); otherwise, with disc = b² - c, there is no hit when disc < 0, and the first hit is at t = -b - sqrt(disc) (or 0 if that is negative, meaning the ray starts inside).

Ray against a box: the slab method

An axis-aligned box is the overlap of three slabs (between two x planes, two y planes, two z planes). For each axis, compute where the ray enters and leaves that slab; the ray is inside the box between the latest entry and the earliest exit:

C++
float tmin = 0, tmax = INFINITY;
for each axis a:
    if (d[a] == 0) { if (p[a] < min[a] || p[a] > max[a]) no hit; }
    else {
        float t1 = (min[a] - p[a]) / d[a], t2 = (max[a] - p[a]) / d[a];
        if (t1 > t2) swap(t1, t2);
        tmin = max(tmin, t1); tmax = min(tmax, t2);
        if (tmin > tmax) no hit;
    }
hit at tmin

The axis that produced the final tmin is the face that was hit, which gives the normal for bullet holes or ricochets. The practice writes this test.

Moving objects

  • Sphere against sphere: centres closer than the sum of the radii, exactly as circles in 2D.
  • Box against box: overlap on all three axes (CheckCollisionBoxes).
  • Sphere against box: clamp the centre into the box for the closest point, as in 2D (CheckCollisionBoxSphere).

For level geometry that is not boxes, raylib's GetRayCollisionMesh and a few rays (down for the floor, forward for walls) are often enough for a small game; larger games use a physics library such as Jolt or Bullet.
