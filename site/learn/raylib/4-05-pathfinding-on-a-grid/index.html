Pathfinding on a Grid

lesson 4.055 of 5 in milestone 45 min1 practice task

Walking straight at the player gets enemies stuck on walls. This lesson finds paths around obstacles on a tile map - breadth-first search for equal costs, A* with a heuristic for speed, costs for different terrain, and flow fields when many enemies chase one target.

The problem

An enemy in a maze cannot just walk towards the player: the straight line goes through walls. It needs a path: a list of tiles from where it is to where it wants to be, around the obstacles.

A tile map is already a graph: each walkable tile is a node, connected to its walkable neighbours (4 directions, or 8 with diagonals).

Breadth-first search

BFS explores tiles in order of distance from the start, like a ripple spreading in water:

C++
std::vector<int> came(map.width * map.height, -1);       // where each tile was reached from
std::queue<int> frontier;
frontier.push(start); came[start] = start;
while (!frontier.empty())
{
    const int cur = frontier.front(); frontier.pop();
    if (cur == goal) break;
    for (int next : neighbours(cur))
        if (came[next] == -1 && walkable(next)) { came[next] = cur; frontier.push(next); }
}
// walk back from goal to start through came[], then reverse

When every step costs the same, the first time BFS reaches the goal it has found a shortest path. The came array records how each tile was reached; following it backwards from the goal gives the path.

A*

BFS explores in all directions, even away from the goal. A* explores the most promising tiles first. For each tile it knows:

  • g: the cost of the best path found so far from the start;
  • h: a heuristic, an estimate of the cost from the tile to the goal;
  • f = g + h: the estimated cost of a path through this tile.

A* always expands the tile with the smallest f next, using a priority queue (std::priority_queue with a comparison on f). With 4-direction movement, the Manhattan distance |dx| + |dy| is the standard heuristic. As long as the heuristic never overestimates the real cost, A* still finds a shortest path, usually after exploring far fewer tiles than BFS.

Terrain costs

Swamp could cost 3 to cross and road 1. Then the cheapest path is not always the shortest, and BFS no longer works: use Dijkstra's algorithm (A* with h = 0) or A* with the costs added to g. The heuristic must use the cheapest possible cost per step so it still never overestimates.

Following a path

  • Recompute the path only every half second or when the target moves to another tile, not every frame.
  • Move towards the next tile's centre; when close enough, move on to the one after.
  • Smooth it: skip waypoints when there is a clear line of sight to a later one, so enemies walk diagonally across open rooms instead of zig-zagging along grid lines.

Many enemies, one target

Fifty enemies chasing the player would run fifty searches. A flow field runs one: a BFS (or Dijkstra) from the player outwards over the whole map, storing each tile's distance. Each enemy then simply steps to its neighbour with the smallest distance. The cost no longer depends on the number of enemies, which is how tower defence and swarm games handle hundreds of units.
