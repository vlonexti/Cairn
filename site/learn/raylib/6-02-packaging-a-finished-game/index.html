Packaging a Finished Game

lesson 6.022 of 3 in milestone 65 min1 practice task

Turning a project that runs on your computer into a game anyone can download - release builds, loading assets reliably, an asset cache, the window and icon, testing on a clean machine, a web build with Emscripten, and publishing on itch.io.

A release build

Switch Visual Studio to Release. Debug builds are often ten times slower and need debug runtime DLLs that players do not have. Then:

  • Static runtime: set C/C++ > Code Generation > Runtime Library to /MT, so the game does not need the Visual C++ Redistributable installed. With vcpkg, use the x64-windows-static triplet so raylib is linked in too, and the game is a single .exe plus its assets.
  • No console: SubSystem Windows with entry point mainCRTStartup (lesson 1.01).
  • Icon: add a resource file (.rc) with an .ico for the file's icon in Explorer, and call SetWindowIcon(LoadImage("icon.png")) for the title bar.

Assets that always load

The classic bug of a first release: it works in Visual Studio, but double-clicking the .exe shows a black window, because the assets are loaded relative to the working directory, which is now different. Fix it once at start-up:

C++
ChangeDirectory(GetApplicationDirectory());     // relative paths now start next to the .exe

and make the build copy the assets folder next to the .exe (a post-build step, or CMake's file(COPY ...)).

Check every load: a missing texture has an id of 0 (IsTextureValid in raylib 5.5). Show a clear message ("assets/player.png is missing") instead of an invisible player.

An asset cache

When several objects use the same texture, load it once and share it:

C++
class TextureCache
{
public:
    Texture2D get(const std::string& path)
    {
        auto it = m_textures.find(path);
        if (it != m_textures.end()) return it->second;
        Texture2D t = LoadTexture(path.c_str());
        m_textures.emplace(path, t);
        return t;
    }
    ~TextureCache() { for (auto& [path, t] : m_textures) UnloadTexture(t); }   // before CloseWindow
private:
    std::unordered_map<std::string, Texture2D> m_textures;
};

Normalise the paths used as keys (assets/./player.png and assets/player.png are the same file), and destroy the cache before CloseWindow, since unloading needs the graphics context. Reference counting lets the cache free textures a level no longer uses; the practice builds it.

Test on a clean machine

Your computer has Visual Studio, vcpkg and every DLL; players' computers do not. Before publishing, run the game from a zip on a computer (or a fresh Windows virtual machine, or Windows Sandbox) that has never seen your development tools. Check the window size on a small laptop screen and a big monitor, a gamepad, and that settings and saves end up in %APPDATA%.

A web build

raylib compiles to WebAssembly with Emscripten, so the game runs in a browser with nothing to install. The main loop must give control back to the browser every frame, so it becomes a function:

C++
#if defined(PLATFORM_WEB)
#include <emscripten/emscripten.h>
#endif

void frame() { update(); draw(); }

int main()
{
    InitWindow(800, 450, "Game");
#if defined(PLATFORM_WEB)
    emscripten_set_main_loop(frame, 0, 1);       // the browser calls frame()
#else
    SetTargetFPS(60);
    while (!WindowShouldClose()) frame();
#endif
    CloseWindow();
}

Build raylib for the web (make PLATFORM=PLATFORM_WEB), compile with emcc ... -s USE_GLFW=3 --preload-file assets, and you get an .html, a .js, a .wasm and a .data file with the assets. Browsers only start audio after the player clicks, so show a "click to start" screen first.

Publishing

itch.io is the usual home for small games: upload the Windows zip and the web build (as a zip with index.html, set to "playable in the browser"), add screenshots, a short description and the controls. A short GIF of gameplay does more than any description. Use version numbers in the zip names and keep a changelog.
