Sound and Music

lesson 2.044 of 5 in milestone 25 min1 practice task

Playing sound effects and streaming music with raylib's audio module - the audio device, Sound versus Music, volume and pitch, playing the same sound many times at once, a little random variation, and volume settings in decibels and percentages.

The audio device

Audio has its own start and end, like the window:

C++
InitWindow(800, 450, "Sound");
InitAudioDevice();
// load sounds and music, run the game ...
CloseAudioDevice();
CloseWindow();

Sound and Music

Type Loaded Use
Sound Completely into memory Short effects: jumps, hits, coins. Starts instantly
Music Streamed from the file in small pieces Long tracks and ambience. Little memory
C++
Sound jump = LoadSound("assets/jump.wav");
Music theme = LoadMusicStream("assets/theme.ogg");
PlayMusicStream(theme);

while (!WindowShouldClose())
{
    UpdateMusicStream(theme);              // every frame, or the music stutters and stops
    if (IsKeyPressed(KEY_SPACE)) PlaySound(jump);
    // ...
}
UnloadSound(jump);
UnloadMusicStream(theme);

UpdateMusicStream refills the stream's buffer. Forget it and the music plays a fraction of a second and stops: the most common audio bug in raylib games. WAV and OGG are the usual formats; OGG is much smaller for music.

Volume and pitch

SetSoundVolume(s, 0.5f), SetSoundPitch(s, 1.2f) and SetMusicVolume(m, v) change one sound; SetMasterVolume(v) changes everything. Pitch 2.0 is an octave up and plays twice as fast.

Variation: hearing exactly the same footstep fifty times sounds mechanical. Vary the pitch a little each time:

C++
SetSoundPitch(step, 0.9f + GetRandomValue(0, 20) / 100.0f);   // 0.9 .. 1.1
PlaySound(step);

The same sound many times

PlaySound on a Sound that is already playing restarts it. For rapid gunfire or many coins collected at once, that cuts each sound off. Make a few aliases that share the same sample data and play them in turn:

C++
Sound coin = LoadSound("assets/coin.wav");
Sound coinVoices[4];
for (Sound& v : coinVoices) v = LoadSoundAlias(coin);
int next = 0;
// to play:
PlaySound(coinVoices[next]); next = (next + 1) % 4;
// at the end: UnloadSoundAlias for each, then UnloadSound(coin)

Volume settings players understand

Loudness is heard roughly logarithmically: halving the amplitude (0.5) sounds only a little quieter, about -6 decibels. A volume slider that maps 0-100 % straight to amplitude feels like it does nothing for most of its range and then drops suddenly at the bottom. A better mapping is through decibels, for example 0 % = silent and 1-100 % spread over -40 dB to 0 dB:

C++
float sliderToAmplitude(int percent)
{
    if (percent <= 0) return 0.0f;
    const float db = -40.0f * (1.0f - percent / 100.0f);
    return std::pow(10.0f, db / 20.0f);
}

Keep separate music and effects volumes (and multiply each by a master volume) so players can turn the music down without losing the effects.

Sound and gameplay

Sound is feedback. Each important event deserves one: jumping, landing, hitting, being hit, collecting, a menu choice, a level complete. Playing them from the place in the code where the event happens, not from the drawing code, keeps them in time with the game even when frames are dropped.
