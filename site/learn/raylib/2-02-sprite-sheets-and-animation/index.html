Sprite Sheets and Animation

lesson 2.022 of 5 in milestone 25 min1 practice task

Animation is a sequence of frames shown one after another. This lesson cuts frames out of a sprite sheet, plays them at their own speed using a timer, handles looping and one-shot animations, and switches between animations as a character's state changes.

Sprite sheets

A sprite sheet is one texture holding many frames in a grid. A 4-frame walk cycle of 32 × 32 frames is a 128 × 32 picture. Loading one texture instead of many is faster to draw and easier to manage.

The source rectangle of frame i in a sheet with columns frames per row:

C++
Rectangle frameRect(int i, int columns, float w, float h)
{
    return { (i % columns) * w, (i / columns) * h, w, h };
}

Playing frames over time

An animation shows each frame for a while, then moves to the next. Count time, not game frames, so the animation runs at the same speed at any frame rate (lesson 1.04):

C++
struct Animation
{
    int first, count;      // frames first .. first + count - 1 in the sheet
    float fps;             // animation frames per second
    bool loop;
};

struct Animator
{
    const Animation* anim{ nullptr };
    float time{ 0 };

    void play(const Animation& a) { if (anim != &a) { anim = &a; time = 0; } }
    void update(float dt) { time += dt; }

    int frame() const
    {
        int i = static_cast<int>(time * anim->fps);
        i = anim->loop ? i % anim->count : std::min(i, anim->count - 1);
        return anim->first + i;
    }
    bool finished() const { return !anim->loop && time * anim->fps >= anim->count; }
};

Notice play only restarts when the animation changes: calling play(walk) every frame while walking must not restart the walk at frame 0 each frame, which would freeze it on the first picture.

Looping and one-shot animations

  • Looping: idle, walk, run. The frame wraps around with %.
  • One-shot: attack, hurt, death. It stops on the last frame, and finished() tells the game to go back to idle (or to remove the enemy).

Some animations need events at a particular frame: the sword's hit should only count on frame 3 of the attack, and a footstep sound should play on frames 1 and 3 of the walk. Check when the frame number changes to a given value, not while it is that value, or the sound plays every game frame.

Choosing the animation from the state

The character's state picks the animation:

C++
if (attacking)          animator.play(attackAnim);
else if (!onGround)     animator.play(jumpAnim);
else if (fabs(vel.x) > 1) animator.play(walkAnim);
else                    animator.play(idleAnim);
animator.update(dt);

Rectangle src = frameRect(animator.frame(), 8, 32, 32);
if (facingLeft) src.width = -src.width;                      // lesson 2.01's flip
DrawTexturePro(sheet, src, { pos.x, pos.y, 64, 64 }, { 32, 64 }, 0, WHITE);

The order of the checks is a priority list: an attack overrides everything, jumping overrides walking. Lesson 4.04 turns this into a proper state machine.

Frame timing that varies

Hand-made animations often hold some frames longer than others: the wind-up of an attack is slow, the strike is fast. Store a duration per frame instead of one fps, and find the current frame by walking through the durations; the practice does this.
