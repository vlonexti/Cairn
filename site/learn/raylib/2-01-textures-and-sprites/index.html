Textures and Sprites

lesson 2.011 of 5 in milestone 25 min1 practice task

Loading images onto the GPU as textures, drawing them whole or in part, scaling, rotating and tinting them with DrawTexturePro, the origin point, flipping, and loading and unloading assets at the right time.

Images and textures

raylib has two kinds of picture:

Type Lives in Use
Image Main memory (CPU) Loading, editing pixels, generating pictures
Texture2D Video memory (GPU) Drawing, every frame

Most of the time you load a file straight into a texture:

C++
Texture2D player = LoadTexture("assets/player.png");   // after InitWindow
// ... game loop: DrawTexture(player, 100, 200, WHITE);
UnloadTexture(player);                                  // before CloseWindow

LoadTexture needs the OpenGL context, so it must come after InitWindow, and UnloadTexture before CloseWindow. Loading inside the game loop every frame is a classic mistake: it re-reads the file and allocates video memory 60 times a second.

Paths are relative to the working directory, which in Visual Studio is the project folder, not the folder of the .exe. Call ChangeDirectory(GetApplicationDirectory()) at start-up and copy the assets next to the program, and the same paths work everywhere.

Drawing

Function Draws
DrawTexture(tex, x, y, tint) The whole texture at its own size
DrawTextureV(tex, pos, tint) The same with a Vector2
DrawTextureEx(tex, pos, rotation, scale, tint) Rotated (degrees) and scaled
DrawTextureRec(tex, source, pos, tint) Part of the texture (the source rectangle)
DrawTexturePro(tex, source, dest, origin, rotation, tint) Part of it, into any rectangle, rotated around origin

The tint multiplies every pixel's colour: WHITE leaves it as it is, RED keeps only the red channel, and Fade(WHITE, 0.5f) makes it half transparent. Flashing a sprite white when it is hit or red when it is low on health is one tint away.

DrawTexturePro

This one function does everything, so it is worth understanding:

C++
const Rectangle source{ 0, 0, 32, 32 };                       // which part of the texture, in texture pixels
const Rectangle dest{ pos.x, pos.y, 64, 64 };                  // where on screen, and how big
const Vector2 origin{ 32, 32 };                                // pivot, relative to dest's top-left
DrawTexturePro(tex, source, dest, origin, angleDegrees, WHITE);
  • dest.x, dest.y is where the origin ends up on screen. With origin at the centre of dest, pos is the sprite's centre and rotation spins it around its middle.
  • A negative source width flips the picture horizontally; a negative height flips it vertically. That is how one "facing right" picture serves for both directions.

Pixel art

Small pixel-art sprites scaled up look blurry with the default bilinear filtering. Set point filtering for crisp pixels:

C++
SetTextureFilter(tex, TEXTURE_FILTER_POINT);

and scale by whole numbers (2×, 3×, 4×) so every source pixel becomes the same number of screen pixels.

Keeping assets together

As soon as there are more than a few textures, keep them in one place that loads everything at start-up and unloads it at the end:

C++
struct Assets
{
    Texture2D player, tiles, enemy;
    void load() { player = LoadTexture("assets/player.png"); /* ... */ }
    void unload() { UnloadTexture(player); /* ... */ }
};

Lesson 6.02 adds a cache keyed by file name, so the same picture is never loaded twice.
