Starting Processes Well

lesson 1.022 of 5 in milestone 15 min1 practice task

Everything that goes into a new process besides its command line - the environment block and how to build one, the working directory, which handles it inherits and how to limit them to exactly the ones you mean, and the creation flags that matter.

More than a command line

The Win32 API course (lesson 5.03) covered CreateProcessW, quoting arguments and waiting for the result. A child process inherits much more than its arguments from the call that creates it, and getting the rest right is what makes launching helpers reliable:

C++
BOOL CreateProcessW(
    LPCWSTR application,          // nullptr: take it from the command line
    LPWSTR commandLine,           // writable buffer
    LPSECURITY_ATTRIBUTES, LPSECURITY_ATTRIBUTES,
    BOOL inheritHandles,          // may the child inherit handles at all?
    DWORD flags,                  // CREATE_NO_WINDOW, CREATE_UNICODE_ENVIRONMENT, ...
    LPVOID environment,           // nullptr: a copy of ours
    LPCWSTR currentDirectory,     // nullptr: ours
    LPSTARTUPINFOW startup,       // standard handles, window settings, attributes
    LPPROCESS_INFORMATION info);  // the handles and IDs of the new process and its thread

The environment block

Every process has a set of environment variables (PATH, TEMP, your own settings). By default a child gets a copy of the parent's. To give it a different set, pass an environment block: one buffer of NAME=value strings, each ending with a zero, the whole block ending with an extra zero.

Text
A=1\0Path=C:\Tools;C:\Windows\System32\0TEMP=C:\Temp\0\0

Rules that matter:

  • With CREATE_UNICODE_ENVIRONMENT the block is UTF-16 (wchar_t); use it always.
  • Windows expects the variables sorted by name, ignoring case. Names are case-insensitive: Path and PATH are the same variable, and a block must not contain both.
  • A block replaces the whole environment. Start from the parent's (GetEnvironmentStringsW), change what you need, and keep SystemRoot, Path and TEMP, which many programs need to work at all.

Passing settings to a helper through environment variables is common and simple; but they are visible to anything that can inspect the process, so never put secrets in them.

The working directory

Relative paths in the child, and the order it searches for some files, depend on its current directory. By default it inherits yours, which is often not what you want (your own current directory can be anything the user chose). Pass the directory explicitly, usually the folder of the tool or of the project it works on.

Handle inheritance

A kernel object handle can be marked inheritable. If inheritHandles is TRUE, the child receives a copy of every inheritable handle the parent has, at the same values. That is how a child gets the ends of pipes for its standard streams (lesson 1.04).

The danger is "every". In a multi-threaded program, another thread may create an inheritable handle at the same moment, and it leaks into your child; the child then keeps a pipe or file open that you expected to close, and the other end never sees end-of-file. The fix is to name the exact handles to inherit with an attribute list:

C++
SIZE_T size{};
InitializeProcThreadAttributeList(nullptr, 1, 0, &size);
std::vector<std::byte> storage(size);
auto* list{ reinterpret_cast<LPPROC_THREAD_ATTRIBUTE_LIST>(storage.data()) };
InitializeProcThreadAttributeList(list, 1, 0, &size);

HANDLE inherit[]{ childStdin, childStdout };
UpdateProcThreadAttribute(list, 0, PROC_THREAD_ATTRIBUTE_HANDLE_LIST, inherit, sizeof(inherit), nullptr, nullptr);

STARTUPINFOEXW si{ { sizeof(si) } };
si.lpAttributeList = list;
CreateProcessW(nullptr, cmd.data(), nullptr, nullptr, TRUE, EXTENDED_STARTUPINFO_PRESENT | CREATE_UNICODE_ENVIRONMENT,
               env.data(), directory.c_str(), &si.StartupInfo, &pi);
DeleteProcThreadAttributeList(list);

Now only those two handles are passed, whatever else is inheritable.

Creation flags

Flag Effect
CREATE_NO_WINDOW a console program runs without opening a console window
CREATE_NEW_CONSOLE give it its own console window
CREATE_SUSPENDED create it with its main thread paused, for example to add it to a job before it runs (lesson 1.03)
CREATE_UNICODE_ENVIRONMENT the environment block is UTF-16
EXTENDED_STARTUPINFO_PRESENT startup is a STARTUPINFOEXW with an attribute list
BELOW_NORMAL_PRIORITY_CLASS run it at lower priority, good for background work
