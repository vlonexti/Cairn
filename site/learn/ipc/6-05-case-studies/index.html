Courses/Processes and Communication/Building Real Systems

Case Studies

lesson 6.055 of 5 in milestone 65 min

How real systems combine the techniques of this course - a multi-process browser, an editor and its language servers, a game and its live editor link, a Windows service with a tray application - and the questions to ask when designing your own.

A browser

A modern browser such as Chrome or Edge runs as many processes: one browser process (the window, tabs, network, storage), a renderer process per site (running its HTML, CSS and JavaScript), a GPU process, and utility processes for audio, network and storage.

  • Isolation: a crash or exploit in one site's renderer is contained; renderers run in a strict sandbox with almost no rights.
  • Communication: named pipes carrying a custom message system (Mojo) with typed interfaces generated from definition files.
  • Shared memory: rendered frames and large data move through shared memory, with only small messages over the pipes.
  • Supervision: a crashed renderer shows the "Aw, Snap!" page; the browser process carries on.

Every idea from this course is there: processes for isolation, pipes for messages, shared memory for bulk data, protocol design with versioned interfaces, and security at every boundary.

An editor and its language servers

VS Code and many other editors get code intelligence from language servers: separate processes, one per language, speaking the Language Server Protocol.

  • Transport: usually the server's stdin and stdout (lesson 1.04), with Content-Length framing.
  • Protocol: JSON-RPC 2.0, with requests and ids (completion, go to definition), notifications (document changed), and capabilities negotiated in an initialize handshake (lesson 5.02).
  • Independence: the server can be written in any language, by anyone, and work with any editor that speaks the protocol. That is the strongest argument for a documented, language-neutral protocol.

A game and its live editor

Game engines often connect a running game to an editor or debug tool: change a value in the editor and see it in the game at once.

  • Discovery: the game listens on a loopback port (or named pipe) and announces itself through a port file, or the editor launches the game with the endpoint on the command line.
  • Commands: a request and response protocol over a socket or pipe: set this property, spawn this object, reload this asset.
  • Telemetry: frame times, memory and object counts streamed back, or published in shared memory with a seqlock so the tool never slows the game (lesson 3.05).
  • Robustness: either side can restart; the connection is re-established automatically, and the game never blocks waiting for the tool.

A service and its tray application

A Windows service runs in session 0 under its own account; the user's tray icon runs in the user's session. They cannot share windows or Local\ objects, so:

  • the service creates a named pipe with a security descriptor that allows the interactive users (lesson 5.05);
  • the tray application connects as a client, sends commands (pause, settings), and receives events (status changes);
  • the service impersonates the client when it must act with the user's rights, and validates every request, because any program the user runs can connect.

Designing your own

Faced with a new system, walk through the questions this course has raised:

  1. Which processes, and why? Isolation, rights, crash containment, or just separate products?
  2. Who finds whom? Inherited handles, names, port files, command-line arguments.
  3. Which channel? Pipes or sockets for messages, shared memory for bulk or latest-state data, events and mutexes for signalling.
  4. What is the protocol? Handshake, envelope, versioning, requests, responses and events, limits.
  5. What fails, and how do you notice? Timeouts, process handles, heartbeats, abandoned mutexes.
  6. Who could abuse it? Access control, tokens, validation, impersonation.
  7. How will you test and debug it? Layers, fault injection, transcripts, logs with ids.

The project that ends this course answers all seven for one complete system.
