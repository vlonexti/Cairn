File Mappings

lesson 3.011 of 5 in milestone 35 min1 practice task

Shared memory on Windows - a named file mapping backed by the page file, views mapped into each process at different addresses, sizes and page rounding, Local and Global names, who creates and who opens, and when the memory goes away.

The fastest channel there is

Every method so far copies data: from the sender into the kernel, and from the kernel into the receiver. Shared memory copies nothing. The kernel maps the same physical pages into two (or more) processes' address spaces; a byte written by one is immediately visible to the other.

On Windows, shared memory is a file mapping object. It can be backed by a real file (lesson 3.04) or, for pure IPC, by the page file:

C++
constexpr DWORD SIZE{ 64 * 1024 };

// The creator (often the server, or whichever process starts first)
HANDLE mapping{ CreateFileMappingW(INVALID_HANDLE_VALUE,         // page-file backed: no real file
                                   &security,                     // who may open it (lesson 5.05)
                                   PAGE_READWRITE,
                                   0, SIZE,                       // size: high and low 32 bits
                                   LR"(Local\xenon-telemetry)") };
const bool existed{ GetLastError() == ERROR_ALREADY_EXISTS };     // someone created it first

void* view{ MapViewOfFile(mapping, FILE_MAP_READ | FILE_MAP_WRITE, 0, 0, SIZE) };
// ... use `view` as SIZE bytes of memory ...
UnmapViewOfFile(view);
CloseHandle(mapping);
C++
// Another process
HANDLE mapping{ OpenFileMappingW(FILE_MAP_READ, FALSE, LR"(Local\xenon-telemetry)") };
const void* view{ MapViewOfFile(mapping, FILE_MAP_READ, 0, 0, 0) };   // 0: map all of it

CreateFileMappingW with a name opens the existing object if it already exists (and sets ERROR_ALREADY_EXISTS), so it serves both sides when either might start first. OpenFileMappingW only opens, failing with ERROR_FILE_NOT_FOUND if nobody created it.

Different addresses

The view appears at some address in each process, chosen independently: 0x1F0000 in one, 0x2A0000 in the other. The bytes are the same; the addresses are not. That one fact shapes everything you put into shared memory (lesson 3.02): a pointer stored in shared memory is meaningless to the other process.

Sizes and pages

Memory is mapped in whole pages (4 KB), so a mapping's real size is rounded up to a page. A view's starting offset must be a multiple of the allocation granularity, 64 KB on Windows (GetSystemInfo reports it). Pages are committed lazily: a 1 GB page-file mapping costs nothing until its pages are touched, then each touched page costs RAM or page file.

The size is given as two 32-bit halves because mappings can be larger than 4 GB: high word size >> 32, low word size & 0xFFFFFFFF.

Names: Local and Global

Kernel object names (mappings, and the events and mutexes of milestone 4) live in a namespace per session:

  • Local\name (or just name): visible only within the current login session. The usual choice for programs on a user's desktop.
  • Global\name: visible across sessions, so a service in session 0 and a desktop program can share it. Creating global objects needs the SeCreateGlobalPrivilege right, which services and administrators have.

After the prefix the name may not contain another backslash. As with pipe names, choose names that will not collide: product, purpose, and a user or session identifier.

Lifetime

A mapping exists as long as any process holds a handle to it or has a view mapped. When the last one is gone, a page-file mapping and its contents vanish. So:

  • If the creator exits while another process still has it open, the data stays.
  • If every process closes it, the next process to create it gets fresh, zeroed memory. A page-file mapping always starts zeroed, which is useful: an all-zero header can mean "not yet initialised" (lesson 3.02).

What it does not give you

Shared memory moves no messages and sends no signals. It does not tell a reader that new data has arrived, it does not stop two writers from colliding, and it does not tell you when the other process has died. Every one of those must be built on top: atomics and ring buffers (lesson 3.03), events (milestone 4), seqlocks (lesson 3.05), and watching the other process's handle.
