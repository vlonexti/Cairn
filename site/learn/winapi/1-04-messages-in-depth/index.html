Messages in Depth

lesson 1.044 of 5 in milestone 15 min1 practice task

How messages really flow - posted versus sent messages, the order of messages when a window is created and destroyed, how WPARAM and LPARAM pack several values, storing per-window data, and custom messages of your own.

Posted and sent

There are two ways a message reaches a window procedure:

Posted Sent
Function PostMessageW SendMessageW
Goes Into the queue; the loop dispatches it later Straight to the window procedure (on its thread)
Returns Immediately, before it is handled After it is handled, with the procedure's result
Typical Input, WM_PAINT, WM_TIMER, WM_QUIT, your own notifications WM_CREATE, WM_SIZE, WM_SETTEXT, asking a control a question

SendMessageW is a function call through the window system. If the window belongs to another thread, the calling thread waits while that thread processes the message, which is how two threads can deadlock: each waiting for the other to answer. Use PostMessageW from worker threads (lesson 5.04).

Some messages are never really in the queue: WM_PAINT, WM_TIMER and WM_MOUSEMOVE are produced on demand when the queue is otherwise empty, and repeated ones are combined. Ten invalidations before the next paint give one WM_PAINT.

A window's life

Creating a window sends, in order (among others): WM_NCCREATE, WM_NCCALCSIZE, WM_CREATE, then WM_SIZE and WM_MOVE as it gets its position, and WM_SHOWWINDOW when it is shown. Destroying it sends WM_DESTROY and, last of all, WM_NCDESTROY. "NC" means non-client: the frame and title bar.

WM_CREATE is where a window creates its child controls and resources; WM_DESTROY is where it frees them.

Packed parameters

WPARAM and LPARAM are just numbers; each message defines what they hold. Often two 16-bit values are packed into one parameter:

C++
case WM_SIZE:
{
    const int width = LOWORD(lParam);       // low 16 bits
    const int height = HIWORD(lParam);      // high 16 bits
    // wParam: SIZE_MAXIMIZED, SIZE_MINIMIZED, SIZE_RESTORED
    return 0;
}
case WM_LBUTTONDOWN:
{
    const int x = GET_X_LPARAM(lParam);     // from <windowsx.h>; SIGNED
    const int y = GET_Y_LPARAM(lParam);
    return 0;
}

Use GET_X_LPARAM rather than LOWORD for mouse positions: with several monitors, a position can be negative, and LOWORD would turn -1 into 65535. MAKELPARAM(lo, hi) packs two values for sending. The practice writes these macros as functions.

Data for each window

The window procedure is a free function, but a window usually belongs to a C++ object. The standard pattern passes this as the last argument of CreateWindowExW, picks it up in WM_NCCREATE, and stores it in the window with SetWindowLongPtrW(hwnd, GWLP_USERDATA, ...):

C++
class MainWindow
{
public:
    static LRESULT CALLBACK Proc(HWND hwnd, UINT msg, WPARAM wParam, LPARAM lParam)
    {
        MainWindow* self = nullptr;
        if (msg == WM_NCCREATE)
        {
            self = static_cast<MainWindow*>(reinterpret_cast<CREATESTRUCTW*>(lParam)->lpCreateParams);
            self->m_hwnd = hwnd;
            SetWindowLongPtrW(hwnd, GWLP_USERDATA, reinterpret_cast<LONG_PTR>(self));
        }
        else self = reinterpret_cast<MainWindow*>(GetWindowLongPtrW(hwnd, GWLP_USERDATA));
        return self ? self->handle(msg, wParam, lParam) : DefWindowProcW(hwnd, msg, wParam, lParam);
    }
private:
    LRESULT handle(UINT msg, WPARAM wParam, LPARAM lParam);    // an ordinary member function
    HWND m_hwnd{};
};
// CreateWindowExW(..., instance, this);

Messages before WM_NCCREATE (there is at least WM_GETMINMAXINFO) arrive while the pointer is not yet stored, hence the null check.

Your own messages

For messages of your own, use numbers from WM_APP (0x8000) to 0xBFFF within your application:

C++
constexpr UINT WM_APP_SEARCH_DONE = WM_APP + 1;
PostMessageW(hwnd, WM_APP_SEARCH_DONE, count, 0);     // from a worker thread: "the search finished"

WM_USER (0x0400 and up) is reserved for a window class's own private messages; controls use that range, so do not send WM_USER messages to windows you did not write. Between programs, RegisterWindowMessageW(L"name") gives a number unique across the system.
