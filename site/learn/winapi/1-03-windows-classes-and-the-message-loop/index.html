Windows, Classes and the Message Loop

lesson 1.033 of 5 in milestone 15 min1 practice task

The smallest real Windows program - registering a window class, creating a window, running the message loop, and writing the window procedure that handles messages. This lesson builds it line by line and explains each step.

The whole program

C++
#define WIN32_LEAN_AND_MEAN
#define NOMINMAX
#include <windows.h>

LRESULT CALLBACK WndProc(HWND hwnd, UINT msg, WPARAM wParam, LPARAM lParam)
{
    switch (msg)
    {
    case WM_DESTROY:
        PostQuitMessage(0);          // ends the message loop
        return 0;
    }
    return DefWindowProcW(hwnd, msg, wParam, lParam);   // default handling for everything else
}

int WINAPI wWinMain(HINSTANCE instance, HINSTANCE, PWSTR commandLine, int showCommand)
{
    // 1. Describe a kind of window.
    WNDCLASSEXW wc{ sizeof(wc) };
    wc.lpfnWndProc = WndProc;
    wc.hInstance = instance;
    wc.hCursor = LoadCursorW(nullptr, IDC_ARROW);
    wc.hbrBackground = reinterpret_cast<HBRUSH>(COLOR_WINDOW + 1);
    wc.lpszClassName = L"XenonMainWindow";
    if (!RegisterClassExW(&wc)) return 1;

    // 2. Create one.
    HWND hwnd = CreateWindowExW(0, L"XenonMainWindow", L"Hello, Windows", WS_OVERLAPPEDWINDOW,
                                CW_USEDEFAULT, CW_USEDEFAULT, 800, 500, nullptr, nullptr, instance, nullptr);
    if (!hwnd) return 1;
    ShowWindow(hwnd, showCommand);

    // 3. Run the message loop.
    MSG msg;
    while (GetMessageW(&msg, nullptr, 0, 0) > 0)
    {
        TranslateMessage(&msg);      // turns key presses into WM_CHAR messages
        DispatchMessageW(&msg);      // calls the window procedure
    }
    return static_cast<int>(msg.wParam);
}

In Visual Studio, create a Windows Desktop Application (or an empty project with SubSystem set to Windows) so wWinMain is the entry point.

Step 1: the window class

A window class describes a kind of window: which window procedure handles its messages, its cursor, its background brush, its icon. Every window belongs to a class. RegisterClassExW registers it under a name, once per program. Buttons, edit boxes and list boxes are windows of classes Windows registers for you (L"BUTTON", L"EDIT"), which is how controls work (lesson 2.05).

COLOR_WINDOW + 1 is an odd convention: a system colour index plus one, cast to a brush, tells Windows to paint the background in the user's window colour.

Step 2: creating the window

CreateWindowExW takes the extended style, class name, title, style, position, size, parent, menu, instance and a user pointer. WS_OVERLAPPEDWINDOW is the usual top-level window with a title bar, border, and minimise, maximise and close buttons. CW_USEDEFAULT lets Windows choose the position.

The size includes the border and title bar. To get a client area (the inside) of exactly 800 × 500, compute the outer size first with AdjustWindowRectEx (or AdjustWindowRectExForDpi, lesson 3.04).

Step 3: the message loop

Windows does not call your code directly when something happens. It puts a message in your thread's message queue: a key was pressed, the mouse moved, the window must be repainted. The loop takes messages out one by one:

flowchart LR
    Q[Message queue] -->|GetMessageW| L[Your loop] -->|DispatchMessageW| P[WndProc]
  • GetMessageW waits until there is a message and returns it. It returns 0 for WM_QUIT (the loop ends) and -1 on error, which is why the loop tests > 0 rather than just "true".
  • TranslateMessage creates character messages from key messages (lesson 2.01).
  • DispatchMessageW calls the window procedure of the window the message is for.

Step 4: the window procedure

The window procedure (WndProc) is called with each message: the window, the message number (WM_...), and two parameters whose meaning depends on the message. It returns a result whose meaning also depends on the message.

Anything you do not handle goes to DefWindowProcW, which implements standard behaviour: moving and resizing the window, the system menu, closing on Alt+F4, and so on. Forgetting to call it for unhandled messages gives a window that cannot even be moved.

Closing

Clicking the close button sends WM_CLOSE; the default handling calls DestroyWindow, which sends WM_DESTROY. The main window handles WM_DESTROY by calling PostQuitMessage(0), which posts WM_QUIT, which makes GetMessageW return 0 and the loop end. To ask "save changes?" before closing, handle WM_CLOSE and only call DestroyWindow if the user agrees.
