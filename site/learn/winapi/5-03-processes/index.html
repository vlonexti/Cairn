Processes

lesson 5.033 of 5 in milestone 55 min1 practice task

Starting other programs from yours - CreateProcessW and its mutable command line, quoting arguments correctly, waiting for a child and reading its exit code, capturing its output through pipes, and opening documents with ShellExecuteExW.

CreateProcessW

Programs often run other programs: an editor runs a compiler, a launcher runs a game, a tool runs git. The base function is CreateProcessW:

C++
std::wstring commandLine = L"\"C:\\Tools\\formatter.exe\" --in-place \"C:\\My Notes\\today.md\"";

STARTUPINFOW si{ sizeof(si) };
PROCESS_INFORMATION pi{};
if (!CreateProcessW(nullptr, commandLine.data(),    // MUTABLE buffer: CreateProcessW may write to it
                    nullptr, nullptr, FALSE, CREATE_NO_WINDOW, nullptr, nullptr, &si, &pi))
{
    const DWORD error = GetLastError();     // 2: program not found
}
else
{
    WaitForSingleObject(pi.hProcess, INFINITE);
    DWORD exitCode = 0;
    GetExitCodeProcess(pi.hProcess, &exitCode);  // 0 usually means success
    CloseHandle(pi.hThread);
    CloseHandle(pi.hProcess);
}

Things that surprise everyone:

  • The command line must be a writable buffer; passing a string literal crashes.
  • pi returns two handles, the process and its main thread, and both must be closed.
  • Waiting with INFINITE on the UI thread freezes the window until the child ends. Wait on a worker thread (lesson 5.04), or register a callback with RegisterWaitForSingleObject.
  • CREATE_NO_WINDOW stops a console program from flashing up a black console window.

Quoting arguments

On Windows, a program receives its command line as one string, and each program splits it into arguments itself (the C runtime and CommandLineToArgvW follow the same rules). So the caller must quote arguments so that they split back correctly:

  • An argument with spaces or tabs (or an empty argument) must be wrapped in double quotes.
  • A " inside an argument is written as \".
  • Backslashes are literal, except before a ": then each backslash must be doubled. So C:\My Folder\ as one argument is written "C:\My Folder\\": otherwise the final \" would be read as an escaped quote and swallow the rest of the line.

Getting this wrong makes paths with spaces fail, and, worse, lets an argument containing quotes inject extra arguments. The practice writes both the splitting and the quoting functions, and checks that one undoes the other.

Capturing output

To read what a console program prints, give it a pipe as its standard output:

C++
SECURITY_ATTRIBUTES sa{ sizeof(sa), nullptr, TRUE };           // TRUE: the handle can be inherited
HANDLE readEnd, writeEnd;
CreatePipe(&readEnd, &writeEnd, &sa, 0);
SetHandleInformation(readEnd, HANDLE_FLAG_INHERIT, 0);          // the child gets only the write end

STARTUPINFOW si{ sizeof(si) };
si.dwFlags = STARTF_USESTDHANDLES;
si.hStdOutput = writeEnd;
si.hStdError = writeEnd;
si.hStdInput = GetStdHandle(STD_INPUT_HANDLE);
CreateProcessW(nullptr, cmd.data(), nullptr, nullptr, TRUE /* inherit */, CREATE_NO_WINDOW, nullptr, nullptr, &si, &pi);
CloseHandle(writeEnd);                                          // our copy: otherwise ReadFile never sees the end

char buffer[4096];
DWORD n;
std::string output;
while (ReadFile(readEnd, buffer, sizeof(buffer), &n, nullptr) && n > 0) output.append(buffer, n);

Closing our copy of the write end is essential: the pipe only reports end-of-file when every write handle is closed, and if we keep one, the read loop waits forever after the child exits. If the child can also wait on input, or output is very large, read on a separate thread so neither side blocks the other.

Console programs usually print in the console's code page or UTF-8; decode the bytes with lesson 1.02's conversion and normalise \r\n.

Opening documents

To open a file with the user's default program ("open this PDF", "show this folder"), do not start a specific .exe: let the shell decide.

C++
SHELLEXECUTEINFOW sei{ sizeof(sei) };
sei.fMask = SEE_MASK_NOASYNC;
sei.lpVerb = L"open";              // or "edit", "print"; nullptr = the default verb
sei.lpFile = L"C:\\Notes\\report.pdf";
sei.nShow = SW_SHOWNORMAL;
ShellExecuteExW(&sei);

Opening a web page is the same call with a URL. To show a file selected in Explorer, run explorer.exe /select,"path" or use SHOpenFolderAndSelectItems.

Your own process

GetCommandLineW and CommandLineToArgvW give your program's own arguments; GetModuleFileNameW(nullptr, ...) its own .exe path; ExitProcess ends it (prefer returning from wWinMain). A job object groups child processes so they are all ended when your program exits, which keeps helper processes from being left behind.
