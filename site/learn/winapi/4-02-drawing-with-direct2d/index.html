Drawing with Direct2D

lesson 4.022 of 4 in milestone 45 min1 practice task

Direct2D draws antialiased shapes, gradients and bitmaps on the GPU. This lesson creates the factory and a render target for a window, separates device-independent and device-dependent resources, handles device loss, and uses transforms to move, rotate and scale drawings.

The pieces

Direct2D is a COM-based API (lesson 3.02):

Object What Lifetime
ID2D1Factory Creates everything else Whole program
ID2D1HwndRenderTarget Draws into a window Until the device is lost
Brushes, bitmaps, layers Belong to one render target Same as the render target
Geometries, stroke styles Device-independent Whole program

The distinction matters: device-dependent resources (the render target, brushes, bitmaps) live on the GPU and must be re-created if the device is lost; device-independent ones (geometries) do not.

C++
#include <d2d1.h>
#pragma comment(lib, "d2d1.lib")

ComPtr<ID2D1Factory> g_factory;
D2D1CreateFactory(D2D1_FACTORY_TYPE_SINGLE_THREADED, g_factory.GetAddressOf());   // once

Creating the render target lazily

C++
HRESULT createDeviceResources(HWND hwnd)
{
    if (m_target) return S_OK;
    RECT rc; GetClientRect(hwnd, &rc);
    HRESULT hr = g_factory->CreateHwndRenderTarget(
        D2D1::RenderTargetProperties(D2D1_RENDER_TARGET_TYPE_DEFAULT, D2D1::PixelFormat(), 96.0f, 96.0f),
        D2D1::HwndRenderTargetProperties(hwnd, D2D1::SizeU(rc.right, rc.bottom)),
        m_target.ReleaseAndGetAddressOf());
    if (SUCCEEDED(hr)) hr = m_target->CreateSolidColorBrush(D2D1::ColorF(0.2f, 0.4f, 0.8f), m_brush.ReleaseAndGetAddressOf());
    if (SUCCEEDED(hr)) m_target->SetDpi(float(GetDpiForWindow(hwnd)), float(GetDpiForWindow(hwnd)));
    return hr;
}

SetDpi makes Direct2D work in device-independent pixels (DIPs, 1/96 inch): you draw at 96-DPI sizes and it scales to the monitor, which removes most of lesson 3.04's arithmetic.

Drawing

C++
case WM_PAINT:
{
    PAINTSTRUCT ps;
    BeginPaint(hwnd, &ps);
    if (SUCCEEDED(createDeviceResources(hwnd)))
    {
        m_target->BeginDraw();
        m_target->Clear(D2D1::ColorF(D2D1::ColorF::White));
        m_target->FillEllipse(D2D1::Ellipse(D2D1::Point2F(150, 120), 80, 50), m_brush.Get());
        m_target->DrawLine(D2D1::Point2F(20, 20), D2D1::Point2F(300, 200), m_brush.Get(), 3.0f);
        m_target->DrawRoundedRectangle(D2D1::RoundedRect(D2D1::RectF(20, 220, 300, 300), 8, 8), m_brush.Get(), 1.5f);
        const HRESULT hr = m_target->EndDraw();
        if (hr == D2DERR_RECREATE_TARGET) discardDeviceResources();      // device lost: re-create next time
    }
    EndPaint(hwnd, &ps);
    return 0;
}
case WM_SIZE:
    if (m_target) m_target->Resize(D2D1::SizeU(LOWORD(lParam), HIWORD(lParam)));
    return 0;

The device can be lost when the graphics driver is updated, the GPU resets, or a remote desktop session starts. EndDraw then returns D2DERR_RECREATE_TARGET; release every device-dependent resource and let the next paint re-create them. Programs that skip this go blank after a driver update until restarted.

Colours in Direct2D are floats from 0 to 1 (D2D1::ColorF(r, g, b, a)), and coordinates are floats: a 1-pixel line on a whole coordinate is drawn across two pixel rows, half intensity each. To get crisp 1-pixel lines, put them at half coordinates (10.5).

Geometry

Complex shapes are path geometries, built from lines and curves once and drawn many times:

C++
ComPtr<ID2D1PathGeometry> path;
g_factory->CreatePathGeometry(&path);
ComPtr<ID2D1GeometrySink> sink;
path->Open(&sink);
sink->BeginFigure(D2D1::Point2F(0, 0), D2D1_FIGURE_BEGIN_FILLED);
sink->AddLine(D2D1::Point2F(40, 0));
sink->AddBezier(D2D1::BezierSegment(D2D1::Point2F(60, 0), D2D1::Point2F(60, 40), D2D1::Point2F(40, 40)));
sink->AddLine(D2D1::Point2F(0, 40));
sink->EndFigure(D2D1_FIGURE_END_CLOSED);
sink->Close();
// m_target->FillGeometry(path.Get(), brush); geometries can also hit-test: path->FillContainsPoint(...)

Transforms

Every drawing call goes through the render target's transform, a 3 × 2 matrix (D2D1::Matrix3x2F). Draw a shape around the origin once, then place it anywhere:

C++
m_target->SetTransform(D2D1::Matrix3x2F::Rotation(angle, D2D1::Point2F(0, 0)) *
                       D2D1::Matrix3x2F::Translation(200, 150));
m_target->FillGeometry(path.Get(), m_brush.Get());                // rotated, then moved to (200, 150)
m_target->SetTransform(D2D1::Matrix3x2F::Identity());

Order matters: with Direct2D's row-vector convention, A * B means "first A, then B". Rotating then translating spins the shape in place and moves it; translating then rotating swings it around the origin. Zooming and panning a whole drawing (a map, a diagram) is one scale-and-translate transform, and its inverse turns mouse positions back into drawing coordinates. The practice implements these matrices.
