High-DPI Screens

lesson 3.044 of 5 in milestone 35 min1 practice task

Laptops and 4K monitors run at 150 % or 200 % scaling, and a program that ignores it is either tiny or blurry. This lesson declares per-monitor DPI awareness, scales sizes and fonts with the DPI, handles moving between monitors with WM_DPICHANGED, and picks the right icon sizes.

What DPI scaling is

Windows assumes 96 dots per inch at 100 % scaling. A 14-inch 1080p laptop usually runs at 150 % (144 DPI), a 27-inch 4K monitor at 150 % or 200 %. At 150 %, a button that should look 80 pixels wide must be 120 physical pixels wide.

A program that does not declare otherwise is DPI-unaware: Windows draws it at 96 DPI and stretches the result, which makes all its text blurry. To look sharp, a program declares that it handles DPI itself, and then scales everything.

Declaring awareness

Declare per-monitor v2 awareness in the application manifest (lesson 6.02):

C++
<application xmlns="urn:schemas-microsoft-com:asm.v3">
  <windowsSettings>
    <dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">PerMonitorV2</dpiAwareness>
  </windowsSettings>
</application>

or call SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2) before creating any window. Per-monitor v2 means: each window has the DPI of the monitor it is on, and the program is told when it changes. It also makes Windows scale the non-client area, dialogs and common controls automatically.

Scaling numbers

Design at 96 DPI and scale every size by dpi / 96, rounding to the nearest pixel. MulDiv does exactly that without overflow:

C++
const UINT dpi = GetDpiForWindow(hwnd);
int scale(int value96) { return MulDiv(value96, dpi, 96); }      // rounds half away from zero

const int padding = scale(10);       // 15 at 144 DPI
const int buttonWidth = scale(80);   // 120 at 144 DPI

Apply it to everything measured in pixels: margins, control sizes, line widths, icon sizes, the minimum window size. Scale from the 96-DPI design value each time, not from the previous scaled value, or rounding errors build up as the window moves between monitors.

System metrics have DPI-aware versions: GetSystemMetricsForDpi(SM_CXVSCROLL, dpi), AdjustWindowRectExForDpi, SystemParametersInfoForDpi.

Fonts

Font sizes are in points (1/72 inch). The height in pixels is -MulDiv(points, dpi, 72) (the minus sign asks for the character height, not the cell height). Re-create fonts when the DPI changes; for the standard message font, SystemParametersInfoForDpi(SPI_GETNONCLIENTMETRICS, ..., dpi) gives it already scaled.

WM_DPICHANGED

When a window moves to a monitor with a different DPI (or the user changes the scaling), it receives WM_DPICHANGED with the new DPI and a suggested rectangle: the window's new size and position so it looks the same physical size. Use that rectangle, then re-create fonts and lay out again:

C++
case WM_DPICHANGED:
{
    m_dpi = HIWORD(wParam);
    const RECT* suggested = reinterpret_cast<RECT*>(lParam);
    SetWindowPos(hwnd, nullptr, suggested->left, suggested->top, suggested->right - suggested->left,
                 suggested->bottom - suggested->top, SWP_NOZORDER | SWP_NOACTIVATE);
    recreateFonts();
    layout();                         // lesson 3.03's single layout function
    return 0;
}

Icons and images

An icon at 16 × 16 looks tiny at 200 %. Ship icons in several sizes (16, 20, 24, 32, 40, 48, 64, 256) inside the .ico, and load the right one with LoadIconWithScaleDown or LoadImageW at scale(16). For toolbars, prefer vector graphics (Direct2D, an icon font such as Segoe Fluent Icons) that scale to any size. When only one bitmap size is available, choose the nearest larger one and scale it down, which looks far better than scaling a small one up.

Testing

Test at 100 %, 150 % and 200 %, and drag the window between two monitors with different scaling. A second monitor is not required: change the scaling in Settings > Display while the program runs, which sends the same WM_DPICHANGED.
