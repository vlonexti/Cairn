The Console

lesson 7.022 of 6 in milestone 75 min1 practice task

Writing programs that live in a terminal - console and GUI programs, attaching or creating a console, standard handles, Unicode output with WriteConsoleW and UTF-8 code pages, colour and cursor control with virtual terminal sequences, reading keys as input records, and handling Ctrl+C and closing the window.

Console programs and GUI programs

Every Windows executable is marked as either a console program or a GUI program (the /SUBSYSTEM:CONSOLE or /SUBSYSTEM:WINDOWS linker option):

  • A console program started from Explorer gets a new console window; started from a terminal, it shares that terminal.
  • A GUI program has no console. If it needs one, AttachConsole(ATTACH_PARENT_PROCESS) joins the terminal that started it (for command-line tools with a GUI), and AllocConsole() creates a new one (for a debug window).

Standard handles and Unicode

GetStdHandle(STD_OUTPUT_HANDLE) (also STD_INPUT_HANDLE, STD_ERROR_HANDLE) gives the console's handles. Text output has two routes:

  • WriteConsoleW writes UTF-16 directly to a console: every character appears correctly, whatever the code page. It fails if output is redirected to a file or pipe (program > out.txt), so check with GetConsoleMode whether the handle is a console and use WriteFile otherwise.
  • Bytes (printf, std::cout, WriteFile) are interpreted in the console's output code page. Call SetConsoleOutputCP(CP_UTF8) at start-up, and write UTF-8, to get the same result.

Colour and cursor: virtual terminal sequences

Modern Windows consoles understand the same escape sequences as Linux and macOS terminals, once enabled:

C++
HANDLE out{ GetStdHandle(STD_OUTPUT_HANDLE) };
DWORD mode{ 0 };
GetConsoleMode(out, &mode);
SetConsoleMode(out, mode | ENABLE_VIRTUAL_TERMINAL_PROCESSING);

std::wprintf(L"\x1b[1;32mOK\x1b[0m  done\n");          // bold green "OK", then reset
std::wprintf(L"\x1b[2K\r%3d%%", percent);              // clear the line, back to its start, rewrite progress
Sequence Effect
ESC[0m reset all attributes
ESC[1m bold or bright
ESC[30m ... ESC[37m foreground colour (black, red, green, yellow, blue, magenta, cyan, white)
ESC[40m ... ESC[47m background colour
ESC[90m ... ESC[97m bright foreground colours
ESC[2K erase the whole line
ESC[<row>;<col>H move the cursor (1-based)
ESC[?25l, ESC[?25h hide, show the cursor

ESC is the character 27 (\x1b). The older SetConsoleTextAttribute API still works, but sequences are portable and work over SSH.

Reading keys

ReadConsoleW reads a line the console has already edited. To react to individual keys (arrows, function keys, key releases), switch off line input and read input records:

C++
INPUT_RECORD records[16];
DWORD count{ 0 };
ReadConsoleInputW(in, records, 16, &count);
for (DWORD i{ 0 }; i < count; ++i)
{
    if (records[i].EventType != KEY_EVENT || !records[i].Event.KeyEvent.bKeyDown) continue;
    const KEY_EVENT_RECORD& key{ records[i].Event.KeyEvent };
    // key.wVirtualKeyCode (VK_LEFT, VK_RETURN ...), key.uChar.UnicodeChar, key.dwControlKeyState
}

Ctrl+C and closing

By default Ctrl+C ends a console program at once. To clean up first (save a file, stop a worker), register a handler:

C++
std::atomic<bool> g_stop{ false };

BOOL WINAPI onConsoleEvent(DWORD type)
{
    if (type == CTRL_C_EVENT || type == CTRL_BREAK_EVENT || type == CTRL_CLOSE_EVENT)
    {
        g_stop = true;          // the main loop notices and exits cleanly
        return TRUE;            // handled
    }
    return FALSE;
}

SetConsoleCtrlHandler(onConsoleEvent, TRUE);

The handler runs on a new thread, so it only sets a flag. For CTRL_CLOSE_EVENT (the window's close button) Windows waits only a few seconds before ending the process, so cleanup must be quick.
