Services

lesson 7.044 of 6 in milestone 75 min1 practice task

Programs that run in the background without anyone signed in - what a Windows service is, the service control manager, the service main function and control handler, reporting state with SetServiceStatus, start and stop pending states with checkpoints and wait hints, installing with sc.exe, accounts, and the rules that come with session 0.

What a service is

A service is a program that the service control manager (SCM) starts, usually at boot, and that runs without a signed-in user and without a window: a backup agent, a database, a web server, an update checker. The Services app (services.msc) and sc.exe list them. Writing one is mostly about speaking the SCM's protocol correctly.

The shape of a service program

C++
SERVICE_STATUS_HANDLE g_statusHandle{};
SERVICE_STATUS g_status{ SERVICE_WIN32_OWN_PROCESS };
HANDLE g_stopEvent{};

void report(DWORD state, DWORD exitCode = NO_ERROR, DWORD waitHint = 0)
{
    static DWORD checkPoint{ 1 };
    g_status.dwCurrentState = state;
    g_status.dwWin32ExitCode = exitCode;
    g_status.dwWaitHint = waitHint;
    g_status.dwControlsAccepted = (state == SERVICE_START_PENDING) ? 0 : SERVICE_ACCEPT_STOP | SERVICE_ACCEPT_SHUTDOWN;
    g_status.dwCheckPoint = (state == SERVICE_RUNNING || state == SERVICE_STOPPED) ? 0 : checkPoint++;
    SetServiceStatus(g_statusHandle, &g_status);
}

DWORD WINAPI handler(DWORD control, DWORD, void*, void*)
{
    switch (control)
    {
    case SERVICE_CONTROL_STOP:
    case SERVICE_CONTROL_SHUTDOWN:
        report(SERVICE_STOP_PENDING, NO_ERROR, 5000);
        SetEvent(g_stopEvent);
        return NO_ERROR;
    case SERVICE_CONTROL_INTERROGATE:
        return NO_ERROR;
    default:
        return ERROR_CALL_NOT_IMPLEMENTED;
    }
}

void WINAPI serviceMain(DWORD, LPWSTR*)
{
    g_statusHandle = RegisterServiceCtrlHandlerExW(L"XenonAgent", handler, nullptr);
    report(SERVICE_START_PENDING, NO_ERROR, 3000);
    g_stopEvent = CreateEventW(nullptr, TRUE, FALSE, nullptr);
    // ... start up, calling report(SERVICE_START_PENDING, ...) again if it takes a while ...
    report(SERVICE_RUNNING);
    WaitForSingleObject(g_stopEvent, INFINITE);          // the real work runs on other threads
    // ... shut down ...
    report(SERVICE_STOPPED);
}

int wmain()
{
    SERVICE_TABLE_ENTRYW table[]{ { const_cast<LPWSTR>(L"XenonAgent"), serviceMain }, { nullptr, nullptr } };
    if (!StartServiceCtrlDispatcherW(table))
        return static_cast<int>(GetLastError());          // ERROR_FAILED_SERVICE_CONTROLLER_CONNECT: run from a console
}
  • wmain hands control to the SCM with StartServiceCtrlDispatcherW, which calls serviceMain on a new thread and returns only when the service stops.
  • serviceMain registers the control handler first, then reports its state.
  • The handler receives controls (stop, shutdown, pause, interrogate) and must return quickly: it signals the main code and reports a pending state.

The state machine

State Meaning Checkpoint and wait hint
SERVICE_START_PENDING starting checkpoint increases with each report; wait hint = how long until the next
SERVICE_RUNNING running 0
SERVICE_STOP_PENDING stopping increasing, with a wait hint
SERVICE_STOPPED stopped 0; dwWin32ExitCode says why
SERVICE_PAUSE_PENDING, SERVICE_PAUSED, SERVICE_CONTINUE_PENDING pausing, if supported as above

In a pending state, the SCM expects either the checkpoint to increase or the state to change before the wait hint runs out; otherwise it decides the service has hung. dwControlsAccepted says which controls the service takes now: none while starting. Practice 7.04 implements these rules.

Installing and running

Text
sc create XenonAgent binPath= "C:\Program Files\Xenon\agent.exe" start= auto
sc start XenonAgent
sc query XenonAgent
sc stop XenonAgent
sc delete XenonAgent

(The space after each = is required by sc.) Installers usually call CreateServiceW instead. A service runs as an account: LocalSystem (all-powerful: avoid), LocalService or NetworkService (limited), or a dedicated account. Choose the least powerful one that works.

Life in session 0

Services run in session 0, separate from users' desktops, so a service cannot show windows or message boxes. Log to the Windows event log or a file, and talk to a user-side program through a named pipe or a socket (the Processes and Communication course), checking who is connecting. During development, give the program a "console mode" switch that runs the same work in a normal console, so you can debug it without installing it.
