Access Tokens and Privileges

lesson 7.055 of 6 in milestone 75 min1 practice task

How Windows knows who a program runs as - the access token of your own process, reading the user's SID, groups, elevation and integrity level with GetTokenInformation, SIDs as strings, privileges and why AdjustTokenPrivileges can succeed without granting anything, and asking for elevation through a manifest.

Every process has a token

When a user signs in, Windows creates an access token describing them: their user SID (security identifier), the groups they belong to, their privileges, and their integrity level. Every process they start gets a copy. Whenever a process opens a file, a registry key or another process, Windows compares its token with the object's security descriptor.

This lesson reads the token of your own process, which is what programs need to decide, for example, whether to offer an "install for all users" option.

Reading your token

C++
HANDLE token{};
if (!OpenProcessToken(GetCurrentProcess(), TOKEN_QUERY, &token)) return GetLastError();

TOKEN_ELEVATION elevation{};
DWORD length{ 0 };
GetTokenInformation(token, TokenElevation, &elevation, sizeof elevation, &length);
bool elevated{ elevation.TokenIsElevated != 0 };

Variable-sized information (the user, the groups, the integrity level) uses the "ask for the size first" pattern of the Reading Documentation course:

C++
DWORD needed{ 0 };
GetTokenInformation(token, TokenUser, nullptr, 0, &needed);          // fails with ERROR_INSUFFICIENT_BUFFER
std::vector<std::byte> buffer(needed);
if (GetTokenInformation(token, TokenUser, buffer.data(), needed, &needed))
{
    auto* user{ reinterpret_cast<TOKEN_USER*>(buffer.data()) };
    LPWSTR text{};
    if (ConvertSidToStringSidW(user->User.Sid, &text))
    {
        std::wcout << text << L'\n';                                  // S-1-5-21-...-1001
        LocalFree(text);                                              // the API allocated it
    }
}
CloseHandle(token);

SIDs

A SID identifies a user, group or computer. In binary it is a revision (1), a count of sub-authorities, a 6-byte identifier authority (big-endian), and that many 32-bit sub-authorities (little-endian). Written as text: S-1-5-21-3623811015-3361044348-30300820-1013, meaning revision 1, authority 5 (NT), then the sub-authorities. Some are well known: S-1-5-18 is LocalSystem, S-1-5-32-544 is the Administrators group, S-1-1-0 is Everyone. Practice 7.05 converts between the two forms.

Integrity levels and UAC

The token's integrity level is a SID whose last sub-authority gives the level: 0x1000 low (sandboxed processes), 0x2000 medium (normal programs), 0x3000 high (elevated), 0x4000 system. A lower-integrity process cannot write to higher-integrity objects or send certain messages to their windows.

With UAC, even an administrator normally runs at medium integrity with a filtered token; elevation ("Run as administrator", a consent prompt) starts a new process with the full token at high integrity. A program that always needs it declares so in its manifest:

xml
<requestedExecutionLevel level="requireAdministrator" uiAccess="false"/>

Most programs should use asInvoker and elevate only a small helper for the few operations that need it (ShellExecuteExW with the verb runas), following the principle of least privilege.

Privileges

Privileges are rights that are not about a specific object: shutting down the system (SeShutdownPrivilege), changing the system time, debugging programs, backing up files. A token lists the privileges it has, each enabled or disabled; most are disabled until a program enables the one it needs, just before using it:

C++
TOKEN_PRIVILEGES tp{ 1 };
LookupPrivilegeValueW(nullptr, SE_SHUTDOWN_NAME, &tp.Privileges[0].Luid);
tp.Privileges[0].Attributes = SE_PRIVILEGE_ENABLED;
AdjustTokenPrivileges(token, FALSE, &tp, 0, nullptr, nullptr);      // token opened with TOKEN_ADJUST_PRIVILEGES
if (GetLastError() == ERROR_NOT_ALL_ASSIGNED) { /* the token does not have this privilege at all */ }

AdjustTokenPrivileges is a famous documentation trap: it returns success even when it could not enable the privilege, because the token never had it. The only way to know is to check GetLastError() for ERROR_NOT_ALL_ASSIGNED (1300) afterwards, even on success.
