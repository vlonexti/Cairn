The Registry and Settings

lesson 5.022 of 5 in milestone 55 min1 practice task

The registry is Windows' hierarchical settings database. This lesson explains its structure, the per-user and per-machine hives, reading and writing values with RegGetValueW and RegSetValueExW, value types, and when a settings file in AppData is the better choice.

Keys, values and hives

The registry is a tree. Keys are like folders and contain subkeys and values; each value has a name, a type and data. The roots are hives:

Root Holds Writable by a normal program
HKEY_CURRENT_USER (HKCU) The current user's settings Yes
HKEY_LOCAL_MACHINE (HKLM) Settings for all users, installed programs, drivers No (needs administrator)
HKEY_CLASSES_ROOT File associations and COM classes (a merged view of HKCU and HKLM) Through HKCU

A program's own settings go under HKEY_CURRENT_USER\Software\<Company>\<Program>. Writing to HKLM from a normal program fails with "access denied", which is how it should be: the installer (lesson 6.02) writes machine-wide keys once, with administrator rights.

Value types

Type Holds
REG_SZ A string (UTF-16, null-terminated)
REG_EXPAND_SZ A string with %VARIABLES% to expand
REG_MULTI_SZ A list of strings, each null-terminated, with an extra null at the end
REG_DWORD A 32-bit number
REG_QWORD A 64-bit number
REG_BINARY Raw bytes

Reading

RegGetValueW reads a value in one call, checks its type, and guarantees string termination:

C++
DWORD readDword(const wchar_t* name, DWORD fallback)
{
    DWORD value = 0, size = sizeof(value);
    const LSTATUS st = RegGetValueW(HKEY_CURRENT_USER, L"Software\\Xenon\\Notes", name,
                                    RRF_RT_REG_DWORD, nullptr, &value, &size);
    return st == ERROR_SUCCESS ? value : fallback;
}

std::wstring readString(const wchar_t* name, const std::wstring& fallback)
{
    DWORD bytes = 0;
    if (RegGetValueW(HKEY_CURRENT_USER, L"Software\\Xenon\\Notes", name, RRF_RT_REG_SZ, nullptr, nullptr, &bytes) != ERROR_SUCCESS)
        return fallback;
    std::wstring s(bytes / sizeof(wchar_t), L'\0');
    if (RegGetValueW(HKEY_CURRENT_USER, L"Software\\Xenon\\Notes", name, RRF_RT_REG_SZ, nullptr, s.data(), &bytes) != ERROR_SUCCESS)
        return fallback;
    s.resize(bytes / sizeof(wchar_t) - 1);       // drop the terminating null
    return s;
}

Registry functions return the error code directly (an LSTATUS) instead of setting GetLastError. A missing value (ERROR_FILE_NOT_FOUND) is normal on first run: use the default, exactly like lesson 6.01's settings file in the raylib course.

Writing

C++
HKEY key;
if (RegCreateKeyExW(HKEY_CURRENT_USER, L"Software\\Xenon\\Notes", 0, nullptr, 0, KEY_SET_VALUE, nullptr, &key, nullptr) == ERROR_SUCCESS)
{
    const DWORD wrap = 1;
    RegSetValueExW(key, L"WordWrap", 0, REG_DWORD, reinterpret_cast<const BYTE*>(&wrap), sizeof(wrap));
    const std::wstring font = L"Cascadia Mono";
    RegSetValueExW(key, L"Font", 0, REG_SZ, reinterpret_cast<const BYTE*>(font.c_str()),
                   static_cast<DWORD>((font.size() + 1) * sizeof(wchar_t)));      // size in BYTES, including the null
    RegCloseKey(key);
}

The size of a REG_SZ is in bytes and includes the terminating null: passing the character count is the most common registry bug, and stores half the string.

Registry or file?

Registry Settings file in AppData
Built in, typed values, atomic per value Easy to back up, copy, diff and edit
Needed for file associations, autostart, COM Works the same on every platform
Awkward for large or structured data Any structure (JSON, TOML, INI)
Left behind if uninstall forgets it Deleting the folder removes everything

A good rule: use the registry for what Windows itself reads (file associations, "open with", uninstall information, autostart under ...\CurrentVersion\Run), and a file in %APPDATA% for your program's own preferences.

Watching settings

RegNotifyChangeKeyValue signals an event when a key changes, which is how a program notices that the user switched the system to dark mode: the setting AppsUseLightTheme under HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize changes, and top-level windows also receive WM_SETTINGCHANGE.
