Common Dialogs

lesson 3.022 of 5 in milestone 35 min1 practice task

Windows provides the Open, Save, folder, colour and font dialogs every program needs. This lesson uses the modern IFileOpenDialog and IFileSaveDialog through COM, with file type filters, default extensions and folders, and the older colour and font dialogs.

COM in five minutes

The modern file dialogs are COM objects. COM is Windows' system for objects shared between components: you create an object by its class id, get an interface (a table of virtual functions), call methods that return HRESULTs (lesson 1.01), and Release() the interface when done.

C++
#include <shobjidl.h>        // IFileOpenDialog
#include <wrl/client.h>      // Microsoft::WRL::ComPtr: a smart pointer that calls Release
using Microsoft::WRL::ComPtr;

// once per thread that uses COM, at start-up; CoUninitialize at the end
CoInitializeEx(nullptr, COINIT_APARTMENTTHREADED | COINIT_DISABLE_OLE1DDE);

ComPtr is to COM what std::unique_ptr is to new: it releases the object automatically. The UI thread must use the apartment-threaded model (STA) for dialogs.

Open

C++
std::optional<std::wstring> askOpenFile(HWND owner)
{
    ComPtr<IFileOpenDialog> dialog;
    if (FAILED(CoCreateInstance(CLSID_FileOpenDialog, nullptr, CLSCTX_INPROC_SERVER, IID_PPV_ARGS(&dialog)))) return {};

    const COMDLG_FILTERSPEC types[] = {
        { L"Text documents", L"*.txt;*.md" },
        { L"All files", L"*.*" },
    };
    dialog->SetFileTypes(ARRAYSIZE(types), types);
    dialog->SetFileTypeIndex(1);                         // 1-based
    dialog->SetTitle(L"Open a note");

    if (FAILED(dialog->Show(owner))) return {};         // also when the user cancels: HRESULT_FROM_WIN32(ERROR_CANCELLED)
    ComPtr<IShellItem> item;
    if (FAILED(dialog->GetResult(&item))) return {};
    PWSTR path = nullptr;
    if (FAILED(item->GetDisplayName(SIGDN_FILESYSPATH, &path))) return {};
    std::wstring result{ path };
    CoTaskMemFree(path);                                 // memory allocated by COM is freed with CoTaskMemFree
    return result;
}

IID_PPV_ARGS(&dialog) passes both the interface's id and the pointer to fill, so they cannot mismatch. Cancelling is reported as a failed HRESULT with the code ERROR_CANCELLED (1223), which is not an error to show the user.

Options set with SetOptions(FOS_...): FOS_ALLOWMULTISELECT (then use GetResults), FOS_PICKFOLDERS (a folder picker), FOS_FILEMUSTEXIST.

Save

IFileSaveDialog works the same way, with a few extras:

C++
dialog->SetFileName(L"Untitled.txt");                 // suggested name
dialog->SetDefaultExtension(L"txt");                  // added if the user types a name without one
dialog->SetOptions(options | FOS_OVERWRITEPROMPT);    // "Replace existing file?" (on by default)

The default extension follows the selected file type when it changes. The practice computes exactly what file name the user ends up with.

The older filter string

Older code uses GetOpenFileNameW with an OPENFILENAMEW structure. Its filter is a single string of pairs separated by null characters, ended by two nulls:

C++
const wchar_t* filter = L"Text documents (*.txt)\0*.txt\0All files (*.*)\0*.*\0";   // the literal adds the last \0

Building that string from a list, getting the embedded nulls right, is a classic bug source; the practice builds it.

Colour and font

C++
static COLORREF custom[16];                         // the dialog's 16 custom colours, kept between calls
CHOOSECOLORW cc{ sizeof(cc) };
cc.hwndOwner = owner;
cc.rgbResult = m_colour;
cc.lpCustColors = custom;
cc.Flags = CC_FULLOPEN | CC_RGBINIT;
if (ChooseColorW(&cc)) m_colour = cc.rgbResult;

LOGFONTW lf = m_logFont;
CHOOSEFONTW cf{ sizeof(cf) };
cf.hwndOwner = owner;
cf.lpLogFont = &lf;
cf.Flags = CF_SCREENFONTS | CF_INITTOLOGFONTSTRUCT;
if (ChooseFontW(&cf)) { m_logFont = lf; recreateFont(); }

Remembering the folder

Users expect the Open dialog to start in the folder they used last. The new dialogs remember it per program automatically; SetFolder sets it explicitly (from an IShellItem made with SHCreateItemFromParsingName), and SetClientGuid keeps separate memories for different dialogs in one program ("open image" and "open project").
