The text view: two options

Option 1, the EDIT control. A multi-line EDIT (ES_MULTILINE | ES_AUTOVSCROLL | WS_VSCROLL, plus ES_AUTOHSCROLL | WS_HSCROLL when word wrap is off) gives you editing, selection, the caret, clipboard and a single undo level for free. Raise its text limit (EM_SETLIMITTEXT) above the default 30 000 characters. Word wrap is switched by re-creating the control with or without ES_AUTOHSCROLL, moving the text across. Line and column come from EM_LINEFROMCHAR and EM_LINEINDEX. This is how Notepad was built for decades.

Option 2, your own view. A Direct2D window with DirectWrite layouts (lesson 4.03) and your own document model: multi-level undo, syntax colouring, very large files. The project at the end of this milestone writes that model: the text, edits, undo and redo with typing grouped into words, line and column, find and replace.

Start with option 1; the model can replace it later without changing the rest of the program.

Encodings and line endings

A text editor must save a file the way it found it. Opening a file:

  1. Read the bytes.
  2. Detect the encoding: a BOM (byte order mark) EF BB BF means UTF-8, FF FE UTF-16 little-endian, FE FF UTF-16 big-endian. Without a BOM, check whether the bytes are valid UTF-8 (lesson 1.02's decoder without replacements); if not, assume the legacy code page (CP_ACP).
  3. Convert to the internal form (UTF-16 for the EDIT control, or UTF-8 for your own model).
  4. Detect the line endings: CRLF, LF or CR. If a file mixes them, use the most common one.

Remember both, show them in the status bar, and use them when saving: a Unix file with LF endings stays LF, and a UTF-8 file without a BOM stays without one. The practice writes this detection and conversion.

Dirty state and closing

Track whether the document differs from what is on disk (an EN_CHANGE notification sets the flag; saving clears it), and show it in the title. Every path that discards the document goes through one function:

C++
bool confirmDiscard()          // true if it is OK to continue
{
    if (!m_dirty) return true;
    const int answer = MessageBoxW(m_hwnd, (L"Save changes to " + displayName() + L"?").c_str(), L"Xenon Notes",
                                   MB_YESNOCANCEL | MB_ICONWARNING);
    if (answer == IDCANCEL) return false;
    if (answer == IDYES) return save();      // false if the save failed or was cancelled
    return true;
}

New, Open, opening a recent file, dropping a file, and WM_CLOSE all call it first. Windows also sends WM_QUERYENDSESSION when the user signs out: answer it the same way.

Find and Replace

Use modeless dialogs (lesson 3.01) so the user can keep editing. Search from the caret, wrapping around at the end, with "Match case"; Replace All should be one undo step. Keep the last search text so F3 (Find Next) works after the dialog is closed.

Order to build in

  1. Window, menu and an EDIT control that fills the client area, with the message font.
  2. Open and Save As with file dialogs; reading and writing UTF-8.
  3. Dirty flag, title, confirmDiscard everywhere.
  4. Encoding and line-ending detection, kept when saving; status bar.
  5. Find, Find Next, Replace, Go To Line.
  6. Word wrap, font selection, zoom; settings saved.
  7. Recent files, drag and drop, command-line file argument, high DPI.
