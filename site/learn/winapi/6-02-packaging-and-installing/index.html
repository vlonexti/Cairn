Packaging and Installing

lesson 6.022 of 3 in milestone 65 min1 practice task

Getting a Windows program onto other people's computers - the application manifest, version information, icons, static or dynamic runtime, per-user installs without administrator rights, MSIX and installers, code signing and SmartScreen, and updates.

The application manifest

The manifest is an XML file embedded in the .exe that tells Windows how to treat the program. Several earlier lessons asked for one; here it is in one place:

C++
<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
<assembly xmlns="urn:schemas-microsoft-com:asm.v1" manifestVersion="1.0">
  <assemblyIdentity type="win32" name="Xenon.Notes" version="1.2.0.0"/>
  <dependency><dependentAssembly>                                          <!-- lesson 3.05: visual styles -->
    <assemblyIdentity type="win32" name="Microsoft.Windows.Common-Controls" version="6.0.0.0"
                      processorArchitecture="*" publicKeyToken="6595b64144ccf1df" language="*"/>
  </dependentAssembly></dependency>
  <trustInfo xmlns="urn:schemas-microsoft-com:asm.v3"><security><requestedPrivileges>
    <requestedExecutionLevel level="asInvoker" uiAccess="false"/>          <!-- no administrator prompt -->
  </requestedPrivileges></security></trustInfo>
  <application xmlns="urn:schemas-microsoft-com:asm.v3"><windowsSettings>
    <dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">PerMonitorV2</dpiAwareness>   <!-- 3.04 -->
    <longPathAware xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">true</longPathAware>         <!-- 5.01 -->
    <activeCodePage xmlns="http://schemas.microsoft.com/SMI/2019/WindowsSettings">UTF-8</activeCodePage>      <!-- 1.02 -->
  </windowsSettings></application>
</assembly>

Add it in Visual Studio under Manifest Tool > Input and Output > Additional Manifest Files. asInvoker is right for almost every program: requesting requireAdministrator makes every start show a UAC prompt, which users rightly distrust.

Version information and icon

A VERSIONINFO resource (lesson 2.04) puts the version, product name, company and copyright in the file's Properties dialog. The version is four 16-bit numbers, major.minor.patch.build, stored as two 32-bit values (FILEVERSION 1,2,0,0). The practice packs, unpacks and compares them, which is also what an update check does.

The icon resource with the lowest id becomes the .exe's icon in Explorer; include all sizes (lesson 3.04).

Runtime and dependencies

  • Link the C runtime statically (/MT) to avoid requiring the Visual C++ Redistributable, or install the redistributable with your installer if you link dynamically (/MD).
  • Ship any DLLs you use next to the .exe (the DLL course explains the search order).
  • Test on a clean Windows virtual machine or Windows Sandbox: the only reliable way to find a missing dependency.

Installing per user

A program does not need administrator rights to be installed. A per-user install puts it in %LOCALAPPDATA%\Programs\<Name> and writes only to HKEY_CURRENT_USER:

What Where
Program files %LOCALAPPDATA%\Programs\XenonNotes\
Start menu shortcut %APPDATA%\Microsoft\Windows\Start Menu\Programs\
File associations HKCU\Software\Classes (lesson 5.05)
Entry in Settings > Apps HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\XenonNotes with DisplayName, DisplayVersion, Publisher, UninstallString

Per-machine installs into Program Files need administrator rights once, during installation.

Installer options

Tool Notes
MSIX Windows' modern package format: clean install and uninstall, automatic updates, required for the Microsoft Store; must be signed
WiX Toolset Builds MSI installers from XML; the standard for enterprise deployment
Inno Setup, NSIS Script-based .exe installers, simple and popular for small programs
A zip For tools that need no installation at all ("portable")

Whatever you use, uninstalling must remove everything the installer added, and nothing the user created.

Code signing and SmartScreen

An unsigned downloaded .exe shows SmartScreen's "Windows protected your PC" warning. Signing with a code-signing certificate (signtool sign /fd SHA256 /tr <timestamp server> /td SHA256 app.exe) identifies you as the publisher; the warning disappears as the signature builds reputation. Always add a timestamp so the signature stays valid after the certificate expires. Microsoft's Trusted Signing service and the Microsoft Store are alternatives to buying a certificate.

Updates

The simplest update check downloads a small file with the latest version number (over HTTPS, with WinHTTP or URLDownloadToFileW), compares it with the running version, and offers a download page. Never run downloaded code without verifying its signature. MSIX and the Store handle updates themselves.
