Dialog Boxes

lesson 3.011 of 5 in milestone 35 min1 practice task

Dialogs are windows built from a template, with keyboard navigation and default buttons for free. This lesson creates modal and modeless dialogs, writes the dialog procedure, moves data in and out of the controls, validates input, and returns a result.

What a dialog gives you

A dialog box is a window whose controls are described by a template in the resource file, created and laid out by Windows. Compared with creating controls by hand (lesson 2.05) it adds, for free:

  • Tab and arrow navigation, mnemonics, Enter for the default button and Esc for Cancel;
  • layout in dialog units, which scale with the dialog's font (so the dialog grows with the user's text size);
  • IDOK and IDCANCEL handling, and the focus going to the first control.

The template

C++
IDD_RENAME DIALOGEX 0, 0, 220, 70
STYLE DS_MODALFRAME | DS_SHELLFONT | WS_POPUP | WS_CAPTION | WS_SYSMENU
CAPTION "Rename"
FONT 9, "Segoe UI"
BEGIN
    LTEXT        "&New name:", IDC_STATIC, 7, 9, 50, 8
    EDITTEXT     IDC_NAME, 60, 7, 153, 14, ES_AUTOHSCROLL
    AUTOCHECKBOX "&Keep the extension", IDC_KEEPEXT, 60, 26, 120, 10
    DEFPUSHBUTTON "OK", IDOK, 109, 49, 50, 14
    PUSHBUTTON   "Cancel", IDCANCEL, 163, 49, 50, 14
END

Positions and sizes are in dialog units: horizontally a quarter of the font's average character width, vertically an eighth of its height. Visual Studio's dialog editor writes this for you. The label comes just before its edit box in the template so its mnemonic (Alt+N) moves the focus to the edit box.

Modal dialogs

A modal dialog disables its owner and runs its own message loop until it is closed; DialogBoxParamW returns only then:

C++
struct RenameData { std::wstring name; bool keepExtension{ true }; };

INT_PTR CALLBACK RenameProc(HWND dlg, UINT msg, WPARAM wParam, LPARAM lParam)
{
    auto* data = reinterpret_cast<RenameData*>(GetWindowLongPtrW(dlg, DWLP_USER));
    switch (msg)
    {
    case WM_INITDIALOG:                                  // data in: fill the controls
        data = reinterpret_cast<RenameData*>(lParam);
        SetWindowLongPtrW(dlg, DWLP_USER, lParam);
        SetDlgItemTextW(dlg, IDC_NAME, data->name.c_str());
        CheckDlgButton(dlg, IDC_KEEPEXT, data->keepExtension ? BST_CHECKED : BST_UNCHECKED);
        return TRUE;                                     // TRUE: set the focus to the first control
    case WM_COMMAND:
        switch (LOWORD(wParam))
        {
        case IDOK:                                       // data out: read and validate
        {
            const std::wstring name = getText(dlg, IDC_NAME);
            if (!validFileName(name))
            {
                MessageBoxW(dlg, L"A name cannot contain \\ / : * ? \" < > |", L"Rename", MB_ICONWARNING);
                SetFocus(GetDlgItem(dlg, IDC_NAME));
                return TRUE;                             // stay open
            }
            data->name = name;
            data->keepExtension = IsDlgButtonChecked(dlg, IDC_KEEPEXT) == BST_CHECKED;
            EndDialog(dlg, IDOK);
            return TRUE;
        }
        case IDCANCEL: EndDialog(dlg, IDCANCEL); return TRUE;    // also Esc and the close button
        }
        break;
    }
    return FALSE;                                        // not handled: the dialog manager does the default
}

RenameData data{ L"notes.txt" };
if (DialogBoxParamW(instance, MAKEINTRESOURCEW(IDD_RENAME), owner, RenameProc, reinterpret_cast<LPARAM>(&data)) == IDOK)
    rename(data);

Note the differences from a window procedure: it returns TRUE or FALSE ("handled or not"), never calls DefWindowProcW, and ends with EndDialog, never DestroyWindow. The last parameter of DialogBoxParamW carries a pointer to the dialog's data, which arrives as lParam in WM_INITDIALOG.

The data pattern

A dialog is easiest to get right when it works on a plain struct: the caller fills it, WM_INITDIALOG copies it into the controls, IDOK validates and copies it back, and Cancel leaves it untouched. All the rules about valid values can then be written and tested as a normal function on the struct, as in the practice.

Good validation tells the user what is wrong and puts the focus on the field, or better, disables OK while the input is invalid (check on EN_CHANGE) and shows why next to the field.

Modeless dialogs

A modeless dialog (a Find window, a tool palette) stays open while the user keeps working in the main window. Create it with CreateDialogParamW, show it, and let the main message loop pass its messages through IsDialogMessageW so its keyboard navigation works:

C++
if (!(g_findDialog && IsDialogMessageW(g_findDialog, &msg))) { TranslateMessage(&msg); DispatchMessageW(&msg); }

Close a modeless dialog with DestroyWindow, not EndDialog, and set g_findDialog back to null in its WM_DESTROY.

Message boxes and task dialogs

For simple questions, MessageBoxW(owner, text, title, MB_YESNOCANCEL | MB_ICONQUESTION) returns IDYES, IDNO or IDCANCEL. TaskDialogIndirect is its modern replacement, with a main instruction, explanatory text, command links, a check box ("Don't ask again") and a progress bar. Always pass the owner window, so the box is modal to it and appears in front of it.
