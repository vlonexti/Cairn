Keyboard Input

lesson 2.011 of 5 in milestone 25 min1 practice task

Keys arrive as WM_KEYDOWN and WM_KEYUP with virtual-key codes, text arrives as WM_CHAR after TranslateMessage. This lesson explains the difference, the information packed into lParam, auto-repeat, modifier keys, system keys and keyboard focus.

Keys and characters

Pressing Shift+A produces several messages:

Message Means wParam
WM_KEYDOWN Shift went down VK_SHIFT
WM_KEYDOWN A went down 'A' (the virtual key)
WM_CHAR The character "A" was typed L'A' (a UTF-16 unit)
WM_KEYUP A went up 'A'
WM_KEYUP Shift went up VK_SHIFT

Key messages tell you which physical key moved, as a virtual-key code: 'A' to 'Z', '0' to '9', VK_LEFT, VK_RETURN, VK_F5, VK_CONTROL and so on. They are for commands: arrows to move, Delete to delete, F5 to refresh.

Character messages tell you which text the user typed, after the keyboard layout, Shift, Caps Lock and dead keys (é from ´ then e) are applied. They are for text input. TranslateMessage in the message loop makes them; leave it out and no WM_CHAR ever arrives. Characters above U+FFFF arrive as two WM_CHAR messages, one per surrogate (lesson 1.02).

Never build text from WM_KEYDOWN: it knows nothing about layouts, so a French or German user gets the wrong letters.

What lParam holds

For key messages, lParam packs details of the keystroke:

Bits Meaning
0 - 15 Repeat count (auto-repeat may combine several)
16 - 23 Scan code (the physical key's hardware code)
24 Extended key (right Ctrl, right Alt, arrow keys of the separate block, Insert/Delete ...)
29 Context code: Alt was down (for WM_SYSKEYDOWN)
30 Previous key state: 1 if the key was already down (this is an auto-repeat)
31 Transition state: 0 for down, 1 for up

Bit 30 is the useful one: holding a key sends WM_KEYDOWN again and again, and bit 30 tells a first press apart from repeats. A game-style "jump once per press" checks it. The practice decodes all the fields.

Modifier keys

To know whether Ctrl or Shift is held when a key arrives, ask:

C++
const bool ctrl = GetKeyState(VK_CONTROL) < 0;      // high bit set = down
const bool shift = GetKeyState(VK_SHIFT) < 0;

GetKeyState gives the state as of the message being processed, which is what you want inside a window procedure. GetAsyncKeyState gives the state right now, which may differ if the program is behind; it is for polling, not for handling messages. Left and right versions exist (VK_LSHIFT, VK_RSHIFT) when it matters.

System keys

Keys pressed with Alt held, and F10, arrive as WM_SYSKEYDOWN / WM_SYSKEYUP / WM_SYSCHAR instead. DefWindowProcW uses them for the menu (Alt opens it, Alt+F opens File) and for Alt+F4. If you handle Alt combinations yourself, still pass the messages you do not use to DefWindowProcW, or Alt+F4 stops working.

Focus

Keyboard messages go to the window with the keyboard focus: one window in the system at a time. Clicking a control gives it the focus; SetFocus(hwnd) moves it in code. A window learns it gained or lost focus through WM_SETFOCUS and WM_KILLFOCUS: a text editor creates its caret (CreateCaret, ShowCaret) on the first and destroys it on the second.

When a top-level window is reactivated, it should give the focus back to the control that had it, which dialogs do automatically (lesson 3.01).
