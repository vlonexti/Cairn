Files and Directories

lesson 5.011 of 5 in milestone 55 min1 practice task

Reading and writing files with CreateFileW, sharing modes and why "the file is in use", listing directories with FindFirstFileW, Windows paths and their traps (drive letters, UNC, long paths, reserved names), known folders, and watching a folder for changes.

CreateFileW

CreateFileW opens (or creates) files, and also pipes, devices and directories:

C++
HANDLE h = CreateFileW(L"C:\\Notes\\today.txt",
                       GENERIC_READ,                 // what we want to do
                       FILE_SHARE_READ,              // what others may do while we have it open
                       nullptr,
                       OPEN_EXISTING,                // what to do if it exists / does not exist
                       FILE_ATTRIBUTE_NORMAL, nullptr);
if (h == INVALID_HANDLE_VALUE) { /* GetLastError: 2 not found, 5 access denied, 32 in use */ }

LARGE_INTEGER size;
GetFileSizeEx(h, &size);
std::string data(static_cast<size_t>(size.QuadPart), '\0');
DWORD read = 0;
ReadFile(h, data.data(), static_cast<DWORD>(data.size()), &read, nullptr);
CloseHandle(h);
Creation If the file exists If not
CREATE_NEW Fails (80) Creates
CREATE_ALWAYS Truncates to empty Creates
OPEN_EXISTING Opens Fails (2)
OPEN_ALWAYS Opens Creates
TRUNCATE_EXISTING Truncates Fails

For ordinary reading and writing, std::ifstream, std::ofstream and std::filesystem work fine on Windows (with std::filesystem::path holding wide strings). CreateFileW is for the cases they do not cover: share modes, overlapped (asynchronous) I/O, file attributes, and opening directories.

Sharing and "the file is in use"

The share mode says what other programs may do with the file while you have it open. Windows enforces it: if you open a file without FILE_SHARE_WRITE, nobody else can open it for writing, and they get error 32, ERROR_SHARING_VIOLATION. That is the "file is open in another program" message. An editor that keeps files open blocks other programs; good editors read the file and close it straight away.

Antivirus scanners and backup tools often open files briefly, so a save that fails with a sharing violation should be retried a few times with a short delay before giving up.

Saving safely

The pattern from the raylib course's saves applies here, with Windows functions: write to a temporary file in the same folder, then ReplaceFileW (which also keeps the original's attributes and permissions) or MoveFileExW(temp, target, MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH).

Listing a directory

C++
WIN32_FIND_DATAW fd;
HANDLE find = FindFirstFileExW(L"C:\\Notes\\*", FindExInfoBasic, &fd, FindExSearchNameMatch, nullptr, FIND_FIRST_EX_LARGE_FETCH);
if (find != INVALID_HANDLE_VALUE)
{
    do
    {
        if (wcscmp(fd.cFileName, L".") == 0 || wcscmp(fd.cFileName, L"..") == 0) continue;
        const bool isDir = fd.dwFileAttributes & FILE_ATTRIBUTE_DIRECTORY;
        const ULONGLONG size = (ULONGLONG(fd.nFileSizeHigh) << 32) | fd.nFileSizeLow;
        // ...
    } while (FindNextFileW(find, &fd));
    FindClose(find);                 // not CloseHandle
}

Every directory lists . and .., which must be skipped or a recursive search loops forever. Also skip directories with FILE_ATTRIBUTE_REPARSE_POINT when recursing: junctions and symbolic links can point back up the tree.

Paths

Windows paths have more forms than people expect:

Form Example
Drive absolute C:\Users\Sam\notes.txt
Drive relative (current directory of that drive) C:notes.txt
Root relative (current drive) \Users\Sam
Relative ..\notes.txt
UNC (network) \\server\share\folder\file.txt
Long-path prefix \\?\C:\very\long\path...

Both \ and / work as separators in most APIs; . and .. are resolved by the system. Names are case-insensitive (but case-preserving). The classic MAX_PATH limit is 260 characters; longer paths need the \\?\ prefix or the longPathAware manifest setting. The reserved names CON, NUL, COM1 and so on (practice 3.01) cannot be used as file names in any folder.

Combining and normalising paths correctly (joining with exactly one separator, resolving .. without going above the root, keeping UNC roots intact) is the practice.

Known folders

Never hard-code C:\Users\... or Documents: the folder can be redirected, renamed in another language, or on another drive. Ask the system:

C++
PWSTR path = nullptr;
if (SUCCEEDED(SHGetKnownFolderPath(FOLDERID_RoamingAppData, 0, nullptr, &path)))
{
    std::filesystem::path settings = std::filesystem::path(path) / L"Xenon";
    CoTaskMemFree(path);
}

FOLDERID_RoamingAppData (settings), FOLDERID_LocalAppData (caches, large data), FOLDERID_Documents (the user's documents), FOLDERID_Downloads.

Watching for changes

An editor should notice when the open file changes on disk; a file list should refresh when files are added. ReadDirectoryChangesW reports each change (added, removed, modified, renamed) in a folder, optionally with its subfolders. Use it on a worker thread or with overlapped I/O, and expect bursts: one save in another editor can produce several notifications, so wait a moment and re-check rather than reloading on every one.
