Layout and Resizing

lesson 3.033 of 5 in milestone 35 min1 practice task

Win32 has no layout engine - when a window is resized, you move its controls. This lesson lays controls out in WM_SIZE with anchors, sets a minimum size with WM_GETMINMAXINFO, moves many controls at once without flicker, and builds a splitter.

WM_SIZE

When the user resizes a window, it receives WM_SIZE with the new client size. Positioning the controls is up to you:

C++
case WM_SIZE:
{
    const int w = LOWORD(lParam), h = HIWORD(lParam);
    const int pad = 10, buttonW = 80, buttonH = 26;
    MoveWindow(m_list, pad, pad, w - 2 * pad, h - 3 * pad - buttonH, TRUE);
    MoveWindow(m_ok, w - pad - 2 * buttonW - pad, h - pad - buttonH, buttonW, buttonH, TRUE);
    MoveWindow(m_cancel, w - pad - buttonW, h - pad - buttonH, buttonW, buttonH, TRUE);
    return 0;
}

Writing that maths for every control gets messy. Most layouts are described better with anchors.

Anchors

Each control remembers its distances from the edges of the parent at the original size, and which edges it is anchored to:

Anchored to When the window grows by dx
Left only Stays where it is
Right only Moves right by dx
Left and right Stretches by dx
Neither Stays centred in the same relative position

The same on the vertical axis with top and bottom. A list that fills the window is anchored on all four sides; OK and Cancel at the bottom right are anchored right and bottom; a search box along the top is anchored left, right and top. The practice builds this layout engine.

A minimum size

Below some size the layout breaks: controls overlap or get negative widths. Tell Windows the minimum window size (frame included) in WM_GETMINMAXINFO:

C++
case WM_GETMINMAXINFO:
{
    auto* mmi = reinterpret_cast<MINMAXINFO*>(lParam);
    mmi->ptMinTrackSize.x = m_minWindowSize.cx;    // computed once with AdjustWindowRectExForDpi
    mmi->ptMinTrackSize.y = m_minWindowSize.cy;
    return 0;
}

Moving many controls

Moving twenty controls one by one repaints twenty times and flickers. Deferred window positioning moves them all in one step:

C++
HDWP batch = BeginDeferWindowPos(static_cast<int>(m_controls.size()));
for (const auto& c : m_controls)
{
    const RECT r = c.layout(width, height);
    batch = DeferWindowPos(batch, c.hwnd, nullptr, r.left, r.top, r.right - r.left, r.bottom - r.top,
                           SWP_NOZORDER | SWP_NOACTIVATE);
}
EndDeferWindowPos(batch);

Setting WS_CLIPCHILDREN on the parent stops it from painting its background over the children, the other big source of flicker on resizing.

Splitters

A splitter is the bar between two panes that the user drags to change their sizes. It is not a control: it is a strip of the parent's client area between the two child windows.

  1. In WM_SETCURSOR, show IDC_SIZEWE when the mouse is over the strip (lesson 2.02).
  2. On WM_LBUTTONDOWN over it, capture the mouse and remember the offset between the mouse and the split position.
  3. On WM_MOUSEMOVE while captured, set the split position, clamped so neither pane gets smaller than its minimum, and lay out again.
  4. On WM_LBUTTONUP, release the capture, and save the position in the settings (lesson 5.02).

Storing the split as a fraction of the width rather than pixels keeps it sensible when the window is resized or moved to a monitor with a different DPI.

Keeping the layout in one function

Put all layout in one function, layout(width, height), and call it from WM_SIZE, after the splitter moves, after a font change and after a DPI change (lesson 3.04). When the layout is computed in exactly one place, it cannot disagree with itself.
