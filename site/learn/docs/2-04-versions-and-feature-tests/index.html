Versions and Feature Tests

lesson 2.044 of 4 in milestone 25 min1 practice task

Making sure what you read applies to what you compile - version markers on reference pages, choosing the language standard with /std and -std, compiler support tables, __cplusplus and _MSVC_LANG, feature-test macros from the version header, deprecated and removed features, and reading the std::format specification as an example of a C++20 feature.

Is it in my version?

C++ gets a new standard every three years: C++11, 14, 17, 20, 23, 26. Reference pages mark what belongs to which:

  • (since C++17) next to an overload or member: only available from that version.
  • (until C++20) or (removed in C++20): gone from that version on.
  • (deprecated in C++17): still works, may be removed later; compilers warn.

Before you rely on something, check the marker against the standard you compile with:

Compiler Option Example
MSVC /std:c++17, /std:c++20, /std:c++latest Visual Studio: Project Properties > C/C++ > Language
GCC, Clang -std=c++17, -std=c++20, -std=c++2b

Supported by my compiler?

A feature being in the standard does not mean your compiler has it yet. cppreference's "Compiler support" pages list each feature and the first version of GCC, Clang and MSVC that implements it. std::format is C++20 but arrived in GCC 13 only; std::print is C++23 and needs recent compilers.

Checking in code

The macro __cplusplus holds the standard version (202002L for C++20). MSVC leaves it at 199711L unless you add /Zc:__cplusplus, and gives the real value in _MSVC_LANG. More precise are feature-test macros, defined by including <version>:

C++
#include <iostream>
#include <version>

int main()
{
#ifdef __cpp_lib_format
    std::cout << "std::format available, version " << __cpp_lib_format << '\n';
#else
    std::cout << "no std::format\n";
#endif
#ifdef __cpp_lib_expected
    std::cout << "std::expected available\n";
#endif
}

Each library page lists its macro in a Notes table ("Feature-test macro: __cpp_lib_format, value 201907L"). Use them for code that must build on several compilers, with a fallback in the #else.

Reading a specification inside a page: std::format

Some pages contain a small language of their own. The format specification for std::format (C++20) is one, and it rewards precise reading. A replacement field is {index:spec}, and the spec for numbers and strings is:

Text
fill-and-align  sign  #  0  width  .precision  L  type
Part Values Effect
fill and align < left, > right, ^ centre, optionally preceded by a fill character {:*>6} pads with * to width 6, right-aligned
sign + always, - only negative (default), space: a space for positive {:+} gives +5
# alternate form {:#x} gives 0xff
0 pad numbers with zeros after the sign {:05} gives 00042
width minimum width {:8}
precision digits after the point for floating point; maximum characters for strings {:.2f}, {:.3}
type d x X b o for integers; f e g for floating point; s for strings {:b} gives binary

Defaults matter, and the page states them: numbers align right, strings align left. So std::format("[{:6}]", 42) is [ 42] while std::format("[{:6}]", "ab") is [ab ].

C++
#include <format>
#include <iostream>

int main()
{
    std::cout << std::format("[{:6}] [{:6}] [{:^6}]\n", 42, "ab", "mid");
    std::cout << std::format("{:#x} {:08.3f} {:+} {:*<5}|\n", 255, 3.14159, 7, "x");
}
