Reading Signatures

lesson 1.033 of 4 in milestone 15 min1 practice task

Decoding the declarations at the top of C++ reference pages - parameter and return types, const, references and pointers, default arguments, overload sets, templates and their named requirements, noexcept and nodiscard - so a signature tells you how to call a function before you read a word of prose.

A signature is a summary

The declaration at the top of a reference page already answers most questions: what you pass, what you get back, what may be changed, and what may fail. Learn to read it first.

C++
[[nodiscard]] std::size_t count_words(const std::string& text, char separator = ' ') noexcept;

Read it piece by piece:

Piece Means
[[nodiscard]] ignoring the result is almost certainly a bug; the compiler warns
std::size_t returns a count, never negative
const std::string& text reads your string without copying it and without changing it
char separator = ' ' a default argument: you may leave it out
noexcept never throws an exception

Parameters: who owns what, who changes what

Parameter type Meaning for the caller
T (by value) the function gets its own copy; yours is untouched
const T& read-only access to yours, no copy
T& an output or in-out parameter: your object may be changed
T&& the function may take over (move from) your object
const T* read-only access through a pointer; check the docs whether null is allowed
T* may be changed through the pointer; check whether null is allowed
std::string_view, std::span<const T> a read-only view; the function will not keep it after returning (unless it says so)
std::unique_ptr<T> by value the function takes ownership

A non-const reference or pointer is the strongest signal on the page: something of yours changes. Find out what.

Overload sets

Many functions come as a numbered set of overloads. cppreference shows them as (1), (2) ..., each with its own description:

C++
iterator insert(const_iterator pos, const T& value);                    // (1)
iterator insert(const_iterator pos, size_type count, const T& value);   // (3)
template<class InputIt>
iterator insert(const_iterator pos, InputIt first, InputIt last);       // (4)
iterator insert(const_iterator pos, std::initializer_list<T> list);     // (5)

The compiler picks one from your arguments, and the surprises come from conversions: v.insert(v.begin(), 3, 7) inserts three sevens (3), not 3 and 7. Identify the overload you are calling before reading the description.

Templates and named requirements

Generic functions are templates, and the names of their parameters are documentation:

C++
template<class InputIt, class T>
InputIt find(InputIt first, InputIt last, const T& value);

template<class RandomIt, class Compare>
void sort(RandomIt first, RandomIt last, Compare comp);

InputIt and RandomIt refer to named requirements: an input iterator can only be read once going forward; a random-access iterator can jump anywhere (like a vector's, unlike a list's). So std::sort on a std::list fails to compile, and the signature already told you. Compare must be a strict weak ordering: comp(a, a) must be false, which is why passing <= breaks std::sort in ways that are hard to see.

Ranges and concepts (C++20) state requirements directly:

C++
template<std::random_access_iterator I, std::sentinel_for<I> S, class Comp = std::ranges::less>
    requires std::sortable<I, Comp>
constexpr I sort(I first, S last, Comp comp = {});

Long, but each line is a rule about what you may pass.

Return types

  • bool: success or a yes/no answer; check which.
  • An iterator: often "end" means "not found".
  • std::pair<iterator, bool>: std::map::insert tells you where the element is and whether it was inserted.
  • std::optional<T>: may be empty.
  • void: nothing to check, but failure may still be reported by exception.
  • auto or a long template type: read the Return value section.
