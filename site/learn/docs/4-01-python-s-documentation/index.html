Python's Documentation

lesson 4.011 of 4 in milestone 45 min1 practice task

Finding and reading docs.python.org - the tutorial, library reference and language reference - Python signature notation with defaults, / and *, the version notes that say when behaviour changed, how a page describes exceptions, and help(), docstrings and type stubs from inside Python.

Three books in one site

docs.python.org holds several documents, and knowing which to open saves time:

Document For
Tutorial learning the language from the start
Library Reference built-in functions, types (str, list, dict) and every standard module: the one you will use most
Language Reference the exact rules of the syntax and semantics, like the C++ standard
HOWTOs how-to guides on single topics: sorting, logging, regular expressions
What's New per version, what was added and changed

Use the version selector at the top: pages differ between Python 3.9 and 3.13, and search engines often land on an old one.

Reading a Python signature

Python pages write signatures in Python syntax:

Python
str.split(sep=None, maxsplit=-1)
sorted(iterable, /, *, key=None, reverse=False)
int(x, /, base=10)
  • name=value: a default; you may leave the argument out.
  • A / marks the end of positional-only parameters: sorted(iterable=x) is an error; you must write sorted(x).
  • A * marks the start of keyword-only parameters: sorted(x, None, True) is an error; you must write sorted(x, reverse=True).
  • Older pages use brackets for optional arguments: range(start, stop[, step]).

Defaults such as sep=None often stand for a different behaviour, not a value, and the description explains it. For str.split, sep=None means "split on runs of whitespace and drop empty strings", while any given separator means "split exactly at each occurrence, keeping empty strings". The project of milestone 1 implemented exactly this difference.

What the description promises

Python pages are prose more than tables, so read for these phrases:

  • "Raises ValueError if ...", "If ... a TypeError is raised": the exceptions to handle.
  • "Return a new list ..." versus "... in place": sorted() returns a new list, list.sort() changes the list and returns None. Using x = x.sort() is a classic bug the page warns about.
  • "The result is guaranteed to be stable", "CPython implementation detail: ...": the first you may rely on; the second you may not, other Pythons can differ.
  • Exact edge rules: slicing s[i:j:k] documents what happens with negative and out-of-range indices and with a negative step (practice 4.01 implements them).

Version notes

Pages carry boxed notes that matter as much as the text:

  • Added in version 3.9. You cannot use it on 3.8.
  • Changed in version 3.7: for example, "dictionary order is guaranteed to be insertion order". Code relying on the new behaviour silently misbehaves on older versions.
  • Deprecated since version 3.12, will be removed in version 3.14. Plan to move away.

From inside Python

  • help(str.split) prints the docstring, which usually summarises the page.
  • obj.__doc__ is the same text; your own functions get one when their first statement is a string literal.
  • Type hints and the typeshed stubs (what editors use for completion) show parameter and return types, which the prose sometimes leaves implicit.
Python
>>> help(str.split)
