Structures, Flags and Versions

lesson 3.044 of 4 in milestone 35 min1 practice task

Reading the parts of Windows pages that describe data - structures whose first member gives their size, reserved fields, zero-initialisation, flag parameters that combine with OR versus parameters that take one value, mutually exclusive flags, and version requirements and _WIN32_WINNT.

Structures that know their size

Many Windows structures start with a member holding their own size: cb, cbSize, dwSize, dwOSVersionInfoSize. The page always says the same thing about it in some form: "The size of the structure, in bytes. You must set this member before calling the function."

C++
STARTUPINFOW si{};          // zero every member
si.cb = sizeof(si);         // then the size
PROCESS_INFORMATION pi{};
CreateProcessW(..., &si, &pi);

Why? Structures grow in new Windows versions. The size tells the function which version of the structure you compiled against, so it reads and writes only the members you have. A function that receives a size it does not know fails with ERROR_INVALID_PARAMETER rather than writing past the end of your memory. Forgetting to set it usually makes the call fail; setting it to the size of the wrong structure can make it write outside your object.

Two more habits from the same pages:

  • Zero-initialise every structure ({}): members you do not set must usually be zero or null, and reserved members "must be zero" even though nothing uses them yet. Garbage in a reserved field is a bug waiting for the Windows version that starts using it.
  • Read each member's description for whether it is in (you fill it), out (the function fills it) or both. The same structure is often used both ways.

Flags or a single value

Parameters with named constants come in two kinds, and the wording says which:

  • "This parameter can be one or more of the following values": flags, combined with |. Each value is a separate bit: FILE_SHARE_READ | FILE_SHARE_WRITE.
  • "This parameter can be one of the following values": an enumeration. Combining values is wrong, and since they are often consecutive numbers (CREATE_NEW 1, CREATE_ALWAYS 2, OPEN_EXISTING 3, OPEN_ALWAYS 4, TRUNCATE_EXISTING 5), OR-ing two gives a third, unintended one. CREATE_NEW | CREATE_ALWAYS is 3, which is OPEN_EXISTING.

Flag lists often come with rules: "cannot be combined with", "requires", "if this flag is specified, the x parameter must be ...". When a page has such rules, the function usually checks them and fails with ERROR_INVALID_PARAMETER; some combinations are just documented as undefined.

Versions

The Requirements table gives the minimum Windows version. To use a function or structure member from a newer version, the headers must be told your target, through _WIN32_WINNT (or NTDDI_VERSION), defined before including windows.h:

C++
#define _WIN32_WINNT 0x0A00     // Windows 10
#include <windows.h>

If you target an older version than a function needs, the declaration is hidden and the code does not compile; if you call a function your users' Windows does not have, the program fails to start, so for optional features look the function up at run time with GetProcAddress (the DLLs course covers this). Some members are documented "Windows 10, version 1703 and later": the structure is the same size, but older systems ignore the member.
