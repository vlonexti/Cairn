Type Conversion and static_cast

lesson 2.055 of 9 in milestone 25 min3 practice tasks

C++ converts between types automatically when it has to. Some conversions lose information. When you want a conversion, say so with static_cast<Type>(value).

Conversions happen without being asked

Whenever a value of one type is used where another is expected, C++ converts it. This is called an implicit conversion: the compiler does it without you writing anything.

C++
double d{ 5 };     // the int 5 becomes the double 5.0
int i = 3.9;       // the double 3.9 becomes the int 3: the .9 is gone

The first is harmless. The second lost information, and nothing warned you.

Widening and narrowing

flowchart LR
    subgraph SAFE["Widening: always fits"]
        direction LR
        c["char"] --> s["short"] --> i["int"] --> l["long long"]
        f["float"] --> d["double"]
    end
    subgraph RISKY["Narrowing: may lose information"]
        direction LR
        d2["double 3.9"] --> i2["int 3"]
        l2["long long<br/>5 billion"] --> i3["int<br/>does not fit"]
    end
Direction Safe?
Widening To a type that can hold every value of the original Yes
Narrowing To a type that cannot Only if you know the value fits

This is why the course uses braces. Brace initialization refuses to narrow:

C++
int a = 3.5;    // compiles; a is 3
int b{ 3.5 };   // error: narrowing conversion

Mixed arithmetic

When an operator has two different types to work with, the compiler converts one side first so both match. Roughly, the "smaller" type is converted to the "larger" one.

Expression Result type Note
int + double double
int + long long long long
char + char int types smaller than int are widened to int first
int + unsigned unsigned the trap from 2.02 Integers

The important detail: the conversion happens one operator at a time, not for the statement as a whole.

C++
#include <iostream>

int main()
{
    int total{ 7 };
    int count{ 2 };
    double wrong{ static_cast<double>(total / count) };    // 3
    double right{ static_cast<double>(total) / count };    // 3.5
    std::cout << wrong << ' ' << right << '\n';
    return 0;
}
flowchart TD
    A["total / count"] --> B["int / int gives 3"] --> C["converted afterwards: 3.0<br/>the .5 is already lost"]
    D["static_cast&lt;double&gt;(total) / count"] --> E["double / int<br/>count is widened to double"] --> F["3.5"]

In the first line the division is finished, as integer division, before any double is involved.

Converting on purpose

static_cast is how you tell the compiler, and the next reader, "I mean this conversion".

C++
static_cast<new type>(value)
C++
double price{ 9.99 };
int whole{ static_cast<int>(price) };     // 9
char letter{ static_cast<char>(72) };     // 'H'
int code{ static_cast<int>('H') };        // 72

It also satisfies brace initialization, because you have stated your intent:

C++
int b{ static_cast<int>(3.5) };    // fine: 3

[!tip] Why not the shorter (int)price? That older form comes from C and still compiles. It will attempt almost any conversion, including dangerous ones, and it is hard to search for. static_cast only performs sensible conversions and stands out in the code.

Converting is not rounding

static_cast<int> cuts off the decimals. It does not round. For rounding, use <cmath>.

Call Result Rule
static_cast<int>(2.9) 2 cut off
std::round(2.5) 3.0 to the nearest whole number
std::floor(2.9) 2.0 always down
std::ceil(2.1) 3.0 always up

The <cmath> functions return a double. To store a rounded value in an int, combine the two:

C++
int rounded{ static_cast<int>(std::round(2.7)) };    // 3

Other casts exist

C++ has three more named casts for specialised jobs. You will not need them for a long time. The one you will meet is dynamic_cast, in 8.06 Object Slicing, Casting and Composition.
