Floating Point Numbers

lesson 2.033 of 9 in milestone 25 min3 practice tasks

float and double store decimals approximately. 0.1 + 0.2 is not exactly 0.3. Use double by default, never compare with ==, and never use them where every cent must be exact.

Decimals are approximate

Write one third as a decimal and you get 0.3333... for ever. You have to stop somewhere, so what you write down is slightly off.

Computers have the same problem in binary, with different numbers. In binary, 0.1 goes on for ever. The computer stores the closest value that fits.

C++
#include <iomanip>
#include <iostream>

int main()
{
    double x{ 0.1 + 0.2 };
    std::cout << std::setprecision(17) << x << '\n';    // 0.30000000000000004
    std::cout << (x == 0.3) << '\n';                    // 0, meaning false
    return 0;
}

Types that work this way are called floating point types.

How much precision do you get?

A floating point number is stored like scientific notation: some significant digits, and a power that says where the point goes.

   6.02 × 10^23
   ────    ────
  digits  where the point goes

  ┌──────┬───────────┬──────────────────────────────────────────────┐
  │ sign │ exponent  │               the digits                     │
  │ 1 bit│ 11 bits   │                52 bits                       │
  └──────┴───────────┴──────────────────────────────────────────────┘
                     a double: 64 bits in total

Only so many digits fit. Anything beyond that is rounded away.

Type Size Reliable significant digits
float 4 bytes about 7
double 8 bytes about 15
Output
 float   holding 123456789  prints  123456792    (ran out of digits)
 double  holding 123456789  prints  123456789

[!tip] Use double The extra precision is nearly always worth four more bytes. float is for cases where you hold millions of values and memory is tight, such as graphics.

Writing decimal literals

C++
double d{ 3.14 };        // a literal with a point is a double
float f{ 3.14f };        // the f suffix makes it a float
double big{ 6.02e23 };   // 6.02 × 10^23
double tiny{ 1.5e-9 };   // 0.0000000015

Controlling how they print

By default std::cout shows about six significant digits. The header <iomanip> lets you choose.

C++
#include <iomanip>
#include <iostream>

int main()
{
    double pi{ 3.14159265 };
    std::cout << pi << '\n';                                        // 3.14159
    std::cout << std::setprecision(3) << pi << '\n';                // 3.14  (3 significant digits)
    std::cout << std::fixed << std::setprecision(2) << pi << '\n';  // 3.14  (2 digits after the point)
    return 0;
}
Setting Meaning
std::setprecision(n) alone n significant digits in total
std::fixed then std::setprecision(n) exactly n digits after the point

Comparing safely

Because of the tiny errors, asking "are these exactly equal?" is the wrong question. Ask "are these close enough?"

C++
#include <cmath>

bool approxEqual(double a, double b)
{
    return std::abs(a - b) < 1e-9;
}

std::abs gives the size of the difference without its sign. If that is smaller than a tiny tolerance, treat the two as equal.

flowchart LR
    A["0.1 + 0.2"] --> C{"== 0.3 ?"}
    C -->|"exact comparison"| N["false"]
    A --> D{"difference<br/>below 0.000000001 ?"}
    D -->|"tolerance"| Y["true"]

Special values

Floating point has three values that are not ordinary numbers.

Expression Result Meaning
1.0 / 0.0 inf infinity
-1.0 / 0.0 -inf negative infinity
0.0 / 0.0 nan "not a number"
Integers are different

Dividing a floating point number by zero gives inf. Dividing an integer by zero (5 / 0) is undefined behaviour and usually crashes the program.

Money

Do not store money in a double. Errors of a fraction of a cent add up, and they anger accountants. Store the amount in the smallest unit as an integer:

C++
std::int64_t priceInCents{ 1999 };    // 19.99
