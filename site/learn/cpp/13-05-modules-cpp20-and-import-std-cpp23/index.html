Modules (C++20) and import std (C++23)

lesson 13.055 of 10 in milestone 135 min

Modules replace header files: you export what is public and import it elsewhere. A module is compiled once, leaks no macros and has no include-order problems. C++23's import std; brings in the whole standard library in one line.

What is wrong with headers

#include is textual substitution (1.08 Multiple Files and Headers). That simple model has real costs.

Writing a module

math.cppm: the interface

C++
module;                  // the global module fragment: old-style includes go here
#include <cmath>

export module math;      // this file is the interface of module "math"

export namespace math
{
    constexpr double pi{ 3.14159265358979 };

    double circleArea(double radius) { return pi * radius * radius; }

    template <typename T>
    T square(T x) { return x * x; }
}

double helper() { return 42.0; }    // not exported: importers cannot see it

main.cpp

C++
import std;      // C++23: the entire standard library
import math;

int main()
{
    std::println("{}", math::circleArea(2.0));
    // helper();   error: not visible outside the module
    return 0;
}
Line Meaning
export module math; Declares a module interface unit: the file that defines what module math offers
export on a declaration or a block Makes it visible to importers
import math; Makes the exported names of math available
module; followed by #includes The global module fragment, for headers that must still be included textually

Everything not exported has module linkage: it is usable throughout the module and invisible outside it. That is true encapsulation at the level of a library, which headers never offered. Templates may live in a module interface and be exported like anything else.

Interface and implementation

As with a header and a source file, a module can separate what it declares from how it is implemented.

C++
// geometry.cppm: the interface
export module geometry;

export double area(double width, double height);
C++
// geometry.cpp: an implementation unit
module geometry;

double area(double width, double height)
{
    return width * height;
}

A change to the implementation unit does not force importers to recompile.

Partitions

A large module can be divided into partitions, which are internal to it.

C++
// physics.cppm
export module game:physics;

export double gravity();
C++
// game.cppm
export module game;

export import :physics;    // re-export the partition

Users write import game;. The partitions are an organisational detail they never see.

import std;

import std; makes the whole standard library available. Because the library is compiled once into a module, importing all of it is typically faster than including <iostream> alone. import std.compat; additionally provides the C library names in the global namespace.

Building

Modules introduce an ordering requirement that headers did not have: a module's interface must be compiled before anything that imports it. The build system has to discover those dependencies by scanning the sources.

CMake
cmake_minimum_required(VERSION 3.30)
project(ModuleDemo LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_MODULE_STD ON)

add_executable(app main.cpp)
target_sources(app PUBLIC FILE_SET CXX_MODULES FILES math.cppm)

CMake 3.28 and later handle the scanning, with the Ninja generator or Visual Studio. The interface file's extension is a convention: .cppm for Clang and GCC, .ixx for Visual Studio.

Toolchain Status
Microsoft's compiler The most mature support
Clang 17 and later, GCC 14 and later Work well with CMake and Ninja
Third-party libraries Most still ship headers only
You need both

Headers are not going away. Existing libraries use them, and a module can still include them in its global module fragment. Know both models: write new code as modules where your tools allow, and expect to consume headers for years.
