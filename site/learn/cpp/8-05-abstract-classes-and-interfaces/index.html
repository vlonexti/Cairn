Abstract Classes and Interfaces

lesson 8.055 of 7 in milestone 85 min3 practice tasks

A pure virtual function, declared = 0, has no implementation in the base: derived classes must supply one. A class with any pure virtual function is abstract and cannot be instantiated. A class made only of pure virtual functions is an interface: a contract.

Pure virtual functions

Animal::speak in the last lessons returned "..." because it had to return something. Often there is no sensible default: what is the area of "a shape"? A pure virtual function declares the operation without defining it.

C++
#include <iostream>
#include <string_view>

class Shape
{
public:
    virtual ~Shape() = default;

    virtual double area() const = 0;
    virtual std::string_view name() const = 0;

    void describe() const
    {
        std::cout << name() << " with area " << area() << '\n';
    }
};

class Circle : public Shape
{
public:
    explicit Circle(double radius) : m_radius{ radius } {}

    double area() const override { return 3.14159 * m_radius * m_radius; }
    std::string_view name() const override { return "Circle"; }

private:
    double m_radius{};
};

int main()
{
    // Shape s{};    error: Shape is abstract
    const Circle c{ 2.0 };
    c.describe();    // Circle with area 12.5664
    return 0;
}
Term Meaning
Pure virtual function Declared with = 0; derived classes must override it
Abstract class Has at least one pure virtual function; cannot be instantiated
Concrete class Has none left unimplemented; can be instantiated

A derived class that fails to override even one pure virtual function is itself abstract. The compiler enforces completeness for you.

Notice describe: a non-virtual function in the base that calls the virtual ones. The base class fixes the overall behaviour and the derived classes supply the variable parts.

Interfaces

An interface is an abstract class with no data and only pure virtual functions (plus the virtual destructor). It states what a type can do and nothing about how.

C++
class ILogger
{
public:
    virtual ~ILogger() = default;
    virtual void log(std::string_view message) = 0;
};

class ConsoleLogger : public ILogger
{
public:
    void log(std::string_view message) override { std::cout << "[console] " << message << '\n'; }
};

class FileLogger : public ILogger
{
public:
    void log(std::string_view message) override { m_file << message << '\n'; }

private:
    std::ofstream m_file{ "app.log" };
};

class Game
{
public:
    explicit Game(ILogger& logger) : m_logger{ logger } {}
    void start() { m_logger.log("Game started"); }

private:
    ILogger& m_logger;
};

C++ has no interface keyword; this is a convention. The I prefix is one common way to mark it.

Why depend on an interface?

Game knows about ILogger and about no particular logger.

Benefit Example
Implementations can be swapped Log to a file in production and to the console while developing, with no change to Game
Testing is easy Pass a FakeLogger that records messages, then check what was logged
Compilation is decoupled Changing FileLogger does not recompile Game

High-level code depending on an abstraction, with the details plugged in from outside, is the dependency inversion principle. Supplying the dependency through the constructor, as here, is dependency injection.

A pure virtual function with a body

A pure virtual function may still have a definition, written outside the class. Derived classes must override it, and can call the base version explicitly.

C++
class Animal
{
public:
    virtual ~Animal() = default;
    virtual void speak() const = 0;
};

void Animal::speak() const
{
    std::cout << "(a generic sound)\n";
}

class Fish : public Animal
{
public:
    void speak() const override { Animal::speak(); }
};

This offers a default while forcing each derived class to opt in deliberately.

The non-virtual interface idiom

A public non-virtual function fixes the sequence of steps. Private virtual functions are the points derived classes may customise.

C++
class Report
{
public:
    void generate()
    {
        header();
        body();
        footer();
    }

private:
    virtual void header() { std::cout << "== REPORT ==\n"; }
    virtual void body() = 0;
    virtual void footer() { std::cout << "== END ==\n"; }
};

Derived classes can override a private virtual function; they just cannot call it. So the base keeps control of when each step runs, and can add checks or logging around them in one place. In design-pattern terms this is the Template Method pattern: 13.08 C++ Idioms and Design Patterns.
