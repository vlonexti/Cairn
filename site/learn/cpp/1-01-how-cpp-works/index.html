How C++ Works

lesson 1.011 of 10 in milestone 15 min3 practice tasks

You write text (source code). A compiler translates it into machine code. A linker joins the pieces into one program that your computer runs directly.

The big picture

A computer's processor (the CPU) understands only numbers. Nobody wants to write programs as long lists of numbers, so we write them in a language people can read, and a tool translates that into the numbers the processor needs.

C++ is one of those languages. The translating happens before the program runs.

flowchart LR
    A["main.cpp<br/>(what you write)"] --> C["Compiler<br/>translates it"]
    C --> O["main.obj<br/>(translated piece)"]
    O --> L["Linker<br/>joins the pieces"]
    LIB["Standard library<br/>(ready-made code)"] --> L
    L --> E["program.exe"]
    E --> R["The CPU runs it"]
Step What it does Think of it as
You write Type instructions into a text file ending in .cpp Writing a recipe
Compiler Checks the file follows the rules of C++ and translates it Translating the recipe into the cook's language
Linker Joins your translated code with ready-made library code Binding the chapters into one book
Run The finished program starts Cooking

You will hear three words constantly. They are worth learning now:

  • Source code: the text you write.
  • Build (or compile): turn source code into a program. This is both steps above, compiler then linker.
  • Run: start the program that was built.

Why translate ahead of time?

Some languages, such as Python, are translated a line at a time while the program runs. C++ does all of that work once, in advance.

The trade

You get speed. Nothing stands between your program and the processor. That is why games, web browsers, operating systems and trading systems are written in C++. You pay with strictness. The compiler refuses to build anything it cannot make sense of. That feels harsh in week one. Later you will be glad of it, because every mistake it catches is one that never reaches your running program.

Three kinds of mistakes

Every programmer makes all three, every day. Knowing which kind you are looking at tells you where to look.

When it shows up Name Example Who notices
While building Compile error You forgot a ; The compiler. Nothing is built.
While building Linker error You promised a function existed but never wrote it The linker. Nothing is built.
While running Logic error (a bug) It builds and runs, but prints the wrong total Only you
Errors are not a judgement

A compile error is the compiler saying "I got stuck here". It gives you the line number. Read it, fix it, build again. Professionals do this hundreds of times a day.

Where C++ came from

flowchart LR
    A["1972<br/>C"] --> B["1985<br/>C++"] --> C["1998<br/>first standard"] --> D["2011<br/>modern C++"] --> E["2020<br/>C++20"] --> F["2023<br/>C++23"]

C++ gets a new version every three years, named after the year. This course teaches modern C++ (C++20, with the useful parts of C++23). You do not need to know the history yet; the full story is in 13.10 C++ Standards Timeline and Where to Go Next.
