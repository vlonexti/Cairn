Compile-Time Programming — constexpr, consteval, constinit

lesson 11.044 of 7 in milestone 116 min2 practice tasks

Modern C++ can run real code inside the compiler: loops, std::vector, std::string, even new and delete, provided nothing allocated escapes to run time. constexpr may run at compile time, consteval must, and constinit guarantees a static variable is initialized at compile time while leaving it mutable.

The keywords

2.06 const and constexpr introduced constexpr. Here is the full set.

Keyword Applies to Meaning
constexpr A variable Its value is a compile-time constant; implies const
constexpr A function May be evaluated at compile time when its arguments are constant; otherwise runs normally
consteval A function Must be evaluated at compile time. An immediate function.
constinit A static or thread-local variable Initialized at compile time, but not const
if constexpr A branch Selected at compile time; the other branch is discarded
if consteval (C++23) A branch Taken when the function is being evaluated at compile time 
flowchart LR
    A["constexpr int sq(int n)"] -->|"sq(5) where a constant is required"| CT["evaluated by the compiler:<br/>25 is stored in the program"]
    A -->|"sq(userInput)"| RT["runs at run time"]
    B["consteval int sq2(int n)"] -->|"sq2(5)"| CT
    B -->|"sq2(userInput)"| ERR["compile error"]

An evaluation done by the compiler is a constant evaluation. It is forced wherever the language needs a constant: the initializer of a constexpr variable, a template argument, an array bound, a case label, a static_assert.

[!note] constexpr on a function is a permission, not a guarantee int x{ sq(5) }; with a non-constexpr x may or may not be folded by the optimiser. To be certain, initialize a constexpr variable, or make the function consteval.

Real algorithms at compile time

C++
#include <array>
#include <cstddef>
#include <iostream>

constexpr bool isPrime(int n)
{
    if (n < 2)
    {
        return false;
    }
    for (int i{ 2 }; i * i <= n; ++i)
    {
        if (n % i == 0)
        {
            return false;
        }
    }
    return true;
}

template <std::size_t N>
constexpr std::array<int, N> firstPrimes()
{
    std::array<int, N> result{};
    std::size_t found{ 0 };
    for (int n{ 2 }; found < N; ++n)
    {
        if (isPrime(n))
        {
            result[found++] = n;
        }
    }
    return result;
}

constexpr auto primes{ firstPrimes<10>() };
static_assert(primes[9] == 29);

int main()
{
    for (int p : primes)
    {
        std::cout << p << ' ';
    }
    std::cout << '\n';
    return 0;
}

The loop runs in the compiler. The executable contains the finished table and no code to compute it. This is the modern way to build lookup tables.

Containers at compile time

Since C++20, dynamic allocation is permitted during constant evaluation, on one condition: everything allocated must be released before the evaluation ends. This is a transient allocation.

C++
constexpr int sumOfSquares(int n)
{
    std::vector<int> values{};
    for (int i{ 1 }; i <= n; ++i)
    {
        values.push_back(i * i);
    }
    return std::accumulate(values.begin(), values.end(), 0);
}    // the vector is destroyed here, inside the evaluation

static_assert(sumOfSquares(3) == 14);

std::vector and std::string are usable inside a constexpr function. What you cannot do is make a constexpr variable of those types that holds heap memory, because that memory would have to survive into the running program. Return a std::array or a plain value instead.

Hashing strings for a switch

A switch needs integer constants (3.02 switch). A constexpr hash function supplies them from strings and also runs normally on run-time input.

C++
constexpr std::uint32_t hashName(std::string_view text)
{
    std::uint32_t hash{ 2166136261u };
    for (char c : text)
    {
        hash ^= static_cast<std::uint8_t>(c);
        hash *= 16777619u;
    }
    return hash;
}

switch (hashName(command))            // run time: hashes what the user typed
{
case hashName("jump"): jump(); break; // compile time: a case label must be a constant
case hashName("run"):  run();  break;
}

One function, used in both worlds. Two different strings can hash to the same value, so real code confirms the match afterwards.

consteval

C++
consteval int square(int n)
{
    return n * n;
}

constexpr int a{ square(8) };    // 64, computed by the compiler

int x{ 3 };
int b{ square(x) };              // error: x is not a constant expression

Use consteval when a run-time call would be a mistake. Its best-known use is validation: std::format checks its format string through a consteval constructor, which is how a wrong format string becomes a compile error (10.07 Formatting with std::format and std::print). You can do the same:

C++
consteval int checkedPercent(int value)
{
    if (value < 0 || value > 100)
    {
        throw "percentage out of range";    // reaching a throw makes the evaluation fail
    }
    return value;
}

constexpr int volume{ checkedPercent(80) };     // fine
// constexpr int bad{ checkedPercent(140) };    // compile error

constinit

A global with a dynamic initializer is initialized at program start, before main. Across different source files the order is unspecified, so one global's initializer may use another that has not been initialized yet. That is the static initialization order fiasco.

C++
constinit int g_counter{ 0 };                 // initialized at compile time; still modifiable
constinit thread_local int t_calls{ 0 };

constinit makes the compiler verify that the initializer is a constant expression. A variable initialized at compile time exists before any code runs, so it cannot be caught in that ordering problem. Unlike constexpr, it does not make the variable const.

Values with constexpr, types with templates

The original way to compute at compile time was recursion through template instantiation (9.02 Non-Type Parameters and Template Specialization):

C++
template <unsigned N>
struct Factorial
{
    static constexpr unsigned value{ N * Factorial<N - 1>::value };
};

template <>
struct Factorial<0>
{
    static constexpr unsigned value{ 1 };
};

Today:

C++
constexpr unsigned factorial(unsigned n)
{
    return n <= 1 ? 1 : n * factorial(n - 1);
}
The division of labour

Compute values with constexpr functions: they are ordinary code, testable at run time too. Use templates and traits to compute types: 11.07 Template Metaprogramming Techniques.

What is not allowed

Restriction Detail
Undefined behaviour The compiler rejects it during constant evaluation
Input and output No streams, no files
reinterpret_cast Not permitted
Non-transient allocation Memory must be released before the evaluation ends
Unbounded work Compilers limit the number of steps and the recursion depth

The first row is a benefit. An overflow, an out-of-bounds index or a read of an uninitialized variable inside a constant evaluation is a compile error. Testing a constexpr function with static_assert therefore proves those cases are free of undefined behaviour.
