Futures, Promises, std::async and Thread Pools

lesson 12.044 of 7 in milestone 126 min2 practice tasks

A future is a handle to a result that will be available later. std::async(f) runs f, possibly on another thread, and returns a future; get() waits for the value, or rethrows the exception. A promise is the writing end of the same channel. std::packaged_task wraps a callable for use in thread pools.

Tasks, not threads

With raw threads you manage the thread, a place for its result, the synchronization and any exception by hand. A task is a unit of work with a result. A future is how you collect it.

C++
#include <chrono>
#include <future>
#include <iostream>
#include <thread>

int slowSquare(int x)
{
    std::this_thread::sleep_for(std::chrono::milliseconds{ 300 });
    return x * x;
}

int main()
{
    std::future<int> a{ std::async(std::launch::async, slowSquare, 4) };
    std::future<int> b{ std::async(std::launch::async, slowSquare, 5) };

    std::cout << a.get() + b.get() << '\n';    // 41, after about 0.3 s, not 0.6
    return 0;
}

    Main->>Main: a.get() + b.get() is 41

get() blocks until the result is ready, then returns it. The result may be retrieved once: get() moves it out and leaves the future empty.

Launch policies

Policy Behaviour
std::launch::async Runs on a new thread, starting immediately
std::launch::deferred Runs lazily, on the calling thread, when get() or wait() is called
Neither given The implementation may choose either

Without a policy, your "parallel" code may be deferred and run sequentially. Say std::launch::async when you mean it.

[!warning] A future from std::async blocks in its destructor Unlike any other future, one returned by std::async waits for its task when destroyed. So this runs synchronously:

C++
std::async(std::launch::async, work);    // the temporary future is destroyed at once, and waits

Always keep the future.

Exceptions cross threads

An exception thrown inside a task is captured and stored. It is rethrown in the thread that calls get().

C++
auto task{ std::async(std::launch::async, []() -> int
{
    throw std::runtime_error{ "failed in the task" };
}) };

try
{
    task.get();
}
catch (const std::exception& e)
{
    std::cout << "caught: " << e.what() << '\n';
}

This is something raw threads cannot do: an exception escaping a thread's function calls std::terminate.

The future interface

Member Does
get() Waits, then returns the value or rethrows. Once only.
wait() Waits without retrieving
wait_for(duration) Waits up to a limit; returns ready, timeout or deferred
valid() Whether it still refers to a shared state
share() Converts to a std::shared_future, whose get() can be called repeatedly and from several threads

The shared state, and std::promise

A future is the reading end of a one-shot channel. The writing end is a promise. Between them is a shared state that holds the value or exception and is kept alive by whichever end still exists.

 promise (write end) ──────── shared state ──────── future (read end)
   set_value(v) ──────────────▶  [ v ]  ──────────────▶ get()
C++
std::promise<std::string> promise{};
std::future<std::string> future{ promise.get_future() };

std::jthread worker{ [p = std::move(promise)]() mutable
{
    p.set_value("a result from the worker");
} };

std::cout << future.get() << '\n';

std::async creates this pair for you. Use a promise directly when the result is produced by something other than a function's return, for example a callback from another library. set_exception(std::current_exception()) delivers a failure. A std::promise<void> makes a convenient one-time "go" signal for threads waiting on a shared future.

std::packaged_task

A packaged_task wraps a callable so that calling it stores the result in a shared state. It separates where the work runs from who receives the result.

C++
std::packaged_task<int(int, int)> task{ [](int a, int b) { return a + b; } };
std::future<int> result{ task.get_future() };

std::jthread t{ std::move(task), 2, 3 };
std::cout << result.get() << '\n';    // 5
Tool You supply It handles
std::async A callable The thread, the shared state, exceptions
std::packaged_task A callable, and the place it runs The shared state, exceptions
std::promise The value itself, whenever it is ready The shared state

A thread pool

Creating a thread for every small task wastes far more time than the task takes. A thread pool keeps a fixed set of worker threads that take tasks from a shared queue.

flowchart LR
    S["submit(task)"] --> Q["task queue<br/>mutex and condition variable"]
    Q --> W1["worker 1"] & W2["worker 2"] & W3["worker 3"] & W4["worker 4"]
    W1 & W2 & W3 & W4 --> F["futures are fulfilled"]
C++
class ThreadPool
{
public:
    explicit ThreadPool(unsigned count = std::thread::hardware_concurrency())
    {
        for (unsigned i{ 0 }; i < count; ++i)
        {
            m_workers.emplace_back([this](std::stop_token stop)
            {
                while (true)
                {
                    std::move_only_function<void()> task{};
                    {
                        std::unique_lock lock{ m_mutex };
                        if (!m_available.wait(lock, stop, [this] { return !m_tasks.empty(); }))
                        {
                            return;    // a stop was requested and the queue is empty
                        }
                        task = std::move(m_tasks.front());
                        m_tasks.pop();
                    }
                    task();
                }
            });
        }
    }

    template <typename F>
    auto submit(F f) -> std::future<std::invoke_result_t<F>>
    {
        std::packaged_task<std::invoke_result_t<F>()> task{ std::move(f) };
        auto future{ task.get_future() };
        {
            std::lock_guard lock{ m_mutex };
            m_tasks.emplace(std::move(task));
        }
        m_available.notify_one();
        return future;
    }

private:
    std::queue<std::move_only_function<void()>> m_tasks{};
    std::mutex m_mutex{};
    std::condition_variable_any m_available{};
    std::vector<std::jthread> m_workers{};
};

A packaged_task cannot be copied, so the queue holds std::move_only_function (C++23), a type-erased callable that need not be copyable (11.06 Type Erasure).

Member order is doing real work

m_workers is declared last, so it is destroyed first. Each jthread's destructor requests a stop and joins, while the mutex, condition variable and queue the workers use still exist. Reorder the members and the workers would touch destroyed objects.
