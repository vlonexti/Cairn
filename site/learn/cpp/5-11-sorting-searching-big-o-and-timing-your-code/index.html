Sorting, Searching, Big-O and Timing Your Code

lesson 5.1111 of 11 in milestone 55 min3 practice tasks

See how sorting and searching actually work, describe their speed with Big-O notation, and measure real time with <chrono>. Then use std::sort in real code.

How does the work grow?

A program that is instant on ten items may take hours on a million. Big-O notation describes how the amount of work grows as the input size, called n, grows. It ignores constant factors and keeps only the dominant term.

Big-O Name Steps for n = 1,000 Example
O(1) constant 1 v[i], push_back
O(log n) logarithmic about 10 Binary search
O(n) linear 1,000 Linear search, summing
O(n log n) linearithmic about 10,000 std::sort, merge sort
O(n²) quadratic 1,000,000 Selection sort, two nested loops over the data
O(2ⁿ) exponential astronomically many Simple recursive Fibonacci

The practical question Big-O answers is: what happens when the input doubles?

Complexity When n doubles, the work
O(1) Stays the same
O(log n) Increases by one step
O(n) Doubles
O(n log n) Slightly more than doubles
O(n²) Quadruples

Selection sort

Find the smallest element, swap it to the front, and repeat on the rest.

Output
 [5 3 8 1 9]    smallest is 1: swap it with the first
 [1 3 8 5 9]    smallest of the rest is 3: already in place
 [1 3 8 5 9]    smallest of the rest is 5: swap it with 8
 [1 3 5 8 9]    done
C++
void selectionSort(std::vector<int>& v)
{
    for (std::size_t i{ 0 }; i + 1 < v.size(); ++i)
    {
        std::size_t smallest{ i };
        for (std::size_t j{ i + 1 }; j < v.size(); ++j)
        {
            if (v[j] < v[smallest])
            {
                smallest = j;
            }
        }
        std::swap(v[i], v[smallest]);
    }
}

Two nested loops over the data: O(n²).

Insertion sort

Take each element in turn and slide it left into its place among those already sorted, the way you sort a hand of cards.

C++
void insertionSort(std::vector<int>& v)
{
    for (std::size_t i{ 1 }; i < v.size(); ++i)
    {
        const int key{ v[i] };
        std::size_t j{ i };
        while (j > 0 && v[j - 1] > key)
        {
            v[j] = v[j - 1];    // shift the larger element right
            --j;
        }
        v[j] = key;
    }
}

Also O(n²) in general, but close to O(n) when the data is already nearly sorted, and very fast for small inputs.

Merge sort

A divide and conquer algorithm: split the problem, solve the parts, combine the answers.

flowchart TD
    A["8 3 5 1"] --> B["8 3"] & C["5 1"]
    B --> D["8"] & E["3"]
    C --> F["5"] & G["1"]
    D & E --> H["3 8"]
    F & G --> I["1 5"]
    H & I --> J["1 3 5 8"]
  1. Split the range in half, recursively (5.09 Recursion), until each piece has one element.
  2. Merge pairs of sorted pieces: repeatedly take the smaller of the two front elements.

There are log n levels of splitting, and each level does n work to merge: O(n log n).

Binary search

On sorted data you can discard half the candidates with each comparison.

Output
 looking for 23 in [2 5 8 12 16 23 38 56 72 91]

 low 0, high 9, middle 4:  16 is too small   search the right half
 low 5, high 9, middle 7:  56 is too large   search the left half
 low 5, high 6, middle 5:  23 found          3 steps, not 6

A million sorted elements need at most about 20 comparisons. That is O(log n).

C++
std::ranges::sort(v);
const bool present{ std::ranges::binary_search(v, 23) };
const auto position{ std::ranges::lower_bound(v, 23) };    // first element not less than 23

In real code

Write these algorithms once to understand them. After that, use the library: std::sort is O(n log n), carefully tuned, and correct. The reason to know the theory is to choose well, for example noticing that a linear search inside a loop has quietly made your program O(n²).

Measuring time

Big-O predicts how time grows. To learn how long something actually takes, measure it.

C++
#include <chrono>

class Timer
{
public:
    void reset()
    {
        m_start = Clock::now();
    }

    double elapsedMs() const
    {
        return std::chrono::duration<double, std::milli>(Clock::now() - m_start).count();
    }

private:
    using Clock = std::chrono::steady_clock;
    Clock::time_point m_start{ Clock::now() };
};
C++
Timer timer{};
selectionSort(bigVector);
std::cout << "took " << timer.elapsedMs() << " ms\n";

Timer is a class, the subject of the next milestone (6.01 Classes and Objects). For now, use it as given. steady_clock is the clock meant for measuring intervals.

Measure properly

Time a Release build: Debug builds can be ten to fifty times slower and distort comparisons. Run each measurement several times, and use input of a realistic size and shape.
