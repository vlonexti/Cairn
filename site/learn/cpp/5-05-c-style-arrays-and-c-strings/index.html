C-Style Arrays and C-Strings

lesson 5.055 of 11 in milestone 55 min3 practice tasks

int arr[5]{}; is the raw array inherited from C. Passed to a function it decays to a pointer and loses its length. A C-string is a char array ending in '\0'. Learn them to read existing code; write std::array, std::vector and std::string.

Why learn the old way?

C++ grew out of C and still contains C's arrays and strings. New code should not use them, but operating-system interfaces, C libraries and thirty years of existing code do. You need to read them fluently.

C-style arrays

C++
#include <iostream>
#include <iterator>

int main()
{
    int scores[5]{ 90, 80, 70, 60, 50 };
    scores[0] = 100;
    std::cout << std::size(scores) << '\n';    // 5
    return 0;
}
 scores    ┌─────┬─────┬─────┬─────┬─────┐
           │ 100 │ 80  │ 70  │ 60  │ 50  │
           └─────┴─────┴─────┴─────┴─────┘
 address:   0x100 0x104 0x108 0x10C 0x110       each int is 4 bytes

The length goes in square brackets after the name. There is no .size(), no .at() and no bounds checking of any kind.

Array decay

This is the property that makes C-style arrays hazardous.

C++
void print(int arr[])    // this really means: int* arr
{
    std::cout << sizeof(arr) << '\n';    // 8: the size of a pointer
}
flowchart LR
    A["int scores[5]<br/>knows it has 5 elements"] -->|"passed to a function"| P["int*<br/>only an address:<br/>the length is gone"]

When a C-style array is passed to a function, it converts to a pointer to its first element. This is decay. The function receives an address and nothing else, so the length has to travel as a separate argument:

C++
void print(const int* values, std::size_t length);

Nothing ensures the two stay in agreement. A wrong length means reading or writing beyond the array: the classic buffer overflow.

Pointer arithmetic

Because an array name converts to a pointer, pointers can be used to walk an array.

Expression Meaning
int* p{ scores }; p points at scores[0]
*(p + 2) The element two places on: scores[2]
p[2] Exactly the same thing
++p; p now points at the next element
Output
  p    p+1   p+2   p+3   p+4
  ▼     ▼     ▼     ▼     ▼
 [100] [80]  [70]  [60]  [50]

Adding 1 to a pointer moves it by one element, not one byte. For an int* that is 4 bytes. In fact a[i] is defined as *(a + i).

C-strings

A C-string is an array of char with a null terminator, the character '\0' (value 0), marking the end.

C++
char name[]{ "Ada" };    // four chars: 'A' 'd' 'a' '\0'
 ┌───┬───┬───┬────┐
 │ A │ d │ a │ \0 │
 └───┴───┴───┴────┘

No length is stored. Every function that needs it walks the characters until it meets the terminator.

Fact Consequence
A literal "hello" is a const char[6] Five letters plus the terminator
Functions live in <cstring> std::strlen, std::strcpy, std::strcmp
None of them check sizes Copying into too small an array overflows it
== on two char* compares addresses Not the text

Converting between the two worlds is easy:

C++
const char* greeting{ "Hello" };
std::string s{ greeting };            // C-string to std::string
const char* raw{ s.c_str() };         // std::string to C-string, for a C function

The modern equivalents

C style Modern C++
int a[5]; std::array<int, 5>
An array whose size is decided while running std::vector<int>
char s[100]; or const char* std::string or std::string_view
std::strlen(s) s.length()
std::strcmp(a, b) == 0 a == b
A pointer and a length std::span

std::span

std::span (C++20) is to arrays what std::string_view is to text: a pointer and a length carried together, with no ownership.

C++
#include <iostream>
#include <span>
#include <vector>

int sum(std::span<const int> data)
{
    int total{ 0 };
    for (int x : data)
    {
        total += x;
    }
    return total;
}

int main()
{
    int raw[]{ 1, 2, 3 };
    std::vector<int> v{ 4, 5 };
    std::cout << sum(raw) << ' ' << sum(v) << '\n';    // 6 9
    return 0;
}

One function accepts a C-style array, a std::array or a vector, and the length can never disagree with the data.
