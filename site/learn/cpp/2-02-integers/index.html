Integers

lesson 2.022 of 9 in milestone 25 min3 practice tasks

Integers hold whole numbers. Signed ones can be negative; unsigned ones cannot. Going past the limit is overflow: unsigned wraps round to the other end, and signed is undefined behaviour.

Signed and unsigned

An integer is a whole number. Every integer type comes in two versions.

 8 bits, signed    :  -128 ────────── 0 ────────── 127
 8 bits, unsigned  :                  0 ─────────────────────────── 255

Both have 256 values to spend. The signed version spends half of them below zero. The unsigned version starts at zero and reaches twice as high.

C++
int temperature{ -5 };             // signed: this is the default
unsigned int population{ 8000 };   // unsigned: never negative

Overflow

What happens when a number goes past the end of its range? Think of a car's mileage counter rolling from 99999 back to 00000.

flowchart LR
    A["unsigned: 255"] -->|"+ 1"| B["0"]
    C["unsigned: 0"] -->|"- 1"| D["4294967295"]
C++
#include <iostream>

int main()
{
    unsigned int u{ 0 };
    u = u - 1;
    std::cout << u << '\n';    // 4294967295
    return 0;
}

The two versions behave very differently here.

What overflow does
Unsigned Wraps round to the other end. Guaranteed, on every computer.
Signed Undefined behaviour. Anything may happen.
Signed overflow is undefined behaviour

int big{ 2147483647 }; ++big; has no defined result. In practice you often see a large negative number, but nothing promises that. If a value might pass two billion, use a bigger type.

Why not use unsigned for anything that cannot be negative?

It sounds sensible: a count is never negative, so make it unsigned. In practice this causes more bugs than it prevents.

C++
#include <iostream>

int main()
{
    unsigned int items{ 3 };
    int change{ -1 };
    std::cout << (change < items) << '\n';    // prints 0, meaning false
    return 0;
}

When signed and unsigned meet, the signed value is converted to unsigned. So -1 becomes 4294967295, which is not less than 3.

The rule this course follows

Use plain int for counts and arithmetic. Keep unsigned for working with individual bits (2.09 Bit Manipulation).

Integers with an exact size

When you need a guaranteed size, #include <cstdint> gives you types with the number of bits in the name.

Type Bits Range
std::int8_t / std::uint8_t 8 -128 to 127 / 0 to 255
std::int16_t / std::uint16_t 16 about ±32 thousand / 0 to 65,535
std::int32_t / std::uint32_t 32 about ±2.1 billion / 0 to 4.2 billion
std::int64_t / std::uint64_t 64 about ±9.2 billion billion

One more turns up constantly: std::size_t. It is the unsigned type C++ uses for sizes, including the result of sizeof.

The 8-bit types print as characters

std::cout << std::int8_t{ 65 }; prints A, not 65. On most systems these types are really char underneath.

Writing whole numbers in code

A value written directly in your code is called a literal. There are several ways to write an integer literal.

C++
int decimal{ 255 };
int hex{ 0xFF };                    // base 16, also 255
int binary{ 0b1111'1111 };          // base 2, also 255
int million{ 1'000'000 };           // ' is only there to help you read it
long long big{ 9'000'000'000LL };   // LL marks the literal as long long
Prefix or suffix Meaning
0x hexadecimal (base 16)
0b binary (base 2)
' between digits a separator the compiler ignores
LL at the end this literal is a long long
u at the end this literal is unsigned
A leading zero means octal

017 is not seventeen. A literal starting with 0 is read in base 8, so it is 15. Never pad a number with zeros.

Two reminders from Milestone 1

  • Dividing integers cuts off the decimals: 7 / 2 is 3.
  • With %, the sign of the result follows the left-hand side: -7 % 3 is -1.
