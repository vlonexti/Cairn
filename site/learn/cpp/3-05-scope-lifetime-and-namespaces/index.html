Scope, Lifetime and Namespaces

lesson 3.055 of 8 in milestone 35 min3 practice tasks

Scope is where in the code a name can be used. Lifetime is when during the run the variable exists. Namespaces group names so that two things called the same do not clash.

Two questions about every variable

Question Called Decided
On which lines may I use this name? Scope By where it is declared in the source
For how long does the value exist in memory? Lifetime While the program runs

For the local variables you have used so far the two coincide, which is why they are easy to mix up. They come apart in the next lesson.

Every pair of braces is a scope

A name declared inside a block can be used from its declaration to the block's closing brace.

┌─ main ───────────────────────────────────┐
│  int x{ 1 };                             │
│                                          │
│  ┌─ if block ─────────────────────────┐  │
│  │  int y{ 2 };                       │  │
│  │  can use: x, y                     │  │
│  │                                    │  │
│  │  ┌─ for block ──────────────────┐  │  │
│  │  │  int z{ 3 };                 │  │  │
│  │  │  can use: x, y, z            │  │  │
│  │  └──────────────────────────────┘  │  │
│  │  z is out of scope                 │  │
│  └────────────────────────────────────┘  │
│  y and z are out of scope                │
└──────────────────────────────────────────┘

Code can see outwards, never inwards. An inner block can use names from the blocks around it. An outer block cannot reach into an inner one.

Lifetime of a local variable

sequenceDiagram
    participant Code
    participant Memory
    Code->>Memory: execution reaches int y{ 2 }
    Note over Memory: y exists
    Code->>Memory: execution reaches the closing brace
    Note over Memory: y is destroyed

A local variable is created when execution reaches its definition and destroyed at the closing brace of its block. That is automatic, and it explains the name for this kind of lifetime: automatic storage duration.

Keep scopes small

Declare each variable in the smallest block that needs it, as close to its first use as you can. Fewer lines can touch it, so fewer lines can break it.

Shadowing

An inner block may declare a name that already exists in an outer block. The inner one hides the outer one until its block ends.

C++
#include <iostream>

int main()
{
    int apples{ 5 };
    {
        int apples{ 10 };               // a second, separate variable
        std::cout << apples << '\n';    // 10
    }
    std::cout << apples << '\n';        // 5
    return 0;
}

This is legal and almost always a mistake. You think you are changing one variable and you are changing another. Give the inner variable a different name.

Namespaces

As programs grow, names collide. Two libraries may each have a function called add. A namespace is a named group that keeps them apart, in the way a surname separates two people called Sam.

flowchart TD
    G["the global namespace"] --> STD["std<br/>cout, string, ..."]
    G --> M["Math<br/>add, pi"]
    G --> GA["Game<br/>add, Player"]
    GA --> GAU["Game::Utils<br/>clamp"]
C++
#include <iostream>

namespace Math
{
    constexpr double pi{ 3.14159 };

    int add(int a, int b)
    {
        return a + b;
    }
}

namespace Game::Utils
{
    int clamp(int value, int low, int high)
    {
        return value < low ? low : (value > high ? high : value);
    }
}

int main()
{
    std::cout << Math::add(2, 3) << ' ' << Math::pi << '\n';
    std::cout << Game::Utils::clamp(15, 0, 10) << '\n';    // 10
    return 0;
}

:: is the scope resolution operator. Read Math::add as "the add that lives in Math". You have used it since your first program: std::cout is "the cout in std".

A name declared outside every function and every namespace belongs to the global namespace.

using: shorter names, with a cost

Form Effect Verdict
using std::cout; Lets you write cout for this one name Fine inside a function or a .cpp file
using namespace std; Brings in every name from std Avoid
namespace GU = Game::Utils; A short alias for a long namespace Fine

[!danger] Why this course never writes using namespace std; std contains thousands of names, including common words such as count, max, distance and swap. Importing all of them invites clashes with your own names, and the errors that result are baffling. In a header it is worse still, because it leaks into every file that includes that header.
