Memory Layout, Alignment, Unions and Bit Fields

lesson 13.022 of 10 in milestone 136 min2 practice tasks

Every type has a size and an alignment: its address must be a multiple of the alignment. The compiler inserts padding to arrange that. Unions overlay members in the same memory. Bit fields pack members into bits. Endianness fixes the byte order. All of it matters for performance, file formats, networking and hardware.

Alignment and padding

A processor reads a value fastest, and on some architectures only, when it starts at an address that is a multiple of a particular number. That number is the type's alignment.

C++
struct Loose
{
    char a{};
    double b{};
    char c{};
};    // sizeof is 24

struct Tight
{
    double b{};
    char a{};
    char c{};
};    // sizeof is 16
Output
 Loose:  [a][· · · · · · ·][b b b b b b b b][c][· · · · · · ·]      24 bytes
          1    7 padding         8           1    7 padding

 Tight:  [b b b b b b b b][a][c][· · · · · ·]                        16 bytes
                8          1  1    6 padding
Rule Consequence
Each member is placed at the next offset that satisfies its alignment Padding appears between members
A struct's alignment is that of its most strictly aligned member
A struct's size is rounded up to a multiple of its alignment Padding appears at the end, so that arrays of the struct stay aligned
Members are laid out in declaration order Reordering them changes the size
Facility Does
sizeof(T) The size in bytes
alignof(T) The alignment
offsetof(S, member) The byte offset of a member
alignas(N) Requests a stricter alignment, for SIMD or to avoid false sharing (12.05 Atomics and the Memory Model)
[[no_unique_address]] Allows an empty member to occupy no space
Order members from the largest alignment to the smallest

That minimises padding without thought. Where a size matters, pin it down: static_assert(sizeof(Tight) == 16);

In a million-element array, the difference between 24 and 16 bytes is 8 MB, and more elements per cache line: 13.04 Performance, Caches and Data-Oriented Design.

Endianness

A multi-byte number has to be laid out in some byte order. For 0x12345678:

Output
 address:         +0    +1    +2    +3
 little-endian:   78    56    34    12      least significant byte first: x86, most ARM
 big-endian:      12    34    56    78      most significant byte first: "network byte order"
C++
#include <bit>

if constexpr (std::endian::native == std::endian::little)
{
    // this machine is little-endian
}

const std::uint32_t swapped{ std::byteswap(x) };    // C++23

Within one program it never matters. It matters the moment bytes leave the process: a file format or a network protocol must state its byte order, and code must convert explicitly. Serializing with shifts and masks (2.09 Bit Manipulation) gives the same bytes on every machine, because shifts are defined on values, not on memory.

Unions

A union gives all its members the same storage. Its size is that of its largest member.

C++
union Value
{
    int i;
    float f;
    char bytes[4];
};    // sizeof is 4
 ┌─────────────────┐
 │ i / f / bytes   │     one piece of storage; only the member last written is "active"
 └─────────────────┘
Rule Detail
One active member at a time Writing a member makes it the active one
Reading an inactive member is undefined in C++ It is permitted in C. Use std::bit_cast for punning: 13.01 Undefined Behavior and Object Lifetime
Members with non-trivial constructors or destructors You must construct and destroy them yourself, with std::construct_at and std::destroy_at

A union alone does not know which member is active. Pairing it with a discriminator gives a tagged union:

C++
struct Token
{
    enum class Kind { number, op } kind{};

    union
    {
        double number;
        char op;
    };
};

That is precisely what std::variant is, with the bookkeeping and lifetime management done correctly for you (10.04 std::optional, std::variant, std::any and std::tuple). Write a raw union only when you must match an externally defined layout.

Bit fields

A member can be given a width in bits.

C++
struct Flags
{
    std::uint8_t visible : 1;
    std::uint8_t solid : 1;
    std::uint8_t layer : 3;     // 0 to 7
    std::uint8_t unused : 3;
};    // sizeof is 1
Output
 one byte:  [unused unused unused][layer layer layer][solid][visible]

The compiler generates the shifts and masks. Assigning a value too large for the field truncates it.

Limitation Detail
No address You cannot take a pointer or reference to a bit field
Layout is implementation-defined The order of the fields within the storage unit, and how they straddle units, vary between compilers
Not atomic Adjacent bit fields share a memory location, so two threads writing different fields race
Not for portable formats

Because the layout varies, a bit-field struct written to a file by one compiler may be misread by another. For anything that crosses a boundary, use explicit shifts and masks.

Categories of type

Several operations are valid only for types with simple layouts.

Property Means Query
Trivially copyable Can be copied with memcpy and written as raw bytes std::is_trivially_copyable_v<T>
Standard layout Its layout is compatible with C std::is_standard_layout_v<T>
Aggregate Can be brace-initialized member by member std::is_aggregate_v<T>
Implicit-lifetime Can come into existence in raw storage without a constructor call

A type loses trivial copyability by having a user-provided copy operation or destructor, a virtual function, or a member that is not trivially copyable, such as a std::string.

Talking to C

C++
extern "C" void callback(int value);

C++ encodes a function's parameter types into its linker symbol, a process called name mangling, which is what makes overloading work. extern "C" turns that off for a declaration, so C code, or an operating system or another language, can find the function by its plain name. Such functions cannot be overloaded.
