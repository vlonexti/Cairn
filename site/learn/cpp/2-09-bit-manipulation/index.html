Bit Manipulation

lesson 2.099 of 9 in milestone 25 min3 practice tasks

Bitwise operators work on the individual bits of a number: & AND, | OR, ^ XOR, ~ NOT, << and >> shift. They let you pack many on/off settings into one number and pull packed values apart.

Why work with single bits?

A bool takes a whole byte to store one yes/no answer. One byte has eight bits, so it could hold eight. When memory is tight, or a file format or a piece of hardware dictates the layout, programmers pack several small values into one number and operate on its bits directly.

This lesson is the most technical in the milestone. It builds on 2.01 Memory, Bits and Fundamental Types and 2.02 Integers.

Binary and hexadecimal

Output
 position:    7    6    5    4    3    2    1    0
 worth:     128   64   32   16    8    4    2    1
 bits:        0    0    0    0    1    1    0    1     =  8 + 4 + 1  =  13

Bits are numbered from the right, starting at 0.

Hexadecimal (base 16) is the usual shorthand, because one hex digit is exactly four bits:

Hex Binary Hex Binary
0 0000 8 1000
1 0001 A 1010
4 0100 D 1101
7 0111 F 1111

So 0xFF is 1111 1111, a full byte of ones.

The six operators

Each works on every bit position separately.

Output
        a = 1100            a = 1100            a = 1100
        b = 1010            b = 1010            b = 1010
  a & b = 1000        a | b = 1110        a ^ b = 0110
     both are 1         either is 1        they differ

     ~a = 0011     every bit flipped
 a << 1 = 1000     moved left one place: the top bit falls off, a 0 comes in
 a >> 2 = 0011     moved right two places
Operator Name A result bit is 1 when
& AND both bits are 1
| OR either bit is 1
^ XOR the bits are different
~ NOT the bit was 0
<< left shift (moves bits left; each place doubles the value)
>> right shift (moves bits right; each place halves the value)
Do not confuse these with the logical operators

&& and || combine two bool values into one. & and | combine two numbers bit by bit. And here << shifts bits; it only means "print" when the left side is std::cout.

Seeing the bits

std::bitset prints a number in binary and has functions for individual bits.

C++
#include <bitset>
#include <iostream>

int main()
{
    std::bitset<8> bits{ 0b0000'1101 };
    std::cout << bits << '\n';            // 00001101
    bits.set(7);                          // switch bit 7 on
    bits.flip(0);                         // toggle bit 0
    std::cout << bits << '\n';            // 10001100
    std::cout << bits.test(2) << '\n';    // 1: bit 2 is on
    std::cout << bits.count() << '\n';    // 3 bits are on
    return 0;
}

Bit flags

A flag is a single yes/no setting. Give each flag its own bit by shifting a 1 into place. A value with one chosen bit set, used to pick that bit out, is called a mask.

C++
#include <cstdint>

constexpr std::uint8_t flagRead{ 1 << 0 };       // 0000 0001
constexpr std::uint8_t flagWrite{ 1 << 1 };      // 0000 0010
constexpr std::uint8_t flagExecute{ 1 << 2 };    // 0000 0100

There are exactly four things you ever do with a flag:

To Write Why it works
Switch on flags |= mask; OR with 1 forces the bit to 1
Switch off flags &= ~mask; AND with 0 forces the bit to 0; all other bits are ANDed with 1 and survive
Toggle flags ^= mask; XOR with 1 flips the bit
Test (flags & mask) != 0 AND leaves only that bit; non-zero means it was on
C++
std::uint8_t perms{ 0 };
perms |= flagRead;                            // 0000 0001
perms |= flagWrite;                           // 0000 0011
perms &= ~flagWrite;                          // 0000 0001
perms ^= flagExecute;                         // 0000 0101
bool canRead{ (perms & flagRead) != 0 };      // true

Packing and unpacking with masks

A colour on screen is three values from 0 to 255: red, green and blue. They are commonly packed into one 32-bit number written 0xRRGGBB.

Output
 color        = 0000 0000 | 1111 1111 | 1000 1000 | 0000 0000     0xFF8800
 color >> 8   =             0000 0000 | 1111 1111 | 1000 1000     green is now at the bottom
       & 0xFF =                                     1000 1000     keep only the lowest 8 bits

The pattern for extracting a field is always shift it to the bottom, then mask off the rest:

C++
std::uint32_t color{ 0xFF8800 };
std::uint32_t red{ (color >> 16) & 0xFF };      // 0xFF
std::uint32_t green{ (color >> 8) & 0xFF };     // 0x88
std::uint32_t blue{ color & 0xFF };             // 0x00

Packing is the reverse, shift each part into position, then OR them together:

C++
std::uint32_t packed{ (red << 16) | (green << 8) | blue };
Use unsigned types for bit work

Shifting a negative signed number gives results that depend on details you do not want to rely on. This is the main job unsigned types exist for.
