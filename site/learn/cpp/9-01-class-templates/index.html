Class Templates

lesson 9.011 of 6 in milestone 95 min3 practice tasks

A class template is a pattern for classes, parameterized by type: Box<int>, Box<std::string>. It is how std::vector<T> works. The compiler can often deduce the arguments (CTAD), and alias templates give long instantiations short names.

One template, many classes

4.02 Function Templates parameterized a function by type. A class template does the same for a class.

C++
#include <iostream>
#include <string>
#include <utility>

template <typename T>
class Box
{
public:
    explicit Box(T value) : m_value{ std::move(value) } {}

    const T& get() const { return m_value; }
    void set(T value) { m_value = std::move(value); }

private:
    T m_value{};
};

int main()
{
    Box<int> a{ 5 };
    Box<std::string> b{ "hello" };
    std::cout << a.get() << ' ' << b.get() << '\n';
    return 0;
}
flowchart TD
    T["template &lt;typename T&gt;<br/>class Box"] -->|"Box&lt;int&gt;"| I["class Box&lt;int&gt;<br/>int m_value"]
    T -->|"Box&lt;std::string&gt;"| S["class Box&lt;std::string&gt;<br/>std::string m_value"]
    T -->|"Box&lt;Point&gt;"| P["class Box&lt;Point&gt;<br/>Point m_value"]

Each distinct set of arguments instantiates a separate class. Box<int> and Box<std::string> are unrelated types: neither converts to the other, and each has its own static members.

Member functions of a class template are instantiated only if used. A Box<T> whose T lacks some operation is fine as long as no code calls the member that needs it.

Several parameters

C++
template <typename K, typename V>
struct Pair
{
    K key{};
    V value{};
};

Pair<std::string, int> score{ "Ann", 90 };

Defining members outside the class

C++
template <typename T>
class Stack
{
public:
    void push(const T& item);
    T pop();
    bool empty() const { return m_items.empty(); }

private:
    std::vector<T> m_items{};
};

template <typename T>
void Stack<T>::push(const T& item)
{
    m_items.push_back(item);
}

template <typename T>
T Stack<T>::pop()
{
    T top{ std::move(m_items.back()) };
    m_items.pop_back();
    return top;
}

Each out-of-class definition repeats the template header and qualifies the name with Stack<T>::. Inside the class's own scope, the bare name Stack means Stack<T>.

The whole template belongs in the header

As with function templates, the compiler needs the full definition at every point of use. Declarations and member definitions all go in the header.

Class template argument deduction

Since C++17 the compiler can deduce a class template's arguments from the constructor arguments. This is CTAD.

C++
std::pair p{ 1, 2.5 };       // std::pair<int, double>
std::vector v{ 1, 2, 3 };    // std::vector<int>
Box b{ 3.14 };               // Box<double>

Deduction guides

When the default deduction gives the wrong answer, a deduction guide states the mapping explicitly.

C++
Box(const char*) -> Box<std::string>;

Box text{ "hello" };    // Box<std::string>, not Box<const char*>

A guide has the form constructor-like signature -> resulting type. It affects only deduction; the object is then constructed by an ordinary constructor of the deduced class.

Alias templates

A using alias can itself take template parameters.

C++
template <typename T>
using Grid = std::vector<std::vector<T>>;

Grid<char> map(10, std::vector<char>(10, '.'));

template <typename V>
using StringMap = std::map<std::string, V>;

An alias template is purely a shorthand. Grid<char> is std::vector<std::vector<char>>, not a new type.

Default template arguments

C++
template <typename T, typename Container = std::vector<T>>
class Stack2
{
private:
    Container m_items{};
};

Stack2<int> a{};                     // stores in a std::vector<int>
Stack2<int, std::deque<int>> b{};    // stores in a std::deque<int>

This is how std::stack and std::queue are defined in the standard library: they are adaptors that provide an interface over a container you can choose.

Templates and inheritance compared

Both give "one piece of code, many types". They differ in when the type is fixed.

Class template Virtual functions
Type chosen At compile time At run time
Cost per call None; calls can be inlined An indirect call
Different types in one container No: Box<int> and Box<double> are unrelated Yes, through a base pointer
Requirement on the type It must support the operations used It must derive from the base

They are sometimes called static and dynamic polymorphism.
