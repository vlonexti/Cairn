Vector as a Stack, and Capacity

lesson 5.033 of 11 in milestone 55 min3 practice tasks

A vector has a size (elements in use) and a capacity (room reserved). When it runs out of room it reallocates. push_back, pop_back and back make it a natural stack: last in, first out.

Size and capacity

A vector usually reserves more room than it is using, so that adding an element does not always require new memory.

 size is 3                capacity is 4
 ┌──────┬──────┬──────┬──────┐
 │  10  │  20  │  30  │      │    one slot reserved, not yet in use
 └──────┴──────┴──────┴──────┘
Meaning
v.size() How many elements it holds
v.capacity() How many it could hold before needing more memory

Reallocation

When the capacity is used up, the next push_back cannot extend the block in place. The vector reallocates:

flowchart LR
    A["old block, capacity 4<br/>10 20 30 40"] -->|"1. allocate a larger block"| B["new block, capacity 8"]
    B -->|"2. move the elements across"| C["10 20 30 40 _ _ _ _"]
    C -->|"3. add 50, release the old block"| D["10 20 30 40 50 _ _ _"]

Each reallocation grows the capacity by a factor (1.5 with Microsoft's compiler, 2 with most others), so reallocations become rarer as the vector grows. Averaged over many calls, push_back takes constant time. The term for that is amortized constant time.

C++
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> v{};
    for (int i{ 0 }; i < 10; ++i)
    {
        v.push_back(i);
        std::cout << "size " << v.size() << "  capacity " << v.capacity() << '\n';
    }
    return 0;
}
Reallocation invalidates everything that points into the vector

After a reallocation the elements live at new addresses. Any pointer, reference or iterator to an element obtained earlier now refers to released memory.

C++
int& first{ v[0] };
v.push_back(99);    // may reallocate
first = 1;          // undefined behaviour if it did

This is called invalidation, and it is one of the most common sources of subtle bugs in C++.

reserve and resize

reserve(n) resize(n)
Changes the size No Yes, to n
Changes the capacity To at least n Only if needed
Creates elements No Yes, with default values
Use it when You are about to push_back roughly n elements You want n elements to exist now
C++
std::vector<int> v{};
v.reserve(1000);    // one allocation, done in advance
for (int i{ 0 }; i < 1000; ++i)
{
    v.push_back(i);    // never reallocates
}

When you know roughly how many elements are coming, reserve is a free speed-up. It also guarantees that no invalidation happens during the fill.

A vector as a stack

A stack is a collection where you add and remove at the same end. The last item in is the first out, abbreviated LIFO.

 push 1      push 2      push 3      pop
 ┌───┐       ┌───┐       ┌───┐       ┌───┐
 │   │       │   │       │ 3 │ top   │   │
 │   │       │ 2 │ top   │ 2 │       │ 2 │ top
 │ 1 │ top   │ 1 │       │ 1 │       │ 1 │
 └───┘       └───┘       └───┘       └───┘

The end of a vector is exactly where adding and removing are cheap.

Stack operation Vector call
Push v.push_back(x)
Look at the top v.back()
Pop v.pop_back()
Is it empty? v.empty()
C++
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> stack{};
    stack.push_back(1);
    stack.push_back(2);
    stack.push_back(3);
    std::cout << stack.back() << '\n';    // 3
    stack.pop_back();
    std::cout << stack.back() << '\n';    // 2
    return 0;
}

[!warning] pop_back returns nothing Read back() first if you need the value. And both back() and pop_back() on an empty vector are undefined behaviour, so check empty() first.

Stacks are everywhere: undo history, matching brackets, evaluating expressions, backtracking through a maze. The mechanism that tracks your own function calls is a stack too. The library also offers std::stack<T> in <stack>, a thin wrapper with push, pop and top.

emplace_back

push_back takes a finished element and puts it in. emplace_back takes the ingredients and builds the element directly inside the vector.

C++
struct Point
{
    int x{};
    int y{};
};

std::vector<Point> points{};
points.push_back({ 1, 2 });    // build a Point, then move it in
points.emplace_back(3, 4);     // build it in place

For simple types the difference is negligible. It matters for elements that are expensive to construct.
