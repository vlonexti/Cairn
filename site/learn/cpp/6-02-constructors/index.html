Constructors

lesson 6.022 of 9 in milestone 65 min3 practice tasks

A constructor is a special member function that runs when an object is created and puts it in a valid state. Initialize members in a member initializer list. Know the default, delegating, converting (explicit) and copy constructors.

Born valid

If the data is private, how does an object get its starting values? Through a constructor: a member function with the same name as the class and no return type. It runs automatically whenever an object is created.

C++
#include <iostream>

class Fraction
{
public:
    Fraction(int numerator, int denominator)
        : m_numerator{ numerator }, m_denominator{ denominator }
    {
        if (m_denominator == 0)
        {
            m_denominator = 1;
        }
    }

    double value() const
    {
        return static_cast<double>(m_numerator) / m_denominator;
    }

private:
    int m_numerator{};
    int m_denominator{ 1 };
};

int main()
{
    Fraction half{ 1, 2 };
    std::cout << half.value() << '\n';    // 0.5
    return 0;
}

Because construction always goes through this function, an invalid Fraction can never exist. The invariant holds from the first moment.

The member initializer list

The part after the colon is the member initializer list. It initializes each member directly.

C++
Fraction(int n, int d) : m_numerator{ n }, m_denominator{ d } {}    // initializes
Fraction(int n, int d) { m_numerator = n; m_denominator = d; }      // initializes with defaults, then assigns
Initializer list Assignment in the body
Steps One Two: default-initialize, then overwrite
Works for const members Yes No
Works for reference members Yes No
Works for members with no default constructor Yes No

Use the list for initializing members. Use the body for anything else, such as validation.

[!warning] Members are initialized in the order they are declared The order you write them in the list is ignored. If one member's initializer uses another member, the declaration order decides whether that is safe. Keep the list in declaration order so the code says what actually happens.

Default constructor

A constructor that can be called with no arguments is the default constructor. It is what Fraction f{}; uses.

C++
class Fraction
{
public:
    Fraction() = default;
    Fraction(int numerator, int denominator = 1)
        : m_numerator{ numerator }, m_denominator{ denominator }
    {
    }

private:
    int m_numerator{ 0 };
    int m_denominator{ 1 };
};

Fraction a{};        // 0/1
Fraction b{ 5 };     // 5/1
Fraction c{ 3, 4 };  // 3/4

If a class declares no constructors, the compiler supplies a default one. As soon as you write any constructor, it stops. = default asks for the compiler's version back; it uses the default member initializers.

Delegating constructors

One constructor can hand the work to another, so shared setup is written once.

C++
class Employee
{
public:
    Employee(std::string_view name, int id) : m_name{ name }, m_id{ id } {}
    Employee(std::string_view name) : Employee{ name, 0 } {}

private:
    std::string m_name{};
    int m_id{};
};

Converting constructors and explicit

A constructor callable with one argument also defines an implicit conversion from that argument's type.

C++
class Meters
{
public:
    Meters(double value) : m_value{ value } {}

private:
    double m_value{};
};

void run(Meters distance);

run(5.0);    // compiles: 5.0 is silently converted to a Meters

Occasionally that is what you want. More often it hides a mistake. explicit switches the implicit conversion off:

C++
explicit Meters(double value) : m_value{ value } {}

run(5.0);              // error
run(Meters{ 5.0 });    // fine: the conversion is visible

[!tip] Make single-argument constructors explicit by default Remove it only when the conversion is natural and harmless, as with std::string from a string literal.

Copy constructor

Creating an object from another of the same type uses the copy constructor.

C++
Fraction a{ 1, 2 };
Fraction b{ a };    // b is a copy of a

The compiler writes one for you that copies each member in turn. That is correct for classes like Fraction. It is wrong for classes that own a resource such as memory, which is the subject of 7.03 Copy Semantics — Shallow vs Deep.

Copy elision

C++
Fraction make()
{
    return Fraction{ 1, 3 };
}

Fraction f{ make() };    // no copy is made

The compiler constructs the result directly in f. Skipping the copy like this is copy elision, and in this form C++17 guarantees it. Returning objects by value is therefore cheap.

Temporary objects

An object can be created without a name, used once and discarded.

C++
print(Fraction{ 2, 3 });
std::cout << Fraction{ 1, 2 }.value() << '\n';

A temporary lives until the end of the statement that created it.

constexpr constructors

A constructor can be constexpr, which allows objects of the class to be built at compile time.

C++
class Color
{
public:
    constexpr Color(int r, int g, int b) : m_r{ r }, m_g{ g }, m_b{ b } {}
    constexpr int red() const { return m_r; }

private:
    int m_r{};
    int m_g{};
    int m_b{};
};

constexpr Color orange{ 255, 136, 0 };

Which constructor runs?

Code Constructor
T t{}; Default
T t{ a, b }; The one whose parameters match
T t{ other }; Copy
T t = 5; Converting, unless it is explicit
