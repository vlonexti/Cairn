Choosing STL Containers

lesson 10.011 of 9 in milestone 106 min2 practice tasks

The standard library offers sequence containers (ordered by position), associative containers (sorted by key), unordered containers (hash tables) and adaptors (stack, queue, priority queue). Default to std::vector, and switch only when a specific operation needs to be faster.

Big-O (5.11 Sorting, Searching, Big-O and Timing Your Code) is not the whole story. It counts steps and says nothing about how long a step takes. Following a pointer to a node somewhere else in memory can be a hundred times slower than reading the next element of an array.

A vector often beats a list where theory says it should not

Inserting in the middle of a std::list is O(1) and in a std::vector it is O(n). Yet for small and medium sizes the vector usually wins, because shifting contiguous elements is fast and reaching the insertion point in a list is not. Measure before switching: 13.04 Performance, Caches and Data-Oriented Design.

std::list is absent from the chart on purpose. Its real advantages are narrow: iterators and references to its elements stay valid through insertions and removals elsewhere, and whole sections can be moved between lists in constant time. Choose it for those, not for speed.

Iterator invalidation

Which operations invalidate iterators, pointers and references into the container is part of each container's contract, and a frequent source of bugs.

Container Insertion invalidates Erasure invalidates
vector Everything, if it reallocates; otherwise from the insertion point on From the erased element on
deque All iterators All iterators, unless at an end
list, set, map Nothing Only the erased element
unordered_* All iterators, if it rehashes Only the erased element

Adaptors

An adaptor wraps another container and exposes only the operations of a particular data structure.

C++
#include <iostream>
#include <queue>
#include <stack>
#include <vector>

int main()
{
    std::stack<int> stack{};    // last in, first out
    stack.push(1);
    stack.push(2);
    std::cout << stack.top() << '\n';    // 2

    std::queue<int> queue{};    // first in, first out
    queue.push(1);
    queue.push(2);
    std::cout << queue.front() << '\n';    // 1

    std::priority_queue<int> largestFirst{};
    largestFirst.push(5);
    largestFirst.push(9);
    largestFirst.push(2);
    std::cout << largestFirst.top() << '\n';    // 9

    std::priority_queue<int, std::vector<int>, std::greater<>> smallestFirst{};
    smallestFirst.push(5);
    smallestFirst.push(9);
    smallestFirst.push(2);
    std::cout << smallestFirst.top() << '\n';    // 2
    return 0;
}
Adaptor Order Default underlying container
std::stack LIFO deque
std::queue FIFO deque
std::priority_queue Largest first vector, arranged as a heap

A priority queue gives O(log n) insertion and removal with O(1) access to the top. As with the vector-based stack, pop() returns nothing: read top() or front() first.

A shared interface

Nearly every container provides size(), empty(), clear(), begin() and end(), insert, erase, emplace, swap and comparison operators. That uniformity is why one algorithm works across all of them, and why switching container later is usually a small change. Hide the choice behind a type alias and it is a one-line change.
