Classes and Objects

lesson 6.011 of 9 in milestone 65 min3 practice tasks

A class combines data (member variables) with the functions that work on it (member functions). The data is usually private, and the public functions are the only way in. That protection is called encapsulation.

The problem with a plain struct

C++
struct Account
{
    double balance{};
};

void deposit(Account& account, double amount)
{
    account.balance += amount;
}

Nothing stops any line of code, anywhere, from writing account.balance = -1000000;. The rule "a balance is never negative" exists only in the programmer's head.

A class lets the type itself enforce its rules.

C++
#include <iostream>

class BankAccount
{
public:
    void deposit(double amount)
    {
        if (amount > 0)
        {
            m_balance += amount;
        }
    }

    bool withdraw(double amount)
    {
        if (amount <= 0 || amount > m_balance)
        {
            return false;
        }
        m_balance -= amount;
        return true;
    }

    double balance() const
    {
        return m_balance;
    }

private:
    double m_balance{ 0.0 };
};

int main()
{
    BankAccount account{};
    account.deposit(100);
    account.withdraw(30);
    std::cout << account.balance() << '\n';    // 70
    // account.m_balance = -5;    error: m_balance is private
    return 0;
}

The balance can now change only through deposit and withdraw, and both refuse invalid amounts.

Class and object

A class is a type. An object is one value of that type. One class, any number of objects, each with its own data.

flowchart LR
    C["class BankAccount<br/>(the type)"] --> A["alice<br/>balance 500"]
    C --> B["bob<br/>balance 20"]
    C --> D["carol<br/>balance 9000"]
Term Meaning
Member variable Data stored in each object (m_balance)
Member function A function that belongs to the class and works on one object (deposit)
Object or instance One value of the class type (account)

A member function is called on an object with the dot: account.deposit(100). Inside it, member names such as m_balance refer to that object's data.

Access specifiers

Specifier Who may use it
public Any code
private Only the class's own member functions
protected The class and classes derived from it: 8.02 Inheritance and Access

The public part is the class's interface: what users of the class can do. The private part is its implementation: how it does it.

class and struct

The language makes exactly one distinction: members of a class are private unless you say otherwise, and members of a struct are public.

The convention built on that is what matters:

Use When
struct Plain data with no rules to protect: Point, Color
class There is a rule that must always hold, so the data is private

A rule that must hold for an object to be valid is an invariant. "The balance is never negative" is one. "The denominator is never zero" is another. Protecting invariants is the reason classes exist.

This course prefixes member variables with m_ so they stand out from parameters and local variables.

Access functions

A function that reports a private value is a getter. One that changes it is a setter.

C++
class Player
{
public:
    const std::string& name() const { return m_name; }
    int health() const { return m_health; }
    void setHealth(int health) { m_health = std::clamp(health, 0, 100); }

private:
    std::string m_name{};
    int m_health{ 100 };
};

The setter is where the invariant is enforced: health stays between 0 and 100 whatever the caller passes. The const after the parameter list promises that the function does not modify the object: 6.04 this, const Member Functions and Chaining.

Do not write a getter and setter for every member by reflex

That simply rebuilds a struct with extra typing. Ask what the object should be able to do. player.takeDamage(10) expresses intent and keeps the rule inside the class. player.setHealth(player.health() - 10) pushes the arithmetic, and the chance to get it wrong, onto every caller.

What encapsulation buys you

Benefit Why
Invariants hold No outside code can put the object in an invalid state
The implementation can change Switch double m_balance to an integer number of cents and no caller needs to change
Bugs are easier to find Only the member functions can modify the data, so there are few places to look
