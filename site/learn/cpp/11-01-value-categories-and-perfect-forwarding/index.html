Value Categories and Perfect Forwarding

lesson 11.011 of 7 in milestone 116 min2 practice tasks

Every expression has a type and a value category: lvalue, xvalue or prvalue. In a template, T&& is a forwarding reference: it binds to anything and records whether the argument was an lvalue or an rvalue. std::forward<T>(x) passes it on with that category intact, which is perfect forwarding.

Value categories, precisely

7.05 Move Semantics used a two-way split into lvalues and rvalues. The standard uses three primary categories, defined by two independent properties: does the expression have identity (does it refer to a particular object), and may its resources be moved from?

flowchart TD

    E --> R["rvalue<br/>may be moved from"]
    GL --> L["lvalue<br/>x, *p, v[0], a call returning T&"]
    GL --> X["xvalue<br/>std::move(x), a call returning T&&"]
    R --> X
    R --> PR["prvalue<br/>42, x + 1, T{}, a call returning T"]
Category Identity Movable Examples
lvalue Yes No x, *p, v[0], a string literal
xvalue ("expiring") Yes Yes std::move(x), static_cast<T&&>(x)
prvalue ("pure rvalue") No Yes 42, x + 1, T{}, make()

A value category is a property of an expression, not of an object or a type. The same object can be named by an lvalue expression (x) and by an xvalue expression (std::move(x)).

A named rvalue reference is an lvalue
C++
void f(std::string&& s)
{
    g(s);               // s is a name, so this expression is an lvalue: g copies
    g(std::move(s));    // an xvalue: g may move
}

The type of s is std::string&&. The value category of the expression s is lvalue, because it has a name and could be used again. This is what makes forwarding necessary.

Forwarding references

T&& has a special meaning when, and only when, T is a template parameter deduced from that very parameter.

C++
template <typename T>
void wrapper(T&& arg);       // forwarding reference: binds to anything

void f(std::string&& s);     // rvalue reference: binds to rvalues only
auto&& x{ expression };      // also a forwarding reference
Declaration Kind
template <typename T> void f(T&&) Forwarding reference
auto&& Forwarding reference
void f(Widget&&) Rvalue reference: no deduction
template <typename T> void f(const T&&) Rvalue reference: const disqualifies it
template <typename T> void f(std::vector<T>&&) Rvalue reference: not of the form T&&

Reference collapsing

Two rules produce the behaviour.

A special deduction rule. When an lvalue of type A is passed to T&&, T is deduced as A&. When an rvalue is passed, T is deduced as A.

Reference collapsing. A reference to a reference, which can only arise through templates and aliases, collapses:

Output
 &  &   becomes  &        &  &&  becomes  &
 && &   becomes  &        && &&  becomes  &&

 an lvalue reference anywhere wins
Argument T deduced as T&& becomes
An lvalue std::string std::string& std::string& &&, which collapses to std::string&
An rvalue std::string std::string std::string&&

So T itself encodes the argument's original value category.

std::forward

Inside wrapper, arg is a name and therefore an lvalue, whatever was passed. std::forward<T>(arg) restores the original category by reading it back out of T.

C++
#include <iostream>
#include <string>
#include <utility>

void process(const std::string&) { std::cout << "copy\n"; }
void process(std::string&&)      { std::cout << "move\n"; }

template <typename T>
void relay(T&& arg)
{
    process(std::forward<T>(arg));
}

int main()
{
    std::string name{ "Ann" };
    relay(name);                    // copy
    relay(std::string{ "Bo" });     // move
    relay(std::move(name));         // move
    return 0;
}
flowchart LR
    A["relay(name)<br/>an lvalue"] --> F["T is std::string&amp;<br/>forward yields an lvalue"] --> C["process(const std::string&amp;)"]
    B["relay(temporary)<br/>an rvalue"] --> G["T is std::string<br/>forward yields an rvalue"] --> M["process(std::string&amp;&amp;)"]

std::forward<T>(arg) is static_cast<T&&>(arg). With T as std::string& it collapses to an lvalue reference; with T as std::string it is an rvalue reference.

std::move(x) std::forward<T>(x)
Produces Always an rvalue An lvalue or an rvalue, as recorded in T
Use with An rvalue reference or object you are finished with A forwarding reference
Template argument Deduced Must be written explicitly

The standard use: wrapping construction

C++
template <typename T, typename... Args>
std::unique_ptr<T> make(Args&&... args)
{
    return std::unique_ptr<T>{ new T(std::forward<Args>(args)...) };
}

Each argument reaches T's constructor exactly as the caller supplied it: lvalues are copied from, rvalues moved from, and nothing is copied in between. std::make_unique, emplace_back and the constructor of std::thread all work this way.

decltype and decltype(auto)

Expression Yields
decltype(x) where x is a name The declared type of x
decltype((x)), or any other lvalue expression of type T T&
decltype( an xvalue ) T&&
decltype( a prvalue ) T
C++
int x{};
decltype(x) a{};        // int
decltype((x)) b{ x };   // int&: the parentheses make it an expression, not a name

auto strips references and top-level const. decltype(auto) deduces with the decltype rules, preserving them. That is what a forwarding wrapper needs for its return type:

C++
template <typename F, typename... Args>
decltype(auto) call(F&& f, Args&&... args)
{
    return std::forward<F>(f)(std::forward<Args>(args)...);
}

If f returns a reference, so does call. std::invoke(f, args...) generalises the call itself to member function pointers and member data pointers.
