CMake, Libraries and Package Managers

lesson 10.099 of 9 in milestone 105 min1 practice task

Real projects have many files and use third-party libraries. CMake describes what to build portably and generates the build files for your tools. Libraries are static (copied into your executable) or dynamic (loaded while running). vcpkg and Conan download libraries for you.

Beyond a single program

Xenon compiles your files for you. A real project needs a description of what to build: which source files form which programs and libraries, with which settings, depending on which outside code. This lesson is about that machinery. It cannot be run inside Xenon, but you will need it for your first project outside.

Using a library takes three things

What Who needs it Why
The headers The compiler To know what the library declares
The library file The linker To resolve the calls
The dynamic library, if there is one The running program It must be found beside the executable or on the system path

Missing headers give compile errors. A missing library file gives "unresolved external symbol". A missing DLL gives an error when the program starts. Knowing which stage failed tells you which of the three is wrong (1.08 Multiple Files and Headers).

CMake

CMake does not compile anything. It reads a description of your project and generates build files for whatever tool you use: a Visual Studio solution, Makefiles or Ninja files.

 my_game/
 ├── CMakeLists.txt
 ├── src/
 │   ├── main.cpp
 │   └── game/
 │       ├── Player.h
 │       └── Player.cpp
 └── tests/
     └── test_player.cpp

CMakeLists.txt

CMake
cmake_minimum_required(VERSION 3.25)
project(MyGame VERSION 1.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# A library holding the game logic
add_library(game_core src/game/Player.cpp)
target_include_directories(game_core PUBLIC src)

if (MSVC)
    target_compile_options(game_core PRIVATE /W4 /permissive-)
else()
    target_compile_options(game_core PRIVATE -Wall -Wextra -Wconversion -pedantic)
endif()

# The program
add_executable(my_game src/main.cpp)
target_link_libraries(my_game PRIVATE game_core)

Building

Terminal
cmake -S . -B build
Terminal
cmake --build build --config Release
flowchart LR
    CM["CMakeLists.txt"] -->|"configure:<br/>cmake -S . -B build"| G["build/<br/>generated build files"]
    G -->|"build:<br/>cmake --build build"| E["my_game.exe"]

Everything generated goes into build/, separate from your sources. Visual Studio, CLion and VS Code all open a CMake project directly.

Targets

Modern CMake is organised around targets: a library or an executable, together with what it needs.

Command Does
add_executable(name sources...) Defines a program
add_library(name sources...) Defines a library
target_include_directories(...) Says where a target's headers are
target_compile_options(...) Adds compiler flags for a target
target_link_libraries(a PRIVATE b) Makes a use b

Each property carries a visibility keyword that says who it applies to.

Keyword Applies to
PRIVATE This target only
PUBLIC This target and everything that links to it
INTERFACE Only the things that link to it (as for a header-only library)

game_core's include directory is PUBLIC, so my_game receives it automatically by linking to game_core. Putting the logic in a library, with a thin executable on top, also lets a test program link the same library.

Getting third-party libraries

FetchContent

Built into CMake: it downloads and builds a dependency as part of your project.

CMake
include(FetchContent)
FetchContent_Declare(fmt
    GIT_REPOSITORY https://github.com/fmtlib/fmt.git
    GIT_TAG 11.0.2)
FetchContent_MakeAvailable(fmt)

target_link_libraries(my_game PRIVATE fmt::fmt)

vcpkg

A package manager downloads, builds and caches libraries, so each project only lists what it needs. vcpkg is Microsoft's; it works on every platform.

Terminal
vcpkg new --application
Terminal
vcpkg add port raylib nlohmann-json
CMake
find_package(raylib CONFIG REQUIRED)
target_link_libraries(my_game PRIVATE raylib)

Pass vcpkg's toolchain file when configuring, and find_package locates what it installed. Conan is a widely used alternative with the same purpose.

Approach Good for
FetchContent A few small dependencies; nothing extra to install
vcpkg or Conan Many or large dependencies; builds are cached and shared across projects
