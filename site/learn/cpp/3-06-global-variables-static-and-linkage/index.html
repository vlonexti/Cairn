Global Variables, static and Linkage

lesson 3.066 of 8 in milestone 35 min3 practice tasks

Globals exist for the whole run of the program. Linkage decides whether other .cpp files can see a name. A static local keeps its value between calls. Avoid globals that can change.

Global variables

A variable defined outside every function is global. Any function below it in the file can use it.

C++
#include <iostream>

int g_score{ 0 };

void addPoints()
{
    g_score += 10;
}

int main()
{
    addPoints();
    std::cout << g_score << '\n';    // 10
    return 0;
}
Local variable Global variable
Scope Its block The rest of the file
Lifetime Until its block ends The whole run: created before main, destroyed after it
If you give no value Unpredictable Zero

Here scope and lifetime separate. This lifetime is called static storage duration. The g_ prefix is a common convention that marks a name as global.

Avoid globals that can change

When any function anywhere can modify g_score, a wrong value makes every function a suspect. A function that only uses its parameters can be understood and tested on its own. Pass values in as arguments and hand results back with return.

Global constants are fine. Nothing can change them, so nothing can break them.

Linkage: can other files see it?

Scope is about one file. In a program with several .cpp files there is a further question: can a name defined in one file be used from another? That property is linkage.

Linkage Meaning
External One shared thing that every file can refer to
Internal Private to this file. Another file may use the same name for something else.

What you write at file level decides which you get:

Written outside any function Linkage Typical use
void helper(); or a function definition external Functions other files call
int counter{ 0 }; external (A changeable global: avoid)
static void helper() internal A helper that only this file needs
namespace { void helper() {} } internal The modern way to say the same
constexpr int limit{ 5 }; internal A constant used in one file
inline constexpr int limit{ 5 }; in a header external A constant shared by many files

To use another file's external variable you declare it with extern: "this exists, and it is defined somewhere else". The usual place for such declarations is a header.

inline: defined in a header, without breaking the rule

You met the One Definition Rule in 1.08 Multiple Files and Headers: a definition may appear only once in the program. A header is pasted into every file that includes it, so anything defined in a header would break that rule.

inline is the exception. It tells the linker: "this definition will turn up in several files; they are all the same one."

C++
// constants.h
#pragma once

namespace constants
{
    inline constexpr double gravity{ 9.81 };
    inline constexpr int maxPlayers{ 4 };
}

This is the standard way to share constants. It is also why the Random helper in 3.04 Random Numbers used inline.

static locals: a function with a memory

Put static on a local variable and it gets the long lifetime of a global while keeping the small scope of a local.

C++
#include <iostream>

int nextId()
{
    static int s_id{ 0 };    // initialized once, the first time through
    return ++s_id;
}

int main()
{
    std::cout << nextId() << ' ' << nextId() << ' ' << nextId() << '\n';    // 1 2 3
    return 0;
}
Call s_id before s_id after
first 0 1
second 1 2
third 2 3

An ordinary local would be created afresh at 0 on every call. Only nextId can touch s_id, which makes this far safer than a global counter.

One word, several meanings

static is the most overloaded keyword in C++. Its meaning depends on where it appears.

Where Meaning
On a local variable Lives for the whole run and keeps its value between calls
On a global variable or function Internal linkage: private to this file
On a class member Shared by all objects of the class: 6.05 Static Members and Friends
