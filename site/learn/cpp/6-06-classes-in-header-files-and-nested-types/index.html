Classes in Header Files and Nested Types

lesson 6.066 of 9 in milestone 65 min3 practice tasks

Put the class definition in Name.h and the member function bodies in Name.cpp, written as ClassName::function. Small functions can stay in the header. Types can be nested inside a class, as in Player::State.

Splitting a class across files

The pattern from 1.08 Multiple Files and Headers applies to classes: the header says what exists, and the source file says how it works.

flowchart LR
    H["Date.h<br/>the class definition:<br/>members and declarations"] -.->|"#include"| C["Date.cpp<br/>the member function bodies"]
    H -.->|"#include"| M["main.cpp<br/>uses Date"]

Date.h

C++
#pragma once
#include <string>

class Date
{
public:
    Date(int year, int month, int day);

    void print() const;
    std::string toString() const;

    int year() const { return m_year; }

private:
    int m_year{};
    int m_month{};
    int m_day{};
};

Date.cpp

C++
#include "Date.h"
#include <iostream>

Date::Date(int year, int month, int day)
    : m_year{ year }, m_month{ month }, m_day{ day }
{
}

void Date::print() const
{
    std::cout << toString() << '\n';
}

std::string Date::toString() const
{
    return std::to_string(m_year) + '-' + std::to_string(m_month) + '-' + std::to_string(m_day);
}

Outside the class, every member function's name is prefixed with Date::. That is the scope resolution operator from 3.05 Scope, Lifetime and Namespaces, saying "the print that belongs to Date".

The definition must match the declaration exactly

The const is part of the function's signature. void Date::print() without it defines a different function, and the compiler reports that no such member was declared.

What goes where

In the header In the .cpp file
The class definition, with all its members The bodies of member functions of any size
One-line functions such as getters Helper functions only this file needs
Templates, in full Definitions of static data that is not inline

A member function defined inside the class is implicitly inline, so it does not break the One Definition Rule when the header is included from several files.

Why not put everything in the header? Each file that includes the header recompiles all of it, and any change to a function body forces every such file to rebuild. Keeping bodies in the .cpp file keeps builds fast and hides the implementation.

Public first

List the public section first and the private section last. People reading a header want the interface; the private members are detail.

Nested types

A type can be declared inside a class.

C++
class Player
{
public:
    enum class State { idle, running, jumping };

    struct Stats
    {
        int strength{};
        int dexterity{};
    };

    using Id = int;

    State state() const { return m_state; }

private:
    State m_state{ State::idle };
    Stats m_stats{};
    Id m_id{};
};

Player::State s{ Player::State::running };

From outside, a nested type is named through the class: Player::State.

Reason to nest Example
The type only makes sense with the class Player::State
It avoids a clash Player::State and Door::State coexist
It can be hidden A nested type in the private section cannot be named outside

Forward declarations

To declare a function that takes a Foo& or Foo*, the compiler needs to know that Foo is a class. It does not need the class's contents.

C++
class Foo;                 // forward declaration: "Foo is a class, defined elsewhere"

void process(Foo& foo);    // fine: the size of Foo is not needed
The header uses Foo as Needs
A reference or pointer, in declarations A forward declaration is enough
A member by value, or calls its functions #include "Foo.h"

Forward declarations cut down what each file has to compile, and they are the only way out when two classes refer to each other: neither header can include the other first.
