Concepts (C++20)

lesson 9.044 of 6 in milestone 95 min3 practice tasks

A concept is a named compile-time requirement on template arguments, such as "T must be a number" or "T must be printable". Constrained templates give clear error messages and let you overload on what a type can do. They live in <concepts>.

The problem

An unconstrained template accepts any type, and fails only when some line deep in its body does not compile for it.

C++
template <typename T>
T average(const std::vector<T>& values);    // adds with + and divides

average(std::vector<std::string>{ "a", "b" });
// dozens of lines of errors from inside the template

The requirement "T must be a number" exists, but only implicitly, in the body. A concept states it in the declaration.

A constrained template

C++
#include <concepts>
#include <iostream>
#include <vector>

template <typename T>
concept Number = std::integral<T> || std::floating_point<T>;

template <Number T>
double average(const std::vector<T>& values)
{
    if (values.empty())
    {
        return 0.0;
    }
    double total{ 0.0 };
    for (const T& v : values)
    {
        total += static_cast<double>(v);
    }
    return total / static_cast<double>(values.size());
}

int main()
{
    std::cout << average(std::vector{ 1, 2, 4 }) << '\n';    // 2.33333
    // average(std::vector<std::string>{ "a" });   error: std::string does not satisfy Number
    return 0;
}

A concept is a compile-time predicate on types: for any T, Number<T> is true or false. A type for which it is true satisfies (or models) the concept. The error for a bad argument now appears at the call, in terms of the requirement.

Four ways to write a constraint

All four mean the same thing.

C++
template <std::integral T>                 // 1. in place of typename
T half(T x) { return x / 2; }

template <typename T>
    requires std::integral<T>              // 2. a requires-clause
T half2(T x) { return x / 2; }

template <typename T>
T half3(T x) requires std::integral<T>     // 3. a trailing requires-clause
{
    return x / 2;
}

auto half4(std::integral auto x)           // 4. the abbreviated form
{
    return x / 2;
}
Form Best for
1 One simple constraint per parameter
2 Compound constraints, or constraints relating several parameters
3 Member functions of class templates
4 Short functions

Writing your own: requires-expressions

A requires-expression lists code that must be valid for the concept to hold. Nothing in it is executed; the compiler only checks that it would compile.

C++
template <typename T>
concept Printable = requires(std::ostream& out, const T& value)
{
    { out << value } -> std::same_as<std::ostream&>;
};

template <typename T>
concept Shape = requires(const T& shape)
{
    { shape.area() } -> std::convertible_to<double>;
    { shape.name() } -> std::convertible_to<std::string_view>;
};

template <typename C>
concept Container = requires(C container)
{
    typename C::value_type;
    container.begin();
    container.end();
    { container.size() } -> std::integral;
};
Requirement Syntax Means
Simple c.begin(); This expression compiles
Type typename C::value_type; This nested type exists
Compound { expr } -> concept; The expression compiles, and its type satisfies the concept
Nested requires condition; This compile-time condition is true 
flowchart LR
    T["A type T"] --> R{"Checked at<br/>compile time"}
    R -->|"every requirement is valid"| OK["the template can be used"]
    R -->|"one is not"| E["clear error:<br/>T does not satisfy Shape"]

[!note] Two meanings of requires A requires-clause (requires std::integral<T>) attaches a constraint to a template. A requires-expression (requires(T x) { ... }) is a boolean expression that tests validity. You will occasionally see both together: requires requires(T x) { x + x; }.

Overloading on concepts

Constrained templates can be overloaded. Among the candidates that match, the most constrained is chosen.

C++
void describe(std::integral auto x)       { std::cout << x << " is an integer\n"; }
void describe(std::floating_point auto x) { std::cout << x << " is a floating-point number\n"; }
void describe(const auto&)                { std::cout << "something else\n"; }

describe(5);
describe(2.5);
describe("hi");

One constraint is "more constrained" than another when it subsumes it: satisfying the first logically implies satisfying the second. std::signed_integral subsumes std::integral, so an overload on it is preferred for an int. If neither subsumes the other and both match, the call is ambiguous.

Standard concepts worth knowing

Concept Meaning
std::integral, std::signed_integral, std::floating_point Kinds of number
std::same_as<T, U>, std::convertible_to<From, To>, std::derived_from<D, B> Relations between types
std::equality_comparable, std::totally_ordered == works; < and the rest work
std::default_initializable, std::movable, std::copyable, std::regular What can be done with objects
std::invocable<F, Args...>, std::predicate<F, Args...> Callables

What concepts replaced
