Input Validation and assert

lesson 3.077 of 8 in milestone 35 min3 practice tasks

People type things you did not expect. When std::cin >> number receives letters it enters a fail state: you must clear() it and discard the bad input. Use assert to catch mistakes in your own code while developing.

Two kinds of things go wrong

Kind Example Whose fault Response
Bad input The user types abc for their age Nobody's. It will happen. Detect it and ask again. Never crash.
A bug Your function is called with a count of 0 The programmer's Stop loudly so it gets fixed

A robust program treats these differently. This lesson covers both.

What std::cin does with bad input

Output
 int age{};
 std::cin >> age;          the user types:  abc  then Enter

 waiting input:  [a][b][c][\n]
                  ▲
                  cannot make a number from 'a'

 1. age is set to 0
 2. std::cin enters a FAIL STATE: every later >> is silently skipped
 3. "abc" is STILL waiting to be read

Point 2 is the dangerous one. After a single bad entry, every later read in the program does nothing, and a loop that asks again will spin for ever.

The repair: clear, then discard

flowchart TD
    R["std::cin >> x"] --> Q{"did it fail?"}
    Q -- yes --> C["std::cin.clear()<br/>leave the fail state"] --> I["discard the rest of the line"] --> P["say what was wrong"] --> R
    Q -- no --> I2["discard the rest of the line<br/>(drops extras such as 5abc)"] --> E{"within range?"}
    E -- no --> P
    E -- yes --> OK["valid value"]
Step Code Why
Detect if (!std::cin) A stream used as a condition is false when it has failed
Reset std::cin.clear(); Leaves the fail state so reading works again
Discard std::cin.ignore(...) Throws away the bad characters still waiting

A reusable getInt

C++
#include <cstdlib>
#include <iostream>
#include <limits>
#include <string_view>

void ignoreLine()
{
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
}

int getInt(std::string_view prompt, int min, int max)
{
    while (true)
    {
        std::cout << prompt;
        int x{};
        std::cin >> x;

        if (!std::cin)
        {
            if (std::cin.eof())
            {
                std::exit(0);    // the input was closed: nothing more can arrive
            }
            std::cin.clear();
            ignoreLine();
            std::cout << "That is not a number. Try again.\n";
            continue;
        }

        ignoreLine();

        if (x < min || x > max)
        {
            std::cout << "It must be between " << min << " and " << max << ".\n";
            continue;
        }
        return x;
    }
}

int main()
{
    int age{ getInt("Enter your age (0-120): ", 0, 120) };
    std::cout << "You are " << age << '\n';
    return 0;
}
Output
Enter your age (0-120): abc
That is not a number. Try again.
Enter your age (0-120): 500
It must be between 0 and 120.
Enter your age (0-120): 25
You are 25

ignoreLine reads as "skip characters, however many there are, up to and including the next new line". The long expression is simply the largest count the function accepts.

Notice the shape: while (true) with continue for every rejection and a single return for success. It is the standard pattern for "keep asking until the answer is acceptable".

Keep this function

Put getInt and ignoreLine in a header of your own. Almost every interactive program you write from here on needs them.

assert: catching your own mistakes

An assertion states something that must be true at that point if the program is correct. If it is false, the program stops at once and reports the file and line.

C++
#include <cassert>

double average(int total, int count)
{
    assert(count > 0 && "count must be positive");
    return static_cast<double>(total) / count;
}
Output
Assertion failed: count > 0 && "count must be positive", file main.cpp, line 5

The && "text" is a trick for attaching a message: a string literal counts as true, so it does not change the test, and it appears in the report.

Property Detail
Checked when While the program runs, in Debug builds
In Release builds Removed entirely: no check, no cost
Use it for Conditions that can only be false if the code has a bug

[!danger] Never validate input with assert Assertions vanish in Release builds, so the check would disappear from the finished program. And bad input is not a bug: it deserves a polite message, not a crash.

static_assert: checked by the compiler

C++
static_assert(sizeof(int) >= 4, "this program needs an int of at least 32 bits");

The condition must be something the compiler can work out. If it is false, the program does not build. There is no cost at run time at all.

Choosing the right tool

Situation Tool
The user typed something unusable Validate and ask again
Something outside your control failed (a missing file) Report and recover, later with exceptions: 9.05 Exceptions
"This cannot happen" in your own logic assert
An assumption about types or the platform static_assert
