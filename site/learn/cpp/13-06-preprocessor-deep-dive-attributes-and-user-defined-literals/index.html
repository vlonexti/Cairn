Preprocessor Deep Dive, Attributes and User-Defined Literals

lesson 13.066 of 10 in milestone 137 min3 practice tasks

The preprocessor is a text-substitution engine that runs before compilation: powerful, and blind to types and scope. Know macros, conditional compilation, # and ##, and X-macros, and when not to use them. Attributes give the compiler extra information. User-defined literals let you write 5_km.

Macros

The preprocessor works on tokens before the compiler proper sees anything. A macro is a rule for replacing one sequence of tokens with another.

C++
#define PI 3.14159                 // object-like
#define SQUARE(x) ((x) * (x))      // function-like

It knows nothing about types, scopes or namespaces, which is the source of every problem with macros.

Use Expands to Result
SQUARE(1 + 2) ((1 + 2) * (1 + 2)) 9. Without the inner parentheses it would be 1 + 2 * 1 + 2, which is 5.
SQUARE(i++) ((i++) * (i++)) i is modified twice in one expression: undefined behaviour

A function evaluates its argument once. A macro pastes it wherever the parameter appears.

Operator Effect Example
#x Turns the argument into a string literal #define STR(x) #x makes STR(hello) into "hello"
a##b Joins two tokens into one #define VAR(n) var##n makes VAR(1) into var1
__VA_ARGS__ The arguments of a variadic macro #define LOG(...) print(__VA_ARGS__)
__VA_OPT__(x) Emits x only if there are variadic arguments (C++20)

Predefined macros and std::source_location

Macro Value
__FILE__, __LINE__ The current file name and line number
__func__ The enclosing function's name (strictly a predefined variable)
__cplusplus The language version, such as 202302L
_WIN32, __linux__, __APPLE__ Defined on the corresponding platform
_MSC_VER, __GNUC__, __clang__ Defined by the corresponding compiler
NDEBUG Defined in release builds; disables assert

__FILE__ and __LINE__ used to require a macro so that they expanded at the call site. std::source_location does it with a default argument:

C++
#include <print>
#include <source_location>
#include <string_view>

void log(std::string_view message, std::source_location where = std::source_location::current())
{
    std::println("{}:{} [{}] {}", where.file_name(), where.line(), where.function_name(), message);
}

int main()
{
    log("starting up");    // reports THIS line, in main
    return 0;
}

A default argument is evaluated where the call is written, so current() captures the caller's location.

Conditional compilation

C++
#if defined(_WIN32)
    #include <windows.h>
#elif defined(__linux__)
    #include <unistd.h>
#endif

#ifndef NDEBUG
    #define DEBUG_LOG(message) std::cerr << message << '\n'
#else
    #define DEBUG_LOG(message) ((void)0)
#endif

#if __has_include(<format>)
    #include <format>
#endif

Code in a branch that is not selected is removed before compilation, so it need not even be valid for the current platform. That is the preprocessor's one irreplaceable job: choosing between pieces of code that cannot all compile in one place.

Directive Purpose
#if, #ifdef, #ifndef, #elif, #else, #endif Select code
__has_include(<header>) Tests whether a header exists
Feature-test macros, from <version> Test for a language or library feature, such as __cpp_lib_print
#error "message" Stops compilation with a message
#pragma once, #pragma warning(...) Compiler-specific instructions

X-macros

Some lists must appear in several forms that have to stay in step: an enum, its names as strings, a count. An X-macro defines the list once and expands it differently each time.

C++
#include <iostream>
#include <string_view>

#define COLOR_LIST(X) \
    X(red)            \
    X(green)          \
    X(blue)

enum class Color
{
#define X(name) name,
    COLOR_LIST(X)
#undef X
};

constexpr std::string_view toString(Color color)
{
    switch (color)
    {
#define X(name) case Color::name: return #name;
        COLOR_LIST(X)
#undef X
    }
    return "?";
}

int main()
{
    std::cout << toString(Color::green) << '\n';    // green
    return 0;
}

COLOR_LIST takes the name of another macro and applies it to each entry. Define X one way to produce enumerators, another way to produce case lines. Add a colour to the list and both update. Until reflection arrives (11.07 Template Metaprogramming Techniques), this is the standard way to do it.

Rules for macros
  • Name them in ALL_CAPS, so they cannot be mistaken for anything else.
  • Parenthesize every parameter and the whole replacement.
  • #undef helper macros when finished.
  • Prefer constexpr variables and functions, templates, inline functions and std::source_location wherever they can do the job.

Macros ignore namespaces and scope, so a macro in one header can silently rewrite code in another. The classic case is <windows.h> defining min and max, which breaks std::min and std::max unless NOMINMAX is defined first.

Attributes

An attribute attaches information to a declaration or statement. It never changes the meaning of a correct program; it affects diagnostics and optimization.

Attribute Meaning
[[nodiscard]], [[nodiscard("reason")]] Warn if the result is ignored
[[maybe_unused]] Do not warn that this is unused
[[deprecated("use g instead")]] Warn wherever this is used
[[fallthrough]] Falling into the next case is deliberate
[[noreturn]] The function never returns to its caller
[[likely]], [[unlikely]] Which branch to optimize for
[[no_unique_address]] An empty member need not occupy storage
[[assume(expression)]] (C++23) The optimizer may take the expression as true. If it is not, the behaviour is undefined.
C++
[[nodiscard]] std::expected<Data, Error> load(std::string_view path);

load("x.dat");    // warning: the result is discarded

if (x > 0) [[likely]]
{
    fastPath();
}

[[nodiscard]] is the one to use freely: on any function whose result is the whole point of calling it, and especially on functions that report errors through their return value.

User-defined literals

A literal operator gives meaning to a suffix on a literal.

C++
#include <iostream>

struct Meters
{
    double value{};
};

constexpr Meters operator""_m(long double v) { return Meters{ static_cast<double>(v) }; }
constexpr Meters operator""_m(unsigned long long v) { return Meters{ static_cast<double>(v) }; }
constexpr Meters operator""_km(long double v) { return Meters{ static_cast<double>(v) * 1000.0 }; }

int main()
{
    constexpr auto distance{ 3.5_km };
    constexpr auto height{ 12_m };
    std::cout << distance.value << ' ' << height.value << '\n';    // 3500 12
    return 0;
}
Literal The operator's parameter
An integer, 12_m unsigned long long
A floating-point number, 3.5_km long double
A character, 'x'_c char
A string, "text"_s (const char*, std::size_t)

Suffixes you define must begin with an underscore. Those without one are reserved for the standard library: s, ms, h, sv, i and so on.

Literals make units part of the type at no run-time cost, as <chrono> does (10.08 Time and std::chrono). Made consteval, a literal operator can also validate its argument during compilation:

C++
consteval std::uint32_t operator""_rgb(const char* text, std::size_t length);

const auto orange{ "#FF8800"_rgb };    // a malformed colour would be a compile error
