References

lesson 4.033 of 7 in milestone 45 min4 practice tasks

A reference is a second name for an existing variable. Pass by reference to let a function change the caller's variable. Pass by const reference to avoid copying something large.

A second name for the same box

C++
#include <iostream>

int main()
{
    int x{ 5 };
    int& ref{ x };    // ref is another name for x

    ref = 10;
    std::cout << x << '\n';    // 10
    return 0;
}
        x ─┐
           ├──▶ ┌──────┐
      ref ─┘    │  10  │    one box, two names
                └──────┘

int& reads "reference to int". There is no second box. Anything done to ref is done to x.

Rule Consequence
A reference must be initialized int& r; does not compile
It cannot be made to refer to something else ref = y; copies the value of y into x
It always refers to something There is no "empty" reference

Pass by value and pass by reference

This is what references are for.

C++
#include <iostream>

void addOneByValue(int n)
{
    ++n;    // changes the copy
}

void addOneByReference(int& n)
{
    ++n;    // changes the caller's variable
}

int main()
{
    int score{ 5 };
    addOneByValue(score);
    std::cout << score << '\n';    // 5
    addOneByReference(score);
    std::cout << score << '\n';    // 6
    return 0;
}

Pass by const reference

Copying an int costs nothing. Copying a std::string of a million characters copies a million characters. A const reference gives the function access to the original with a promise not to change it.

C++
void printReport(const std::string& report)
{
    std::cout << report << '\n';
}

No copy is made, and the compiler rejects any attempt to modify report inside the function.

Choosing a parameter type

flowchart TD
    Q1{"Must the function<br/>change the caller's object?"} -- yes --> A["T&"]
    Q1 -- no --> Q2{"Is it cheap to copy?"}
    Q2 -- "yes: int, double, char, bool,<br/>enums, std::string_view" --> B["T (by value)"]
    Q2 -- "no: std::string, containers,<br/>most structs" --> C["const T&"]

This decision comes up for every function you will ever write. Learn the three outcomes.

Returning more than one value

A function has one return value. Reference parameters, often called out-parameters, are one way round that:

C++
void minMax(int a, int b, int& outMin, int& outMax)
{
    outMin = a < b ? a : b;
    outMax = a < b ? b : a;
}

int low{};
int high{};
minMax(8, 3, low, high);    // low is 3, high is 8

It works, but nothing at the call site shows that low and high will be changed. Returning a struct is usually clearer: 4.06 Structs.

Dangling references

A reference is only valid while the thing it refers to exists.

C++
int& broken()
{
    int local{ 5 };
    return local;    // local is destroyed here
}

The caller receives a reference to a variable that no longer exists. Using it is undefined behaviour. A reference in this state is said to be dangling.

Never return a reference to a local variable

Return by value instead. Returning a reference is only safe when the object outlives the function call, for example a parameter that was itself passed by reference.

What a reference can bind to

Declaration Allowed? Why
int& r{ x }; Yes x is a variable
int& r{ 5 }; No 5 is a temporary value with no lasting home
const int& r{ 5 }; Yes A const reference may bind to a temporary and keeps it alive

This is why const std::string& parameters accept string literals and results of expressions.

Two terms you will meet often from here on:

Term Roughly Examples
lvalue Something with a name and a lasting location x, name, values[0]
rvalue A temporary value 5, x + 1, the result of a function returning by value

They matter a great deal in 7.05 Move Semantics.
