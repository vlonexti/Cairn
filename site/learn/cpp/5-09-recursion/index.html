Recursion

lesson 5.099 of 11 in milestone 55 min5 practice tasks

A recursive function calls itself on a smaller version of the same problem. It needs a base case that stops, and a recursive case that moves towards it. Every call gets its own set of local variables.

A function that calls itself

Some problems contain smaller copies of themselves. The factorial of 4 is 4 times the factorial of 3. A folder contains files and more folders. For problems like that, a function may call itself.

C++
#include <iostream>

int factorial(int n)
{
    if (n <= 1)
    {
        return 1;                    // base case: answer directly
    }
    return n * factorial(n - 1);     // recursive case: a smaller problem
}

int main()
{
    std::cout << factorial(4) << '\n';    // 24
    return 0;
}
Part Job
Base case A version of the problem simple enough to answer without recursing
Recursive case Reduce the problem and call again, so that the base case is eventually reached

What happens during the calls

Each call is a separate activation of the function, with its own n. The calls stack up until the base case, then return one by one.

factorial(4)
│ 4 * factorial(3)
│     │ 3 * factorial(2)
│     │     │ 2 * factorial(1)
│     │     │     └─ returns 1            the base case
│     │     └─ returns 2 * 1 = 2
│     └─ returns 3 * 2 = 6
└─ returns 4 * 6 = 24

The memory that records each unfinished call, with its parameters and local variables, is one stack frame. The frames live on the call stack, which is a stack in exactly the sense of 5.03 Vector as a Stack, and Capacity.

No base case means stack overflow

The call stack has a limited size. Recursion that never stops fills it and the program crashes with a stack overflow. Even correct recursion can overflow if it goes very deep, for example a million levels.

How to think recursively

Do not try to follow every call in your head. Ask two questions:

  1. What is the simplest input, and what is its answer?
  2. Assuming the function already works for a smaller input, how do I use that result to answer this one?

If both answers are right, the function is right. Trusting step 2 is called the recursive leap of faith.

Three classic examples

Sum of the digits

C++
int digitSum(int n)
{
    return n < 10 ? n : n % 10 + digitSum(n / 10);
}

The last digit, plus the digit sum of everything before it.

Fast power

C++
long long power(long long base, int exponent)
{
    if (exponent == 0)
    {
        return 1;
    }
    const long long half{ power(base, exponent / 2) };
    return exponent % 2 == 0 ? half * half : half * half * base;
}

This halves the problem on each call. Computing the millionth power takes about 20 calls, not a million.

Binary search

C++
int binarySearch(const std::vector<int>& v, int target, int low, int high)
{
    if (low > high)
    {
        return -1;    // not found
    }
    const int mid{ low + (high - low) / 2 };
    const int value{ v[static_cast<std::size_t>(mid)] };
    if (value == target)
    {
        return mid;
    }
    return value < target ? binarySearch(v, target, mid + 1, high)
                          : binarySearch(v, target, low, mid - 1);
}

Look at the middle of a sorted range and discard the half that cannot contain the target.

Fibonacci: a trap and its fix

C++
int fib(int n)
{
    return n < 2 ? n : fib(n - 1) + fib(n - 2);
}

Elegant, and disastrously slow:

Output
                 fib(5)
            /             \
        fib(4)            fib(3)          fib(3) is computed twice,
        /    \            /    \          fib(2) three times,
    fib(3)  fib(2)    fib(2)  fib(1)      and it doubles with each level

The same subproblems are recomputed again and again. fib(40) makes over 300 million calls.

The fix is to remember each answer the first time it is computed. That technique is memoization.

C++
long long fibMemo(int n)
{
    static std::vector<long long> cache{ 0, 1 };
    const auto index{ static_cast<std::size_t>(n) };
    if (index < cache.size())
    {
        return cache[index];
    }
    const long long result{ fibMemo(n - 1) + fibMemo(n - 2) };
    cache.push_back(result);
    return result;
}

The static local (3.06 Global Variables, static and Linkage) keeps the cache between calls. Each value is now computed once.

Recursion or a loop?

Recursion Loop
Natural for Trees, nested structures, divide and conquer, backtracking Plain repetition
Memory One stack frame per call Constant
Failure mode Stack overflow Infinite loop

Anything recursive can be rewritten as a loop, and the reverse. Choose recursion when the problem is recursive by nature: folders inside folders, mazes, permutations, tree structures. Choose a loop for simple counting.
