Streams In Depth — istream, ostream, stringstream

lesson 10.055 of 9 in milestone 106 min3 practice tasks

A stream is a sequence of characters flowing in or out. The console, files and strings share one interface, so the same << and >> code works for all of them. This lesson covers formatting manipulators, stream states and string streams for parsing.

One interface, many sources

std::istringstream, std::ostringstream, std::stringstream A std::string in memory <sstream>

The stream library is itself a class hierarchy. Because a std::ofstream is a std::ostream, any function that takes a std::ostream& works with the console, a file or a string. Every operator<< you have written for your own types (6.07 Operator Overloading Basics) therefore works with all three, unchanged.

C++
void report(std::ostream& out, const Player& player)
{
    out << player << '\n';
}

report(std::cout, hero);    // to the console
report(logFile, hero);      // to a file
report(buffer, hero);       // into a string

Reading

Call Reads
in >> x A formatted value, skipping leading whitespace
in.get(ch) One character, including whitespace
std::getline(in, line) A whole line, discarding the '\n'
std::getline(in, text, ',') Up to a delimiter of your choice
in.peek() The next character, without consuming it
in.ignore(n, '\n') Discards up to n characters, through the next new line
in.unget() Puts the last character back

>> is formatted input: it interprets characters as a value of the target type. The others are unformatted: they deal in raw characters.

Formatting output with manipulators

A manipulator is an object sent to a stream to change how it formats. Most are in <iomanip>.

Manipulator Effect Example output
std::setw(8) Minimum width of the next item 42
std::left, std::right Alignment within the width ab
std::setfill('*') The padding character *****7
std::fixed, std::setprecision(2) Digits after the point 3.14
std::scientific Exponent notation 1.234500e+03
std::hex, std::dec, std::oct The base for integers ff
std::showbase Prefix the base 0xff
std::boolalpha true and false as words true
std::showpos A + on positive numbers +5
C++
#include <iomanip>
#include <iostream>

int main()
{
    std::cout << std::left << std::setw(10) << "Item" << std::right << std::setw(8) << "Price" << '\n';
    std::cout << std::left << std::setw(10) << "Apple" << std::right << std::setw(8)
              << std::fixed << std::setprecision(2) << 0.5 << '\n';
    return 0;
}

[!warning] Manipulators are sticky, except setw std::hex, std::fixed, std::setprecision and the rest stay in force until changed, which surprises code that prints afterwards. std::setw alone applies to one item and resets. std::format avoids the problem entirely: 10.07 Formatting with std::format and std::print.

Stream states

Every stream carries a set of state flags.

              ┌── goodbit   nothing wrong
 stream state ├── eofbit    the end of the input was reached
              ├── failbit   the last operation failed, e.g. letters where a number was expected
              └── badbit    a serious error; the stream may be unusable
Test True when
if (stream) Neither failbit nor badbit is set
stream.fail() failbit or badbit is set
stream.eof() eofbit is set
stream.clear() (Resets the flags to good)

Once a stream has failed, every later operation on it does nothing until clear() is called. That is the behaviour you handled in 3.07 Input Validation and assert.

The read loop

An input operation returns the stream, and a stream converts to false once it has failed. So the read itself is the loop condition.

C++
int x{};
int sum{ 0 };
while (std::cin >> x)
{
    sum += x;
}
C++
std::string line{};
while (std::getline(file, line))
{
    process(line);
}

[!warning] Do not loop on eof() while (!in.eof()) is a classic bug. eofbit is only set after a read has run off the end, so the loop body executes once more with a failed read and stale data. Test the read itself.

String streams

A string stream reads from, or writes to, a string in memory. It makes every stream technique available for text you already hold.

C++
#include <iomanip>
#include <iostream>
#include <sstream>
#include <string>

int main()
{
    // Parse: pull typed values out of a string.
    std::istringstream in{ "Ann 31 1.68" };
    std::string name{};
    int age{};
    double height{};
    in >> name >> age >> height;

    // Split on a delimiter.
    std::istringstream csv{ "red,green,blue" };
    std::string token{};
    while (std::getline(csv, token, ','))
    {
        std::cout << token << '\n';
    }

    // Build a string with formatting.
    std::ostringstream out{};
    out << std::fixed << std::setprecision(1) << "HP: " << 72.456 << '%';
    const std::string label{ out.str() };    // HP: 72.5%

    std::cout << name << ' ' << age << ' ' << height << ' ' << label << '\n';
    return 0;
}
flowchart LR
    S["the text: Ann 31 1.68"] --> I["istringstream"] -->|">>"| N["name"] & A["age"] & H["height"]
    V["values"] -->|"<<"| O["ostringstream"] --> R[".str() gives a std::string"]

The standard pattern for line-oriented input combines both: read a whole line with std::getline, then parse that line with an istringstream. A malformed line then cannot leave the main input stream in a failed state.

Validating a whole string

C++
bool parseInt(const std::string& text, int& result)
{
    std::istringstream stream{ text };
    stream >> result;
    return stream && (stream >> std::ws).eof();
}

The value must parse, and nothing but whitespace may follow it. This rejects "12abc", which a bare >> would accept as 12. Where speed matters, std::from_chars in <charconv> does the same job without the stream machinery.
