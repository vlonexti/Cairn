Virtual Functions and Polymorphism

lesson 8.033 of 7 in milestone 85 min3 practice tasks

A virtual function called through a base pointer or reference runs the version belonging to the object's actual class. That is polymorphism: one interface, many behaviours. Mark overrides with override, and give polymorphic base classes a virtual destructor.

One call, many behaviours

C++
#include <iostream>
#include <string_view>

class Animal
{
public:
    virtual ~Animal() = default;
    virtual std::string_view speak() const { return "..."; }
};

class Dog : public Animal
{
public:
    std::string_view speak() const override { return "Woof"; }
};

class Cat : public Animal
{
public:
    std::string_view speak() const override { return "Meow"; }
};

void makeNoise(const Animal& animal)
{
    std::cout << animal.speak() << '\n';
}

int main()
{
    const Dog dog{};
    const Cat cat{};
    makeNoise(dog);    // Woof
    makeNoise(cat);    // Meow
    return 0;
}

makeNoise is written once, against Animal. It works for every class derived from Animal, including ones written years later, without being recompiled.

Static type and dynamic type

Every expression has two types.

Meaning Known
Static type The type written in the code At compile time
Dynamic type The type of the object actually referred to At run time

In makeNoise(dog), the parameter's static type is const Animal& and its dynamic type is Dog.

Function Chosen by
Non-virtual The static type
virtual The dynamic type 
flowchart LR
    R["const Animal& animal"] -->|"animal.speak()"| Q{"dynamic type?"}
    Q -->|Dog| W["Dog::speak"]
    Q -->|Cat| M["Cat::speak"]
    Q -->|Animal| N["Animal::speak"]

Choosing the function at run time is dynamic dispatch. A derived function that replaces a virtual one overrides it, which is different from the hiding described in 8.02 Inheritance and Access.

Polymorphic collections

C++
std::vector<std::unique_ptr<Animal>> zoo{};
zoo.push_back(std::make_unique<Dog>());
zoo.push_back(std::make_unique<Cat>());

for (const auto& animal : zoo)
{
    std::cout << animal->speak() << '\n';    // Woof, Meow
}
Polymorphism requires a pointer or a reference

A std::vector<Animal> stores Animal objects by value. Putting a Dog in it copies only the Animal part and discards the rest. That is slicing: 8.06 Object Slicing, Casting and Composition.

override and final

C++
class Dog : public Animal
{
public:
    std::string_view speak() const override;    // checked: a matching virtual must exist
};

Without override, a small mismatch, such as a missing const or a different parameter type, silently declares a new, unrelated function. With it, the mismatch is a compile error.

Specifier Effect
override The compiler verifies that this overrides a base virtual function
final on a function Derived classes may not override it further
final on a class Nothing may derive from it

[!tip] Always write override It costs one word and converts a silent bug into a diagnostic.

Virtual destructors

C++
Animal* a{ new Dog{} };
delete a;

If ~Animal is not virtual, the destructor is chosen by the static type. Only ~Animal runs, the Dog part is never destroyed, and the behaviour is undefined.

The base class Destructor should be
Will be deleted through a base pointer public and virtual
Must never be deleted through a base pointer protected and non-virtual

A working rule: a class with any virtual function gets a virtual destructor.

Covariant return types

An override must normally match the base signature exactly. One relaxation: where the base returns a pointer or reference to a class, the override may return a pointer or reference to a class derived from it.

C++
class Shape
{
public:
    virtual ~Shape() = default;
    virtual Shape* clone() const = 0;
};

class Circle : public Shape
{
public:
    Circle* clone() const override { return new Circle{ *this }; }
};

Printing polymorphic objects

operator<< is a non-member, so it cannot be virtual. Have it forward to a virtual member function:

C++
class Shape
{
public:
    virtual ~Shape() = default;

    friend std::ostream& operator<<(std::ostream& out, const Shape& shape)
    {
        return shape.print(out);
    }

private:
    virtual std::ostream& print(std::ostream& out) const = 0;
};

class Circle : public Shape
{
private:
    std::ostream& print(std::ostream& out) const override
    {
        return out << "Circle(r=" << m_radius << ')';
    }

    double m_radius{ 1.0 };
};

One non-virtual public function delegating to a private virtual one is a common and useful shape, known as the non-virtual interface idiom.

Three traps

Trap What happens
Calling a virtual function from a constructor or destructor The current class's version runs. The derived part does not exist yet, or no longer exists.
Giving an override a different default argument Default arguments are taken from the static type, so the base's default is used with the derived function
Calling Base::f() explicitly Dynamic dispatch is bypassed
