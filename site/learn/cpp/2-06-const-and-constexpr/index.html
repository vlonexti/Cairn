const and constexpr

lesson 2.066 of 9 in milestone 25 min3 practice tasks

const means "this value never changes after it is set". constexpr means "this value is known while compiling". Use them wherever you can: they prevent mistakes and cost nothing.

const: a locked box

Most values in a program never need to change after they are set. Marking them const lets the compiler enforce that.

C++
const double gravity{ 9.81 };
gravity = 10.0;    // error: you cannot assign to a const variable
 ┌──────────────┐
 │     9.81     │   gravity   (locked: read only)
 └──────────────┘

Two rules:

  • A const variable must be given its value when it is created.
  • That value may come from anywhere, including the keyboard. It simply cannot change afterwards.
C++
int age{};
std::cin >> age;
const int ageNextYear{ age + 1 };    // set once while running, then locked

[!tip] Make things const by default When you read const on a variable, you know its value at every later line without checking. In a long function that is a real help. Leave const off only when the value has to change.

constexpr: worked out by the compiler

Some values are known before the program ever runs: the number of seconds in a day, the size of a chess board. constexpr asks the compiler to calculate them during the build.

C++
constexpr double pi{ 3.14159265358979 };
constexpr int secondsPerDay{ 24 * 60 * 60 };    // the compiler stores 86400

int x{};
std::cin >> x;
constexpr int bad{ x * 2 };    // error: x is not known while compiling

You will hear these two phases called compile time and run time. The distinction comes up again and again in C++.

const constexpr
Can change after it is set No No
Value may come from input while running Yes No
Calculated during the build Sometimes Always
Use it for Any value you will not modify True constants: pi, maxPlayers, gridSize

constexpr functions

A function can be constexpr too. That means the compiler may run it during the build when its arguments are known.

C++
#include <iostream>

constexpr int square(int n)
{
    return n * n;
}

int main()
{
    constexpr int a{ square(5) };    // worked out while compiling: 25

    int side{};
    std::cin >> side;
    int b{ square(side) };           // the same function, used while running

    std::cout << a << ' ' << b << '\n';
    return 0;
}

One function serves both purposes.

Replace magic numbers with names

A magic number is a bare number in the code with no explanation.

C++
total = price * 1.08;    // what is 1.08?
C++
constexpr double salesTaxRate{ 0.08 };
total = price * (1.0 + salesTaxRate);

The second version explains itself. And when the rate changes, you change one line instead of hunting for every 1.08.

Sharing constants between files

Constants that several files need go in a header, grouped under a name:

C++
// constants.h
#pragma once

namespace constants
{
    inline constexpr double pi{ 3.14159265358979 };
    inline constexpr int maxPlayers{ 4 };
}

Any file that includes the header writes constants::pi. Take the namespace and inline parts on trust for now. Both are explained in Milestone 3: 3.05 Scope, Lifetime and Namespaces and 3.06 Global Variables, static and Linkage.

const parameters

A parameter can be const as well: the function promises not to change it.

C++
void printPrice(const double price)

For a simple value that is copied anyway, this is optional. It becomes important with references, where it means "I will look at your data but not alter it": 4.03 References.
