Maps and Sets

lesson 10.022 of 9 in milestone 106 min3 practice tasks

A map stores key to value pairs, like a dictionary. A set stores unique values. std::map and std::set keep their keys sorted, in a tree with O(log n) operations. std::unordered_map and std::unordered_set hash their keys: O(1) on average, with no order.

std::map: a dictionary

A vector finds an element by position. A map finds a value by its key.

C++
#include <iostream>
#include <map>
#include <string>

int main()
{
    std::map<std::string, int> ages{ { "Ann", 31 }, { "Bo", 25 } };
    ages["Cy"] = 40;                 // insert, or overwrite if present
    ages.insert({ "Di", 22 });       // insert only if absent
    ages.emplace("Ed", 50);          // construct in place, only if absent

    for (const auto& [name, age] : ages)
    {
        std::cout << name << ": " << age << '\n';
    }
    return 0;
}
 key      value          always sorted by key
 "Ann" ─▶ 31
 "Bo"  ─▶ 25
 "Cy"  ─▶ 40
 "Di"  ─▶ 22
 "Ed"  ─▶ 50

Each element is a std::pair<const Key, Value>. Iteration visits them in key order, and structured bindings name the two halves. Keys are unique and cannot be modified in place.

Looking things up

[!danger] map[key] inserts when the key is missing operator[] returns a reference to the value for that key, creating a value-initialized one if there is none. So if (ages["Zed"] == 0) silently adds "Zed" with the value 0. For the same reason it cannot be used on a const map.

To Use When the key is absent
Test for presence ages.contains("Bo") Returns false
Get the element ages.find("Bo") Returns ages.end()
Get the value, or fail loudly ages.at("Bo") Throws std::out_of_range
Get or create the value ages["Bo"] Inserts a default value
C++
if (const auto it{ ages.find("Bo") }; it != ages.end())
{
    std::cout << it->first << " is " << it->second << '\n';
}

find returns an iterator to the pair: first is the key and second the value. It does one lookup, where contains followed by at would do two.

Updating and erasing

C++
ages.erase("Ann");
++ages["Bo"];
std::erase_if(ages, [](const auto& entry) { return entry.second > 45; });

The counting idiom

The inserting behaviour of operator[] is exactly right for counting.

C++
std::map<std::string, int> wordCount{};
for (const auto& word : words)
{
    ++wordCount[word];    // absent: created as 0, then incremented
}

std::unordered_map: a hash table

The interface is the same. The implementation and its guarantees differ.

flowchart LR
    K["key: apple"] --> H["hash the key to a number,<br/>reduce it to a bucket index"] --> B["bucket 2 holds<br/>(apple, 5)"]

A hash function turns a key into a number, which selects a bucket. Lookup goes straight to that bucket, so it is O(1) on average. Two keys landing in the same bucket is a collision; many collisions degrade lookup towards O(n). When the table becomes too full it rehashes into more buckets, which invalidates iterators.

A key type needs For map / set For unordered_map / unordered_set
An ordering: operator< or <=> A hash function and operator==

The built-in and standard types already have both. For a type of your own, supply a hash:

C++
struct Point
{
    int x{};
    int y{};
    bool operator==(const Point&) const = default;
};

struct PointHash
{
    std::size_t operator()(const Point& p) const noexcept
    {
        return std::hash<int>{}(p.x) ^ (std::hash<int>{}(p.y) << 1);
    }
};

std::unordered_map<Point, char, PointHash> tiles{};

Two objects that compare equal must produce the same hash. A hash that spreads keys evenly keeps the table fast.

Sets

A set is a map with keys and no values: a collection of unique elements.

C++
#include <iostream>
#include <set>

int main()
{
    std::set<int> s{ 5, 1, 5, 3, 1 };    // 1 3 5: duplicates dropped, kept sorted
    s.insert(2);                         // 1 2 3 5

    const auto [position, inserted]{ s.insert(3) };
    std::cout << std::boolalpha << inserted << ' ' << s.contains(3) << '\n';    // false true
    return 0;
}

insert returns a pair: an iterator to the element and a bool saying whether an insertion took place. Sets answer "have I seen this before?", remove duplicates and keep sorted unique collections.

Allowing duplicate keys

std::multimap and std::multiset permit several elements with the same key.

C++
std::multimap<std::string, std::string> phoneBook{};
phoneBook.insert({ "Ann", "555-1111" });
phoneBook.insert({ "Ann", "555-2222" });

const auto [first, last]{ phoneBook.equal_range("Ann") };
for (auto it{ first }; it != last; ++it)
{
    std::cout << it->second << '\n';
}

equal_range returns the half-open range of elements with that key. A std::map<Key, std::vector<Value>> is often a clearer way to express the same thing.

What sorted order buys you

Only the tree-based containers can answer questions about neighbours and ranges.

C++
std::map<int, char> grades{ { 0, 'F' }, { 50, 'C' }, { 70, 'B' }, { 90, 'A' } };

auto it{ grades.upper_bound(75) };    // the first key greater than 75: 90
--it;                                 // the last key not greater than 75: 70
std::cout << it->second << '\n';      // B
Member Returns an iterator to
lower_bound(k) The first element with a key not less than k
upper_bound(k) The first element with a key greater than k

Range queries, "the next larger", leaderboards and time-ordered events all fall out of this.

Comparison

map / set unordered_map / unordered_set
Structure Balanced tree Hash table
Lookup, insert, erase O(log n) O(1) average, O(n) worst case
Iteration order Sorted by key Unspecified
Range queries Yes No
The key needs An ordering A hash and ==
Choose when You need order or neighbours You only look up by key, and speed matters

C++23 adds std::flat_map and std::flat_set: the sorted interface, stored in contiguous vectors. Lookups are cache-friendly; insertions are O(n).
