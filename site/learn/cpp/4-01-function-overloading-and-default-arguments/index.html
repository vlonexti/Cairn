Function Overloading and Default Arguments

lesson 4.011 of 7 in milestone 45 min3 practice tasks

Overloading gives several functions the same name with different parameters, and the compiler picks the best match for each call. Default arguments supply a value when the caller leaves a parameter out.

One name, several functions

Two functions may share a name as long as their parameter lists differ. This is overloading.

C++
#include <iostream>

int add(int a, int b)
{
    return a + b;
}

double add(double a, double b)
{
    return a + b;
}

int add(int a, int b, int c)
{
    return a + b + c;
}

int main()
{
    std::cout << add(1, 2) << '\n';        // the (int, int) version
    std::cout << add(1.5, 2.5) << '\n';    // the (double, double) version
    std::cout << add(1, 2, 3) << '\n';     // the three-parameter version
    return 0;
}

The caller writes add and the compiler chooses. That choice is called overload resolution, and it happens entirely at compile time.

flowchart LR
    C["add(1.5, 2.5)"] --> R{"Which version<br/>fits best?"}
    R -->|"exact match: chosen"| D["double add(double, double)"]
    R -.->|"would need a conversion"| I["int add(int, int)"]
    R -.->|"wrong number of arguments"| T["int add(int, int, int)"]

How the compiler ranks the candidates

For each argument, the compiler prefers the candidate that needs the least conversion.

Rank Kind of match Example
1 (best) Exact int to int
2 Promotion char or short to int; float to double
3 Standard conversion int to double; double to int
4 User-defined conversion Conversions you define on classes (Milestone 6)

If two candidates are equally good, the call is ambiguous and does not compile:

C++
void f(long value);
void f(double value);

f(5);    // error: int to long and int to double are both rank 3

Fix it by making the argument's type exact (f(5L) or f(5.0)) or by adding an int overload.

What makes two overloads different?

The functions differ in Allowed?
Number of parameters Yes
Types of parameters Yes
Only the return type No
Only the parameter names No

The return type is not considered, because a call such as add(1, 2); gives the compiler no way to tell which result you wanted.

Default arguments

A parameter can name a value to use when the caller supplies none.

C++
#include <iostream>

void printLine(int length = 20, char symbol = '-')
{
    for (int i{ 0 }; i < length; ++i)
    {
        std::cout << symbol;
    }
    std::cout << '\n';
}

int main()
{
    printLine();           // 20 dashes
    printLine(5);          // 5 dashes
    printLine(5, '*');     // 5 stars
    return 0;
}
Rule Detail
Defaults go on the right void f(int a, int b = 2) is fine. void f(int a = 1, int b) is not.
Arguments fill from the left You cannot skip length and give only symbol.
State the default once When a function has a declaration in a header, put the default there and not in the definition.
Overloads and defaults can collide

void log(int level); together with void log(int level, int indent = 0); makes log(3) ambiguous. Use one mechanism or the other for a given name.

Forbidding an overload

= delete declares that a particular overload must not be called. It is a precise way to block an unwanted conversion.

C++
void printInt(int x);
void printInt(char) = delete;
void printInt(bool) = delete;

printInt(5);      // fine
printInt('a');    // error: this overload is deleted

Without the deleted versions, 'a' would be promoted to int and print as 97.
