Copy Semantics — Shallow vs Deep

lesson 7.033 of 8 in milestone 75 min3 practice tasks

The default copy copies each member, and for a pointer that means the address, not the data. Two objects then own one block of memory and both delete it. A class that owns a resource needs a copy constructor and a copy assignment operator that make a deep copy.

The shallow copy trap

Here is a class that owns a dynamic array, with a correct constructor and destructor.

C++
class Buffer
{
public:
    explicit Buffer(std::size_t size) : m_data{ new int[size]{} }, m_size{ size } {}
    ~Buffer() { delete[] m_data; }

private:
    int* m_data{};
    std::size_t m_size{};
};

{
    Buffer a{ 3 };
    Buffer b{ a };    // the compiler-generated copy
}                     // b is destroyed: delete[]. a is destroyed: delete[] on the SAME block.

The copy constructor the compiler generates copies member by member. Copying m_data copies an address.

 SHALLOW COPY
  a.m_data ──┐
             ├──▶ [ 0 | 0 | 0 ]     one block, two owners
  b.m_data ──┘

Both objects believe they own the block, both destructors release it, and the program has a double delete. Before that, a change made through a silently appears in b.

Deep copy

A deep copy duplicates the data, so each object owns its own block.

 DEEP COPY
  a.m_data ────▶ [ 1 | 2 | 3 ]
  b.m_data ────▶ [ 1 | 2 | 3 ]      separate blocks

Two functions create copies, and a class that owns a resource must define both.

The copy constructor

C++
Buffer(const Buffer& other)
    : m_data{ new int[other.m_size] }, m_size{ other.m_size }
{
    std::copy(other.m_data, other.m_data + m_size, m_data);
}

It builds a new object from an existing one: allocate a block of the same size, then copy the contents.

The copy assignment operator

C++
Buffer& operator=(const Buffer& other)
{
    if (this == &other)
    {
        return *this;                               // a = a must not destroy its own data
    }
    int* fresh{ new int[other.m_size] };            // allocate first
    std::copy(other.m_data, other.m_data + other.m_size, fresh);
    delete[] m_data;                                // only then release the old block
    m_data = fresh;
    m_size = other.m_size;
    return *this;
}

Assignment is harder, because the left-hand object already holds a block that must be released. The order matters: if the allocation failed after the old block had been deleted, the object would be left pointing at released memory.

Which one runs?

flowchart TD
    Q{"Does the object on the left<br/>already exist?"} -- "no: Buffer b{ a };<br/>Buffer b = a;<br/>passing or returning by value" --> C["Copy constructor"]
    Q -- "yes: b = a;" --> A["Copy assignment<br/>(must release the old data)"]

Note that Buffer b = a; is a construction despite the = sign, because b is being created.

Copy and swap

There is a way to write assignment that reuses the copy constructor and is correct by construction.

C++
friend void swap(Buffer& a, Buffer& b) noexcept
{
    using std::swap;
    swap(a.m_data, b.m_data);
    swap(a.m_size, b.m_size);
}

Buffer& operator=(Buffer other)    // by value: the parameter is already a copy
{
    swap(*this, other);
    return *this;
}                                  // other, now holding the old data, is destroyed here
flowchart LR
    A["b = a"] --> B["other is a copy of a<br/>(copy constructor)"] --> C["swap this object's contents<br/>with other's"] --> D["other is destroyed,<br/>releasing the old data"]
Concern How it is handled
Self-assignment Harmless: a copy is made and swapped in
Allocation failure It happens while making the parameter, before this object is touched
Duplicate code The copying logic exists only in the copy constructor

This is the copy-and-swap idiom.

Forbidding copies

Some things should not be copied at all: an open file, a lock, a window. Say so, and the compiler enforces it.

C++
class Window
{
public:
    Window(const Window&) = delete;
    Window& operator=(const Window&) = delete;
};

Any attempt to copy a Window is now a compile error.

The real lesson

Everything above exists because Buffer holds a raw owning pointer. Replace it with a std::vector<int> and the compiler-generated copy is already a deep copy, the destructor is already correct, and you write none of this.

Write a deep copy by hand when you are building a low-level resource class. Everywhere else, use members that copy themselves correctly.
