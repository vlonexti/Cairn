Threads and std::jthread

lesson 12.011 of 7 in milestone 126 min2 practice tasks

A thread is an independent path of execution; several can run at the same time on different processor cores. std::thread starts one and must be joined. std::jthread (C++20) joins automatically and supports cooperative cancellation through std::stop_token. Both are in <thread>.

Concurrency and parallelism

Concurrency is about structure: staying responsive while waiting. Parallelism is about speed: using every core. Threads provide both.

All threads of a program share one address space: globals, the heap and anything reachable through a pointer or reference. Each has its own stack. That sharing is the source of both the power and every difficulty in this milestone.

Starting threads

C++
#include <iostream>
#include <thread>

void work(int id, int count)
{
    for (int i{ 0 }; i < count; ++i)
    {
        std::cout << "worker " << id << " step " << i << '\n';
    }
}

int main()
{
    std::thread t1{ work, 1, 3 };
    std::thread t2{ [] { std::cout << "a lambda on its own thread\n"; } };

    t1.join();
    t2.join();
    std::cout << "hardware threads: " << std::thread::hardware_concurrency() << '\n';
    return 0;
}

A std::thread is given a callable and its arguments, and starts running it immediately. join() blocks until that thread finishes. The order in which the two threads' output appears is not determined: it can differ on every run.

[!danger] A joinable std::thread must not be destroyed If a std::thread object is destroyed while still joinable, std::terminate is called. Before that you must join() it, or detach() it, which lets it run on with nothing able to wait for it. Detaching is rarely right: a detached thread that touches locals or globals after they are destroyed is undefined behaviour.

Passing arguments

Arguments are copied (or moved) into storage owned by the new thread, and the callable receives those copies. That is a safety measure: the caller's variables might be gone by the time the thread runs.

C++
void fill(std::vector<int>& values);

std::vector<int> data{};
std::thread t{ fill, std::ref(data) };    // an explicit reference
t.join();

std::ref creates a std::reference_wrapper, which is copied in place of the object. You take on the obligation that data outlives the thread.

std::jthread

std::jthread is a thread with RAII.

C++
{
    std::jthread t{ work, 1, 3 };
}    // the destructor requests a stop, then joins
std::thread std::jthread
Destroyed while joinable std::terminate Requests stop and joins
Cancellation None built in std::stop_token
Exception safety A throw between start and join() terminates Joins during unwinding

Prefer std::jthread in new code.

Cooperative cancellation

A thread cannot be killed safely from outside: it might hold a lock or be half-way through an update. Instead it is asked to stop, and checks for the request at points where stopping is safe.

C++
#include <chrono>
#include <iostream>
#include <thread>

int main()
{
    using namespace std::chrono_literals;

    std::jthread worker{ [](std::stop_token token)
    {
        while (!token.stop_requested())
        {
            std::cout << "working\n";
            std::this_thread::sleep_for(200ms);
        }
        std::cout << "stopping cleanly\n";
    } };

    std::this_thread::sleep_for(700ms);
    worker.request_stop();
    return 0;
}

If the callable's first parameter is a std::stop_token, jthread supplies one connected to its own stop source.

Thread utilities

Facility Does
std::this_thread::get_id() Identifies the current thread
std::this_thread::sleep_for(d), sleep_until(t) Suspends the current thread
std::this_thread::yield() Offers the processor to other threads
std::thread::hardware_concurrency() The number of hardware threads; may return 0 if unknown
thread_local int x; A separate x for every thread

thread_local gives a variable thread storage duration: each thread has its own instance, created when the thread first uses it. It is the simplest way to avoid sharing.

Dividing work

The basic pattern for parallel speed-up: partition the data, give each thread its own part and its own place to write.

C++
long long parallelSum(const std::vector<int>& values, unsigned parts)
{
    std::vector<long long> partial(parts, 0);
    {
        std::vector<std::jthread> threads{};
        const std::size_t chunk{ values.size() / parts };
        for (unsigned p{ 0 }; p < parts; ++p)
        {
            const auto first{ values.begin() + static_cast<std::ptrdiff_t>(p * chunk) };
            const auto last{ p == parts - 1 ? values.end() : first + static_cast<std::ptrdiff_t>(chunk) };
            threads.emplace_back([first, last, &partial, p]
            {
                partial[p] = std::accumulate(first, last, 0LL);
            });
        }
    }    // every jthread joins here
    return std::accumulate(partial.begin(), partial.end(), 0LL);
}
Output
 values:  [■■■■■■■■|■■■■■■■■|■■■■■■■■|■■■■■■■■]
            thread 0  thread 1  thread 2  thread 3
               ↓         ↓         ↓         ↓
 partial: [   s0   ,   s1    ,   s2    ,   s3   ]    summed after all have joined

This is correct because nothing is shared for writing. Every thread reads its own slice of values, which nobody modifies, and writes only partial[p], which no other thread touches. The results are combined after the joins.

Shared writable data needs synchronization

Two threads accessing the same object, at least one of them writing, with no synchronization, is a data race and undefined behaviour. That is the subject of 12.02 Data Races, Mutexes and Locks.

The cost of a thread

Creating a thread costs tens of microseconds and a stack of about a megabyte. More runnable threads than cores gains nothing and adds switching overhead. For many small tasks, reuse a fixed set of threads: a thread pool, in 12.04 Futures, Promises, std::async and Thread Pools.
