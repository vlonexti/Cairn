Container Classes and std::initializer_list

lesson 7.088 of 8 in milestone 75 min2 practice tasks

A container class holds and manages a collection, like a small std::vector of your own. Building one brings together the whole milestone: heap memory, RAII, the Rule of Five and operators. std::initializer_list lets it accept { 1, 2, 3 }.

Everything at once

This lesson builds IntArray, a resizable array of int. You would use std::vector in real code. Writing one yourself is how you find out whether the last seven lessons have landed.

 ┌──────────────────────── IntArray ────────────────────────┐
 │ data:       int* m_data          std::size_t m_size      │
 ├──────────────────────────────────────────────────────────┤
 │ construct:  IntArray()   IntArray(n)   IntArray{1, 2, 3} │
 │ destroy:    ~IntArray()                                  │
 │ copy:       IntArray(const IntArray&)                    │
 │ move:       IntArray(IntArray&&) noexcept                │
 │ assign:     operator=(IntArray)                          │
 │ access:     operator[]   size()   begin()   end()        │
 │ modify:     resize(n)   push_back(x)                     │
 └──────────────────────────────────────────────────────────┘
C++
#include <algorithm>
#include <cassert>
#include <cstddef>
#include <initializer_list>
#include <iostream>
#include <utility>

class IntArray
{
public:
    IntArray() = default;

    explicit IntArray(std::size_t size)
        : m_data{ size ? new int[size]{} : nullptr }, m_size{ size }
    {
    }

    IntArray(std::initializer_list<int> values) : IntArray(values.size())
    {
        std::copy(values.begin(), values.end(), m_data);
    }

    ~IntArray() { delete[] m_data; }

    IntArray(const IntArray& other) : IntArray(other.m_size)
    {
        std::copy(other.m_data, other.m_data + m_size, m_data);
    }

    IntArray(IntArray&& other) noexcept
        : m_data{ std::exchange(other.m_data, nullptr) }, m_size{ std::exchange(other.m_size, 0) }
    {
    }

    IntArray& operator=(IntArray other) noexcept
    {
        std::swap(m_data, other.m_data);
        std::swap(m_size, other.m_size);
        return *this;
    }

    int& operator[](std::size_t i)
    {
        assert(i < m_size);
        return m_data[i];
    }

    const int& operator[](std::size_t i) const
    {
        assert(i < m_size);
        return m_data[i];
    }

    std::size_t size() const { return m_size; }

    void resize(std::size_t size)
    {
        IntArray replacement(size);
        std::copy(m_data, m_data + std::min(size, m_size), replacement.m_data);
        *this = std::move(replacement);
    }

    void push_back(int value)
    {
        resize(m_size + 1);
        m_data[m_size - 1] = value;
    }

    int* begin() { return m_data; }
    int* end() { return m_data + m_size; }
    const int* begin() const { return m_data; }
    const int* end() const { return m_data + m_size; }

private:
    int* m_data{ nullptr };
    std::size_t m_size{ 0 };
};

int main()
{
    IntArray a{ 1, 2, 3 };
    a.push_back(4);
    for (int x : a)
    {
        std::cout << x << ' ';    // 1 2 3 4
    }
    std::cout << '\n';
    return 0;
}

Two details deserve a closer look.

One assignment operator serves both copy and move. It takes its parameter by value. When the argument is an lvalue, the parameter is built by the copy constructor. When it is an rvalue, it is built by the move constructor. Either way, the function swaps contents with it and lets it carry the old data away. That is copy and swap again.

begin() and end() make the range-based loop work. A range-based for needs nothing more than those two functions returning something that behaves like an iterator, and a plain pointer does.

std::initializer_list

 IntArray a{ 1, 2, 3 };
            └───┬───┘
    the compiler builds a hidden constant array [1, 2, 3]
    and passes a small view of it: std::initializer_list<int>
        with  begin()   end()   size()

A constructor taking a std::initializer_list<T> is what lets a class be initialized from a braced list of any length.

Braces prefer the list constructor

If a class has an initializer_list constructor, brace initialization chooses it whenever it can. That is the reason for the rule in 5.01 std::vector Basics: std::vector<int> v{ 5 }; is one element with the value 5. std::vector<int> v(5); is five elements. IntArray has the same behaviour, which is why resize writes IntArray replacement(size); with parentheses.

What a real vector does better

push_back here reallocates and copies every time, so adding n elements costs O(n²) in total. std::vector keeps a capacity larger than its size and grows it by a constant factor when full, making push_back amortized constant time (5.03 Vector as a Stack, and Capacity). Adding that is the natural next step.
