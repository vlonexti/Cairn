Operator Overloading Basics

lesson 6.077 of 9 in milestone 65 min3 practice tasks

Operators can be taught to work with your own types, so that a + b, a == b and std::cout << a all make sense. An operator is simply a function named operator+. Use non-member functions for symmetric operators, and = default for comparisons.

Operators are functions

For built-in types, a + b is built into the language. For your own types, the compiler looks for a function with a special name.

Output
 a + b      means      operator+(a, b)       a non-member function
            or         a.operator+(b)        a member function

Defining that function is operator overloading. It adds no new capability. It lets types such as vectors, fractions and money read the way the maths does.

Arithmetic operators

C++
#include <iostream>

class Vec2
{
public:
    Vec2(double x, double y) : m_x{ x }, m_y{ y } {}

    Vec2& operator+=(const Vec2& other)
    {
        m_x += other.m_x;
        m_y += other.m_y;
        return *this;
    }

    friend Vec2 operator+(Vec2 a, const Vec2& b)
    {
        a += b;
        return a;
    }

    friend Vec2 operator*(const Vec2& v, double k) { return { v.m_x * k, v.m_y * k }; }
    friend Vec2 operator*(double k, const Vec2& v) { return v * k; }

    friend std::ostream& operator<<(std::ostream& out, const Vec2& v)
    {
        return out << '(' << v.m_x << ", " << v.m_y << ')';
    }

private:
    double m_x{};
    double m_y{};
};

int main()
{
    Vec2 p{ 1, 2 };
    const Vec2 v{ 3, 4 };
    std::cout << p + v * 2 << '\n';    // (7, 10)
    p += v;
    std::cout << p << '\n';            // (4, 6)
    return 0;
}

Three points in that class are worth isolating.

Detail Why
+= is a member and returns *this by reference It modifies its left operand, and can be chained
+ is written in terms of += One place holds the arithmetic. a is taken by value, so it is already a copy to modify and return.
* is defined twice v * 2 and 2 * v are different calls. A member function could only handle the first, because the left operand would have to be a Vec2.

Input and output operators

std::cout << v calls operator<<(std::cout, v). The left operand is the stream, a type you cannot add members to, so this operator must be a non-member.

C++
friend std::ostream& operator<<(std::ostream& out, const Vec2& v)
{
    return out << '(' << v.m_x << ", " << v.m_y << ')';
}

friend std::istream& operator>>(std::istream& in, Vec2& v)
{
    return in >> v.m_x >> v.m_y;
}

Both return the stream they were given. That is what makes chaining work:

flowchart LR
    A["std::cout &lt;&lt; a &lt;&lt; b"] --> B["operator&lt;&lt;(std::cout, a)<br/>returns std::cout"] --> C["operator&lt;&lt;(std::cout, b)"]

The same technique prints an enum by name:

C++
std::ostream& operator<<(std::ostream& out, Color c)
{
    switch (c)
    {
    case Color::red:   return out << "red";
    case Color::green: return out << "green";
    case Color::blue:  return out << "blue";
    }
    return out << "unknown";
}

Comparison operators

Since C++20 the compiler can write these for you.

C++
class Version
{
public:
    Version(int major, int minor, int patch) : m_major{ major }, m_minor{ minor }, m_patch{ patch } {}

    bool operator==(const Version&) const = default;
    auto operator<=>(const Version&) const = default;

private:
    int m_major{};
    int m_minor{};
    int m_patch{};
};

Version{ 1, 2, 0 } < Version{ 1, 10, 0 };    // true
Declaration You get
operator== defaulted == and !=, comparing every member
operator<=> defaulted <, >, <= and >=, comparing members in declaration order

<=> is the three-way comparison operator, nicknamed the spaceship. It answers "less, equal or greater?" in one call, and the compiler rewrites a < b as (a <=> b) < 0.

When the default order is wrong, write it yourself:

C++
std::strong_ordering operator<=>(const Card& other) const
{
    return m_rank <=> other.m_rank;    // compare by rank only
}

If you write <=> by hand, also write ==. The compiler only derives == from a defaulted <=>.

Member or non-member?

    Q -->|"+ - * / == &lt; &lt;&lt; &gt;&gt;<br/>symmetric, or a stream on the left"| N["Non-member,<br/>a friend if it needs private data"]

The rules

You cannot
Invent new operators There is no **
Change precedence or the number of operands * always binds tighter than +
Overload ::, ., ?: or sizeof
Overload an operator for built-in types only At least one operand must be a type you defined
Keep the meaning obvious

Overload an operator only when its meaning for your type is what anyone would expect. A + that subtracts, or a << that deletes a file, makes code impossible to read. When in doubt, use a named function.
