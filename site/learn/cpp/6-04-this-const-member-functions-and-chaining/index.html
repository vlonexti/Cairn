this, const Member Functions and Chaining

lesson 6.044 of 9 in milestone 65 min3 practice tasks

Inside a member function, this points at the object the function was called on. Mark every function that does not modify the object const: only those can be called on const objects. Return *this by reference to allow chaining.

The hidden this pointer

There is one copy of each member function, shared by every object of the class. So how does add know whose m_count to change?

C++
class Counter
{
public:
    void add(int n) { m_count += n; }

private:
    int m_count{};
};

Counter a{};
Counter b{};
a.add(5);

The compiler passes the object's address as a hidden argument. Conceptually it rewrites the code to:

C++
void add(Counter* const this, int n) { this->m_count += n; }

add(&a, 5);
flowchart LR
    A["a.add(5)"] -->|"this is &a"| F["add<br/>this->m_count += 5"]
    B["b.add(5)"] -->|"this is &b"| F

Inside any member function, this is a pointer to the object it was called on. Writing m_count is shorthand for this->m_count. You rarely need to write this yourself. The main exception follows.

Method chaining

A member function that returns a reference to its own object lets the next call follow immediately.

C++
#include <iostream>

class Calc
{
public:
    Calc& add(int n)
    {
        m_value += n;
        return *this;
    }

    Calc& multiply(int n)
    {
        m_value *= n;
        return *this;
    }

    int value() const { return m_value; }

private:
    int m_value{};
};

int main()
{
    Calc c{};
    std::cout << c.add(5).multiply(3).add(1).value() << '\n';    // 16
    return 0;
}

*this is the object itself. Returning it by reference means each call in the chain works on the same object. Returning by value would hand each call a copy.

std::cout << a << b works on the same principle: each << returns the stream.

const member functions

A const after the parameter list is a promise: this function does not modify the object.

C++
class Circle
{
public:
    double area() const { return 3.14159 * m_radius * m_radius; }
    void setRadius(double radius) { m_radius = radius; }

private:
    double m_radius{ 1.0 };
};

const Circle unit{};
unit.area();          // fine: area is a const member function
unit.setRadius(2);    // error: setRadius is not
Declared as Callable on a non-const object Callable on a const object or through const&
void f() Yes No
void f() const Yes Yes

Inside a const member function, this is a pointer to const, so the compiler rejects any attempt to change a member.

[!tip] Mark every member function that does not change the object const Objects are passed by const& most of the time (4.03 References). A function that is not marked const cannot be called through such a reference, even if it changes nothing. Getting this right throughout a codebase is called const correctness.

Overloading on const

A class can offer two versions of a function, one for const objects and one for the rest.

C++
class Text
{
public:
    char& at(std::size_t i) { return m_text[i]; }                // modifiable
    const char& at(std::size_t i) const { return m_text[i]; }    // read-only

private:
    std::string m_text{};
};

The compiler picks by whether the object is const. This is how v[i] on a vector gives a modifiable element or a read-only one.

mutable

A member marked mutable may be changed even inside a const function.

C++
class Cache
{
public:
    int lookup() const
    {
        ++m_hits;
        return 42;
    }

private:
    mutable int m_hits{};
};

It is for data that is not part of the object's visible state: usage counters, cached results, locks. Use it rarely.

Returning references to members

C++
const std::string& name() const { return m_name; }    // cheap and read-only
std::string& name() { return m_name; }                // hands out write access

The first is the standard getter for anything expensive to copy. The second lets callers change the member directly, which bypasses whatever rule the class was protecting.

Do not keep a reference into a temporary object
C++
const auto& n{ makePlayer().name() };    // the Player is destroyed at the end of this line

n now refers to a member of an object that no longer exists.

Ref-qualifiers

You can go one step further and provide different behaviour for named objects and for temporaries.

C++
const std::string& name() const& { return m_name; }        // called on a named object
std::string name() && { return std::move(m_name); }        // called on a temporary

The & and && after the parameter list are ref-qualifiers. With this pair, the dangerous line above becomes safe, because a temporary hands back its string by value. std::move is explained in 7.05 Move Semantics.
