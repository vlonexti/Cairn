Inheritance Basics

lesson 8.011 of 7 in milestone 85 min3 practice tasks

Inheritance defines a new class (the derived class) from an existing one (the base class), reusing its members and adding more. It models is-a: a Dog is an Animal. The base part is constructed first and destroyed last.

Modelling "is-a"

Composition says one thing has another. Inheritance says one thing is a kind of another. A derived class contains everything its base class has, and can be used wherever the base is expected.

Syntax

C++
#include <iostream>
#include <string>

class Animal
{
public:
    std::string name{};
    int age{};

    void eat() const { std::cout << name << " eats\n"; }
};

class Dog : public Animal
{
public:
    void fetch() const { std::cout << name << " fetches\n"; }
};

int main()
{
    Dog rex{};
    rex.name = "Rex";
    rex.eat();      // inherited from Animal
    rex.fetch();    // Dog's own
    return 0;
}

: public Animal makes Dog a derived class of Animal. A Dog object physically contains an Animal, called its base subobject, followed by whatever Dog adds.

 a Dog object
 ┌─────────────────────────────┐

 │ │ name          age       │ │     the base part comes first
 │ └─────────────────────────┘ │

Construction and destruction order

A derived object is built from the inside out.

C++
#include <iostream>
#include <string>
#include <string_view>

class Animal
{
public:
    explicit Animal(std::string_view name) : m_name{ name } { std::cout << "Animal constructed\n"; }
    ~Animal() { std::cout << "Animal destroyed\n"; }

protected:
    std::string m_name{};
};

class Dog : public Animal
{
public:
    Dog(std::string_view name, std::string_view breed)
        : Animal{ name }, m_breed{ breed }
    {
        std::cout << "Dog constructed\n";
    }

    ~Dog() { std::cout << "Dog destroyed\n"; }

private:
    std::string m_breed{};
};

int main()
{
    Dog d{ "Rex", "Collie" };
    return 0;
}

Step Order
Construction Base class, then the derived class's members, then the derived constructor's body
Destruction Exactly the reverse

The reasoning is the one from 6.03 Destructors and Object Lifetime: the derived part may depend on the base part, so the base must exist first and outlast it.

A derived class initializes its base through a base constructor

Dog cannot write m_name{ name } in its own initializer list, because m_name is not Dog's member to initialize. It names a base constructor instead: Animal{ name }. If none is named, the base's default constructor is used, and if there is none the code does not compile.

Inheriting constructors

Constructors are not inherited by default. When a derived class adds no data that needs initializing, it can adopt the base's constructors wholesale:

C++
class Dog : public Animal
{
public:
    using Animal::Animal;
};

The is-a test

Inheritance is a strong commitment. Before using it, ask whether every derived object can stand in for a base object everywhere a base is used. This is the idea of substitutability.

Proposed Verdict Why
Circle is a Shape Yes Anything valid for a shape is valid for a circle
Stack is a Vector No A vector allows insertion anywhere; a stack must not. Use composition.
Square is a Rectangle Usually no Code that sets a rectangle's width and height independently breaks a square

When the test fails, the relationship is "is implemented using", and that is composition: 7.07 Object Relationships.
