auto, Type Deduction and Type Aliases

lesson 4.077 of 7 in milestone 45 min3 practice tasks

auto asks the compiler to work out a variable's type from its initializer. using Name = Type; gives a type a second name. Both shorten code; use them where the type is obvious or noisy.

auto: let the compiler name the type

Every initializer already has a type. With auto, the variable simply takes it.

C++
auto a{ 5 };            // int
auto b{ 5.0 };          // double
auto c{ 'x' };          // char
auto d{ add(2, 3) };    // whatever add returns
flowchart LR
    I["initializer: 3.14"] -->|"the compiler reads its type"| A["auto x is double"]

This is type deduction. The variable still has one fixed type, chosen at compile time. auto is not "any type".

[!warning] Text in quotes is not a std::string auto s{ "hi" }; deduces const char*, the primitive C form of a string, because that is what a string literal is. Write the type out when you want a std::string.

auto drops const and references

This is the rule that catches people.

C++
const int ci{ 5 };
auto x{ ci };           // int: const is dropped
const auto y{ ci };     // const int: you added it back

int n{ 1 };
int& ref{ n };
auto z{ ref };          // int: a COPY of n, not a reference
auto& z2{ ref };        // int&: a reference to n

Plain auto always means "a fresh copy". Anything more, you ask for:

You write You get
auto A copy, not const
const auto A const copy
auto& A reference
const auto& A const reference: no copy, no modification

const auto& is the form you will write most, in loops over containers in Milestone 5.

When to use it

Good use Why
The type is written on the same line auto p{ static_cast<double>(x) }; repeats nothing
The type is long and adds nothing Iterators and lambdas, coming in Milestone 5
Loop variables for (const auto& item : items)
Poor use Why
The type is not obvious from the line auto x{ getValue() }; hides whether x is an int or a double
You want a conversion auto never converts; it takes exactly the initializer's type

The test is whether a reader can tell the type without looking elsewhere.

Deduced return types

A function can use auto in place of its return type.

C++
auto average(int total, int count)
{
    return static_cast<double>(total) / count;    // deduced: double
}

Every return in the function must produce the same type. For functions other people call, writing the return type out is usually kinder to the reader.

You will also see the trailing return type form, which means the same as the ordinary one:

C++
auto add(int a, int b) -> int
{
    return a + b;
}

Type aliases

using gives an existing type an additional name.

C++
using Score = int;
using Inventory = std::vector<std::string>;

Score best{ 9001 };
Benefit Example
States intent Score says more than int
Shortens long types Inventory instead of std::vector<std::string>
One place to change Switching Score to long long later is a one-line edit

The older spelling is typedef int Score;. It does the same thing and reads backwards. Prefer using.

An alias is not a new type

Score and int are the same type and mix freely. The compiler will not stop you passing a Score where an Age is expected. For a type that is truly distinct, use a struct or an enum class.

decltype

decltype(expression) is the type of an expression, without evaluating it.

C++
int x{ 5 };
decltype(x) y{ 10 };    // y is int

Unlike auto, it keeps const and references exactly as they are. It earns its place in templates, where you need to name a type you cannot write directly.
