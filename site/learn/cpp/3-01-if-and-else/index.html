if and else

lesson 3.011 of 8 in milestone 35 min4 practice tasks

if (condition) { ... } runs a block only when the condition is true. else if adds further choices and else catches everything left. Only the first branch that matches runs.

Programs that decide

Until now every statement ran, top to bottom, every time. Control flow is how a program chooses which statements to run. if is the foundation of it.

C++
#include <iostream>

int main()
{
    int score{ 73 };

    if (score >= 90)
    {
        std::cout << "A\n";
    }
    else if (score >= 80)
    {
        std::cout << "B\n";
    }
    else if (score >= 70)
    {
        std::cout << "C\n";
    }
    else
    {
        std::cout << "F\n";
    }
    return 0;
}
flowchart TD
    S["score is 73"] --> Q1{"score >= 90?"}
    Q1 -- yes --> A["A"]
    Q1 -- no --> Q2{"score >= 80?"}
    Q2 -- yes --> B["B"]
    Q2 -- no --> Q3{"score >= 70?"}
    Q3 -- yes --> C["C (this one runs)"]
    Q3 -- no --> F["F"]
Part Meaning
if (condition) Run the block when the condition is true
else if (condition) Otherwise, try this condition
else Otherwise, when nothing above matched

Each path through the statement is called a branch. The conditions are tested in order, and only the first true branch runs. The rest are skipped, even if their conditions would also be true.

Order does the work for you

Because of that rule, else if (score >= 80) does not need to say && score < 90. If execution reaches it, the first test has already failed.

Always use braces

Without braces, an if controls exactly one statement.

C++
if (lives == 0)
    std::cout << "Game over\n";
    resetGame();    // NOT part of the if. This runs every time.

The indentation suggests one thing and the compiler does another. Write the braces every time, even for one line.

Combining conditions

Two nested tests can usually be flattened with &&:

C++
if (hasTicket)
{
    if (age >= 18)
    {
        std::cout << "Enjoy the film\n";
    }
}
C++
if (hasTicket && age >= 18)
{
    std::cout << "Enjoy the film\n";
}

The second says the same thing with less to read.

Early return

Deeply nested code is hard to follow. A common remedy is to deal with the unusual cases first and leave.

C++
double safeDivide(double a, double b)
{
    if (b == 0.0)
    {
        std::cout << "Cannot divide by zero\n";
        return 0.0;
    }
    return a / b;
}

A check at the top that rejects bad input is called a guard clause. With the problem cases out of the way, the main logic sits at the outer level with no indentation.

A variable that belongs to the if

You can create a variable inside the if itself. It exists only for that statement.

C++
if (int remainder{ n % 3 }; remainder == 0)
{
    std::cout << "divisible by three\n";
}
// remainder no longer exists here

The part before the ; creates the variable and the part after is the condition. This keeps a helper variable from lingering where it is not needed.

Four classic traps

Written Problem
if (x = 5) Assigns 5 to x, then treats 5 as true. You meant ==.
if (x > 0); The ; ends the if. The block after it always runs.
if (0 < x < 10) Always true. Write x > 0 && x < 10.
if (a == b) with two double values Rounding makes this unreliable: 2.03 Floating Point Numbers

The compiler warns about the first two.
