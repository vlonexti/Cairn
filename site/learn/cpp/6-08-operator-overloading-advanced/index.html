Operator Overloading — Advanced

lesson 6.088 of 9 in milestone 65 min3 practice tasks

The remaining operators: unary (-x, !x), increment and decrement in prefix and postfix form, subscript [], the function-call operator (), conversions such as explicit operator bool, and assignment =.

Unary operators

A unary operator has one operand, the object itself, so as a member it takes no parameters.

C++
class Vec2
{
public:
    Vec2(double x, double y) : m_x{ x }, m_y{ y } {}

    Vec2 operator-() const { return { -m_x, -m_y }; }           // -v
    bool operator!() const { return m_x == 0 && m_y == 0; }     // !v: "is it zero?"

private:
    double m_x{};
    double m_y{};
};

Both are const and return a new value. Negating a vector should not change the original.

Increment and decrement

Prefix and postfix are two different functions. The language tells them apart by an unused int parameter on the postfix form.

C++
class Digit
{
public:
    Digit& operator++()          // prefix: ++d
    {
        m_digit = (m_digit == 9) ? 0 : m_digit + 1;
        return *this;
    }

    Digit operator++(int)        // postfix: d++
    {
        const Digit old{ *this };
        ++(*this);
        return old;
    }

private:
    int m_digit{};
};
flowchart LR
    P["++d"] --> P1["increment"] --> P2["return *this by reference"]
    Q["d++"] --> Q1["copy the old value"] --> Q2["increment"] --> Q3["return the copy by value"]
Prefix ++d Postfix d++
Signature T& operator++() T operator++(int)
Returns The object itself, already incremented A copy of the old value
Cost Nothing extra One copy

Postfix is written in terms of prefix, so the rule lives in one place. The extra copy is the reason to prefer ++it for iterators and other class types.

Subscript []

C++
class IntList
{
public:
    int& operator[](std::size_t i) { return m_data[i]; }
    const int& operator[](std::size_t i) const { return m_data[i]; }

private:
    std::vector<int> m_data{};
};

IntList list{};
list[2] = 7;

Returning a reference is what allows list[2] = 7. The const overload (6.04 this, const Member Functions and Chaining) makes reading work on const objects while preventing writes. operator[] must be a member.

The function-call operator ()

A class that defines operator() produces objects that can be called like functions. Such an object is a function object, or functor.

C++
#include <iostream>

class Accumulator
{
public:
    int operator()(int x)
    {
        m_total += x;
        return m_total;
    }

private:
    int m_total{};
};

int main()
{
    Accumulator acc{};
    acc(5);
    acc(10);
    std::cout << acc(1) << '\n';    // 16
    return 0;
}

Unlike a plain function, a functor has member variables, so it remembers state between calls.

This is what a lambda really is. The compiler turns each lambda into a small class with an operator(), and the captures become its members:

Output
 [limit](int x) { return x > limit; }

 becomes, roughly:

 class Unnamed
 {
 public:
     bool operator()(int x) const { return x > limit; }
 private:
     int limit;
 };

That explains two things from 5.07 Lambdas: every lambda has its own unnamed type, and captures by copy are read-only unless the lambda is mutable, because operator() is const by default.

operator() can take any number of parameters, which also makes it a common choice for grid access: matrix(row, col).

Conversion operators

A conversion operator lets an object be converted to another type. It is the mirror image of a converting constructor (6.02 Constructors).

C++
class Cents
{
public:
    explicit Cents(int cents) : m_cents{ cents } {}

    explicit operator int() const { return m_cents; }
    explicit operator bool() const { return m_cents != 0; }

private:
    int m_cents{};
};

Cents c{ 250 };
int raw{ static_cast<int>(c) };
if (c)
{
    std::cout << "not empty\n";
}

There is no return type in the declaration: the type converted to is the operator's name.

[!tip] Make conversion operators explicit Without it, your objects convert silently wherever an int or bool is accepted, including in arithmetic. explicit operator bool is the one with a useful exception: it still works directly in an if or while condition, which is exactly where you want it.

Assignment =

C++
class Thing
{
public:
    Thing& operator=(const Thing& other)
    {
        if (this == &other)
        {
            return *this;    // assigning an object to itself: nothing to do
        }
        // copy other's data into this object
        return *this;
    }
};

This is the copy assignment operator. It differs from the copy constructor in that the left-hand object already exists and has old contents to deal with.

Code Runs
Thing b{ a }; Copy constructor: b is being created
b = a; Copy assignment: b already exists

The compiler generates one that assigns each member in turn. You need to write your own only when the class owns a resource, and that story is told in full in 7.03 Copy Semantics — Shallow vs Deep.

Operators and templates

Once your type has the operators, generic code accepts it with no further work.

C++
template <typename T>
T sum3(const T& a, const T& b, const T& c)
{
    return a + b + c;
}

sum3(Vec2{ 1, 1 }, Vec2{ 2, 2 }, Vec2{ 3, 3 });    // uses your operator+
std::sort(cards.begin(), cards.end());             // uses your operator<

That is the practical payoff of overloading: your types plug into the standard library.

Three operators to leave alone

Do not overload &&, || or the comma operator. The built-in versions evaluate left to right and can stop early; overloaded versions are ordinary function calls and lose that behaviour.
