std::optional, std::variant, std::any and std::tuple

lesson 10.044 of 9 in milestone 106 min3 practice tasks

Vocabulary types that say what you mean. optional<T> is maybe a T. variant<A, B, C> is exactly one of A, B or C. any is anything at all. tuple<A, B, C> is an A and a B and a C, without names. pair is a tuple of two.

Types that express intent

These four are called vocabulary types because they appear in interfaces everywhere and every C++ programmer reads them the same way.

You mean Type
A value that may be absent std::optional<T>
A value, or an error std::expected<T, E>: 9.06 Exception Safety, noexcept and std::expected
Exactly one of several known types std::variant<...>
Several values together A struct, or std::tuple
A value of any type whatever std::any

std::optional: maybe a value

C++
#include <iostream>
#include <optional>
#include <vector>

std::optional<std::size_t> findIndex(const std::vector<int>& v, int target)
{
    for (std::size_t i{ 0 }; i < v.size(); ++i)
    {
        if (v[i] == target)
        {
            return i;
        }
    }
    return std::nullopt;
}

int main()
{
    const std::vector<int> nums{ 4, 7, 9 };
    if (const auto index{ findIndex(nums, 7) })
    {
        std::cout << "found at " << *index << '\n';
    }
    std::cout << findIndex(nums, 5).has_value() << '\n';    // 0
    return 0;
}
 optional<int>   ┌───────────┬──────────┐
                 │ has value │   int    │
                 │   true    │    3     │     *opt is 3
                 └───────────┴──────────┘
                 │   false   │ (unused) │     std::nullopt

An optional<T> holds its T inside itself, with a flag. There is no heap allocation.

Operation Behaviour when empty
if (opt) or opt.has_value() False
*opt, opt->member Undefined behaviour: check first
opt.value() Throws std::bad_optional_access
opt.value_or(fallback) Returns the fallback

It replaces the tradition of sentinel values: -1, nullptr or an empty string standing for "none". Those rely on every caller remembering the convention. An optional makes the possibility part of the type. C++23 adds and_then, transform and or_else for chaining operations on optionals without nested ifs.

std::variant: one of these types

A variant holds a value of exactly one of the types listed, and knows which.

C++
std::variant<int, double, std::string> v{ 42 };
v = 3.14;       // now holds a double
v = "hello";    // now holds a std::string
Operation Result
std::holds_alternative<T>(v) Whether it currently holds a T
std::get<T>(v) The value; throws std::bad_variant_access if it holds something else
std::get_if<T>(&v) A pointer to the value, or nullptr
v.index() The position of the active alternative in the list

Each of the types is an alternative. A variant is a type-safe replacement for a C union: it always knows which member is live.

std::visit: handling every case

std::visit calls a function with whatever the variant currently holds. The function must accept every alternative, and the usual way to build one is from a set of lambdas.

C++
#include <iostream>
#include <variant>
#include <vector>

struct Circle
{
    double radius{};
};

struct Rect
{
    double width{};
    double height{};
};

using Shape = std::variant<Circle, Rect>;

template <typename... Fs>
struct Overloaded : Fs...
{
    using Fs::operator()...;
};

double area(const Shape& shape)
{
    return std::visit(Overloaded{
        [](const Circle& c) { return 3.14159 * c.radius * c.radius; },
        [](const Rect& r) { return r.width * r.height; },
    }, shape);
}

int main()
{
    const std::vector<Shape> shapes{ Circle{ 1.0 }, Rect{ 2.0, 3.0 } };
    for (const Shape& shape : shapes)
    {
        std::cout << area(shape) << '\n';
    }
    return 0;
}

Overloaded inherits from every lambda it is given and brings all their operator()s into one overload set. It uses a variadic template (9.03 Variadic Templates and Fold Expressions), multiple inheritance and CTAD in three lines. It is common enough to be worth memorising.

flowchart LR
    V["a Shape"] --> Q{"std::visit:<br/>which alternative?"}
    Q -->|Circle| C["the Circle lambda"]
    Q -->|Rect| R["the Rect lambda"]

If you add an alternative to Shape and forget to handle it, the code does not compile.

Variant or virtual functions?

Both give "one variable, several possible types".

std::variant Inheritance with virtual
Set of types Closed: listed up front Open: new classes can be added later
Adding an operation Easy: write a new visitor Hard: edit every class
Adding a type Hard: update every visitor Easy: write one class
Storage By value, no heap, no vtable Usually a heap object behind a pointer
A forgotten case A compile error A missing override may go unnoticed

Choose a variant when the set of types is fixed and operations keep being added. Choose inheritance when new types will be added by code you do not control.

std::any: anything

C++
#include <any>

std::any a{ 5 };
a = std::string{ "hi" };
std::cout << std::any_cast<std::string>(a) << '\n';    // throws std::bad_any_cast if the type is wrong

An any can hold any copyable type, discovers which only at run time, and may allocate. It is rarely the right tool: if you know the possible types, a variant is safer and faster. How it works inside is the subject of 11.06 Type Erasure.

std::pair and std::tuple

C++
#include <tuple>

std::pair<std::string, int> p{ "Ann", 31 };
// p.first, p.second

std::tuple<std::string, int, double> t{ "Bo", 25, 1.82 };
std::get<0>(t);         // "Bo": by position
std::get<double>(t);    // 1.82: by type, when that type appears once

const auto [name, age, height]{ t };    // structured bindings

std::tuple<int, int> divmod(int a, int b)
{
    return { a / b, a % b };
}

const auto [quotient, remainder]{ divmod(17, 5) };    // 3 and 2

std::tie builds a tuple of references, which makes comparing several fields in order a single line:

C++
bool operator<(const Person& a, const Person& b)
{
    return std::tie(a.last, a.first, a.age) < std::tie(b.last, b.first, b.age);
}

Tuples compare lexicographically: by the first element, then the second where the first are equal, and so on.

Prefer a named struct when the values mean something

result.quotient documents itself. std::get<0>(result) does not. Use tuples for generic code and throwaway returns, and structs for anything a reader has to understand.
