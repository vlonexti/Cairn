Multiple Files and Headers

lesson 1.088 of 10 in milestone 15 min3 practice tasks

Real programs are split across files. A header (.h) says what exists. A source file (.cpp) says how it works. #include the header wherever you need those functions.

Why split a program up?

A program in one file is fine at fifty lines. At five thousand it is a nightmare to find anything in. So programmers group related functions into their own files.

That raises a problem you met in the last lesson: a function must be known before it is called. If add lives in another file, how does main.cpp know about it? The answer is a header file.

Menu and kitchen

Think of a restaurant. The menu lists what you can order. The kitchen is where the food is made. You only need the menu to order.

flowchart LR
    H["mathx.h<br/>the menu<br/>(declarations)"]
    C["mathx.cpp<br/>the kitchen<br/>(definitions)"]
    M["main.cpp<br/>the customer<br/>(calls the functions)"]
    H -.->|"#include"| C
    H -.->|"#include"| M
File Contains Example
mathx.h Declarations: the name of each function, what it needs and what it returns int add(int x, int y);
mathx.cpp Definitions: the actual instructions int add(int x, int y) { return x + y; }
main.cpp Code that uses the functions add(2, 3)

mathx.h

C++
#pragma once

int add(int x, int y);
int multiply(int x, int y);

mathx.cpp

C++
#include "mathx.h"

int add(int x, int y)
{
    return x + y;
}

int multiply(int x, int y)
{
    return x * y;
}

main.cpp

C++
#include <iostream>
#include "mathx.h"

int main()
{
    std::cout << add(2, 3) << ' ' << multiply(2, 3) << '\n';
    return 0;
}

What #include really does

Nothing clever. It pastes the contents of the named file in at that spot, before the compiler starts.

 main.cpp as you wrote it            main.cpp as the compiler sees it
┌──────────────────────────┐        ┌────────────────────────────┐
│ #include "mathx.h"       │  ───▶  │ int add(int x, int y);     │
│                          │        │ int multiply(int x, int y);│
│ int main() { ... }       │        │ int main() { ... }         │
└──────────────────────────┘        └────────────────────────────┘
Written as Used for
#include <iostream> Headers that come with C++
#include "mathx.h" Headers you wrote yourself

How the pieces are joined

Remember the compiler and the linker from the first lesson? This is where the linker earns its place.

flowchart TD
    MC["main.cpp"] -->|"compiled on its own"| MO["main.obj<br/>needs: add, multiply"]
    XC["mathx.cpp"] -->|"compiled on its own"| XO["mathx.obj<br/>provides: add, multiply"]
    MO --> L["Linker<br/>matches needs to provides"]
    XO --> L
    L --> EXE["program.exe"]

Each .cpp file is compiled separately. While compiling main.cpp, the compiler only has the declaration of add. It trusts that the real thing exists somewhere. The linker then checks that it does.

"Unresolved external symbol"

This is the linker saying: "something calls add, but no file provides it." Either you declared a function and never wrote it, or its definition does not match the declaration exactly (a different name or different parameters).

#pragma once

Put this as the first line of every header you write. It stops the header being pasted twice into the same file, which can cause "already defined" errors as programs grow.

One rule to remember

How many times? Where it goes
Declaration (int add(int x, int y);) As often as you like The header
Definition (the version with a body) Exactly once in the whole program A .cpp file

If you put a function's body in a header, every file that includes it gets its own copy, and the linker complains that it has too many.
