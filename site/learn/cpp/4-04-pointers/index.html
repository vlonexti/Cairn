Pointers

lesson 4.044 of 7 in milestone 45 min4 practice tasks

A pointer is a variable that stores a memory address. &x gives the address of x. *ptr follows the address to the value. Unlike a reference, a pointer can be nullptr and can be aimed at something else.

A variable that holds an address

Every variable lives at an address in memory (2.01 Memory, Bits and Fundamental Types). A pointer stores one of those addresses.

C++
int x{ 42 };
int* ptr{ &x };    // ptr holds the address of x
       ptr                          x
  ┌────────────┐             ┌────────────┐
  │   0x7ff0 ──┼───────────▶ │     42     │
  └────────────┘             └────────────┘
  lives at 0x7ff8            lives at 0x7ff0
Expression Meaning Value here
x The value of x 42
&x The address of x 0x7ff0
ptr The address stored in ptr 0x7ff0
*ptr The value at that address 42
&ptr The address of the pointer itself 0x7ff8

Following a pointer to the thing it points at is called dereferencing.

C++
*ptr = 100;                // change x through the pointer
std::cout << x << '\n';    // 100

[!info] * and & each have two meanings

Symbol In a declaration In an expression
* int* p: p is a pointer to int *p: dereference p
& int& r: r is a reference to int &x: the address of x

Aiming a pointer somewhere else

C++
#include <iostream>

int main()
{
    int a{ 1 };
    int b{ 2 };
    int* p{ &a };
    std::cout << *p << '\n';    // 1
    p = &b;                     // p now points at b
    std::cout << *p << '\n';    // 2
    return 0;
}

Assigning to p changes where it points. Assigning to *p changes the thing it points at. Keep those two apart and pointers stop being confusing.

nullptr: pointing at nothing

A pointer can deliberately point at nothing. That value is nullptr.

C++
int* p{ nullptr };

if (p != nullptr)
{
    std::cout << *p << '\n';
}
else
{
    std::cout << "no value\n";
}

A pointer converts to false when it is null, so if (p) means the same as if (p != nullptr).

Dereferencing a null pointer is undefined behaviour

In practice the program usually crashes with an access violation. Whenever a pointer might be null, test it before you dereference it.

Passing an address to a function

C++
void reset(int* p)
{
    if (p)
    {
        *p = 0;
    }
}

int score{ 99 };
reset(&score);     // the & at the call shows that score may be changed
reset(nullptr);    // allowed: "there is nothing to reset"

A pointer parameter can express "there might be no object". A reference parameter cannot.

Pointers and const

const can apply to the thing pointed at, to the pointer itself, or to both. Read the declaration from right to left.

Declaration Read as Change the value through it? Aim it elsewhere?
const int* p pointer to const int No Yes
int* const p const pointer to int Yes No
const int* const p const pointer to const int No No

The first is by far the most common. It means "I will look, but not touch", exactly like a const reference.

Pointers to structs: ->

To reach a member through a pointer, use ->.

C++
struct Point
{
    int x{};
    int y{};
};

Point pt{ 3, 4 };
Point* pp{ &pt };

std::cout << (*pp).x << '\n';    // 3: dereference, then take the member
std::cout << pp->x << '\n';      // 3: the same thing, written the usual way

Pointer or reference?

Reference T& Pointer T*
Can be null No Yes
Can be aimed elsewhere No Yes
Must be initialized Yes No, but always do it

Use a reference unless you need one of the two things only a pointer can do. Pointers become essential with dynamic memory: 7.02 new and delete — Dynamic Memory.

Dangling pointers

Like a reference, a pointer can outlive its target.

C++
int* p{};
{
    int temp{ 5 };
    p = &temp;
}             // temp is destroyed here
*p = 1;       // undefined behaviour: p is dangling

Nothing sets p to null for you. It still holds the old address, and that memory may now be used for something else.
