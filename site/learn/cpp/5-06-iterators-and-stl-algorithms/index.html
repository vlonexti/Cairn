Iterators and STL Algorithms

lesson 5.066 of 11 in milestone 55 min4 practice tasks

An iterator marks a position in a container. begin() is the first element and end() is one past the last. The <algorithm> library supplies tested functions (sort, find, count and many more) that work on any such range.

Iterators mark positions

An iterator behaves like a pointer to an element: you can read through it with * and step it forward with ++.

 std::vector<int> v{ 10, 20, 30, 40 };

   v.begin()                       v.end()
      ▼                               ▼
   ┌──────┬──────┬──────┬──────┐ ┌ ─ ─ ─┐
   │  10  │  20  │  30  │  40  │   past
   └──────┴──────┴──────┴──────┘ └ ─ ─ ─┘
C++
auto it{ v.begin() };
std::cout << *it << '\n';    // 10
++it;
std::cout << *it << '\n';    // 20

end() does not refer to an element. It is the position just after the last one, and it must never be dereferenced. A pair of iterators describes a half-open range, written [begin, end): the first is included and the last is not.

This is what a range-based loop does underneath:

C++
for (auto i{ v.begin() }; i != v.end(); ++i)
{
    std::cout << *i << ' ';
}
Pair Covers
begin(), end() First to last
cbegin(), cend() The same, read-only
rbegin(), rend() Last to first

The point of iterators is that they give every container the same interface. An algorithm written against iterators works for a vector, an array, a string, and containers you have not met yet.

Algorithms

#include <algorithm> (and <numeric> for a few) gives you about a hundred functions that operate on ranges.

C++
#include <algorithm>
#include <iostream>
#include <numeric>
#include <vector>

int main()
{
    std::vector<int> v{ 30, 10, 40, 20, 10 };

    std::sort(v.begin(), v.end());                             // 10 10 20 30 40
    const auto tens{ std::count(v.begin(), v.end(), 10) };     // 2
    const int total{ std::accumulate(v.begin(), v.end(), 0) }; // 110

    const auto it{ std::find(v.begin(), v.end(), 30) };
    if (it != v.end())
    {
        std::cout << "30 is at index " << (it - v.begin()) << '\n';    // 3
    }
    std::cout << tens << " tens, total " << total << '\n';
    return 0;
}

[!note] "Not found" is end() Searching algorithms return an iterator. When nothing matches they return the range's end(). Always compare against it before dereferencing. Subtracting begin() from an iterator into a vector gives the index.

The ones worth knowing first

To Use
Sort std::sort; std::stable_sort keeps equal elements in their original order
Sort descending std::sort(first, last, std::greater{})
Reverse std::reverse
Find a value std::find
Find by a condition std::find_if
Count std::count, std::count_if
Sum or combine std::accumulate
Smallest, largest std::min_element, std::max_element (they return iterators)
Test a condition std::all_of, std::any_of, std::none_of
Copy std::copy, std::copy_if
Apply a function to each std::transform
Fill std::fill; std::iota writes 1, 2, 3, ...
Search sorted data std::binary_search, std::lower_bound
Shuffle std::shuffle(first, last, engine)

The _if versions take a function that decides which elements count. Supplying that function is what lambdas are for, in the next lesson.

Removing elements

C++20 added two plain functions that do what everyone wanted:

C++
std::erase(v, 20);                                  // remove every 20
std::erase_if(v, [](int x) { return x > 25; });     // remove by a condition

To remove duplicates: sort, then std::unique (which moves duplicates to the back and returns where they start), then erase that tail.

C++
std::sort(v.begin(), v.end());
v.erase(std::unique(v.begin(), v.end()), v.end());

The ranges versions

Passing begin() and end() every time is repetitive and allows mistakes such as mixing two containers. C++20's ranges algorithms take the container itself.

C++
std::ranges::sort(v);
const auto it{ std::ranges::find(v, 30) };

They do the same work with a cleaner call. Prefer them in new code. There is much more to ranges in 10.03 Ranges and Views (C++20/23).

Why not write the loop yourself?

Reason Detail
Correct They have been tested by millions of users. Your loop has not.
Clear std::sort states the intent. A hand-written loop has to be read and understood.
Fast Library authors optimise them for each compiler and processor.

A good habit: before writing a loop over a container, ask whether an algorithm already says what you mean.
