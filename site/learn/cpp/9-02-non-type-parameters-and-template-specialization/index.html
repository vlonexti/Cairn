Non-Type Parameters and Template Specialization

lesson 9.022 of 6 in milestone 95 min3 practice tasks

Templates can take values as well as types, as in template <int N>: that is how std::array<T, N> knows its size. Specialization supplies a custom version for particular arguments: full (Box<bool>) or partial (Box<T*>).

Non-type template parameters

A template parameter can be a compile-time value.

C++
#include <cstddef>
#include <iostream>

template <typename T, std::size_t N>
class StaticArray
{
public:
    constexpr std::size_t size() const { return N; }
    T& operator[](std::size_t i) { return m_data[i]; }
    const T& operator[](std::size_t i) const { return m_data[i]; }

private:
    T m_data[N]{};
};

int main()
{
    StaticArray<int, 5> a{};
    a[0] = 42;
    std::cout << a.size() << ' ' << a[0] << '\n';
    return 0;
}

N is part of the type. StaticArray<int, 5> and StaticArray<int, 6> are different classes, and the size costs nothing at run time because it is not stored anywhere.

Allowed as a non-type parameter Since
Integers, char, bool, enums Always
Pointers and references to objects with static storage Always
auto (the type is deduced from the argument) C++17
Floating-point types, and simple class types C++20

The argument must be a constant expression, since templates are resolved by the compiler.

Full specialization

A specialization replaces the general template for specific arguments. A full (or explicit) specialization fixes all of them.

C++
template <typename T>
class Storage
{
public:
    explicit Storage(T value) : m_value{ value } {}
    void print() const { std::cout << m_value << '\n'; }

private:
    T m_value{};
};

template <>
class Storage<double>
{
public:
    explicit Storage(double value) : m_value{ value } {}
    void print() const { std::cout << std::fixed << std::setprecision(2) << m_value << '\n'; }

private:
    double m_value{};
};
flowchart TD
    U["Storage&lt;X&gt;"] --> Q{"Is X double?"}
    Q -- yes --> S["the specialization<br/>Storage&lt;double&gt;"]
    Q -- no --> G["the primary template"]

The original is called the primary template. A specialization is an entirely separate class: it shares nothing with the primary template except the name, and may have different members altogether.

[!warning] std::vector<bool> is a specialization The library specializes std::vector<bool> to pack eight elements into each byte. Its elements are therefore not real bool objects: operator[] returns a small proxy object, and you cannot take a bool& or bool* to an element. It is widely regarded as a mistake, and a good illustration of how a specialization can break the expectations set by the primary template.

Specializing function templates

Function templates can be fully specialized too:

C++
template <typename T>
void printValue(const T& value) { std::cout << value << '\n'; }

template <>
void printValue<bool>(const bool& value) { std::cout << (value ? "yes" : "no") << '\n'; }
For functions, prefer overloading

An ordinary overload, void printValue(bool value), does the same job and takes part in overload resolution in the normal way. Function template specializations do not, which leads to surprising choices. Reserve specialization for class templates.

Partial specialization

A partial specialization covers a family of arguments. It is itself still a template.

C++
#include <array>
#include <iostream>
#include <string_view>

template <typename T>
struct TypeName
{
    static constexpr std::string_view value{ "something else" };
};

template <typename T>
struct TypeName<T*>
{
    static constexpr std::string_view value{ "a pointer" };
};

template <typename T, std::size_t N>
struct TypeName<std::array<T, N>>
{
    static constexpr std::string_view value{ "a std::array" };
};

int main()
{
    std::cout << TypeName<int>::value << '\n';                     // something else
    std::cout << TypeName<int*>::value << '\n';                    // a pointer
    std::cout << TypeName<std::array<char, 3>>::value << '\n';     // a std::array
    return 0;
}

The pattern in angle brackets after the name, such as T*, is matched against the arguments. TypeName<int*> matches T* with T being int.

Only class templates and variable templates can be partially specialized. Function templates cannot; they overload instead.

Which one is chosen?

Output
 most specialized wins:

 full specialization   >   the best-matching partial specialization   >   the primary template

If two partial specializations match and neither is more specialized than the other, the use is ambiguous and does not compile.

Using partial specialization to ask questions about types at compile time, as TypeName does, is the foundation of 11.02 Type Traits.

Computing with templates

Non-type parameters and specialization together can compute values during compilation: recursion on N, with a specialization as the base case.

C++
template <int N>
struct Factorial
{
    static constexpr int value{ N * Factorial<N - 1>::value };
};

template <>
struct Factorial<0>
{
    static constexpr int value{ 1 };
};

static_assert(Factorial<5>::value == 120);

This is the original form of template metaprogramming. A constexpr function says the same thing far more readably, and is what you should write today. The technique reappears in 11.07 Template Metaprogramming Techniques.
