Random Numbers

lesson 3.044 of 8 in milestone 35 min3 practice tasks

Create one random engine, seed it once, and use a distribution to turn its output into numbers in the range you want. Never create a new engine each time you need a number.

Computers cannot be random

A computer follows instructions exactly, so it cannot roll a real die. What it can do is run a formula whose output looks random: each number is calculated from the one before. These are called pseudo-random numbers.

Because every number depends on the previous one, the starting value decides the whole sequence. That starting value is the seed.

Three parts

flowchart LR
    SEED["Seed<br/>where to start"] --> ENG["Engine<br/>std::mt19937<br/>produces raw numbers"]
    ENG --> DIST["Distribution<br/>shapes them into a range"]
    DIST --> OUT["4"]
Part Job Like
Seed The starting point of the sequence Shuffling a deck
Engine Produces a long stream of raw, random-looking numbers The shuffled deck
Distribution Converts raw numbers into what you asked for, such as 1 to 6 The rules for reading a card

The code

C++
#include <iostream>
#include <random>

int main()
{
    std::mt19937 rng{ std::random_device{}() };    // one engine, seeded once
    std::uniform_int_distribution die{ 1, 6 };     // 1 to 6, both included

    for (int i{ 0 }; i < 10; ++i)
    {
        std::cout << die(rng) << ' ';
    }
    std::cout << '\n';
    return 0;
}
Piece What it is
std::mt19937 A well-tested engine (the "Mersenne Twister")
std::random_device{}() Asks the operating system for an unpredictable seed
std::uniform_int_distribution{ 1, 6 } Whole numbers from 1 to 6, each equally likely
die(rng) Draw one number: the distribution takes what it needs from the engine

Other distributions

Distribution Produces
std::uniform_real_distribution{ 0.0, 1.0 } Decimals from 0 up to, but not including, 1
std::bernoulli_distribution{ 0.5 } true or false, here with a 50% chance
std::normal_distribution{ 170.0, 10.0 } A bell curve centred on 170

The same seed gives the same sequence

Output
 seed 42  gives  17, 3, 88, 41, ...
 seed 42  gives  17, 3, 88, 41, ...     identical
 seed 99  gives  62, 9, 14, 77, ...

This is a feature. A fixed seed makes a "random" program repeatable, which is exactly what you need when testing or chasing a bug.

C++
std::mt19937 testRng{ 42 };    // same numbers on every run
You want Seed with
Different results on every run (a game) std::random_device{}()
Identical results on every run (a test) a fixed number

One engine for the whole program

Do not create an engine inside the function that uses it
C++
int roll()
{
    std::mt19937 rng{ std::random_device{}() };    // a new engine on every call
    return std::uniform_int_distribution{ 1, 6 }(rng);
}

This throws away the engine after one number. It is slow, and you lose the quality the engine is designed to give over a long sequence.

The usual solution is a small header that every file shares:

C++
// random.h
#pragma once
#include <random>

namespace Random
{
    inline std::mt19937 rng{ std::random_device{}() };

    inline int get(int min, int max)
    {
        return std::uniform_int_distribution{ min, max }(rng);
    }
}
C++
int roll{ Random::get(1, 6) };

The engine is created once, when the program starts, and every call to Random::get draws from it. The namespace and inline keywords are explained in the next two lessons.

[!warning] You will see rand() in old code std::rand() % 6 + 1 is the method inherited from C. Its numbers are of poor quality and slightly favour some results. Recognise it; do not write it.
