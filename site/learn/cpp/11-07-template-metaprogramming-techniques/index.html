Template Metaprogramming Techniques

lesson 11.077 of 7 in milestone 116 min2 practice tasks

Template metaprogramming treats types as data and templates as functions that run in the compiler. The core tools are type lists, std::index_sequence, recursive instantiation, fold expressions and if constexpr. They are what std::tuple, std::variant, serialization libraries and expression templates are built from.

Templates as functions on types

Output
 an ordinary function:    values   →  f(...)                        →  a value
 a metafunction:          types    →  Template<...>::type or ::value →  a type or a value
C++
template <typename T>
struct AddPointer
{
    using type = T*;
};

AddPointer<int>::type p{};    // int*

A class template used this way is a metafunction: its template parameters are the inputs and a nested type or value is the output. The type traits of 11.02 Type Traits are metafunctions. The language they form is purely functional: there is no mutation, so iteration is expressed as recursion or as pack expansion.

Type lists

A type list is a template whose only purpose is to carry a pack of types.

C++
#include <cstddef>
#include <type_traits>

template <typename... Ts>
struct TypeList {};

template <typename List>
struct Length;

template <typename... Ts>
struct Length<TypeList<Ts...>> : std::integral_constant<std::size_t, sizeof...(Ts)> {};

template <typename T, typename List>
struct Contains;

template <typename T, typename... Ts>
struct Contains<T, TypeList<Ts...>> : std::bool_constant<(std::is_same_v<T, Ts> || ...)> {};

template <typename List>
struct Front;

template <typename Head, typename... Tail>
struct Front<TypeList<Head, Tail...>>
{
    using type = Head;
};

template <typename T, typename List>
struct PushFront;

template <typename T, typename... Ts>
struct PushFront<T, TypeList<Ts...>>
{
    using type = TypeList<T, Ts...>;
};

struct Position {};
struct Velocity {};
struct Health {};

using Components = TypeList<Position, Velocity, Health>;

static_assert(Length<Components>::value == 3);
static_assert(Contains<Health, Components>::value);
static_assert(std::is_same_v<Front<Components>::type, Position>);

Every operation follows one shape. The primary template is declared and left undefined. A partial specialization on TypeList<Ts...> pattern-matches the list and exposes its contents as a pack. From there a fold expression or a pack expansion does the work.

Operation Technique
Length sizeof...(Ts)
Contains A fold over ||
Front Match TypeList<Head, Tail...>
PushFront Re-expand into a new TypeList

Recursion: the index of a type

When each step depends on the last, recurse with one specialization for the base case and one for the general case.

C++
template <typename T, typename List>
struct IndexOf;

template <typename T, typename... Ts>
struct IndexOf<T, TypeList<T, Ts...>> : std::integral_constant<std::size_t, 0> {};

template <typename T, typename Head, typename... Ts>
struct IndexOf<T, TypeList<Head, Ts...>>
    : std::integral_constant<std::size_t, 1 + IndexOf<T, TypeList<Ts...>>::value> {};

static_assert(IndexOf<Health, Components>::value == 2);
flowchart LR
    A["IndexOf&lt;Health, [Position, Velocity, Health]&gt;"] --> B["1 + IndexOf&lt;Health, [Velocity, Health]&gt;"] --> C["1 + 1 + IndexOf&lt;Health, [Health]&gt;"] --> D["1 + 1 + 0 = 2"]

The first specialization matches when the head is T, and it is more specialized than the second, so it is preferred (9.02 Non-Type Parameters and Template Specialization). If T is absent, the recursion reaches TypeList<>, which matches neither, and compilation fails on the undefined primary template.

std::index_sequence: iterating by position

std::get<I>(tuple) needs I as a compile-time constant, so a run-time loop cannot visit a tuple. An index_sequence supplies the indices as a pack.

C++
#include <cstddef>
#include <iostream>
#include <tuple>
#include <utility>

template <typename Tuple, std::size_t... Is>
void printTupleImpl(const Tuple& t, std::index_sequence<Is...>)
{
    ((std::cout << (Is == 0 ? "" : ", ") << std::get<Is>(t)), ...);
}

template <typename... Ts>
void printTuple(const std::tuple<Ts...>& t)
{
    printTupleImpl(t, std::index_sequence_for<Ts...>{});
    std::cout << '\n';
}

int main()
{
    printTuple(std::tuple{ 1, "two", 3.0 });    // 1, two, 3
    return 0;
}
Tool Produces
std::index_sequence<0, 1, 2> A type carrying a pack of indices
std::make_index_sequence<N> index_sequence<0, 1, ..., N-1>
std::index_sequence_for<Ts...> The same, with N as sizeof...(Ts)

The pattern always has two layers: a public function creates the sequence, and an implementation function deduces Is... from it and expands a pattern over the indices. std::apply(f, tuple), which calls f with the tuple's elements as separate arguments, is implemented exactly this way.

For each type

C++
template <typename... Ts, typename F>
void forEachType(F&& f)
{
    (f.template operator()<Ts>(), ...);
}

forEachType<int, double, char>([]<typename T>() { std::cout << sizeof(T) << ' '; });    // 4 8 1

[]<typename T>() is a lambda with an explicit template parameter (C++20). The .template tells the compiler that the < after operator() begins a template argument list, which it cannot know for a dependent name.

Expression templates

A numeric library that returned a new vector from every + would allocate a temporary for each operator. Expression templates make the operators return a lightweight object whose type records the expression, and evaluate nothing until assignment.

Output
 a + b + c
     has the type   AddExpr<AddExpr<Vec, Vec>, Vec>
     and is evaluated as   result[i] = a[i] + b[i] + c[i]   in a single pass
C++
template <typename L, typename R>
struct AddExpr
{
    const L& left;
    const R& right;

    double operator[](std::size_t i) const { return left[i] + right[i]; }
    std::size_t size() const { return left.size(); }
};

operator+ returns an AddExpr holding references to its operands. Assigning the final expression to a vector runs one loop calling operator[], which the compiler inlines into the arithmetic on the elements. No temporaries are created. Eigen and other linear-algebra libraries are built on this.

[!danger] Expression templates and auto auto sum{ a + b }; captures the expression object, with its references to a and b, not a vector. If either operand is a temporary, the references dangle. Libraries of this kind ask you to name the result type explicitly.

Reflection

Most metaprogramming exists to answer questions the language could not answer directly: what members does this struct have, what are this enum's enumerators? C++26 adds static reflection, which lets code inspect and generate declarations at compile time and should replace much of what this lesson describes. Compiler support is still arriving: 13.10 C++ Standards Timeline and Where to Go Next.

Guidelines

Guideline Reason
Prefer constexpr functions, concepts and if constexpr They are ordinary, readable code: 11.04 Compile-Time Programming — constexpr, consteval, constinit
Keep metaprogramming inside libraries Expose a simple interface; contain the complexity
Watch compile times Each instantiation costs time and memory in the compiler. Folds and pack expansions are far cheaper than recursion.
Give good errors Constrain the entry points with concepts or static_assert so users see a message, not an instantiation trace
