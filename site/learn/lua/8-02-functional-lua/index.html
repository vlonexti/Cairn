Functional Lua

lesson 8.022 of 5 in milestone 85 min2 practice tasks

Writing Lua with functions as building blocks - a small library of map, filter, reduce, find and zip, composing functions and building pipelines, partial application and currying, memoising any function, lazy sequences built from closures, and when a plain loop is clearer.

Functions as building blocks

Lesson 3.03 showed functions as values and closures. A handful of small general functions, combined, replace many hand-written loops. Lua has no such library built in, so you write one (or reuse one), once.

map, filter, reduce

Lua
local F = {}

function F.map(t, fn)
    local out = {}
    for i, v in ipairs(t) do out[i] = fn(v, i) end
    return out
end

function F.filter(t, keep)
    local out = {}
    for _, v in ipairs(t) do
        if keep(v) then out[#out + 1] = v end
    end
    return out
end

function F.reduce(t, fn, acc)
    for _, v in ipairs(t) do acc = fn(acc, v) end
    return acc
end

function F.find(t, test)
    for i, v in ipairs(t) do
        if test(v) then return v, i end
    end
end

local prices = { 4.5, 12, 3.25, 20 }
local withTax = F.map(prices, function(p) return p * 1.2 end)
local cheap = F.filter(prices, function(p) return p < 10 end)
local total = F.reduce(prices, function(a, b) return a + b end, 0)
print(table.concat(withTax, " "), table.concat(cheap, " "), total, F.find(prices, function(p) return p > 10 end))

Each function does one thing, and the function you pass says what should happen to each element.

zip and range

Lua
local function zip(a, b)
    local out = {}
    for i = 1, math.min(#a, #b) do out[i] = { a[i], b[i] } end
    return out
end

local function range(from, to, step)
    local out = {}
    for i = from, to, step or 1 do out[#out + 1] = i end
    return out
end

for _, pair in ipairs(zip({ "ada", "bob" }, { 91, 48 })) do print(pair[1], pair[2]) end
print(table.concat(range(10, 1, -3), ","))

Composing functions

compose(f, g) makes a function that runs g and then f. A pipe runs any number of functions left to right:

Lua
local function pipe(...)
    local fns = { ... }
    return function(x)
        for _, fn in ipairs(fns) do x = fn(x) end
        return x
    end
end

local slug = pipe(
    function(s) return s:lower() end,
    function(s) return s:gsub("[^%w]+", "-") end,
    function(s) return (s:gsub("^%-+", ""):gsub("%-+$", "")) end
)
print(slug("  Hello, World! 2026 "))

Note the brackets around s:gsub(...): gsub returns two values (the string and a count), and passing both on would surprise the next function.

Partial application and currying

Fixing some arguments now and giving the rest later:

Lua
local function partial(fn, ...)
    local fixed = table.pack(...)
    return function(...)
        local args = { table.unpack(fixed, 1, fixed.n) }
        local more = table.pack(...)
        for i = 1, more.n do args[fixed.n + i] = more[i] end
        return fn(table.unpack(args, 1, fixed.n + more.n))
    end
end

local function greet(greeting, name, mark) return greeting .. ", " .. name .. (mark or ".") end
local hello = partial(greet, "Hello")
print(hello("Ada"), hello("Bob", "!"))

local function curry2(fn) return function(a) return function(b) return fn(a, b) end end end
local add = curry2(function(a, b) return a + b end)
print(add(2)(3))

table.pack keeps count of the values (n) even when some are nil, which a plain {...} cannot do.

Memoising any function

A memo table remembers results by argument. With several arguments, join them into one key:

Lua
local function memoize(fn)
    local cache = {}
    return function(...)
        local key = table.concat({ ... }, "\0")
        local hit = cache[key]
        if hit == nil then
            hit = table.pack(fn(...))
            cache[key] = hit
        end
        return table.unpack(hit, 1, hit.n)
    end
end

local calls = 0
local slowAdd = memoize(function(a, b) calls = calls + 1; return a + b end)
print(slowAdd(2, 3), slowAdd(2, 3), slowAdd(3, 2), calls)

The "\0" separator keeps (1, 23) and (12, 3) from both becoming "123". This version only suits arguments that turn into text (numbers and strings).

Lazy sequences

A generator function that returns the next value each time it is called can describe an endless sequence. Helpers that take and return such functions work lazily, doing only the work asked for:

Lua
local function naturals()
    local n = 0
    return function() n = n + 1; return n end
end

local function lazyFilter(gen, keep)
    return function()
        while true do
            local v = gen()
            if v == nil or keep(v) then return v end
        end
    end
end

local function take(gen, count)
    local out = {}
    for i = 1, count do
        local v = gen()
        if v == nil then break end
        out[i] = v
    end
    return out
end

local odd = lazyFilter(naturals(), function(n) return n % 2 == 1 end)
local squaresOfOdd = function() local v = odd(); return v and v * v end
print(table.concat(take(squaresOfOdd, 5), " "))

Coroutines (lesson 6.03) are the other way to write lazy sequences in Lua.

When a loop is clearer

Functional style shines for simple transformations. A loop is clearer when the steps depend on each other, when you need to stop early on complicated conditions, or when performance matters in a hot path (each map builds a new table). Use whichever reads better.
