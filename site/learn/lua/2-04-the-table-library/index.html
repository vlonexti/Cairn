The Table Library

lesson 2.044 of 5 in milestone 25 min1 practice task

table.sort with and without a comparison function, sorting records and sorting by several keys, sorting a dictionary's keys for ordered output, table.concat, table.unpack and table.pack, and table.move.

table.sort

table.sort(t) sorts a list in place (it changes t and returns nothing), smallest first:

Lua
local nums = { 5, 2, 9, 1, 7 }
table.sort(nums)
print(table.concat(nums, " "))

local names = { "lua", "C", "Rust", "ada" }
table.sort(names)
print(table.concat(names, " "))
Output
1 2 5 7 9
C Rust ada lua

Strings sort by byte value, so capitals come first. For any other order, pass a comparison function: it gets two items and returns true when the first must come before the second.

Lua
local nums = { 5, 2, 9, 1, 7 }
table.sort(nums, function(a, b) return a > b end)
print(table.concat(nums, " "))

local names = { "lua", "C", "Rust", "ada" }
table.sort(names, function(a, b) return a:lower() < b:lower() end)
print(table.concat(names, " "))
Output
9 7 5 2 1
ada C lua Rust

function(a, b) ... end written right inside the call is a function without a name; lesson 3.03 explains it. For now, read it as "the rule for the order".

The rule must be strict

Return a < b, never a <= b. With <= two equal items each claim to come first, and table.sort can fail with "invalid order function for sorting". table.sort is also not stable: equal items may swap places.

Sorting records

Lua
local people = {
    { name = "Grace", age = 85 },
    { name = "Ada", age = 36 },
    { name = "Linus", age = 36 },
}
table.sort(people, function(a, b)
    if a.age ~= b.age then return a.age < b.age end   -- first by age
    return a.name < b.name                             -- then by name
end)
for _, p in ipairs(people) do print(p.age, p.name) end
Output
36	Ada
36	Linus
85	Grace

Comparing the first key and only falling back to the second when they are equal sorts by several keys at once, and also makes the order of equal ages predictable.

Ordered output from a dictionary

pairs has no order, so to print a dictionary sorted, collect its keys, sort them, then look each one up:

Lua
local stock = { plums = 12, apples = 4, pears = 7 }
local keys = {}
for k in pairs(stock) do keys[#keys + 1] = k end
table.sort(keys)
for _, k in ipairs(keys) do print(k, stock[k]) end
Output
apples	4
pears	7
plums	12

concat, unpack, pack, move

Lua
local parts = { "2026", "11", "16" }
print(table.concat(parts, "-"))
print(table.concat(parts, "", 2, 3))   -- only items 2 to 3

print(table.unpack({ 10, 20, 30 }))
local a, b = table.unpack({ 10, 20, 30 })
print(a + b)
print(math.max(table.unpack({ 4, 9, 2 })))

local packed = table.pack("x", nil, "z")
print(packed.n, packed[1], packed[3])

local src, dst = { 1, 2, 3 }, { "a", "b", "c", "d" }
table.move(src, 1, 3, 2, dst)          -- copy src[1..3] into dst from position 2
print(table.concat(dst, " "))
Output
2026-11-16
1116
10	20	30
30
9
3	x	z
a 1 2 3
  • table.unpack(t) turns a list into separate values: what you need to pass a list to a function that takes separate arguments, like math.max.
  • table.pack(...) does the opposite and records the count in n, which matters when some values are nil.
  • table.move(a, from, to, at, b) copies a range, into another table or within the same one.

table.concat only joins strings and numbers. A list containing true or a table is an error: convert with tostring first.
