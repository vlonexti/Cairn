Iterators and the Generic for

lesson 6.022 of 5 in milestone 65 min1 practice task

How for ... in really works with an iterator function, writing iterators as closures, stateless iterators like ipairs, next, iterating in sorted order, io.lines for reading input, and the __pairs gone from 5.4.

What for ... in does

for k, v in pairs(t) is a generic for. It works with any iterator: a function that returns the next values each time it is called, and nil when there are no more. The loop calls it again and again until it gets nil.

The simplest iterators are closures:

Lua
local function count_to(n)
    local i = 0
    return function()
        i = i + 1
        if i <= n then return i end
    end
end

for x in count_to(3) do io.write(x, " ") end
print()

local next_number = count_to(2)
print(next_number(), next_number(), next_number())
Output
1 2 3 
1	2

count_to(3) returns the iterator; the loop calls it until it returns nothing. (The third call of next_number returns no value at all, so print gets only two values. A for loop treats "nothing" as nil and stops.)

Useful iterators

Lua
local function range(from, to, step)
    step = step or 1
    local i = from - step
    return function()
        i = i + step
        if (step > 0 and i <= to) or (step < 0 and i >= to) then return i end
    end
end

local function chars(s)
    local i = 0
    return function()
        i = i + 1
        if i <= #s then return i, s:sub(i, i) end
    end
end

local function filtered(list, keep)
    local i = 0
    return function()
        repeat i = i + 1 until list[i] == nil or keep(list[i])
        return list[i]
    end
end

for n in range(10, 0, -5) do io.write(n, " ") end
print()
for pos, ch in chars("Lua") do io.write(pos, ch, " ") end
print()
for n in filtered({ 3, 8, 1, 6, 7 }, function(x) return x > 4 end) do io.write(n, " ") end
print()
Output
10 5 0 
1L 2u 3a 
8 6 7

Sorted pairs

pairs has no order. An iterator can collect and sort the keys first, then hand them out in order:

Lua
local function sorted_pairs(t)
    local keys = {}
    for k in pairs(t) do keys[#keys + 1] = k end
    table.sort(keys, function(a, b) return tostring(a) < tostring(b) end)
    local i = 0
    return function()
        i = i + 1
        local k = keys[i]
        if k ~= nil then return k, t[k] end
    end
end

for name, score in sorted_pairs({ zed = 3, amy = 9, kim = 5 }) do print(name, score) end
Output
amy	9
kim	5
zed	3

Stateless iterators

The full rule is that for vars in f, state, start do calls f(state, control) each round, where control is the first value of the last round. pairs and ipairs return all three, so they need no closure:

Lua
local function iter(t, i)
    i = i + 1
    if t[i] ~= nil then return i, t[i] end
end
local function my_ipairs(t) return iter, t, 0 end

for i, v in my_ipairs({ "a", "b", "c" }) do io.write(i, v, " ") end
print()

print(next({ 10 }))
print(next({}))
for k, v in next, { x = 1 } do print(k, v) end
Output
1a 2b 3c 
1	10
nil
x	1

next(t, k) returns the key after k (and its value), and next(t) the first one. pairs(t) is simply next, t, nil. next(t) == nil is the standard test for an empty table.

Reading input line by line

io.lines() is an iterator over the lines of standard input; io.lines(name) over a file's lines:

Lua
local total, count = 0, 0
for line in io.lines() do
    local n = tonumber(line)
    if n then
        total = total + n
        count = count + 1
    end
end
print(count .. " numbers, total " .. total)

When you press Run, type numbers one per line; the program sees the end of input when you press Ctrl+D. In the practice tasks the input is all given at once, and the loop ends after the last line.

io.lines() can also take formats: for a, b in io.lines(name, "n", "n") reads two numbers per round.

Changing a table while iterating

With pairs, you may change or remove (set to nil) existing keys during the loop, but you must not add new keys: the order is then undefined and keys may be skipped or repeated. Collect the new keys in another table and add them after the loop.
