Performance in Lua

lesson 8.055 of 5 in milestone 85 min2 practice tasks

Making Lua code fast where it matters - measuring with os.clock before changing anything, locals versus globals, caching functions in locals, building strings with table.concat instead of .., reusing tables instead of creating them in loops, array-style tables, avoiding closures in hot loops, and the garbage collector's cost.

Measure first

Most code is fast enough. The slow part of a program is rarely where you guess, so measure before changing anything. os.clock() gives the processor time used so far:

Lua
local function time(label, fn, ...)
    local start = os.clock()
    fn(...)
    print(string.format("%-12s %.3f s", label, os.clock() - start))
end

time("empty loop", function() for i = 1, 1e6 do end end)

Repeat a measurement a few times and only trust differences that are clearly larger than the noise.

Locals are faster than globals

A global is a lookup in the table _ENV (lesson 7.01) every time; a local lives in a register. Inside hot loops, copying a library function into a local helps:

Lua
local N = 1e6

local function globalsVersion()
    local s = 0
    for i = 1, N do s = s + math.sin(i) end
    return s
end

local function localsVersion()
    local sin = math.sin              -- looked up once
    local s = 0
    for i = 1, N do s = s + sin(i) end
    return s
end

local t0 = os.clock(); globalsVersion(); local a = os.clock() - t0
t0 = os.clock(); localsVersion(); local b = os.clock() - t0
print(b <= a * 1.2 and "locals were at least as fast" or "no clear difference here")

The difference is small for one call and noticeable in millions. It is also one more reason to declare everything local.

Building strings

Strings never change, so s = s .. piece in a loop copies the whole string every time: O(n²) for n pieces. Collect pieces in a table and join once:

Lua
local N = 20000

local t0 = os.clock()
local s = ""
for i = 1, N do s = s .. i .. "," end
local slow = os.clock() - t0

t0 = os.clock()
local parts = {}
for i = 1, N do parts[#parts + 1] = i end
local fast = table.concat(parts, ",") .. ","
local quick = os.clock() - t0

print(#s == #fast, quick < slow)

table.concat builds the result in one pass. For a few pieces .. is fine; this matters for loops.

Do not create tables in hot loops

Every {} allocates memory the garbage collector must later free. In a loop that runs every frame, reuse tables:

Lua
local function distanceNew(points)
    local total = 0
    for i = 2, #points do
        local d = { x = points[i].x - points[i - 1].x, y = points[i].y - points[i - 1].y }   -- a new table each time
        total = total + math.sqrt(d.x * d.x + d.y * d.y)
    end
    return total
end

local function distanceReuse(points)
    local total = 0
    local sqrt = math.sqrt
    for i = 2, #points do
        local dx = points[i].x - points[i - 1].x            -- plain locals instead of a table
        local dy = points[i].y - points[i - 1].y
        total = total + sqrt(dx * dx + dy * dy)
    end
    return total
end

local pts = {}
for i = 1, 1000 do pts[i] = { x = i, y = i % 7 } end
print(math.abs(distanceNew(pts) - distanceReuse(pts)) < 1e-9)

The same applies to closures: function() ... end inside a loop creates a new function object each time. Define it once outside.

Arrays are faster than hashes

Lua stores the keys 1..n of a table in a compact array part, and other keys in a hash part. Lists built with consecutive integer keys starting at 1 are fast and small; keys like t[1000000] = true on an otherwise empty table go into the hash part. When you know the size, a numeric for filling 1..n keeps everything in the array part.

ipairs and numeric for loops over arrays are faster than pairs over the same data.

The garbage collector

Lua frees memory automatically, but the work happens while your program runs. Fewer temporary tables and strings means less collection work. You can watch memory use:

Lua
collectgarbage()
local before = collectgarbage("count")          -- kilobytes in use
local junk = {}
for i = 1, 10000 do junk[i] = { i } end
local after = collectgarbage("count")
junk = nil
collectgarbage()
print(after > before, collectgarbage("count") < after)

For games, many people run a small step each frame (collectgarbage("step", n)) to avoid long pauses.

Small wins that add up

  • Prefer x * x to x ^ 2 in hot code (^ always works in floating point).
  • #t + 1 is fine for appending; table.insert(t, v) is a function call doing the same.
  • String patterns are compiled each call; when matching the same pattern in a loop, simpler patterns are faster.
  • LuaJIT (lesson 6.05) runs many Lua programs several times faster with no changes, when it is available.
