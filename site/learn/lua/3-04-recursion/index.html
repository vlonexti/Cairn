Recursion

lesson 3.044 of 5 in milestone 35 min1 practice task

Functions that call themselves, the base case, why a local recursive function needs local function, walking nested tables, speeding up repeated work with memoisation, and Lua's proper tail calls.

A function that calls itself

A recursive function solves a problem by solving a smaller copy of the same problem. It needs a base case that stops, and every other call must move towards it:

Lua
local function factorial(n)
    if n <= 1 then return 1 end          -- base case
    return n * factorial(n - 1)          -- a smaller problem
end

print(factorial(5), factorial(20))
Output
120	2432902008176640000

local function factorial matters here. It declares the local name first, then the function, so the body can see factorial. Written as local factorial = function(n) ... factorial(n - 1) ... end, the name inside refers to a global factorial that does not exist yet, and the call fails.

Without a base case (or with one the calls never reach) the program fails with "stack overflow" after about 200,000 nested calls.

Walking nested data

Recursion fits data that contains smaller versions of itself, like tables in tables:

Lua
local function sum_all(t)
    local total = 0
    for _, v in pairs(t) do
        if type(v) == "table" then
            total = total + sum_all(v)
        else
            total = total + v
        end
    end
    return total
end

print(sum_all({ 1, 2, { 3, 4, { 5 } }, { 6 } }))

local function depth(t)
    if type(t) ~= "table" then return 0 end
    local deepest = 0
    for _, v in pairs(t) do deepest = math.max(deepest, depth(v)) end
    return deepest + 1
end
print(depth({ 1, { 2, { 3 } } }), depth({}), depth(5))
Output
21
3	1	0

A tree of files and folders, a menu with sub-menus, a parsed expression: the shape is always "a value, or a table of more of the same".

Remembering answers

The direct recursive Fibonacci recomputes the same values over and over, so it gets slow very fast:

Lua
local calls = 0
local function slow_fib(n)
    calls = calls + 1
    if n < 2 then return n end
    return slow_fib(n - 1) + slow_fib(n - 2)
end
print(slow_fib(25), calls)
Output
75025	242785

Memoisation stores each answer in a table the first time and looks it up afterwards:

Lua
local memo = {}
local function fib(n)
    if n < 2 then return n end
    if memo[n] then return memo[n] end
    local result = fib(n - 1) + fib(n - 2)
    memo[n] = result
    return result
end
print(fib(25), fib(90))
Output
75025	2880067194370816120

From hundreds of thousands of calls down to about a hundred.

Tail calls

When a function's very last action is return f(args), Lua does not keep the current call around while f runs: it replaces it. Such a tail call uses no extra stack, so a tail-recursive function can run any number of times:

Lua
local function count_down(n)
    if n == 0 then return "done" end
    return count_down(n - 1)     -- a tail call
end
print(count_down(1000000))
Output
done

return n * f(n - 1) is not a tail call (the multiplication still has to happen afterwards), and neither is return (f(x)) or f(x); return. Only return f(args) exactly.
