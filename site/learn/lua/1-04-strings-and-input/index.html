Strings and Input

lesson 1.044 of 5 in milestone 15 min2 practice tasks

Writing strings with quotes, escapes and long brackets, joining with .., the length operator #, strings never changing, io.write versus print, and reading input with io.read and its formats.

Writing strings

Single and double quotes mean the same; pick the one that avoids escaping:

Lua
local a = "It's fine"
local b = 'She said "hi"'
local c = "Tab:\tNewline:\nBackslash: \\ Quote: \""
print(a)
print(b)
print(c)
Output
It's fine
She said "hi"
Tab:	Newline:
Backslash: \ Quote: "

A long string between [[ and ]] spans lines and takes everything literally, with no escapes. If the text itself contains ]], put the same number of = signs in both brackets: [==[ ... ]==].

Lua
local poem = [[
Roses are red,
  the moon is "Lua".]]
print(poem)
Output
Roses are red,
  the moon is "Lua".

(A line break straight after [[ is skipped.)

Joining and measuring

.. joins two strings. Numbers are turned into text automatically; anything else must go through tostring:

Lua
local name = "Ada"
local greeting = "Hello, " .. name .. "!"
print(greeting)
print("Total: " .. 3 * 4)
print("Ready: " .. tostring(true))
print(#greeting, #"")
Output
Hello, Ada!
Total: 12
Ready: true
11	0

# gives a string's length in bytes. For plain English text that is the number of letters; for letters outside ASCII it is more (lesson 4.05).

Joining nil is an error

"Hi " .. nil stops the program: "attempt to concatenate a nil value". It usually means a variable was never set, or input ran out.

Strings never change. Every operation that seems to change one, like string.upper, returns a new string:

Lua
local word = "lua"
local loud = string.upper(word)
print(word, loud, word:upper())
Output
lua	LUA	LUA

word:upper() is a shorter way of writing string.upper(word). Milestone 4 uses it everywhere.

print and io.write

print adds tabs between values and a newline at the end. io.write writes exactly what you give it, nothing more, which is what you want for prompts and for building a line in pieces:

Lua
io.write("Loading")
io.write(".", ".", ".")
io.write(" done\n")
io.write("Answer: ", 42, "\n")
Output
Loading... done
Answer: 42

Reading input

io.read reads from the keyboard (standard input). Its argument says what to read:

Call Reads Gives at the end of input
io.read() or io.read("l") the next line, without its newline nil
io.read("n") a number, skipping spaces and newlines before it nil (also if the text is not a number)
io.read("L") the next line, with its newline nil
io.read("a") everything that is left ""
Lua
io.write("Your name? ")
local name = io.read()
io.write("Your age? ")
local age = io.read("n")
print("Hello, " .. name .. ". Next year you are " .. age + 1 .. ".")

When you press Run, a console opens under the code and the program waits there for you to type each answer and press Enter.

Several formats in one call return several values: local a, b = io.read("n", "n") reads two numbers from the same line or from two lines.

Reading a line, then a number

io.read("n") leaves the rest of its line unread. If you read a number and then want the next full line, read once more with io.read() to finish the number's line first. Reading every line with io.read() and converting with tonumber avoids the problem.
