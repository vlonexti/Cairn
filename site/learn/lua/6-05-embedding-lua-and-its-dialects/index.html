Embedding Lua and Its Dialects

lesson 6.055 of 5 in milestone 65 min1 practice task

How a C program runs Lua with the C API and its stack, giving scripts functions written in C, the garbage collector, Lua's versions and the dialects LuaJIT and Luau, and where to go next with LÖVE, Neovim and Roblox.

Lua inside a C program

Everything in this course ran in the lua command, which is itself a small C program around the Lua library. Any C or C++ program can do the same: link the library, create a Lua state, and hand it scripts. The C course on this site covers enough C to read this.

C
#include <lua.h>
#include <lauxlib.h>
#include <lualib.h>
#include <stdio.h>

int main(void)
{
    lua_State *L = luaL_newstate();      /* a fresh Lua world */
    luaL_openlibs(L);                    /* string, table, math, io, os... */

    if (luaL_dostring(L, "print('hello from Lua', 6 * 7)") != LUA_OK) {
        fprintf(stderr, "error: %s\n", lua_tostring(L, -1));
    }

    lua_close(L);
    return 0;
}
Terminal
gcc host.c -o host -llua -lm
./host

Each lua_State is a completely separate Lua world with its own globals. A game can run one state per mod, so mods cannot see each other.

The stack

C and Lua exchange values through a stack that belongs to the state. C pushes values onto it, calls Lua, and reads the results off it. Index 1 is the bottom; negative indexes count from the top (-1 is the top value).

C
/* call the Lua function area(w, h) from C */
lua_getglobal(L, "area");                 /* stack: area            */
lua_pushnumber(L, 3);                     /* stack: area 3          */
lua_pushnumber(L, 4);                     /* stack: area 3 4        */
if (lua_pcall(L, 2, 1, 0) == LUA_OK) {    /* 2 arguments, 1 result  */
    printf("%g\n", lua_tonumber(L, -1));  /* stack: 12              */
    lua_pop(L, 1);                        /* stack: empty again     */
}

lua_pcall is the C side of pcall: a script that crashes reports an error instead of killing the host program.

Giving scripts your functions

The other direction is what makes Lua a scripting language: the host gives Lua functions written in C. Such a function receives its arguments on the stack, pushes its results, and returns how many it pushed:

C
/* Lua will see this as  game.damage(target_id, amount) -> remaining hp */
static int l_damage(lua_State *L)
{
    lua_Integer id = luaL_checkinteger(L, 1);   /* raises a Lua error if not an integer */
    lua_Integer amount = luaL_checkinteger(L, 2);
    lua_Integer hp = apply_damage(id, amount);  /* the game's own C function */
    lua_pushinteger(L, hp);
    return 1;                                   /* one result */
}

static const luaL_Reg game_lib[] = {
    { "damage", l_damage },
    { NULL, NULL },
};

/* at start-up: */
luaL_newlib(L, game_lib);    /* a table with the functions */
lua_setglobal(L, "game");    /* scripts call game.damage(...) */

A script then reads like part of the game:

Lua
local hp = game.damage(enemy_id, 15)
if hp <= 0 then print("defeated!") end

That is the whole model behind World of Warcraft add-ons, Redis scripts and Neovim plugins: the host decides what the scripts may touch. A host that does not want scripts to delete files simply leaves out io and os.

The garbage collector

Lua frees memory itself. Periodically the garbage collector finds tables, strings, functions and coroutines that nothing can reach any more and frees them. Lua 5.4 can run it incrementally (a little at a time, the default) or generationally (young objects checked more often):

Lua
local before = collectgarbage("count")
local junk = {}
for i = 1, 100000 do junk[i] = { i } end
local during = collectgarbage("count")
junk = nil
collectgarbage()
local after = collectgarbage("count")
print(during > before + 1000, after < during)
Output
true	true

collectgarbage("count") is the memory in use, in kilobytes. Games sometimes run collectgarbage("step") once per frame to keep collection pauses small. A __gc metamethod on a table runs when the collector frees it, the hook a C library uses to free its own resources.

Versions and dialects

Version Notes
Lua 5.1 (2006) Still widespread through LuaJIT; no integers, no goto, setfenv instead of _ENV
Lua 5.2 (2011) _ENV, goto, bit32
Lua 5.3 (2015) Integers, bitwise operators, utf8, //
Lua 5.4 (2020) <const> and <close>, generational GC; this course

LuaJIT is a very fast compiler for Lua 5.1 (with some 5.2 additions) and has an FFI that calls C functions straight from Lua. LÖVE, OpenResty and Neovim use it. Integer subtypes, //, <close> and utf8 are missing; bit.band(a, b) replaces a & b.

Luau, Roblox's language, started from Lua 5.1 and added gradual type annotations (local hp: number = 100), compound assignment (x += 1), continue, string interpolation (`hp is {hp}`) and a sandbox. Everything else in this course (tables, metatables, closures, coroutines) works the same.

Where to go next

  • Games with LÖVE (love2d.org): you write love.load, love.update(dt) and love.draw(), and LÖVE calls them every frame. Milestones 2, 3 and 5 are exactly what you need.
  • Neovim: init.lua configures the editor with the vim table (vim.opt.number = true, vim.keymap.set(...)).
  • Roblox: Luau scripts work with game, workspace and events (part.Touched:Connect(function(hit) ... end)), using the colon method calls from lesson 5.03.
  • Embedding: take the C fragments above, build the Lua 5.4 source (one make), and give a program of your own a scripting language.
  • The book: Programming in Lua by Roberto Ierusalimschy, Lua's lead designer, and the free reference manual at lua.org/manual/5.4.
