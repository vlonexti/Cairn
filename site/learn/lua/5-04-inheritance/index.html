Inheritance

lesson 5.044 of 5 in milestone 55 min1 practice task

Making a subclass whose missing keys fall back to its base class, calling the base constructor and overridden methods, polymorphism with one loop over different kinds of object, checking what an object is, and when composition is simpler.

A chain of __index

A subclass is a class whose own missing keys fall back to another class. Since a class is just a table, give it a metatable whose __index is the base class:

Lua
local Animal = {}
Animal.__index = Animal

function Animal.new(name, sound)
    return setmetatable({ name = name, sound = sound or "..." }, Animal)
end
function Animal:speak() return self.name .. " says " .. self.sound end
function Animal:describe() return self.name .. " is an animal" end

local Dog = setmetatable({}, { __index = Animal })   -- Dog falls back to Animal
Dog.__index = Dog                                    -- dogs fall back to Dog

function Dog.new(name, trick)
    local self = Animal.new(name, "woof")            -- build the Animal part
    self.trick = trick
    return setmetatable(self, Dog)                   -- then make it a Dog
end
function Dog:describe()                              -- override
    return Animal.describe(self) .. " that can " .. self.trick
end
function Dog:fetch() return self.name .. " fetches the ball" end

local cat = Animal.new("Tom", "meow")
local rex = Dog.new("Rex", "roll over")
print(cat:speak())
print(rex:speak())          -- found in Animal
print(rex:describe())       -- Dog's own version
print(rex:fetch())
print(cat.fetch)
Output
Tom says meow
Rex says woof
Rex is an animal that can roll over
Rex fetches the ball
nil

Looking up rex:speak: not in rex, so try Dog (rex's metatable's __index); not in Dog, so try Animal (Dog's metatable's __index); found. Any depth works the same way.

Calling the base class

Lua has no super. Call the base class's function by name and pass self yourself: Animal.describe(self). The same goes for the constructor: Dog.new calls Animal.new to fill in the shared fields, then sets the metatable to Dog.

One loop, many kinds

Polymorphism: code that calls obj:area() works for any object that has an area method, whatever its class:

Lua
local Shape = {}
Shape.__index = Shape
function Shape:describe() return string.format("%s with area %.2f", self.kind, self:area()) end

local Circle = setmetatable({}, { __index = Shape })
Circle.__index = Circle
function Circle.new(r) return setmetatable({ kind = "circle", r = r }, Circle) end
function Circle:area() return math.pi * self.r ^ 2 end

local Rect = setmetatable({}, { __index = Shape })
Rect.__index = Rect
function Rect.new(w, h) return setmetatable({ kind = "rectangle", w = w, h = h }, Rect) end
function Rect:area() return self.w * self.h end

local shapes = { Circle.new(1), Rect.new(2, 3), Circle.new(0.5) }
local total = 0
for _, s in ipairs(shapes) do
    print(s:describe())
    total = total + s:area()
end
print(string.format("total %.2f", total))
Output
circle with area 3.14
rectangle with area 6.00
circle with area 0.79
total 9.93

Shape:describe calls self:area(), which runs whichever area the actual object has.

What is this object?

There is no built-in instanceof. Walk up the chain of metatables:

Lua
local Base = {}
Base.__index = Base
local Child = setmetatable({}, { __index = Base })
Child.__index = Child

local function is_a(obj, class)
    local mt = getmetatable(obj)
    while mt do
        if mt == class then return true end
        local parent = getmetatable(mt)
        mt = parent and parent.__index
    end
    return false
end

local c = setmetatable({}, Child)
print(is_a(c, Child), is_a(c, Base), is_a({}, Base), is_a(setmetatable({}, Base), Child))
Output
true	true	false	false

Often a simpler question is better: "can it do what I need?", if obj.area then.

A helper for classes

Writing the two __index lines for every class gets old. Many projects have a tiny helper like this one:

Lua
local function class(parent)
    local c = {}
    c.__index = c
    if parent then setmetatable(c, { __index = parent }) end
    c.new = function(...)
        local obj = setmetatable({}, c)
        if obj.init then obj:init(...) end
        return obj
    end
    return c
end

local Animal = class()
function Animal:init(name) self.name = name end
function Animal:hello() return "I am " .. self.name end

local Bird = class(Animal)
function Bird:init(name, can_fly)
    Animal.init(self, name)
    self.can_fly = can_fly
end

local b = Bird.new("Pip", true)
print(b:hello(), b.can_fly)
Output
I am Pip	true

Libraries such as middleclass and classic do the same with more features, and Roblox's Luau adds typed classes. They are all built on this __index chain.

Composition

Deep hierarchies get hard to follow. Often an object that has another object reads more simply than one that is another: a Player with a position vector and an inventory table, rather than Player inheriting from Movable inheriting from Entity. Use inheritance for real "is a kind of" relationships, and keep it shallow.
