Files and the os Library

lesson 6.044 of 5 in milestone 65 min1 practice task

Opening files with io.open and its modes, reading with read and lines, writing and appending, closing reliably with close variables, saving and loading data as Lua tables, and time, dates, clocks and the environment from os.

Opening a file

io.open(name, mode) returns a file handle, or nil and a message when it cannot:

Mode Means
"r" read (the default); the file must exist
"w" write: creates the file, or empties an existing one
"a" append: write at the end, creating the file if needed
"r+" read and write an existing file
add "b" binary, as in "rb": matters on Windows only
Lua
local f = assert(io.open("notes.txt", "w"))
f:write("first line\n", "second line\n", 42, "\n")
f:close()

local f2 = assert(io.open("notes.txt", "a"))
f2:write("added later\n")
f2:close()

local missing, err = io.open("does-not-exist.txt")
print(missing, err)
Output
nil	does-not-exist.txt: No such file or directory

Methods on a handle use the colon: f:write, f:read, f:close. write takes strings and numbers, any number of them, and adds nothing between them.

Reading

f:read(format) takes the same formats as io.read (lesson 1.04): "l" a line, "n" a number, "a" everything. f:lines() is an iterator over the lines:

Lua
local f = assert(io.open("data.txt", "w"))
f:write("10 20\n30\nlast line\n")
f:close()

f = assert(io.open("data.txt"))
local a, b = f:read("n", "n")
local c = f:read("n")
f:read("l")                    -- the rest of the "30" line
print(a, b, c, f:read("l"), f:read("l"))
f:close()

for line in io.lines("data.txt") do io.write("[", line, "] ") end
print()

local whole = assert(io.open("data.txt")):read("a")
print(#whole)
Output
10	20	30	last line	nil
[10 20] [30] [last line] 
19

io.lines(name) opens the file, loops over it and closes it at the end: the shortest way to read a text file. (On the last line assert(io.open(...)):read("a") leaves the handle to be closed by the garbage collector; fine in a quick script, sloppy in a long-running program.)

Closing reliably

A file that is never closed may lose what was written to it. In Lua 5.4, a <close> variable closes its file when the block ends, even if an error stops the block:

Lua
local function save(name, lines)
    local f <close> = assert(io.open(name, "w"))
    for _, line in ipairs(lines) do f:write(line, "\n") end
end                                -- f:close() happens here

save("list.txt", { "milk", "eggs" })
for line in io.lines("list.txt") do print(line) end
Output
milk
eggs

Saving and loading data

Lua itself is a good data format. Write a table out as Lua source with %q (lesson 4.04), and read it back with load, which turns a string of code into a function:

Lua
local function serialize(v, indent)
    indent = indent or ""
    if type(v) == "table" then
        local lines, keys = { "{" }, {}
        for k in pairs(v) do keys[#keys + 1] = k end
        table.sort(keys, function(a, b) return tostring(a) < tostring(b) end)
        for _, k in ipairs(keys) do
            lines[#lines + 1] = string.format("%s  [%s] = %s,", indent, serialize(k), serialize(v[k], indent .. "  "))
        end
        lines[#lines + 1] = indent .. "}"
        return table.concat(lines, "\n")
    end
    return string.format("%q", v)
end

local save = { player = "Ada", level = 3, items = { "map", "lamp" } }
local f <close> = assert(io.open("save.lua", "w"))
f:write("return ", serialize(save), "\n")
f:close()

local loaded = assert(loadfile("save.lua"))()
print(loaded.player, loaded.level, loaded.items[2])
print(io.open("save.lua"):read("a"))
Output
Ada	3	lamp
return {
  ["items"] = {
    [1] = "map",
    [2] = "lamp",
  },
  ["level"] = 3,
  ["player"] = "Ada",
}

loadfile(name) compiles a file into a function without running it; calling it runs the file, and return hands back the table. load(text) does the same for a string.

Only load files you trust

A loaded file is a program: it can do anything your program can, including deleting files. Use this for your own save files and settings, never for data from strangers. For data from elsewhere, use a format with no code in it, such as JSON with a JSON library, or load(text, "data", "t", {}) with an empty environment as the fourth argument so the code cannot reach os or io.

The os library

Lua
local now = os.time()
print(type(now), now > 1700000000)
print(os.date("%Y-%m-%d", 0))
print(os.date("!%H:%M", 3600 * 13 + 60 * 5))
local t = os.date("*t", os.time({ year = 2026, month = 11, day = 16, hour = 12 }))
print(t.year, t.month, t.day, t.wday)
local start = os.clock()
local x = 0
for i = 1, 1000000 do x = x + i end
print(os.clock() - start < 5, x)
print(os.getenv("NO_SUCH_VARIABLE"))
Output
number	true
1970-01-01
13:05
2026	11	16	2
true	500000500000
nil
Function Gives
os.time() the current time as seconds since 1970
os.time{year=, month=, day=, hour=} those seconds for a given date
os.date(format, t) a formatted date; "*t" gives a table; a leading ! uses UTC
os.clock() processor time used, in seconds, for timing code
os.difftime(t2, t1) the seconds between two times
os.getenv(name) an environment variable, or nil
os.remove(name), os.rename(a, b) delete or rename a file
os.exit(code) end the program

wday counts from Sunday = 1, so 2 is a Monday. Formats follow C's strftime: %Y year, %m month, %d day, %H:%M:%S time, %A weekday name.
