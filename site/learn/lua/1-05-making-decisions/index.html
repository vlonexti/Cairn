Making Decisions

lesson 1.055 of 5 in milestone 15 min2 practice tasks

if, elseif and else, the comparison operators with ~= for "not equal", what counts as true (everything except false and nil), and, or and not and what they return, and the x or default idiom.

if

Lua
local temperature = 31

if temperature > 30 then
    print("Hot")
elseif temperature > 15 then
    print("Mild")
else
    print("Cold")
end
Output
Hot

if condition then ... end. Any number of elseif branches (one word), an optional else, and one end that closes the whole statement. The conditions are tested in order and only the first true branch runs.

Comparing

Operator Meaning
== equal
~= not equal (not !=)
< > <= >= order
Lua
print(1 == 1.0, "a" == "a", 1 == "1")
print(3 ~= 4, "apple" < "banana", "Z" < "a")
Output
true	true	false
true	true	true

Values of different types are never equal: 1 == "1" is false. Strings compare letter by letter by their byte values, so all capitals come before all lower-case letters. Comparing a number with a string using < is an error.

What counts as true

Lua's rule is short: false and nil are false. Everything else is true, including 0, "" and an empty table.

Lua
if 0 then print("0 is true") end
if "" then print("empty text is true") end
if nil then print("never") else print("nil is false") end
Output
0 is true
empty text is true
nil is false
Coming from Python, C or JavaScript

if count then does not test whether count is zero. It tests whether count exists. Write if count > 0 then or if count ~= 0 then.

and, or, not

Lua
local age, member = 20, false
if age >= 18 and not member then
    print("Adult, not a member")
end
if age < 12 or age > 65 then
    print("Discount")
else
    print("Full price")
end
Output
Adult, not a member
Full price

and and or stop as soon as the answer is known, and they return one of their operands, not just true or false:

  • a and b gives a if a is false or nil, otherwise b.
  • a or b gives a if a is true (anything but false/nil), otherwise b.
Lua
print(nil or "default", "set" or "default")
print(nil and "x", 5 and "x")
print(false or nil, not nil, not 0)
Output
default	set
nil	x
nil	true	false

That gives two idioms you will see in all Lua code:

Lua
local name = nil
local shown = name or "anonymous"           -- a default for a missing value
local score = 72
local result = score >= 50 and "pass" or "fail"   -- like a ? b : c
print(shown, result)
Output
anonymous	pass
The and-or trick fails when the middle value is false

cond and false or "x" gives "x" even when cond is true, because true and false is false, and then or picks "x". Use a full if when the "true" value can be false or nil.

Checking input

tonumber and io.read("n") give nil for bad input. Test for it before using the value:

Lua
local answer = tonumber("12x")
if answer == nil then
    print("That is not a number.")
elseif answer % 2 == 0 then
    print(answer .. " is even")
else
    print(answer .. " is odd")
end
Output
That is not a number.

if not answer then says the same as if answer == nil then here, since a number is never false.
