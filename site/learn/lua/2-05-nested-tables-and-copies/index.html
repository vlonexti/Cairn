Nested Tables and Copies

lesson 2.055 of 5 in milestone 25 min1 practice task

Tables inside tables for grids and data, references and what really gets copied, shallow and deep copies, comparing tables by content, and printing a nested table so you can see it.

Tables inside tables

A table's values can be tables, which gives you any shape of data you need:

Lua
local grid = {
    { 1, 2, 3 },
    { 4, 5, 6 },
}
print(grid[2][3], #grid, #grid[1])

local game = {
    player = { name = "Ada", hp = 30, items = { "sword", "lamp" } },
    level = 3,
}
print(game.player.name, game.player.items[2], #game.player.items)
game.player.hp = game.player.hp - 5
print(game.player.hp)
Output
6	2	3
Ada	lamp	2
25

Building a grid takes a loop for the rows and one for the columns. Every row must be its own table:

Lua
local rows, cols = 3, 4
local board = {}
for r = 1, rows do
    board[r] = {}
    for c = 1, cols do
        board[r][c] = "."
    end
end
board[2][3] = "#"
for r = 1, rows do print(table.concat(board[r])) end
Output
....
..#.
....

What gets copied

Assigning a table, passing it to a function or storing it inside another table never copies it. Every one of those is the same table:

Lua
local row = { 0, 0, 0 }
local bad = { row, row, row }     -- the same row three times
bad[1][1] = 9
print(bad[1][1], bad[2][1], bad[3][1])
Output
9	9	9

Numbers, strings and booleans behave like separate copies (they cannot be changed in place anyway); tables and functions are shared.

Copying

A shallow copy makes a new table with the same keys and values. Nested tables inside are still shared:

Lua
local function shallow_copy(t)
    local copy = {}
    for k, v in pairs(t) do copy[k] = v end
    return copy
end

local a = { 1, 2, inner = { 3 } }
local b = shallow_copy(a)
b[1] = 100
b.inner[1] = 300
print(a[1], a.inner[1])
Output
1	300

A deep copy copies the nested tables too. It calls itself for every table it meets (a function calling itself is recursion, lesson 3.04):

Lua
local function deep_copy(t)
    if type(t) ~= "table" then return t end
    local copy = {}
    for k, v in pairs(t) do copy[k] = deep_copy(v) end
    return copy
end

local a = { 1, inner = { 2, deeper = { 3 } } }
local b = deep_copy(a)
b.inner.deeper[1] = 99
print(a.inner.deeper[1], b.inner.deeper[1])
Output
3	99

This simple version is fine for data. It does not handle a table that contains itself, and it does not copy metatables (milestone 5).

Comparing by content

== asks whether two tables are the same table. To ask whether they hold the same things, compare key by key, in both directions:

Lua
local function same(a, b)
    if type(a) ~= "table" or type(b) ~= "table" then return a == b end
    for k, v in pairs(a) do
        if not same(v, b[k]) then return false end
    end
    for k in pairs(b) do
        if a[k] == nil then return false end
    end
    return true
end

print(same({ 1, { 2, 3 } }, { 1, { 2, 3 } }), same({ 1, 2 }, { 1, 2, 3 }))
Output
true	false

The test kit's check_eq compares tables exactly this way, which is why your practice tests can say check_eq(result, { 1, 2, 3 }).

Seeing a nested table

print(t) shows only an address. While you work, a small function that writes a table out helps a lot:

Lua
local function show(v)
    if type(v) ~= "table" then
        return type(v) == "string" and string.format("%q", v) or tostring(v)
    end
    local parts = {}
    for _, item in ipairs(v) do parts[#parts + 1] = show(item) end
    local keys = {}
    for k in pairs(v) do
        if not (math.type(k) == "integer" and k >= 1 and k <= #v) then keys[#keys + 1] = k end
    end
    table.sort(keys, function(x, y) return tostring(x) < tostring(y) end)
    for _, k in ipairs(keys) do parts[#parts + 1] = tostring(k) .. " = " .. show(v[k]) end
    return "{" .. table.concat(parts, ", ") .. "}"
end

print(show({ 1, "two", { 3 }, name = "Ada", ok = true }))
Output
{1, "two", {3}, name = "Ada", ok = true}

Keep a function like this in your toolbox; you will reuse it in later practice.
