Data Structures in Lua

lesson 8.011 of 5 in milestone 85 min2 practice tasks

Building the classic data structures from Lua's one table type - stacks, queues that do not shift (two indexes), double-ended queues, sets with union and intersection, linked lists, and a binary heap for priority queues, with the costs of each operation.

Everything is a table

Lua has one data structure, the table, and every other structure is built from it. The trick is choosing how to use the table so the common operations are fast.

A stack

A list with t[#t + 1] = v to push and t[#t] = nil to pop. Both are O(1):

Lua
local Stack = {}
Stack.__index = Stack

function Stack.new() return setmetatable({ n = 0 }, Stack) end
function Stack:push(v) self.n = self.n + 1; self[self.n] = v end
function Stack:pop()
    if self.n == 0 then return nil end
    local v = self[self.n]
    self[self.n] = nil
    self.n = self.n - 1
    return v
end
function Stack:peek() return self[self.n] end

local s = Stack.new()
s:push("a"); s:push("b"); s:push("c")
print(s:pop(), s:pop(), s:peek(), s.n)    --> c  b  a  1

Keeping the count in a field (n) is faster than #self and is not confused by nil values.

A queue that does not shift

table.remove(t, 1) moves every other element down: O(n). A queue that keeps a first and a last index never moves anything:

Lua
local Queue = {}
Queue.__index = Queue

function Queue.new() return setmetatable({ first = 1, last = 0 }, Queue) end
function Queue:push(v) self.last = self.last + 1; self[self.last] = v end
function Queue:pop()
    if self.first > self.last then return nil end
    local v = self[self.first]
    self[self.first] = nil            -- let the value be collected
    self.first = self.first + 1
    return v
end
function Queue:size() return self.last - self.first + 1 end

local q = Queue.new()
for _, name in ipairs({ "ada", "bob", "cy" }) do q:push(name) end
print(q:pop(), q:size())   --> ada  2
q:push("dee")
while q:size() > 0 do io.write(q:pop(), " ") end
print()

The indexes only grow, but that is fine: Lua integers go far past any queue you will ever fill. Adding pushfront (decrementing first) and poplast makes it a double-ended queue.

Sets

A set is a table whose keys are the members and whose values are true:

Lua
local function Set(list)
    local s = {}
    for _, v in ipairs(list) do s[v] = true end
    return s
end

local function union(a, b)
    local r = {}
    for k in pairs(a) do r[k] = true end
    for k in pairs(b) do r[k] = true end
    return r
end

local function intersection(a, b)
    local r = {}
    for k in pairs(a) do if b[k] then r[k] = true end end
    return r
end

local function sorted(s)
    local out = {}
    for k in pairs(s) do out[#out + 1] = k end
    table.sort(out)
    return table.concat(out, ",")
end

local red = Set({ "apple", "cherry", "strawberry" })
local small = Set({ "cherry", "blueberry", "grape" })
print(sorted(union(red, small)))
print(sorted(intersection(red, small)))
print(red.apple, red.grape)          --> true  nil

Membership (set[x]) is O(1), which is why "is it in the list?" questions should use a set instead of a loop.

A linked list

Each node is a table with a value and a next field. Inserting at the front is O(1), and removing from the middle needs no shifting:

Lua
local list = nil
for _, v in ipairs({ 3, 2, 1 }) do
    list = { value = v, next = list }       -- push at the front
end

local function each(node)
    return function()
        if node then
            local v = node.value
            node = node.next
            return v
        end
    end
end

for v in each(list) do io.write(v, " ") end
print()

In Lua, plain lists (arrays) are usually faster than linked lists because of how tables are stored; linked lists are worth it mainly when you insert and remove in the middle a lot.

A binary heap: a priority queue

A heap keeps the smallest item at index 1 and needs only O(log n) work to add an item or take the smallest. Children of position i are at 2i and 2i + 1:

Lua
local Heap = {}
Heap.__index = Heap

function Heap.new(less) return setmetatable({ n = 0, less = less or function(a, b) return a < b end }, Heap) end

function Heap:push(v)
    self.n = self.n + 1
    local i = self.n
    self[i] = v
    while i > 1 do
        local parent = i // 2
        if not self.less(self[i], self[parent]) then break end
        self[i], self[parent] = self[parent], self[i]
        i = parent
    end
end

function Heap:pop()
    if self.n == 0 then return nil end
    local top = self[1]
    self[1] = self[self.n]
    self[self.n] = nil
    self.n = self.n - 1
    local i = 1
    while true do
        local l, r, best = 2 * i, 2 * i + 1, i
        if l <= self.n and self.less(self[l], self[best]) then best = l end
        if r <= self.n and self.less(self[r], self[best]) then best = r end
        if best == i then break end
        self[i], self[best] = self[best], self[i]
        i = best
    end
    return top
end

local tasks = Heap.new(function(a, b) return a.priority < b.priority end)
tasks:push({ priority = 3, name = "write report" })
tasks:push({ priority = 1, name = "fix crash" })
tasks:push({ priority = 2, name = "reply to email" })
while tasks.n > 0 do print(tasks:pop().name) end

The comparison function makes the same heap work for any items: a game's event queue, path finding, or scheduling.

Costs at a glance

structure add remove find
stack (list) O(1) at the end O(1) at the end O(n)
queue (two indexes) O(1) at the back O(1) at the front O(n)
set (keys) O(1) O(1) O(1)
heap O(log n) O(log n) for the smallest smallest in O(1)
