Scope, Globals and Blocks

lesson 3.055 of 5 in milestone 35 min1 practice task

Where a local is visible, blocks and do ... end, shadowing, how globals live in the table _G, why a typo creates a global, the const and close attributes of Lua 5.4, and keeping a file's names private.

A local lives in its block

A local variable is visible from the line after its declaration to the end of the block it is in. Every then ... end, loop body, function body and do ... end is a block:

Lua
local x = "outer"
do
    local x = "inner"      -- a new x, hiding the outer one
    local y = 1
    print(x, y)
end
print(x, y)
Output
inner	1
outer	nil

do ... end makes a block on its own, which is useful to keep helper variables from leaking. The inner x shadows the outer one: same name, different variable. Shadowing is legal but confusing; prefer new names.

Globals are a table

A name that is not a local is a global, and globals are simply fields of a table called _G:

Lua
score = 10                     -- no local: a global
print(_G.score, _G["score"])
_G.level = 3
print(level)
print(type(_G.print), _G.math.pi > 3)
Output
10	10
3
function	true

print, math, string, table and the rest of the standard library are globals too: entries in _G. That has a consequence:

Lua
local function total(list)
    sum = 0                    -- forgot local
    for _, v in ipairs(list) do sum = sum + v end
    return sum
end
print(total({ 1, 2, 3 }), sum)
Output
6	6

sum leaked out of the function into the whole program. A second function using its own sum would silently trample this one. Misspell a variable (totl = totl + 1) and you get a global, plus an "arithmetic on a nil value" error much later.

Finding accidental globals

Run luac -l -p file.lua (shipped with Lua) and look for SETTABUP lines: each one writes a global. Editors with a Lua language server underline undefined globals as you type. Lesson 5.02 shows how to make reading a missing global an error.

Locals are also faster than globals: a local lives in a register, a global is a table lookup every time. That is why Lua code often starts with local insert = table.insert.

const and close

Lua 5.4 adds two attributes for locals:

Lua
local LIMIT <const> = 100
print(LIMIT * 2)
-- LIMIT = 5   would not compile: attempt to assign to const variable 'LIMIT'
Output
200

<const> makes assigning to the variable a compile-time error. <close> is for resources: when the block ends, Lua calls the value's __close metamethod, so a file or lock is released even if an error happens. Lesson 6.04 uses it with files.

Private names in a file

A file is a block too. A local at the top of a file is visible to the rest of that file and to nothing else. A module (lesson 5.05) keeps its helpers local and hands out only what it returns:

Lua
-- shapes.lua
local function square(x) return x * x end   -- private helper

local M = {}
function M.circle_area(r) return math.pi * square(r) end
return M

Upvalues and blocks together

A block can create private state for a function, with no global and no outer variable involved:

Lua
local next_id
do
    local last = 0
    next_id = function()
        last = last + 1
        return "id" .. last
    end
end
print(next_id(), next_id(), last)
Output
id1	id2	nil

last is invisible outside the do block, but the closure keeps it alive.
