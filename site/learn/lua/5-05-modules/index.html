Modules

lesson 5.055 of 5 in milestone 55 min1 practice task

Splitting a program into files with require, the module pattern of a local table that the file returns, how require finds files with package.path and loads each one only once, module-private helpers, and dotted names for folders.

A module is a file that returns a table

Any Lua file can be a module: it builds a table of functions (and values), and returns it. Another file loads it with require:

Lua
-- geometry.lua
local M = {}

local function square(x) return x * x end      -- private: not in M

M.PI = math.pi

function M.circle_area(r)
    return M.PI * square(r)
end

function M.distance(x1, y1, x2, y2)
    return math.sqrt(square(x2 - x1) + square(y2 - y1))
end

return M
Lua
-- main.lua
local geometry = require("geometry")

print(string.format("%.2f", geometry.circle_area(2)))
print(geometry.distance(0, 0, 3, 4))
print(geometry.square)
Text
12.57
5.0
nil

Open the Playground and pick the Two files template under Lua to try this with real files.

The shape is always the same:

  1. local M = {} (the name inside the file does not matter).
  2. Private helpers are local and never put in M.
  3. Public functions go into M.
  4. return M on the last line.

The caller picks its own name for the module: local geo = require("geometry").

How require finds and loads a file

require("geometry") looks through the templates in package.path, replacing ? with the module name:

Lua
print(package.path:gsub(";", "\n"))
Output (yours will differ)
/usr/local/share/lua/5.4/?.lua
/usr/local/share/lua/5.4/?/init.lua
/usr/local/lib/lua/5.4/?.lua
/usr/local/lib/lua/5.4/?/init.lua
./?.lua
./?/init.lua	5

./?.lua is the one that finds geometry.lua in the current folder. A dot in the module name becomes a folder: require("game.enemies") loads game/enemies.lua, and require("game") can load game/init.lua.

require runs a file once. It stores what the file returned in package.loaded, and every later require of the same name returns that same table:

Lua
local a = require("geometry")
local b = require("geometry")
print(a == b, package.loaded.geometry == a)   -- true  true

So a module is a natural place for state shared across a program (a settings table, a cache), and loading it from many files costs nothing.

Do not use globals

Old Lua code (5.0 and earlier) had modules set globals, and some libraries still do. Do not: with local M and return M, a module touches no global names, two modules can never clash, and every file says at its top which modules it uses.

Lua
-- avoid
function circle_area(r) ... end     -- a global, visible to everything

-- prefer
local M = {}
function M.circle_area(r) ... end
return M

A class as a module

A module can return a class just as well:

Lua
-- stack.lua
local Stack = {}
Stack.__index = Stack

function Stack.new() return setmetatable({ items = {} }, Stack) end
function Stack:push(v) self.items[#self.items + 1] = v end
function Stack:pop() return table.remove(self.items) end
function Stack:size() return #self.items end

return Stack
Lua
-- main.lua
local Stack = require("stack")
local s = Stack.new()
s:push("a"); s:push("b")
print(s:pop(), s:size())    -- b  1

Modules in other places

Where Lua is embedded, require often works differently: a game engine may look for modules inside its own data files, and Roblox uses require(script.Parent.Module) with objects instead of names. The pattern of a file that returns a table stays the same everywhere.

In the practice tasks the file you write is a module: it can return a table of functions, and the tests can use them directly or with require("solution").
