UTF-8 and Bytes

lesson 4.055 of 5 in milestone 45 min1 practice task

Lua strings as bytes, why # counts bytes not letters, UTF-8 in brief, the utf8 library with len, char, codepoint and codes, taking characters safely, and the \u escape.

Strings are bytes

A Lua string is a sequence of bytes, any bytes at all. Lua does not know about letters, accents or alphabets. For English text one byte is one letter, so you never notice. For anything else you do:

Lua
local word = "café"
print(#word, word:upper(), word:sub(1, 4))
Output
5	CAFé	caf�

é takes two bytes, so the length is 5; upper changes only the ASCII letters; and sub(1, 4) cut the é in half, leaving a broken byte that shows as �.

UTF-8 in one paragraph

Almost all text today is UTF-8. Every character (every Unicode code point) is stored as 1 to 4 bytes: plain ASCII as one byte with the same value as always, é as two, € and most Asian scripts as three, emoji as four. A program that treats the text as bytes still works for copying, joining, searching for ASCII, and comparing. It goes wrong when it counts, cuts or reverses.

The utf8 library

Lua 5.3 and later include utf8 for exactly those cases:

Lua
local word = "café"
print(utf8.len(word))
print(utf8.char(72, 233, 8364, 128512))
print(utf8.codepoint("é"), utf8.codepoint("A€", 1, -1))

for pos, code in utf8.codes("añ€") do
    print(pos, code, utf8.char(code))
end
Output
4
Hé€😀
233	65	8364
1	97	a
2	241	ñ
4	8364	€
Function Does
utf8.len(s) number of characters, or nil plus a position if s is not valid UTF-8
utf8.char(...) the characters with these code points
utf8.codepoint(s, i, j) the code points of the characters starting between byte i and j
utf8.codes(s) loop over the characters: byte position and code point
utf8.offset(s, n) the byte position where character n starts
utf8.charpattern a pattern matching one UTF-8 character

Working character by character

utf8.charpattern with gmatch gives the characters as strings, which makes counting, reversing and cutting safe:

Lua
local function chars(s)
    local out = {}
    for ch in s:gmatch(utf8.charpattern) do out[#out + 1] = ch end
    return out
end

local list = chars("¡Olé!")
print(#list, table.concat(list, " "))

local reversed = {}
for i = #list, 1, -1 do reversed[#reversed + 1] = list[i] end
print(table.concat(reversed))

local function first_chars(s, n)
    local stop = utf8.offset(s, n + 1)
    return stop and s:sub(1, stop - 1) or s
end
print(first_chars("café crème", 4), first_chars("hi", 10))
Output
5	¡ O l é !
!élO¡
café	hi

utf8.offset(s, n + 1) is the byte where character n + 1 starts, so everything before it is the first n characters.

Escapes

\u{XXXX} puts a code point into a string literal as UTF-8; \xXX puts in one byte; \ddd one byte in decimal:

Lua
print("\u{48}\u{E9}\u{20AC}", "\x41\x42", "\65\66")
print(#"\u{20AC}")
Output
Hé€	AB	AB

Bytes are useful too

Because a string can hold any bytes, Lua strings also carry binary data: file contents, network packets, images. string.pack and string.unpack write and read numbers as raw bytes in a given layout:

Lua
local packed = string.pack("<i4 i2", 1000, -2)
print(#packed, packed:byte(1, -1))
print(string.unpack("<i4 i2", packed))
Output
6	232	3	0	0	254	255
1000	-2	7

< means little-endian, i4 a 4-byte integer, i2 a 2-byte one. unpack returns the values and then the position after them. (The Computer Fundamentals and C courses explain endianness and two's complement, which is why -2 is 254 255.)
