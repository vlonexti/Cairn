Tables as Dictionaries

lesson 2.033 of 5 in milestone 25 min1 practice task

Tables with any keys, the dot shorthand for string keys, records, adding and removing with nil, pairs and its order, counting and grouping, and using a table as a set.

Any value can be a key

A table's keys do not have to be 1, 2, 3. Any value except nil can be a key, most often a string:

Lua
local ages = { ["Ada"] = 36, ["Grace"] = 85 }
ages["Linus"] = 21          -- add
ages["Ada"] = 37            -- replace
ages["Grace"] = nil         -- remove
print(ages["Ada"], ages["Grace"], ages["Nobody"])
Output
37	nil	nil

Setting a key to nil removes it: a table never stores nil values. Reading a key that is not there gives nil, so if ages[name] then tests whether a key exists.

The dot shorthand

When a key is a string that is a valid name, t.name means exactly t["name"], and in a constructor name = value means ["name"] = value:

Lua
local book = { title = "Programming in Lua", year = 2016, pages = 388 }
print(book.title, book["year"])
book.edition = 4
local field = "pages"
print(book[field], book.field)
Output
Programming in Lua	2016
388	nil

The last line shows the classic mistake: book.field is the key "field", not the value of the variable field. Use brackets when the key is in a variable.

A table used like this is a record: one thing with named parts. Lists of records are the bread and butter of Lua programs:

Lua
local people = {
    { name = "Ada", born = 1815 },
    { name = "Alan", born = 1912 },
}
for _, p in ipairs(people) do
    print(p.name .. " was born in " .. p.born)
end
Output
Ada was born in 1815
Alan was born in 1912

A constructor can mix both kinds: { "a", "b", sep = ", " } has [1], [2] and sep.

pairs

pairs(t) visits every key and value in a table:

Lua
local stock = { apples = 4, pears = 0, plums = 12 }
local total = 0
for fruit, count in pairs(stock) do
    total = total + count
end
print(total)
Output
16
pairs has no order

The order of pairs is not the order you wrote the keys in, and may differ from run to run. When order matters, collect the keys in a list and sort it (next lesson), or keep a list beside the table.

ipairs is for the list part (1, 2, 3... in order); pairs is for everything. #t counts only the list part: #stock above is 0.

Counting and grouping

Two patterns that come up all the time:

Lua
local words = { "the", "cat", "and", "the", "hat" }

local counts = {}
for _, w in ipairs(words) do
    counts[w] = (counts[w] or 0) + 1
end
print(counts.the, counts.cat, counts.dog)

local by_letter = {}
for _, w in ipairs(words) do
    local first = w:sub(1, 1)
    by_letter[first] = by_letter[first] or {}
    table.insert(by_letter[first], w)
end
print(table.concat(by_letter.t, " "), #by_letter.c)
Output
2	1	nil
the the	1

(counts[w] or 0) + 1 uses the or default from lesson 1.05: a missing count starts at 0.

Sets

A table whose values are all true is a set: it answers "is this in it?" instantly, however big it is.

Lua
local vowels = { a = true, e = true, i = true, o = true, u = true }
local text, n = "programming in lua", 0
for i = 1, #text do
    if vowels[text:sub(i, i)] then n = n + 1 end
end
print(n .. " vowels")

local seen = {}
for _, w in ipairs({ "b", "a", "b", "c", "a" }) do seen[w] = true end
local unique = 0
for _ in pairs(seen) do unique = unique + 1 end
print(unique .. " different")
Output
6 vowels
3 different

To count the entries of a non-list table you have to loop with pairs; # does not count them.
