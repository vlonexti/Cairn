Serialisation

lesson 8.033 of 5 in milestone 85 min2 practice tasks

Saving Lua tables as text and reading them back - writing values as Lua source with %q, sorting keys so the output is stable, nesting and indentation, refusing cycles and functions, loading saved data safely in an empty environment, and a small JSON encoder and the parts of JSON that do not map to Lua.

Saving a table

A game's save file, a tool's settings, a cache: programs need to turn tables into text and back. Lua's own syntax is a natural format, because load can read it back:

Lua
local function serialize(v, indent)
    indent = indent or ""
    local t = type(v)
    if t == "number" or t == "boolean" or t == "nil" then
        return tostring(v)
    elseif t == "string" then
        return string.format("%q", v)
    elseif t == "table" then
        local keys = {}
        for k in pairs(v) do keys[#keys + 1] = k end
        table.sort(keys, function(a, b) return tostring(a) < tostring(b) end)
        local inner = indent .. "  "
        local parts = {}
        for _, k in ipairs(keys) do
            local key = type(k) == "string" and k:match("^[%a_][%w_]*$") and k or "[" .. serialize(k) .. "]"
            parts[#parts + 1] = inner .. key .. " = " .. serialize(v[k], inner)
        end
        if #parts == 0 then return "{}" end
        return "{\n" .. table.concat(parts, ",\n") .. "\n" .. indent .. "}"
    else
        error("cannot save a " .. t)
    end
end

print(serialize({ name = "Ada", level = 3, items = { "map", "sword" }, ["two words"] = true }))
  • %q quotes a string so that Lua reads back exactly the same string, escapes included.
  • Keys are sorted, so saving the same data twice gives the same text, which makes files easy to compare and keep in version control.
  • Keys that are valid names are written plainly; anything else as [key].

Functions, userdata and threads cannot be saved, so the function refuses them with an error.

Cycles

A table that contains itself (directly or through others) would make this recurse forever. Track the tables currently being written:

Lua
local function serialize(v, seen)
    seen = seen or {}
    if type(v) ~= "table" then
        return type(v) == "string" and string.format("%q", v) or tostring(v)
    end
    if seen[v] then error("cannot save a table that contains itself") end
    seen[v] = true
    local parts = {}
    for i, item in ipairs(v) do parts[i] = serialize(item, seen) end
    seen[v] = nil
    return "{" .. table.concat(parts, ", ") .. "}"
end

print(serialize({ 1, { 2, 3 }, "x" }))
local loop = { 1 }
loop[2] = loop
print(pcall(serialize, loop))

Removing the table from seen after writing it lets the same table appear twice in different places (which is not a cycle).

Loading it back safely

load turns text into a function. Running untrusted text could do anything, so give it an empty environment (lesson 7.01) and check that the result is a table:

Lua
local function deserialize(text)
    local chunk, err = load("return " .. text, "saved data", "t", {})
    if not chunk then return nil, "not valid: " .. err end
    local ok, value = pcall(chunk)
    if not ok then return nil, "failed: " .. value end
    if type(value) ~= "table" then return nil, "not a table" end
    return value
end

local data = deserialize('{ name = "Ada", items = { "map", "sword" }, level = 3 }')
print(data.name, data.items[2], data.level)
print(deserialize('{ x = os.exit() }'))
print(deserialize('{ unclosed = '))

The "t" mode refuses precompiled binary chunks, and with an empty environment the data cannot reach os or io. It can still contain a loop that never ends; lesson 7.01's instruction limit covers that.

JSON

To talk to other programs and web services, JSON is the usual format. Lua tables map onto it, with two wrinkles:

  • JSON has separate arrays and objects; a Lua table can be either, so the encoder must decide (here: a table whose keys are exactly 1 to n is an array).
  • JSON has null, but a Lua table cannot store nil; libraries use a special marker value for it.
Lua
local function encode(v)
    local t = type(v)
    if t == "nil" then return "null"
    elseif t == "boolean" then return tostring(v)
    elseif t == "number" then
        if v ~= v or v == math.huge or v == -math.huge then error("JSON has no NaN or infinity") end
        return math.type(v) == "integer" and tostring(v) or string.format("%.14g", v)
    elseif t == "string" then
        local escapes = { ['"'] = '\\"', ["\\"] = "\\\\", ["\n"] = "\\n", ["\r"] = "\\r", ["\t"] = "\\t" }
        return '"' .. v:gsub('[%c"\\]', function(c) return escapes[c] or string.format("\\u%04x", c:byte()) end) .. '"'
    elseif t == "table" then
        local n = #v
        local count = 0
        for _ in pairs(v) do count = count + 1 end
        if count == n then
            local parts = {}
            for i = 1, n do parts[i] = encode(v[i]) end
            return "[" .. table.concat(parts, ",") .. "]"
        end
        local keys = {}
        for k in pairs(v) do
            if type(k) ~= "string" then error("JSON object keys must be strings") end
            keys[#keys + 1] = k
        end
        table.sort(keys)
        local parts = {}
        for i, k in ipairs(keys) do parts[i] = encode(k) .. ":" .. encode(v[k]) end
        return "{" .. table.concat(parts, ",") .. "}"
    end
    error("cannot encode a " .. t)
end

print(encode({ name = "Ada \"the first\"", langs = { "Lua", "C" }, age = 36, pi = 3.14159, active = true }))
print(encode({}))

Note {} comes out as []: an empty table is ambiguous, one of the classic JSON surprises in Lua. Real libraries (dkjson, lua-cjson) let you mark tables as arrays or objects.
