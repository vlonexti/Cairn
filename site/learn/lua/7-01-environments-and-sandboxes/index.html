Environments and Sandboxes

lesson 7.011 of 3 in milestone 75 min2 practice tasks

Where global names really live - _G, the _ENV upvalue every chunk has, giving code its own environment, load with a custom environment, building a safe sandbox for untrusted scripts, limiting run time with debug.sethook, and modules without globals.

Globals are a table

Every global variable is a field of a table. You have met _G, which holds them:

Lua
score = 10
print(_G.score, _G["score"])         --> 10 10
_G.level = 3
print(level)                         --> 3
for name in pairs({ print = 1, pairs = 1 }) do print(type(_G[name])) end

_ENV

Where does a name like score look itself up? In Lua 5.2 and later every chunk (a file or a string you load) has a hidden local-like variable called _ENV, and a free name x is short for _ENV.x. Normally _ENV is _G, so the two look the same. But you can give a block of code a different environment:

Lua
local function with_settings()
    local _ENV = { print = print, width = 80, height = 24 }   -- globals here are fields of this table
    area = width * height                                       -- writes _ENV.area, not a real global
    print(area)
    return _ENV
end

local env = with_settings()
print(env.area, area)                --> 1920 nil

Inside the function, area, width and print all mean fields of the new table. The real globals are untouched.

load with an environment

load(text, name, mode, env) compiles a string into a function whose _ENV is env. That is how a program can run a configuration or a script while controlling exactly which names it can see:

Lua
local config_text = [[
    title = "My Game"
    width = 1280
    height = width * 9 // 16
]]

local config = {}
local chunk, err = load(config_text, "config", "t", config)
assert(chunk, err)
chunk()
print(config.title, config.width, config.height)   --> My Game 1280 720
print(title)                                      --> nil: nothing leaked into the real globals

The "t" mode allows only text, never precompiled bytecode (which can be crafted to crash Lua). Always pass "t" for anything you did not produce yourself.

A sandbox

A sandbox runs untrusted code with only the functions you hand it. Start from an empty table and add what is safe:

Lua
local function make_sandbox()
    return {
        print = print, pairs = pairs, ipairs = ipairs, type = type, tostring = tostring, tonumber = tonumber,
        string = { format = string.format, upper = string.upper, lower = string.lower, sub = string.sub, rep = string.rep, len = string.len },
        math = { floor = math.floor, max = math.max, min = math.min, abs = math.abs, sqrt = math.sqrt },
        table = { insert = table.insert, concat = table.concat, sort = table.sort },
    }
end

local function run_untrusted(code)
    local chunk, err = load(code, "user script", "t", make_sandbox())
    if not chunk then return false, err end
    return pcall(chunk)
end

print(run_untrusted("return math.max(3, 9) * 2"))           --> true 18
print(run_untrusted("os.remove('important.txt')"))          --> false ...attempt to index a nil value (global 'os')
print(run_untrusted("return 1 +"))                          --> false ...syntax error

What to leave out: os, io, load, loadfile, dofile, require, debug, rawset/rawget and setmetatable on shared tables, collectgarbage, and any of your own functions that can reach them. Copy library tables rather than handing over the real ones, or a script could replace string.format for everybody.

Limiting run time

A sandbox stops dangerous calls, but while true do end still hangs. debug.sethook can call a function every N instructions; raising an error from it stops a runaway script:

Lua
local function run_limited(code, max_steps)
    local chunk = assert(load(code, "script", "t", {}))
    local co = coroutine.create(chunk)
    debug.sethook(co, function() error("too many steps") end, "", max_steps)
    return coroutine.resume(co)
end

print(run_limited("local x = 0 for i = 1, 100 do x = x + i end return x", 100000))   --> true 5050
print(run_limited("while true do end", 100000))                                     --> false ...too many steps

Running the script in its own coroutine keeps the hook from affecting the rest of the program.

Modules without globals

A module file should create no globals at all: everything goes in a local table that the file returns (lesson 5.05). A missing local in a module silently creates a global, so many projects start every module with a guard:

Lua
local M = {}
local _ENV = setmetatable({}, { __index = _G, __newindex = function(_, name)
    error("assigning to undeclared global '" .. name .. "'", 2)
end })

function M.helper() return 42 end     -- fine: a field of M
-- counter = 1                         -- would raise an error instead of making a global
return M.helper()
