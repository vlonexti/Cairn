What a Web API Is

lesson 1.011 of 5 in milestone 15 min1 practice task

Programs talking to programs - what an API is, how web APIs use HTTP, resources and endpoints in the REST style, the other styles you will meet (GraphQL, RPC, WebSockets), and what calling one from Python looks like with urllib and requests.

Programs as users

An API (application programming interface) is a way for one program to use another. You have used many already: the Python standard library is an API, and so is the Windows API. A web API is one you reach over the network, with HTTP: weather services, payment providers, chat platforms, your own server. The program offering it is the server; yours is the client.

What makes web APIs special is that the two sides share nothing but messages. They may be written in different languages, run on different continents, and be upgraded at different times. Everything you need to know must be in the request you send, the response you get, and the documentation.

Resources and endpoints

Most web APIs follow the REST style: the server exposes resources (users, orders, messages) at URLs, and you act on them with HTTP methods:

Method Meaning Example
GET read GET /books/42 gives book 42
POST create (or run an action) POST /books with a new book in the body
PUT replace PUT /books/42 with the whole new book
PATCH change some fields PATCH /books/42 with {"title": "..."}
DELETE remove DELETE /books/42

A method and a path pattern together are an endpoint: GET /books/{id}. The documentation lists the endpoints, what each accepts and what it returns. The data travels as JSON almost everywhere (lesson 1.03).

Other styles

Style Idea You will notice
REST resources at URLs, HTTP methods many endpoints, simple requests
GraphQL one endpoint; the client sends a query naming exactly the fields it wants always POST /graphql, errors inside a 200 response
RPC (JSON-RPC, gRPC) call named procedures POST /rpc with {"method": "getBook", "params": ...}; gRPC uses binary messages
WebSockets, server-sent events a connection that stays open for live updates messages arrive without a request
Webhooks the server calls you when something happens milestone 4

The ideas in this course (requests, errors, authentication, paging, retries) apply to all of them.

A first call

From Python, the standard library can make requests with urllib.request; most people install the friendlier requests package (pip install requests). The same call both ways:

Python
import json
import urllib.request

with urllib.request.urlopen("https://api.example.com/books/42", timeout=10) as response:
    book = json.load(response)
print(book["title"])
Python
import requests

response = requests.get("https://api.example.com/books/42", timeout=10)
response.raise_for_status()          # an exception for 4xx and 5xx statuses
book = response.json()
print(book["title"])

The practice in this course cannot reach the internet, so it uses small fake servers that behave like real ones, including all the ways real ones fail. That is also how professional code is tested: a client that takes its transport (the thing that actually sends requests) as a parameter can be tested without a network, and pointed at the real service in production.
