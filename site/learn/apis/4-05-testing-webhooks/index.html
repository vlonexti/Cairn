Testing Webhooks

lesson 4.055 of 5 in milestone 45 min1 practice task

Testing the code that receives webhooks without waiting for real events - fixture deliveries built and signed in tests, testing every rejection path, replaying recorded deliveries, the service's own test events and CLI tools, and exposing a local endpoint with a tunnel during development.

The awkward part

Webhook code runs when another system decides to call it, which makes it awkward to test: you cannot easily make a real payment fail at three in the morning. The answer is to build deliveries yourself.

Fixture deliveries

A test helper that builds a signed request from an event, exactly as the service would, lets you test the whole receiver:

Python
def make_delivery(secret, event, timestamp, path="/webhooks"):
    body = json.dumps(event, separators=(",", ":"), sort_keys=True).encode()
    signature = hmac.new(secret, f"{timestamp}.".encode() + body, hashlib.sha256).hexdigest()
    head = (f"POST {path} HTTP/1.1\r\nHost: localhost\r\nContent-Type: application/json\r\n"
            f"Content-Length: {len(body)}\r\nWebhook-Signature: t={timestamp},v1={signature}\r\n\r\n")
    return head.encode() + body

With it, each test is one line of setup and one assertion:

  • a valid delivery is accepted and processed once;
  • the same delivery again is accepted but not processed again;
  • a delivery signed with the wrong secret, with a changed body, or with an old timestamp is rejected;
  • a delivery for an unknown event type is accepted and ignored;
  • events delivered out of order leave the newest state;
  • a handler that fails gets a 500, and a later retry of the same event succeeds.

Practice 4.05 writes this helper; the project's tests use the same idea.

Recorded deliveries

Services show recent deliveries (payload, headers and your response) in their dashboard, and many let you resend one. Save a few real payloads (with personal data removed) as test fixtures: they catch differences between the documentation's examples and what the service really sends, such as a field that is sometimes null.

Test events and tools

  • Most services have a "send test webhook" button or an API to trigger sample events.
  • Some ship a CLI that forwards events from their test mode to your local machine.
  • In test mode, you can create the objects (a test payment with a test card) that trigger real events end to end.

Reaching your laptop

A service cannot deliver to http://127.0.0.1:8080. During development, a tunnel service gives your local port a temporary public HTTPS URL; you register that URL as the webhook endpoint in test mode. Remember to remove the subscription afterwards, and never point live-mode webhooks at a laptop.
