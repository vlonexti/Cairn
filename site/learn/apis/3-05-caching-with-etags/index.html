Caching with ETags

lesson 3.055 of 5 in milestone 35 min1 practice task

Not asking for what you already have - HTTP caching headers as an API client uses them, Cache-Control max-age and no-store, ETags with If-None-Match and the 304 Not Modified answer, Last-Modified, and a small client-side cache that saves requests and rate limit.

Why cache

Much API data changes rarely: a user's profile, a product catalogue, configuration. Fetching it again and again wastes time and rate limit. HTTP has caching built in, and many APIs support it.

Freshness: Cache-Control

The response says how long it may be reused without asking again:

Text
Cache-Control: max-age=300

For the next 300 seconds, use your stored copy without a request. Other directives: no-cache (you may store it but must check with the server before each use), no-store (do not keep it at all: often on personal or secret data), private (only the end client may cache it, not shared proxies).

Validation: ETags

After the copy goes stale, you can ask cheaply whether it changed. The original response carried an ETag, a version identifier for that content:

Text
HTTP/1.1 200 OK
ETag: "v42-a7f3"
Cache-Control: max-age=60

Next time, send it back:

Text
GET /v1/catalogue
If-None-Match: "v42-a7f3"
  • If nothing changed, the server answers 304 Not Modified with no body: reuse your copy (and its new freshness headers, if any). Many APIs do not count 304s against your rate limit, or count them less.
  • If it changed, you get a normal 200 with the new body and a new ETag.

Last-Modified and If-Modified-Since work the same way with dates; ETags are more precise. Send the ETag exactly as received, quotes and W/ prefix included.

A small client cache

Python
entry = cache.get(url)
if entry and clock() < entry.fresh_until:
    return entry.body                                   # no request at all
headers = {"If-None-Match": entry.etag} if entry and entry.etag else {}
status, resp_headers, body = transport.send("GET", url, headers)
if status == 304 and entry:
    entry.fresh_until = clock() + max_age(resp_headers)
    return entry.body
if status == 200 and "no-store" not in cache_control(resp_headers):
    cache[url] = Entry(body, resp_headers.get("ETag"), clock() + max_age(resp_headers))
return body

Practice 3.05 builds this with every rule spelled out. A real program would also bound the cache's size and key it by anything that changes the response (query parameters, the Accept header, the user).

Caching your own results

Beyond HTTP caching, cache derived data in your program: the list of countries you fetched at startup, a lookup from user id to name. Give each cache entry a time to live, and invalidate it when you change the data yourself through the API.
