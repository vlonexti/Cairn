Signing Requests with HMAC

lesson 2.044 of 5 in milestone 25 min1 practice task

Proving a request came from you and was not changed - HMAC with a shared secret, building a canonical string from the method, path, sorted query, timestamp and body hash, why every byte must be agreed, timestamps against replay, and comparing signatures in constant time.

Why sign?

A bearer token proves who you are only as long as nobody else has it, and says nothing about whether the request was changed on the way. Some APIs (cloud storage, payment and exchange APIs, and webhooks in milestone 4) instead have you sign each request with a secret that is never sent:

  • The server can check the request came from someone who knows the secret (authenticity).
  • Any change to the signed parts breaks the signature (integrity).
  • With a timestamp in the signed data, an old request cannot be replayed later.

HMAC

The tool is HMAC (hash-based message authentication code): a hash of the message mixed with a secret key. In Python:

Python
import hashlib, hmac

secret = b"s3cr3t-key"
message = b"GET\n/v1/books\nlimit=5\n1793523600\n"
print(hmac.new(secret, message, hashlib.sha256).hexdigest())
Output
48cc02d9fdfca3bf5e2b37130edce25564f2c28edb8ee0ad8cf87f2bb3171dfa

Without the secret, nobody can compute it; change one byte of the message and the result is completely different.

The canonical string

The hard part is agreeing exactly which bytes are signed. Both sides must build the same message from the same request, so APIs define a canonical string. A typical definition:

Text
METHOD          upper case:           POST
PATH            as sent, escaped:     /v1/books
QUERY           sorted by name, then value, each name and value escaped,
                joined with &:        a=1&tag=sf&tag=x
TIMESTAMP       seconds since 1970:   1793523600
BODY HASH       SHA-256 of the body in hex (of no bytes when there is no body)

each on its own line. Every detail matters: upper or lower case, the escaping rules, the order of repeated query keys, whether the body is hashed before or after compression, the final newline. A one-character difference makes every request fail with "invalid signature", so implement the provider's definition exactly, test it against the examples in their documentation, and log the canonical string (not the secret) when debugging.

Replay protection

The timestamp goes into the canonical string and a header (X-Timestamp). The server rejects requests whose timestamp is more than a few minutes away from its own clock, so a captured request stops working quickly. Some APIs add a random nonce that the server remembers for that window, so a request cannot be replayed even within it.

Comparing signatures

The server (and you, when verifying webhooks) must compare the received signature with the expected one using hmac.compare_digest, never ==. An ordinary comparison stops at the first differing character, and the time it takes can leak how many leading characters were right, letting an attacker guess a valid signature one character at a time. compare_digest takes the same time however much matches.

Python
expected = hmac.new(secret, canonical.encode(), hashlib.sha256).hexdigest()
if not hmac.compare_digest(expected, received):
    reject()
