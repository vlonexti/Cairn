Structures, Pointers and Buffers

lesson 6.033 of 5 in milestone 65 min1 practice task

Passing data rather than single values - ctypes Structure and the C rules for field alignment and padding, packed structures, arrays, passing by reference with byref and pointer, buffers created with create_string_buffer, and the question that decides crashes - who owns and frees each piece of memory.

Structures

A C struct becomes a ctypes.Structure subclass whose _fields_ list the members in the same order with the same types:

Python
import ctypes

class Point(ctypes.Structure):
    _fields_ = [("x", ctypes.c_int), ("y", ctypes.c_double)]

p = Point(3, 4.5)
print(ctypes.sizeof(Point), Point.x.offset, Point.y.offset)
print(p.x, p.y)
Output
16 0 8
3 4.5

The size is 16, not 12: C aligns each field to a multiple of its own size (up to 8 on 64-bit systems), so 4 bytes of padding follow x to put y at offset 8; the whole structure's size is rounded up to a multiple of its largest alignment, so arrays of it stay aligned. ctypes follows the same rules as the C compiler, which is the point: the bytes must match exactly. Practice 6.02 computes these layouts by hand.

Some structures are packed (#pragma pack(1) or __attribute__((packed)) in the header): no padding at all. Mirror that with _pack_ = 1 in the class, or every field after the first gap is read from the wrong place.

Arrays and buffers

Python
import ctypes

numbers = (ctypes.c_int * 4)(1, 2, 3, 4)          # int numbers[4]
print(list(numbers), ctypes.sizeof(numbers))
buf = ctypes.create_string_buffer(b"hi", 8)      # char buf[8], writable
print(buf.raw, buf.value)
Output
[1, 2, 3, 4] 16
b'hi\x00\x00\x00\x00\x00\x00' b'hi'

Use create_string_buffer(size) (or create_unicode_buffer for wchar_t) whenever C writes into a buffer you provide, passing its size as the function's documentation says (the buffer-size patterns of the Reading Documentation course, milestone 3, apply unchanged).

Pointers

  • ctypes.byref(obj) passes the address of obj: the light way to pass a structure or a number for C to fill in (int *out).
  • ctypes.pointer(obj) makes a real pointer object you can store; POINTER(Point) is the type "pointer to Point", for argtypes, restype and structure fields.
  • A returned pointer is read with result.contents (one object) or indexing result[i] (an array).
Python
# C:  int get_position(struct point *out);
lib.get_position.argtypes = [ctypes.POINTER(Point)]
lib.get_position.restype = ctypes.c_int
pos = Point()
if lib.get_position(ctypes.byref(pos)) == 0:
    print(pos.x, pos.y)

Who owns the memory?

Every pointer crossing the boundary raises one question, and the header or documentation must answer it:

Situation Rule
you pass a buffer or structure you created you own it; it must stay alive for as long as C uses it
C returns a pointer to its own data C owns it; do not free it, and copy what you need before it changes
C returns memory it allocated for you you must free it, with the function the library documents (mylib_free(p)), never Python's or another C runtime's free

Python objects are freed when nothing references them. If C keeps a pointer to a buffer after the call returns (registering a buffer for later use), keep a Python reference to that buffer for as long as C might use it, or C writes into freed memory.
