Bearer Tokens and Expiry

lesson 2.022 of 5 in milestone 25 min1 practice task

Access tokens that expire - the Authorization Bearer header, expires_in and computing when to renew with a safety margin, refresh tokens, retrying once after a 401, caching a token across calls, and what a JWT is and why a client should not trust what it reads in one.

Tokens instead of keys

Many APIs do not want your long-lived secret on every request. Instead you exchange credentials for an access token that works for a short time, often an hour, and send that:

Text
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...

"Bearer" means whoever holds (bears) the token may use it, so it is still a secret, just a short-lived one. A token endpoint typically answers:

JSON
{"access_token": "eyJ...", "token_type": "Bearer", "expires_in": 3600, "refresh_token": "def50200..."}

expires_in is in seconds from now. Record the time you received it, and renew a little before it runs out: clocks differ, and a request sent one second before expiry may arrive one second after. A margin of 30 to 60 seconds is usual:

Python
self.token = data["access_token"]
self.expires_at = clock() + data["expires_in"]

def valid(self, clock, margin=30):
    return self.token is not None and clock() < self.expires_at - margin

Caching

Getting a token costs a request (and some token endpoints are rate-limited strictly), so keep it and reuse it until it is due for renewal. One token per credentials, shared by every request the program makes. Practice 2.02 builds this cache with a fake clock, which is how you test time-dependent code without waiting.

When the API says 401

Even a "valid" token can be rejected: revoked, the server's clock disagrees, the key was rotated. The standard reaction to 401 Unauthorized:

  1. Throw away the cached token.
  2. Get a new one.
  3. Repeat the request once.
  4. If it fails again, report the error: the credentials themselves are wrong, and looping would only hammer the server.

A 403 Forbidden is different: you are authenticated but not allowed. A new token will not help.

Refresh tokens

With OAuth (next lesson), the token response may include a refresh token: a long-lived secret used only at the token endpoint to get new access tokens without asking the user to sign in again. Store it like a password. Some providers issue a new refresh token on each use and invalidate the old one ("rotation"): always save the one you got last.

JWTs

Access tokens often look like xxxxx.yyyyy.zzzzz: a JWT (JSON Web Token), three base64url parts: a header, a payload of claims (sub who, exp expiry time, scope), and a signature. You can decode the middle part and read it:

Python
import base64, json

token = "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJ1c2VyNDIiLCJleHAiOjE3OTM1MjM2MDB9.c2ln"
payload = token.split(".")[1]
payload += "=" * (-len(payload) % 4)            # restore the padding base64url drops
print(json.loads(base64.urlsafe_b64decode(payload)))
Output
{'sub': 'user42', 'exp': 1793523600}

Reading it is fine for debugging. But a client must not make decisions from claims it has not verified: verifying the signature needs the issuer's keys, and that is the server's job. Treat the access token as an opaque string, and use expires_in from the token response for timing.
