Building URLs and Clients Safely

lesson 1.055 of 5 in milestone 15 min1 practice task

Building requests that do not break on unusual input - escaping path segments and query values with urllib.parse, why string concatenation goes wrong, lists and booleans in query strings - and structuring a small API client around an injectable transport with one place for errors.

Never paste values into URLs

Building a URL with string formatting works until a value contains a special character:

Python
url = f"https://api.example.com/users/{name}/books?q={query}"
# name = "a/b"       -> /users/a/b/books: a different path
# query = "x&admin=1" -> an extra parameter you did not mean to send
# query = "café 50%" -> invalid characters in a URL

That is a bug at best and a security hole at worst. urllib.parse escapes values correctly:

Python
from urllib.parse import quote, urlencode

name = "a/b c"
query = {"q": "café & more", "limit": 20, "tags": ["sf", "classic"]}
path = "/users/" + quote(name, safe="") + "/books"
print(path)
print(urlencode(query))
print(urlencode(query, doseq=True))
Output
/users/a%2Fb%20c/books
q=caf%C3%A9+%26+more&limit=20&tags=%5B%27sf%27%2C+%27classic%27%5D
q=caf%C3%A9+%26+more&limit=20&tags=sf&tags=classic
  • quote(value, safe="") escapes everything that is not a letter, digit or one of _.-~, including /. (Its default safe="/" keeps slashes, which is right for a whole path and wrong for one segment.)
  • urlencode builds a query string, encoding text as UTF-8. Spaces become + in queries, %20 in paths: both are correct in their place.
  • A list becomes its Python text unless you pass doseq=True, which repeats the key. Some APIs want tags=sf,classic instead: the documentation says which.
  • Booleans become True and False, which many APIs do not accept: convert to "true" and "false" yourself.
  • Leave out parameters whose value is None rather than sending None.

A client with one door

Small API clients stay manageable when every request goes through one method that knows the base URL, the headers, the timeout and how to turn errors into exceptions. Everything else calls it:

Python
class ApiError(Exception):
    def __init__(self, status, code, message, request_id):
        super().__init__(f"{status} {code}: {message} (request {request_id})")
        self.status, self.code, self.request_id = status, code, request_id


class BooksClient:
    def __init__(self, transport, base_url, timeout=10):
        self.transport = transport          # anything with .send(method, url, headers, body, timeout)
        self.base_url = base_url.rstrip("/")
        self.timeout = timeout

    def request(self, method, path, query=None, body=None):
        url = self.base_url + path
        if query:
            url += "?" + urlencode({k: v for k, v in query.items() if v is not None}, doseq=True)
        headers = {"Accept": "application/json"}
        data = None
        if body is not None:
            headers["Content-Type"] = "application/json"
            data = json.dumps(body).encode()
        status, resp_headers, raw = self.transport.send(method, url, headers, data, self.timeout)
        payload = json.loads(raw) if raw else None
        if status >= 400:
            error = (payload or {}).get("error", {})
            raise ApiError(status, error.get("code"), error.get("message"), resp_headers.get("X-Request-Id"))
        return payload

    def get_book(self, book_id):
        return self.request("GET", "/books/" + quote(str(book_id), safe=""))

The transport is the only part that touches the network. In production it wraps urllib.request or a requests.Session (which also reuses connections); in tests it is a fake that records what was sent and returns scripted responses. The practice in this milestone builds exactly this, piece by piece.
