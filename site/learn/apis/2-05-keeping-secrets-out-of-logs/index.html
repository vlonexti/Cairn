Keeping Secrets Out of Logs

lesson 2.055 of 5 in milestone 25 min1 practice task

The many quiet ways secrets leak - URLs, headers and bodies in logs, error messages, tracebacks, object reprs and debugging output - and how to redact them systematically, from masking a key for display to scrubbing nested JSON, plus a test that proves no secret reaches the log.

Logs are where keys leak

Logging requests is essential for debugging an integration (lesson 5.05). It is also the most common way secrets escape: logs are kept for months, copied into tickets, shipped to monitoring services, and read by many people. The leaks are rarely deliberate:

Leak How it happens
URL a token or key in the query string, logged with the request line
headers logging all request headers, including Authorization and Cookie
bodies logging a token response, or a login form with a password
exceptions a library's error message includes the URL or the body
reprs print(settings) shows every field of a config object
debugging a temporary print(headers) that is never removed

Redact at one place

The reliable fix is a redaction step that every log line passes through, rather than remembering at each call:

  • Headers: replace the values of Authorization, Proxy-Authorization, Cookie, Set-Cookie and any X-...-Key or X-...-Token header. For Authorization, keeping the scheme (Bearer REDACTED) still helps debugging.
  • URLs: parse the query string and replace the values of known secret parameters (api_key, token, access_token, client_secret, signature).
  • Bodies: walk the parsed JSON and replace values of keys such as password, secret, token, refresh_token, at any depth.
  • Display: when a human must recognise which key is configured, show only the last few characters: ****a1b2.
Python
from urllib.parse import parse_qsl, urlencode, urlsplit, urlunsplit

SECRET_PARAMS = {"api_key", "token", "access_token", "client_secret", "signature"}

def redact_url(url):
    parts = urlsplit(url)
    query = [(k, "REDACTED" if k.lower() in SECRET_PARAMS else v) for k, v in parse_qsl(parts.query, keep_blank_values=True)]
    return urlunsplit(parts._replace(query=urlencode(query)))

print(redact_url("https://api.example.com/v1/books?limit=5&api_key=sk_live_abc"))
Output
https://api.example.com/v1/books?limit=5&api_key=REDACTED

Objects that hide their secrets

Give configuration and credential classes a __repr__ that masks the secret, so an accidental print, a debugger view or an exception message cannot show it:

Python
class Settings:
    def __repr__(self):
        return f"Settings(base_url={self.base_url!r}, api_key='****{self.api_key[-4:]}')"

Test it

Write a test that runs a request through your client with a known fake secret and asserts that the secret appears nowhere in the captured log. It costs a few lines and catches the regression the day someone adds log(headers) for debugging.
