JSON in Python

lesson 1.033 of 5 in milestone 15 min1 practice task

The JSON format and how Python's json module maps it to dicts, lists, strings, numbers, True, False and None - parsing and producing text, what happens with errors, numbers and Unicode, and checking that a document from an API has the shape your code expects.

The format

JSON (JavaScript Object Notation, RFC 8259) is the language of web APIs. It has six kinds of value:

JSON Example Python after json.loads
object {"id": 7, "tags": []} dict
array [1, 2, 3] list
string "Dune" str
number 42, -1.5, 2e3 int (no fraction or exponent) or float
true / false true True / False
null null None

Strings use double quotes only; object keys are always strings; there are no comments and no trailing commas.

Reading and writing

Python
import json

text = '{"id": 7, "title": "Dune", "price": 9.5, "tags": ["sf"], "sequel": null}'
book = json.loads(text)                  # text -> Python objects
print(book["title"], book["price"] * 2, book["sequel"] is None)

book["year"] = 1965
print(json.dumps(book))                  # Python objects -> text
print(json.dumps({"b": 1, "a": [True, None]}, sort_keys=True, separators=(",", ":")))
Output
Dune 19.0 True
{"id": 7, "title": "Dune", "price": 9.5, "tags": ["sf"], "sequel": null, "year": 1965}
{"a":[true,null],"b":1}
  • json.load(f) and json.dump(obj, f) work with files and responses directly.
  • indent=2 makes readable output; sort_keys=True and compact separators make output canonical, which matters when you sign it (lesson 2.04).
  • ensure_ascii=False keeps non-ASCII characters readable instead of é escapes.

When parsing fails

Invalid text raises json.JSONDecodeError (a ValueError) with the position of the problem:

Python
import json

try:
    json.loads('{"id": 7,}')
except json.JSONDecodeError as e:
    print("bad JSON at line", e.lineno, "column", e.colno, "-", e.msg)
Output
bad JSON at line 1 column 9 - Illegal trailing comma before end of object

An API that is failing badly may return an HTML error page with status 502 instead of JSON. Check the status (and ideally the Content-Type) before parsing, and catch the decode error, so that your message says "the server returned HTML with 502" rather than a confusing parse error.

Numbers and other surprises

  • Python's json keeps integers exact however large; other languages (JavaScript) lose precision above 2⁵³, which is why some APIs send big ids as strings. Read the documentation.
  • Money is often sent as an integer number of the smallest unit (cents) or as a string, to avoid float rounding.
  • Dates are not a JSON type: they arrive as strings, usually ISO 8601 ("2026-11-19T08:30:00Z"), or as numbers of seconds since 1970 (lesson 5.02).
  • json.dumps refuses some Python values (datetime, set, bytes) with TypeError; convert them yourself first.

Checking the shape

Code like book["author"]["name"] crashes with KeyError or TypeError the day the API returns something slightly different: an author that is null, a missing field, a number sent as a string. At the boundary where data enters your program, check it, and turn it into your own types:

Python
def parse_book(data):
    if not isinstance(data, dict):
        raise ValueError("book: expected an object")
    title = data.get("title")
    if not isinstance(title, str) or not title:
        raise ValueError("book.title: expected a non-empty string")
    year = data.get("year")
    if year is not None and (not isinstance(year, int) or isinstance(year, bool)):
        raise ValueError("book.year: expected an integer or null")
    return Book(title=title, year=year)

(isinstance(True, int) is true in Python, hence the extra bool check.) Libraries such as pydantic do this from a declared model; the idea is the same.
