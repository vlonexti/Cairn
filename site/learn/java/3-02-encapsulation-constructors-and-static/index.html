Encapsulation, Constructors and static

lesson 3.022 of 5 in milestone 35 min1 practice task

Access modifiers and why fields should be private, getters and setters with validation, constructor overloading and this(...), immutable classes with final fields, static fields and methods, static factory methods, constants, and when a class should be a utility class.

Encapsulation

Encapsulation means an object guards its own data: fields are private, and the only way to change them is through methods that keep them valid.

Java
public class Main {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount("Ada", 100);
        acc.deposit(50);
        System.out.println(acc.withdraw(500));       // false: refused
        System.out.println(acc.getBalance());
        try {
            acc.deposit(-10);
        } catch (IllegalArgumentException e) {
            System.out.println("refused: " + e.getMessage());
        }
        // acc.balance = -1000;                      // error: balance has private access
    }
}

class BankAccount {
    private final String owner;
    private long balance;          // in cents would be safer for money; whole euros keep the example short

    BankAccount(String owner, long opening) {
        this.owner = owner;
        deposit(opening);
    }

    BankAccount(String owner) {
        this(owner, 0);            // calls the other constructor
    }

    void deposit(long amount) {
        if (amount < 0) throw new IllegalArgumentException("negative deposit");
        balance += amount;
    }

    boolean withdraw(long amount) {
        if (amount < 0 || amount > balance) return false;
        balance -= amount;
        return true;
    }

    long getBalance() { return balance; }
    String getOwner() { return owner; }
}
Modifier Visible to
private Only this class
(none) Classes in the same package
protected The same package and subclasses
public Everyone

Make fields private, offer methods for what callers need, and only add a setter when changing a field is really part of the class's job; then validate in the setter.

Constructors

A class can have several constructors (overloading). One can call another with this(...) as its first statement, so the setup logic lives in one place. If you write no constructor, Java provides an empty one; as soon as you write any constructor, that free one disappears.

Immutable classes

A class whose fields are all final and set only in the constructor is immutable. Immutable objects cannot be changed by accident, are safe to share between parts of a program and between threads, and make good map keys. String, Integer and LocalDate are immutable; records (lesson 3.05) are the short way to write your own.

static

A static field belongs to the class, not to any object: there is exactly one, shared by all instances. A static method has no this and can use only static fields and its parameters.

Java
public class Main {
    public static void main(String[] args) {
        Ticket a = new Ticket();
        Ticket b = new Ticket();
        System.out.println(a.getNumber() + " " + b.getNumber() + " issued: " + Ticket.issued());
        Temperature t = Temperature.fromFahrenheit(212);
        System.out.println(t.celsius() + " " + Temperature.ABSOLUTE_ZERO);
        System.out.println(MathUtil.clamp(15, 0, 10));
    }
}

class Ticket {
    private static int next = 1;           // shared by all tickets
    private final int number;

    Ticket() { number = next++; }
    int getNumber() { return number; }
    static int issued() { return next - 1; }
}

class Temperature {
    static final double ABSOLUTE_ZERO = -273.15;     // a constant: static final, UPPER_CASE
    private final double celsius;

    private Temperature(double celsius) { this.celsius = celsius; }   // private: use the factory methods

    static Temperature fromCelsius(double c) { return new Temperature(c); }
    static Temperature fromFahrenheit(double f) { return new Temperature((f - 32) * 5 / 9); }

    double celsius() { return celsius; }
}

final class MathUtil {
    private MathUtil() { }                             // a utility class: no instances
    static int clamp(int v, int lo, int hi) { return Math.max(lo, Math.min(hi, v)); }
}
  • Static factory methods like Temperature.fromFahrenheit have descriptive names, unlike constructors, and can validate or reuse objects. List.of, Integer.valueOf and LocalDate.of are examples.
  • static final fields are constants.
  • A utility class (Math, Arrays, Collections) has only static methods and a private constructor.
  • Avoid mutable static fields outside of small cases like counters: shared state makes programs hard to test and reason about.
