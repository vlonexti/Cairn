Lambdas and Functional Interfaces

lesson 6.011 of 5 in milestone 65 min1 practice task

Passing behaviour as a value - functional interfaces, lambda syntax, method references, the java.util.function interfaces (Function, Predicate, Consumer, Supplier, BiFunction, UnaryOperator), composing functions, effectively final captured variables, and lambdas with the collections API (forEach, removeIf, replaceAll, sort, computeIfAbsent).

Behaviour as a value

A functional interface is an interface with exactly one abstract method. A lambda is a short way to write an object that implements it:

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Comparator<String> byLength = (a, b) -> Integer.compare(a.length(), b.length());   // a lambda
        Runnable hello = () -> System.out.println("hello");
        hello.run();

        List<String> words = new ArrayList<>(List.of("banana", "fig", "cherry", "kiwi"));
        words.sort(byLength);
        System.out.println(words);

        Calculator add = (x, y) -> x + y;                 // our own functional interface
        Calculator power = (x, y) -> {                    // a block body needs return
            int result = 1;
            for (int i = 0; i < y; i++) result *= x;
            return result;
        };
        System.out.println(add.apply(2, 3) + " " + power.apply(2, 10));
    }
}

@FunctionalInterface
interface Calculator {
    int apply(int x, int y);
}

Lambda syntax: (parameters) -> expression, or (parameters) -> { statements; }. Parameter types are inferred; a single parameter needs no parentheses: s -> s.length(). @FunctionalInterface asks the compiler to check that the interface has exactly one abstract method.

The standard functional interfaces

java.util.function provides interfaces for the common shapes, so you rarely define your own:

Interface Method Shape Example
Function<T, R> R apply(T t) T to R String::length
BiFunction<T, U, R> R apply(T t, U u) two inputs to R (a, b) -> a + b
Predicate<T> boolean test(T t) a yes/no question s -> s.isEmpty()
Consumer<T> void accept(T t) uses a value System.out::println
Supplier<T> T get() makes a value ArrayList::new
UnaryOperator<T> T apply(T t) T to T s -> s.trim()
BinaryOperator<T> T apply(T a, T b) two Ts to T Integer::sum

Primitive versions (IntPredicate, ToIntFunction, IntBinaryOperator...) avoid boxing in performance-sensitive code.

Method references

When a lambda only calls an existing method, a method reference says the same more briefly:

Java
import java.util.*;
import java.util.function.*;

public class Main {
    public static void main(String[] args) {
        Function<String, Integer> length = String::length;          // an instance method of the argument
        Function<String, Integer> parse = Integer::parseInt;        // a static method
        Consumer<Object> print = System.out::println;               // an instance method of a specific object
        Supplier<List<String>> newList = ArrayList::new;            // a constructor
        BinaryOperator<Integer> sum = Integer::sum;

        print.accept(length.apply("hello") + parse.apply("41") + sum.apply(1, 0));
        List<String> list = newList.get();
        list.add("made by a supplier");
        print.accept(list);
    }
}

Composing functions

The functional interfaces have default methods for combining them:

Java
import java.util.function.*;

public class Main {
    public static void main(String[] args) {
        Function<Integer, Integer> doubleIt = x -> x * 2;
        Function<Integer, Integer> addTen = x -> x + 10;
        System.out.println(doubleIt.andThen(addTen).apply(5));    // (5 * 2) + 10 = 20
        System.out.println(doubleIt.compose(addTen).apply(5));    // (5 + 10) * 2 = 30

        Predicate<String> notEmpty = s -> !s.isEmpty();
        Predicate<String> shortWord = s -> s.length() < 5;
        Predicate<String> keep = notEmpty.and(shortWord.negate());
        System.out.println(keep.test("banana") + " " + keep.test("fig") + " " + keep.test(""));
    }
}

Capturing variables

A lambda can use local variables from the surrounding code only if they are effectively final (never reassigned after initialisation):

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        int threshold = 3;                                  // effectively final: fine to capture
        List<String> words = List.of("a", "abcd", "ab", "abcdef");
        words.stream().filter(w -> w.length() > threshold).forEach(System.out::println);

        // int count = 0;
        // words.forEach(w -> count++);                    // error: count is not effectively final
        int[] count = {0};                                  // a common workaround; a stream's count() is better
        words.forEach(w -> count[0]++);
        System.out.println(count[0]);
    }
}

Lambdas with collections

Many collection methods take functions:

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>(List.of("ada", "", "grace", "linus", ""));
        names.removeIf(String::isEmpty);
        names.replaceAll(s -> Character.toUpperCase(s.charAt(0)) + s.substring(1));
        names.sort(Comparator.comparing(String::length).thenComparing(Comparator.reverseOrder()));
        names.forEach(n -> System.out.print(n + " "));
        System.out.println();

        Map<Integer, List<String>> byLength = new TreeMap<>();
        for (String n : names) byLength.computeIfAbsent(n.length(), k -> new ArrayList<>()).add(n);
        byLength.forEach((len, group) -> System.out.println(len + ": " + group));

        Map<String, Integer> stock = new HashMap<>(Map.of("tea", 3));
        stock.merge("tea", 2, Integer::sum);
        stock.computeIfPresent("tea", (k, v) -> v > 4 ? v - 4 : v);
        System.out.println(stock);
    }
}
