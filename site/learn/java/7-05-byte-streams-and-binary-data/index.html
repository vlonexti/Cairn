Byte Streams and Binary Data

lesson 7.055 of 5 in milestone 75 min2 practice tasks

Reading and writing bytes - InputStream and OutputStream, byte arrays and ByteArrayOutputStream, buffering, DataOutputStream and DataInputStream for numbers in a fixed format, ByteBuffer and byte order, designing a small binary file format, checksums, and decorating streams.

Text is bytes too

Lesson 4.05 read and wrote text with Files and readers and writers, which turn characters into bytes using an encoding (UTF-8). Underneath, every file, network connection and compressed archive is a sequence of bytes. Java reads and writes them with two abstract classes:

  • InputStream: read() returns the next byte (0–255) or -1 at the end; read(byte[]) fills an array and returns how many bytes it got.
  • OutputStream: write(int) writes one byte; write(byte[]) writes many.

Always close them, which try with resources does for you.

Bytes in memory

ByteArrayOutputStream collects written bytes in memory and ByteArrayInputStream reads from an array: perfect for building data and for tests.

Java
import java.io.*;
import java.nio.charset.StandardCharsets;
import java.util.Arrays;

public class Main {
    public static void main(String[] args) throws IOException {
        var out = new ByteArrayOutputStream();
        out.write(72);
        out.write("ello".getBytes(StandardCharsets.UTF_8));
        byte[] bytes = out.toByteArray();
        System.out.println(Arrays.toString(bytes));                 // [72, 101, 108, 108, 111]
        System.out.println(new String(bytes, StandardCharsets.UTF_8));

        try (var in = new ByteArrayInputStream(bytes)) {
            int b;
            while ((b = in.read()) != -1) System.out.print(Integer.toHexString(b) + " ");
        }
        System.out.println();
    }
}

A Java byte is signed (−128 to 127). b & 0xFF gives its unsigned value (0 to 255).

Streams wrap streams

Streams are designed to be stacked: each wrapper adds one ability to the stream inside it.

Java
try (var out = new DataOutputStream(            // numbers in a fixed binary format
               new BufferedOutputStream(        // fewer, larger writes to the disk
               new FileOutputStream("scores.bin")))) {
    out.writeInt(3);
}

BufferedInputStream and BufferedOutputStream make many small reads and writes fast. GZIPOutputStream compresses, CipherOutputStream encrypts, and CheckedOutputStream keeps a checksum, all by wrapping another stream.

Numbers as bytes

DataOutputStream writes int, long, double and so on in a fixed big-endian format, and DataInputStream reads them back in the same order:

Java
import java.io.*;

public class Main {
    public static void main(String[] args) throws IOException {
        var buffer = new ByteArrayOutputStream();
        try (var out = new DataOutputStream(buffer)) {
            out.writeInt(2);                    // how many records follow
            out.writeUTF("Ada");                // a length-prefixed string
            out.writeDouble(98.5);
            out.writeUTF("Linus");
            out.writeDouble(87.25);
        }
        System.out.println(buffer.size() + " bytes");

        try (var in = new DataInputStream(new ByteArrayInputStream(buffer.toByteArray()))) {
            int count = in.readInt();
            for (int i = 0; i < count; i++) System.out.println(in.readUTF() + " " + in.readDouble());
        }
    }
}

Reading must follow exactly the order of writing; there are no labels in the data. Reading past the end throws EOFException.

ByteBuffer and byte order

Many file formats are little-endian (the low byte first), which DataOutputStream cannot do. ByteBuffer can, and also reads and writes at any position:

Java
import java.nio.ByteBuffer;
import java.nio.ByteOrder;
import java.util.HexFormat;

public class Main {
    public static void main(String[] args) {
        ByteBuffer big = ByteBuffer.allocate(4).putInt(0x12345678);
        ByteBuffer little = ByteBuffer.allocate(4).order(ByteOrder.LITTLE_ENDIAN).putInt(0x12345678);
        System.out.println(HexFormat.of().formatHex(big.array()));      // 12345678
        System.out.println(HexFormat.of().formatHex(little.array()));   // 78563412

        ByteBuffer read = ByteBuffer.wrap(little.array()).order(ByteOrder.LITTLE_ENDIAN);
        System.out.println(Integer.toHexString(read.getInt()));         // 12345678
    }
}

Designing a small format

A robust binary file usually has:

  1. a magic number at the start (a few fixed bytes) so you can tell the file is yours;
  2. a version so newer programs can still read older files;
  3. lengths before variable-sized data (strings, lists);
  4. a checksum at the end to detect damage.
Java
import java.util.zip.CRC32;

public class Main {
    public static void main(String[] args) {
        CRC32 crc = new CRC32();
        crc.update("hello".getBytes());
        System.out.println(Long.toHexString(crc.getValue()));     // 3610a686
    }
}
