Classes and Objects

lesson 3.011 of 5 in milestone 35 min1 practice task

Defining your own classes with fields, constructors and instance methods, creating objects with new, the this reference, references and null, toString, object identity versus equality, and how to design a class around the data it owns.

A class

A class is a blueprint: it describes the data an object holds (fields) and what it can do (methods). Each object made from it with new is an instance with its own copy of the fields.

Java
public class Main {
    public static void main(String[] args) {
        Counter clicks = new Counter("clicks");
        Counter errors = new Counter("errors");
        clicks.increment();
        clicks.increment();
        errors.increment();
        System.out.println(clicks.describe());
        System.out.println(errors.describe());
        clicks.reset();
        System.out.println(clicks);              // uses toString
    }
}

class Counter {
    private final String name;   // fields: every Counter has its own
    private int count;           // starts at 0

    Counter(String name) {       // the constructor: runs when new Counter(...) is called
        this.name = name;
    }

    void increment() { count++; }
    void reset() { count = 0; }
    int getCount() { return count; }

    String describe() { return name + ": " + count; }

    @Override
    public String toString() { return "Counter[" + name + "=" + count + "]"; }
}
  • new Counter("clicks") allocates an object and runs the constructor, which has the class's name and no return type.
  • Methods without static are instance methods: they run on one object and use its fields.
  • this is the object the method or constructor is running on. this.name = name copies the parameter into the field with the same name.
  • Overriding toString decides how the object prints. @Override asks the compiler to check that you really are overriding a method.

Several classes can live in one file, but only one can be public, and it gives the file its name. In larger programs each class gets its own file.

Objects are references

A variable of a class type holds a reference to an object. Assigning it copies the reference:

Java
public class Main {
    public static void main(String[] args) {
        Point a = new Point(1, 2);
        Point b = a;                 // the same object
        Point c = new Point(1, 2);   // a different object with the same values
        b.x = 10;
        System.out.println(a.x);              // 10
        System.out.println(a == b);           // true: same object
        System.out.println(a == c);           // false: different objects
        System.out.println(a.equals(c));      // false too: Object.equals compares identity unless overridden

        Point nothing = null;
        try {
            System.out.println(nothing.x);
        } catch (NullPointerException e) {
            System.out.println("NullPointerException: there is no object");
        }
    }
}

class Point {
    int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
}

To make equals compare contents, a class must override equals (and hashCode; lesson 4.02). Records (lesson 3.05) do that automatically.

Methods that work with other objects

Methods can take and return objects, including objects of their own class:

Java
public class Main {
    public static void main(String[] args) {
        Fraction half = new Fraction(1, 2);
        Fraction third = new Fraction(1, 3);
        Fraction sum = half.plus(third);
        System.out.println(half + " + " + third + " = " + sum);
        System.out.println(new Fraction(6, 8));
    }
}

class Fraction {
    private final int num, den;

    Fraction(int num, int den) {
        if (den == 0) throw new IllegalArgumentException("denominator is zero");
        int g = gcd(Math.abs(num), Math.abs(den));
        int sign = den < 0 ? -1 : 1;
        this.num = sign * num / g;
        this.den = sign * den / g;
    }

    Fraction plus(Fraction other) {
        return new Fraction(num * other.den + other.num * den, den * other.den);
    }

    private static int gcd(int a, int b) { return b == 0 ? Math.max(a, 1) : gcd(b, a % b); }

    @Override
    public String toString() { return num + "/" + den; }
}

Fraction keeps its fields final: once made, a fraction never changes, and plus returns a new fraction. Immutable objects like this (and String) are simple to reason about and safe to share.

Designing a class

Ask: what data belongs together, and what operations keep that data correct? A BankAccount owns a balance and offers deposit and withdraw, which refuse to make it invalid. A class with good methods means the rest of the program never has to repeat those rules.
