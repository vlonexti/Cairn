Generics

lesson 4.011 of 5 in milestone 45 min1 practice task

Type parameters on classes, interfaces and methods, why generics replaced Object and casts, bounded types with extends, wildcards with ? extends and ? super (PECS), type erasure and its limits, and writing your own generic container.

Why generics

Before generics (Java 5), a list held Objects. Every read needed a cast, and putting the wrong type in was only discovered when the program crashed:

Java
List names = new ArrayList();        // a "raw" list
names.add("Ada");
names.add(42);                       // nothing stops this
String first = (String) names.get(0);
String second = (String) names.get(1);   // ClassCastException at run time

With a type parameter, List<String> holds only strings, the compiler checks every add, and no casts are needed. Mistakes become compile errors.

A generic class

Java
public class Main {
    public static void main(String[] args) {
        Box<String> name = new Box<>("Ada");
        Box<Integer> age = new Box<>(36);
        String n = name.get();              // no cast
        int a = age.get() + 1;
        System.out.println(n + " " + a + " " + name.map(String::length).get());

        Pair<String, Integer> entry = new Pair<>("apples", 4);
        System.out.println(entry + " " + entry.swap());
    }
}

class Box<T> {
    private final T value;
    Box(T value) { this.value = value; }
    T get() { return value; }
    <R> Box<R> map(java.util.function.Function<T, R> f) { return new Box<>(f.apply(value)); }   // a generic method
}

record Pair<A, B>(A first, B second) {
    Pair<B, A> swap() { return new Pair<>(second, first); }
}

By convention, type parameters are single capital letters: T (type), E (element), K/V (key/value), R (result). Type arguments must be reference types: Box<int> is not allowed, use Box<Integer>.

Generic methods

A method can have its own type parameters, written before the return type. The compiler infers them from the arguments:

Java
import java.util.List;

public class Main {
    public static void main(String[] args) {
        System.out.println(last(List.of("a", "b", "c")));
        System.out.println(last(List.of(1, 2, 3)));
        System.out.println(max(List.of(4, 9, 2)) + " " + max(List.of("pear", "apple")));
    }

    static <T> T last(List<T> items) {
        return items.get(items.size() - 1);
    }

    static <T extends Comparable<T>> T max(List<T> items) {      // a bounded type parameter
        T best = items.get(0);
        for (T item : items) if (item.compareTo(best) > 0) best = item;
        return best;
    }
}

T extends Comparable<T> means "any T that can be compared with itself", which is what lets the body call compareTo.

Wildcards

A List<Integer> is not a List<Number>, even though Integer is a Number. (If it were, you could add a Double to a list of integers through the List<Number> variable.) Wildcards express "a list of some type":

Java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> ints = List.of(1, 2, 3);
        List<Double> doubles = List.of(1.5, 2.5);
        System.out.println(sum(ints) + " " + sum(doubles));

        List<Number> numbers = new ArrayList<>();
        List<Object> objects = new ArrayList<>();
        addOnes(numbers, 2);
        addOnes(objects, 1);
        System.out.println(numbers + " " + objects);
    }

    static double sum(List<? extends Number> values) {      // read Numbers from it
        double total = 0;
        for (Number n : values) total += n.doubleValue();
        return total;
    }

    static void addOnes(List<? super Integer> target, int count) {   // write Integers into it
        for (int i = 0; i < count; i++) target.add(1);
    }
}

The rule of thumb is PECS: Producer Extends, Consumer Super. A parameter you only read from takes ? extends T; one you only write to takes ? super T. Collections.copy(List<? super T> dest, List<? extends T> src) uses both.

Type erasure

Generics exist only at compile time: the compiler checks the types and then erases them, so at run time a List<String> is just a List. Consequences:

  • new T() and new T[10] are not allowed (the type is unknown at run time).
  • x instanceof List<String> is not allowed; x instanceof List<?> is.
  • You cannot overload f(List<String>) and f(List<Integer>): after erasure they are the same.
