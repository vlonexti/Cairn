Inheritance and Polymorphism

lesson 3.033 of 5 in milestone 35 min1 practice task

Extending a class with extends, calling the superclass constructor with super, overriding methods and @Override, protected members, dynamic dispatch and polymorphism, the Object class with toString, equals and hashCode, casting with instanceof patterns, final, and when to prefer composition.

extends

A class can extend one other class, its superclass, inheriting its fields and methods and adding or changing some:

Java
public class Main {
    public static void main(String[] args) {
        Employee[] staff = {
            new Employee("Ada", 4000),
            new Manager("Grace", 5000, 3),
            new Intern("Linus", 1200, 6),
        };
        double total = 0;
        for (Employee e : staff) {
            System.out.println(e.describe());     // each object answers in its own way
            total += e.monthlyCost();
        }
        System.out.println("Total: " + total);
    }
}

class Employee {
    private final String name;
    protected final double salary;               // visible to subclasses

    Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }

    String getName() { return name; }
    double monthlyCost() { return salary; }
    String describe() { return name + " costs " + monthlyCost(); }
}

class Manager extends Employee {
    private final int reports;

    Manager(String name, double salary, int reports) {
        super(name, salary);                     // must be the first statement
        this.reports = reports;
    }

    @Override
    double monthlyCost() { return super.monthlyCost() + 200 * reports; }

    @Override
    String describe() { return super.describe() + " (manages " + reports + ")"; }
}

class Intern extends Employee {
    private final int months;

    Intern(String name, double stipend, int months) {
        super(name, stipend);
        this.months = months;
    }

    @Override
    String describe() { return getName() + " is an intern for " + months + " months"; }
}
  • super(...) runs the superclass constructor; it must come first. If you leave it out, Java calls super() with no arguments.
  • Overriding: a subclass method with the same signature replaces the inherited one. @Override makes the compiler check that it really overrides something (a typo would otherwise create a new method silently).
  • super.method() calls the superclass's version.

Polymorphism

A variable of type Employee can refer to a Manager. When a method is called, Java uses the version of the actual object's class, decided at run time (dynamic dispatch). So describe() in Employee calls monthlyCost(), and for a manager that is the manager's version. Code written for Employee works for every subclass, including ones written later.

The Object class

Every class extends Object, directly or indirectly, and inherits toString, equals and hashCode. Override them to give your class sensible behaviour:

Java
import java.util.HashSet;
import java.util.Objects;
import java.util.Set;

public class Main {
    public static void main(String[] args) {
        Book a = new Book("Dune", 1965);
        Book b = new Book("Dune", 1965);
        System.out.println(a + " " + a.equals(b));
        Set<Book> shelf = new HashSet<>();
        shelf.add(a);
        shelf.add(b);
        System.out.println(shelf.size());      // 1: equal books count once
    }
}

class Book {
    private final String title;
    private final int year;

    Book(String title, int year) { this.title = title; this.year = year; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Book other)) return false;
        return year == other.year && title.equals(other.title);
    }

    @Override
    public int hashCode() { return Objects.hash(title, year); }

    @Override
    public String toString() { return title + " (" + year + ")"; }
}

The rule: objects that are equal must have equal hash codes. Override both together, or HashSet and HashMap will misbehave (lesson 4.02).

instanceof and casting

instanceof checks an object's type; the pattern form also gives you a variable of that type:

Java
public class Main {
    public static void main(String[] args) {
        Object[] things = {"text", 42, 3.5, new int[] {1, 2}};
        for (Object o : things) {
            if (o instanceof String s) System.out.println("a string of length " + s.length());
            else if (o instanceof Integer i && i > 40) System.out.println("a big int " + i);
            else System.out.println("something else: " + o.getClass().getSimpleName());
        }
    }
}

The old form, ((String) o).length(), casts explicitly and throws ClassCastException if the object is not that type. Many instanceof checks in a row usually mean a method should be overridden instead.

final

A final class cannot be extended (String is final); a final method cannot be overridden. Use final for classes not designed for inheritance.

Composition over inheritance

Inheritance means "is a": a Manager is an Employee. When the relationship is "has a" (a Car has an Engine), hold the other object in a field instead: composition. It is more flexible, since you can swap the part, and avoids deep hierarchies that are hard to change. Java allows only one superclass, but any number of interfaces (next lesson).
