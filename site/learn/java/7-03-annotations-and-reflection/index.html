Annotations and Reflection

lesson 7.033 of 5 in milestone 75 min2 practice tasks

Code that describes and inspects code - the built-in annotations, writing your own with @interface, retention and targets, reading annotations and members at run time with reflection, calling methods and creating objects by name, and the costs that come with it.

Annotations

An annotation is a label on code, written with @. It changes nothing by itself; a tool that reads it decides what it means. You have used several:

Annotation Read by Meaning
@Override the compiler error if the method does not override anything
@Deprecated the compiler warning wherever it is used
@SuppressWarnings("unchecked") the compiler silence one kind of warning
@FunctionalInterface the compiler error unless the interface has one abstract method
@Test JUnit (lesson 6.05) this method is a test

Frameworks such as Spring, JPA and Jackson are driven mostly by annotations.

Writing your own

An annotation type is declared with @interface. Its "methods" are its settings, optionally with defaults. Two meta-annotations say where it may go and how long it is kept:

Java
import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)       // keep it in the class file and visible to reflection
@Target(ElementType.METHOD)              // only on methods
public @interface Command {
    String value();                       // the command's name
    String help() default "";
}

RetentionPolicy.SOURCE annotations disappear after compiling (for compiler checks), CLASS ones are in the class file but invisible at run time, and RUNTIME ones can be read by reflection.

Reflection

Reflection lets a program look at classes while it runs: their fields, methods, constructors and annotations. It starts from a Class object:

Java
import java.lang.reflect.*;
import java.util.Arrays;

public class Main {
    public static class Account {
        private final String owner;
        private long cents;
        public Account(String owner) { this.owner = owner; }
        public void deposit(long amount) { cents += amount; }
        public long balance() { return cents; }
    }

    public static void main(String[] args) throws Exception {
        Class<?> type = Account.class;                       // or object.getClass(), or Class.forName("...")
        System.out.println(type.getSimpleName());

        for (Field f : type.getDeclaredFields())
            System.out.println("field " + f.getName() + ": " + f.getType().getSimpleName());

        Object acc = type.getConstructor(String.class).newInstance("Ada");
        Method deposit = type.getMethod("deposit", long.class);
        deposit.invoke(acc, 250L);
        System.out.println(type.getMethod("balance").invoke(acc));     // 250

        Field cents = type.getDeclaredField("cents");
        cents.setAccessible(true);                           // reach a private field
        System.out.println(cents.getLong(acc));
        System.out.println(Arrays.toString(type.getConstructors()));
    }
}

getMethods() returns public methods including inherited ones; getDeclaredMethods() returns every method declared in that class, private ones too.

Annotations plus reflection

Together they let a small framework find and call your code:

Java
import java.lang.annotation.*;
import java.lang.reflect.Method;
import java.util.Arrays;
import java.util.Comparator;

public class Main {
    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.METHOD)
    @interface Check { String value(); }

    public static class Checks {
        @Check("addition works") public boolean add() { return 1 + 1 == 2; }
        @Check("strings compare") public boolean strings() { return "a".compareTo("b") < 0; }
        public boolean notACheck() { return false; }
    }

    public static void main(String[] args) throws Exception {
        Object target = new Checks();
        Method[] methods = Checks.class.getDeclaredMethods();
        Arrays.sort(methods, Comparator.comparing(Method::getName));     // the order is not guaranteed otherwise
        for (Method m : methods) {
            Check c = m.getAnnotation(Check.class);
            if (c == null) continue;
            boolean ok = (boolean) m.invoke(target);
            System.out.println((ok ? "pass " : "FAIL ") + c.value());
        }
    }
}

That is a test runner in twenty lines: JUnit works on the same idea.

The costs

  • Speed: reflective calls are slower than direct ones (much less so in modern JVMs, but still).
  • Safety: names are strings, so a typo is found only when the code runs, and refactoring tools may miss them.
  • Encapsulation: setAccessible(true) breaks private, and the module system (Java 9+) blocks it for classes in other modules unless they open themselves.
  • Exceptions: invoke wraps whatever the method throws in an InvocationTargetException; the real one is getCause().

Use reflection in frameworks and tools, not in everyday application logic.
