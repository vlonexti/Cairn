Dates and Times with java.time

lesson 7.044 of 5 in milestone 75 min2 practice tasks

Getting time right - Instant for moments, LocalDate and LocalDateTime for calendar values, ZonedDateTime and time zones, Duration and Period, adding and comparing, ChronoUnit.between, formatting and parsing with DateTimeFormatter, and a Clock for testable code.

Which type?

Lesson 6.03 gave a first look at java.time. The key to using it well is picking the type that means what you mean:

Type Means Example
Instant a moment on the global timeline when an order was placed
LocalDate a calendar date, no time or zone a birthday
LocalTime a time of day, no date or zone "the shop opens at 09:00"
LocalDateTime date and time, no zone a meeting written on a wall calendar
ZonedDateTime date, time and time zone "10:00 in Tokyo on 20 November"
Duration an amount of time in seconds and nanoseconds 90 minutes
Period an amount in years, months and days 3 months

All of them are immutable: plusDays returns a new object.

Local values

Java
import java.time.*;
import java.time.temporal.ChronoUnit;

public class Main {
    public static void main(String[] args) {
        LocalDate start = LocalDate.of(2026, 1, 31);
        System.out.println(start.plusMonths(1));             // 2026-02-28: clamped to the month's end
        System.out.println(start.getDayOfWeek());            // SATURDAY
        System.out.println(start.isLeapYear());              // false

        LocalDate due = LocalDate.of(2026, 11, 20);
        System.out.println(ChronoUnit.DAYS.between(start, due));      // 293
        Period p = Period.between(start, due);
        System.out.println(p.getMonths() + " months " + p.getDays() + " days");

        LocalTime opens = LocalTime.of(9, 0);
        System.out.println(opens.plusMinutes(90).isBefore(LocalTime.NOON));   // true
    }
}

Moments and zones

An Instant is what a server should store: it is the same everywhere. Turn it into local date and time only to show it to a person, with their zone:

Java
import java.time.*;

public class Main {
    public static void main(String[] args) {
        Instant placed = Instant.parse("2026-11-20T23:30:00Z");
        ZonedDateTime tokyo = placed.atZone(ZoneId.of("Asia/Tokyo"));
        ZonedDateTime london = placed.atZone(ZoneId.of("Europe/London"));
        System.out.println(tokyo.toLocalDate() + " in Tokyo, " + london.toLocalDate() + " in London");

        ZonedDateTime meeting = ZonedDateTime.of(2026, 3, 29, 0, 30, 0, 0, ZoneId.of("Europe/London"));
        System.out.println(meeting.plusHours(2));     // daylight saving starts that night: 03:30+01:00
    }
}

Adding hours to a ZonedDateTime follows the real clock across daylight-saving changes; a LocalDateTime knows nothing about them.

Duration and Period

Duration measures exact time (Duration.ofMinutes(90), Duration.between(instantA, instantB)); Period measures calendar steps (Period.ofMonths(1)), whose length in days depends on where you start. "One day" as a Period across a daylight-saving change is 23 or 25 hours; as a Duration it is always 24.

Java
import java.time.*;

public class Main {
    public static void main(String[] args) {
        Duration call = Duration.ofSeconds(4000);
        System.out.println(call.toHours() + "h " + call.toMinutesPart() + "m " + call.toSecondsPart() + "s");
        System.out.println(call.compareTo(Duration.ofHours(1)) > 0);
    }
}

Formatting and parsing

DateTimeFormatter turns values into text and back. Use the predefined ISO formats for data, and a pattern (with a locale) for people:

Java
import java.time.*;
import java.time.format.*;
import java.util.Locale;

public class Main {
    public static void main(String[] args) {
        LocalDateTime t = LocalDateTime.of(2026, 11, 20, 14, 5);
        System.out.println(t.format(DateTimeFormatter.ISO_LOCAL_DATE_TIME));      // 2026-11-20T14:05:00
        var human = DateTimeFormatter.ofPattern("EEEE d MMMM yyyy, HH:mm", Locale.UK);
        System.out.println(t.format(human));                                      // Friday 20 November 2026, 14:05

        LocalDate parsed = LocalDate.parse("20/11/2026", DateTimeFormatter.ofPattern("dd/MM/yyyy"));
        System.out.println(parsed);
        try {
            LocalDate.parse("31/02/2026", DateTimeFormatter.ofPattern("dd/MM/uuuu").withResolverStyle(ResolverStyle.STRICT));
        } catch (DateTimeParseException e) {
            System.out.println("not a real date");
        }
    }
}

Pattern letters are case-sensitive: MM is month, mm is minute; HH is 0–23, hh is 1–12. With ResolverStyle.STRICT, use uuuu for the year.

Testable time: Clock

Code that calls LocalDate.now() gives a different answer every day, which makes it hard to test. Pass a Clock in instead; tests use a fixed one:

Java
import java.time.*;

public class Main {
    static boolean isOverdue(LocalDate due, Clock clock) {
        return LocalDate.now(clock).isAfter(due);
    }

    public static void main(String[] args) {
        Clock fixed = Clock.fixed(Instant.parse("2026-11-20T12:00:00Z"), ZoneOffset.UTC);
        System.out.println(isOverdue(LocalDate.of(2026, 11, 19), fixed));   // true, today and every day
    }
}
