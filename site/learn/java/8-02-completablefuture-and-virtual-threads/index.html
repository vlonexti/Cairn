CompletableFuture and Virtual Threads

lesson 8.022 of 5 in milestone 85 min2 practice tasks

Modern concurrency in Java - CompletableFuture for chaining work that finishes later (supplyAsync, thenApply, thenCompose, thenCombine, allOf), handling failures with exceptionally and handle, timeouts with orTimeout, and virtual threads that make one cheap thread per task practical again.

Beyond Future

Lesson 6.04 used ExecutorService and Future: you submit work and later call get(), which blocks until it is done. To do something with the result, you have to wait for it first. CompletableFuture lets you say what happens next without blocking.

A pipeline of steps

The examples in this lesson start real threads, which the runner in your browser does not allow, so run them on your computer with java Main.java. The practice tasks are written so they need no threads of their own.

Java
import java.util.concurrent.*;

public class Main {
    static String fetchUser(int id) {
        sleep(50);
        return "user" + id;
    }

    static void sleep(long ms) {
        try { Thread.sleep(ms); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
    }

    public static void main(String[] args) {
        CompletableFuture<String> greeting = CompletableFuture
                .supplyAsync(() -> fetchUser(7))           // runs on another thread
                .thenApply(String::toUpperCase)            // then transform the result
                .thenApply(name -> "Hello, " + name);
        System.out.println("started, not waiting yet");
        System.out.println(greeting.join());               // wait only at the very end
    }
}
  • supplyAsync(supplier) starts work that returns a value (runAsync for work with no value).
  • thenApply(fn) transforms the result when it arrives, like map on a stream.
  • join() waits and returns the result (like get(), without checked exceptions).

Steps that are themselves asynchronous

When the next step also returns a CompletableFuture, use thenCompose (like flatMap), so you do not end up with a future of a future:

Java
import java.util.concurrent.*;

public class Main {
    static CompletableFuture<Integer> findUserId(String name) {
        return CompletableFuture.supplyAsync(() -> name.length() * 10);
    }

    static CompletableFuture<String> loadOrders(int userId) {
        return CompletableFuture.supplyAsync(() -> "orders of " + userId);
    }

    public static void main(String[] args) {
        String result = findUserId("ada")
                .thenCompose(Main::loadOrders)
                .join();
        System.out.println(result);
    }
}

Waiting for several

thenCombine joins two independent results; allOf waits for any number:

Java
import java.util.*;
import java.util.concurrent.*;
import java.util.stream.*;

public class Main {
    static CompletableFuture<Integer> price(String item, int ms, int value) {
        return CompletableFuture.supplyAsync(() -> {
            try { Thread.sleep(ms); } catch (InterruptedException e) { throw new RuntimeException(e); }
            return value;
        });
    }

    public static void main(String[] args) {
        long start = System.nanoTime();
        var total = price("tea", 100, 3).thenCombine(price("cake", 100, 4), Integer::sum);
        System.out.println("tea + cake = " + total.join());

        List<CompletableFuture<Integer>> all = List.of(price("a", 80, 1), price("b", 120, 2), price("c", 60, 3));
        CompletableFuture.allOf(all.toArray(new CompletableFuture[0])).join();
        int sum = all.stream().mapToInt(CompletableFuture::join).sum();
        long ms = (System.nanoTime() - start) / 1_000_000;
        System.out.println("sum " + sum + ", about " + (ms < 400 ? "as long as the slowest" : "the sum of all"));
    }
}

anyOf completes with the first one to finish.

Failures

An exception inside a stage completes the future exceptionally, and the following thenApply steps are skipped. Recover with exceptionally (only on failure) or handle (always, with the result or the error):

Java
import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) {
        CompletableFuture<Integer> parsed = CompletableFuture
                .supplyAsync(() -> Integer.parseInt("forty-two"))
                .thenApply(n -> n * 2)                          // skipped
                .exceptionally(e -> {
                    System.out.println("failed: " + e.getCause().getClass().getSimpleName());
                    return 0;
                });
        System.out.println(parsed.join());

        String status = CompletableFuture.supplyAsync(() -> 10 / 2)
                .handle((value, error) -> error == null ? "ok " + value : "error " + error.getMessage())
                .join();
        System.out.println(status);
    }
}

The error passed to these callbacks is usually a CompletionException wrapping the real one; getCause() gives the original.

Timeouts

Java
import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) {
        String r = CompletableFuture.supplyAsync(() -> {
                    try { Thread.sleep(2000); } catch (InterruptedException e) { }
                    return "slow answer";
                })
                .completeOnTimeout("default answer", 100, TimeUnit.MILLISECONDS)
                .join();
        System.out.println(r);
    }
}

orTimeout(ms, unit) fails with a TimeoutException instead of giving a default.

Which threads?

supplyAsync without an executor uses the shared ForkJoinPool.commonPool(), sized for the number of processor cores: right for calculations, wrong for work that mostly waits (network, files). Pass your own executor for waiting work: supplyAsync(task, executor).

Virtual threads

Classic Java threads are operating system threads: each costs memory, and a few thousand is a lot. Since Java 21, virtual threads are managed by the JVM and are cheap enough to create one per task, even a million. When a virtual thread waits (sleep, I/O, a lock), it gives up its carrier thread for others.

Java
import java.util.concurrent.*;
import java.util.stream.*;

public class Main {
    public static void main(String[] args) throws Exception {
        long start = System.nanoTime();
        try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
            var futures = IntStream.range(0, 10_000)
                    .mapToObj(i -> executor.submit(() -> {
                        Thread.sleep(100);                // 10,000 tasks that each wait 100 ms
                        return i;
                    }))
                    .toList();
            long sum = 0;
            for (var f : futures) sum += f.get();
            System.out.println("sum " + sum);
        }
        long ms = (System.nanoTime() - start) / 1_000_000;
        System.out.println(ms < 5000 ? "finished in well under a second per thousand" : "slow");
        Thread t = Thread.ofVirtual().start(() -> System.out.println("virtual: " + Thread.currentThread().isVirtual()));
        t.join();
    }
}

With virtual threads you can write plain, blocking, easy-to-read code (var page = fetch(url);) and still handle many tasks at once. They help with waiting, not with calculating: CPU-heavy work still needs about one thread per core.
