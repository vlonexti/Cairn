Methods that call themselves - base cases and recursive cases, how the call stack works, tracing factorial and Fibonacci, recursion on arrays and strings, the cost of naive recursion and memoization, StackOverflowError, and when to prefer a loop.

A method that calls itself

A recursive method solves a problem by calling itself on a smaller version of the same problem. Every recursive method needs:

  1. a base case that is answered directly, without recursion;
  2. a recursive case that moves toward the base case.
Java
public class Main {
    public static void main(String[] args) {
        System.out.println(factorial(5));
        System.out.println(sumTo(100));
        System.out.println(power(2, 10));
    }

    static long factorial(int n) {
        if (n <= 1) return 1;                  // base case
        return n * factorial(n - 1);           // recursive case: a smaller problem
    }

    static int sumTo(int n) {
        return n == 0 ? 0 : n + sumTo(n - 1);
    }

    static long power(long base, int exp) {
        if (exp == 0) return 1;
        long half = power(base, exp / 2);      // halves the problem each time
        return exp % 2 == 0 ? half * half : half * half * base;
    }
}

The call stack

Each call gets its own stack frame holding its parameters and local variables. factorial(4) waits for factorial(3), which waits for factorial(2), and so on; when the base case returns, the waiting calls finish in reverse order:

Text
factorial(4)
  4 * factorial(3)
        3 * factorial(2)
              2 * factorial(1)
                    1             <- base case
              2 * 1 = 2
        3 * 2 = 6
  4 * 6 = 24

Without a base case (or with one that is never reached), calls pile up until the stack runs out of space and Java throws StackOverflowError.

Recursion on arrays and strings

Recursion fits problems that contain smaller copies of themselves. Pass indexes to work on part of an array without copying it:

Java
public class Main {
    public static void main(String[] args) {
        System.out.println(reverse("recursion"));
        System.out.println(isPalindrome("racecar") + " " + isPalindrome("java"));
        int[] sorted = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
        System.out.println(binarySearch(sorted, 23, 0, sorted.length - 1));
        System.out.println(countDigits(90210));
    }

    static String reverse(String s) {
        if (s.length() <= 1) return s;
        return reverse(s.substring(1)) + s.charAt(0);
    }

    static boolean isPalindrome(String s) {
        if (s.length() <= 1) return true;
        return s.charAt(0) == s.charAt(s.length() - 1) && isPalindrome(s.substring(1, s.length() - 1));
    }

    static int binarySearch(int[] a, int target, int lo, int hi) {
        if (lo > hi) return -1;                // nothing left: not found
        int mid = (lo + hi) / 2;
        if (a[mid] == target) return mid;
        if (a[mid] < target) return binarySearch(a, target, mid + 1, hi);
        return binarySearch(a, target, lo, mid - 1);
    }

    static int countDigits(int n) {
        return n < 10 ? 1 : 1 + countDigits(n / 10);
    }
}

Repeated work and memoization

The direct recursive Fibonacci is elegant and terribly slow: fib(n) calls fib(n-1) and fib(n-2), which recompute the same values again and again, roughly 1.6ⁿ calls in total. Memoization stores each answer the first time it is computed:

Java
import java.util.HashMap;
import java.util.Map;

public class Main {
    static int calls = 0;
    static final Map<Integer, Long> memo = new HashMap<>();

    public static void main(String[] args) {
        System.out.println(slowFib(25) + " after " + calls + " calls");
        calls = 0;
        System.out.println(fastFib(90) + " after " + calls + " calls");
    }

    static long slowFib(int n) {
        calls++;
        return n < 2 ? n : slowFib(n - 1) + slowFib(n - 2);
    }

    static long fastFib(int n) {
        calls++;
        if (n < 2) return n;
        Long known = memo.get(n);
        if (known != null) return known;
        long result = fastFib(n - 1) + fastFib(n - 2);
        memo.put(n, result);
        return result;
    }
}

Recursion or a loop?

Anything recursive can be written with a loop, and vice versa. Use recursion when the problem is naturally recursive: trees (lesson 5.05), nested structures, divide-and-conquer algorithms like merge sort and quicksort (lesson 5.02), and exploring all combinations. Use a loop for simple repetition such as summing an array: it is clearer and cannot overflow the stack.
