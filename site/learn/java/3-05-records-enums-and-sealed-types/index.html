Records, Enums and Sealed Types

lesson 3.055 of 5 in milestone 35 min1 practice task

Modern Java data modelling - records with compact constructors and value equality, enums with fields, methods and switch, EnumMap, sealed interfaces that list their implementations, and pattern matching in switch with record patterns for exhaustive handling of every case.

Records

A record is a class for plain data. One line gives you private final fields, a constructor, accessors, and equals, hashCode and toString based on the values:

Java
import java.util.HashSet;
import java.util.Set;

public class Main {
    public static void main(String[] args) {
        Point a = new Point(1, 2);
        Point b = new Point(1, 2);
        System.out.println(a + " " + a.equals(b) + " " + a.x());     // accessors are x() and y()
        Set<Point> set = new HashSet<>(Set.of(a));
        System.out.println(set.contains(b));                          // true: value equality
        System.out.println(a.plus(new Point(10, 10)));
        System.out.println(new Range(3, 7).length());
        try {
            new Range(5, 1);
        } catch (IllegalArgumentException e) {
            System.out.println(e.getMessage());
        }
    }
}

record Point(int x, int y) {
    Point plus(Point other) { return new Point(x + other.x, y + other.y); }   // records can have methods
}

record Range(int start, int end) {
    Range {                                                 // a compact constructor: validation
        if (start > end) throw new IllegalArgumentException("start after end: " + start + " > " + end);
    }
    int length() { return end - start; }
}

Records are immutable: to "change" one, create a new one. Use them for values that are compared, stored in sets and maps, returned from methods, and passed between parts of a program.

Enums

An enum is a type with a fixed set of named values. Enums can have fields, constructors and methods:

Java
import java.util.EnumMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Planet home = Planet.EARTH;
        System.out.printf("%s: %.2f m/s2%n", home, home.surfaceGravity());
        for (Planet p : Planet.values()) System.out.print(p.name().toLowerCase() + " ");
        System.out.println();
        System.out.println(Planet.valueOf("MARS").ordinal());

        Map<Planet, Integer> visits = new EnumMap<>(Planet.class);
        visits.merge(Planet.MARS, 1, Integer::sum);
        visits.merge(Planet.MARS, 1, Integer::sum);
        System.out.println(visits);

        Level level = Level.WARN;
        String colour = switch (level) {
            case DEBUG, INFO -> "grey";
            case WARN -> "orange";
            case ERROR -> "red";
        };                                             // no default needed: every constant is covered
        System.out.println(colour + " " + level.isAtLeast(Level.INFO));
    }
}

enum Planet {
    MERCURY(3.303e23, 2.4397e6), EARTH(5.976e24, 6.37814e6), MARS(6.421e23, 3.3972e6);

    private final double mass, radius;
    Planet(double mass, double radius) { this.mass = mass; this.radius = radius; }

    double surfaceGravity() { return 6.67300e-11 * mass / (radius * radius); }
}

enum Level {
    DEBUG, INFO, WARN, ERROR;
    boolean isAtLeast(Level other) { return compareTo(other) >= 0; }
}

Use enums instead of int or String codes for fixed sets: directions, card suits, order states, log levels. The compiler then rejects invalid values, and a switch can be checked for completeness.

Sealed types

A sealed interface or class lists exactly which classes may implement or extend it. Together with records, that models data that is "one of these kinds":

Java
public class Main {
    public static void main(String[] args) {
        Shape[] shapes = {new Circle(1), new Square(2), new Rect(2, 3)};
        for (Shape s : shapes) System.out.printf("%s -> %.2f%n", s, area(s));
        System.out.println(describe(new Rect(4, 4)) + ", " + describe(new Rect(2, 5)));
    }

    static double area(Shape s) {
        return switch (s) {                            // pattern matching for switch
            case Circle c -> Math.PI * c.r() * c.r();
            case Square sq -> sq.side() * sq.side();
            case Rect(double w, double h) -> w * h;    // a record pattern takes the record apart
        };                                             // exhaustive: every permitted type is covered
    }

    static String describe(Shape s) {
        return switch (s) {
            case Rect(double w, double h) when w == h -> "a square-shaped rectangle";   // a guard
            case Rect r -> "a rectangle";
            default -> "another shape";
        };
    }
}

sealed interface Shape permits Circle, Square, Rect { }
record Circle(double r) implements Shape { }
record Square(double side) implements Shape { }
record Rect(double w, double h) implements Shape { }

Because the compiler knows every possible Shape, the switch in area needs no default. If someone adds Triangle to the permits list, every switch that does not handle it stops compiling, showing exactly what to update. This style, data as records and behaviour as functions that switch over them, complements classic object-oriented polymorphism.
