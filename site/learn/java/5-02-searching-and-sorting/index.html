Searching and Sorting

lesson 5.022 of 5 in milestone 55 min1 practice task

Linear and binary search with their invariants and the overflow-safe midpoint, the simple sorts (selection and insertion) and why they are O(n²), divide and conquer with merge sort and quicksort, stability, choosing a pivot, and what Java's own sorts use.

Searching

Linear search checks every item: O(n), but it works on any list. Binary search needs a sorted array and halves the range each step: O(log n).

Java
public class Main {
    public static void main(String[] args) {
        int[] sorted = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
        for (int target : new int[] {23, 2, 91, 7}) System.out.print(binarySearch(sorted, target) + " ");
        System.out.println();
    }

    static int binarySearch(int[] a, int target) {
        int lo = 0, hi = a.length - 1;            // the target, if present, is always in a[lo..hi]
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;         // not (lo + hi) / 2: that can overflow for huge arrays
            if (a[mid] == target) return mid;
            if (a[mid] < target) lo = mid + 1;    // the target is to the right
            else hi = mid - 1;                    // the target is to the left
        }
        return -1;
    }
}

The comment on the first line is the loop's invariant: a statement that is true before every round. Binary search is famously easy to get subtly wrong (infinite loops, off-by-one bounds); keeping the invariant in mind is how to get it right. Arrays.binarySearch and Collections.binarySearch do it for you.

Simple sorts

Selection sort repeatedly finds the smallest remaining item and swaps it into place. Insertion sort takes each item and slides it left into the sorted part, like sorting playing cards in your hand:

Java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        int[] a = {29, 10, 14, 37, 13};
        selectionSort(a);
        System.out.println(Arrays.toString(a));
        int[] b = {5, 2, 4, 6, 1, 3};
        insertionSort(b);
        System.out.println(Arrays.toString(b));
    }

    static void selectionSort(int[] a) {
        for (int i = 0; i < a.length - 1; i++) {
            int min = i;
            for (int j = i + 1; j < a.length; j++) if (a[j] < a[min]) min = j;
            int tmp = a[i]; a[i] = a[min]; a[min] = tmp;
        }
    }

    static void insertionSort(int[] a) {
        for (int i = 1; i < a.length; i++) {
            int key = a[i];
            int j = i - 1;
            while (j >= 0 && a[j] > key) {
                a[j + 1] = a[j];        // shift bigger items right
                j--;
            }
            a[j + 1] = key;
        }
    }
}

Both are O(n²) in the worst case. Insertion sort is O(n) on data that is already nearly sorted, which is why fast library sorts use it for small pieces.

Merge sort

Divide and conquer: split the array in half, sort each half recursively, then merge the two sorted halves in one pass. There are log n levels of splitting and each level does O(n) merging work, so merge sort is O(n log n) in every case. It needs O(n) extra space and is stable (equal items keep their order).

Java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        int[] a = {38, 27, 43, 3, 9, 82, 10};
        mergeSort(a, 0, a.length);
        System.out.println(Arrays.toString(a));
    }

    static void mergeSort(int[] a, int from, int to) {          // sorts a[from..to)
        if (to - from < 2) return;
        int mid = (from + to) >>> 1;
        mergeSort(a, from, mid);
        mergeSort(a, mid, to);
        int[] merged = new int[to - from];
        int i = from, j = mid, k = 0;
        while (i < mid && j < to) merged[k++] = a[i] <= a[j] ? a[i++] : a[j++];   // <= keeps it stable
        while (i < mid) merged[k++] = a[i++];
        while (j < to) merged[k++] = a[j++];
        System.arraycopy(merged, 0, a, from, merged.length);
    }
}

Quicksort

Quicksort picks a pivot, partitions the array so smaller items come before it and larger after, and recursively sorts both sides. It sorts in place and is very fast in practice: O(n log n) on average, but O(n²) when the pivots are consistently bad (for example, always the first item of already sorted data). Choosing the middle item or a random one avoids the common bad cases.

Java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        int[] a = {10, 80, 30, 90, 40, 50, 70};
        quickSort(a, 0, a.length - 1);
        System.out.println(Arrays.toString(a));
    }

    static void quickSort(int[] a, int lo, int hi) {
        if (lo >= hi) return;
        int pivot = a[(lo + hi) >>> 1];
        int i = lo, j = hi;
        while (i <= j) {                                // Hoare-style partition
            while (a[i] < pivot) i++;
            while (a[j] > pivot) j--;
            if (i <= j) {
                int t = a[i]; a[i] = a[j]; a[j] = t;
                i++; j--;
            }
        }
        quickSort(a, lo, j);
        quickSort(a, i, hi);
    }
}

Java's own sorts

Call Algorithm Stable
Arrays.sort(int[]) and other primitives Dual-pivot quicksort Not needed (equal numbers are identical)
Arrays.sort(Object[]), List.sort, Collections.sort TimSort (merge sort + insertion sort, fast on partly sorted data) Yes

Use the library sorts in real programs. Writing the algorithms yourself is how you learn the ideas they rely on: divide and conquer, invariants, and analysing recursive work.
