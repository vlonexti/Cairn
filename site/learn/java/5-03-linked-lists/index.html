Linked Lists

lesson 5.033 of 5 in milestone 55 min1 practice task

Building a singly linked list from nodes - adding at the front and back with a tail reference, getting by index, removing, reversing in place, iterating with Iterator, the edge cases of empty and one-element lists, doubly linked lists and sentinel nodes, and comparing linked lists with array lists.

Nodes and links

A linked list stores each item in a node that also holds a reference to the next node. The list keeps a reference to the first node, the head; the last node's next is null.

flowchart LR
  H[head] --> A["7 | next"] --> B["3 | next"] --> C["9 | next"] --> N[null]

Adding at the front is O(1): make a new node point at the old head. There is no indexing in O(1): reaching item i means following i links.

A singly linked list

Java
import java.util.Iterator;
import java.util.NoSuchElementException;

public class Main {
    public static void main(String[] args) {
        MyList<String> list = new MyList<>();
        list.addLast("b");
        list.addFirst("a");
        list.addLast("c");
        list.addLast("d");
        System.out.println(list + " size " + list.size() + " get(2)=" + list.get(2));
        list.remove("c");
        list.reverse();
        System.out.println(list);
        for (String s : list) System.out.print(s.toUpperCase());
        System.out.println();
    }
}

class MyList<T> implements Iterable<T> {
    private static class Node<T> {
        T value;
        Node<T> next;
        Node(T value, Node<T> next) { this.value = value; this.next = next; }
    }

    private Node<T> head, tail;
    private int size;

    void addFirst(T value) {
        head = new Node<>(value, head);
        if (tail == null) tail = head;            // the list was empty
        size++;
    }

    void addLast(T value) {
        Node<T> node = new Node<>(value, null);
        if (tail == null) head = tail = node;     // the list was empty
        else { tail.next = node; tail = node; }
        size++;
    }

    T get(int index) {
        if (index < 0 || index >= size) throw new IndexOutOfBoundsException("index " + index);
        Node<T> n = head;
        for (int i = 0; i < index; i++) n = n.next;
        return n.value;
    }

    boolean remove(T value) {
        Node<T> prev = null;
        for (Node<T> n = head; n != null; prev = n, n = n.next) {
            if (n.value.equals(value)) {
                if (prev == null) head = n.next; else prev.next = n.next;   // unlink
                if (n == tail) tail = prev;
                size--;
                return true;
            }
        }
        return false;
    }

    void reverse() {
        Node<T> prev = null, cur = head;
        tail = head;
        while (cur != null) {
            Node<T> next = cur.next;
            cur.next = prev;                      // turn the arrow around
            prev = cur;
            cur = next;
        }
        head = prev;
    }

    int size() { return size; }

    public Iterator<T> iterator() {
        return new Iterator<>() {
            private Node<T> next = head;
            public boolean hasNext() { return next != null; }
            public T next() {
                if (next == null) throw new NoSuchElementException();
                T v = next.value;
                next = next.next;
                return v;
            }
        };
    }

    @Override
    public String toString() {
        StringBuilder sb = new StringBuilder("[");
        for (Node<T> n = head; n != null; n = n.next) sb.append(n.value).append(n.next != null ? ", " : "");
        return sb.append("]").toString();
    }
}

Points to notice:

  • Node is a private static nested class: it is part of the list's implementation, invisible outside.
  • Keeping a tail reference makes addLast O(1) instead of walking the whole list.
  • Every method that changes the list must handle the edge cases: the empty list, a one-node list, and changes at the head or the tail. Most linked-list bugs live there; draw the boxes and arrows on paper for each case.
  • Implementing Iterable lets the list work with the enhanced for.

Reversing in place

reverse walks the list once with three references (prev, cur, next) and turns each link around: O(n) time and O(1) extra space. It is a classic interview question because it tests exactly the pointer handling above.

Doubly linked lists

A doubly linked node also points to the previous node. Removing a node you already hold becomes O(1) (no need to find its predecessor), and the list can be walked backwards. java.util.LinkedList is doubly linked. Many implementations use a sentinel (dummy) node at both ends, so that the first and last real nodes are not special cases.

Linked list or array list?

ArrayList Linked list
get(i) O(1) O(n)
add/remove at the front O(n) O(1)
add at the end O(1) amortised O(1) with a tail
memory compact array one object per item, with extra references
cache friendliness excellent poor

In practice ArrayList (and ArrayDeque for queues) win almost every benchmark, because modern processors are very fast at reading consecutive memory. Linked structures matter as building blocks: queues, hash table buckets, adjacency lists in graphs, and trees, which are linked lists with more than one next.
