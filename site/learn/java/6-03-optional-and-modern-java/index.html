Optional and Modern Java

lesson 6.033 of 5 in milestone 65 min1 practice task

Representing maybe-missing values with Optional and its methods (map, filter, orElse, orElseGet, orElseThrow, ifPresent), when not to use it, and a tour of modern Java features - var, text blocks, switch expressions and pattern matching, records and sealed types together, the java.time date API, and immutable collections.

Optional

null as "no value" causes NullPointerExceptions far from where the null came from. Optional<T> makes "maybe missing" part of a method's type, so callers must decide what to do:

Java
import java.util.*;

public class Main {
    static final Map<String, String> EMAILS = Map.of("ada", "ada@example.com", "bob", "");

    public static void main(String[] args) {
        System.out.println(findEmail("ada").orElse("no email"));
        System.out.println(findEmail("zed").orElse("no email"));

        String domain = findEmail("ada")
            .map(e -> e.substring(e.indexOf('@') + 1))      // transform if present
            .orElse("unknown");
        System.out.println(domain);

        findEmail("bob").ifPresentOrElse(e -> System.out.println("send to " + e), () -> System.out.println("bob has none"));

        try {
            String e = findEmail("zed").orElseThrow(() -> new NoSuchElementException("no email for zed"));
        } catch (NoSuchElementException ex) {
            System.out.println(ex.getMessage());
        }
    }

    static Optional<String> findEmail(String user) {
        return Optional.ofNullable(EMAILS.get(user)).filter(e -> !e.isBlank());
    }
}
Method Does
Optional.of(x), ofNullable(x), empty() Create (of throws for null)
isPresent(), isEmpty() Test
map(f), flatMap(f), filter(p) Transform, keeping "missing" missing
orElse(v), orElseGet(supplier) A default (orElseGet computes it only when needed)
orElseThrow(), orElseThrow(supplier) The value, or an exception
ifPresent(f), ifPresentOrElse(f, g) Act on it

Streams return Optional from findFirst, min and max.

Use Optional as a return type for "maybe nothing". Do not use it for fields or parameters, do not call get() without checking (use orElseThrow() to make the intent clear), and never return null from a method declared to return an Optional.

Modern Java in one place

Java has changed a lot since Java 8. Code written today looks like this:

Java
import java.time.*;
import java.time.format.DateTimeFormatter;
import java.time.temporal.ChronoUnit;
import java.util.*;

public class Main {
    public static void main(String[] args) {
        var orders = List.of(                                         // var: inferred local types
            new Order("A-1", new Paid(LocalDate.of(2026, 3, 1), 4999)),
            new Order("A-2", new Pending()),
            new Order("A-3", new Refunded("damaged", 1250)));

        for (var order : orders) System.out.println(order.id() + ": " + describe(order.status()));

        String report = """
            Orders: %d
            Generated: %s
            """.formatted(orders.size(), LocalDate.of(2026, 3, 14).format(DateTimeFormatter.ISO_DATE));   // a text block
        System.out.print(report);

        LocalDate due = LocalDate.of(2026, 1, 31).plusMonths(1);       // java.time: immutable dates
        System.out.println(due + " " + due.getDayOfWeek() + " " + ChronoUnit.DAYS.between(LocalDate.of(2026, 1, 1), due));
        Duration d = Duration.ofMinutes(135);
        System.out.println(d.toHours() + "h " + d.toMinutesPart() + "m");
    }

    static String describe(Status s) {
        return switch (s) {                                            // pattern matching over a sealed type
            case Paid(LocalDate on, long cents) when cents > 10_000 -> "large payment on " + on;
            case Paid(LocalDate on, long cents) -> "paid %d.%02d on %s".formatted(cents / 100, cents % 100, on);
            case Pending p -> "waiting for payment";
            case Refunded(String reason, long cents) -> "refunded (" + reason + ")";
        };
    }
}

sealed interface Status permits Paid, Pending, Refunded { }
record Paid(LocalDate on, long cents) implements Status { }
record Pending() implements Status { }
record Refunded(String reason, long cents) implements Status { }
record Order(String id, Status status) { }

java.time

Use java.time for dates and times (never the old Date and Calendar):

Class Holds
LocalDate, LocalTime, LocalDateTime A date / time / both, without a time zone
ZonedDateTime, Instant A moment in time, with a zone / in UTC
Duration, Period An amount of time / of days, months, years
DateTimeFormatter Formatting and parsing

All are immutable: date.plusDays(1) returns a new date.
