Files and I/O

lesson 4.055 of 5 in milestone 45 min1 practice task

Reading and writing text files with java.nio.file - Path and Files, readString, readAllLines, lines and write, BufferedReader and BufferedWriter for large files, character encodings, directories and walking them, handling IOException, parsing CSV records, and the older java.io classes you will still meet.

Path and Files

Modern Java uses java.nio.file: a Path names a file, and the Files class does the work:

Java
import java.io.IOException;
import java.nio.file.*;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Path file = Path.of("notes.txt");
        Files.writeString(file, "first line\nsecond line\n");
        Files.writeString(file, "appended\n", StandardOpenOption.APPEND);

        String all = Files.readString(file);
        List<String> lines = Files.readAllLines(file);
        System.out.println(all.length() + " characters, " + lines.size() + " lines, last: " + lines.get(lines.size() - 1));

        Files.write(Path.of("numbers.txt"), List.of("1", "2", "3"));
        long sum = 0;
        try (var stream = Files.lines(Path.of("numbers.txt"))) {      // lazy: one line at a time
            sum = stream.mapToLong(Long::parseLong).sum();
        }
        System.out.println(sum + " " + Files.exists(file) + " " + Files.size(file));
    }
}

main declares throws IOException here to keep the example short; real programs catch it where they can report the problem.

Paths and directories

Java
import java.io.IOException;
import java.nio.file.*;
import java.util.stream.Stream;

public class Main {
    public static void main(String[] args) throws IOException {
        Path dir = Path.of("data", "2026");
        Files.createDirectories(dir);                     // all missing levels; fine if it exists
        Path report = dir.resolve("report.csv");          // data/2026/report.csv
        Files.writeString(report, "id,total\n1,9.50\n");
        System.out.println(report.getFileName() + " in " + report.getParent());

        try (Stream<Path> all = Files.walk(Path.of("data"))) {
            all.filter(Files::isRegularFile).forEach(p -> System.out.println("found " + p.toString().replace('\\', '/')));
        }
        Files.copy(report, dir.resolve("backup.csv"), StandardCopyOption.REPLACE_EXISTING);
        Files.delete(dir.resolve("backup.csv"));
    }
}

Build paths with Path.of(a, b, c) and resolve, never by gluing strings with / or \: the separator differs between systems.

Large files: buffered readers and writers

readAllLines loads the whole file into memory. For big files, read line by line with a BufferedReader, and write with a BufferedWriter, both in try-with-resources:

Java
import java.io.*;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) throws IOException {
        Path log = Path.of("log.txt");
        try (BufferedWriter out = Files.newBufferedWriter(log)) {
            for (int i = 1; i <= 5; i++) {
                out.write("entry " + i);
                out.newLine();
            }
        }                                                   // closing flushes the buffer to disk

        int count = 0;
        try (BufferedReader in = Files.newBufferedReader(log)) {
            String line;
            while ((line = in.readLine()) != null) {
                if (line.endsWith("3") || line.endsWith("5")) count++;
            }
        }
        System.out.println(count);
    }
}

Text is stored as bytes using an encoding. Files methods use UTF-8 by default, which handles every language; pass StandardCharsets.UTF_8 explicitly when using older APIs.

Errors

File operations fail for reasons outside your program. The specific exceptions tell you why:

Java
import java.io.IOException;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) {
        try {
            String text = Files.readString(Path.of("settings.ini"));
            System.out.println(text);
        } catch (NoSuchFileException e) {
            System.out.println("no settings file: using defaults");
        } catch (AccessDeniedException e) {
            System.out.println("not allowed to read " + e.getFile());
        } catch (IOException e) {
            System.out.println("could not read settings: " + e.getMessage());
        }
    }
}

Reading records

A common task is reading structured lines into objects. Keep parsing in its own method, and decide what to do with bad lines:

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<String> lines = List.of("name,score", "Ada,95", "Grace,abc", "Linus,72", "");
        List<Result> results = new ArrayList<>();
        List<String> problems = new ArrayList<>();
        for (int i = 1; i < lines.size(); i++) {
            String line = lines.get(i);
            if (line.isBlank()) continue;
            String[] f = line.split(",");
            try {
                results.add(new Result(f[0].trim(), Integer.parseInt(f[1].trim())));
            } catch (NumberFormatException | ArrayIndexOutOfBoundsException e) {
                problems.add("line " + (i + 1) + ": " + line);
            }
        }
        System.out.println(results);
        System.out.println(problems);
    }
}

record Result(String name, int score) { }

catch (A | B e) is a multi-catch: one handler for several exception types. Real CSV can contain quoted commas; use a library such as Apache Commons CSV for files you do not control.

The older java.io

You will meet older code using java.io.File, FileReader, FileWriter and Scanner(new File(...)). They still work; Path and Files are the modern replacements with better error messages. file.toPath() and path.toFile() convert between them.
