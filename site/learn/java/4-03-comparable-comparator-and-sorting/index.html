Comparable, Comparator and Sorting

lesson 4.033 of 5 in milestone 45 min1 practice task

Natural ordering with Comparable, external orderings with Comparator, building comparators with comparing, thenComparing, reversed and nullsFirst, sorting lists and arrays, stability, sorted collections with custom orderings, the compareTo contract, and common mistakes like subtracting to compare.

Natural order: Comparable

A class that implements Comparable<T> has a natural order: compareTo returns a negative number when this comes first, zero when equal, positive when this comes after. Strings, numbers and dates already have one.

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<Student> students = new ArrayList<>(List.of(
            new Student("Grace", 88), new Student("Ada", 95), new Student("Linus", 88)));
        Collections.sort(students);                 // uses compareTo
        System.out.println(students);
    }
}

record Student(String name, int score) implements Comparable<Student> {
    @Override
    public int compareTo(Student other) {
        return name.compareTo(other.name);          // natural order: by name
    }
}

Other orders: Comparator

A Comparator is an ordering kept outside the class, so one class can be sorted many ways. The Comparator helper methods build them from the fields to compare:

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<Student> students = new ArrayList<>(List.of(
            new Student("Grace", 88, 2), new Student("Ada", 95, 1),
            new Student("Linus", 88, 1), new Student("Barbara", 72, 3)));

        students.sort(Comparator.comparingInt(Student::score).reversed()
                                .thenComparing(Student::name));      // by score, highest first; ties by name
        System.out.println(students);

        students.sort(Comparator.comparingInt(Student::year).thenComparing(Student::score, Comparator.reverseOrder()));
        System.out.println(students);

        Comparator<String> byLength = Comparator.comparingInt(String::length);
        List<String> words = new ArrayList<>(List.of("kiwi", "fig", "banana", "pear"));
        words.sort(byLength.thenComparing(Comparator.naturalOrder()));
        System.out.println(words);
    }
}

record Student(String name, int score, int year) { }
Builder Meaning
Comparator.comparing(f), comparingInt(f), comparingDouble(f) Compare by a key
.thenComparing(g) Break ties with a second key
.reversed() The opposite order
Comparator.naturalOrder(), reverseOrder() Natural order and its reverse
Comparator.nullsFirst(c), nullsLast(c) Allow nulls

Student::score is a method reference: shorthand for the lambda s -> s.score() (lesson 6.01).

Sorting

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        int[] nums = {5, 3, 9, 1};
        Arrays.sort(nums);                                      // primitives: natural order only
        Integer[] boxed = {5, 3, 9, 1};
        Arrays.sort(boxed, Comparator.reverseOrder());          // objects: any comparator
        System.out.println(Arrays.toString(nums) + " " + Arrays.toString(boxed));

        List<String> names = new ArrayList<>(List.of("bob", "Alice", "carol"));
        names.sort(String.CASE_INSENSITIVE_ORDER);
        System.out.println(names);

        TreeSet<String> byLength = new TreeSet<>(Comparator.comparingInt(String::length).thenComparing(s -> s));
        byLength.addAll(List.of("pear", "fig", "banana", "kiwi"));
        System.out.println(byLength + " first=" + byLength.first());
    }
}

Sorting objects in Java (List.sort, Collections.sort, Arrays.sort on objects) is stable: equal items keep their relative order. That is what makes sorting by one key and then another work as expected.

The compareTo contract

A correct comparison must be consistent: if a < b then b > a; if a < b and b < c then a < c; and ideally compareTo returns 0 exactly when equals is true (a TreeSet treats compare-0 items as duplicates).

A classic bug is comparing by subtraction:

Java
public class Main {
    public static void main(String[] args) {
        int a = Integer.MIN_VALUE, b = 1;
        System.out.println(a - b > 0);                 // true: the subtraction overflows, so the order is wrong
        System.out.println(Integer.compare(a, b));     // -1: correct
    }
}

Always use Integer.compare, Double.compare, or the Comparator builders.
