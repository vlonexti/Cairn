Regular Expressions

lesson 8.011 of 5 in milestone 85 min2 practice tasks

Finding and taking apart text with java.util.regex - Pattern and Matcher, matches versus find, groups and named groups, looping over every match, replacing with a function, splitting, flags such as CASE_INSENSITIVE, the escaping rules in Java strings, and when a regular expression is the wrong tool.

Patterns in Java

A regular expression describes a shape of text: "one or more digits", "a word followed by @". Java's support lives in java.util.regex: a Pattern is the compiled expression and a Matcher applies it to one piece of text.

Java
import java.util.regex.*;

public class Main {
    public static void main(String[] args) {
        Pattern date = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
        Matcher m = date.matcher("due 2026-11-20, paid 2026-12-01");
        while (m.find()) {
            System.out.println(m.group() + " -> year " + m.group(1) + ", month " + m.group(2));
        }
    }
}

Backslashes must be doubled inside Java strings: the regex \d is written "\\d". Text blocks and Pattern.quote help, but the doubling is the most common stumbling block.

The pattern language in brief

piece matches
. any character except a new line
\d, \w, \s a digit, a word character (letter, digit, _), a space
[abc], [a-z], [^0-9] one of, a range, anything except
*, +, ?, {2,5} 0 or more, 1 or more, 0 or 1, 2 to 5 times
*?, +? the same, but as few as possible (lazy)
^, $ the start and end of the text (or line, with MULTILINE)
\b a word boundary
(...), (?<name>...), (?:...) a group, a named group, a group that is not captured
`a b`

matches, find and lookingAt

Java
import java.util.regex.*;

public class Main {
    public static void main(String[] args) {
        Pattern number = Pattern.compile("\\d+");
        System.out.println(number.matcher("123").matches());        // true: the whole text
        System.out.println(number.matcher("abc 123").matches());    // false
        System.out.println(number.matcher("abc 123").find());       // true: somewhere inside
        System.out.println(number.matcher("123abc").lookingAt());   // true: at the start
        System.out.println("2026".matches("\\d{4}"));               // String.matches = whole text
    }
}

Use matches for validation ("is this a postcode?") and find for searching.

Named groups

Names make complex patterns readable and survive changes in the number of groups:

Java
import java.util.regex.*;

public class Main {
    public static void main(String[] args) {
        Pattern line = Pattern.compile("(?<time>\\d{2}:\\d{2}) (?<level>INFO|WARN|ERROR) (?<msg>.*)");
        Matcher m = line.matcher("14:03 ERROR disk full");
        if (m.matches()) {
            System.out.println(m.group("level") + " at " + m.group("time") + ": " + m.group("msg"));
        }
    }
}

Every match as a stream

Matcher.results() gives a Stream<MatchResult>, which fits the stream style of lesson 6.02:

Java
import java.util.regex.*;
import java.util.stream.*;

public class Main {
    public static void main(String[] args) {
        String text = "Contact ada@example.com or bob@mail.example.org today.";
        var emails = Pattern.compile("[\\w.]+@[\\w-]+(?:\\.[\\w-]+)+")
                .matcher(text)
                .results()
                .map(MatchResult::group)
                .collect(Collectors.toList());
        System.out.println(emails);
    }
}

Replacing

replaceAll with a replacement string can refer to groups with $1 or ${name}. With a function, each match can be replaced by anything you compute:

Java
import java.util.regex.*;

public class Main {
    public static void main(String[] args) {
        String date = "2026-11-20";
        System.out.println(date.replaceAll("(\\d{4})-(\\d{2})-(\\d{2})", "$3/$2/$1"));

        Matcher m = Pattern.compile("\\$(\\d+(?:\\.\\d+)?)").matcher("tea $2.50, cake $4");
        String doubled = m.replaceAll(r -> "\\$" + String.format("%.2f", Double.parseDouble(r.group(1)) * 2));
        System.out.println(doubled);

        System.out.println("a.b.c".replace(".", "/"));          // replace (not replaceAll) takes plain text
    }
}

In a replacement string, $ and \ are special; Matcher.quoteReplacement(text) makes any text safe to use there.

Splitting

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        System.out.println(Arrays.toString("a, b,,  c".split("\\s*,\\s*")));
        System.out.println(Arrays.toString("one  two\tthree".split("\\s+")));
        System.out.println(Arrays.toString("1.2.3".split("\\.")));        // . must be escaped
        System.out.println(Arrays.toString("a,b,,".split(",")));          // trailing empty parts dropped
        System.out.println(Arrays.toString("a,b,,".split(",", -1)));      // kept with a negative limit
    }
}

Flags

Java
import java.util.regex.*;

public class Main {
    public static void main(String[] args) {
        Pattern hello = Pattern.compile("^hello$", Pattern.CASE_INSENSITIVE | Pattern.MULTILINE);
        System.out.println(hello.matcher("Hi\nHELLO\nbye").find());
        System.out.println("HeLLo".matches("(?i)hello"));            // a flag inside the pattern
    }
}

COMMENTS ((?x)) allows spaces and # comments in a pattern, which helps with long ones.

Compile once

String.matches, split and replaceAll compile the pattern on every call. In a loop, keep a private static final Pattern and reuse it.

When not to use a regex

Regular expressions are great for tokens, simple formats and searching. They are the wrong tool for nested structures (HTML, JSON, arithmetic with brackets): use a parser. And a pattern like (a+)+$ on a long string of as can take exponential time; keep patterns simple, and limit input length when the pattern comes from users.
