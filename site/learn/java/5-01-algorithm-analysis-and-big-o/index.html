Algorithm Analysis and Big O

lesson 5.011 of 5 in milestone 56 min1 practice task

How to compare algorithms independently of computers - counting basic steps, Big O notation and the common growth classes from O(1) to O(2^n), analysing loops, nested loops and halving, best, worst and average cases, the costs of Java's collection operations, measuring with System.nanoTime, and space complexity.

Counting steps

How fast is an algorithm? Timing it depends on the computer, the JVM warming up and what else is running. Instead we count how the number of basic steps grows with the size of the input, n.

Java
public class Main {
    public static void main(String[] args) {
        int[] data = new int[1000];
        for (int i = 0; i < data.length; i++) data[i] = i;
        System.out.println(contains(data, 999) + " " + hasDuplicate(data) + " " + binarySearch(data, 999));
    }

    static boolean contains(int[] a, int target) {      // up to n comparisons: O(n)
        for (int x : a) if (x == target) return true;
        return false;
    }

    static boolean hasDuplicate(int[] a) {              // about n*n/2 comparisons: O(n²)
        for (int i = 0; i < a.length; i++)
            for (int j = i + 1; j < a.length; j++)
                if (a[i] == a[j]) return true;
        return false;
    }

    static int binarySearch(int[] a, int target) {      // halves the range each step: O(log n)
        int lo = 0, hi = a.length - 1;
        while (lo <= hi) {
            int mid = (lo + hi) >>> 1;
            if (a[mid] == target) return mid;
            if (a[mid] < target) lo = mid + 1; else hi = mid - 1;
        }
        return -1;
    }
}

Big O

Big O describes the growth rate, ignoring constant factors and smaller terms: 3n² + 5n + 20 steps is O(n²), because for large n the n² term dominates everything else.

Class Name Example n = 1 000 n = 1 000 000
O(1) constant array index, HashMap.get 1 1
O(log n) logarithmic binary search 10 20
O(n) linear one loop over the data 1 000 1 000 000
O(n log n) linearithmic merge sort, Arrays.sort 10 000 20 000 000
O(n²) quadratic nested loops over the data 1 000 000 10¹² (hours)
O(2ⁿ) exponential trying every subset, naive Fibonacci 10³⁰¹ forever

The difference between O(n log n) and O(n²) is the difference between a program that sorts a million items in a fraction of a second and one that takes days.

Analysing code

  • Simple statements are O(1).
  • A loop that runs n times around O(1) work is O(n).
  • Nested loops multiply: an O(n) loop inside an O(n) loop is O(n²).
  • Sequential parts add, and the biggest wins: O(n) followed by O(n²) is O(n²).
  • A loop that halves (or doubles) its range each step is O(log n).
  • A method call costs whatever that method costs: calling an O(n) method inside an O(n) loop is O(n²).

That last rule hides many slow programs:

Java
for (String word : words) {               // n times
    if (!unique.contains(word)) {         // ArrayList.contains is O(n): the whole loop is O(n²)
        unique.add(word);
    }
}
// With a HashSet, contains is O(1) on average, and the loop is O(n).

Best, worst and average

Linear search finds the target immediately in the best case (it is first), checks everything in the worst case (it is last or missing), and about half in the average case. Big O usually describes the worst case, because that is the guarantee. Quicksort is O(n log n) on average but O(n²) in its worst case; merge sort is O(n log n) always.

Costs of Java's collections

Operation ArrayList LinkedList HashMap / HashSet TreeMap / TreeSet
get by index O(1) O(n) - -
add at the end O(1) amortised O(1) - -
insert / remove at the front O(n) O(1) - -
contains / find by key O(n) O(n) O(1) average O(log n)
add / remove by key - - O(1) average O(log n)
iterate in sorted order - - no order O(n)

"Amortised O(1)" means that occasionally an add costs O(n), when the array is full and must be copied into a bigger one, but spread over many adds the average is constant (lesson 5.04 builds such a list).

Measuring

Analysis predicts; measurement confirms. System.nanoTime() measures elapsed time:

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        for (int n : new int[] {2_000, 4_000, 8_000}) {
            List<Integer> list = new ArrayList<>();
            Set<Integer> set = new HashSet<>();
            for (int i = 0; i < n; i++) { list.add(i); set.add(i); }
            long t0 = System.nanoTime();
            int found = 0;
            for (int i = 0; i < n; i++) if (list.contains(n - 1 - i)) found++;      // O(n²) in total
            long t1 = System.nanoTime();
            for (int i = 0; i < n; i++) if (set.contains(n - 1 - i)) found++;       // O(n) in total
            long t2 = System.nanoTime();
            System.out.printf("n=%d list=%d ms set=%d ms (%d)%n", n, (t1 - t0) / 1_000_000, (t2 - t1) / 1_000_000, found);
        }
    }
}

Doubling n roughly quadruples the list time (quadratic) and roughly doubles the set time (linear). Small timings are noisy: the JVM compiles hot code while running, so measure repeatedly with large inputs, or use a benchmarking tool such as JMH.

Space

Algorithms also use memory. Making a copy of the input is O(n) extra space; a few variables are O(1); recursion uses stack space proportional to its depth (O(log n) for binary search written recursively, O(n) for a recursive sum).
