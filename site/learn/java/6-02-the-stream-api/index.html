The Stream API

lesson 6.022 of 5 in milestone 65 min1 practice task

Processing data declaratively with streams - creating streams, intermediate operations (filter, map, flatMap, sorted, distinct, limit), terminal operations (collect, toList, count, reduce, anyMatch, min, max), primitive streams and summary statistics, Collectors for grouping, partitioning, joining and mapping, laziness, and when a loop is clearer.

A pipeline

A stream is a sequence of values flowing through a pipeline of operations. It describes what to compute, not how to loop:

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<String> words = List.of("stream", "lambda", "java", "list", "map", "filter", "java");
        List<String> result = words.stream()
            .filter(w -> w.length() > 3)          // keep some
            .map(String::toUpperCase)             // transform each
            .distinct()                           // drop repeats
            .sorted()                             // order
            .toList();                            // collect (Java 16+)
        System.out.println(result);
        System.out.println(words.stream().filter(w -> w.startsWith("l")).count());
    }
}

A pipeline has a source (list.stream(), Arrays.stream(array), Stream.of(...), IntStream.range(0, 10), Files.lines(path)), any number of intermediate operations that return a new stream, and one terminal operation that produces a result.

Intermediate Does
filter(pred) Keeps matching items
map(f), mapToInt(f) Transforms each item
flatMap(f) Replaces each item by a stream of items, flattened
distinct(), sorted(), sorted(cmp) Removes repeats, sorts
limit(n), skip(n), takeWhile(p), dropWhile(p) Cuts the stream
peek(f) Looks at items as they pass (for debugging)
Terminal Gives
toList(), collect(...) A collection
forEach(f) Runs f on each item
count(), sum(), average(), min(), max() Numbers (some as Optional)
anyMatch, allMatch, noneMatch Booleans
findFirst(), findAny() An Optional item
reduce(identity, op) Combines all items into one

Numbers

IntStream, LongStream and DoubleStream have arithmetic built in:

Java
import java.util.*;
import java.util.stream.*;

public class Main {
    public static void main(String[] args) {
        System.out.println(IntStream.rangeClosed(1, 100).sum());
        System.out.println(IntStream.rangeClosed(1, 10).filter(n -> n % 2 == 0).map(n -> n * n).boxed().toList());
        int[] scores = {72, 95, 88, 61, 79};
        IntSummaryStatistics stats = Arrays.stream(scores).summaryStatistics();
        System.out.println(stats.getMin() + " " + stats.getMax() + " " + stats.getAverage());
        System.out.println(Stream.of("a", "bb", "ccc").mapToInt(String::length).sum());
        System.out.println(Stream.iterate(1, x -> x * 2).limit(10).reduce(0, Integer::sum));
    }
}

Collectors

collect with the Collectors helpers builds maps, groups and strings:

Java
import java.util.*;
import java.util.stream.*;

public class Main {
    public static void main(String[] args) {
        List<Person> people = List.of(
            new Person("Ada", "London", 36), new Person("Grace", "New York", 85),
            new Person("Linus", "Helsinki", 55), new Person("Alan", "London", 41));

        Map<String, List<String>> byCity = people.stream()
            .collect(Collectors.groupingBy(Person::city, TreeMap::new, Collectors.mapping(Person::name, Collectors.toList())));
        System.out.println(byCity);

        Map<String, Long> countByCity = people.stream().collect(Collectors.groupingBy(Person::city, Collectors.counting()));
        System.out.println(new TreeMap<>(countByCity));

        Map<Boolean, List<String>> over50 = people.stream()
            .collect(Collectors.partitioningBy(p -> p.age() > 50, Collectors.mapping(Person::name, Collectors.toList())));
        System.out.println(over50);

        String names = people.stream().map(Person::name).sorted().collect(Collectors.joining(", ", "[", "]"));
        double avgAge = people.stream().collect(Collectors.averagingInt(Person::age));
        Map<String, Integer> ageByName = people.stream().collect(Collectors.toMap(Person::name, Person::age));
        Optional<Person> oldest = people.stream().max(Comparator.comparingInt(Person::age));
        System.out.println(names + " " + avgAge + " " + ageByName.get("Linus") + " " + oldest.map(Person::name).orElse("-"));
    }
}

record Person(String name, String city, int age) { }

toMap throws if two items have the same key; pass a merge function as a third argument to combine them.

flatMap

Java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<String> lines = List.of("the quick brown fox", "jumps over", "the lazy dog");
        List<String> words = lines.stream()
            .flatMap(line -> Arrays.stream(line.split(" ")))      // each line becomes many words
            .distinct()
            .toList();
        System.out.println(words.size() + " " + words);
    }
}

Laziness

Intermediate operations do nothing until a terminal operation runs, and then items flow through one at a time. That allows infinite sources with limit, and lets findFirst stop early. A stream can be used once; calling a second terminal operation on it throws IllegalStateException.

Stream lambdas should not change shared state (no adding to an outside list in map); use collectors instead. parallelStream() splits work across cores, but only helps for large, CPU-heavy, side-effect-free pipelines.

Streams or loops?

Streams shine for transform-filter-collect pipelines and grouping. A plain loop is often clearer when you need indexes, early exits with complex conditions, checked exceptions, or several results at once. Use whichever reads better.
