Interfaces and Abstract Classes

lesson 3.044 of 5 in milestone 35 min1 practice task

Abstract classes and abstract methods, interfaces as contracts, implementing several interfaces, default and static interface methods, programming to an interface, the built-in Comparable and Iterable, functional interfaces as a preview of lambdas, and choosing between an interface and an abstract class.

Abstract classes

An abstract class cannot be instantiated. It holds shared code and declares abstract methods, without bodies, that every concrete subclass must implement:

Java
public class Main {
    public static void main(String[] args) {
        Shape[] shapes = {new Circle(1), new Rectangle(2, 3), new Circle(0.5)};
        double total = 0;
        for (Shape s : shapes) {
            System.out.println(s.describe());
            total += s.area();
        }
        System.out.printf("Total area: %.2f%n", total);
        // new Shape("x");          // error: Shape is abstract; cannot be instantiated
    }
}

abstract class Shape {
    private final String name;

    protected Shape(String name) { this.name = name; }

    abstract double area();                   // no body: subclasses must provide it

    String describe() { return String.format("%s with area %.2f", name, area()); }   // shared code
}

class Circle extends Shape {
    private final double r;
    Circle(double r) { super("circle"); this.r = r; }
    @Override double area() { return Math.PI * r * r; }
}

class Rectangle extends Shape {
    private final double w, h;
    Rectangle(double w, double h) { super("rectangle"); this.w = w; this.h = h; }
    @Override double area() { return w * h; }
}

Interfaces

An interface is a contract: a list of methods a class promises to provide. A class implements any number of interfaces:

Java
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Notifier> channels = List.of(new EmailNotifier("ada@example.com"), new SmsNotifier("+3161234"));
        for (Notifier n : channels) {
            if (n.isAvailable()) n.send("Your order has shipped");
        }
        Notifier quiet = new EmailNotifier("not-an-address");
        quiet.sendAll(List.of("a", "b"));      // a default method
    }
}

interface Notifier {
    boolean isAvailable();
    void send(String message);

    default void sendAll(List<String> messages) {       // a default method: implementers get it for free
        if (!isAvailable()) {
            System.out.println("not available");
            return;
        }
        for (String m : messages) send(m);
    }
}

class EmailNotifier implements Notifier {
    private final String address;
    EmailNotifier(String address) { this.address = address; }
    public boolean isAvailable() { return address.contains("@"); }
    public void send(String message) { System.out.println("email to " + address + ": " + message); }
}

class SmsNotifier implements Notifier {
    private final String number;
    SmsNotifier(String number) { this.number = number; }
    public boolean isAvailable() { return number.startsWith("+"); }
    public void send(String message) { System.out.println("sms to " + number + ": " + message); }
}

Interface methods are public automatically, so implementing methods must be public too. Interfaces can also have static methods and constants, but no instance fields.

Program to an interface

Declare variables and parameters with interface types (List, Notifier), and create concrete classes (ArrayList, SmsNotifier) in one place. Code that depends only on the interface works with any implementation, including test fakes, and the implementation can change without touching it.

Built-in interfaces

Comparable<T> gives a class a natural order, used by Collections.sort, Arrays.sort, TreeSet and TreeMap:

Java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Version> versions = new ArrayList<>(List.of(new Version(1, 10), new Version(1, 2), new Version(0, 9)));
        Collections.sort(versions);
        System.out.println(versions);
    }
}

class Version implements Comparable<Version> {
    private final int major, minor;
    Version(int major, int minor) { this.major = major; this.minor = minor; }

    @Override
    public int compareTo(Version other) {          // negative, zero or positive
        if (major != other.major) return Integer.compare(major, other.major);
        return Integer.compare(minor, other.minor);
    }

    @Override
    public String toString() { return major + "." + minor; }
}

Other everyday interfaces: Iterable<T> (usable in an enhanced for), Comparator<T> (an external ordering, lesson 4.03), Runnable (a task for a thread, lesson 6.04), and AutoCloseable (try-with-resources, lesson 4.05).

An interface with exactly one abstract method is a functional interface; a lambda can implement it in one line (lesson 6.01): Comparator<String> byLength = (a, b) -> a.length() - b.length();

Interface or abstract class?

Interface Abstract class
A capability that unrelated classes share (Comparable, Notifier) A family of closely related classes sharing code and state (Shape)
A class can implement many A class can extend only one
No instance fields Fields and constructors

Prefer interfaces; reach for an abstract class when subclasses really share state and code. Often both: an interface for the contract and an abstract class with a partial implementation.
