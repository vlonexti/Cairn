Memory Is a Row of Bytes

lesson 1.011 of 5 in milestone 15 min1 practice task

A program's memory is one long row of bytes, each with a number called its address. Every variable occupies a few of those bytes, sizeof says how many, and & gives the address of the first one. Addresses are written in hexadecimal and change from run to run.

One long row

Everything a running program works with, its variables, its strings, its arrays, even its own machine code, sits in memory. To the program, memory looks like one very long row of bytes. Each byte holds a number from 0 to 255, and each byte has its own number too: its address.

Text
address   0x1000  0x1001  0x1002  0x1003  0x1004  0x1005  0x1006  0x1007
value       2A      00      00      00      48      69      00      FF

That is the whole model. There are no "variables" in memory, no types, no names: only bytes with addresses. Variables, types and names are how your code decides to read those bytes.

A variable is a few bytes

When you write int score{ 42 };, the compiler sets aside a few bytes somewhere in that row and agrees with itself that those bytes are score. How many bytes depends on the type, and sizeof tells you:

C++
#include <iostream>

int main()
{
    std::cout << "char:      " << sizeof(char) << '\n';
    std::cout << "short:     " << sizeof(short) << '\n';
    std::cout << "int:       " << sizeof(int) << '\n';
    std::cout << "long long: " << sizeof(long long) << '\n';
    std::cout << "float:     " << sizeof(float) << '\n';
    std::cout << "double:    " << sizeof(double) << '\n';
    std::cout << "int*:      " << sizeof(int*) << '\n';
}

On a 64-bit Windows program you get 1, 2, 4, 8, 4, 8 and 8. char is 1 by definition; the others are set by the platform, which is why code that cares uses the fixed-width types from <cstdint>: std::uint8_t, std::int32_t, std::uint64_t and friends always have the size in their name.

The last line matters for this whole course: an address is itself a number that takes 8 bytes in a 64-bit program, whatever it points at.

& gives an address

The & operator in front of a variable gives the address of its first byte:

C++
#include <iostream>

int main()
{
    int score{ 42 };
    double ratio{ 0.75 };
    char grade{ 'A' };

    std::cout << "score is at " << &score << " and takes " << sizeof(score) << " bytes\n";
    std::cout << "ratio is at " << &ratio << " and takes " << sizeof(ratio) << " bytes\n";
    std::cout << "grade is at " << static_cast<void*>(&grade) << '\n';
}

Two things to notice:

  • Addresses are printed in hexadecimal, because a 64-bit address in decimal is a long unreadable number. 0x000000E5B1AFF8A4 is easier to compare by eye than 986 316 798 116.
  • For grade we had to cast to void*. std::cout treats a char* as the start of a text string and would try to print characters from that address until it found a zero byte. void* means "just an address", and prints as one.

Run it twice and the addresses change. Windows places the stack, the heap and the program itself at a random position every time it starts (address space layout randomisation, ASLR), so a bug cannot rely on a fixed address. The distances between your variables usually stay the same; the starting point moves.

Bigger values span several bytes

A 4-byte int occupies four consecutive addresses, and &score is the address of the lowest of them. Which byte holds which part of the number is the byte order. Every x86 and ARM computer you will use is little-endian: the least significant byte comes first.

So the int 0x12345678 is stored as 78 56 34 12. This looks backwards on paper and is completely natural to the processor: the byte at the variable's address is always the lowest part, whatever the size.

Looking at the bytes

You can look at any object's bytes with a pointer to unsigned char, the one type C++ guarantees may view the bytes of anything. Pointers are the next lesson, so for now read this as "start at the object's address and read one byte at a time":

C++
#include <cstdio>

int main()
{
    int value{ 0x12345678 };
    const unsigned char* bytes{ reinterpret_cast<const unsigned char*>(&value) };
    for (int i{ 0 }; i < static_cast<int>(sizeof(value)); ++i)
        std::printf("byte %d: %02X\n", i, bytes[i]);
}

It prints 78, 56, 34, 12. You will write a full hex dump of any object in this milestone's project.

Tip

A debugger's Memory window shows exactly this row of bytes. In Visual Studio, while stopped at a breakpoint, open Debug > Windows > Memory > Memory 1 and type &score in the address box. Watching the bytes change as you step is the fastest way to build a picture of memory.
