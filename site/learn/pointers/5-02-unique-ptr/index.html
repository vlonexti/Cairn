unique_ptr

lesson 5.022 of 5 in milestone 55 min1 practice task

std::unique_ptr is a pointer that owns its object and deletes it when it goes away. It cannot be copied, only moved, so ownership is written in the type. make_unique, get, release and reset, unique_ptr in containers and as return values, and custom deleters for FILE*, HANDLE and anything else.

Ownership in the type

std::unique_ptr<T> (from <memory>) is RAII for one heap object. It holds a pointer and deletes it in its destructor:

C++
#include <memory>

{
    std::unique_ptr<Enemy> boss{ std::make_unique<Enemy>("Golem", 500) };
    boss->attack();               // used like a pointer
    Enemy& e{ *boss };
}                                 // boss deleted here, automatically

std::make_unique<T>(args...) does the new for you and passes the arguments to the constructor. You never write new or delete yourself.

A unique_ptr is the same size as a raw pointer and compiles to the same code; using it costs nothing at run time.

It can be moved, not copied

There is exactly one owner, so a unique_ptr cannot be copied. That is the whole point: the compiler now enforces lesson 4.04's rule.

C++
std::unique_ptr<Enemy> a{ std::make_unique<Enemy>() };
std::unique_ptr<Enemy> b{ a };              // error: copying is deleted
std::unique_ptr<Enemy> c{ std::move(a) };   // fine: ownership moves to c, a is now empty (nullptr)

Moving transfers ownership, and the source is left holding nullptr. Ownership transfers that lesson 4.04 could only describe in comments are now visible in the code:

C++
std::unique_ptr<Texture> loadTexture(const char* path);         // the caller receives ownership
void Level::adopt(std::unique_ptr<Enemy> enemy);                // the level takes ownership
level.adopt(std::move(enemy));                                  // and the call site shows it

Returning a unique_ptr from a function needs no std::move; returning a local moves it automatically.

Getting at the pointer

Call Does
p.get() returns the raw pointer, still owned by p (for borrowing)
p.reset() deletes the object now and leaves p empty
p.reset(q) deletes the old object and takes ownership of raw pointer q
p.release() gives up ownership without deleting: returns the raw pointer, and you must free it
if (p) true when it holds an object

get() is how you pass the object to a function that only borrows it: draw(boss.get()), or better draw(*boss) with a reference parameter. release() is rare; it is for handing ownership to code that only understands raw pointers.

Watch out

Never create two unique_ptrs from the same raw pointer, and never delete what get() returned. Both mean two owners.

In containers

std::vector<std::unique_ptr<Enemy>> owns its enemies: removing an element deletes that enemy, and destroying the vector deletes them all. That replaces the hand-written destructor of lesson 4.04's Level:

C++
class Level
{
public:
    Enemy* spawn()
    {
        enemies.push_back(std::make_unique<Enemy>());
        return enemies.back().get();          // borrowed pointer for the caller
    }
private:
    std::vector<std::unique_ptr<Enemy>> enemies;   // no destructor needed
};

And because a unique_ptr cannot be copied, the class automatically becomes non-copyable but movable, which is exactly right.

Arrays

std::unique_ptr<int[]> buffer{ std::make_unique<int[]>(1000) }; owns an array and uses delete[], with buffer[i] for indexing. In practice std::vector is almost always better; the array form is for interfacing with code that wants a raw buffer.

Custom deleters

Not everything is freed with delete. A unique_ptr can call any function instead, given as a second template argument. The neatest way is a small struct:

C++
struct CloseFile { void operator()(std::FILE* f) const { std::fclose(f); } };
using FilePtr = std::unique_ptr<std::FILE, CloseFile>;

FilePtr file{ std::fopen("save.dat", "rb") };    // fclose runs automatically
if (!file) return false;
std::fread(buffer, 1, size, file.get());

The same pattern wraps any C or Windows resource:

C++
struct CloseHandleDeleter { void operator()(HANDLE h) const { if (h && h != INVALID_HANDLE_VALUE) CloseHandle(h); } };
using UniqueHandle = std::unique_ptr<void, CloseHandleDeleter>;   // HANDLE is a void*

struct LocalFreeDeleter { void operator()(void* p) const { LocalFree(p); } };

Because the deleter struct is empty, the unique_ptr stays the size of one pointer.
