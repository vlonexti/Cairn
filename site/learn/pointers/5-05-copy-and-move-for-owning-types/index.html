Copy and Move for Owning Types

lesson 5.055 of 5 in milestone 55 min1 practice task

A class that owns memory must decide what copying and moving mean. The rule of five, a deep copy, a move that steals the pointer and leaves the source empty, copy-and-swap for safe assignment, self-assignment, and the rule of zero - letting members that already own do it all.

The default copy is a shallow copy

Here is a minimal owning buffer:

C++
class Buffer
{
public:
    explicit Buffer(std::size_t n) : data{ new int[n]{} }, size{ n } {}
    ~Buffer() { delete[] data; }
private:
    int* data;
    std::size_t size;
};

The compiler writes a copy constructor for it automatically, copying each member. Copying data copies the address, so two Buffers end up owning one array, and the second destructor deletes it again. A class that owns a resource must write, or delete, the special member functions itself.

The rule of five

A class that needs a destructor almost certainly needs all five of these:

Function Called when
destructor ~Buffer() the object dies
copy constructor Buffer(const Buffer&) a new object is made as a copy
copy assignment operator=(const Buffer&) an existing object is overwritten with a copy
move constructor Buffer(Buffer&&) noexcept a new object takes over a temporary or std::moved one
move assignment operator=(Buffer&&) noexcept an existing object takes over another

Deep copy

A copy that makes its own array and copies the values:

C++
Buffer(const Buffer& other) : data{ new int[other.size] }, size{ other.size }
{
    std::copy(other.data, other.data + other.size, data);
}

Now each Buffer owns its own memory, and the destructors never collide.

Move: steal the pointer

Copying a large buffer just to destroy the original straight away (returning from a function, putting a temporary into a vector) is wasteful. A move takes the other object's pointer and leaves it empty:

C++
Buffer(Buffer&& other) noexcept : data{ other.data }, size{ other.size }
{
    other.data = nullptr;     // the source must no longer own it
    other.size = 0;
}

No allocation, no copying of elements: two pointer assignments. The moved-from object must stay valid but empty, because its destructor still runs (and delete[] nullptr is harmless).

Mark moves noexcept. std::vector only moves its elements when it grows if their move cannot throw; otherwise it copies them to stay safe, and all the benefit is lost.

Assignment with copy-and-swap

Assignment must release what the object already owns, copy the new contents, and survive a = a. Written by hand it is easy to get wrong. The copy-and-swap idiom does it in two lines:

C++
friend void swap(Buffer& a, Buffer& b) noexcept
{
    std::swap(a.data, b.data);
    std::swap(a.size, b.size);
}

Buffer& operator=(Buffer other) noexcept   // taken BY VALUE: copied or moved in by the caller
{
    swap(*this, other);                    // take its contents; give it ours
    return *this;                          // other's destructor frees our old memory
}

Taking the parameter by value means the compiler copies or moves into it as appropriate, so this one function serves as both copy and move assignment. If the copy throws (out of memory), it throws before *this is touched, so the object is never left half-assigned. And a = a simply copies and swaps, harmlessly.

The rule of zero

All of that is how std::vector and std::unique_ptr are written, and that is the point: if every member manages itself, the class needs none of the five. Write Buffer with a vector and the compiler's defaults are all correct:

C++
class Buffer
{
public:
    explicit Buffer(std::size_t n) : data(n) {}
private:
    std::vector<int> data;      // copy, move and destroy are all handled
};

A class holding a std::unique_ptr member is automatically movable and not copyable; one holding std::shared_ptr copies by sharing. So the practical rule is:

  • Rule of zero for ordinary classes: no destructor, no copy or move functions; members own.
  • Rule of five only in the small number of classes whose job is to own one raw resource, so that everything else can follow the rule of zero.
