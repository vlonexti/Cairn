Dereferencing

lesson 1.033 of 5 in milestone 15 min1 practice task

The * operator follows a pointer to the object at its address, to read it or to write it. Two pointers to one object see each other's writes. The -> operator reaches a member through a pointer, and const can protect either the pointer or the value it points at.

Following the address

* in front of a pointer means "the object at this address". This is called dereferencing:

C++
#include <iostream>

int main()
{
    int score{ 42 };
    int* p{ &score };

    std::cout << *p << '\n';   // read through p: 42
    *p = 100;                  // write through p
    std::cout << score << '\n';  // 100: score itself changed
    *p += 5;
    std::cout << score << '\n';  // 105
}

*p is not a copy of score. It is score, reached by its address. Anything you can do to score, you can do to *p.

The star now has two jobs, and context tells them apart:

Where Meaning
In a declaration: int* p p is a pointer to int
In an expression: *p the int that p points at

& and * undo each other: *&score is score, and &*p is p.

Two names for one object

When two pointers hold the same address, a write through one is seen through the other. Programmers call this aliasing:

C++
#include <iostream>

int main()
{
    int health{ 100 };
    int* shown{ &health };     // what the health bar reads
    int* damage{ &health };    // what the combat code changes

    *damage -= 30;
    std::cout << *shown << '\n';   // 70: same object
}

This is the main reason pointers exist: several parts of a program can work on one object instead of each holding its own copy.

Arrows for members

For a pointer to a struct or class, (*p).member reaches a member. The brackets are needed because . binds tighter than *, and that is ugly enough that C++ has a shorthand: p->member.

C++
#include <iostream>
#include <string>

struct Player
{
    std::string name;
    int health;
};

int main()
{
    Player hero{ "Ada", 100 };
    Player* p{ &hero };

    (*p).health -= 10;   // works
    p->health -= 10;     // the same, and what everyone writes
    std::cout << p->name << " has " << p->health << '\n';   // Ada has 80
}

Dereferencing nullptr

A pointer holding nullptr points at no object, so *p has nothing to reach. On Windows reading address 0 makes the processor raise an access violation and the program is stopped:

C++
int* p{ nullptr };
*p = 5;   // crash: Exception thrown: write access violation. p was nullptr.

So code that might receive nullptr must check first: if (p) *p = 5;. Lesson 1.05 covers this and the other kinds of bad pointer in detail.

const and pointers

A pointer involves two things that could be read-only: the object it points at, and the pointer variable itself. const can protect either, depending on which side of the star it sits:

C++
int score{ 42 };
int other{ 7 };

const int* a{ &score };   // pointer to const int: *a = 1 is an error, a = &other is fine
int* const b{ &score };   // const pointer to int: *b = 1 is fine, b = &other is an error
const int* const c{ &score };  // neither can change

Read right to left: int* const b is "b is a const pointer to int"; const int* a is "a is a pointer to an int that is const".

The first form, pointer to const, is the one you use all the time. A function that only reads through a pointer takes const T*, which both documents and enforces that it will not change the caller's object.

Note

const int* does not make score constant. score can still be changed directly or through another pointer. It only means this pointer is not allowed to change it.
