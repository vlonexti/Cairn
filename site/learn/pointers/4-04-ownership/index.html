Ownership

lesson 4.044 of 5 in milestone 45 min1 practice task

Every heap object needs exactly one owner responsible for freeing it; every other pointer to it only borrows. Owning versus borrowing pointers, transferring ownership, who frees what across a function or library boundary, and writing ownership down so the next reader does not have to guess.

Somebody has to free it

The heap does not know when an object is no longer needed, so the program must decide, and one part of the program must actually call delete. That part is the object's owner. Every other piece of code that holds a pointer to the object is a borrower: it may use the object, but must not free it and must not use it after the owner does.

C++
class Level
{
public:
    ~Level() { for (Enemy* e : enemies) delete e; }   // the Level owns its enemies
    Enemy* spawn() { enemies.push_back(new Enemy{}); return enemies.back(); }
private:
    std::vector<Enemy*> enemies;
};

Enemy* target{ level.spawn() };   // the caller borrows: it must not delete target

Nothing in the type Enemy* says whether a given pointer owns or borrows. Both are just addresses. That is the root of most memory bugs:

If two places think they own it If nobody thinks they own it
both delete: a double free nobody deletes: a leak
one deletes while the other still uses it: use after free

The rule

Every heap object has exactly one owner at any moment, and the owner frees it exactly once.

Borrowers must not outlive what they borrow. In practice that means a borrowed pointer is used inside one call, or stored only by something that is guaranteed to be destroyed first.

Transferring ownership

Ownership can move. A function that creates an object and returns a raw pointer usually hands ownership to the caller:

C++
// Returns a new Texture. The caller owns it and must delete it.
Texture* loadTexture(const char* path);

Ownership can also be handed in:

C++
// Takes ownership of `enemy`: the level will delete it.
void Level::adopt(Enemy* enemy);

And a function can take an object out of a container and give it away:

C++
// Removes the enemy from the level and returns it. The caller now owns it.
Enemy* Level::release(Enemy* enemy);

With raw pointers, the only place these facts are recorded is the comment. Milestone 5's std::unique_ptr puts them in the type, so the compiler enforces them; for now, every function that deals in owning pointers must say which way ownership goes.

Across a library boundary

C libraries and the Windows API each follow a documented convention, and reading the documentation for it is part of using any function that returns memory:

  • Caller allocates, callee fills: you pass a buffer and its size (GetModuleFileNameW(nullptr, buffer, size)). You own the buffer throughout.
  • Callee allocates, caller frees with a named function: FormatMessageW with FORMAT_MESSAGE_ALLOCATE_BUFFER gives you text you must free with LocalFree; CommandLineToArgvW gives an array you free with LocalFree; SHGetKnownFolderPath gives a path you free with CoTaskMemFree.
  • Callee keeps ownership: getenv returns a pointer into the environment that you must not free; GetCommandLineW returns a pointer you must not free.

Freeing with the wrong function, or freeing something you only borrowed, is undefined. When the documentation says "the caller must free this with X", that is the ownership rule written down.

Containers own their elements

A std::vector<Enemy> owns its Enemy objects outright: destroying the vector destroys them. A std::vector<Enemy*> owns only the pointers; destroying it frees nothing they point at. That is why the Level above needed its own destructor, and why the next milestone replaces std::vector<Enemy*> with std::vector<std::unique_ptr<Enemy>>.

Copies and ownership

A class that owns a raw pointer has a trap: the default copy constructor copies the pointer, so two objects now "own" one block, and both destructors delete it.

C++
Level a;
Level b{ a };      // b.enemies holds the same pointers as a.enemies
// end of scope: b deletes every enemy, then a deletes them again

Until milestone 5 shows how to copy or move properly, a class that owns raw pointers should forbid copying: Level(const Level&) = delete; Level& operator=(const Level&) = delete;.
