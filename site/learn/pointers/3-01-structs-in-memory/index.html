Structs in Memory

lesson 3.011 of 5 in milestone 35 min1 practice task

A struct's members sit at fixed offsets from its start, in the order they are declared, with padding added so each member is suitably aligned. offsetof gives a member's offset, the arrow operator is "base address plus offset", and reordering members can make a struct smaller.

Members at fixed offsets

A struct is a block of memory with its members placed one after another in declaration order. Each member sits at a fixed distance from the start of the struct: its offset. That offset is the same for every object of that type, which is what makes p->member cheap: it is the address in p plus a number the compiler already knows.

C++
#include <cstddef>
#include <cstdio>

struct Enemy
{
    int id;          // offset 0
    float x, y;      // offsets 4 and 8
    int health;      // offset 12
};

int main()
{
    std::printf("id %zu, x %zu, y %zu, health %zu, size %zu\n",
                offsetof(Enemy, id), offsetof(Enemy, x), offsetof(Enemy, y),
                offsetof(Enemy, health), sizeof(Enemy));
}

It prints offsets 0, 4, 8, 12 and a size of 16. offsetof (from <cstddef>) is how you ask the compiler for a member's offset.

So enemy->health compiles to "take the address in enemy, add 12, read 4 bytes". If enemy holds 0x2000, the health is the int at 0x200C. Debuggers, memory viewers and anything that reads a struct out of a file or a packet think exactly like this.

Alignment and padding

The processor reads a 4-byte value fastest when its address is a multiple of 4, and an 8-byte value when its address is a multiple of 8. Each type has an alignment: the number its address must be a multiple of. For the basic types the alignment equals the size: 1 for char, 4 for int and float, 8 for double, long long and pointers.

To keep every member aligned, the compiler inserts unused padding bytes:

C++
struct Pickup
{
    char kind;       // offset 0, then 7 bytes of padding
    double expires;  // offset 8 (must be a multiple of 8)
    int amount;      // offset 16
    bool active;     // offset 20, then 3 bytes of padding
};                   // size 24

Two rules produce every layout:

  1. Each member goes at the next offset that is a multiple of its alignment.
  2. The struct's size is rounded up to a multiple of its largest member alignment, so that in an array every element's members stay aligned too.

That trailing padding is why sizeof(Pickup) is 24 and not 21.

Ordering to save space

Declaring the largest members first removes most of the padding:

C++
struct PickupSorted
{
    double expires;  // 0
    int amount;      // 8
    char kind;       // 12
    bool active;     // 13, then 2 bytes of padding
};                   // size 16

A third smaller with the same data. For one object it does not matter; for a million particles in an array it is 8 MB less memory and fewer cache lines to read. Lots of game code sorts members by size for exactly this reason.

Note

Padding bytes are real bytes with unspecified contents. Writing a struct straight to a file or a socket writes the padding too, which can leak whatever was in that memory. Compare structs member by member, not with memcmp, for the same reason.

Nested structs and arrays in structs

A member that is itself a struct is placed whole, aligned to its own largest member. An array member is its elements in a row. Offsets add up:

C++
struct Vec3 { float x, y, z; };          // size 12, alignment 4
struct Transform
{
    Vec3 position;     // 0..11
    Vec3 scale;        // 12..23
    float yaw;         // 24
};
// offsetof(Transform, scale) + offsetof(Vec3, y) == 16: transform.scale.y lives 16 bytes in

Through a byte pointer

Because a member is just "base plus offset", you can reach one through a byte pointer:

C++
Enemy e{ 7, 1.0f, 2.0f, 50 };
unsigned char* base{ reinterpret_cast<unsigned char*>(&e) };
int health;
std::memcpy(&health, base + offsetof(Enemy, health), sizeof(health));   // 50

You would not write this for a struct you can name; e.health is clearer. It matters when the layout is only known as numbers: a file format, a packet, a structure documented as "the health is at offset 0x0C". The next lessons follow chains of such offsets.

Classes are the same

A class with private members is laid out the same way. A class with virtual functions has one extra hidden member at offset 0: a pointer to its table of functions, the vtable pointer (lesson 3.05). So a class with virtual functions and one int is 16 bytes on 64-bit: 8 for the hidden pointer, 4 for the int, 4 of padding.
