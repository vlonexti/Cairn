Linked Structures

lesson 3.044 of 5 in milestone 35 min1 practice task

Data structures held together by pointers - singly and doubly linked lists, a sentinel node that removes the special cases, trees - what they cost in memory and speed compared with an array, and the intrusive lists that games and operating systems use.

Nodes that point at nodes

An array keeps its elements side by side. A linked structure keeps each element in its own block, a node, and links the nodes with pointers:

C++
struct Node
{
    int value;
    Node* next;      // the following node, or nullptr at the end
};
Text
head
 |
 v
[ 4 | *]--->[ 9 | *]--->[ 2 | nullptr ]

The list is reached through one pointer, head. Walking it is a pointer that follows next until it meets nullptr:

C++
for (Node* n{ head }; n != nullptr; n = n->next)
    std::cout << n->value << '\n';

What linking buys

Inserting or removing in the middle of an array moves every element after it. In a linked list it changes two or three pointers, however long the list is:

C++
// insert value after node `at`
Node* fresh{ new Node{ value, at->next } };
at->next = fresh;

And a node never moves, so a pointer to it stays valid while other nodes come and go. That is the property that matters most in practice: a std::vector invalidates pointers into it when it grows; a list never does.

What it costs

  • Memory. Every node carries a pointer (two in a doubly linked list) and is a separate heap block with the allocator's own bookkeeping. A list of ints can easily use 32 bytes per 4-byte value.
  • Speed. The nodes are scattered around the heap. Walking a list jumps from address to address, and each jump is likely a cache miss: the processor waits for main memory every step. Walking a std::vector of the same values runs from one cache line to the next and is often ten or more times faster.
  • No indexing. Reaching the 500th element means following 499 pointers.

So the default in C++ is std::vector. Linked structures earn their place when nodes must not move, when items are inserted and removed constantly in the middle of very long sequences, or when the structure itself is naturally a graph of objects.

Doubly linked, with a sentinel

A node with both next and prev can be removed knowing only its own address, and the list can be walked both ways. The neatest version keeps one extra sentinel node that is not an element at all: the list is a ring through it.

Text
      +-------------------------------------------+
      v                                           |
 [sentinel] <-> [ 4 ] <-> [ 9 ] <-> [ 2 ] <-------+

An empty list is the sentinel pointing at itself. Every real node always has a real prev and next (possibly the sentinel), so insert and remove have no nullptr checks and no special cases:

C++
void unlink(Node* n)
{
    n->prev->next = n->next;
    n->next->prev = n->prev;
}

void insertBefore(Node* where, Node* n)
{
    n->prev = where->prev;
    n->next = where;
    where->prev->next = n;
    where->prev = n;
}

std::list is built this way.

Intrusive lists

In a game engine or an operating system kernel, the links are often stored inside the objects themselves, instead of in separate nodes that point at them:

C++
struct Enemy
{
    Enemy* nextActive;    // the list of enemies that need updating this frame
    Enemy* prevActive;
    float x, y;
    int health;
};

No extra allocation per list entry, and from an object you can unlink it directly. The Windows kernel's LIST_ENTRY is this pattern: a struct with Flink and Blink embedded in hundreds of kernel structures, with a macro (CONTAINING_RECORD) that subtracts the member's offset to get back from the links to the object around them. That is lesson 3.01's offsets in reverse.

Trees

A node with two child pointers instead of one next makes a binary tree; a node with a vector of child pointers makes a general tree. A game's scene graph, a file system, a parsed program and a UI layout are all trees of nodes linked by pointers. The same rules apply: whoever creates the nodes must free them, and a parent's destructor usually frees its children.
