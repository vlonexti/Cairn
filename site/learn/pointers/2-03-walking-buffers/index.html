Walking Buffers

lesson 2.033 of 5 in milestone 25 min1 practice task

Loops that move a pointer instead of an index, begin and end pointers as in the standard library, C strings as pointers to a run of chars ending in zero, and the classic string functions written by hand.

Index loops and pointer loops

Here is the same loop written two ways:

C++
// with an index
for (int i{ 0 }; i < count; ++i) total += values[i];

// with a moving pointer
for (const int* p{ values }; p != values + count; ++p) total += *p;

Both compile to nearly the same machine code today. The pointer version is worth knowing because the whole standard library is built on it: every algorithm takes a begin and an end, and works by moving the first towards the second.

C++
std::sort(values, values + count);              // plain pointers work as iterators
auto it{ std::find(values, values + count, 64) };

Begin and end

A function that takes a range as two pointers needs no count at all:

C++
#include <iostream>

const int* findValue(const int* begin, const int* end, int wanted)
{
    for (const int* p{ begin }; p != end; ++p)
        if (*p == wanted) return p;
    return end;                     // "not found" is the end pointer
}

int main()
{
    const int values[]{ 7, 3, 9, 3, 1 };
    const int* found{ findValue(values, values + 5, 9) };
    if (found != values + 5)
        std::cout << "9 is at index " << (found - values) << '\n';   // 2
}

Returning end for "not found" is the standard library's convention. It avoids a separate success flag and keeps the result a valid position in the range. A sub-range is free: findValue(values + 2, values + 5, 3) searches only the last three elements.

C strings

A C string is an array of char ending in a zero byte, written '\0'. There is no length stored anywhere; the zero marks the end. A string literal "cat" is 4 bytes: c, a, t, \0.

Text
 'c'  'a'  't'  '\0'
 63   61   74   00

So a const char* to a C string is a begin pointer, and the end is found by walking:

C++
std::size_t length(const char* s)
{
    const char* p{ s };
    while (*p != '\0') ++p;
    return static_cast<std::size_t>(p - s);
}

Every C string function works like this: copy, compare and search all walk until they meet the zero.

C++
char* copy(char* destination, const char* source)
{
    char* out{ destination };
    while ((*out++ = *source++) != '\0') {}   // copy each char, including the final zero
    return destination;
}

That one-line loop is famous. Read it slowly: copy the char at source into out, move both on, stop when the char just copied was the zero. It is also famous for being dangerous: it has no idea how big destination is.

Danger

strcpy and friends write until the source's zero byte, however far that is. If the destination is smaller, they write past its end into whatever follows. That single mistake was behind a large share of security holes for decades. Use std::string, or the size-checked versions (strcpy_s, strncpy with care, std::string_view for reading).

Why std::string still matters here

std::string stores its own length and keeps a zero after the last character, so s.c_str() and s.data() give a valid C string for C APIs. Lots of Windows and C library functions take const char* or const wchar_t*, so you pass .c_str(), and that pointer is valid only as long as the string is alive and unchanged.

C++
const char* name{ std::string("temporary").c_str() };   // dangles at the end of the line

Two pointers at once

Some algorithms walk two pointers towards each other. Reversing in place is the classic:

C++
void reverse(int* begin, int* end)
{
    while (begin < end)
    {
        --end;                       // end points one past: step back to a real element
        const int t{ *begin }; *begin = *end; *end = t;
        ++begin;
    }
}

Checking whether a word is a palindrome, merging two sorted arrays and removing items while compacting an array all follow the same shape: two pointers, each moving when its condition says so.
