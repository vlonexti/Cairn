Arena Allocators

lesson 6.022 of 5 in milestone 65 min1 practice task

An arena hands out memory by moving one pointer forward and frees everything at once by moving it back. Bump allocation, alignment, frame arenas reset every frame, markers for rewinding part of an arena, and the rules for what may live in one.

The fastest allocator there is

An arena (also called a linear or bump allocator) owns one block of memory and an offset into it. Allocating moves the offset forward; that is all.

C++
class Arena
{
public:
    explicit Arena(std::size_t size) : memory(size) {}

    void* allocate(std::size_t bytes, std::size_t align = alignof(std::max_align_t))
    {
        const std::size_t start{ alignUp(used, align) };
        if (start + bytes > memory.size()) return nullptr;     // full
        used = start + bytes;
        return memory.data() + start;
    }

    void reset() { used = 0; }        // frees everything at once

private:
    std::vector<std::byte> memory;
    std::size_t used{ 0 };
};
Text
 start                         used                           end
   |                             |                              |
   [ obj A ][ pad ][ obj B ][ C ] ................ free ..........

An allocation is an addition and a comparison. There are no headers, no free lists, no searching, and no fragmentation: everything allocated sits side by side in the order it was made, which is also the best possible order for the cache.

No individual frees

The price is that you cannot free one object. Memory comes back all at once, with reset(). That sounds limiting and turns out to fit a lot of real work, because many allocations share one lifetime:

  • Per frame: everything a game computes during one frame (visible-object lists, temporary strings, draw commands) is garbage at the end of the frame. One frame arena, reset at the start of every frame, replaces thousands of new/delete pairs.
  • Per level: everything loaded for a level dies when the level is unloaded.
  • Per request: a server handling one request, or a compiler compiling one function.

Alignment

Each allocation must start at an address suitable for its type, so the offset is rounded up first. Asking for a double after a char wastes up to 7 bytes of padding, just like struct padding (lesson 3.01). The default alignment of alignof(std::max_align_t) (16) is always safe; passing the real alignof(T) packs objects more tightly.

The arena's own memory must be aligned too. std::vector<std::byte> gets its block from new, which returns memory aligned to at least 16, so offsets that are multiples of 16 are 16-aligned addresses. For larger alignments (64 for a cache line, 4096 for a page), align the address, not the offset:

C++
std::uintptr_t address{ reinterpret_cast<std::uintptr_t>(memory.data()) + used };
std::uintptr_t aligned{ alignUp(address, align) };

Markers

A marker remembers the current offset so you can roll back to it later, freeing everything allocated since, but keeping what came before. That makes the arena a stack allocator:

C++
Marker before{ arena.mark() };
buildPathfindingGraph(arena);       // lots of temporary allocations
Path path{ findPath(arena) };       // ...
arena.rewind(before);               // all of that is gone; earlier allocations stay

Rewinding must happen in last-in, first-out order: rewinding to an older marker discards everything after it, including allocations made after a newer marker.

What may live in an arena

reset() does not run destructors. It just forgets the memory. So objects in an arena should be trivially destructible, or you must call their destructors yourself before resetting:

  • Plain structs of numbers, arrays of them, and views over them: perfect.
  • A std::string or std::vector object placed in an arena still allocates its contents on the normal heap, and resetting without destroying it leaks that.

C++17's std::pmr::monotonic_buffer_resource is a standard arena, and the std::pmr::vector and std::pmr::string types can be told to allocate their contents from it, so a whole frame's worth of containers lives inside one arena.

To construct an object in arena memory you use placement new, which runs a constructor at an address you supply:

C++
void* place{ arena.allocate(sizeof(Particle), alignof(Particle)) };
Particle* p{ new (place) Particle{ x, y } };     // no allocation: construct at that address
