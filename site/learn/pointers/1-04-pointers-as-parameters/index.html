Pointers as Parameters

lesson 1.044 of 5 in milestone 15 min1 practice task

C++ passes arguments by copying them, so a function cannot change the caller's variables, unless it receives their addresses. Out-parameters, swap, returning several results, optional parameters with nullptr, and when a reference is the better choice.

Functions get copies

When you call a function, each argument is copied into the function's parameter. Changing the parameter changes the copy:

C++
#include <iostream>

void heal(int health)
{
    health += 25;          // changes the local copy only
}

int main()
{
    int health{ 50 };
    heal(health);
    std::cout << health << '\n';   // still 50
}

The health inside heal is a separate variable in heal's stack frame (lesson 4.02 shows the frames). It vanishes when the function returns.

Passing the address

If the function receives the address instead, it can reach the caller's variable:

C++
#include <iostream>

void heal(int* health)
{
    *health += 25;         // follow the address to the caller's variable
}

int main()
{
    int health{ 50 };
    heal(&health);          // pass where health is, not what it is
    std::cout << health << '\n';   // 75
}

The pointer is still copied, but a copy of an address points at the same place. This is how C, and lots of Windows API functions, let a function change things in its caller.

The classic: swap

C++
#include <iostream>

void swapInts(int* a, int* b)
{
    const int old{ *a };
    *a = *b;
    *b = old;
}

int main()
{
    int left{ 1 }, right{ 2 };
    swapInts(&left, &right);
    std::cout << left << ' ' << right << '\n';   // 2 1
}

Without pointers (or references) swap cannot be written at all.

Out-parameters

A function returns one value, but sometimes it has several results. A common pattern returns success or failure and writes the results through pointers, called out-parameters:

C++
// Splits "12:45" into hours and minutes. Returns false if the text is not a time.
bool parseTime(const std::string& text, int* hours, int* minutes);

int h{}, m{};
if (parseTime("12:45", &h, &m)) { /* use h and m */ }

The Windows API is full of these: GetExitCodeProcess(process, &exitCode) returns success as a BOOL and the exit code through a pointer. Modern C++ often prefers returning a struct or a std::optional, but you will read out-parameters constantly.

Optional parameters

A pointer parameter can be nullptr, which gives a natural way to say "I do not want this result":

C++
void stats(const int* values, int count, int* minOut, int* maxOut)
{
    // ... work out lo and hi ...
    if (minOut) *minOut = lo;     // the caller may not want the minimum
    if (maxOut) *maxOut = hi;
}

stats(data, 10, nullptr, &largest);   // only interested in the maximum

The rule that follows: if a parameter may be nullptr, check before writing through it. If it may not, say so in the function's comment, or better, use a reference.

References: pointers that cannot be null

A C++ reference (int&) is an address too, under the hood, but with three differences: it must be bound to an object when created, it can never be re-pointed, and it cannot be null. You use it without * or &:

C++
void heal(int& health) { health += 25; }
heal(health);   // no & at the call

So which to use?

Use When
T& the function always needs an object to change
const T& the function only reads a large object and wants to avoid a copy
T* "no object" is a valid answer (nullptr), or the code talks to a C API
const T* the same, read only

This course uses pointers almost everywhere, because pointers are the subject. In your own C++ code, prefer references when null is not meaningful.
