Pointers Are Variables That Hold Addresses

lesson 1.022 of 5 in milestone 15 min1 practice task

A pointer is an ordinary variable whose value is an address. Its type says what kind of value lives at that address. Declaring, initialising and printing pointers, nullptr for "no address", and why int* and double* are different types even though both are 8 bytes.

Storing an address

The last lesson printed addresses with &. A pointer is a variable that stores one:

C++
#include <iostream>

int main()
{
    int score{ 42 };
    int* where{ &score };          // where holds the address of score

    std::cout << "score lives at " << &score << '\n';
    std::cout << "where holds    " << where << '\n';     // the same number
    std::cout << "where itself is at " << &where << '\n';  // a different address: where is a variable too
}

Read int* where as "where is a pointer to an int". It is an 8-byte variable like any other: it has its own address (&where), its own bytes, and a value. The value just happens to be an address.

The type says what is at the address

int*, double* and char* are all 8 bytes and all hold an address, yet they are different types and do not mix:

C++
int score{ 42 };
double ratio{ 0.5 };

int* p{ &score };     // fine
double* q{ &ratio };  // fine
int* r{ &ratio };     // error: cannot convert double* to int*

The type is the instruction for reading the address: int* says "at this address start 4 bytes that form an int". If the compiler let you aim an int* at a double, reading through it would take the first 4 of the double's 8 bytes and call them an int, which is nonsense. So the compiler refuses unless you explicitly ask with a cast, which this course will only do for looking at raw bytes (lesson 2.05).

Where the star goes

All of these declare the same thing:

C++
int* a;
int *a;
int * a;

This course writes int* a because the star is part of the type. But beware: in a declaration of several names, the star belongs to each name separately.

C++
int* a, b;     // a is int*, b is a plain int!
int *c, *d;    // both pointers

Declare one pointer per line and the trap never bites.

nullptr: no address at all

A pointer that does not point anywhere yet should hold nullptr:

C++
int* target{ nullptr };       // points at nothing
if (target == nullptr) { /* nothing chosen yet */ }
if (!target) { /* the same test, shorter */ }

nullptr is an address that is never a valid object (address 0 on every system you will meet). It is the pointer equivalent of "none". Old code uses NULL or 0; nullptr is the modern spelling and cannot be mistaken for the integer 0.

Watch out

A pointer declared without a value, int* p;, holds whatever bytes happened to be in its memory: a random address. Using it reads or writes some arbitrary place. Always initialise pointers, to a real address or to nullptr.

Pointers can change

A pointer is a variable, so it can be pointed somewhere else:

C++
#include <iostream>

int main()
{
    int red{ 1 }, green{ 2 }, blue{ 3 };
    int* chosen{ &red };
    std::cout << chosen << '\n';
    chosen = &blue;                 // now it holds blue's address
    std::cout << chosen << '\n';
    chosen = nullptr;               // and now nothing
    std::cout << chosen << '\n';    // prints 0000000000000000
    (void)green;
}

Changing chosen never changes red, green or blue. It only changes which address chosen holds. Changing the value at the address is the next lesson.

Addresses can be compared

Two pointers of the same type can be compared with == and !=: they are equal when they hold the same address, that is, when they point at the same object. This is how you ask "are these the same thing?" rather than "do these hold equal values?":

C++
int a{ 5 }, b{ 5 };
int* p{ &a };
int* q{ &a };
int* r{ &b };
// p == q: true, same object.  p == r: false, different objects, even though a == b.
