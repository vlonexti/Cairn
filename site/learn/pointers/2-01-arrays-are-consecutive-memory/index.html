Arrays Are Consecutive Memory

lesson 2.011 of 5 in milestone 25 min1 practice task

An array is its elements placed one after another with no gaps, so element i sits at the start address plus i times the element size. An array's name turns into a pointer to its first element when passed to a function, which is why the function loses the length and sizeof stops working.

Side by side

An array is the simplest data structure there is: its elements stored one after another, with nothing in between.

C++
#include <iostream>

int main()
{
    int scores[5]{ 90, 72, 85, 64, 99 };
    for (int i{ 0 }; i < 5; ++i)
        std::cout << "scores[" << i << "] is at " << &scores[i] << '\n';
}

Each address is 4 more than the last, because each int is 4 bytes. That gives the one formula that every array access uses:

address of element i = address of element 0 + i × size of one element

This is why indexing is fast: reaching scores[1000] is one multiplication and one addition, not a walk past 999 others. And it is why arrays start at 0: element 0 is at the start plus 0.

The name becomes a pointer

In almost every expression, an array's name turns into a pointer to its first element. This is called decay:

C++
int scores[5]{ 90, 72, 85, 64, 99 };
int* p{ scores };        // the same as &scores[0]
std::cout << *p;         // 90

Decay is what happens when you pass an array to a function. These three declarations all mean exactly the same thing, a pointer:

C++
int sum(int values[5], int count);
int sum(int values[], int count);
int sum(int* values, int count);

The 5 in the first one is ignored. The function receives an address and nothing else, so it cannot know how long the array is. That is why C-style functions always take a count alongside the pointer, and why so many bugs are "the count was wrong".

sizeof after decay

sizeof on a real array gives the size of the whole array. On a decayed pointer it gives the size of a pointer:

C++
#include <iostream>

void show(int values[])
{
    std::cout << "inside: " << sizeof(values) << '\n';   // 8: just a pointer
}

int main()
{
    int scores[5]{};
    std::cout << "outside: " << sizeof(scores) << '\n';  // 20: five ints
    std::cout << "count: " << sizeof(scores) / sizeof(scores[0]) << '\n';
    show(scores);
}

The compiler warns about sizeof on an array parameter for exactly this reason. Inside the function, the count has to come from the caller. In modern C++, std::size(scores) gives the count of a real array and refuses to compile on a pointer, which is safer than the division.

Indexing is pointer arithmetic

values[i] is defined as *(values + i): "start at values, move i elements along, and follow". The next lesson takes that apart. For now it explains a curiosity: because addition does not care about order, i[values] also compiles and means the same. Do not write it; just know that [] is arithmetic on an address.

No bounds checking

Nothing stops scores[5] or scores[-1]. The formula happily computes an address outside the array and the program reads or writes whatever is there: another variable, a return address, padding. In a debug build MSVC's runtime checks may catch a write just past a local array when the function returns:

Text
Run-Time Check Failure #2 - Stack around the variable 'scores' was corrupted.

That message means "something wrote past the end of scores", and the culprit ran some time before the message appeared.

Arrays of other things

The formula works for any element type. An array of 3 doubles has elements 8 bytes apart. An array of structs has elements sizeof(struct) apart, padding included (lesson 3.01). std::array<int, 5> and std::vector<int> store their elements exactly the same way, consecutively, which is why vec.data() gives a pointer you can pass to C functions expecting int* and a count.
