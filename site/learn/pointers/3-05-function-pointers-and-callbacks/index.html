Function Pointers and Callbacks

lesson 3.055 of 5 in milestone 35 min1 practice task

Functions live in memory too, and a function pointer holds the address of one. The declaration syntax and how to tame it with using, tables of functions, C-style callbacks with a void* context, how virtual functions are tables of function pointers, and std::function.

Functions have addresses

A program's machine code is in memory like everything else, so every function has an address. A function pointer holds one, and calling through it runs that function:

C++
#include <iostream>

int add(int a, int b) { return a + b; }
int multiply(int a, int b) { return a * b; }

int main()
{
    int (*op)(int, int){ add };      // op points at add
    std::cout << op(3, 4) << '\n';   // 7
    op = multiply;
    std::cout << op(3, 4) << '\n';   // 12
}

A function's name turns into a pointer to it, the way an array's name does, so add and &add are the same here.

Taming the syntax

int (*op)(int, int) reads "op is a pointer to a function taking two ints and returning an int". The brackets around *op are required: without them, int* op(int, int) declares a function returning int*. Give the type a name and the problem goes away:

C++
using BinaryOp = int (*)(int, int);

BinaryOp op{ add };
int apply(BinaryOp f, int a, int b) { return f(a, b); }

Tables of functions

An array of function pointers turns a decision into a lookup. Interpreters, state machines and command handlers are built this way:

C++
using Handler = void (*)(Game&);

void onMove(Game& g);
void onAttack(Game& g);
void onQuit(Game& g);

constexpr Handler handlers[]{ onMove, onAttack, onQuit };
handlers[static_cast<int>(command)](game);     // no switch needed

Each entry is just an 8-byte address. A table like this is what a switch statement often compiles into, too: a jump table of addresses indexed by the case value.

Callbacks with a context

A callback is a function you hand to other code to call later or for each item. C interfaces take a function pointer plus a void* context that they pass back unchanged, because a plain function pointer cannot carry any data of its own:

C++
// The library's side
void forEachFile(const char* folder, bool (*visit)(const char* name, void* context), void* context);

// Your side: count files, stop after 100
struct Counter { int seen; int limit; };

bool countOne(const char* name, void* context)
{
    Counter* c{ static_cast<Counter*>(context) };   // turn the void* back into what it really is
    ++c->seen;
    return c->seen < c->limit;                      // false: stop early
}

Counter counter{ 0, 100 };
forEachFile("C:\\Games", countOne, &counter);

void* is "an address of anything": any object pointer converts to it, and static_cast converts it back to the type it really was. The library never looks inside. The Windows API does this everywhere: EnumWindows(callback, lParam), CreateThread(..., startRoutine, parameter, ...), window procedures with GWLP_USERDATA.

Virtual functions are tables

A class with virtual functions gets a hidden table of function pointers, the vtable, one per class, and every object carries a pointer to its class's table (lesson 3.01's hidden member at offset 0):

Text
object of Archer          vtable for Archer
[ vptr  ] ------------->  [ &Archer::attack ]
[ health ]                [ &Archer::move   ]
[ arrows ]                [ &Archer::~Archer ]

A virtual call unit->attack() compiles to: read the vtable pointer at offset 0 of the object, read the function address at the right slot of the table, call it. Two loads and an indirect call, which is why a virtual call costs a little more than a direct one, and why the decision can happen at run time. The DLLs course builds COM-style interfaces from exactly these tables.

std::function and lambdas

Modern C++ wraps all of this. A lambda with captures carries its own data, so it needs no void* context, and std::function can hold any callable with the right signature:

C++
int limit{ 100 };
int seen{ 0 };
std::function<bool(const std::string&)> visit{ [&](const std::string&) { return ++seen < limit; } };

The cost is that a std::function may allocate and always calls indirectly. Inside your own C++ code prefer it, or a template parameter, for clarity; when calling a C API, you still need a plain function pointer and a context, and a lambda without captures converts to a plain function pointer to fill that role.
