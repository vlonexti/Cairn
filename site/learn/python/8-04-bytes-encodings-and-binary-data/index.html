Bytes, Encodings and Binary Data

lesson 8.044 of 6 in milestone 85 min2 practice tasks

The difference between text and bytes - bytes and bytearray, encoding and decoding with UTF-8, what goes wrong with the wrong encoding, hex and base64, reading and writing binary files, packing numbers with the struct module, and memoryview for working on part of a buffer without copying.

Text is not bytes

A str holds characters. Files, networks and most other programs deal in bytes: numbers from 0 to 255. Turning text into bytes is encoding; turning bytes back into text is decoding.

Python
text = "café"
data = text.encode("utf-8")
print(data, len(text), len(data))
print(data.decode("utf-8"))
Output
b'caf\xc3\xa9' 4 5
café

é takes two bytes in UTF-8, so the text has 4 characters but 5 bytes. A bytes literal is written b'...'; bytes that are not printable ASCII show as \x...

The wrong encoding

Decoding with an encoding that does not match gives either an error or quietly wrong text:

Python
data = "café".encode("utf-8")
print(data.decode("latin-1"))
try:
    b"\xff\xfe".decode("utf-8")
except UnicodeDecodeError as e:
    print("error:", e.reason)
print(b"\xff abc".decode("utf-8", errors="replace"))
Output
cafÃ©
error: invalid start byte
� abc

cafÃ© is the classic sign of UTF-8 read as Latin-1. Always say the encoding when opening text files (open(path, encoding="utf-8")), and decide on purpose what to do with bad bytes (errors="replace" or "strict").

Working with bytes

bytes cannot be changed; bytearray can:

Python
b = bytes([72, 105])
print(b, b[0], list(b))

buf = bytearray(b"hello")
buf[0] = ord("J")
buf += b"!"
print(buf, buf.hex(" "))
print(bytes.fromhex("48 69"))
Output
b'Hi' 72 [72, 105]
bytearray(b'Jello!') 4a 65 6c 6c 6f 21
b'Hi'

Indexing a bytes gives an int; slicing gives bytes.

Base64

Base64 turns any bytes into plain ASCII text, so binary data can travel through JSON, email or URLs:

Python
import base64

raw = bytes([0, 255, 128, 64])
text = base64.b64encode(raw).decode("ascii")
print(text, base64.b64decode(text) == raw)
Output
AP+AQA== True

It is an encoding, not encryption: anyone can decode it.

Binary files

Open with "rb" or "wb" to read and write bytes with no decoding:

Python
with open("image.png", "rb") as f:
    header = f.read(8)
print(header == b"\x89PNG\r\n\x1a\n")

Packing numbers with struct

Binary formats store numbers as fixed-size groups of bytes. struct.pack turns values into bytes by a format string, and struct.unpack reverses it:

Python
import struct

data = struct.pack("<HIf", 7, 1_000_000, 1.5)
print(data.hex(" "), len(data))
print(struct.unpack("<HIf", data))
Output
07 00 40 42 0f 00 00 00 c0 3f 10
(7, 1000000, 1.5)

The format starts with the byte order, < for little-endian (most PCs) or > for big-endian (network order), then one letter per value: b/B 1 byte, h/H 2, i/I 4, q/Q 8 (lower case signed, upper case unsigned), f and d for floats, 5s for 5 raw bytes. struct.calcsize gives the total size.

Reading records one after another:

Python
import struct

RECORD = struct.Struct("<I8sB")       # id, name (8 bytes), score
rows = [(1, b"Ada", 91), (2, b"Bob", 48)]
blob = b"".join(RECORD.pack(*r) for r in rows)

for id_, name, score in RECORD.iter_unpack(blob):
    print(id_, name.rstrip(b"\0").decode(), score)
Output
1 Ada 91
2 Bob 48

8s pads short names with zero bytes, which is why the reader strips them.

Integers to bytes directly

Python
n = 1_000_000
data = n.to_bytes(4, "big")
print(data.hex(), int.from_bytes(data, "big"))
Output
000f4240 1000000

memoryview: slices without copying

Slicing bytes makes a copy. A memoryview looks at part of a buffer without copying, and can write into a bytearray:

Python
buf = bytearray(8)
view = memoryview(buf)
view[2:4] = b"\x12\x34"
print(buf.hex(" "), view[2:4].tobytes())
Output
00 00 12 34 00 00 00 00 b'\x124'

For large files or network buffers this avoids copying megabytes just to look at a header.
