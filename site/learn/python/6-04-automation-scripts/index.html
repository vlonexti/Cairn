Automation Scripts

lesson 6.044 of 5 in milestone 65 min1 practice task

Turning Python code into tools you run every day - command-line arguments with argparse, exit codes, reading from standard input, working through folders of files safely, running other programs with subprocess, and logging what a script did.

A script's shape

A useful script has a main function, reads its arguments, does its work, and exits with a status:

Python
import argparse
import sys

def main(argv=None):
    parser = argparse.ArgumentParser(description="Count lines in text files.")
    parser.add_argument("files", nargs="+", help="files to count")
    parser.add_argument("--min", type=int, default=0, help="only show files with at least this many lines")
    parser.add_argument("-q", "--quiet", action="store_true", help="print only the total")
    args = parser.parse_args(argv)

    total = 0
    for name in args.files:
        try:
            with open(name, encoding="utf-8") as f:
                count = sum(1 for _ in f)
        except OSError as e:
            print(f"error: {e}", file=sys.stderr)
            return 1
        total += count
        if not args.quiet and count >= args.min:
            print(f"{count:6} {name}")
    print(f"{total:6} total")
    return 0

if __name__ == "__main__":
    sys.exit(main())

Running python count.py --help prints a help text generated from the definitions; wrong arguments give a clear error. Passing argv explicitly to main makes the script easy to test: main(["notes.txt", "--quiet"]).

argparse in brief

Definition Command line
add_argument("path") A required positional argument
add_argument("files", nargs="+") One or more
add_argument("--limit", type=int, default=10) An option with a value
add_argument("-v", "--verbose", action="store_true") A flag
add_argument("--mode", choices=["fast", "safe"]) Only these values

Exit codes and streams

By convention, exit code 0 means success and anything else failure; other programs and scripts (and CI systems) rely on it. Write results to standard output and messages and errors to standard error (print(..., file=sys.stderr)), so results can be redirected to a file (python count.py *.txt > counts.txt) without the errors mixed in.

Reading standard input makes a script work in pipelines: for line in sys.stdin:.

Working through files safely

Automation often changes many files at once, so build in safety:

Python
from pathlib import Path

def rename_photos(folder, dry_run=True):
    for i, path in enumerate(sorted(Path(folder).glob("*.jpg")), start=1):
        target = path.with_name(f"photo-{i:03}.jpg")
        if target.exists():
            print(f"skip {path.name}: {target.name} exists")
            continue
        print(f"{path.name} -> {target.name}")
        if not dry_run:
            path.rename(target)
  • A dry run that only prints what would happen, as the default.
  • Never overwrite without checking.
  • Work on a copy first; keep backups.
  • Log every change (below), so it can be undone.

Running other programs

subprocess.run starts another program and waits for it. Pass the command as a list (no shell, no quoting problems: the Win32 course's lesson 5.03 explains why quoting is hard):

Python
import subprocess, sys

result = subprocess.run([sys.executable, "--version"], capture_output=True, text=True)
print(result.returncode, result.stdout.strip() or result.stderr.strip())

check=True raises an exception if the program fails. Avoid shell=True with any text that comes from users or files.

Logging

For scripts that run unattended, the logging module records what happened with times and levels, to the screen and a file:

Python
import logging

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s")
log = logging.getLogger("backup")
log.info("copied %d files", 42)
log.warning("skipped %s: locked", "notes.docx")

Scheduling

To run a script every day, use the system's scheduler: Task Scheduler on Windows (action: python.exe, argument: the script's full path), cron on Linux and macOS. Use full paths everywhere, because scheduled tasks do not start in your usual folder.
