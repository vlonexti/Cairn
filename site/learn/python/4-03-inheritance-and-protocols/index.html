Inheritance and Protocols

lesson 4.033 of 5 in milestone 45 min1 practice task

Sharing behaviour between classes - subclasses, overriding methods, super(), abstract base classes, and Python's duck typing, where any object with the right methods will do. This lesson also says when composition is better than inheritance.

Subclasses

A subclass inherits everything from its base class and can add or override methods:

Python
class Shape:
    def __init__(self, name):
        self.name = name

    def area(self):
        return 0.0

    def describe(self):
        return f"{self.name} with area {self.area():.2f}"


class Rectangle(Shape):
    def __init__(self, width, height):
        super().__init__("rectangle")      # let the base class set up its part
        self.width, self.height = width, height

    def area(self):                        # overrides Shape.area
        return self.width * self.height


class Circle(Shape):
    def __init__(self, radius):
        super().__init__("circle")
        self.radius = radius

    def area(self):
        return 3.141592653589793 * self.radius ** 2


for shape in [Rectangle(3, 4), Circle(1)]:
    print(shape.describe())

describe is written once, in Shape, and calls whichever area the actual object has: this is polymorphism. isinstance(shape, Shape) is true for both.

super()

super() gives access to the base class's version of a method, most often to extend __init__ or to add to a method rather than replace it:

Python
class LoggedRectangle(Rectangle):
    def area(self):
        result = super().area()
        print(f"area computed: {result}")
        return result

Abstract base classes

When a base class only describes what subclasses must provide, make it abstract so it cannot be used by mistake:

Python
from abc import ABC, abstractmethod

class Exporter(ABC):
    @abstractmethod
    def export(self, rows):
        """Return the rows as text."""

class CsvExporter(Exporter):
    def export(self, rows):
        return "\n".join(",".join(map(str, row)) for row in rows)

print(CsvExporter().export([(1, 2), (3, 4)]))
# Exporter() would raise TypeError: abstract methods are missing

Duck typing

Python does not require a shared base class. If an object has the methods that are used, it works: "if it walks like a duck and quacks like a duck...". len() works on anything with __len__; a function that calls .write(text) works with a file, a StringIO, or your own class with a write method.

Python
import io

def save_report(out, lines):
    for line in lines:
        out.write(line + "\n")

buffer = io.StringIO()
save_report(buffer, ["a", "b"])        # works with any object that has write()
print(repr(buffer.getvalue()))

typing.Protocol (lesson 5.05) lets you describe such a "duck" for type checkers without inheritance.

Composition over inheritance

Inheritance means "is a": a circle is a shape. When the relationship is "has a" (a car has an engine), store the other object in an attribute instead: composition. It is more flexible (the engine can be swapped) and avoids deep class hierarchies that are hard to change. A good rule: inherit only when the subclass truly can be used everywhere the base class can.
