Testing in Depth

lesson 8.022 of 6 in milestone 85 min2 practice tasks

Going beyond assert - the unittest module with test cases, setUp and assertions, testing exceptions, running many inputs with subTest, replacing slow or unpredictable parts with unittest.mock, patching, and how pytest's fixtures and parametrize do the same with less code.

What a test needs

Lesson 5.05 showed tests as functions full of assert. Real projects add three things:

  1. A runner that finds the tests, runs each one even if another fails, and reports.
  2. Set-up shared between tests, so each starts from a fresh state.
  3. Fakes for the parts you cannot run in a test: the network, the clock, random numbers, files.

Python ships unittest for the first two and unittest.mock for the third. Most projects use the third-party pytest on top, which you will meet at the end.

unittest

Python
import unittest

def average(values):
    if not values:
        raise ValueError("no values")
    return sum(values) / len(values)

class AverageTests(unittest.TestCase):
    def test_simple(self):
        self.assertEqual(average([2, 4]), 3)

    def test_float(self):
        self.assertAlmostEqual(average([0.1, 0.2]), 0.15)

    def test_empty_raises(self):
        with self.assertRaises(ValueError):
            average([])

unittest.main(argv=["x"], exit=False, verbosity=0)

Each method whose name starts with test is one test. The assert... methods print both values when they fail, which assert alone does not. The most used are assertEqual, assertTrue, assertIn, assertIsNone, assertAlmostEqual (for floats) and assertRaises.

On your own machine, python -m unittest finds files named test*.py and runs them.

A fresh start for every test

setUp runs before each test, tearDown after it, even when the test failed:

Python
import unittest

class Cart:
    def __init__(self):
        self.items = {}

    def add(self, name, qty=1):
        self.items[name] = self.items.get(name, 0) + qty

class CartTests(unittest.TestCase):
    def setUp(self):
        self.cart = Cart()
        self.cart.add("tea", 2)

    def test_add_more(self):
        self.cart.add("tea")
        self.assertEqual(self.cart.items["tea"], 3)

    def test_starts_with_two(self):
        self.assertEqual(self.cart.items, {"tea": 2})   # not 3: a new cart for each test

unittest.main(argv=["x"], exit=False, verbosity=0)

Tests must not depend on each other or on their order. A fresh object per test is how you guarantee it.

Many inputs, one test

subTest reports each failing case separately instead of stopping at the first:

Python
def test_many(self):
    for text, expected in [("1", 1), ("-2", -2), (" 3 ", 3)]:
        with self.subTest(text=text):
            self.assertEqual(int(text), expected)

Fakes with unittest.mock

A Mock is an object that accepts any call and remembers it. You can tell it what to return and later ask how it was used:

Python
from unittest.mock import Mock

def notify(user, sender):
    if user["email"]:
        sender.send(user["email"], "Your order shipped")
        return True
    return False

sender = Mock()
print(notify({"email": "ada@example.com"}, sender))
sender.send.assert_called_once_with("ada@example.com", "Your order shipped")
print(sender.send.call_count)
Output
True
1

Passing the dependency in (here sender) makes testing easy: the test gives a mock, the real program gives a real sender. This is the same idea as dependency injection in other languages.

return_value and side_effect control what a mock gives back:

Python
from unittest.mock import Mock

api = Mock()
api.get_price.return_value = 4.5
print(api.get_price("tea"))

api.get_stock.side_effect = [3, 0, TimeoutError("slow")]   # one result per call
print(api.get_stock(), api.get_stock())
try:
    api.get_stock()
except TimeoutError as e:
    print("raised", e)
Output
4.5
3 0
raised slow

Patching what you cannot pass in

When code calls something directly, like time.time() or random.random(), patch swaps it for a mock during the test:

Python
import random
from unittest.mock import patch

def roll():
    return random.randint(1, 6)

with patch("random.randint", return_value=6):
    print(roll(), roll())
print(1 <= roll() <= 6)
Output
6 6
True

Patch the name where it is looked up. If a module did from random import randint, you patch "thatmodule.randint", not "random.randint".

pytest in brief

pytest runs plain functions with plain assert, and rewrites the assert so a failure shows the values:

Python
# test_cart.py, run with: python -m pytest
import pytest

@pytest.fixture
def cart():
    c = Cart()
    c.add("tea", 2)
    return c

def test_add_more(cart):          # the fixture is passed in by name
    cart.add("tea")
    assert cart.items["tea"] == 3

@pytest.mark.parametrize("text, expected", [("1", 1), ("-2", -2)])
def test_parse(text, expected):
    assert int(text) == expected

def test_empty():
    with pytest.raises(ValueError):
        average([])

Fixtures replace setUp, parametrize replaces loops of subTest, and pytest.raises replaces assertRaises. The ideas are the same; pytest only needs less code.
