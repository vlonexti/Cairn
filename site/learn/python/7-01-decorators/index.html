Decorators

lesson 7.011 of 6 in milestone 75 min2 practice tasks

Functions that wrap other functions - why the @ syntax exists, writing a decorator step by step, keeping the wrapped function's name with functools.wraps, decorators that take arguments, stacking them, and the decorators the standard library gives you.

Functions are values

A decorator rests on two things you already know (lesson 3.03): a function can be passed to another function, and a function can build and return a new function that remembers its surroundings (a closure).

Python
def shout(text):
    return text.upper() + "!"

def twice(func):
    def run(text):
        return func(func(text))
    return run

louder = twice(shout)
print(louder("hi"))          # HI!!

twice takes a function and returns a new one that does something extra around it. That is all a decorator is.

The @ syntax

Wrapping a function and keeping the same name is so common that Python has a shorthand. These two are exactly the same:

Python
def log_calls(func):
    def wrapper(*args, **kwargs):
        print(f"calling {func.__name__}{args}")
        result = func(*args, **kwargs)
        print(f"{func.__name__} returned {result}")
        return result
    return wrapper

@log_calls
def add(a, b):
    return a + b

# the line above is short for:   add = log_calls(add)
add(2, 3)

*args, **kwargs (lesson 3.02) lets the wrapper accept whatever the original accepts and pass it all on, so one decorator works for any function.

Keep the name: functools.wraps

After decorating, add is wrapper, so its name and docstring are wrong, which confuses error messages, help text and tests. functools.wraps copies them across:

Python
import functools

def log_calls(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@log_calls
def add(a, b):
    """Adds two numbers."""
    return a + b

print(add.__name__, "-", add.__doc__)     # add - Adds two numbers.

Put @functools.wraps(func) on every wrapper you write. It costs nothing.

A useful decorator: timing

Python
import functools
import time

def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = time.perf_counter() - start
            print(f"{func.__name__} took {elapsed * 1000:.1f} ms")
    return wrapper

@timed
def slow_sum(n):
    return sum(range(n))

slow_sum(1_000_000)

The finally makes the time print even when the function raises.

Decorators that take arguments

@retry(times=3) needs one more layer: retry(times=3) is called first and must return the actual decorator.

Python
import functools

def repeat(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(times=3)
def greet(name):
    print("hello", name)

greet("Ada")

Read it from the outside in: repeat(3) returns decorator; decorator(greet) returns wrapper; calling greet runs wrapper.

Stacking

Several decorators apply from the bottom up: the one nearest the def wraps first.

Python
@timed
@log_calls
def mul(a, b):
    return a * b
# mul = timed(log_calls(mul))

Decorators you already have

Decorator What it does
@property a method read like an attribute (lesson 4.01)
@staticmethod, @classmethod methods without an instance, or with the class (lesson 4.01)
@dataclass writes __init__, __repr__ and __eq__ for you (lesson 4.04)
@functools.lru_cache remembers results for arguments it has seen (lesson 5.04)
@functools.cache the same with no size limit

A decorator can also be applied to a class: @dataclass is one. It receives the class and returns it (changed) or a replacement.

When to write one

Write a decorator when the same "before and after" code would otherwise be copied into many functions: logging, timing, checking arguments, retrying, caching, counting calls. If only one function needs it, plain code inside that function is clearer.
