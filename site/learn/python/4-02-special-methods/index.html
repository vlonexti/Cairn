Special Methods

lesson 4.022 of 5 in milestone 45 min1 practice task

Making your classes behave like built-in types - repr and str for printing, eq and ordering, arithmetic operators, len, getitem and iter for containers, contains, and hash for use in sets and as keys.

Methods Python calls for you

Methods with double underscores on both sides ("dunder" methods) are called by Python's own syntax:

You write Python calls
repr(x), the REPL, debugging x.__repr__()
str(x), print(x), f-strings x.__str__() (falls back to __repr__)
x == y x.__eq__(y)
x < y x.__lt__(y)
x + y, x * y x.__add__(y), x.__mul__(y)
len(x) x.__len__()
x[i] x.__getitem__(i)
for item in x x.__iter__()
item in x x.__contains__(item)
hash(x), sets, dict keys x.__hash__()

A vector

Python
import math

class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    def __eq__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __mul__(self, k):
        return Vector(self.x * k, self.y * k)

    def __rmul__(self, k):            # k * v, when k is on the left
        return self * k

    def __abs__(self):
        return math.hypot(self.x, self.y)


v = Vector(3, 4)
print(v + Vector(1, 1), 2 * v, abs(v), v == Vector(3, 4))

__repr__ should look like the code that would create the object: it is what you see when debugging. Returning NotImplemented (not raising) from __eq__ lets Python try the other side or fall back to "not equal".

Containers

A class that holds items can support len, indexing, in and loops:

Python
class Playlist:
    def __init__(self, *songs):
        self._songs = list(songs)

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, index):
        return self._songs[index]          # slices work too, because lists support them

    def __iter__(self):
        return iter(self._songs)

    def __contains__(self, song):
        return song in self._songs


p = Playlist("Intro", "Theme", "Outro")
print(len(p), p[1], p[-1], "Theme" in p, [s.upper() for s in p])

Ordering and hashing

Defining __eq__ and __lt__, plus functools.total_ordering, gives all six comparisons, so sorted() works on your objects. An object used in a set or as a dictionary key needs __hash__ consistent with __eq__ (equal objects must have equal hashes); a class that defines __eq__ without __hash__ becomes unhashable, which is correct for mutable objects. Dataclasses (lesson 4.04) write most of this for you.
