Classes and Objects

lesson 4.011 of 5 in milestone 45 min1 practice task

Bundling data and behaviour together - defining a class, init and self, attributes and methods, class attributes, keeping an object valid, properties, and when a class is better than a dictionary or a few functions.

A class is a new type

A class describes a kind of object: what data it holds (attributes) and what it can do (methods). Each instance has its own data:

Python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def describe(self):
        return f"{self.owner}: {self.balance:.2f}"


a = BankAccount("Ada")
b = BankAccount("Grace", 100)
a.deposit(25)
print(a.describe(), "|", b.describe())
  • __init__ runs when an instance is created and sets up its attributes.
  • self is the instance the method is working on. a.deposit(25) is the same as BankAccount.deposit(a, 25).
  • Attributes are created by assigning to self.something.

Class names use CapitalisedWords; methods follow function naming (lower_case).

Keeping objects valid

A class can protect its data so the object never gets into a nonsense state:

Python
class BankAccount:
    def __init__(self, owner, balance=0):
        if balance < 0:
            raise ValueError("balance cannot be negative")
        self.owner = owner
        self._balance = balance

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("amount must be positive")
        if amount > self._balance:
            raise ValueError("insufficient funds")
        self._balance -= amount

    @property
    def balance(self):
        return self._balance


acct = BankAccount("Ada", 50)
acct.withdraw(20)
print(acct.balance)       # 30: read like an attribute

A leading underscore (_balance) means "internal: do not touch from outside"; Python does not enforce it, but everyone respects it. A property exposes a value for reading while the class controls how it changes. raise (lesson 4.05) refuses invalid requests.

Class attributes

Attributes defined in the class body belong to the class, shared by all instances:

Python
class Dice:
    sides = 6                 # shared
    def __init__(self):
        self.rolls = []       # per instance

print(Dice.sides, Dice().sides)

Use class attributes for constants and defaults; never for mutable data that each instance should have its own copy of (the same trap as mutable default arguments, lesson 3.02).

Methods that do not need an instance

Python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    @classmethod
    def from_fahrenheit(cls, f):           # another way to create an instance
        return cls((f - 32) * 5 / 9)

    @staticmethod
    def is_valid(celsius):                 # just a function kept with the class
        return celsius >= -273.15

print(Temperature.from_fahrenheit(212).celsius, Temperature.is_valid(-300))

When to write a class

Use a class when data and the operations on it belong together and the data has rules (an account's balance cannot go negative). For a few related values with no behaviour, a dictionary, tuple or dataclass (lesson 4.04) is simpler. For a single operation, a function is enough.
