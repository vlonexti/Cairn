Text Processing and Regular Expressions

lesson 6.011 of 5 in milestone 65 min1 practice task

Finding and extracting patterns in text with the re module - the pattern language, search, findall and fullmatch, groups and named groups, substitution, flags, and when plain string methods are the better tool.

What regular expressions are for

String methods (lesson 2.01) find fixed text. A regular expression describes a pattern: "a date like 2026-11-15", "an email address", "a word followed by a number". The re module searches for patterns, extracts parts of them and replaces them.

Always write patterns as raw strings (r"..."), so backslashes reach re unchanged.

The pattern language

Pattern Matches
abc The text abc
. Any character except a new line
\d, \w, \s A digit, a word character (letter, digit, _), whitespace
\D, \W, \S Anything but those
[aeiou], [a-z0-9], [^,] One character from a set, a range, or not in the set
*, +, ? Zero or more, one or more, zero or one of what precedes
{3}, {2,4} Exactly 3, between 2 and 4
^, $ Start, end (of the text, or of each line with re.M)
\b A word boundary
a|b a or b
( ) A group: captures the part it matches
\., \( A literal dot or parenthesis

* and + are greedy (they take as much as possible); *? and +? take as little as possible.

Searching

Python
import re

text = "Orders: #1042 on 2026-11-15, #1043 on 2026-11-16."
print(re.findall(r"#(\d+)", text))                  # ['1042', '1043']: the group's text
m = re.search(r"(\d{4})-(\d{2})-(\d{2})", text)     # the first match, or None
if m:
    print(m.group(0), m.group(1), m.groups())
print(bool(re.fullmatch(r"\d{4}-\d{2}-\d{2}", "2026-11-15")))   # the WHOLE text must match
Function Returns
re.search(p, s) First match anywhere, or None
re.match(p, s) Match at the start only
re.fullmatch(p, s) Match of the whole string: use it for validation
re.findall(p, s) List of matches (or of groups)
re.finditer(p, s) Match objects one by one, with positions
re.split(p, s) Split at matches
re.sub(p, repl, s) Replace matches

Named groups

Names make complicated patterns readable:

Python
import re

line = "2026-11-15 10:42:07 ERROR disk full"
pattern = re.compile(r"(?P<date>\S+) (?P<time>\S+) (?P<level>[A-Z]+) (?P<message>.*)")
m = pattern.match(line)
print(m["level"], "-", m["message"], m.groupdict())

re.compile builds the pattern once, which is tidier (and a little faster) when it is used many times.

Replacing

Python
import re

print(re.sub(r"\s+", " ", "too    many   spaces"))                  # collapse whitespace
print(re.sub(r"(\d{4})-(\d{2})-(\d{2})", r"\3/\2/\1", "2026-11-15"))   # 15/11/2026: groups in the replacement
print(re.sub(r"\d+", lambda m: str(int(m.group()) * 2), "3 apples, 10 pears"))

Flags

re.I ignores case, re.M makes ^ and $ match at every line, re.S lets . match new lines too, and re.X allows spaces and comments inside the pattern for long expressions.

When not to use them

Regular expressions are compact but hard to read. For fixed text, in, startswith, split and replace are clearer. For structured formats such as CSV, JSON and HTML, use a real parser (lesson 6.02): patterns for them break on the first unusual input. Test patterns on examples, including ones that should not match.
