Logging

lesson 8.011 of 6 in milestone 85 min2 practice tasks

Telling yourself what a program did - why print is not enough, the logging module's loggers, levels, handlers and formatters, one logger per module with name, logging exceptions with tracebacks, lazy formatting, and configuring it once at start-up.

Why not print?

print is fine while you are writing a script. In a program that runs for hours, or that other people run, you need more:

  • levels, so you can see only warnings normally and everything when something goes wrong;
  • where and when: the time, the module and the line of each message;
  • where it goes: the screen, a file, or both, without changing the code that logs.

The logging module in the standard library gives you all three.

A first logger

Python
import logging
import sys

logging.basicConfig(level=logging.INFO, format="%(levelname)s %(name)s: %(message)s", stream=sys.stdout)
log = logging.getLogger("shop")

log.debug("not shown: below the INFO level")
log.info("started with %d items", 3)
log.warning("stock low for %s", "tea")
log.error("payment failed")
Output
INFO shop: started with 3 items
WARNING shop: stock low for tea
ERROR shop: payment failed

The five levels, from least to most serious, are DEBUG, INFO, WARNING, ERROR and CRITICAL. A logger shows a message when its level is at least the configured one.

Notice log.info("started with %d items", 3): the values are passed separately, not with an f-string. The text is only built if the message is actually shown, which saves work when debug messages are switched off.

One logger per module

The convention is a module-level logger named after the module:

Python
import logging

log = logging.getLogger(__name__)     # "shop.orders" for the file shop/orders.py

def place(order):
    log.info("placing order %s", order.id)

Logger names form a tree split by dots: shop.orders is a child of shop. Settings on shop apply to all its children, so you can turn on debug messages for one part of a program only:

Python
import logging
import sys

logging.basicConfig(level=logging.WARNING, format="%(levelname)s %(name)s: %(message)s", stream=sys.stdout)
logging.getLogger("shop.orders").setLevel(logging.DEBUG)

logging.getLogger("shop.orders").debug("details about an order")
logging.getLogger("shop.stock").debug("not shown: shop.stock is still at WARNING")
Output
DEBUG shop.orders: details about an order

Handlers and formatters

A handler decides where messages go; a formatter decides how they look. One logger can have several handlers, each with its own level:

Python
import logging

log = logging.getLogger("app")
log.setLevel(logging.DEBUG)

screen = logging.StreamHandler()
screen.setLevel(logging.WARNING)
screen.setFormatter(logging.Formatter("%(levelname)s: %(message)s"))

file = logging.FileHandler("app.log", encoding="utf-8")
file.setLevel(logging.DEBUG)
file.setFormatter(logging.Formatter("%(asctime)s %(name)s %(levelname)s %(message)s"))

log.addHandler(screen)
log.addHandler(file)

Everything goes to the file; only warnings and worse reach the screen. Useful format fields include %(asctime)s, %(name)s, %(levelname)s, %(module)s, %(funcName)s and %(lineno)d.

Logging exceptions

Inside an except block, log.exception logs at ERROR level and adds the traceback:

Python
import logging
import sys

logging.basicConfig(level=logging.INFO, format="%(levelname)s: %(message)s", stream=sys.stdout)
log = logging.getLogger("demo")

try:
    1 / 0
except ZeroDivisionError:
    log.exception("could not work out the average")
print("the program carried on")

The output shows the message, then the full traceback, then carries on. That traceback is often everything you need to fix a bug reported by someone else.

Configure once, at the top

Libraries and modules only create loggers and log. The program's entry point configures them, once:

Python
def main():
    logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(name)s: %(message)s")
    ...

if __name__ == "__main__":
    main()

basicConfig does nothing if logging was already configured, so call it before anything else logs. For bigger programs, logging.config.dictConfig takes the whole setup as a dictionary (often loaded from a file).

Testing what was logged

The caplog-style trick without any test framework: attach a handler that keeps records in a list.

Python
import logging

class ListHandler(logging.Handler):
    def __init__(self):
        super().__init__()
        self.records = []

    def emit(self, record):
        self.records.append(record)

log = logging.getLogger("test.demo")
log.setLevel(logging.DEBUG)
log.propagate = False            # do not also send to the root logger
handler = ListHandler()
log.addHandler(handler)

log.warning("disk at %d%%", 91)
print(handler.records[0].levelname, handler.records[0].getMessage())
Output
WARNING disk at 91%

record.getMessage() gives the finished text; record.args holds the values.
