Iterators and Generators

lesson 5.022 of 5 in milestone 55 min1 practice task

How for loops really work - iterables and iterators, iter and next, writing generator functions with yield, lazy pipelines that process data of any size, infinite sequences, and yield from.

The iteration protocol

A for loop works with any iterable: lists, strings, dictionaries, files, ranges. Behind the scenes it asks the iterable for an iterator with iter() and calls next() on it until it raises StopIteration:

Python
it = iter([10, 20, 30])
print(next(it), next(it), next(it))
# next(it) now would raise StopIteration: the loop's signal to stop

An iterator is used up once it has been walked through; a list can be iterated again and again because each for gets a fresh iterator.

Generator functions

A function containing yield is a generator function. Calling it does not run the body; it returns a generator, and each next() runs the body up to the next yield:

Python
def countdown(n):
    print("starting")
    while n > 0:
        yield n
        n -= 1
    print("done")

for value in countdown(3):
    print(value)

The function's local variables survive between yields, so generators are an easy way to write iterators without a class.

Lazy pipelines

Generators produce values on demand. That lets you process data far larger than memory, one item at a time, by chaining small steps:

Python
def read_numbers(lines):
    for line in lines:
        line = line.strip()
        if line:
            yield int(line)

def only_even(numbers):
    for n in numbers:
        if n % 2 == 0:
            yield n

lines = ["4", "", "7", "10", "3"]          # could be a file with millions of lines
print(sum(only_even(read_numbers(lines))))   # 14

No intermediate list is ever built: each number flows through the whole pipeline before the next is read.

Infinite sequences

A generator can go on forever; the consumer decides when to stop:

Python
import itertools

def fibonacci():
    a, b = 0, 1
    while True:
        yield a
        a, b = b, a + b

print(list(itertools.islice(fibonacci(), 10)))

itertools.islice takes the first n items; next(gen) takes one.

yield from

yield from other yields every item of another iterable, which makes recursive generators short:

Python
def flatten(items):
    for item in items:
        if isinstance(item, list):
            yield from flatten(item)
        else:
            yield item

print(list(flatten([1, [2, [3, 4]], 5])))

Iterators in the standard library

Many built-ins return lazy iterators rather than lists: range, enumerate, zip, map, filter, reversed, dictionary views, and file objects. Wrap one in list(...) when you really need all the items at once, for example to index them or loop over them twice.
