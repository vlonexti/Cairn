Advanced Classes

lesson 7.033 of 6 in milestone 75 min2 practice tasks

What happens behind attribute access - properties with setters, descriptors that reuse one rule across many attributes, slots for small memory-light objects, abstract base classes that refuse to be half-finished, init_subclass for registering subclasses, generic classes, and what a metaclass is.

Properties with a setter

Lesson 4.01 used @property to make a read-only value. A property can also control writing, so a class can check every assignment while users still write plain obj.x = value:

Python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius            # goes through the setter below

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("below absolute zero")
        self._celsius = value

    @property
    def fahrenheit(self):                 # computed, read-only
        return self._celsius * 9 / 5 + 32

t = Temperature(20)
t.celsius = 25
print(t.fahrenheit)       # 77.0

Descriptors: one rule for many attributes

If ten attributes all need "must be positive", ten properties repeat themselves. A descriptor is a class whose objects, placed in another class, control access to an attribute. @property is itself built from one.

Python
class Positive:
    def __set_name__(self, owner, name):
        self.name = "_" + name                 # where the value is really stored

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self                        # accessed on the class itself
        return getattr(obj, self.name)

    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError(f"{self.name[1:]} must be positive, got {value}")
        setattr(obj, self.name, value)

class Box:
    width = Positive()
    height = Positive()

    def __init__(self, width, height):
        self.width = width
        self.height = height

b = Box(3, 4)
try:
    b.height = -1
except ValueError as e:
    print(e)              # height must be positive, got -1

__set_name__ tells the descriptor which attribute it was assigned to. You will rarely write descriptors, but knowing that @property, methods and @classmethod all work this way explains a lot of Python.

slots

Each object normally keeps its attributes in a dictionary, which is flexible but costs memory. Listing the attributes in __slots__ replaces that dictionary with fixed storage: objects get smaller and faster, and assigning an attribute that is not listed is an error.

Python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
try:
    p.z = 3
except AttributeError as e:
    print("no:", e)

Use it for classes with millions of instances. @dataclass(slots=True) does the same for a dataclass.

Abstract base classes

Lesson 4.03 showed duck typing and protocols. When you want a base class that cannot be used until the subclass fills in the gaps, use abc:

Python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...

    def describe(self):                       # shared code can use the abstract method
        return f"{type(self).__name__} with area {self.area():.2f}"

class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side ** 2

print(Square(3).describe())
try:
    Shape()
except TypeError as e:
    print(e)

A subclass that forgets area cannot be created either, so the mistake shows up at once, not later in a half-working object.

init_subclass: subclasses that register themselves

A base class can run code each time someone subclasses it. Plugins use this to collect every subclass by name:

Python
class Command:
    registry = {}

    def __init_subclass__(cls, name, **kwargs):
        super().__init_subclass__(**kwargs)
        Command.registry[name] = cls

class Hello(Command, name="hello"):
    def run(self):
        return "hi!"

class Bye(Command, name="bye"):
    def run(self):
        return "see you"

print(Command.registry["bye"]().run())

Generic classes

A container class can say what it holds with a type parameter (Python 3.12+). Python does not check it while running; editors and type checkers do (lesson 5.05):

Python
class Stack[T]:
    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()

s: Stack[int] = Stack()
s.push(1)
print(s.pop())

What a metaclass is

Classes are objects too, and the class of a class is its metaclass, normally type. type(name, bases, namespace) builds a class from parts, which is what the class statement does for you:

Python
Dog = type("Dog", (), {"sound": "woof", "speak": lambda self: self.sound})
print(Dog().speak())

A custom metaclass can change how classes are built. ORMs and frameworks use them; in your own code, __init_subclass__, decorators and descriptors almost always do the job more simply.
