Type Hints and Testing

lesson 5.055 of 5 in milestone 55 min1 practice task

Making Python code safer as it grows - type hints for functions, collections and optional values, checking them with mypy or Pyright, Protocols for duck typing - and automated tests with assert, pytest, fixtures and parametrised tests.

Type hints

Type hints say what types a function expects and returns. Python ignores them when running; editors and type checkers use them to find mistakes before the code runs:

Python
def average(values: list[float]) -> float:
    return sum(values) / len(values)

def find_user(users: dict[str, int], name: str) -> int | None:
    return users.get(name)

print(average([1.0, 2.5]), find_user({"ada": 1}, "bob"))
Hint Means
int, str, float, bool That type
list[int], dict[str, float], set[str], tuple[int, str] Collections with their item types
tuple[int, ...] A tuple of any length of ints
X | None An X or None
Callable[[int], str] (from collections.abc import Callable) A function from int to str
Iterable[str], Iterator[int] Anything you can loop over / an iterator

With hints, find_user(users, "bob") + 1 is reported by the checker: the result may be None. Running mypy main.py or using Pyright (built into VS Code's Python extension) checks a whole project.

Protocols

typing.Protocol describes a "duck" (lesson 4.03) for the type checker, without requiring inheritance:

Python
from typing import Protocol

class HasArea(Protocol):
    def area(self) -> float: ...

def total_area(shapes: list[HasArea]) -> float:
    return sum(s.area() for s in shapes)

Any class with an area() method returning a float is accepted.

Tests with assert

The simplest test is a function full of asserts:

Python
def slug(title: str) -> str:
    return "-".join(title.lower().split())

def test_slug():
    assert slug("Hello World") == "hello-world"
    assert slug("  many   spaces ") == "many-spaces"
    assert slug("") == ""

test_slug()
print("all good")

The practice on this site works the same way: @test functions with check_eq, or plain test_... functions with assert.

pytest

pytest (pip install pytest) finds every test_*.py file and every test_* function in it, runs them, and reports failures with the values involved:

Output
tests/test_slug.py::test_slug PASSED
tests/test_money.py::test_add FAILED
    assert add(2, 3) == 6
    where 5 = add(2, 3)

Two features make tests short:

Python
import pytest

@pytest.mark.parametrize("title, expected", [
    ("Hello World", "hello-world"),
    ("  A  b ", "a-b"),
    ("", ""),
])
def test_slug(title, expected):
    assert slug(title) == expected

def test_bad_age_raises():
    with pytest.raises(ValueError):
        int("forty")

Fixtures provide prepared objects to tests by naming them as parameters (tmp_path gives a fresh temporary folder, for testing file code).

What to test

Test the behaviour callers rely on: normal cases, edge cases (empty input, zero, the largest value, a single item), and error cases (what is raised). Write a test for every bug you fix, so it cannot come back. Small pure functions, which take arguments and return results without printing or reading files, are the easiest to test: one more reason to write code that way.
