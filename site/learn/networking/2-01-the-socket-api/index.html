The Socket API

lesson 2.011 of 5 in milestone 25 min1 practice task

Winsock, Windows' socket library - starting it up, resolving a name with getaddrinfo, creating a socket and connecting to the first address that answers, send and recv and what their return values mean, closing, and reading WSAGetLastError's error codes.

Sockets

A socket is the program's end of a network conversation: a handle you send bytes into and receive bytes from. The API, invented for BSD Unix in the 1980s, is nearly identical on every system; on Windows it is Winsock, in <winsock2.h> and <ws2tcpip.h>, linked with ws2_32.lib.

Starting up

Winsock must be initialised once per process before any other call, and cleaned up at the end:

C++
#include <winsock2.h>
#include <ws2tcpip.h>
#pragma comment(lib, "ws2_32.lib")

WSADATA wsa{};
if (WSAStartup(MAKEWORD(2, 2), &wsa) != 0) return 1;
// ... use sockets ...
WSACleanup();

Connecting to a server

Resolve the name, then try each address until one connects:

C++
SOCKET connectTo(const char* host, const char* port)
{
    addrinfo hints{};
    hints.ai_family = AF_UNSPEC;          // IPv4 or IPv6
    hints.ai_socktype = SOCK_STREAM;      // TCP
    addrinfo* list{};
    if (getaddrinfo(host, port, &hints, &list) != 0) return INVALID_SOCKET;

    SOCKET s{ INVALID_SOCKET };
    for (addrinfo* a{ list }; a; a = a->ai_next)
    {
        s = socket(a->ai_family, a->ai_socktype, a->ai_protocol);
        if (s == INVALID_SOCKET) continue;
        if (connect(s, a->ai_addr, static_cast<int>(a->ai_addrlen)) == 0) break;   // connected
        closesocket(s);
        s = INVALID_SOCKET;
    }
    freeaddrinfo(list);
    return s;
}

Trying every address is not optional politeness: a name often has both an IPv6 and an IPv4 address, and one may be unreachable from your network.

Sending and receiving

C++
int sent{ send(s, data, length, 0) };           // bytes accepted, or SOCKET_ERROR
int got{ recv(s, buffer, sizeof(buffer), 0) };  // bytes received, 0 at end, or SOCKET_ERROR

What the return values mean is the most important thing in this milestone:

Call returns Means
send > 0 that many bytes were accepted into the socket's buffer; possibly fewer than you asked
recv > 0 that many bytes arrived: any amount up to the buffer size, regardless of how the other side sent them
recv == 0 the other side closed its sending direction: end of stream
SOCKET_ERROR an error: call WSAGetLastError()

TCP is a byte stream (lesson 1.04). A message the other side sent with one send can arrive in several recvs, and several messages can arrive in one. Everything about framing from earlier courses applies: lengths or delimiters, and loops that read until a whole message is there.

Errors

Winsock reports errors through WSAGetLastError(), with codes from 10000 up. The ones you meet constantly:

Code Name Usually means
10035 WSAEWOULDBLOCK a non-blocking socket has nothing to do yet (lesson 2.04): not an error
10054 WSAECONNRESET the other side reset the connection (crashed, or closed abruptly)
10053 WSAECONNABORTED your side aborted it (often a timeout inside Windows)
10060 WSAETIMEDOUT connecting or sending timed out
10061 WSAECONNREFUSED nothing is listening on that port
10065 WSAEHOSTUNREACH no route to that machine
10048 WSAEADDRINUSE the port you tried to bind is taken

Network code must expect every one of these at any moment: the network is the least reliable thing your program touches.

Closing

closesocket(s) releases the socket. If unsent data is still buffered, Windows keeps trying to deliver it in the background. To tell the other side "I have finished sending" while still receiving its reply, call shutdown(s, SD_SEND) first; the other side's recv then returns 0 once it has read everything (lesson 2.02).
