Addresses, Subnets and NAT

lesson 1.022 of 5 in milestone 15 min1 practice task

IPv4 addresses as 32-bit numbers, prefixes and subnet masks in CIDR notation, network and broadcast addresses, the private ranges, how NAT lets a whole home share one public address, ports, and a first look at IPv6.

An IPv4 address is a 32-bit number

192.168.1.20 is four bytes written in decimal and separated by dots. As one number it is 0xC0A80114, or 3 232 235 796. Every device on an IPv4 network has one (per network interface), and every IP packet carries a source and a destination address.

Thinking of addresses as numbers makes everything else simple: comparing, masking and counting them is integer arithmetic.

Networks and prefixes

Addresses are grouped into networks (subnets). The first part of an address identifies the network; the rest identifies a device on it. How many bits are the network part is the prefix length, written after a slash in CIDR notation:

Text
192.168.1.0/24     the first 24 bits are the network: 192.168.1.x
                   devices 192.168.1.1 to 192.168.1.254
10.0.0.0/8         the first 8 bits: 10.x.x.x, about 16.7 million addresses

The same thing as a subnet mask is a 32-bit number with the prefix's bits set: /24 is 255.255.255.0, /20 is 255.255.240.0.

For a network N/p:

Computed as
mask the top p bits set
network address any address in it & mask
broadcast address network address `
usable hosts 2^(32−p) − 2 (the network and broadcast addresses are reserved)
"is address A in it?" (A & mask) == network

So 192.168.1.77 is in 192.168.1.0/24 because 0xC0A8014D & 0xFFFFFF00 == 0xC0A80100.

Private ranges and NAT

Three ranges are reserved for private networks and never appear on the public internet:

Range CIDR
10.0.0.0 to 10.255.255.255 10.0.0.0/8
172.16.0.0 to 172.31.255.255 172.16.0.0/12
192.168.0.0 to 192.168.255.255 192.168.0.0/16

Your home devices almost certainly have addresses in one of them. They reach the internet through a router doing network address translation (NAT): it rewrites each outgoing packet's private source address and port to its own single public address and a port it picks, remembers the mapping, and rewrites replies back. To the rest of the internet, the whole household is one address.

NAT has a consequence every multiplayer and peer-to-peer program meets: a device behind NAT can make outgoing connections freely, but nothing outside can start a connection to it, because the router has no mapping for an unsolicited packet. That is why games use servers with public addresses, or relay and "hole punching" techniques.

Two more special ranges: 127.0.0.0/8 is loopback (your own machine), and 169.254.0.0/16 is link-local (a device that failed to get an address).

Ports

An IP address reaches a machine; a port (a 16-bit number, 0 to 65535) reaches one program on it. A connection is identified by the full five-tuple: protocol, source address, source port, destination address, destination port. Servers listen on well-known ports (80 for HTTP, 443 for HTTPS, 53 for DNS); clients get a temporary ephemeral port from the operating system (on Windows 49152 to 65535).

IPv6

IPv4 has only about 4.3 billion addresses, which ran out years ago; NAT is partly a workaround. IPv6 addresses are 128 bits, written as eight groups of four hex digits, with leading zeros dropped and one run of zero groups shortened to :::

Text
2001:0db8:0000:0000:0000:ff00:0042:8329  =  2001:db8::ff00:42:8329
::1                                          loopback
fe80::/10                                    link-local

The same prefix arithmetic applies, on 128 bits. Most modern networks run both versions side by side; code that uses getaddrinfo (lesson 2.01) handles both without caring which it got.
