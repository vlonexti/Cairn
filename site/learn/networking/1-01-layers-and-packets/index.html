Layers and Packets

lesson 1.011 of 5 in milestone 15 min1 practice task

Data crosses a network in packets, each wrapped in the headers of several layers - link, internet, transport and application. Encapsulation, what each layer is responsible for, the MTU that limits packet size, and why the layering lets you ignore most of the network most of the time.

Packets

A network does not carry your data as one continuous stream. It carries packets: chunks of at most around 1500 bytes, each travelling independently. A web page, a game update or a file is cut into packets, sent, and put back together at the other end.

Each packet carries headers: small blocks of information that tell each part of the network what to do with it. Different headers are added by different layers of software, each solving one problem and trusting the layer below to solve the rest.

The four layers

The internet's design (the TCP/IP model) has four layers:

Layer Job Examples Addresses
Application what the data means HTTP, DNS, your game's protocol URLs, names
Transport which program gets it; optionally reliability TCP, UDP ports
Internet getting it across networks to the right machine IPv4, IPv6 IP addresses
Link getting it to the next device on this network Ethernet, Wi-Fi MAC addresses

(The older seven-layer OSI model splits some of these further; "layer 4" for transport and "layer 3" for IP come from it, and you will hear those numbers often.)

Encapsulation

Sending, each layer wraps what it receives from the layer above in its own header:

Text
application:                                    [ HTTP request: GET / HTTP/1.1 ... ]
transport:                       [ TCP header ][ HTTP request ...                  ]
internet:            [ IP header ][ TCP header ][ HTTP request ...                  ]
link:   [ Ethernet ][ IP header ][ TCP header ][ HTTP request ...                  ][ FCS ]

Receiving, each layer reads and removes its own header and passes the rest up. The Ethernet card checks the frame and hands the IP packet to the operating system; IP checks the destination address and hands the TCP segment to TCP; TCP finds which program owns the destination port and hands it the data.

Each layer only looks at its own header. A router in the middle of the internet reads the IP header to decide where to send the packet next, and never looks at TCP or HTTP. Your program reads HTTP and never sees Ethernet. That separation is what lets the internet run every kind of application over every kind of cable and radio.

Overhead

Headers cost bytes. A typical TCP packet over Ethernet carries:

Header Bytes
Ethernet 14 (plus 4 of checksum at the end)
IPv4 20 (IPv6: 40)
TCP 20 (often 32 with options)
UDP instead of TCP 8

For a large transfer this is a few percent. For a game sending 40-byte updates 60 times a second, the headers are bigger than the data, which is one reason game protocols pack data tightly and batch updates.

The MTU

Each link has a maximum transmission unit (MTU): the largest IP packet it carries in one piece. For Ethernet it is 1500 bytes. So the most application data one TCP packet can carry is 1500 − 20 (IP) − 20 (TCP) = 1460 bytes (the TCP maximum segment size, MSS). For UDP it is 1500 − 20 − 8 = 1472.

Some paths have smaller MTUs (VPNs and some tunnels add headers of their own). A packet too large for a link must be fragmented into pieces or dropped; fragmentation is slow and fragile, so TCP adjusts its segment size to the path, and protocols over UDP keep packets comfortably small (around 1200 bytes is a common safe size).
