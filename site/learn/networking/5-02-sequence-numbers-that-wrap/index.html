Sequence Numbers That Wrap

lesson 5.022 of 5 in milestone 55 min1 practice task

Numbering packets with a small counter that wraps around - comparing sequence numbers correctly across the wrap with half-range arithmetic, the signed difference between two numbers, and discarding duplicates and stale packets with a sliding window.

A number on every packet

Every packet carries a sequence number that the sender increments each time. Receivers use it to tell which packet is newer, to drop duplicates, and (next lesson) to say which ones arrived.

Bytes on the wire are precious, so the number is usually 16 bits. At 60 packets a second it wraps from 65 535 back to 0 every 18 minutes. Comparing with a plain a > b fails at the wrap: packet 2 is newer than packet 65 534, though 2 < 65 534.

Half-range comparison

Treat the numbers as points on a circle. a is newer than b if going forward from b to a is less than half way round:

C++
bool sequenceGreater(std::uint16_t a, std::uint16_t b)
{
    return (a > b && a - b < 32768) || (a < b && b - a > 32768);
}

An equivalent and shorter form uses the signed difference: subtract in 16-bit unsigned arithmetic and reinterpret as a signed 16-bit number.

C++
int sequenceDifference(std::uint16_t a, std::uint16_t b)
{
    return static_cast<std::int16_t>(static_cast<std::uint16_t>(a - b));
}
C++
sequenceDifference(5, 3)         //  2: 5 is two packets newer
sequenceDifference(2, 65534)     //  4: across the wrap
sequenceDifference(65534, 2)     // -4

Exactly half way round (a difference of 32 768) is ambiguous; it never matters in practice because no protocol keeps that many packets in flight. This is the same "serial number arithmetic" TCP uses for its 32-bit sequence numbers (RFC 1982).

Duplicates and stale packets

Because UDP may duplicate and reorder, a receiver keeps a little history:

  • the latest sequence number seen so far;
  • which of the recent numbers before it have also been seen, usually as a bit per number for the last 32 to 256.

When a packet arrives:

Difference from latest Meaning Action
positive newer than anything seen accept; slide the window forward
zero, or already marked duplicate drop
negative, inside the window late but new accept, mark it seen
negative, beyond the window too old to judge drop

For newest-wins data (positions), you can go further and ignore any packet older than the latest, since its state is stale anyway; reliable messages inside it must still be processed, which is why the decision belongs to each kind of data, not to the packet.
