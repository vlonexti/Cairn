URLs and Encoding

lesson 3.033 of 5 in milestone 35 min1 practice task

The parts of a URL - scheme, host, port, path, query and fragment - percent-encoding and which characters need it, query strings and form encoding, and resolving a relative link against a base URL.

The parts of a URL

Text
https://xenon.justloofy.dev:8443/courses/net%20working?tab=lessons&sort=new#part-2
\___/   \_________________/ \__/\____________________/ \__________________/ \____/
scheme          host        port        path                  query         fragment
Part Notes
scheme http, https, ws, ftp... case-insensitive
host a name or address; IPv6 addresses go in brackets: http://[::1]:8080/
port optional; defaults to 80 for http, 443 for https
path starts with /; / if absent
query after ?; usually name=value pairs joined with &
fragment after #; never sent to the server, used by the browser to jump within a page

A URL can also contain user:password@ before the host. Never use it: the credentials end up in logs and histories.

For an HTTP request, the client sends the path and query as the request target (GET /courses/net%20working?tab=lessons HTTP/1.1) and the host and port in the Host header.

Percent-encoding

URLs may only contain a limited set of characters. Anything else is percent-encoded: each byte of its UTF-8 encoding written as % and two hex digits.

Text
space        -> %20
é (C3 A9)    -> %C3%A9
/            -> %2F   (when it is part of a name, not a separator)

The characters that never need encoding are the unreserved ones: letters, digits, -, ., _ and ~. Others are reserved because they have meaning in URLs (/ ? # & = : @ and more); they must be encoded when used as data. When building a URL from user input, encode every part that comes from outside; when parsing one, decode each part after splitting it at its separators, so an encoded %2F stays part of a name instead of becoming a path separator.

Decoding must reject broken sequences: a % not followed by two hex digits. Accepting them sloppily has been the cause of many security bugs (a check passes on the encoded form, then the decoded form means something else).

Query strings and forms

A query string is a list of name=value pairs separated by &. HTML forms submit their fields the same way (as the body of a POST with Content-Type: application/x-www-form-urlencoded), with one quirk: in form encoding a space is written +, so + itself must be sent as %2B. When parsing form data or queries, turn + into a space before percent-decoding.

Text
q=networking+basics&level=2&tag=c%2B%2B   ->   q = "networking basics", level = "2", tag = "c++"

The same name can appear several times (tag=a&tag=b); keep all of them in order.

Relative URLs

Links in a page are often relative to the page's own URL (the base). Resolving href against https://site/a/b/page.html:

href Result
other.html https://site/a/b/other.html (same folder)
../up.html https://site/a/up.html
/root.html https://site/root.html (from the host)
//cdn.site/x.js https://cdn.site/x.js (same scheme)
https://other/x itself: already absolute
?page=2 https://site/a/b/page.html?page=2

The path rules are the same . and .. folding as file paths (the IPC course's lesson 6.01), with / instead of \.
