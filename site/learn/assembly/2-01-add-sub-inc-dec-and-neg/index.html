add, sub, inc, dec and neg

lesson 2.011 of 5 in milestone 25 min1 practice task

add and sub combine two operands into the first, inc and dec add or take away one, and neg flips the sign. Results wrap around at the register's size, so 32-bit arithmetic wraps at 2 to the 32 and also clears the upper half. The same add instruction serves signed and unsigned numbers, because two's complement makes them the same bits.

Two operands, one result

x86 arithmetic overwrites its first operand:

Instruction Does
add rax, rbx rax = rax + rbx
sub rax, 5 rax = rax − 5
inc rcx rcx = rcx + 1
dec rcx rcx = rcx − 1
neg rax rax = −rax

There is no "c = a + b" in one instruction (except with lea, lesson 4.01): copy first, then add.

Assembly
        global  _start
        section .text
_start:
        mov     rbx, 1000
        mov     rax, rbx
        add     rax, 337        ; rax = 1337
        sub     rax, 1300       ; rax = 37
        inc     rax             ; 38
        dec     rbx             ; rbx = 999
        neg     rbx             ; -999
        add     rax, rbx        ; 38 - 999 = -961
        mov     rdi, rax
        call    print_int
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Wrapping around

A register has a fixed number of bits, so results wrap around like a car's odometer. With 8 bits, 255 + 1 is 0; with 64 bits, the biggest unsigned number plus one is 0 too.

32-bit arithmetic clears the top too

Like mov, any instruction writing a 32-bit register zeroes the upper half. add eax, 1 with rax = 0x1_FFFFFFFF gives rax = 0, not 0x2_00000000. Use 64-bit registers when numbers can grow beyond about 4 billion.

One add for signed and unsigned

In two's complement (from the Fundamentals course), −1 is all 1 bits. Adding 1 to it gives all 0 bits: 0, which is right whether you read the bits as signed (−1 + 1) or unsigned (the largest value + 1, wrapping). That is the beauty of two's complement: the same add and sub work for both. Only comparisons, division and widening need to know which you mean.

Instructions with memory

Arithmetic can read or update memory directly (lesson 4.01 shows addressing):

Assembly
        add     rax, [rel total]        ; rax += the 8 bytes at total
        add     qword [rel total], 5    ; the 8 bytes at total += 5
        inc     dword [rel count]       ; the 4 bytes at count += 1

When neither operand is a register, NASM cannot tell the size, so you write it: byte, word, dword or qword. Only one operand may be in memory: add [a], [b] does not exist.
