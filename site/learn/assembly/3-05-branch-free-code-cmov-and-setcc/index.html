Branch-Free Code cmov and setcc

lesson 3.055 of 5 in milestone 35 min1 practice task

Processors guess which way each jump will go and work ahead; a wrong guess wastes many cycles. cmovcc copies a value only if a condition holds, and setcc turns a condition into a 0 or 1 byte, so simple choices need no jump at all. Compilers use them for min, max, abs and boolean results.

Why avoid jumps?

A modern processor works on many instructions at once, in a long pipeline. When it meets a conditional jump it does not wait to find out the answer: it predicts which way the jump will go and carries on working down that path. If the guess was right, nothing is lost. If wrong, all that work is thrown away, which costs around 15 to 20 cycles.

Predictors are very good at patterns (a loop that runs 1000 times is predicted right 999 times), but a jump that depends on random data is wrong about half the time. For small choices, it is better not to jump at all.

cmov: copy only if

cmovcc destination, source copies the source only when the condition holds. The conditions are the same letters as the jumps: cmove, cmovne, cmovl, cmovg, cmovb, cmova, ...

The processor always runs all three instructions; there is nothing to guess. Some useful ones:

Assembly
; abs(x)
        mov     rax, rdi
        neg     rax             ; rax = -x, and the flags say whether -x is negative
        cmovs   rax, rdi        ; if -x is negative, x was positive: use x

; clamp x to at most 100
        mov     rax, rdi
        mov     ecx, 100
        cmp     rax, rcx
        cmovg   rax, rcx

cmov cannot take a constant as its source, so put the constant in a register first, as above.

setcc: a condition as a number

setcc writes 1 or 0 into a byte register depending on the condition:

Assembly
; return (a == b)
        xor     eax, eax        ; clear all of rax first...
        cmp     rdi, rsi
        sete    al              ; ...because sete only writes al
        ret

Clear the register before the cmp: xor changes the flags, so doing it after would wreck the comparison. Then sete al writes 1 or 0 into the low byte, and the rest is already 0. (The other way is movzx eax, al after the setcc.)

Tricks with no compare at all

Some answers fall straight out of arithmetic:

Assembly
; sign(x): -1, 0 or 1
        mov     rax, rdi
        sar     rax, 63         ; -1 if negative, else 0
        xor     ecx, ecx
        test    rdi, rdi
        setg    cl              ; 1 if positive, else 0
        or      rax, rcx        ; -1, 0 or 1

; abs(x) with a mask
        mov     rax, rdi
        sar     rax, 63         ; all 1s if negative, else 0
        xor     rdi, rax        ; flip the bits if negative
        sub     rdi, rax        ; and add 1 if negative: two's complement negation
        mov     rax, rdi

When to use them

A jump is still better when the choice skips a lot of work (computing both sides costs more than a misprediction), or when the pattern is predictable. For a quick choice between two ready values, cmov or setcc wins. Compilers decide this for you at -O2, which is why you see cmov in their output so often.
