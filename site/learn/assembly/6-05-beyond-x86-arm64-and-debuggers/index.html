Beyond x86 ARM64 and Debuggers

lesson 6.055 of 5 in milestone 65 min1 practice task

ARM64, in phones and Apple-chip Macs, is a load-store design with 31 registers and fixed 4-byte instructions, so arithmetic never touches memory directly. RISC-V is a small open design built on the same ideas. A debugger such as gdb steps through instructions and shows registers and memory, and objdump shows any program's machine code.

The same ideas, another instruction set

You now know how a processor works: registers, memory, flags, jumps, a stack, a calling convention. Every other instruction set is a variation on these themes. The big one is ARM64 (AArch64): almost every phone, Apple-chip Macs, and a growing share of servers.

ARM64 at a glance

x86-64 ARM64
registers 16 general 31 general (x0 to x30, 32-bit halves w0 to w30) plus a zero register
instruction size 1 to 15 bytes always 4 bytes
memory in arithmetic yes: add rax, [rdi] no: only ldr (load) and str (store) touch memory
operands two: add rax, rbx overwrites rax three: add x0, x1, x2
return address pushed by call kept in register x30 by bl
arguments rdi, rsi, rdx, rcx, r8, r9 x0 to x7
result rax x0

The same C function, compiled by GCC for each:

C
long sum(const long *v, long n)
{
    long t = 0;
    for (long i = 0; i < n; i++) t += v[i];
    return t;
}
Assembly
; x86-64
sum:    test    rsi, rsi
        jle     .L9
        lea     rdx, [rdi+rsi*8]
        xor     eax, eax
.L8:    add     rax, QWORD PTR [rdi]
        add     rdi, 8
        cmp     rdi, rdx
        jne     .L8
        ret
.L9:    xor     eax, eax
        ret
Output
// ARM64 (GCC 15, -O2)
sum:    cmp     x1, 0
        ble     .L4
        mov     x2, x0                // the pointer
        add     x1, x0, x1, lsl 3     // end = v + n * 8 (lsl 3: shifted left by 3)
        mov     x0, 0                 // the total, in the result register
.L3:    ldr     x3, [x2], 8           // load *v, then v += 8
        add     x0, x0, x3
        cmp     x2, x1
        bne     .L3
        ret
.L4:    mov     x0, 0
        ret

The shape is identical: a test in front, a rotated loop, a moving pointer. ARM64 loads into a register first (ldr with "post-increment", moving the pointer in the same instruction), then adds.

Fixed-size instructions and load-store design make the processor's job of decoding easier, which is part of why ARM chips are so power-efficient. x86 chips do the same internally: they translate x86 instructions into simpler micro-operations.

RISC-V is a newer open instruction set in the same style, free for anyone to build: 32 registers, lw/sw to load and store, add a0, a0, a1. It appears in microcontrollers, storage drives and research chips, and anyone can design a RISC-V processor without a licence.

Debuggers

A debugger runs a program under control: stop at an instruction, step one at a time, look at registers and memory. On Linux, gdb:

Output
nasm -f elf64 -g -F dwarf program.asm -o program.o     # -g: debugging information
ld program.o -o program
gdb ./program
(gdb) layout asm            # show the instructions
(gdb) break _start          # stop at _start
(gdb) run
(gdb) stepi                 # one instruction (nexti steps over calls)
(gdb) info registers rax rbx rsp
(gdb) x/16xb $rsp           # 16 bytes at rsp, in hex
(gdb) x/s &message          # a string in memory
(gdb) backtrace             # the chain of return addresses
(gdb) continue

The demos in this course do what stepi and info registers do. On Windows, Visual Studio and WinDbg have the same features; on macOS, lldb.

Looking inside any program

objdump -d -M intel /bin/ls | less disassembles a real program: every instruction with its address and machine-code bytes. You can now read it. That is the starting point of reverse engineering, malware analysis and security research, and of understanding exactly what your own compiler produced.

Where next

  • Read compiler output for code you write in C, C++ or Rust: Compiler Explorer with -O2.
  • The Intel and AMD manuals (free) describe every instruction; Agner Fog's optimisation guides and instruction tables give real timings.
  • Write an operating system: the OSDev wiki starts from a boot sector in assembly.
  • Try ARM64 or RISC-V with QEMU, an emulator that runs other instruction sets on your computer.
