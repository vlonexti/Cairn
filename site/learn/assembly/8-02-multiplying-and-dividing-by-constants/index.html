Multiplying and Dividing by Constants

lesson 8.022 of 5 in milestone 85 min2 practice tasks

How compilers avoid slow instructions - multiplying by small constants with lea and shifts, dividing unsigned numbers by powers of two with shr, signed division by powers of two with a bias, replacing division by any constant with a multiply by a magic number and a shift, and computing remainders from the quotient.

Why avoid div?

imul takes about 3 cycles; div and idiv can take 10 to 40 or more. Division by a constant (by 10 to print a number, by 60 for minutes) is common, so compilers replace it with faster instructions. Recognising these patterns makes compiler output (lesson 6.01) readable, and lets you write them yourself.

Multiplying with lea

lea computes base + index × scale + displacement without touching memory, with a scale of 1, 2, 4 or 8. That makes small multiplications one instruction:

Assembly
        global  _start

        section .text
_start:
        mov     rbx, 7
        lea     rdi, [rbx + rbx*2]      ; 3 x
        call    print_int
        call    print_newline
        lea     rdi, [rbx + rbx*4]      ; 5 x
        call    print_int
        call    print_newline
        lea     rdi, [rbx*8 + rbx]      ; 9 x
        call    print_int
        call    print_newline
        lea     rax, [rbx + rbx*4]      ; 5 x
        lea     rdi, [rax + rax]        ; then 2 x: 10 x
        call    print_int
        call    print_newline
        mov     rdi, rbx
        shl     rdi, 4                  ; 16 x
        sub     rdi, rbx                ; 15 x
        call    print_int
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Powers of two are a shift; other constants become a short combination of lea, shl, add and sub.

Dividing by powers of two

For unsigned numbers, dividing by 2^k is shr k, and the remainder is and with 2^k − 1:

Assembly
        global  _start

        section .text
_start:
        mov     rbx, 1000
        mov     rdi, rbx
        shr     rdi, 3                  ; 1000 / 8 = 125
        call    print_int
        call    print_newline
        mov     rdi, rbx
        and     rdi, 7                  ; 1000 % 8 = 0
        call    print_int
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

For signed numbers, sar rounds towards minus infinity (−7 >> 1 is −4), but C's division rounds towards zero (−7 / 2 is −3). The fix is to add 2^k − 1 first when the number is negative:

Assembly
        global  _start

        section .text
div4:                                   ; rdi / 4, rounding towards zero like C
        mov     rax, rdi
        sar     rax, 63                 ; all 1s if negative, else 0
        and     rax, 3                  ; 3 if negative, else 0
        add     rax, rdi
        sar     rax, 2
        ret

_start:
        mov     rdi, -7
        call    div4
        mov     rdi, rax
        call    print_int               ; -1, as -7 / 4 in C
        call    print_newline
        mov     rdi, 7
        call    div4
        mov     rdi, rax
        call    print_int               ; 1
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Dividing by any constant: the magic number

To divide by 10, multiply by 2^67 / 10 (rounded up) and keep only the top bits: x / 10 = (x × 0xCCCCCCCCCCCCCCCD) >> 67. The 64-bit mul leaves the high half of the 128-bit product in rdx, which is already a shift by 64; three more give 67:

Assembly
        global  _start

        section .text
div10:                                  ; unsigned rdi / 10
        mov     rax, 0xCCCCCCCCCCCCCCCD
        mul     rdi                     ; rdx:rax = rdi * magic
        mov     rax, rdx
        shr     rax, 3
        ret

_start:
        mov     rdi, 1234567
        call    div10
        mov     rdi, rax
        call    print_int               ; 123456
        call    print_newline
        mov     rdi, -1                 ; the largest unsigned number
        call    div10
        mov     rdi, rax
        call    print_uint              ; 1844674407370955161
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

The magic number and the shift are chosen so the result is exact for every 64-bit input. Compilers compute them for any divisor; you can see them by compiling x / 7 or x / 1000 on Compiler Explorer. Signed division uses a signed magic number and a correction for negative values.

Remainders from the quotient

Once you have q = x / 10, the remainder is x − q × 10, with no second division:

Assembly
        global  _start

        section .text
_start:
        mov     rbx, 1234567
        mov     rax, 0xCCCCCCCCCCCCCCCD
        mul     rbx
        shr     rdx, 3                  ; rdx = 123456
        lea     rcx, [rdx + rdx*4]      ; q * 5
        add     rcx, rcx                ; q * 10
        mov     rdi, rbx
        sub     rdi, rcx                ; 1234567 - 1234560 = 7
        call    print_int
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

This pair is exactly what a fast "print a number" routine does for each digit (lesson 6.02's printer can use it).

Is it worth it?

Write division as div first; it is correct and clear. Change it to a multiply when it is in a hot loop and the divisor is fixed, and test the result against div for many values, including 0, 1, the largest value and numbers just around multiples of the divisor.
