System Calls write and exit

lesson 1.044 of 6 in milestone 15 min1 practice task

A program cannot touch the screen, files or the keyboard itself - it asks the operating system with the syscall instruction. On Linux the call's number goes in rax and its arguments in rdi, rsi, rdx, r10, r8 and r9, and the result comes back in rax. write (1) prints bytes, read (0) reads them, exit (60) ends the program.

Asking the operating system

Programs run in user mode, where the processor refuses to touch hardware directly. Printing, reading the keyboard, opening files, and even ending the program are done by the operating system's kernel, and a program asks for them with a system call. The syscall instruction switches the processor into the kernel, which does the work and comes back.

On 64-bit Linux:

Register Holds
rax the system call's number; afterwards, its result
rdi, rsi, rdx, r10, r8, r9 its arguments, in that order

syscall itself changes rcx and r11 (it uses them to remember where to come back to), so don't keep anything there across a system call.

The three you need

Number Name Arguments Returns
0 read file, buffer address, maximum bytes bytes read (0 at the end)
1 write file, bytes' address, how many bytes written
60 exit exit code does not return

Files are numbered: 0 is standard input, 1 standard output, 2 standard error. These are the same streams as stdin, stdout and stderr in C, whose printf ends up making exactly this write call.

Printing

Assembly
        global  _start

        section .data
greeting: db    "Hello, ", 0
name:   db      "Ada", 10
name_length equ $ - name

        section .text
_start:
        mov     eax, 1                  ; write
        mov     edi, 1                  ; standard output
        lea     rsi, [rel greeting]
        mov     edx, 7                  ; "Hello, " is 7 bytes
        syscall

        mov     eax, 1                  ; write again (rax now holds the last result, so set it again)
        mov     edi, 1
        lea     rsi, [rel name]
        mov     edx, name_length
        syscall

        mov     eax, 60
        xor     edi, edi
        syscall
  • lea rsi, [rel greeting] puts the address of the label into rsi (lesson 4.01 explains lea and rel). write needs to know where the bytes are, not what they are.
  • write prints exactly the number of bytes you ask for. Ask for 3 and you get Hel; ask for too many and you print whatever follows in memory.
  • A system call puts its result in rax, so set eax again before the next call.

Errors

When a system call fails, it returns a negative number: minus an error code. write to file 9, which is not open, returns −9 (-EBADF, "bad file descriptor"). C's library turns those into errno (from the C course). Here you can see it as an exit code:

Assembly
        global  _start
        section .data
text:   db      "lost", 10
        section .text
_start:
        mov     eax, 1
        mov     edi, 9                  ; a file that is not open
        lea     rsi, [rel text]
        mov     edx, 5
        syscall                         ; rax = -9
        neg     rax                     ; make it positive
        mov     rdi, rax                ; exit code 9
        mov     eax, 60
        syscall

Standard error

Write to file 2 instead of 1 and the text goes to standard error. On the website it still appears in the console, but it is a separate stream: running ./program > out.txt in a terminal saves only standard output.

Hundreds of system calls

Linux has over 350 system calls: open (2), close (3), mmap (9) for memory, fork (57) and execve (59) for new programs, and more. Every program, in any language, does its work through them. The command strace ./program lists each one a program makes.
