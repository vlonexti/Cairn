Jump Tables and Function Pointers

lesson 8.033 of 5 in milestone 85 min2 practice tasks

Code addresses as data - a jump table that turns a switch into one bounds check and one indirect jump, tables of function addresses, calling through a register, passing a function to another function as a callback, and dispatching commands by number; with the bounds checks that keep indirect jumps safe.

Addresses of code

A label in the text section is just an address, like a label in the data section. You can store it, load it and jump to it. That gives two powerful tools: jump tables (a fast switch) and function pointers (callbacks, plug-in functions, command tables).

A jump table

A switch with many cases on small numbers becomes a table of addresses. The code checks the range once, then jumps through the table:

Assembly
        global  _start

        section .data
names:  db      "zero", 0, "one", 0, "two", 0, "many", 0

        section .text
describe:                               ; rdi = n; prints a word for 0, 1, 2, else "many"
        cmp     rdi, 2
        ja      .many                   ; unsigned: also catches negative numbers
        lea     rax, [rel .table]
        jmp     [rax + rdi*8]
.case0: lea     rdi, [rel names]
        jmp     .print
.case1: lea     rdi, [rel names + 5]
        jmp     .print
.case2: lea     rdi, [rel names + 9]
        jmp     .print
.many:  lea     rdi, [rel names + 13]
.print: call    print_str
        call    print_newline
        ret

        section .data
        align   8
.table: dq      describe.case0, describe.case1, describe.case2

        section .text
_start:
        xor     ebx, ebx
.loop:  mov     rdi, rbx
        call    describe
        inc     rbx
        cmp     rbx, 4
        jl      .loop
        mov     rdi, -1
        call    describe
        mov     eax, 60
        xor     edi, edi
        syscall

The ja check is essential: without it, a large or negative number would read an address from past the end of the table and jump there. One unsigned comparison covers both directions, because a negative number viewed as unsigned is huge.

The local labels .case0 belong to describe, so from the data section they are written as describe.case0.

Calling through a register

call rax (or call [rax]) calls whatever address the register holds. A table of function addresses lets a number choose the function:

Assembly
        global  _start

        section .text
add_op: lea     rax, [rdi + rsi]
        ret
sub_op: mov     rax, rdi
        sub     rax, rsi
        ret
mul_op: mov     rax, rdi
        imul    rax, rsi
        ret

        section .data
        align   8
ops:    dq      add_op, sub_op, mul_op
OPS     equ     ($ - ops) / 8

        section .text
apply_op:                               ; rdi = op number, rsi = a, rdx = b; -1 for a bad op
        mov     rax, -1
        cmp     rdi, OPS
        jae     .bad
        lea     rcx, [rel ops]
        mov     rcx, [rcx + rdi*8]      ; the function's address
        mov     rdi, rsi
        mov     rsi, rdx
        jmp     rcx                     ; a tail call: its ret returns to our caller
.bad:   ret

_start:
        xor     ebx, ebx
.next:  mov     rdi, rbx
        mov     esi, 12
        mov     edx, 5
        call    apply_op
        mov     rdi, rax
        call    print_int
        call    print_newline
        inc     rbx
        cmp     rbx, 4
        jl      .next
        mov     eax, 60
        xor     edi, edi
        syscall

jmp rcx at the end is a tail call: instead of call rcx followed by ret, it jumps, and the called function's own ret goes straight back to apply_op's caller.

Callbacks

A function can take another function as an argument, as C's qsort takes a comparison. Here map applies a function to each element of an array:

Assembly
        global  _start

        section .data
values: dq      1, 2, 3, 4, 5
COUNT   equ     ($ - values) / 8

        section .text
square: mov     rax, rdi
        imul    rax, rdi
        ret

negate: mov     rax, rdi
        neg     rax
        ret

map:                                    ; rdi = array, rsi = count, rdx = function; changes the array in place
        push    rbx
        push    r12
        push    r13
        mov     rbx, rdi
        mov     r12, rsi
        mov     r13, rdx
.loop:  test    r12, r12
        jz      .done
        mov     rdi, [rbx]
        call    r13                     ; the callback, called with the element
        mov     [rbx], rax
        add     rbx, 8
        dec     r12
        jmp     .loop
.done:  pop     r13
        pop     r12
        pop     rbx
        ret

print_all:
        push    rbx
        push    r12
        lea     rbx, [rel values]
        mov     r12d, COUNT
.p:     mov     rdi, [rbx]
        call    print_int
        mov     edi, ' '
        call    print_char
        add     rbx, 8
        dec     r12
        jnz     .p
        call    print_newline
        pop     r12
        pop     rbx
        ret

_start:
        lea     rdi, [rel values]
        mov     esi, COUNT
        lea     rdx, [rel square]
        call    map
        call    print_all
        lea     rdi, [rel values]
        mov     esi, COUNT
        lea     rdx, [rel negate]
        call    map
        call    print_all
        mov     eax, 60
        xor     edi, edi
        syscall

map keeps the array pointer, the count and the callback in callee-saved registers, because the callback may change any scratch register. Three pushes plus the return address leave the stack 16-byte aligned at each call.

Safety

An indirect jump or call goes wherever the register says. Bugs (or attackers) that control that value control the program, which is why:

  • every table index is bounds-checked first, with an unsigned comparison;
  • tables of addresses live in read-only data where possible (section .rodata);
  • modern systems add protections such as Control-flow Enforcement Technology, which require indirect targets to start with an endbr64 instruction. Compilers add it for you; hand-written code that runs with those protections on needs it too.
