Data db, dw, dd, dq and equ

lesson 1.055 of 6 in milestone 15 min1 practice task

db, dw, dd and dq put 1, 2, 4 and 8-byte values into the program, stored little-endian. A label is just the address of the next byte, $ is the current address, and equ names a constant such as a length. times repeats, .bss reserves zeroed space with resb and resq, and .rodata holds data that must not change.

Defining bytes

Directive Size Example
db 1 byte db 65, "text", 10, 0
dw 2 bytes (a "word") dw 1000
dd 4 bytes (a "double word") dd 100000, -1
dq 8 bytes (a "quad word") dq 0x1122334455667788

These are not instructions: they tell the assembler to place bytes in the program file. In db, a string in quotes stands for its characters' codes, one byte each; there is no terminator unless you add 0 yourself.

The names come from the 16-bit 8086, where a "word" was 16 bits; that is why a 32-bit value is a "double word". Instructions use the same names: byte, word, dword, qword.

Little-endian

x86 stores multi-byte values lowest byte first. dd 0x11223344 becomes the bytes 44 33 22 11. The Fundamentals course has a demo of it.

Labels are addresses

A label means "the address where the next byte goes". It is not a variable and has no type or size: count: dd 5 only names the first of the four bytes. The instruction that uses it decides how many bytes to read.

$ and equ

$ is the address of the current position. $ - message, written right after the message, is "here minus where the message started": its length, worked out by the assembler.

equ gives a name to a number. It takes no space in the program; it is like #define in C:

Assembly
        global  _start

        section .data
banner: db      "*** Xenon ***", 10
banner_len equ  $ - banner
STDOUT  equ     1
SYS_WRITE equ   1
SYS_EXIT equ    60

        section .text
_start:
        mov     eax, SYS_WRITE
        mov     edi, STDOUT
        lea     rsi, [rel banner]
        mov     edx, banner_len
        syscall
        mov     eax, SYS_EXIT
        mov     edi, banner_len         ; exit code: the length, 14
        syscall

times

times count thing repeats something:

Assembly
        global  _start
        section .data
line:   times 20 db "="
        db      10
line_len equ    $ - line

        section .text
_start:
        mov     eax, 1
        mov     edi, 1
        lea     rsi, [rel line]
        mov     edx, line_len
        syscall
        mov     eax, 60
        xor     edi, edi
        syscall

The sections

Section Holds Can change
.text instructions no
.data data with starting values yes
.rodata read-only data: constant text and tables no (writing crashes)
.bss space reserved and set to zero when the program starts yes

.bss takes no room in the program file, only a note of how much to reserve. Reserve with resb (bytes), resw, resd, resq:

Assembly
        section .bss
buffer: resb    256             ; 256 bytes, all 0
counts: resq    10              ; ten 8-byte numbers, all 0

The operating system loads each section into memory with the right permissions: .text can run but not be written, .data can be written but not run. A program that writes to its own code crashes, which is a protection against attacks.
