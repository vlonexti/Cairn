Floating Point with SSE

lesson 7.011 of 5 in milestone 75 min2 practice tasks

Doubles and floats in x86-64 - the xmm registers, movsd and movss, addsd, subsd, mulsd, divsd and sqrtsd, converting with cvtsi2sd, cvttsd2si and cvtsd2si, comparing with comisd and the flags it sets, constants in .data, and the calling convention for floating-point arguments and results.

A second set of registers

Integers live in rax, rbx and friends. Floating-point numbers live in the sixteen 128-bit xmm registers, xmm0 to xmm15, and use their own instructions. Lesson 6.04 used them to process four numbers at once; this lesson uses them for one number at a time, which is how compilers do ordinary double arithmetic. Instructions ending in sd work on one scalar double (64 bits), those ending in ss on one scalar single (a 32-bit float).

Instruction Meaning
movsd xmm0, [rel x] / movsd [rel x], xmm0 load or store a double
movsd xmm1, xmm0 copy between xmm registers
addsd, subsd, mulsd, divsd arithmetic: addsd xmm0, xmm1 is xmm0 += xmm1
sqrtsd xmm0, xmm1 xmm0 = sqrt(xmm1)
minsd, maxsd smaller, larger
cvtsi2sd xmm0, rax integer to double
cvttsd2si rax, xmm0 double to integer, truncating (dropping the fraction)
cvtsd2si rax, xmm0 double to integer, rounding to the nearest (ties to even)
comisd xmm0, xmm1 compare, setting the flags
pxor xmm0, xmm0 make zero

There is no "load an immediate" for floats: constants go in .data (or .rodata) and are loaded from memory.

A first calculation

Assembly
        global  _start
        section .data
radius: dq      2.5
pi:     dq      3.141592653589793
hundred: dq     100.0

        section .text
_start:
        movsd   xmm0, [rel radius]
        mulsd   xmm0, xmm0              ; r * r
        mulsd   xmm0, [rel pi]          ; pi * r * r = 19.6349...
        mulsd   xmm0, [rel hundred]     ; two decimals as a whole number
        cvtsd2si rdi, xmm0              ; 1963 (rounded)
        call    print_int
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

dq 2.5 stores the 8-byte double for 2.5; NASM knows a number with a decimal point is floating point.

Integers in, integers out

Converting is the bridge between the two worlds. The average of integers, for example, is computed in doubles and converted back:

Assembly
        global  _start
        section .data
values: dq      4, 9, 10
        section .text

; average_x10: rdi = an array of 8-byte integers, rsi = count (>= 1).
; Returns the average times 10, truncated: [4, 9, 10] gives 76 (7.666...).
average_x10:
        pxor    xmm0, xmm0              ; the sum
        xor     ecx, ecx
.loop:  cmp     rcx, rsi
        jae     .done
        cvtsi2sd xmm1, qword [rdi + rcx*8]
        addsd   xmm0, xmm1
        inc     rcx
        jmp     .loop
.done:  cvtsi2sd xmm1, rsi
        divsd   xmm0, xmm1              ; the average
        mov     eax, 10
        cvtsi2sd xmm1, rax
        mulsd   xmm0, xmm1
        cvttsd2si rax, xmm0             ; drop the fraction
        ret

_start:
        lea     rdi, [rel values]
        mov     esi, 3
        call    average_x10
        mov     rdi, rax
        call    print_int               ; 76
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Note cvtsi2sd xmm1, qword [...]: the size has to be stated when the source is memory.

Rounding: truncate or round?

cvttsd2si always cuts towards zero: 7.9 becomes 7 and −7.9 becomes −7. cvtsd2si uses the current rounding mode, which is round to nearest, ties to even unless a program changes it: 7.5 becomes 8, 6.5 becomes 6, −3.5 becomes −4. Ties to even avoids the steady upward drift that "always round .5 up" causes over many operations.

Comparing

comisd xmm0, xmm1 compares two doubles and sets the flags like an unsigned comparison: use ja, jae, jb, jbe, je (not jg and jl). If either value is NaN the result is "unordered", which sets the parity flag (jp).

Assembly
        comisd  xmm0, xmm1
        jp      .not_a_number       ; NaN involved
        jb      .smaller            ; xmm0 < xmm1

maxsd and minsd often replace the comparison entirely.

The calling convention

In the System V convention (lesson 5.02), the first eight floating-point arguments arrive in xmm0 to xmm7, separately from the integer registers, and a floating-point result is returned in xmm0. double scale(long n, double factor) gets n in rdi and factor in xmm0. All xmm registers are caller-saved: any call may change them.
