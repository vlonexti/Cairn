Registers

lesson 1.022 of 6 in milestone 15 min1 practice task

Registers are the processor's own tiny, fast storage - sixteen 64-bit general-purpose ones on x86-64, plus rip (the next instruction) and rflags. The low 32, 16 and 8 bits of each have their own names, such as eax, ax and al. Writing a 32-bit register clears the top half of the 64-bit one; writing 8 or 16 bits does not.

Storage inside the processor

Memory is big but, by the processor's standards, slow: reading it can take a hundred cycles. Registers are a handful of storage slots inside the processor itself, read and written in a fraction of a cycle. Almost every instruction works on registers, so programs constantly move values from memory into registers, work on them, and store the results back.

x86-64 has 16 general-purpose registers, each 64 bits:

Register Traditional use
rax accumulator: results, return values, system call numbers
rbx base: a general register that functions keep safe
rcx counter: loop counts, shift counts, 4th argument
rdx data: the high half in multiply and divide, 3rd argument
rsi, rdi source and destination index: the 2nd and 1st arguments
rbp base pointer: the stack frame (lesson 5.03)
rsp stack pointer: the top of the stack. Leave it alone for now
r8 to r15 eight more, added when x86 went 64-bit

The "traditional uses" come from the 1970s Intel 8086. Today most instructions work on any register, but some conventions (which registers hold arguments, which ones functions must keep) matter a lot, as module 5 shows.

Two special registers cannot be used directly: rip, the instruction pointer, holds the address of the next instruction, and rflags holds the flags that comparisons set (lesson 2.04).

Smaller views of the same register

Each register has names for its lower parts, a history of how x86 grew from 16 to 32 to 64 bits:

64 bits low 32 low 16 low 8
rax eax ax al
rbx ebx bx bl
rcx ecx cx cl
rdx edx dx dl
rsi esi si sil
rdi edi di dil
rbp ebp bp bpl
rsp esp sp spl
r8 r8d r8w r8b
... r15 r15d r15w r15b

eax is not a separate register: it is the bottom 32 bits of rax. (There are also ah, bh, ch, dh for bits 8 to 15 of the first four, a leftover you will rarely need.)

  1. mov al, 0xAA changes only the lowest byte.
  2. mov ax, 0xBBBB changes only the lowest 16 bits.
  3. mov eax, 0xCC sets the low 32 bits and clears the upper 32.
  4. mov rax, -1 sets all 64 bits to 1.
The 32-bit rule

Writing a 32-bit register (eax, r9d) always zeroes the top 32 bits of the 64-bit register. Writing an 8- or 16-bit one leaves the rest alone. That is why compilers so often write mov eax, 5 instead of mov rax, 5: it does the same thing with a shorter instruction.

Values have no types

A register holds 64 bits, nothing more. Whether those bits are a number, a character, an address or a negative number is up to the instructions you use on them. -1 and 18446744073709551615 are the same 64 bits (all 1s, in two's complement, from the Fundamentals course): add does not care, but comparisons and divisions come in signed and unsigned versions (lesson 3.03).
