call and ret

lesson 5.011 of 5 in milestone 55 min1 practice task

call pushes the address of the next instruction onto the stack and jumps to the function; ret pops that address back into rip. That is all a function call is. Because the return address lives on the stack, a function must pop exactly what it pushed before ret, and functions can call other functions as deep as the stack allows.

Two instructions

You have used call print_int since module 1. Here is what it does:

Instruction Same as
call label push the address of the next instruction, then jmp label
ret pop an address into rip: jump back to it

The pushed address is the return address: where to carry on afterwards. Nothing else happens. There are no parameters, no local variables and no return values in the hardware: those are all conventions built from registers and the stack.

Writing your own functions

Assembly
        global  _start
        section .text

; square: rdi = x. Returns x * x in rax.
square:
        mov     rax, rdi
        imul    rax, rdi
        ret

; sum_of_squares: rdi = a, rsi = b. Returns a*a + b*b.
sum_of_squares:
        push    rbx
        push    r12
        mov     r12, rsi                ; keep b: square may change rsi
        call    square                  ; a * a (a is already in rdi)
        mov     rbx, rax
        mov     rdi, r12
        call    square                  ; b * b
        add     rax, rbx
        pop     r12
        pop     rbx
        ret

_start:
        mov     edi, 3
        mov     esi, 4
        call    sum_of_squares          ; 25
        mov     rdi, rax
        call    print_int
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall
  • A function is a label, instructions, and ret. Write a comment saying what goes in and what comes out: nothing else will tell the reader.
  • Functions can be anywhere in .text; the program still starts at _start. Make sure execution cannot "fall into" a function by accident.
  • sum_of_squares calls square, so it keeps what it needs in rbx and r12, and saves the caller's values of those first.

The return address must be on top

When ret runs, whatever is on top of the stack is taken as the return address. If a function pushed something and forgot to pop it, ret jumps to that value instead, which is almost always a crash:

Assembly
broken:
        push    rbx
        ; ... forgot pop rbx ...
        ret                     ; "returns" to the address that rbx held

This is also how a classic stack buffer overflow attack works: a program writes past a local buffer on the stack, over the return address, and ret jumps wherever the attacker chose. Modern systems defend with stack canaries, non-executable stacks and address randomisation.

Calls inside calls

Each call pushes another return address, so calls nest naturally: _start calls sum_of_squares, which calls square, and each ret goes back exactly one level. The stack holds the chain of "where to go back to", which is what a debugger shows as the backtrace.
