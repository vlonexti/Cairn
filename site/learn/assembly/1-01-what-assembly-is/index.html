What Assembly Is

lesson 1.011 of 6 in milestone 15 min1 practice task

A processor runs machine code - numbers that each mean one small instruction. Assembly gives every instruction a name, and an assembler turns the names back into the numbers. This course writes x86-64 assembly in Intel syntax with NASM, for Linux. A program has sections for data and code, labels that name addresses, and starts at _start.

The processor's own language

A processor does not understand C or Python. It runs machine code: bytes in memory, each group of them one small instruction such as "add these two registers" or "jump to that address". The bytes 48 01 d8, for example, tell an x86-64 processor to add rbx to rax.

Nobody wants to write bytes by hand, so each instruction has a short name, a mnemonic, and a program called an assembler translates the names into bytes:

Assembly Machine code Means
mov eax, 1 b8 01 00 00 00 put 1 in the register eax
add rax, rbx 48 01 d8 rax = rax + rbx
ret c3 return from a function

One line of assembly is one instruction. There is no if, no for, no variables with types: only what the hardware does. Every language you have used is turned into these instructions in the end, by a compiler (C, Rust), or by an interpreter that is itself made of them (Python).

Which assembly?

Every processor family has its own instruction set, so there are many assembly languages:

Family Found in
x86-64 (also called x64, AMD64) most PCs, laptops and servers
ARM64 (AArch64) phones, tablets, Apple-chip Macs, many servers
RISC-V a newer open design, in microcontrollers and growing

This course teaches x86-64, written in Intel syntax (mov eax, 1: destination first), with the NASM assembler, for Linux. Lesson 6.05 compares ARM64. The ideas carry over to all of them.

Why learn assembly?

Few programs are written in assembly today, but reading it is a superpower: you see what your C, C++ or Rust really does, how fast it can be, why a crash happened, and how operating systems, debuggers, compilers and security exploits work. It also makes pointers, the stack and memory obvious forever.

A whole program

Here is a complete program. Press Run:

Assembly
        global  _start

        section .data
message: db     "Hello from assembly!", 10
length  equ     $ - message

        section .text
_start:
        mov     eax, 1              ; system call 1: write
        mov     edi, 1              ; to file 1: standard output
        lea     rsi, [rel message]  ; the address of the bytes
        mov     edx, length         ; how many bytes
        syscall                     ; ask Linux to do it

        mov     eax, 60             ; system call 60: exit
        xor     edi, edi            ; with exit code 0
        syscall

Every part is explained in the next lessons, but you can read the shape already:

  • ; starts a comment, to the end of the line.
  • section .data holds data; section .text holds the instructions (the "text" of the program).
  • A name followed by a colon, like message: or _start:, is a label: a name for the address where the next byte goes.
  • db ("define bytes") puts bytes into the program: the letters of the message, then 10, the new line character.
  • _start is where the program begins, and global _start makes that name visible to the linker, which builds the final program file and needs to know where it starts.
  • The instructions are indented by convention; labels are not.

No safety net

A C program that reaches the end of main returns to the C library, which exits for you. An assembly program has no one to return to. If you leave out the exit system call at the end, the processor keeps running whatever bytes come next in memory, and the program crashes with a segmentation fault. Try it: delete the last three lines and run.

How the website runs it

The website sends your program to Compiler Explorer, which assembles it with NASM into an object file, links it with ld, and runs it on a 64-bit Linux machine, exactly like these commands:

Output
nasm -f elf64 hello.asm -o hello.o
ld hello.o -o hello
./hello

elf64 is the format Linux uses for programs: ELF, the Executable and Linkable Format.
