Working with C

lesson 5.055 of 5 in milestone 55 min1 practice task

Assembly functions that follow the calling convention can be called from C, and C functions from assembly, using global and extern and a linker. int values live in the low 32 bits with undefined upper bits. Windows x64 uses rcx, rdx, r8 and r9 with 32 bytes of shadow space and different saved registers. GCC's inline asm puts single instructions inside C.

Assembly called from C

Because your functions follow the System V convention, a C program can call them. The assembly side makes the name visible to the linker with global; the C side declares the prototype:

Assembly
; mathlib.asm
        global  add_scaled
        section .text
; long add_scaled(long a, long b, long scale): a + b * scale
add_scaled:
        mov     rax, rsi
        imul    rax, rdx
        add     rax, rdi
        ret
C
// main.c
#include <stdio.h>

long add_scaled(long a, long b, long scale);   // written in assembly

int main(void)
{
    printf("%ld\n", add_scaled(1, 2, 10));     // 21
    return 0;
}
Output
nasm -f elf64 mathlib.asm -o mathlib.o
gcc main.c mathlib.o -o app

That is how the hot loops of codecs, crypto libraries and game engines are written: most of the program in C, a few functions in hand-tuned assembly.

C called from assembly

The other way round, extern declares a name that another file defines, and the program is linked with the C library (so it starts at C's main rather than _start):

Assembly
        extern  printf
        global  main
        section .data
format: db      "%d squared is %d", 10, 0
        section .text
main:
        push    rbx                     ; also aligns the stack to 16
        mov     ebx, 12
        lea     rdi, [rel format]
        mov     esi, ebx
        imul    ebx, ebx
        mov     edx, ebx
        xor     eax, eax                ; variadic functions: al = how many vector registers are used
        call    printf
        xor     eax, eax                ; return 0 from main
        pop     rbx
        ret

Built with gcc program.o -o program. The website links assembly without the C library, which is why the course uses system calls and Xenon's routines instead.

int is 32 bits

C's int is 32 bits, so an int argument is in edi and an int result in eax. The convention says nothing about the upper 32 bits of the register: they may hold anything. So:

  • Read int arguments through the 32-bit names (edi, esi), never the full register, unless you extend them first: movsxd rax, edi for a signed int, mov eax, edi for an unsigned.
  • char and short arguments are in dil, di and so on.

C compilers rely on this, which is why their output is full of movsxd and 32-bit instructions.

You can see C do it

This C function contains one assembly instruction, written with GCC's inline assembly. Run it (it is C, compiled with GCC):

C
#include <stdio.h>

long times_three(long x)
{
    long result;
    __asm__("lea (%1,%1,2), %0" : "=r"(result) : "r"(x));   // GCC's own (AT&T) syntax
    return result;
}

int main(void)
{
    printf("%ld\n", times_three(14));
    return 0;
}

Inline assembly uses GCC's AT&T syntax by default (source first, % before registers), and the : "=r"(result) : "r"(x) parts tell the compiler which registers to use. It is handy for a single special instruction; for anything longer, a separate .asm file is clearer.

Windows does it differently

The Microsoft x64 convention, used by Windows, differs in the details:

System V (Linux, macOS) Microsoft x64 (Windows)
integer arguments rdi, rsi, rdx, rcx, r8, r9 rcx, rdx, r8, r9
callee-saved rbx, rbp, r12 to r15 the same plus rdi, rsi and xmm6 to xmm15
before a call 32 bytes of shadow space reserved on the stack for the callee
red zone 128 bytes none
long 64 bits 32 bits

Same instructions, different agreement: code written for one convention cannot simply be called with the other. (The website's C++ course compiles with MSVC by default, which follows the Windows convention.)
