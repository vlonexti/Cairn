Recursion

lesson 5.044 of 5 in milestone 55 min1 practice task

A recursive function calls itself, and each call has its own frame, so it works like any other call - as long as values needed after the inner call are saved first. Every level costs stack space, a base case stops the descent, and recursion too deep runs off the end of the stack and crashes.

Nothing special

To the processor, a function calling itself is just another call: a new return address on the stack, and the same code running again with new register values. The only thing to get right is the usual rule: anything needed after the call must survive it.

Assembly
        global  _start
        section .text

; factorial: rdi = n (0 to 20). Returns n!.
factorial:
        cmp     rdi, 1
        jg      .recurse
        mov     eax, 1                  ; the base case: 0! = 1! = 1
        ret
.recurse:
        push    rbx
        mov     rbx, rdi                ; keep n: the inner call changes rdi
        lea     rdi, [rdi - 1]
        call    factorial               ; rax = (n - 1)!
        imul    rax, rbx                ; n * (n - 1)!
        pop     rbx
        ret

_start:
        mov     edi, 10
        call    factorial
        mov     rdi, rax
        call    print_int               ; 3628800
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Each level saves the caller's rbx, then uses rbx for its own n. When the inner call returns, that level's n is still in rbx, because the inner call saved and restored it. Ten levels deep, there are ten saved rbx values and ten return addresses on the stack.

Two calls: Fibonacci

Assembly
; fib: rdi = n. Returns the nth Fibonacci number: fib(0) = 0, fib(1) = 1.
fib:
        cmp     rdi, 1
        jg      .recurse
        mov     rax, rdi                ; fib(0) = 0, fib(1) = 1
        ret
.recurse:
        push    rbx
        push    r12
        sub     rsp, 8                  ; keep rsp aligned for the calls
        mov     rbx, rdi                ; n
        lea     rdi, [rbx - 1]
        call    fib                     ; fib(n - 1)
        mov     r12, rax                ; keep it across the second call
        lea     rdi, [rbx - 2]
        call    fib                     ; fib(n - 2)
        add     rax, r12
        add     rsp, 8
        pop     r12
        pop     rbx
        ret

The first result must survive the second call, so it goes in r12. This version makes about 2ⁿ calls; a loop does it in n steps, which is why recursion is not always the right tool.

How deep can it go?

The main stack on Linux is usually 8 MB. A frame of 32 bytes allows about 250,000 levels; past that, the next push writes below the stack's end, the processor faults, and the program dies with a segmentation fault: a stack overflow. Some languages turn tail calls (a call that is the last thing a function does) into jumps so they need no extra stack; C and assembly do so only when the optimiser chooses to, or when you write jmp yourself.
