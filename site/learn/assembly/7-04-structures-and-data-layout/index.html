Structures and Data Layout

lesson 7.044 of 5 in milestone 75 min2 practice tasks

Records in assembly - NASM's struc and endstruc for field offsets, istruc and at for initialised records, reaching fields through a pointer, arrays of structures and the index arithmetic they need, matching a C struct's layout and padding, and structure of arrays versus array of structures.

A struct is offsets

To the processor, a C struct is just a block of bytes, and each field is a fixed offset from its start. p->hp is "load from the address in p plus the offset of hp". In assembly you could write the numbers yourself ([rdi + 8]), but names are far easier to read and to change.

struc and endstruc

NASM's struc defines a list of field offsets and the total size, without reserving any memory:

Assembly
struc player
    .id:      resq 1        ; offset 0, 8 bytes
    .hp:      resq 1        ; offset 8
    .score:   resq 1        ; offset 16
    .name:    resb 16       ; offset 24, 16 bytes
endstruc                    ; defines player_size = 40

Now player.hp is the number 8 and player_size is 40. Fields are reached through a pointer:

Assembly
        mov     rax, [rdi + player.score]       ; rdi points at a player
        add     qword [rdi + player.hp], 10     ; heal by 10

istruc: a filled-in record

istruc lays out an actual record in the data section, with at placing each value at its field:

Assembly
        global  _start

struc point
    .x:     resq 1
    .y:     resq 1
endstruc

        section .data
corner: istruc point
            at point.x, dq 3
            at point.y, dq 4
        iend

        section .text
_start:
        lea     rbx, [rel corner]
        mov     rax, [rbx + point.x]
        imul    rax, rax
        mov     rcx, [rbx + point.y]
        imul    rcx, rcx
        add     rax, rcx                ; x*x + y*y
        mov     rdi, rax
        call    print_int               ; 25
        call    print_newline
        mov     rdi, point_size
        call    print_int               ; 16
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Arrays of structures

In an array of records, element i starts at base + i * size. With a size of 1, 2, 4 or 8 the addressing mode can do the multiplication; other sizes need an imul (or a running pointer that adds the size each time):

Assembly
        global  _start

struc item
    .price: resq 1
    .count: resq 1
    .flags: resq 1
endstruc

        section .data
stock:  dq      250, 4, 0               ; three items of three qwords each
        dq      1000, 1, 1
        dq      75, 12, 0

        section .text
; stock_value: rdi = an array of items, rsi = how many. Returns the sum of price * count.
stock_value:
        xor     eax, eax
.loop:  test    rsi, rsi
        jz      .done
        mov     rcx, [rdi + item.price]
        imul    rcx, [rdi + item.count]
        add     rax, rcx
        add     rdi, item_size          ; on to the next record
        dec     rsi
        jmp     .loop
.done:  ret

_start:
        lea     rdi, [rel stock]
        mov     esi, 3
        call    stock_value
        mov     rdi, rax
        call    print_int               ; 250*4 + 1000*1 + 75*12 = 2900
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Matching C's layout

To share a struct with C (lesson 5.05), your offsets must match the C compiler's, padding included (C course lesson 7.02). For struct { char tag; double value; int count; } on x86-64, C puts value at 8 (after 7 padding bytes) and count at 16, and the size is 24. Write the padding into your struc, or use alignb:

Assembly
struc reading
    .tag:    resb 1
             alignb 8        ; pad to the next multiple of 8
    .value:  resq 1          ; offset 8, like C
    .count:  resd 1          ; offset 16
             alignb 8
endstruc                     ; reading_size = 24

Array of structures or structure of arrays?

An array of structures (AoS) keeps each record together: good when code uses all the fields of one record at a time. A structure of arrays (SoA) keeps each field in its own array: good when a loop uses one field of every record, because the values it needs are next to each other in memory (the cache works better) and SIMD can process several at once (lesson 6.04). Games often keep positions, velocities and health in separate arrays for exactly this reason.
