Stack Frames and Locals

lesson 5.033 of 5 in milestone 55 min1 practice task

A function's stack frame holds its return address, saved registers and local variables. The classic prologue pushes rbp and copies rsp into it, so locals sit at fixed offsets like [rbp - 8] however the stack moves; the epilogue undoes it with leave and ret. Optimised code often skips rbp and addresses locals from rsp.

A frame per call

Each call gets its own region of the stack, its frame: the return address call pushed, the callee-saved registers the function saved, and room for local variables that do not fit in registers (arrays, buffers, values kept across calls).

The prologue and epilogue

The traditional frame uses rbp as a fixed anchor:

Assembly
my_function:
        push    rbp             ; save the caller's rbp
        mov     rbp, rsp        ; rbp = the frame's base, fixed from now on
        sub     rsp, 32         ; room for 32 bytes of locals: [rbp - 32] to [rbp - 1]

        mov     qword [rbp - 8], 0      ; a local variable
        lea     rdi, [rbp - 32]         ; the address of a local buffer
        ; ... the body: pushes and calls can move rsp, rbp stays put ...

        leave                   ; mov rsp, rbp  then  pop rbp
        ret
Offset from rbp Holds
[rbp + 16], [rbp + 24]... the 7th, 8th... arguments, if any, pushed by the caller
[rbp + 8] the return address
[rbp] the caller's saved rbp
[rbp - 8] and below this function's locals

Each frame's saved rbp points at the frame before it, so the frames form a linked list up the stack. Debuggers and profilers follow that chain to print a backtrace.

Keep sub rsp a multiple of 16 (after push rbp the stack is aligned again), and call stays aligned.

A local buffer

A function can build text in a buffer on its own stack, as print_uint does. This one writes a number's digits into the caller's buffer, building them backwards in a local one first:

Assembly
        global  _start
        section .bss
out:    resb    32

        section .text
; to_text: rdi = destination buffer, rsi = an unsigned number. Writes its digits and a 0; returns the length.
to_text:
        push    rbp
        mov     rbp, rsp
        sub     rsp, 32                 ; a local buffer at [rbp - 32] .. [rbp - 1]
        lea     r8, [rbp - 1]           ; write digits backwards from the end
        mov     rax, rsi
        mov     ecx, 10
.digit: xor     edx, edx
        div     rcx
        add     dl, '0'
        mov     [r8], dl
        dec     r8
        test    rax, rax
        jnz     .digit
        inc     r8                      ; the first digit
        lea     rcx, [rbp]
        sub     rcx, r8                 ; how many digits
        mov     rax, rcx                ; the result: the length
        mov     rsi, r8
        rep movsb                       ; copy them to the destination
        mov     byte [rdi], 0
        leave
        ret

_start:
        lea     rdi, [rel out]
        mov     esi, 90210
        call    to_text
        mov     rbx, rax
        lea     rdi, [rel out]
        call    print_str
        mov     edi, ' '
        call    print_char
        mov     rdi, rbx
        call    print_int               ; 5 digits
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Without a frame pointer

At -O2, GCC and Clang usually leave rbp out (-fomit-frame-pointer), freeing it as a general register and addressing locals from rsp: [rsp + 8]. It is faster, but the offsets change whenever rsp moves, so the code is harder to read. Debuggers then use separate unwind tables instead of the rbp chain. Small leaf functions often need no frame at all.
