Signed and Unsigned Conditions

lesson 3.033 of 5 in milestone 35 min1 practice task

The same bits compare differently as signed and unsigned numbers - all 1s is -1 or the largest number. cmp sets flags for both readings, and you choose with the jump - jl, jg for signed, jb, ja for unsigned. Using the wrong one is a classic bug, and one unsigned compare can check a whole range.

Same bits, two orders

Take rax = -1 and rbx = 1. Which is bigger?

  • As signed numbers: −1 < 1.
  • As unsigned numbers: 0xFFFFFFFFFFFFFFFF (18,446,744,073,709,551,615) > 1.

The bits do not say which reading you mean, so cmp sets flags for both, and the jump decides:

signed unsigned
< jl (less) jb (below)
<= jle jbe
> jg (greater) ja (above)
>= jge jae

Equality (je, jne) is the same for both.

Assembly
        global  _start
        section .data
s_less: db      "signed: -1 is less than 1", 10, 0
s_above: db     "unsigned: -1 is above 1", 10, 0

        section .text
_start:
        mov     rbx, -1
        cmp     rbx, 1
        jge     .unsigned
        lea     rdi, [rel s_less]
        call    print_str
.unsigned:
        cmp     rbx, 1
        jbe     .done
        lea     rdi, [rel s_above]
        call    print_str
.done:
        mov     eax, 60
        xor     edi, edi
        syscall

Both messages print: the same comparison, read two ways.

How the flags tell them apart

cmp a, b works out a − b:

  • For unsigned numbers, a < b exactly when the subtraction had to borrow: CF = 1. So jb is jc (jump if carry).
  • For signed numbers the sign of the result would tell you, except that the subtraction may overflow and flip it. So the rule is "less when SF ≠ OF": the sign is wrong exactly when overflow happened.

Which one to use

The values are Use
sizes, counts, addresses, array indexes unsigned: jb, ja, ...
characters (bytes 0 to 255) unsigned
values that can be negative signed: jl, jg, ...

C compilers choose from the declared types: int gives jl, unsigned and size_t give jb. In assembly there are no types: you must remember which you meant.

The negative index bug

Checking an index with cmp rax, rcx / jge .out_of_range (signed) lets a negative index through, because −5 is less than the length. jae (unsigned) rejects it, since −5 as unsigned is huge. One unsigned compare checks both ends.

A range in one compare

The same trick checks whether a value is between low and high: subtract low, then compare unsigned against high - low. Anything below low wraps to a huge number:

Assembly
; is the character in al a digit, '0' to '9'?
        sub     al, '0'
        cmp     al, 9
        jbe     .is_digit       ; 0..9 after the subtraction: a digit

Compilers do this all the time for if (c >= '0' && c <= '9').
