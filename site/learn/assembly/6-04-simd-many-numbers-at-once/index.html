SIMD Many Numbers at Once

lesson 6.044 of 5 in milestone 65 min1 practice task

SIMD instructions do the same operation on several values at once. Every x86-64 processor has sixteen 128-bit xmm registers that hold 16 bytes, 8 words, 4 dwords or 2 qwords, with instructions like paddb, paddd and paddq. movdqu loads and stores 16 bytes, and a horizontal sum combines the lanes at the end. AVX widens this to 256 and 512 bits.

One instruction, many values

SIMD means "single instruction, multiple data". An x86-64 processor has 16 registers xmm0 to xmm15, each 128 bits wide, and instructions that treat them as several lanes:

Lanes Add Example
16 × 8-bit bytes paddb pixels, text
8 × 16-bit words paddw audio samples
4 × 32-bit dwords paddd int arrays
2 × 64-bit qwords paddq long arrays
4 floats / 2 doubles addps / addpd graphics, physics

Every x86-64 processor has SSE2, so these always work. Each lane is separate: a carry never crosses into the next lane.

Moving data in and out

Instruction Does
movdqu xmm0, [rsi] load 16 bytes from any address ("u" for unaligned)
movdqu [rdi], xmm0 store 16 bytes
movdqa the same, but the address must be a multiple of 16
movq xmm0, rax / movq rax, xmm0 move 64 bits between a general register and the low lane
pxor xmm0, xmm0 zero a vector register

Adding arrays

Assembly
        global  _start
        section .data
a:      dq      1, 2, 3, 4, 5, 6
b:      dq      10, 20, 30, 40, 50, 60
        section .bss
c:      resq    6

        section .text
_start:
        lea     rsi, [rel a]
        lea     rdx, [rel b]
        lea     rdi, [rel c]
        xor     ecx, ecx                ; byte offset
.loop:
        movdqu  xmm0, [rsi + rcx]       ; two numbers of a
        movdqu  xmm1, [rdx + rcx]       ; two numbers of b
        paddq   xmm0, xmm1              ; two additions at once
        movdqu  [rdi + rcx], xmm0
        add     rcx, 16
        cmp     rcx, 6*8
        jb      .loop

        xor     ebx, ebx                ; print c
.print: lea     rax, [rel c]
        mov     rdi, [rax + rbx*8]
        call    print_int
        mov     edi, ' '
        call    print_char
        inc     rbx
        cmp     rbx, 6
        jb      .print
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Horizontal sum

Adding up all the elements of an array uses lanes as separate running totals (like the four accumulators of lesson 6.03), then combines them at the end, a horizontal step:

Assembly
        pxor    xmm0, xmm0              ; two totals: 0, 0
.loop:  movdqu  xmm1, [rdi]
        paddq   xmm0, xmm1              ; add two elements, one into each total
        add     rdi, 16
        cmp     rdi, rdx
        jb      .loop
        pshufd  xmm1, xmm0, 0x4E        ; swap the two 64-bit halves
        paddq   xmm0, xmm1              ; now both lanes hold the sum
        movq    rax, xmm0

pshufd rearranges the four 32-bit pieces of a register; the constant 0x4E (binary 01 00 11 10) picks pieces 2, 3, 0, 1, which swaps the halves.

Saturation and comparisons

Some SIMD instructions have no ordinary equivalent:

  • paddusb adds bytes with saturation: 200 + 100 gives 255 instead of wrapping to 44. Perfect for brightening pixels.
  • pcmpeqb compares 16 bytes at once, giving 0xFF where they are equal and 0 elsewhere, and pmovmskb turns those 16 results into 16 bits of a general register. That is how fast strlen and memchr implementations scan 16 bytes per step.
  • pminub, pmaxub, pavgb: lane-wise minimum, maximum, average.

Wider: AVX

Newer processors add AVX2 (256-bit ymm registers: 8 ints at once) and AVX-512 (512-bit zmm: 16 ints). Code must check the processor supports them first (with the cpuid instruction), which is why compilers use only SSE2 unless told -mavx2 or -march=native. ARM's version is called NEON.
