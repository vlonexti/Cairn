Reading Compiler Output

lesson 6.011 of 5 in milestone 65 min1 practice task

Compiler output follows recognisable patterns. Leaf functions have no frame, xor zeroes, lea does arithmetic, and test, setcc and cmov replace branches. Division by a constant becomes a multiplication by a magic reciprocal, loops are rotated with one test in front, and simple loops over arrays are vectorised to work on 16 bytes at a time.

Where to look

gcc -O2 -S -masm=intel file.c writes the assembly to file.s; objdump -d -M intel program disassembles a finished program; Compiler Explorer (godbolt.org) shows both live, colour-coded line by line. Its Intel syntax is the GNU assembler's, slightly different from NASM's: QWORD PTR [rdi] where NASM writes qword [rdi], and movabs for a mov of a 64-bit constant.

Everything below is real GCC 15 output at -O2.

Small functions

C
long times9(long x) { return x * 9; }
int is_even(int x) { return x % 2 == 0; }
Assembly
times9:
        lea     rax, [rdi+rdi*8]        ; x + x*8: no multiply at all
        ret
is_even:
        mov     eax, edi
        not     eax                     ; flip the bits: the lowest is now 1 for even x
        and     eax, 1
        ret

No push rbp, no frame: a leaf function that keeps everything in registers needs none. Arguments arrive in rdi (edi for an int), the answer leaves in rax (eax).

Division by a constant

C
unsigned long div10(unsigned long x) { return x / 10; }
Assembly
div10:
        movabs  rax, -3689348814741910323      ; 0xCCCCCCCCCCCCCCCD
        mul     rdi                            ; rdx:rax = x * that
        mov     rax, rdx                       ; keep the high 64 bits
        shr     rax, 3
        ret

No div anywhere. The constant is about 2⁶⁷ ÷ 10, so taking the high 64 bits of the product (that is, dividing by 2⁶⁴) and shifting right by 3 more divides by 2⁶⁷ × 10 ÷ 2⁶⁷: by 10. The constant is chosen so the result is exact for every 64-bit x. mul takes about 3 cycles; div takes 20 to 40. Signed division adds a correction for negative numbers:

Assembly
sdiv3:                                         ; long sdiv3(long x) { return x / 3; }
        movabs  rax, 6148914691236517206       ; 0x5555555555555556, about 2^64 / 3
        imul    rdi
        sar     rdi, 63                        ; -1 if x was negative, else 0
        mov     rax, rdx
        sub     rax, rdi                       ; add 1 for negative x, to round towards zero
        ret

When you see a huge strange constant followed by mul or imul and a shift, think "division".

Loops

C
long sum(const long *v, long n)
{
    long t = 0;
    for (long i = 0; i < n; i++) t += v[i];
    return t;
}
Assembly
sum:
        test    rsi, rsi
        jle     .L9                     ; n <= 0: skip the loop entirely
        lea     rdx, [rdi+rsi*8]        ; end = v + n
        xor     eax, eax
.L8:
        add     rax, QWORD PTR [rdi]    ; t += *v
        add     rdi, 8                  ; v++
        cmp     rdi, rdx
        jne     .L8
        ret
.L9:
        xor     eax, eax
        ret

The index i has disappeared: GCC turned v[i] into a moving pointer and compares it with an end pointer. The loop is rotated (one test before it, one jump per round), exactly as lesson 3.02 described.

Vectorised loops

At -O3 a simple loop over arrays becomes SIMD code that handles four ints per instruction (lesson 6.04):

C
void add(int *restrict d, const int *restrict a, const int *restrict b)
{
    for (int i = 0; i < 1024; i++) d[i] = a[i] + b[i];
}
Assembly
add:
        xor     eax, eax
.L2:
        movdqu  xmm0, XMMWORD PTR [rdx+rax]    ; 16 bytes of b: four ints
        movdqu  xmm1, XMMWORD PTR [rsi+rax]    ; four ints of a
        paddd   xmm0, xmm1                     ; four additions at once
        movups  XMMWORD PTR [rdi+rax], xmm0    ; store four results
        add     rax, 16
        cmp     rax, 4096
        jne     .L2
        ret

256 rounds instead of 1024. (restrict promises the arrays do not overlap; without it GCC would add a check.)

A reading checklist

  1. Find the arguments: rdi, rsi, rdx, rcx, r8, r9 (32-bit names for ints).
  2. Find the result: whatever ends up in rax before ret.
  3. Find the loops: backward jumps to a label.
  4. Name each register by what it holds (a pointer, a count, a total) and write it as a comment.
  5. Look for the patterns: xor reg, reg is 0, lea is arithmetic, a magic constant is a division, cmov and set are small ifs.
