Strings

lesson 4.033 of 5 in milestone 45 min1 practice task

A string is bytes in memory, ending with a 0 byte by C's convention. Loops over strings read one byte at a time with movzx and stop at the 0. Length, copy, compare and case changes are all short loops. The string instructions rep movsb and rep stosb copy and fill whole blocks in one instruction.

Bytes with a zero at the end

Text is bytes: one per ASCII character (or several per character in UTF-8). Assembly has no string type, so programs follow a convention. The C convention, used by print_str and by every C library function, is a zero byte at the end.

Length

Assembly
; rdi = a zero-terminated string. Returns its length.
length:
        xor     eax, eax
.loop:  cmp     byte [rdi + rax], 0
        je      .done
        inc     rax
        jmp     .loop
.done:  ret

cmp byte [rdi + rax], 0 compares one byte of memory with 0 directly: no register needed.

Reading characters

To work on a character, read it with movzx so the rest of the register is clean, then compare and change the low byte:

Assembly
        global  _start
        section .data
text:   db      "Hello, assembly world!", 0

        section .text
_start:
        lea     rbx, [rel text]
        mov     rsi, rbx
.loop:
        movzx   eax, byte [rsi]
        test    al, al
        jz      .done                   ; the 0 at the end
        cmp     al, 'a'
        jb      .next
        cmp     al, 'z'
        ja      .next
        sub     al, 32                  ; 'a' to 'z' become 'A' to 'Z'
        mov     [rsi], al               ; write it back
.next:
        inc     rsi
        jmp     .loop
.done:
        mov     rdi, rbx
        call    print_str
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

This changes the string where it is, which works because it is in .data. Text in .rodata would crash when written.

Copying and comparing

Assembly
; rdi = destination, rsi = source. Copies the string with its 0.
copy:
.loop:  movzx   eax, byte [rsi]
        mov     [rdi], al
        inc     rsi
        inc     rdi
        test    al, al
        jnz     .loop                   ; the 0 was copied too: stop
        ret

; rdi, rsi = two strings. Returns 1 if they are equal.
equal:
.loop:  movzx   eax, byte [rdi]
        cmp     al, [rsi]
        jne     .no                     ; a difference
        test    al, al
        jz      .yes                    ; both ended together
        inc     rdi
        inc     rsi
        jmp     .loop
.yes:   mov     eax, 1
        ret
.no:    xor     eax, eax
        ret

The destination must have room: copying a long string into a short buffer overwrites whatever follows, the buffer overflow of C, with no warning at all here.

The string instructions

x86 has instructions made for blocks of memory. With a rep prefix they repeat rcx times:

Instruction Does, each time
rep movsb copy the byte at [rsi] to [rdi], then move both on
rep stosb store al at [rdi], then move it on
repne scasb compare al with [rdi], move on, stop at a match
Assembly
; fill 64 bytes at buffer with '-'
        lea     rdi, [rel buffer]
        mov     al, '-'
        mov     ecx, 64
        rep stosb

; copy rcx bytes from rsi to rdi
        rep movsb

They move forwards as long as the direction flag is clear, which the calling convention guarantees. Modern processors run rep movsb very fast for large blocks, and C's memcpy and memset often use it.
