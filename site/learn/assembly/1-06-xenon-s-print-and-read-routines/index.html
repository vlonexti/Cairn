Xenon's Print and Read Routines

lesson 1.066 of 6 in milestone 15 min1 practice task

Turning a number into printed digits takes a loop and a division, which come later in the course. Until then, Xenon adds ready-made routines to any program that calls them - print_str, print_int, print_hex, print_bin, print_newline, read_int, read_char and read_line. Put the argument in rdi (and rsi), call, and expect rax, rcx, rdx, rsi, rdi and r8 to r11 to change.

Why routines?

write prints bytes. To print the number 42 you need the bytes '4' and '2', which means dividing by 10 and turning remainders into characters: a loop (module 3) with division (module 2). Lesson 2.05 builds it. Until then, the website gives you a small library.

When your program calls one of these names and does not define it itself, the website adds the routine's code to the end of your program before assembling it. That is all: no magic in the processor. You can read their source in the Cheat Sheet - Routines reference page.

The routines

Routine Give it Does
print_str rdi = address of a zero-terminated string prints it
print_char dil (low byte of rdi) = a character prints one character
print_newline nothing prints a new line
print_int rdi = a signed number prints it in decimal: -42
print_uint rdi = an unsigned number prints it in decimal
print_hex rdi = a number prints 0x2a
print_bin rdi = a number, rsi = how many bits prints 00101010
read_int nothing reads a whole number: rax = the number, rdx = 1, or 0 in both at the end of the input
read_char nothing rax = the next character, or −1 at the end
read_line rdi = a buffer, rsi = its size reads a line without its new line; rax = its length, or −1 at the end

call

call name jumps to a routine, which runs and then comes back to the instruction after the call (lesson 5.01 shows how). Arguments go in rdi, then rsi: the same registers C uses on Linux, so these routines are exactly like calling C functions.

Assembly
        global  _start

        section .data
label:  db      "The answer is ", 0     ; print_str needs the 0 at the end

        section .text
_start:
        lea     rdi, [rel label]
        call    print_str
        mov     edi, 42
        call    print_int
        call    print_newline

        mov     rdi, -1
        call    print_int               ; -1
        call    print_newline
        mov     rdi, -1
        call    print_uint              ; the same bits, unsigned: 18446744073709551615
        call    print_newline
        mov     edi, 255
        call    print_hex               ; 0xff
        call    print_newline
        mov     edi, 5
        mov     esi, 8
        call    print_bin               ; 00000101
        call    print_newline

        mov     eax, 60
        xor     edi, edi
        syscall

Registers that change

A routine is allowed to use some registers for its own work, so after any call:

May have changed Are kept as they were
rax, rcx, rdx, rsi, rdi, r8, r9, r10, r11 rbx, rbp, rsp, r12, r13, r14, r15

So keep values you still need in rbx or r12 to r15 while calling routines. This rule is the calling convention that every function on Linux follows (lesson 5.02).

Reading numbers

Assembly
        global  _start
        section .data
ask:    db      "Two numbers: ", 0
said:   db      "Their sum is ", 0

        section .text
_start:
        lea     rdi, [rel ask]
        call    print_str
        call    read_int                ; rax = the first number
        mov     rbx, rax                ; keep it safe in rbx
        call    read_int                ; rax = the second
        add     rbx, rax
        lea     rdi, [rel said]
        call    print_str
        mov     rdi, rbx
        call    print_int
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

On the website an assembly program gets all of its input when it starts. When you run one that reads, the console asks for the input first: type each line, then press Enter on an empty line (or Ctrl+D) to start the program. In checked tasks the test's input is used.

Don't mix with your own read calls

read_int, read_char and read_line read the input in big pieces and keep what they have not used yet. A program that also makes its own read system calls would miss those bytes. Use one or the other.
