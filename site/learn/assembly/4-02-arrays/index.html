Arrays

lesson 4.022 of 5 in milestone 45 min1 practice task

An array in assembly is an address and a count - nothing marks its end or its type. Loop with an index and a scaled address, or move a pointer along by the element size until it reaches the end. Arrays come from the data section, .bss, or the caller, and the code must know whether each element is 1, 4 or 8 bytes.

An address and a count

In memory an array is just elements side by side. Nothing records how many there are or what they are, so functions take the address of the first element and the count, exactly like C functions taking (const long *values, size_t count).

Looping with an index

Assembly
        global  _start
        section .data
scores: dq      72, 95, 61, 88, 100, 54
count   equ     ($ - scores) / 8        ; 6: the bytes divided by the element size

        section .text
_start:
        lea     rsi, [rel scores]
        xor     ecx, ecx                ; i = 0
        xor     eax, eax                ; total = 0
.loop:
        add     rax, [rsi + rcx*8]      ; total += scores[i]
        inc     rcx
        cmp     rcx, count
        jb      .loop                   ; while i < count (unsigned: it is an index)
        mov     rdi, rax
        call    print_int               ; 470
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

Looping with a pointer

Instead of an index, move a pointer along by the element size and stop at the end address, the begin/end style from the C course:

Assembly
; rdi = the array, rsi = the count. Returns the largest element (count >= 1).
max_of:
        lea     rdx, [rdi + rsi*8]      ; end = one past the last element
        mov     rax, [rdi]              ; best = the first
        add     rdi, 8
.loop:
        cmp     rdi, rdx
        jae     .done
        mov     rcx, [rdi]
        cmp     rcx, rax
        cmovg   rax, rcx
        add     rdi, 8                  ; the next element
        jmp     .loop
.done:
        ret

Both styles are common in compiler output; the pointer style saves the multiplication in the address (which is free anyway on x86) and frees a register.

Element sizes

C type Size Read with
char, unsigned char, int8_t 1 movzx eax, byte [rdi + rcx] / movsx
short, int16_t 2 movsx eax, word [rdi + rcx*2]
int, int32_t 4 mov eax, [rdi + rcx*4] (movsxd to 64 bits)
long, pointers, int64_t 8 mov rax, [rdi + rcx*8]

Get the size wrong and you read pieces of two elements at once, with no error. Assembly will not stop you.

Changing an array

Storing works the same way in reverse. This doubles every element in place:

Assembly
        global  _start
        section .data
values: dq      1, -2, 3, 40
        section .text
_start:
        lea     rbx, [rel values]
        xor     ecx, ecx
.double:
        shl     qword [rbx + rcx*8], 1  ; values[i] *= 2, right in memory
        inc     rcx
        cmp     rcx, 4
        jb      .double

        xor     r12d, r12d              ; print them
.print:
        mov     rdi, [rbx + r12*8]
        call    print_int
        mov     edi, ' '
        call    print_char
        inc     r12
        cmp     r12, 4
        jb      .print
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

The print loop uses r12, not rcx, because the routines may change rcx.

No bounds

Reading values[10] of a 4-element array reads whatever follows it: other data, or memory that does not belong to the program (a segmentation fault). Every check is yours to write, usually one unsigned compare (lesson 3.03).
