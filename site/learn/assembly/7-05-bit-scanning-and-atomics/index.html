Bit Scanning and Atomics

lesson 7.055 of 5 in milestone 75 min2 practice tasks

Instructions that work on single bits - popcnt, bsf, bsr, tzcnt and lzcnt, bt, bts, btr and btc - and the instructions behind every lock and atomic variable - the lock prefix, xadd, xchg and cmpxchg - with a compare-and-swap loop and a spinlock.

Counting and finding bits

Lesson 2.03 handled bits with and, or, shl and loops. Modern x86 has single instructions for the common questions:

Instruction Result
popcnt rax, rdi how many bits of rdi are 1
tzcnt rax, rdi how many 0 bits come before the lowest 1 (64 if rdi is 0)
lzcnt rax, rdi how many 0 bits come before the highest 1 (64 if rdi is 0)
bsf rax, rdi the position of the lowest 1 bit (undefined if rdi is 0: ZF is set)
bsr rax, rdi the position of the highest 1 bit (undefined if rdi is 0)

tzcnt and lzcnt are the newer, safer versions of bsf and bsr because they define the zero case.

Assembly
        global  _start
        section .text
_start:
        mov     rbx, 0b1011000          ; 88
        popcnt  rdi, rbx
        call    print_int               ; 3 bits set
        call    print_newline
        tzcnt   rdi, rbx
        call    print_int               ; 3: the lowest 1 is bit 3
        call    print_newline
        bsr     rdi, rbx
        call    print_int               ; 6: the highest 1 is bit 6
        call    print_newline
        lzcnt   rdi, rbx
        call    print_int               ; 57 leading zeros
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

The position of the highest set bit is ⌊log₂ n⌋, which makes bsr a fast integer logarithm, and tzcnt finds the next free slot in a bitmap of used and free slots in one step.

Testing and changing one bit

Instruction Effect
bt rax, n copies bit n into the carry flag
bts rax, n the same, then sets the bit
btr rax, n the same, then clears it
btc rax, n the same, then flips it

Follow them with jc or setc. With a memory operand and a register bit number, bt can reach any bit of a large bitmap: bt [rel bitmap], rcx.

Why "atomic"

When two threads run add [counter], 1 on different cores, each core reads the value, adds and writes it back; both can read the same old value and one increase is lost (the same race as in the C and C++ concurrency lessons). The lock prefix makes a read-modify-write instruction atomic: no other core can touch that memory in the middle of it.

Assembly
        lock add qword [rel counter], 1     ; safe from every thread
        lock inc qword [rel hits]
        lock or  qword [rel flags], 4

xadd, xchg and cmpxchg

Three instructions give the building blocks of every lock and lock-free structure:

Instruction Effect
lock xadd [mem], rax adds rax to memory and puts the old value in rax: fetch-and-add
xchg [mem], rax swaps them; with a memory operand it is always atomic, even without lock
lock cmpxchg [mem], rcx if memory equals rax, stores rcx there and sets ZF; otherwise loads memory into rax and clears ZF

cmpxchg is compare-and-swap: "change it only if nobody else did in the meantime". Wrapped in a loop it performs any update atomically:

Assembly
        global  _start
        section .data
best:   dq      40

        section .text
; atomic_max: rdi = address of a qword, rsi = a candidate. Stores the candidate if it is larger.
; Returns the value that was there before.
atomic_max:
        mov     rax, [rdi]
.retry: cmp     rax, rsi
        jge     .done                   ; already at least as large
        lock cmpxchg [rdi], rsi         ; still rax? then store rsi
        jne     .retry                  ; someone changed it: rax now holds the new value, try again
.done:  ret

_start:
        lea     rdi, [rel best]
        mov     esi, 75
        call    atomic_max
        mov     rdi, [rel best]
        call    print_int               ; 75
        call    print_newline
        mov     eax, 60
        xor     edi, edi
        syscall

A spinlock

The smallest lock: a qword that is 0 when free and 1 when taken.

Assembly
; spin_lock: rdi = address of the lock
spin_lock:
        mov     eax, 1
.try:   xchg    [rdi], rax              ; take it, and see what it was
        test    rax, rax
        jz      .got                    ; it was free: we have it
.wait:  pause                           ; be kind to the other hyper-thread
        cmp     qword [rdi], 0
        jne     .wait                   ; spin on a plain read until it looks free
        mov     eax, 1
        jmp     .try
.got:   ret

spin_unlock:
        mov     qword [rdi], 0          ; a plain store releases on x86
        ret

Spinning on a plain read (instead of hammering xchg) keeps the cache line from bouncing between cores. Spinlocks suit very short critical sections; anything longer should use the operating system's locks, which put waiting threads to sleep.
