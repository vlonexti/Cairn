How C Becomes Assembly

lesson 6.033 of 5 in milestone 65 min1 practice task

Each C construct turns into a few machine instructions. Locals live in registers or on the stack, arguments arrive in registers, if and loops become compares and jumps, and array indexing becomes an address calculation. Reading compiler output shows what your code costs and what the optimiser does with it.

Looking at the output

gcc -S -masm=intel program.c stops after compiling and writes the assembly to program.s. Compiler Explorer (godbolt.org), the service this website compiles with, shows the same side by side with the source. The Assembly course teaches the language properly; here is enough to read it.

x86-64 has 16 general registers (rax, rbx, rcx, rdx, rsi, rdi, rbp, rsp, r8 to r15). Their low halves have names too: eax is the low 32 bits of rax. On Linux and Mac, the first six integer or pointer arguments arrive in rdi, rsi, rdx, rcx, r8, r9, and the result goes back in rax (eax for an int).

A simple function

C
int add3(int a, int b, int c)
{
    return a + b + c;
}

GCC with -O2:

Assembly
add3:
        add     edi, esi        ; a += b
        lea     eax, [rdi+rdx]  ; result = a + c  (lea computes an address, here used as an adder)
        ret

Three instructions, no memory touched at all. With -O0 the same function stores each argument on the stack and loads it back, which is easier to debug and much slower:

Assembly
add3:
        push    rbp
        mov     rbp, rsp
        mov     DWORD PTR [rbp-4], edi     ; a
        mov     DWORD PTR [rbp-8], esi     ; b
        mov     DWORD PTR [rbp-12], edx    ; c
        mov     edx, DWORD PTR [rbp-4]
        mov     eax, DWORD PTR [rbp-8]
        add     edx, eax
        mov     eax, DWORD PTR [rbp-12]
        add     eax, edx
        pop     rbp
        ret

DWORD PTR [rbp-4] is "the 4 bytes at address rbp - 4": a local variable in the stack frame (lesson 2.02's frames, for real).

if becomes compare and jump

C
int sign(int x)
{
    if (x > 0) return 1;
    if (x < 0) return -1;
    return 0;
}

GCC with -O0:

Assembly
sign:
        push    rbp
        mov     rbp, rsp
        mov     DWORD PTR [rbp-4], edi
        cmp     DWORD PTR [rbp-4], 0     ; compare x with 0, setting the flags
        jle     .L2                      ; jump if less or equal: skip the first return
        mov     eax, 1
        jmp     .L3
.L2:
        cmp     DWORD PTR [rbp-4], 0
        jns     .L4                      ; jump if not negative (the sign flag is clear)
        mov     eax, -1
        jmp     .L3
.L4:
        mov     eax, 0
.L3:
        pop     rbp
        ret

The processor has no if. It has flags, set by comparisons, and conditional jumps that go to a label depending on them. With -O1, GCC gets rid of the jumps altogether:

Assembly
sign:
        mov     eax, edi
        sar     eax, 31          ; shift the sign bit all the way down: -1 if x < 0, else 0
        test    edi, edi
        mov     edx, 1
        cmovg   eax, edx         ; "move if greater": 1 if x > 0
        ret

sar copies the sign bit as it shifts, so a negative number becomes all 1 bits, which is -1. cmovg is a conditional move: no jump, so the processor never has to guess which way the code will go.

Loops and arrays

C
int sum(const int *values, int count)
{
    int total = 0;
    for (int i = 0; i < count; i++) total += values[i];
    return total;
}

Indexing becomes an address calculation, values + i * 4, folded into one memory operand. Step through a loop like the one GCC writes, as the CPU runs it:

[rdi+rdx*4] is values[i]: base address plus index times the size of an int. That is pointer arithmetic (lesson 3.02), done in one instruction by the hardware.

What the optimiser does

At -O2 and -O3 GCC also:

  • keeps variables in registers instead of memory
  • inlines small functions, pasting their bodies in place of the call
  • replaces multiplications by shifts and adds (x * 9 becomes lea eax, [rdi+rdi*8])
  • unrolls and vectorises loops, adding 4 or 8 values per instruction with SIMD registers
  • deletes code whose result is never used

This is why -O2 C is so fast, and also why undefined behaviour (lesson 6.02) gets "optimised" in surprising ways.

The other way round

Assembly to machine code is a simple one-to-one translation, done by the assembler: add edi, esi is the two bytes 01 f7. The Fundamentals course shows how those bytes drive the circuits; the Assembly course has you write the instructions yourself.
