Programs in Several Files

lesson 5.055 of 5 in milestone 55 min1 practice task

Real programs split into modules - a header (.h) declaring what a module offers and a .c file defining it. Each .c file compiles on its own, and the linker joins them, matching declarations to definitions. extern shares a variable, static keeps things private, and make rebuilds only what changed.

Splitting a program

A program of any size is split into modules. Each one has:

  • a header (stack.h) that declares what other files may use: types, function prototypes, constants. It is the module's public face.
  • a source file (stack.c) with the definitions: the function bodies and any private helpers.
C
// stack.h
#ifndef STACK_H
#define STACK_H

#include <stdbool.h>
#include <stddef.h>

#define STACK_MAX 100

struct stack {
    int items[STACK_MAX];
    size_t size;
};

void stack_init(struct stack *s);
bool stack_push(struct stack *s, int value);
bool stack_pop(struct stack *s, int *out);

#endif
C
// stack.c
#include "stack.h"

void stack_init(struct stack *s) { s->size = 0; }

bool stack_push(struct stack *s, int value)
{
    if (s->size == STACK_MAX) return false;
    s->items[s->size++] = value;
    return true;
}

bool stack_pop(struct stack *s, int *out)
{
    if (s->size == 0) return false;
    *out = s->items[--s->size];
    return true;
}
C
// main.c
#include <stdio.h>
#include "stack.h"

int main(void)
{
    struct stack s;
    stack_init(&s);
    stack_push(&s, 1);
    stack_push(&s, 2);
    int top = 0;
    while (stack_pop(&s, &top)) printf("%d\n", top);
    return 0;
}

In the editor, add files with the New file button above the file list (or right-click the list). Every .c file in the project is compiled and linked into the program.

Compile separately, link together

Each .c file is compiled on its own into an object file (.o), knowing only what its headers declared. main.o contains a note: "I call stack_push, address unknown". The linker then joins the object files and the C library, filling in every such address.

graph LR
  A[main.c] --> B[main.o]
  C[stack.c] --> D[stack.o]
  B --> L((linker))
  D --> L
  E[C library] --> L
  L --> P[program]
Output
gcc -c stack.c           # stack.c -> stack.o
gcc -c main.c            # main.c  -> main.o
gcc main.o stack.o -o app

That explains two error messages that come from the linker, not the compiler:

Message Means
undefined reference to 'stack_push' declared (so it compiled), but no file defines it, or that file was not linked in
multiple definition of 'counter' two files define the same thing, often a variable defined in a header

Sharing variables: extern

A header must only declare a shared variable, with extern; exactly one .c file defines it:

C
// settings.h
extern int verbose;          // a declaration: "it exists somewhere"

// settings.c
int verbose = 0;             // the one definition

Functions need no extern: a prototype is already a declaration.

Keeping things private: static

Anything at file level without static is visible to the linker and can clash with the same name in another file. Mark helpers and file-private variables static (lesson 2.03); only what is in the header should be public.

Rebuilding with make

Recompiling everything after each change wastes time in big projects. A Makefile lists what each file depends on, and make rebuilds only the files whose sources changed:

Output
CFLAGS = -std=c17 -Wall -Wextra -g

app: main.o stack.o
	$(CC) main.o stack.o -o app

main.o: main.c stack.h
stack.o: stack.c stack.h

Bigger projects generate their build files with CMake or Meson, but the idea is the same.
