Threads and Atomics

lesson 7.055 of 5 in milestone 75 min2 practice tasks

Running C code in parallel - C11 threads with thrd_create and thrd_join, passing arguments and results, data races, mutexes with mtx_lock, atomic variables from stdatomic.h, condition variables, and how POSIX threads and Windows threads map to the same ideas.

Threads in standard C

Since C11, <threads.h> gives portable threads, and <stdatomic.h> gives atomic variables. (Many programs still use POSIX threads, pthread_create and friends, or the Windows API; the ideas are the same, and a table at the end maps the names.)

A thread runs a function of type int f(void *). thrd_create starts it; thrd_join waits for it and collects its result:

C
#include <stdio.h>
#include <threads.h>

struct job { int from, to; long long sum; };

int add_range(void *arg)
{
    struct job *j = arg;
    for (int i = j->from; i < j->to; i++) j->sum += i;
    return 0;
}

int main(void)
{
    struct job jobs[4];
    thrd_t threads[4];
    for (int t = 0; t < 4; t++)
    {
        jobs[t] = (struct job){ .from = t * 250000, .to = (t + 1) * 250000, .sum = 0 };
        thrd_create(&threads[t], add_range, &jobs[t]);
    }
    long long total = 0;
    for (int t = 0; t < 4; t++)
    {
        thrd_join(threads[t], NULL);
        total += jobs[t].sum;
    }
    printf("%lld\n", total);     /* 499999500000 */
    return 0;
}

Each thread gets a pointer to its own struct job and writes only there, so no two threads touch the same memory. Combining the results after thrd_join needs no locking at all. That is the simplest and best pattern.

Data races

When two threads access the same variable at the same time and at least one writes, the program has a data race, which is undefined behaviour. count++ is a read, an add and a write; two threads can both read 5 and both write 6.

Mutexes

A mutex lets one thread at a time into a critical section:

C
#include <stdio.h>
#include <threads.h>

static long counter = 0;
static mtx_t lock;

int work(void *arg)
{
    (void)arg;
    for (int i = 0; i < 100000; i++)
    {
        mtx_lock(&lock);
        counter++;
        mtx_unlock(&lock);
    }
    return 0;
}

int main(void)
{
    mtx_init(&lock, mtx_plain);
    thrd_t a, b;
    thrd_create(&a, work, NULL);
    thrd_create(&b, work, NULL);
    thrd_join(a, NULL);
    thrd_join(b, NULL);
    mtx_destroy(&lock);
    printf("%ld\n", counter);    /* always 200000 */
    return 0;
}

Keep the locked part short, and lock several mutexes in the same order everywhere to avoid deadlocks.

Atomics

For a single counter or flag, an atomic variable is simpler and faster than a mutex: its operations happen as one indivisible step.

C
#include <stdatomic.h>
#include <stdbool.h>
#include <stdio.h>
#include <threads.h>

static atomic_long hits = 0;
static atomic_bool stop = false;

int count(void *arg)
{
    (void)arg;
    for (int i = 0; i < 100000; i++) atomic_fetch_add(&hits, 1);
    return 0;
}

int main(void)
{
    thrd_t t[4];
    for (int i = 0; i < 4; i++) thrd_create(&t[i], count, NULL);
    for (int i = 0; i < 4; i++) thrd_join(t[i], NULL);
    atomic_store(&stop, true);
    printf("%ld %d\n", atomic_load(&hits), atomic_load(&stop));
    return 0;
}

atomic_compare_exchange_strong(&x, &expected, desired) sets x to desired only if it still equals expected, the building block of lock-free code. The default operations are sequentially consistent (the easiest to reason about); the _explicit versions take weaker memory orders for experts.

Waiting for a condition

A condition variable lets a thread sleep until another one signals that something changed, always together with a mutex and a loop that rechecks the condition:

C
mtx_lock(&lock);
while (queue_is_empty())          /* a loop, not an if: wake-ups can be spurious */
    cnd_wait(&not_empty, &lock);  /* releases the lock while sleeping, takes it back on waking */
int item = queue_pop();
mtx_unlock(&lock);

/* in the producer: */
mtx_lock(&lock);
queue_push(42);
cnd_signal(&not_empty);
mtx_unlock(&lock);

The same ideas under other names

C11 POSIX Windows
thrd_create, thrd_join pthread_create, pthread_join CreateThread, WaitForSingleObject
mtx_lock, mtx_unlock pthread_mutex_lock, pthread_mutex_unlock EnterCriticalSection, LeaveCriticalSection
cnd_wait, cnd_signal pthread_cond_wait, pthread_cond_signal SleepConditionVariableCS, WakeConditionVariable
atomic_fetch_add (the same <stdatomic.h>) InterlockedIncrement

Compile with ThreadSanitizer (-fsanitize=thread with GCC or Clang) while testing threaded code: it reports data races that would otherwise show up as rare, impossible-looking bugs.
