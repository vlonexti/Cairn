C and How It Builds

lesson 1.011 of 5 in milestone 15 min2 practice tasks

C is a small, fast language close to the machine, created in 1972 to write Unix. A C program is text that a compiler turns into machine code in steps - preprocess, compile, assemble, link - and every program starts in a function called main.

Why C

C was created by Dennis Ritchie at Bell Labs in 1972 to write the Unix operating system (the Computer Fundamentals course tells the story in lesson 5.04). Fifty years later it is still everywhere:

  • operating system kernels: Linux, and the cores of Windows and macOS;
  • small chips in cars, washing machines, routers and medical devices;
  • databases (SQLite, PostgreSQL), and the interpreters of other languages: Python's main interpreter is written in C.

C is small - the whole language fits in a short book - and it is close to the machine: you decide exactly how much memory each value takes and where it lives. That makes it fast and powerful, and also unforgiving: C trusts you, and does not stop you from making a mistake. This course teaches the power and the care together.

The first program

C
#include <stdio.h>

int main(void)
{
    printf("Hello, world!\n");
    return 0;
}

Press Run. Line by line:

Line Meaning
#include <stdio.h> Bring in the declarations of the standard input/output functions, such as printf
int main(void) Every C program starts in the function main. It takes nothing (void) and gives back an int
{ ... } The body of the function
printf("Hello, world!\n"); Print the text. \n is a new line. Every statement ends with ;
return 0; Finish, telling the operating system "all went well" (0). Any other number means something went wrong

How C becomes a program

C is a compiled language: before it runs, a compiler turns the text into machine code. It happens in four steps:

flowchart LR
    S["hello.c<br/>your source"] -->|1 preprocess| P["#include and<br/>#define done"]
    P -->|2 compile| A["assembly"]
    A -->|3 assemble| O["object file<br/>(machine code)"]
    O -->|4 link| E["hello<br/>(a program)"]
    L["libraries:<br/>the code of printf"] --> E
  1. Preprocess: lines starting with # are handled first. #include <stdio.h> is replaced by the contents of that header file.
  2. Compile: the C code is translated into assembly for your CPU.
  3. Assemble: the assembly becomes machine code, in an object file.
  4. Link: your object file is joined with the libraries it uses (the machine code of printf lives in the C standard library) into one program.

On your own computer you would run one command, which does all four:

Terminal
gcc hello.c -o hello      # or: clang hello.c -o hello
./hello

On Windows with Visual Studio the command is cl hello.c. On this site, pressing Run does it for you with GCC.

Compiler errors and warnings

When the compiler cannot understand the code, it stops with an error and the line number. When the code is valid but suspicious, it gives a warning and builds anyway. Treat warnings as errors you have not met yet: most of them point at a real bug.

C
#include <stdio.h>

int main(void)
{
    printf("Hello, world!\n")     // error: expected ';' before 'return'
    return 0;
}

The error is reported on the line after the missing semicolon, because that is where the compiler noticed. When an error makes no sense, look at the line above.

Comments

C
#include <stdio.h>

/* A comment can span
   several lines like this. */
int main(void)
{
    // and this kind runs to the end of the line
    printf("Comments are ignored by the compiler.\n");
    return 0;
}
