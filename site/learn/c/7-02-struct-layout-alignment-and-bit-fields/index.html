Struct Layout, Alignment and Bit Fields

lesson 7.022 of 5 in milestone 75 min2 practice tasks

How a struct sits in memory - alignment and padding, sizeof and offsetof, ordering fields to save space, _Alignof and _Alignas, flexible array members for variable-sized structs, bit fields for packed flags, and why binary files need explicit layouts.

Fields have to line up

Most processors read a value fastest (and some only at all) when its address is a multiple of its size: a 4-byte int at an address divisible by 4, an 8-byte double at one divisible by 8. That requirement is the type's alignment. To meet it, the compiler inserts unused padding bytes between struct fields and at the end:

C
#include <stddef.h>
#include <stdio.h>

struct badly_ordered
{
    char tag;       /* 1 byte, then 7 bytes of padding so that value is aligned */
    double value;   /* 8 bytes */
    char flag;      /* 1 byte, then 7 bytes of padding so arrays of the struct stay aligned */
};

struct well_ordered
{
    double value;
    char tag;
    char flag;      /* 6 bytes of padding at the end */
};

int main(void)
{
    printf("%zu %zu\n", sizeof(struct badly_ordered), sizeof(struct well_ordered));   /* 24 16 */
    printf("tag at %zu, value at %zu, flag at %zu\n",
           offsetof(struct badly_ordered, tag), offsetof(struct badly_ordered, value),
           offsetof(struct badly_ordered, flag));
    return 0;
}

The exact numbers are up to the platform (these are for x86-64), which is why you ask with sizeof and offsetof instead of adding up field sizes yourself. A simple rule saves memory: order fields from largest to smallest.

Asking about alignment

_Alignof(type) (spelled alignof with <stdalign.h>) gives a type's alignment; _Alignas(n) asks for a stricter one, for example to put data on a cache line of its own:

C
#include <stdalign.h>
#include <stdio.h>

struct counter
{
    alignas(64) long value;   /* starts on a 64-byte boundary */
};

int main(void)
{
    printf("%zu %zu %zu\n", alignof(char), alignof(double), alignof(struct counter));
    printf("%zu\n", sizeof(struct counter));      /* 64: padded to its alignment */
    return 0;
}

Flexible array members

A struct can end with an array of unspecified size. You allocate the struct plus as many elements as you need in one block:

C
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct message
{
    size_t length;
    char text[];             /* a flexible array member: must be last */
};

struct message *message_new(const char *s)
{
    size_t n = strlen(s);
    struct message *m = malloc(sizeof *m + n + 1);
    if (m == NULL)
        return NULL;
    m->length = n;
    memcpy(m->text, s, n + 1);
    return m;
}

int main(void)
{
    struct message *m = message_new("hello, layout");
    if (m != NULL)
    {
        printf("%zu: %s\n", m->length, m->text);
        free(m);             /* one free for the struct and its text */
    }
    return 0;
}

One allocation instead of two is faster and cannot leak half of the object.

Bit fields

A bit field gives a struct member a width in bits, so several small values share one integer:

C
#include <stdio.h>

struct permissions
{
    unsigned read : 1;
    unsigned write : 1;
    unsigned execute : 1;
    unsigned level : 3;       /* 0 to 7 */
};

int main(void)
{
    struct permissions p = { .read = 1, .write = 0, .execute = 1, .level = 5 };
    p.write = 1;
    p.level += 4;             /* 5 + 4 = 9 does not fit in 3 bits: wraps to 1 */
    printf("r%u w%u x%u level %u, %zu bytes\n", p.read, p.write, p.execute, p.level, sizeof p);
    return 0;
}

Bit fields are convenient inside a program, but how the bits are arranged inside the integer (which end first, whether a field may cross a boundary) is decided by the compiler. For data that leaves the program (files, network, hardware registers), use plain integers with masks and shifts (lesson 5.01) so the layout is exactly what you wrote.

Binary files need explicit layouts

Writing a struct to a file with fwrite(&s, sizeof s, 1, f) writes its padding and its byte order too, so another compiler or computer may read it wrongly. A portable format writes each field on its own, in a fixed size and byte order:

C
#include <stdint.h>
#include <stdio.h>

/* Writes a 32-bit value low byte first (little-endian), whatever the computer's own order. */
void put_u32_le(unsigned char out[4], uint32_t v)
{
    out[0] = (unsigned char)(v & 0xFF);
    out[1] = (unsigned char)((v >> 8) & 0xFF);
    out[2] = (unsigned char)((v >> 16) & 0xFF);
    out[3] = (unsigned char)((v >> 24) & 0xFF);
}

int main(void)
{
    unsigned char bytes[4];
    put_u32_le(bytes, 0x12345678);
    printf("%02x %02x %02x %02x\n", bytes[0], bytes[1], bytes[2], bytes[3]);   /* 78 56 34 12 */
    return 0;
}
