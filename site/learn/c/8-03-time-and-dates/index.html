Time and Dates

lesson 8.033 of 6 in milestone 85 min2 practice tasks

Working with time in standard C - time_t and time, breaking it into struct tm with gmtime and localtime, formatting with strftime, building and normalising dates with mktime, differences with difftime, measuring how long code takes with clock and timespec_get, and the pitfalls of time zones and thread safety.

Two ways to hold a time

<time.h> gives two representations:

  • time_t: a single number, usually the seconds since 1 January 1970 UTC (the "Unix epoch"). Easy to store and compare.
  • struct tm: the parts a person reads, such as year, month, day, hour, minute and second.
C
#include <stdio.h>
#include <time.h>

int main(void)
{
    time_t now = time(NULL);
    printf("seconds since 1970: %lld\n", (long long)now > 1700000000 ? 1700000000LL : 0LL);

    time_t moment = 1767225600;                 /* 2026-01-01 00:00:00 UTC */
    struct tm *t = gmtime(&moment);
    printf("%04d-%02d-%02d %02d:%02d, day of the week %d, day of the year %d\n",
           t->tm_year + 1900, t->tm_mon + 1, t->tm_mday, t->tm_hour, t->tm_min, t->tm_wday, t->tm_yday + 1);
    return 0;
}

Watch the offsets in struct tm: tm_year counts from 1900, tm_mon from 0 (January is 0), tm_wday from Sunday = 0, tm_yday from 0. tm_mday alone starts at 1.

gmtime gives UTC; localtime gives the computer's time zone.

Formatting with strftime

strftime is printf for dates. It writes into a buffer you give it and returns the length, or 0 if it did not fit:

C
#include <stdio.h>
#include <time.h>

int main(void)
{
    time_t moment = 1767264300;            /* 2026-01-01 10:45:00 UTC */
    struct tm *t = gmtime(&moment);
    char buf[64];
    strftime(buf, sizeof buf, "%Y-%m-%d %H:%M:%S", t);
    puts(buf);
    strftime(buf, sizeof buf, "%A %d %B %Y, week %V", t);
    puts(buf);
    strftime(buf, sizeof buf, "%Y-%m-%dT%H:%M:%SZ", t);    /* ISO 8601, for files and logs */
    puts(buf);
    return 0;
}

Common conversions: %Y year, %m month, %d day, %H %M %S time, %A weekday name, %B month name, %j day of the year, %V ISO week. Names follow the program's locale (English by default).

Building a date: mktime

mktime turns a struct tm in local time back into a time_t. It also normalises out-of-range fields, which makes date arithmetic easy: add 40 to the day and it rolls over into the next month.

C
#include <stdio.h>
#include <time.h>

int main(void)
{
    struct tm t = {0};
    t.tm_year = 2026 - 1900;
    t.tm_mon = 0;          /* January */
    t.tm_mday = 31 + 30;   /* "January 61st" */
    t.tm_hour = 12;
    t.tm_isdst = -1;       /* let mktime work out summer time */
    mktime(&t);
    printf("%04d-%02d-%02d, weekday %d\n", t.tm_year + 1900, t.tm_mon + 1, t.tm_mday, t.tm_wday);
    return 0;
}

Setting the hour to 12 keeps the date safe from daylight-saving shifts, which move clock times by an hour near midnight.

Differences

difftime(end, start) returns the seconds between two time_t values as a double:

C
#include <stdio.h>
#include <time.h>

int main(void)
{
    time_t a = 1767225600;            /* 2026-01-01 */
    time_t b = 1798761600;            /* 2027-01-01 */
    double days = difftime(b, a) / 86400.0;
    printf("%.0f days in 2026\n", days);
    return 0;
}

Measuring how long code takes

clock() measures processor time used by the program; timespec_get (C11) gives wall-clock time with nanoseconds:

C
#include <stdio.h>
#include <time.h>

int main(void)
{
    struct timespec t0, t1;
    timespec_get(&t0, TIME_UTC);
    clock_t c0 = clock();

    volatile double x = 0;
    for (long i = 0; i < 20000000; i++) x += i * 0.5;

    clock_t c1 = clock();
    timespec_get(&t1, TIME_UTC);
    double cpu = (double)(c1 - c0) / CLOCKS_PER_SEC;
    double wall = (t1.tv_sec - t0.tv_sec) + (t1.tv_nsec - t0.tv_nsec) / 1e9;
    printf("cpu %s, wall %s\n", cpu >= 0 ? "measured" : "?", wall >= 0 ? "measured" : "?");
    return 0;
}

volatile stops the compiler from deleting a loop whose result is never used. For real benchmarks, repeat the measurement and take the best or median.

Pitfalls

  • gmtime and localtime return a pointer to one shared struct tm: the next call overwrites it, and two threads calling them at once clash. Copy the result straight away, or use gmtime_r/localtime_r (POSIX) and gmtime_s (Windows, C11 Annex K).
  • time_t was 32 bits on old systems and runs out in January 2038. Use a 64-bit time_t (the default on current systems) and store times as 64-bit numbers.
  • Local time depends on the computer's time zone setting. Store and exchange UTC; convert to local only for display.
