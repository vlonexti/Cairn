"Modern C: C11, C17 and C23"

lesson 7.033 of 5 in milestone 75 min2 practice tasks

The newer parts of C - designated initializers and compound literals, anonymous structs and unions, _Static_assert, _Generic for type-based dispatch, _Noreturn, and a tour of C23 (bool, true and false as keywords, nullptr, typeof, constexpr, auto, attributes, digit separators and #embed).

C keeps changing

Much C code is written in a style from 1989. Each standard since has added things that make code shorter and safer: C99 (// comments, bool, declarations anywhere, designated initializers), C11 (_Generic, _Static_assert, threads, atomics, anonymous members), C17 (bug fixes), and C23. Xenon compiles C17; C23 features are shown here for your own projects with a recent compiler (-std=c23).

Designated initializers

Name the fields (or array positions) you set; everything else is zero:

C
#include <stdio.h>

struct window { int width, height; const char *title; int fullscreen; };

int main(void)
{
    struct window w = { .title = "Game", .width = 1280, .height = 720 };
    int lookup[8] = { [2] = 20, [5] = 50 };
    printf("%s %dx%d full=%d | %d %d %d\n", w.title, w.width, w.height, w.fullscreen,
           lookup[2], lookup[5], lookup[0]);
    return 0;
}

Order no longer matters, adding a field never shifts the others, and the code says which value is which.

Compound literals

(type){ ... } creates an unnamed object right where it is needed, which is handy for passing structs and arrays:

C
#include <stdio.h>

struct point { double x, y; };

double dist2(struct point a, struct point b)
{
    double dx = a.x - b.x, dy = a.y - b.y;
    return dx * dx + dy * dy;
}

int sum(const int *values, int n)
{
    int t = 0;
    for (int i = 0; i < n; i++) t += values[i];
    return t;
}

int main(void)
{
    printf("%.1f\n", dist2((struct point){ 0, 0 }, (struct point){ .x = 3, .y = 4 }));
    printf("%d\n", sum((int[]){ 1, 2, 3, 4 }, 4));
    return 0;
}

A compound literal inside a function lives until the end of its block, like a local variable.

Anonymous structs and unions

A struct or union member with no name puts its fields directly in the outer struct. Tagged unions (lesson 4.04) read much better this way:

C
#include <stdio.h>

enum kind { NUMBER, TEXT };

struct value
{
    enum kind kind;
    union
    {
        double number;
        const char *text;
    };                          /* anonymous: v.number, not v.data.number */
};

void show(struct value v)
{
    if (v.kind == NUMBER) printf("number %g\n", v.number);
    else printf("text %s\n", v.text);
}

int main(void)
{
    show((struct value){ .kind = NUMBER, .number = 2.5 });
    show((struct value){ .kind = TEXT, .text = "hi" });
    return 0;
}

_Static_assert

A check done by the compiler: if the condition is false, the program does not compile. Use it for assumptions about sizes and constants:

C
#include <stdint.h>

struct header { uint32_t magic; uint16_t version; uint16_t flags; };

_Static_assert(sizeof(struct header) == 8, "header must stay 8 bytes: it is written to files");
_Static_assert(sizeof(int) >= 4, "this code needs 32-bit ints");

int main(void)
{
    return 0;
}

_Generic: choosing by type

_Generic(expression, type: result, ...) picks a result by the type of the expression, at compile time. Wrapped in a macro, it gives one name for several functions, much like overloading:

C
#include <math.h>
#include <stdio.h>
#include <stdlib.h>

#define absolute(x) _Generic((x), int: abs_int, long: labs, double: fabs, default: fabs)(x)

int abs_int(int x) { return x < 0 ? -x : x; }

#define type_name(x) _Generic((x), int: "int", double: "double", char *: "char *", default: "something else")

int main(void)
{
    printf("%d %ld %.1f\n", absolute(-3), absolute(-4L), absolute(-2.5));
    printf("%s %s %s\n", type_name(1), type_name(1.0), type_name("hi"));
    return 0;
}

(type_name("hi") gives char * because the string literal turns into a pointer to its first character.)

_Noreturn

A function that never returns (it always calls exit or abort) can say so; the compiler then warns if it might return and can optimise its callers:

C
#include <stdio.h>
#include <stdlib.h>

_Noreturn void die(const char *message)
{
    fprintf(stderr, "fatal: %s\n", message);
    exit(1);
}

int main(void)
{
    int ok = 1;
    if (!ok) die("no config");
    puts("running");
    return 0;
}

C23 in brief

C
/* compile with -std=c23 (GCC 14+, Clang 18+) */
#include <stdio.h>

constexpr int max_players = 8;            /* a real compile-time constant, usable for array sizes */

int main(void)
{
    bool ready = true;                    /* bool, true and false are keywords: no header needed */
    int *p = nullptr;                     /* a null pointer constant with its own type */
    auto count = 1'000'000;               /* auto infers the type; ' separates digits */
    typeof(count) copy = count;           /* typeof is standard now */
    int scores[max_players] = {};         /* {} zero-initialises */
    [[maybe_unused]] int debug = 0;       /* standard attributes, like C++ */
    static const unsigned char icon[] = {
        #embed "icon.png"                 /* the bytes of a file, at compile time */
    };
    printf("%d %d %zu %d\n", ready, copy, sizeof icon, p == nullptr);
    return scores[0];
}

Other additions: [[nodiscard]] and [[deprecated]], binary literals 0b1010, strdup in the standard library, and unreachable().
