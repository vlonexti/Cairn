const and Pointers

lesson 3.044 of 5 in milestone 35 min1 practice task

const marks something as read-only, and with pointers there are two things it can protect. const int *p cannot change what it points at; int *const p cannot point anywhere else. Taking const pointers in functions that only read documents the promise, lets callers pass read-only data, and turns accidental writes into compile errors.

const variables

C
const double pi = 3.14159265358979;
pi = 3;          // error: assignment of read-only variable 'pi'

const asks the compiler to refuse any change. It is a promise checked at compile time; it costs nothing when the program runs.

Two places for const

Read pointer declarations from right to left:

Declaration Reads as *p = 5 p = &other
int *p p is a pointer to int ok ok
const int *p p is a pointer to an int that is const error ok
int *const p p is a const pointer to int ok error
const int *const p a const pointer to a const int error error

int const *p means the same as const int *p: what matters is whether const is left or right of the *.

C
#include <stdio.h>

int main(void)
{
    int a = 1, b = 2;

    const int *reader = &a;     // can look, cannot touch
    printf("%d\n", *reader);
    reader = &b;                // fine: it may point elsewhere
    // *reader = 5;             // error: read-only location

    int *const fixed = &a;      // always points at a
    *fixed = 10;                // fine: a changes
    // fixed = &b;              // error: read-only variable

    printf("%d %d\n", a, *reader);
    return 0;
}

The first kind, const T *, is the one you will use all the time.

const in function parameters

A function that only reads through a pointer should say so:

C
size_t strlen(const char *s);                        // reads s
char *strcpy(char *dest, const char *src);           // writes dest, reads src
int sum(const int *values, size_t count);

The signature is documentation the compiler enforces: const char *src guarantees strcpy will not change the source. It also lets callers pass things that are read-only, such as string literals:

C
#include <stdio.h>

int count_spaces(const char *s)
{
    int count = 0;
    for (; *s != '\0'; s++) {      // moving s is fine: the pointer is not const
        if (*s == ' ') count++;
    }
    return count;
}

int main(void)
{
    printf("%d\n", count_spaces("a b c d"));   // 3
    return 0;
}

If count_spaces took a plain char *, writing through it by mistake would compile, and on a literal it would crash.

Converting between them

  • int * to const int * happens automatically: adding a promise is always safe.
  • const int * to int * needs a cast, and GCC warns without one ("discards const qualifier"). Casting const away and then writing is undefined if the object really was const. Do not do it.
Why strchr returns char *

strchr(const char *s, int c) returns a plain char * into s: C has no overloading, so one function serves both writable and read-only strings. Keep the result const char * when the string was const.
