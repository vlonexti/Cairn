Linked Lists

lesson 4.055 of 6 in milestone 45 min1 practice task

A linked list is a chain of nodes on the heap, each holding a value and a pointer to the next, ending in NULL. Adding at the front is instant and nothing ever has to move, but finding the nth element means walking the chain. Inserting and removing use a pointer to the link being changed, and freeing the list walks it once.

Nodes that point to the next

C
struct node {
    int value;
    struct node *next;      // NULL in the last node
};

A list is just a pointer to the first node (the head), and NULL for an empty list:

graph LR
  head([head]) --> A["7 | next"] --> B["3 | next"] --> C["9 | next"] --> N([NULL])

Unlike an array, the nodes can be anywhere in memory. Each one only knows where the next one is.

Pushing onto the front

C
#include <stdio.h>
#include <stdlib.h>

struct node {
    int value;
    struct node *next;
};

// Adds value at the front. Returns false if memory ran out.
int push_front(struct node **head, int value)
{
    struct node *n = malloc(sizeof *n);
    if (n == NULL) return 0;
    n->value = value;
    n->next = *head;        // the new node points at the old first node
    *head = n;              // and becomes the first node
    return 1;
}

void print_list(const struct node *head)
{
    for (const struct node *n = head; n != NULL; n = n->next) {
        printf("%d -> ", n->value);
    }
    printf("NULL\n");
}

void free_list(struct node *head)
{
    while (head != NULL) {
        struct node *next = head->next;    // save it before freeing
        free(head);
        head = next;
    }
}

int main(void)
{
    struct node *list = NULL;
    push_front(&list, 9);
    push_front(&list, 3);
    push_front(&list, 7);
    print_list(list);       // 7 -> 3 -> 9 -> NULL
    free_list(list);
    return 0;
}
  • push_front changes the caller's head pointer, so it takes struct node ** (lesson 3.05).
  • The loop for (n = head; n != NULL; n = n->next) visits every node: memorise it.
  • free_list must read head->next before freeing head; afterwards it would be a use after free.

Removing: a pointer to the link

Removing a node means making the link that points at it skip over it. The neat way keeps a pointer to that link (either head itself or some node's next), so the first node needs no special case:

C
// Removes the first node holding value. Returns 1 if one was removed.
int remove_value(struct node **head, int value)
{
    for (struct node **link = head; *link != NULL; link = &(*link)->next) {
        if ((*link)->value == value) {
            struct node *gone = *link;
            *link = gone->next;     // the link now skips the node
            free(gone);
            return 1;
        }
    }
    return 0;
}

Linus Torvalds called this pointer-to-pointer version "good taste": the special case for the head has disappeared.

Lists or arrays?

Growing array Linked list
get element i instant walk i nodes
add at the end fast (on average) fast if you keep a tail pointer
add at the front or middle move everything after it change two pointers
memory one block, packed together one allocation per node, plus a pointer each

Modern processors read memory that sits together much faster (thanks to caches, see the Fundamentals course), so arrays usually win in practice. Linked lists still shine where elements must never move, and inside operating systems, which link processes and buffers together this way all the time.
