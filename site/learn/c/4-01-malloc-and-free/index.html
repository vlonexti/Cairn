malloc and free

lesson 4.011 of 6 in milestone 45 min1 practice task

Stack memory disappears when a function returns and must have a size known in advance. The heap gives memory of any size that lasts until you free it. malloc returns NULL when it fails, calloc clears the memory, and every malloc needs exactly one free - never zero, never two.

Two places for memory

The stack The heap
holds local variables and parameters whatever you ask for
size fixed when the code is written chosen while the program runs
lasts until the function returns until you free it
limit a few megabytes most of the computer's memory

Locals are perfect until you need memory that outlives the function, or whose size you only learn while the program runs, like "as many numbers as the user types". Then you ask the heap.

malloc

malloc(bytes) (in stdlib.h) finds a block of at least that many bytes and returns its address as a void *, which converts to any pointer type:

C
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int count = 5;
    int *squares = malloc(count * sizeof *squares);
    if (squares == NULL) {
        fprintf(stderr, "out of memory\n");
        return 1;
    }
    for (int i = 0; i < count; i++) {
        squares[i] = i * i;
    }
    for (int i = 0; i < count; i++) {
        printf("%d ", squares[i]);
    }
    printf("\n");
    free(squares);
    return 0;
}
  • count * sizeof *squares is "count elements of whatever squares points at". Writing sizeof *squares instead of sizeof(int) stays right if the type changes later.
  • Memory from malloc holds garbage until you write to it.
  • malloc returns NULL when it cannot find the memory. Check it.
  • A pointer to heap memory is used exactly like an array: squares[i].

calloc(count, size) does the same but sets every byte to 0, and checks that count * size does not overflow:

C
int *counts = calloc(26, sizeof *counts);   // 26 ints, all 0

free

free(pointer) hands the block back. After that the memory is not yours:

The three classic heap bugs
  • Memory leak: never calling free. The memory stays taken until the program ends. Leaking inside a loop in a long-running program (a server, a game) eventually uses up everything.
  • Use after free: reading or writing through a pointer after freeing it. The block may already belong to something else.
  • Double free: freeing the same block twice. It corrupts the heap's own bookkeeping and usually crashes, sometimes much later.

Lesson 4.06 shows the tool that catches all three.

A good habit: set the pointer to NULL after freeing it. free(NULL) is defined to do nothing, so a second free becomes harmless, and a use after free becomes an obvious NULL crash instead of silent corruption.

Who frees?

Every block needs exactly one owner responsible for freeing it. When a function returns heap memory, its documentation must say so:

C
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// Returns a new copy of s on the heap. The caller must free it.
char *copy_text(const char *s)
{
    size_t size = strlen(s) + 1;          // + 1 for the terminator
    char *copy = malloc(size);
    if (copy == NULL) return NULL;
    memcpy(copy, s, size);
    return copy;
}

int main(void)
{
    char *name = copy_text("Dennis Ritchie");
    if (name == NULL) return 1;
    name[0] = 'd';
    printf("%s\n", name);
    free(name);
    name = NULL;
    return 0;
}

Unlike a local's address (lesson 3.03), returning heap memory is fine: it lives until it is freed. (C23 adds this exact function as strdup.)

What malloc really does

The heap is a big region of the program's memory that the C library manages. malloc keeps lists of free blocks, carves out one big enough, and writes a little header just before it recording its size; that is how free knows how much to give back from the pointer alone. When the heap runs out, the library asks the operating system for more (on Linux with the brk and mmap system calls).
