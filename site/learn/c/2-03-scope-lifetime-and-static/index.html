Scope, Lifetime and static

lesson 2.033 of 6 in milestone 25 min1 practice task

Scope is where a name can be used; lifetime is how long the variable exists. Locals live for one call, globals for the whole run. static on a local keeps it alive between calls, and static on a global or function hides it inside its file. Uninitialised locals hold garbage.

Scope: where a name is visible

A variable declared inside { } is visible only from its declaration to the closing brace: block scope.

C
#include <stdio.h>

int main(void)
{
    int total = 0;
    for (int i = 0; i < 3; i++) {
        int doubled = i * 2;        // exists only inside the loop body
        total += doubled;
    }
    // printf("%d", doubled);       // error: 'doubled' undeclared
    printf("%d\n", total);
    return 0;
}

A variable declared outside every function is a global: visible to all the functions below it in the file.

Shadowing

A local with the same name as an outer variable shadows it: inside the block, the name means the inner one. It is legal and confusing. This course compiles with -Wshadow, which warns about it.

Lifetime: how long it exists

Kind Exists Starts as
local (automatic) from the start of its block to the end garbage unless you set it
global the whole run of the program 0 unless you set it
static local the whole run of the program 0 unless you set it
C
#include <stdio.h>

int main(void)
{
    int count;              // no value given
    printf("%d\n", count);  // anything at all: whatever was in that memory
    return 0;
}

GCC warns "'count' is used uninitialized". Always give locals a starting value.

static locals remember

A static local is created once and keeps its value between calls, but its name is still visible only inside the function:

C
#include <stdio.h>

int next_ticket(void)
{
    static int last = 0;    // set to 0 once, when the program starts
    last++;
    return last;
}

int main(void)
{
    printf("%d\n", next_ticket());   // 1
    printf("%d\n", next_ticket());   // 2
    printf("%d\n", next_ticket());   // 3
    return 0;
}

Without static, last would start again at 0 on every call and the function would always return 1.

static outside a function hides

On a global variable or a function, static means something else: visible only in this file. When a program has several .c files (lesson 5.05), static keeps helpers private and avoids name clashes between files.

C
static int helper(int x)        // only this file can call helper
{
    return x * 3;
}

Prefer locals and parameters

Globals are easy to reach for and hard to live with: any function can change them, so a wrong value could have come from anywhere. Pass values in as parameters and get them back as return values. Keep globals for things that really belong to the whole program, and make them static if only one file needs them.
