Files

lesson 5.033 of 5 in milestone 55 min1 practice task

fopen opens a file and returns a FILE pointer, or NULL with errno saying why. The familiar fprintf, fgets and fscanf work on any FILE, and stdin, stdout and stderr are FILEs too. fwrite and fread move raw bytes, fseek and ftell move around in a file, and every opened file must be closed.

Opening and closing

C
#include <stdio.h>

int main(void)
{
    FILE *out = fopen("scores.txt", "w");
    if (out == NULL) {
        perror("scores.txt");        // prints the reason, such as "Permission denied"
        return 1;
    }
    fprintf(out, "Ada 1200\nGrace 950\nLinus 1100\n");
    fclose(out);

    FILE *in = fopen("scores.txt", "r");
    if (in == NULL) {
        perror("scores.txt");
        return 1;
    }
    char name[32];
    int score = 0;
    while (fscanf(in, "%31s %d", name, &score) == 2) {
        printf("%-8s %5d\n", name, score);
    }
    fclose(in);
    return 0;
}

Programs on this website run in a small sandbox with a folder of their own, so they can create and read files; the files disappear when the run ends.

Mode Opens for If the file exists If not
"r" reading read from the start fails
"w" writing emptied created
"a" appending write at the end created
"r+" reading and writing kept fails
add b: "rb", "wb" binary

The b matters on Windows, where text mode turns \n into \r\n on the way out and back on the way in. On Linux and Mac there is no difference, but write it for binary files anyway.

Errors: NULL and errno

Opening fails for many reasons: no such file, no permission, a folder in the way. fopen returns NULL and sets errno (in errno.h) to a code. perror("text") prints your text and the reason; strerror(errno) gives the reason as a string.

C
#include <errno.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    FILE *f = fopen("does-not-exist.txt", "r");
    if (f == NULL) {
        printf("could not open: %s\n", strerror(errno));
        return 1;
    }
    fclose(f);
    return 0;
}

stdin, stdout, stderr

The three streams every program starts with are ordinary FILE *s:

  • printf(...) is fprintf(stdout, ...).
  • fgets(line, size, stdin) reads the keyboard or input.
  • fprintf(stderr, ...) writes errors. They go to a separate stream, so program > out.txt saves the results while errors still show on screen.

That means a function written as void report(FILE *out) can print to the screen or into a file.

Binary files: fwrite and fread

fwrite(pointer, size, count, file) writes count items of size bytes, straight from memory. fread reads them back. Both return how many items they managed:

C
#include <stdio.h>

int main(void)
{
    double readings[4] = {20.5, 21.25, 19.75, 22.0};
    FILE *f = fopen("readings.bin", "wb");
    if (f == NULL) return 1;
    size_t written = fwrite(readings, sizeof readings[0], 4, f);
    fclose(f);
    printf("wrote %zu doubles\n", written);

    double back[4] = {0};
    f = fopen("readings.bin", "rb");
    if (f == NULL) return 1;
    size_t got = fread(back, sizeof back[0], 4, f);
    fclose(f);
    for (size_t i = 0; i < got; i++) printf("%.2f\n", back[i]);
    return 0;
}

Raw memory is quick to save, but the file then depends on the machine's endianness and type sizes. For files shared between machines, write each field's bytes in a fixed order (lesson 5.02).

Moving around

  • ftell(f) returns the current position in bytes.
  • fseek(f, offset, SEEK_SET) jumps to a position from the start (SEEK_CUR from here, SEEK_END from the end).
  • rewind(f) goes back to the start.
C
fseek(f, 0, SEEK_END);
long size = ftell(f);          // the file's size in bytes
rewind(f);

Buffering, and why fclose matters

FILE streams collect output in a buffer in memory and write it out in big pieces, because every system call to the operating system costs time. fclose (or fflush) sends what is left. A program that crashes or forgets fclose can lose the end of its output. Every program has a limit on open files, too, so close each one you open.
