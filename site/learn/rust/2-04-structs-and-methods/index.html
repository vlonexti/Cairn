Structs and Methods

lesson 2.044 of 5 in milestone 25 min1 practice task

Defining structs with named fields, tuple structs and unit structs, creating them with field init shorthand and update syntax, methods in impl blocks with &self, &mut self and self, associated functions like new, deriving Debug, Clone and PartialEq, and privacy with pub.

Structs

A struct groups named values into one type:

Rust
#[derive(Debug, Clone, PartialEq)]
struct Book {
    title: String,
    author: String,
    year: u16,
    pages: u32,
}

fn main() {
    let dune = Book {
        title: String::from("Dune"),
        author: String::from("Frank Herbert"),
        year: 1965,
        pages: 412,
    };
    println!("{} by {} ({})", dune.title, dune.author, dune.year);
    println!("{dune:?}");                       // needs #[derive(Debug)]
    println!("{dune:#?}");                      // pretty-printed

    let messiah = Book { title: String::from("Dune Messiah"), year: 1969, ..dune.clone() };   // update syntax
    println!("{} {}", messiah.title, messiah == dune);
}

#[derive(...)] asks the compiler to generate standard behaviour: Debug for {:?} printing, Clone for .clone(), PartialEq for == (lesson 4.03 covers these traits).

A struct owns its fields. A field of type String means each Book owns its text, which is usually what you want; fields holding references need lifetimes (lesson 4.04).

Methods

Methods are defined in an impl block. The first parameter says how the method uses the value:

Rust
#[derive(Debug)]
struct Counter {
    name: String,
    count: u32,
}

impl Counter {
    fn new(name: &str) -> Counter {            // an associated function: no self, called as Counter::new
        Counter { name: name.to_string(), count: 0 }
    }

    fn increment(&mut self) {                   // &mut self: may change the struct
        self.count += 1;
    }

    fn describe(&self) -> String {              // &self: only reads it
        format!("{}: {}", self.name, self.count)
    }

    fn into_name(self) -> String {             // self: takes ownership; the counter is used up
        self.name
    }
}

fn main() {
    let mut clicks = Counter::new("clicks");
    clicks.increment();
    clicks.increment();
    println!("{}", clicks.describe());
    let name = clicks.into_name();
    println!("{name}");
    // clicks.describe();                       // error: clicks was moved by into_name
}
First parameter Meaning Use for
&self Borrows the value to read it Getters, calculations
&mut self Borrows it to change it Updating fields
self Takes ownership Turning it into something else
none An associated function Constructors like new

The method call clicks.increment() borrows clicks mutably for you; there is no need to write (&mut clicks).increment(). Inside methods, Self is the type being implemented.

Tuple structs and unit structs

Rust
#[derive(Debug, Clone, Copy, PartialEq)]
struct Meters(f64);                 // a tuple struct: a named wrapper

#[derive(Debug, Clone, Copy, PartialEq)]
struct Point(i32, i32);

struct Marker;                      // a unit struct: no fields

impl Meters {
    fn to_feet(self) -> f64 { self.0 * 3.28084 }
}

fn main() {
    let height = Meters(1.8);
    let p = Point(3, 4);
    let _m = Marker;
    println!("{:.2} {:?} {}", height.to_feet(), p, p.0 + p.1);
}

Wrapping a number in a tuple struct (Meters, UserId) makes the compiler stop you mixing up values that have the same underlying type: the newtype pattern.

Privacy

Fields and methods are private to their module unless marked pub. Inside one file's module that does not matter; once code is split into modules (lesson 3.05), keep fields private and expose methods, so that a struct's rules (like a non-negative balance) cannot be broken from outside.
