Operators and Conversions

lesson 8.022 of 5 in milestone 85 min2 practice tasks

Making your types work with Rust's operators and conversions - Add, Sub, Mul and Neg, the assignment forms like AddAssign, Index and IndexMut for [], From and Into, fallible conversions with TryFrom and TryInto, parsing with FromStr and str::parse, and AsRef-style flexibility in function arguments.

Operators are traits

a + b is shorthand for Add::add(a, b). Every operator has a trait in std::ops, and implementing it lets your type use the operator:

Rust
use std::ops::{Add, Mul, Neg, Sub};

#[derive(Debug, Clone, Copy, PartialEq)]
struct V2 {
    x: f64,
    y: f64,
}

impl Add for V2 {
    type Output = V2;
    fn add(self, o: V2) -> V2 {
        V2 { x: self.x + o.x, y: self.y + o.y }
    }
}

impl Sub for V2 {
    type Output = V2;
    fn sub(self, o: V2) -> V2 {
        V2 { x: self.x - o.x, y: self.y - o.y }
    }
}

impl Mul<f64> for V2 {
    type Output = V2;
    fn mul(self, k: f64) -> V2 {
        V2 { x: self.x * k, y: self.y * k }
    }
}

impl Neg for V2 {
    type Output = V2;
    fn neg(self) -> V2 {
        V2 { x: -self.x, y: -self.y }
    }
}

fn main() {
    let a = V2 { x: 1.0, y: 2.0 };
    let b = V2 { x: 3.0, y: 4.0 };
    println!("{:?}", a + b);
    println!("{:?}", (b - a) * 2.0);
    println!("{:?}", -a);
}

type Output says what the operator produces. Mul<f64> means "times an f64"; 2.0 * v would need a separate impl Mul<V2> for f64.

Because V2 is Copy, using it by value is cheap. For large types, implement the traits for references too (impl Add for &Matrix) so &a + &b does not move the operands.

Assignment operators

a += b uses AddAssign, which changes a in place:

Rust
use std::ops::AddAssign;

#[derive(Debug, Default)]
struct Totals {
    count: u32,
    sum: i64,
}

impl AddAssign<i64> for Totals {
    fn add_assign(&mut self, value: i64) {
        self.count += 1;
        self.sum += value;
    }
}

fn main() {
    let mut t = Totals::default();
    for v in [5, 10, 20] {
        t += v;
    }
    println!("{t:?}");
}

Indexing

Index and IndexMut give your type []:

Rust
use std::ops::{Index, IndexMut};

struct Grid {
    width: usize,
    cells: Vec<char>,
}

impl Index<(usize, usize)> for Grid {
    type Output = char;
    fn index(&self, (x, y): (usize, usize)) -> &char {
        &self.cells[y * self.width + x]
    }
}

impl IndexMut<(usize, usize)> for Grid {
    fn index_mut(&mut self, (x, y): (usize, usize)) -> &mut char {
        &mut self.cells[y * self.width + x]
    }
}

fn main() {
    let mut g = Grid { width: 3, cells: vec!['.'; 9] };
    g[(1, 1)] = '#';
    let rows: Vec<String> = g.cells.chunks(3).map(|r| r.iter().collect()).collect();
    println!("{}", rows.join("\n"));
    println!("{}", g[(1, 1)]);
}

Indexing should panic on a bad index, like slices do; offer a get method returning Option for callers who want to check.

From and Into

From describes a conversion that always works. Implementing From<A> for B gives you Into<B> for A for free:

Rust
#[derive(Debug)]
struct Celsius(f64);
#[derive(Debug)]
struct Fahrenheit(f64);

impl From<Celsius> for Fahrenheit {
    fn from(c: Celsius) -> Self {
        Fahrenheit(c.0 * 9.0 / 5.0 + 32.0)
    }
}

fn describe(t: impl Into<Fahrenheit>) -> String {
    let f: Fahrenheit = t.into();
    format!("{:.1} °F", f.0)
}

fn main() {
    let f = Fahrenheit::from(Celsius(100.0));
    println!("{f:?}");
    let g: Fahrenheit = Celsius(-40.0).into();
    println!("{g:?}");
    println!("{}", describe(Celsius(37.0)));
    let s: String = "text".into();       // the standard library is full of From impls
    let big: i64 = 5i32.into();          // widening numbers always works
    println!("{s} {big}");
}

Accepting impl Into<T> makes functions friendlier: callers can pass anything that converts.

Conversions that can fail: TryFrom

When a conversion might not work, implement TryFrom and return a Result:

Rust
use std::convert::TryFrom;

#[derive(Debug, PartialEq)]
struct Percent(u8);

impl TryFrom<i32> for Percent {
    type Error = String;
    fn try_from(v: i32) -> Result<Self, Self::Error> {
        if (0..=100).contains(&v) { Ok(Percent(v as u8)) } else { Err(format!("{v} is not a percentage")) }
    }
}

fn main() {
    println!("{:?}", Percent::try_from(42));
    let p: Result<Percent, _> = 150.try_into();
    println!("{p:?}");
    let small: Result<u8, _> = u8::try_from(300i32);       // number narrowing uses it too
    println!("{small:?}");
}

Prefer u8::try_from(x) to x as u8: as silently truncates (300 becomes 44).

Parsing: FromStr

"42".parse::<i32>() works because i32 implements FromStr. Implement it for your own types to get parse too:

Rust
use std::str::FromStr;

#[derive(Debug, PartialEq)]
struct Rgb(u8, u8, u8);

impl FromStr for Rgb {
    type Err = String;
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        let hex = s.strip_prefix('#').ok_or("must start with #")?;
        if hex.len() != 6 {
            return Err("needs 6 hex digits".into());
        }
        let part = |i: usize| u8::from_str_radix(&hex[i..i + 2], 16).map_err(|e| e.to_string());
        Ok(Rgb(part(0)?, part(2)?, part(4)?))
    }
}

fn main() {
    let c: Rgb = "#ff8800".parse().unwrap();
    println!("{c:?}");
    println!("{:?}", "ff8800".parse::<Rgb>());
    println!("{:?}", "#ff88".parse::<Rgb>());
}
