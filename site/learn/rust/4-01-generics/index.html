Generics

lesson 4.011 of 5 in milestone 45 min1 practice task

Writing code once for many types - generic functions with type parameters and trait bounds, where clauses, generic structs and enums like Option and Result, impl blocks for generic types and for specific types, const generics for array sizes, and monomorphization, which makes generics cost nothing at run time.

Generic functions

A function with a type parameter works for many types. Without a bound, the body can do almost nothing with a T; bounds say what the type must support:

Rust
fn largest<T: PartialOrd + Copy>(items: &[T]) -> Option<T> {
    let mut best = *items.first()?;
    for &item in items {
        if item > best {
            best = item;
        }
    }
    Some(best)
}

fn describe<T: std::fmt::Debug>(label: &str, value: T) -> String {
    format!("{label}: {value:?}")
}

fn main() {
    println!("{:?} {:?} {:?}", largest(&[3, 9, 2]), largest(&[1.5, -2.0]), largest(&['x', 'b']));
    println!("{:?}", largest::<i32>(&[]));
    println!("{}", describe("point", (3, 4)));
    println!("{}", describe("list", vec!["a", "b"]));
}

T: PartialOrd + Copy means "any type that can be compared with < and copied". The compiler checks the bounds where the function is defined, so a generic function either works for every allowed type or does not compile at all.

where clauses

Long bound lists read better in a where clause:

Rust
use std::fmt::Display;

fn join_all<T, U>(items: &[T], extra: U) -> String
where
    T: Display,
    U: Display + Clone,
{
    let mut out: Vec<String> = items.iter().map(|i| i.to_string()).collect();
    out.push(extra.to_string());
    out.join(", ")
}

fn main() {
    println!("{}", join_all(&[1, 2, 3], "and more"));
}

Generic structs and enums

Vec<T>, Option<T>, Result<T, E> and HashMap<K, V> are generic types from the standard library. Your own types can be too:

Rust
#[derive(Debug, Clone, PartialEq)]
struct Pair<T> {
    first: T,
    second: T,
}

impl<T: PartialOrd> Pair<T> {
    fn larger(&self) -> &T {
        if self.first >= self.second { &self.first } else { &self.second }
    }
}

impl<T> Pair<T> {
    fn swap(self) -> Pair<T> {
        Pair { first: self.second, second: self.first }
    }
}

impl Pair<f64> {                         // only for Pair<f64>
    fn distance(&self) -> f64 {
        (self.first - self.second).abs()
    }
}

#[derive(Debug)]
enum Tree<T> {
    Leaf(T),
    Node(Box<Tree<T>>, Box<Tree<T>>),
}

fn count_leaves<T>(t: &Tree<T>) -> usize {
    match t {
        Tree::Leaf(_) => 1,
        Tree::Node(l, r) => count_leaves(l) + count_leaves(r),
    }
}

fn main() {
    let p = Pair { first: 3, second: 8 };
    println!("{} {:?}", p.larger(), p.clone().swap());
    println!("{}", Pair { first: 1.5, second: 4.0 }.distance());
    let t = Tree::Node(Box::new(Tree::Leaf("a")), Box::new(Tree::Node(Box::new(Tree::Leaf("b")), Box::new(Tree::Leaf("c")))));
    println!("{}", count_leaves(&t));
}

impl<T> Pair<T> applies to every Pair; impl<T: PartialOrd> Pair<T> only when T can be compared; impl Pair<f64> only for one concrete type. Box (lesson 5.04) puts the recursive tree parts on the heap.

Const generics

Types can also be parameterised by values, most often array lengths:

Rust
fn sum_all<const N: usize>(values: [i32; N]) -> i32 {
    let mut total = 0;
    for v in values { total += v; }
    total
}

#[derive(Debug)]
struct Grid<const W: usize, const H: usize> {
    cells: [[u8; W]; H],
}

fn main() {
    println!("{} {}", sum_all([1, 2, 3]), sum_all([10; 5]));
    let g = Grid::<3, 2> { cells: [[0; 3]; 2] };
    println!("{:?}", g);
}

Zero-cost

The compiler generates a separate, fully optimised copy of a generic function for each concrete type it is used with (monomorphization). largest::<i32> and largest::<f64> are as fast as hand-written versions. The cost is compile time and binary size, not run time.
