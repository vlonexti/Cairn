Files, Paths and Processes

lesson 7.044 of 5 in milestone 75 min2 practice tasks

Working with the operating system - std::fs for reading, writing and listing files, BufReader for large files, Path and PathBuf, io::Error and its kinds, environment variables and arguments, running other programs with std::process::Command, and exit codes.

Reading and writing whole files

std::fs has one-call helpers for small files. Every one returns a Result with an io::Error, so ? (lesson 3.04) passes failures on:

Rust
use std::fs;
use std::io;

fn main() -> io::Result<()> {
    fs::write("notes.txt", "first line\nsecond line\n")?;
    let text = fs::read_to_string("notes.txt")?;
    println!("{} lines", text.lines().count());

    let bytes = fs::read("notes.txt")?;            // Vec<u8> for binary data
    println!("{} bytes", bytes.len());

    fs::create_dir_all("out/reports")?;
    fs::copy("notes.txt", "out/reports/notes.txt")?;
    fs::remove_file("notes.txt")?;
    Ok(())
}

(Examples in this lesson touch your file system, so they run on your own machine rather than in Xenon's sandbox.)

Large files, line by line

read_to_string loads everything into memory. For a big file, wrap the File in a BufReader and read one line at a time:

Rust
use std::fs::File;
use std::io::{self, BufRead, BufReader, BufWriter, Write};

fn main() -> io::Result<()> {
    let input = BufReader::new(File::open("server.log")?);
    let mut output = BufWriter::new(File::create("errors.log")?);
    for line in input.lines() {
        let line = line?;
        if line.contains("ERROR") {
            writeln!(output, "{line}")?;
        }
    }
    output.flush()?;
    Ok(())
}

BufWriter gathers small writes into large ones. The same BufRead trait works for io::stdin().lock(), so one function can read either a file or standard input.

Errors and their kinds

An io::Error has a kind() you can match on, to treat "not found" differently from "permission denied":

Rust
use std::fs;
use std::io::ErrorKind;

fn main() {
    match fs::read_to_string("does-not-exist.txt") {
        Ok(text) => println!("{} characters", text.len()),
        Err(e) if e.kind() == ErrorKind::NotFound => println!("no such file, using defaults"),
        Err(e) => println!("could not read it: {e}"),
    }
}

Paths

Path (borrowed) and PathBuf (owned) are to file paths what &str and String are to text. They handle / and \ correctly on every system:

Rust
use std::path::{Path, PathBuf};

fn main() {
    let p = Path::new("photos/2026/beach.jpg");
    println!("{:?} {:?} {:?}", p.file_name(), p.extension(), p.parent());
    println!("{:?}", p.file_stem());

    let mut out = PathBuf::from("backup");
    out.push("2026");
    out.push("beach.jpg");
    out.set_extension("png");
    println!("{}", out.display());
}

Paths are not always valid UTF-8, so they print with .display() and convert to &str with to_str(), which returns an Option.

Listing a folder

Rust
use std::fs;
use std::io;

fn main() -> io::Result<()> {
    let mut entries: Vec<_> = fs::read_dir(".")?.collect::<Result<_, _>>()?;
    entries.sort_by_key(|e| e.file_name());
    for entry in entries {
        let meta = entry.metadata()?;
        println!("{:>10} {}", if meta.is_dir() { "<dir>".to_string() } else { meta.len().to_string() }, entry.path().display());
    }
    Ok(())
}

Arguments, environment and exit codes

Rust
use std::env;
use std::process::ExitCode;

fn main() -> ExitCode {
    let args: Vec<String> = env::args().skip(1).collect();      // skip the program name
    let verbose = env::var("VERBOSE").is_ok();
    if args.is_empty() {
        eprintln!("usage: tool FILE...");
        return ExitCode::from(2);
    }
    if verbose { eprintln!("{} files", args.len()); }
    ExitCode::SUCCESS
}

eprintln! writes to standard error, so messages do not mix with the real output. For real argument parsing, the clap crate is the standard choice.

Running other programs

std::process::Command starts a program, passes arguments, and collects its output and exit status:

Rust
use std::process::Command;

fn main() -> std::io::Result<()> {
    let output = Command::new("git").args(["log", "--oneline", "-3"]).output()?;
    if output.status.success() {
        print!("{}", String::from_utf8_lossy(&output.stdout));
    } else {
        eprintln!("git failed: {}", String::from_utf8_lossy(&output.stderr));
    }
    Ok(())
}

Arguments are passed as a list, never glued into one string for a shell, so a file name with spaces or quotes cannot break the command.

A pure core again

As in the command-line project (lesson 6.05), keep parsing and deciding in functions that take &str or impl BufRead and return values, and keep the files, arguments and process handling in a thin main. The core can then be tested without touching the disk.
