Threads and Message Passing

lesson 6.011 of 5 in milestone 65 min1 practice task

Fearless concurrency - spawning threads and joining them, move closures that give a thread its data, scoped threads that can borrow, channels with mpsc for sending messages between threads, multiple producers, worker pools fed by a channel, and how Send and Sync let the compiler rule out data races.

Spawning threads

std::thread::spawn runs a closure on a new operating-system thread. join waits for it and returns its result:

Rust
use std::thread;
use std::time::Duration;

fn main() {
    let handle = thread::spawn(|| {
        for i in 1..=3 {
            println!("worker {i}");
            thread::sleep(Duration::from_millis(5));
        }
        42
    });
    println!("main keeps going");
    let answer = handle.join().unwrap();          // wait; Err if the thread panicked
    println!("worker returned {answer}");
}

The order of output from different threads is not fixed: run it twice and it may differ.

Giving a thread its data

A spawned thread may outlive the function that started it, so it cannot borrow local variables. Use a move closure to give it ownership:

Rust
use std::thread;

fn main() {
    let words = vec!["alpha".to_string(), "beta".to_string(), "gamma".to_string()];
    let handle = thread::spawn(move || {
        words.iter().map(|w| w.len()).sum::<usize>()        // the thread owns words now
    });
    // println!("{words:?}");                                 // error: words was moved into the thread
    println!("{}", handle.join().unwrap());
}

Without move, the compiler refuses: "closure may outlive the current function, but it borrows words". This is the first of several ways Rust stops threading bugs at compile time.

Scoped threads

thread::scope guarantees that every thread started inside it finishes before the scope ends, so those threads may borrow local data:

Rust
use std::thread;

fn main() {
    let data: Vec<u64> = (1..=1_000_000).collect();
    let chunk = data.len() / 4;
    let total: u64 = thread::scope(|s| {
        let handles: Vec<_> = data.chunks(chunk)
            .map(|part| s.spawn(move || part.iter().sum::<u64>()))   // borrows a slice of data
            .collect();
        handles.into_iter().map(|h| h.join().unwrap()).sum()
    });
    println!("{total} {}", total == 1_000_000 * 1_000_001 / 2);
}

This is the simplest way to split work across cores: each thread computes its own part, and the results are combined at the end, with no shared mutable state.

Channels

A channel sends values from one thread to another. mpsc stands for multiple producer, single consumer:

Rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();
    for id in 0..3 {
        let tx = tx.clone();                       // each producer gets its own sender
        thread::spawn(move || {
            for n in 0..2 {
                tx.send(format!("worker {id} item {n}")).unwrap();
            }
        });
    }
    drop(tx);                                      // close the original sender
    let mut received: Vec<String> = rx.iter().collect();   // ends when every sender is gone
    received.sort();
    println!("{} messages, first: {}", received.len(), received[0]);
}

send moves the value into the channel: once sent, the sending thread cannot use it any more, so two threads can never touch the same data. Receiving with rx.recv() blocks until a value arrives (or returns Err when all senders are dropped); iterating over rx does that in a loop.

A worker pool

A common shape: one channel of jobs feeding several workers, and another channel collecting results:

Rust
use std::sync::{mpsc, Arc, Mutex};
use std::thread;

fn main() {
    let (job_tx, job_rx) = mpsc::channel::<u64>();
    let (result_tx, result_rx) = mpsc::channel::<(u64, bool)>();
    let job_rx = Arc::new(Mutex::new(job_rx));          // several workers share one receiver (lesson 6.02)

    let workers: Vec<_> = (0..3).map(|_| {
        let jobs = Arc::clone(&job_rx);
        let results = result_tx.clone();
        thread::spawn(move || loop {
            let job = jobs.lock().unwrap().recv();
            match job {
                Ok(n) => results.send((n, (2..n).take_while(|d| d * d <= n).all(|d| n % d != 0))).unwrap(),
                Err(_) => break,                         // the job channel is closed: stop
            }
        })
    }).collect();
    drop(result_tx);

    for n in [97, 98, 7919, 7920, 104_729] { job_tx.send(n).unwrap(); }
    drop(job_tx);                                       // no more jobs
    let mut results: Vec<_> = result_rx.iter().collect();
    results.sort();
    for w in workers { w.join().unwrap(); }
    println!("{results:?}");
}

Send and Sync

Two marker traits make this safe:

  • Send: a value can be moved to another thread. Almost everything is Send; Rc is not (its counter is not thread-safe), so thread::spawn(move || rc.clone()) does not compile.
  • Sync: a value can be shared between threads by reference. RefCell is not Sync.

The compiler checks these automatically. Code that could cause a data race (two threads accessing the same memory, at least one writing, without synchronisation) does not compile. That is what Rust calls fearless concurrency.
