Deref, AsRef, Borrow and Cow

lesson 7.022 of 5 in milestone 75 min2 practice tasks

The traits behind smart pointers and flexible APIs - Deref and deref coercion, implementing Deref for your own wrapper, the newtype pattern, AsRef for functions that accept many kinds of input, Borrow for map lookups, and Cow for data that is borrowed until it has to be changed.

Deref and deref coercion

Box<T>, Rc<T>, String and Vec<T> all implement Deref: they can be treated as a reference to what is inside. *b on a Box<i32> gives the i32, and method calls look through automatically:

Rust
fn shout(text: &str) -> String {
    text.to_uppercase()
}

fn main() {
    let owned = String::from("hello");
    let boxed = Box::new(String::from("boxed"));
    println!("{}", shout(&owned));   // &String becomes &str
    println!("{}", shout(&boxed));   // &Box<String> becomes &String becomes &str
    println!("{}", boxed.len());     // the method is found through Box
}

This automatic conversion from &Wrapper to &Inner is deref coercion. It is why functions should take &str instead of &String, and &[T] instead of &Vec<T>: they then accept every kind of string or slice.

The newtype pattern

A newtype wraps one value in a struct of its own: struct Email(String). It gives the value a distinct type (so an Email cannot be passed where a Username is expected), lets you implement traits for it, and lets you control which operations exist:

Rust
use std::fmt;

#[derive(Debug, Clone, PartialEq)]
struct Email(String);

impl Email {
    fn parse(text: &str) -> Result<Email, String> {
        match text.split_once('@') {
            Some((user, domain)) if !user.is_empty() && domain.contains('.') => Ok(Email(text.to_lowercase())),
            _ => Err(format!("not an email address: {text}")),
        }
    }

    fn domain(&self) -> &str {
        self.0.split_once('@').map(|(_, d)| d).unwrap_or("")
    }
}

impl fmt::Display for Email {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "<{}>", self.0)
    }
}

fn main() {
    let e = Email::parse("Ada@Example.com").unwrap();
    println!("{e} at {}", e.domain());
    println!("{:?}", Email::parse("nobody"));
}

Once created, an Email is known to be valid everywhere: the check is in one place.

Implementing Deref, carefully

Implementing Deref for a newtype makes all of the inner type's &self methods available on it. That is right for smart pointers and wrappers that really are the inner thing; it is wrong when the wrapper exists to restrict what can be done (it would let every method through).

Rust
use std::ops::Deref;

struct Sorted(Vec<i32>);          // always sorted: only read access is given out

impl Sorted {
    fn new(mut v: Vec<i32>) -> Sorted {
        v.sort();
        Sorted(v)
    }
}

impl Deref for Sorted {
    type Target = [i32];
    fn deref(&self) -> &[i32] {
        &self.0
    }
}

fn main() {
    let s = Sorted::new(vec![5, 1, 4]);
    println!("{:?} min {} has 4: {}", &s[..], s[0], s.binary_search(&4).is_ok());
}

Only Deref (not DerefMut) is implemented, so callers can read the slice but never unsort it.

AsRef: accept anything that can give a reference

AsRef<T> means "can cheaply give a &T". Taking impl AsRef<Path> lets a function accept &str, String, &Path and PathBuf alike; that is how std::fs::read_to_string is declared:

Rust
fn count_words<S: AsRef<str>>(texts: &[S]) -> usize {
    texts.iter().map(|t| t.as_ref().split_whitespace().count()).sum()
}

fn main() {
    let borrowed = ["a b", "c"];
    let owned = vec![String::from("one two three")];
    println!("{} {}", count_words(&borrowed), count_words(&owned));
}

Borrow: looking up owned keys with borrowed values

A HashMap<String, V> can be searched with a &str, without making a String, because String: Borrow<str>. The rule behind Borrow is stricter than AsRef: the borrowed form must hash and compare exactly like the owned one. You rarely implement it; you rely on it every time you call map.get("key").

Cow: borrow until you must own

Cow<'a, T> ("clone on write") holds either a borrowed &'a T or an owned value. A function that usually returns its input unchanged, but sometimes has to build a new value, can avoid allocating in the common case:

Rust
use std::borrow::Cow;

fn normalise_spaces(text: &str) -> Cow<'_, str> {
    if !text.contains("  ") {
        return Cow::Borrowed(text);          // nothing to do: no allocation
    }
    let mut out = String::with_capacity(text.len());
    let mut last_space = false;
    for c in text.chars() {
        if c == ' ' && last_space { continue; }
        last_space = c == ' ';
        out.push(c);
    }
    Cow::Owned(out)
}

fn main() {
    for t in ["already fine", "too   many  spaces"] {
        let n = normalise_spaces(t);
        let kind = if matches!(n, Cow::Borrowed(_)) { "borrowed" } else { "owned" };
        println!("{n:?} ({kind})");
    }
}

A Cow<str> derefs to &str, so callers use it like any string; .into_owned() gives a String when they need one.
