HashMap and HashSet

lesson 3.033 of 5 in milestone 35 min1 practice task

Key-value lookups with HashMap - insert, get, contains_key, remove, iterating, and the entry API for counting and grouping - unique values with HashSet and its set operations, ordered alternatives BTreeMap and BTreeSet, ownership of keys and values, and which key types are allowed.

HashMap

HashMap<K, V> maps keys to values with O(1) average lookup. It lives in std::collections:

Rust
use std::collections::HashMap;

fn main() {
    let mut ages: HashMap<String, u32> = HashMap::new();
    ages.insert("Ada".to_string(), 36);
    ages.insert("Grace".to_string(), 85);
    ages.insert("Ada".to_string(), 37);               // replaces; insert returns Some(36)

    println!("{:?}", ages.get("Ada"));                 // Some(37): look up with &str
    println!("{}", ages.get("Bob").copied().unwrap_or(0));
    println!("{}", ages.contains_key("Grace"));
    if let Some(age) = ages.get_mut("Grace") {
        *age += 1;
    }
    ages.remove("Ada");
    for (name, age) in &ages {                         // order is unspecified
        println!("{name}: {age}");
    }
    println!("{}", ages.len());
}

A HashMap<String, ...> can be looked up with a &str, so you do not need to allocate a String just to search.

Inserting moves the key and value into the map: the map owns them. Values that are Copy (numbers) are copied in.

The entry API

Counting and grouping need "insert if missing, then update". The entry API does it in one lookup:

Rust
use std::collections::HashMap;

fn main() {
    let text = "the cat and the hat and the bat";
    let mut counts: HashMap<&str, usize> = HashMap::new();
    for word in text.split_whitespace() {
        *counts.entry(word).or_insert(0) += 1;
    }
    let mut sorted: Vec<(&str, usize)> = counts.into_iter().collect();
    sorted.sort_by(|a, b| b.1.cmp(&a.1).then(a.0.cmp(b.0)));     // by count, then word
    println!("{sorted:?}");

    let words = ["apple", "avocado", "banana", "blueberry", "cherry"];
    let mut by_letter: HashMap<char, Vec<&str>> = HashMap::new();
    for w in words {
        by_letter.entry(w.chars().next().unwrap()).or_default().push(w);
    }
    let mut letters: Vec<_> = by_letter.keys().collect();
    letters.sort();
    for l in letters {
        println!("{l}: {:?}", by_letter[l]);
    }
}
Entry method Does
entry(k).or_insert(v) Inserts v if missing; returns &mut V
entry(k).or_insert_with(f) Same, computing the value only when needed
entry(k).or_default() Inserts V::default() (0, empty vec...) if missing
entry(k).and_modify(f).or_insert(v) Updates an existing value, or inserts

map[&key] panics when the key is missing; use it only when the key must exist.

HashSet

HashSet<T> holds unique values with fast membership tests:

Rust
use std::collections::HashSet;

fn main() {
    let mut seen = HashSet::new();
    for tag in ["rust", "cli", "rust", "web"] {
        if !seen.insert(tag) {                         // insert returns false for duplicates
            println!("duplicate: {tag}");
        }
    }
    let a: HashSet<i32> = [1, 2, 3, 4].into_iter().collect();
    let b: HashSet<i32> = [3, 4, 5].into_iter().collect();
    let mut both: Vec<_> = a.intersection(&b).copied().collect();
    let mut either: Vec<_> = a.union(&b).copied().collect();
    let mut only_a: Vec<_> = a.difference(&b).copied().collect();
    both.sort(); either.sort(); only_a.sort();
    println!("{both:?} {either:?} {only_a:?} {}", a.contains(&2));
}

Ordered maps and sets

HashMap and HashSet iterate in an unpredictable order. When order matters (printing, ranges, smallest or largest key), use BTreeMap and BTreeSet, which keep keys sorted (O(log n) operations):

Rust
use std::collections::BTreeMap;

fn main() {
    let mut scores = BTreeMap::new();
    for (name, score) in [("linus", 72), ("ada", 95), ("grace", 88)] {
        scores.insert(name, score);
    }
    println!("{scores:?}");                                  // sorted by key
    println!("{:?} {:?}", scores.first_key_value(), scores.last_key_value());
    for (name, s) in scores.range("b".."h") {                // keys from "b" up to "h"
        println!("{name} {s}");
    }
}

Keys

A key type must implement Eq and Hash (for HashMap) or Ord (for BTreeMap). Strings, integers, char, bool, tuples of those, and your own types with #[derive(PartialEq, Eq, Hash)] all work. f64 does not (NaN breaks equality); use an integer representation instead.
