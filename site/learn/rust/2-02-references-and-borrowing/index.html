References and Borrowing

lesson 2.022 of 5 in milestone 25 min1 practice task

Using values without taking ownership - shared references &T and mutable references &mut T, the borrowing rules (many readers or one writer), why they prevent data races and invalid pointers, non-lexical lifetimes, dangling references the compiler refuses, and dereferencing with *.

Borrowing

A reference lets code use a value without owning it. Creating one is called borrowing:

Rust
fn main() {
    let s = String::from("hello world");
    let n = length(&s);              // lend s; we keep ownership
    println!("{s} has {n} bytes");   // s is still ours
}

fn length(text: &String) -> usize {  // &String: a reference to a String
    text.len()
}                                    // the reference goes away; nothing is dropped

&s creates a shared reference; the function can read through it but not change the value.

Mutable references

To let a function change a value, lend it a mutable reference, &mut. Both the variable and the borrow must be marked mutable:

Rust
fn main() {
    let mut s = String::from("hello");
    add_world(&mut s);
    let mut count = 0;
    bump(&mut count);
    bump(&mut count);
    println!("{s} {count}");
}

fn add_world(text: &mut String) {
    text.push_str(", world");
}

fn bump(n: &mut i32) {
    *n += 1;                         // * dereferences: change the value the reference points to
}

The borrowing rules

At any moment, a value can have either:

  • any number of shared references &T, or
  • exactly one mutable reference &mut T,

but not both. And a reference must never outlive the value it points to.

Rust
let mut v = vec![1, 2, 3];
let first = &v[0];           // a shared borrow of v
v.push(4);                   // error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable
println!("{first}");

This rule prevents a real bug: push may move the vector's buffer to a bigger allocation, leaving first pointing at freed memory. In C++ the equivalent code compiles and corrupts memory at run time; in Rust it does not compile. Across threads, the same rule rules out data races (milestone 6).

Borrows end when last used

A borrow lasts until its last use, not until the end of the block, so code like this is fine:

Rust
fn main() {
    let mut scores = vec![10, 20, 30];
    let total: i32 = scores.iter().sum();       // a shared borrow, used here and finished
    scores.push(total);                          // now a mutable borrow is fine
    let last = scores.last().unwrap();           // shared borrow
    println!("{last} {}", scores.len());         // more shared borrows: fine together
}

No dangling references

A function cannot return a reference to something it created, because that value is dropped when the function ends:

Rust
fn dangle() -> &String {          // error[E0106]: missing lifetime specifier
    let s = String::from("hi");
    &s                            // s is dropped here: the reference would point at freed memory
}

Return the owned value instead: fn no_dangle() -> String { String::from("hi") }. Lesson 4.04 explains the lifetimes the compiler uses to check this.

&str and &String

&String coerces to &str automatically (deref coercion), so functions that only read text should take &str and accept both:

Rust
fn shout(text: &str) -> String {
    text.to_uppercase() + "!"
}

fn main() {
    let owned = String::from("hey");
    println!("{} {}", shout(&owned), shout("you"));
}
