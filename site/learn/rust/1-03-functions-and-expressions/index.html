Functions and Expressions

lesson 1.033 of 5 in milestone 15 min1 practice task

Declaring functions with typed parameters and return types, statements versus expressions, returning the last expression without a semicolon, blocks as expressions, early return, unit (), and why Rust has no function overloading or default arguments.

Functions

Rust
fn main() {
    println!("{}", area(3.0, 4.0));
    greet("Grace");
    println!("{}", is_even(10));
    let (q, r) = divide(17, 5);
    println!("{q} remainder {r}");
}

fn area(width: f64, height: f64) -> f64 {
    width * height                     // no semicolon: this is the returned value
}

fn greet(name: &str) {                 // no return type: returns () ("unit")
    println!("Hello, {name}!");
}

fn is_even(n: i32) -> bool {
    n % 2 == 0
}

fn divide(a: i32, b: i32) -> (i32, i32) {
    (a / b, a % b)                     // a tuple returns two values
}

Every parameter needs a type; the return type follows ->. Functions can be defined in any order. Names use snake_case.

Statements and expressions

Rust is an expression language: almost everything produces a value.

  • An expression evaluates to a value: 5, a + b, if ... {} else {}, a block { ... }, a function call.
  • A statement does something and has no value: let x = 5;, or any expression followed by ;.

The last expression in a block, without a semicolon, is the block's value:

Rust
fn main() {
    let y = {
        let x = 3;
        x * x + 1               // the block's value
    };
    let sign = if y > 5 { "big" } else { "small" };    // if is an expression too
    println!("{y} {sign}");
}

Adding a ; after the last expression turns it into a statement, and the block's value becomes (). That is the most common error for newcomers:

Text
error[E0308]: mismatched types
fn square(x: i32) -> i32 {
                     --- expected `i32` because of return type
    x * x;
         - help: remove this semicolon to return this value

Early return

return leaves a function early, typically after checking for a special case:

Rust
fn main() {
    println!("{} {} {}", grade(95), grade(72), grade(-5));
}

fn grade(score: i32) -> char {
    if !(0..=100).contains(&score) {
        return '?';
    }
    match score {
        90..=100 => 'A',
        70..=89 => 'C',
        _ => 'F',
    }
}

0..=100 is an inclusive range; 0..100 excludes the end. match (lesson 2.05) picks a branch by pattern.

No overloading, no defaults

Rust has no function overloading and no default parameter values. Give different functions different names (area_circle, area_rect), or use an Option parameter, a struct of options, or a trait (milestone 4). This keeps every call unambiguous.
