Error Types in Depth

lesson 8.011 of 5 in milestone 85 min2 practice tasks

Designing errors for real programs - an error enum per module, implementing Display and std::error::Error, keeping the cause with source(), From conversions so ? converts errors for you, Box<dyn Error> for small programs, adding context, and what the thiserror and anyhow crates automate.

Beyond String errors

Lesson 3.04 used Result<T, String> and ?. Strings are fine in small examples, but a caller cannot easily tell one failure from another by looking at text. Real Rust code gives each module an error type: usually an enum with one variant per kind of failure.

Rust
use std::fmt;

#[derive(Debug, PartialEq)]
enum ConfigError {
    Missing(String),
    BadNumber { key: String, value: String },
    OutOfRange { key: String, min: i64, max: i64 },
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ConfigError::Missing(key) => write!(f, "missing setting {key}"),
            ConfigError::BadNumber { key, value } => write!(f, "{key} should be a number, not {value:?}"),
            ConfigError::OutOfRange { key, min, max } => write!(f, "{key} must be from {min} to {max}"),
        }
    }
}

impl std::error::Error for ConfigError {}

fn port(settings: &[(&str, &str)]) -> Result<i64, ConfigError> {
    let (_, text) = settings.iter().find(|(k, _)| *k == "port").ok_or(ConfigError::Missing("port".into()))?;
    let n: i64 = text.parse().map_err(|_| ConfigError::BadNumber { key: "port".into(), value: text.to_string() })?;
    if !(1..=65535).contains(&n) {
        return Err(ConfigError::OutOfRange { key: "port".into(), min: 1, max: 65535 });
    }
    Ok(n)
}

fn main() {
    println!("{:?}", port(&[("port", "8080")]));
    for bad in [vec![], vec![("port", "eighty")], vec![("port", "70000")]] {
        match port(&bad) {
            Ok(p) => println!("port {p}"),
            Err(e) => println!("error: {e}"),
        }
    }
}

The caller can match on the variant to react differently (ask again for a bad number, give up for a missing file), and Display gives a message for people. Implementing std::error::Error (which needs Debug and Display) makes the type work with every tool that handles errors generally.

Keeping the cause

When one error is caused by another (a config error caused by an I/O error), keep the original and return it from source():

Rust
use std::error::Error;
use std::fmt;
use std::num::ParseIntError;

#[derive(Debug)]
enum LoadError {
    Io(std::io::Error),
    Parse { line: usize, cause: ParseIntError },
}

impl fmt::Display for LoadError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            LoadError::Io(_) => write!(f, "could not read the scores file"),
            LoadError::Parse { line, .. } => write!(f, "line {line} is not a number"),
        }
    }
}

impl Error for LoadError {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        match self {
            LoadError::Io(e) => Some(e),
            LoadError::Parse { cause, .. } => Some(cause),
        }
    }
}

fn parse_scores(text: &str) -> Result<Vec<i32>, LoadError> {
    text.lines()
        .enumerate()
        .map(|(i, l)| l.trim().parse::<i32>().map_err(|cause| LoadError::Parse { line: i + 1, cause }))
        .collect()
}

fn main() {
    let err = parse_scores("10\n20\nthirty").unwrap_err();
    println!("{err}");
    let mut cause = err.source();
    while let Some(c) = cause {
        println!("  caused by: {c}");
        cause = c.source();
    }
    let _ = LoadError::Io(std::io::Error::other("disk"));
}

Printing the chain of source()s gives messages like "could not read the scores file: caused by: permission denied", which are far more useful than either part alone.

collect() into a Result<Vec<_>, _> stops at the first error, as you see above.

Letting ? convert errors

? calls From::from on the error before returning it. Implement From for the errors your function meets, and ? converts them automatically:

Rust
use std::fmt;
use std::num::ParseIntError;

#[derive(Debug)]
enum AppError {
    Parse(ParseIntError),
    Negative(i64),
}

impl From<ParseIntError> for AppError {
    fn from(e: ParseIntError) -> Self {
        AppError::Parse(e)
    }
}

impl fmt::Display for AppError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            AppError::Parse(e) => write!(f, "not a number ({e})"),
            AppError::Negative(n) => write!(f, "{n} is negative"),
        }
    }
}

fn double(text: &str) -> Result<i64, AppError> {
    let n: i64 = text.parse()?;                 // ParseIntError becomes AppError here
    if n < 0 {
        return Err(AppError::Negative(n));
    }
    Ok(n * 2)
}

fn main() {
    for t in ["21", "x", "-3"] {
        match double(t) {
            Ok(v) => println!("{t} -> {v}"),
            Err(e) => println!("{t} -> error: {e}"),
        }
    }
}

Box<dyn Error> for small programs

When you only want to report an error and stop, not handle each kind, Box<dyn Error> accepts any error type, and ? converts into it:

Rust
use std::error::Error;

fn run() -> Result<i32, Box<dyn Error>> {
    let a: i32 = "40".parse()?;
    let b: i32 = "2".parse()?;
    if a + b != 42 {
        return Err("the answer is wrong".into());     // a &str becomes a boxed error too
    }
    Ok(a + b)
}

fn main() {
    match run() {
        Ok(v) => println!("{v}"),
        Err(e) => eprintln!("error: {e}"),
    }
}

main itself can return Result<(), Box<dyn Error>>; an Err then prints its Debug form and exits with code 1.

Rule of thumb: libraries define their own error enums so callers can match on them; applications often use Box<dyn Error> (or anyhow) at the top, where errors are only reported.

Adding context

A bare "No such file or directory" does not say which file. Wrap errors with what you were doing:

Rust
let text = std::fs::read_to_string(&path)
    .map_err(|e| format!("reading {}: {e}", path.display()))?;

The crates everyone uses

  • thiserror writes the Display, Error and From implementations from attributes: #[derive(Error, Debug)] enum E { #[error("missing {0}")] Missing(String), #[error(transparent)] Io(#[from] io::Error) }.
  • anyhow gives one anyhow::Error type for applications, ? from anything, and .context("reading config") to add messages.

They save typing, but they generate exactly the code this lesson writes by hand.
