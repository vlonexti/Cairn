The Standard Traits

lesson 4.033 of 5 in milestone 45 min1 practice task

The traits every Rust type should know - Debug and Display for printing, Clone and Copy, PartialEq and Eq, PartialOrd and Ord for comparing and sorting, Hash for map keys, Default, From and Into for conversions, FromStr for parsing, and operator overloading with Add and friends - which to derive and which to write by hand.

Deriving

Many standard traits can be derived: the compiler writes the obvious implementation field by field.

Rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord, Default)]
struct Version {
    major: u32,
    minor: u32,
    patch: u32,
}

fn main() {
    let a = Version { major: 1, minor: 10, patch: 0 };
    let b = Version { major: 1, minor: 2, patch: 7 };
    let c = a;                                      // Copy: a is still usable
    println!("{:?} {} {}", a, a == c, a > b);      // Ord compares fields in order: major, minor, patch
    let mut list = vec![a, b, Version::default()];
    list.sort();
    println!("{list:?}");
    let mut set = std::collections::HashSet::new();
    set.insert(a);                                  // Hash + Eq: usable as a key
    println!("{}", set.contains(&c));
}
Trait Gives Derive when
Debug {:?} printing Almost always
Clone .clone() The type can be duplicated
Copy Implicit copies on assignment Small, stack-only types (all fields Copy)
PartialEq, Eq == Values have meaningful equality (Eq if it is total: not for floats)
PartialOrd, Ord <, sorting There is a natural order (field order decides)
Hash Use as HashMap/HashSet key Together with Eq
Default Type::default() Every field has a sensible empty value

Display

Display ({}) is for users and is never derived; write it:

Rust
use std::fmt;

struct Money { cents: i64 }

impl fmt::Display for Money {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let sign = if self.cents < 0 { "-" } else { "" };
        let c = self.cents.abs();
        write!(f, "{sign}{}.{:02} EUR", c / 100, c % 100)
    }
}

fn main() {
    let m = Money { cents: -1250 };
    println!("{m}");
    let s = m.to_string();                  // ToString comes free with Display
    println!("[{s:>14}]");
}

Conversions: From, Into, TryFrom, FromStr

Rust
use std::str::FromStr;

#[derive(Debug, PartialEq)]
struct Celsius(f64);
#[derive(Debug, PartialEq)]
struct Fahrenheit(f64);

impl From<Fahrenheit> for Celsius {
    fn from(f: Fahrenheit) -> Self { Celsius((f.0 - 32.0) * 5.0 / 9.0) }
}

#[derive(Debug, PartialEq)]
struct Rgb(u8, u8, u8);

impl FromStr for Rgb {
    type Err = String;
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        let hex = s.strip_prefix('#').ok_or("missing #")?;
        if hex.len() != 6 { return Err(format!("expected 6 hex digits, got {}", hex.len())); }
        let part = |i: usize| u8::from_str_radix(&hex[i..i + 2], 16).map_err(|e| e.to_string());
        Ok(Rgb(part(0)?, part(2)?, part(4)?))
    }
}

fn main() {
    let c: Celsius = Fahrenheit(212.0).into();      // Into comes free with From
    println!("{c:?}");
    println!("{:?} {:?}", "#ff8800".parse::<Rgb>(), "ff8800".parse::<Rgb>());
}

Implement From (never Into directly); x.into() then works too. Implementing From<YourError> for AppError is what lets ? convert errors (lesson 3.04). FromStr makes "...".parse::<YourType>() work.

Operator overloading

Operators are traits in std::ops: implementing Add gives your type +:

Rust
use std::ops::{Add, Mul, Neg};

#[derive(Debug, Clone, Copy, PartialEq)]
struct Vec2 { x: f64, y: f64 }

impl Add for Vec2 {
    type Output = Vec2;
    fn add(self, o: Vec2) -> Vec2 { Vec2 { x: self.x + o.x, y: self.y + o.y } }
}

impl Mul<f64> for Vec2 {
    type Output = Vec2;
    fn mul(self, k: f64) -> Vec2 { Vec2 { x: self.x * k, y: self.y * k } }
}

impl Neg for Vec2 {
    type Output = Vec2;
    fn neg(self) -> Vec2 { Vec2 { x: -self.x, y: -self.y } }
}

fn main() {
    let a = Vec2 { x: 1.0, y: 2.0 };
    let b = Vec2 { x: 0.5, y: -1.0 };
    println!("{:?}", a + b * 2.0 + -a);
}

Overload operators only where the meaning is obvious (vectors, money, matrices).
