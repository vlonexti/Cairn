Traits

A trait

A trait names a set of methods that types can implement: shared behaviour, like an interface in other languages.

Rust
trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> String;

    fn describe(&self) -> String {                 // a default method: implementers may keep it
        format!("{} with area {:.2}", self.name(), self.area())
    }
}

struct Circle { radius: f64 }
struct Rect { w: f64, h: f64 }

impl Shape for Circle {
    fn area(&self) -> f64 { std::f64::consts::PI * self.radius * self.radius }
    fn name(&self) -> String { "circle".to_string() }
}

impl Shape for Rect {
    fn area(&self) -> f64 { self.w * self.h }
    fn name(&self) -> String { "rectangle".to_string() }
    fn describe(&self) -> String { format!("a {}x{} rectangle", self.w, self.h) }   // override
}

fn main() {
    println!("{}", Circle { radius: 1.0 }.describe());
    println!("{}", Rect { w: 2.0, h: 3.0 }.describe());
}

Traits as parameters

A function can accept any type implementing a trait. Three spellings mean the same thing for one parameter:

Rust
trait Shape { fn area(&self) -> f64; }
struct Square(f64);
impl Shape for Square { fn area(&self) -> f64 { self.0 * self.0 } }
struct Circle(f64);
impl Shape for Circle { fn area(&self) -> f64 { 3.14159 * self.0 * self.0 } }

fn print_area(s: &impl Shape) {                      // impl Trait in argument position
    println!("{:.2}", s.area());
}

fn total_area<S: Shape>(shapes: &[S]) -> f64 {        // a generic bound: all items the same type
    shapes.iter().map(|s| s.area()).sum()
}

fn bigger<'a>(a: &'a impl Shape, b: &'a impl Shape) -> f64 {
    a.area().max(b.area())
}

fn main() {
    print_area(&Square(2.0));
    println!("{}", total_area(&[Square(1.0), Square(2.0)]));
    println!("{:.2}", bigger(&Square(1.0), &Circle(1.0)));
}

A Vec<S> with S: Shape holds one concrete shape type. To mix circles and squares in one list you need trait objects (lesson 4.05).

Returning impl Trait

-> impl Trait returns some type that implements the trait without naming it, which is how functions return iterators and closures:

Rust
fn evens(limit: u32) -> impl Iterator<Item = u32> {
    (0..limit).filter(|n| n % 2 == 0)
}

fn adder(n: i32) -> impl Fn(i32) -> i32 {
    move |x| x + n
}

fn main() {
    println!("{:?}", evens(10).collect::<Vec<_>>());
    println!("{}", adder(5)(10));
}

Implementing traits for existing types

You can implement your own trait for types you did not write, including i32 and String:

Rust
trait Shout {
    fn shout(&self) -> String;
}

impl Shout for str {
    fn shout(&self) -> String { self.to_uppercase() + "!" }
}

impl Shout for i32 {
    fn shout(&self) -> String { format!("{}!!!", self) }
}

fn main() {
    println!("{} {}", "hello".shout(), 42.shout());
}

The orphan rule: you may implement a trait for a type only if the trait or the type is defined in your crate. You cannot implement the standard library's Display for the standard library's Vec, which prevents two crates from giving conflicting implementations. Wrap the type in your own struct (the newtype pattern) when you need to.

Associated types and constants

A trait can require a type or a constant from its implementers. Iterator uses an associated type for its items:

Rust
trait Unit {
    const SYMBOL: &'static str;
    const PER_METER: f64;
    fn from_meters(m: f64) -> f64 { m * Self::PER_METER }
}

struct Feet;
impl Unit for Feet { const SYMBOL: &'static str = "ft"; const PER_METER: f64 = 3.28084; }

struct Centimeters;
impl Unit for Centimeters { const SYMBOL: &'static str = "cm"; const PER_METER: f64 = 100.0; }

fn show<U: Unit>(meters: f64) -> String {
    format!("{:.1} {}", U::from_meters(meters), U::SYMBOL)
}

fn main() {
    println!("{} {}", show::<Feet>(1.8), show::<Centimeters>(1.8));
}

Supertraits and blanket implementations

A trait can require another (trait Named: std::fmt::Display { ... }). And an implementation can cover every type that meets a bound: the standard library implements ToString for every T: Display, which is why anything printable has .to_string().
