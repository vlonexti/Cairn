Strings and Input

lesson 1.055 of 5 in milestone 15 min1 practice task

The two string types - owned String and borrowed &str - and when to use each, common string methods, building strings with push_str and format!, reading lines from standard input, parsing numbers with parse and handling failure, and a first taste of Result and unwrap.

String and &str

Rust has two main string types:

  • String is an owned, growable string stored on the heap. You can change it.
  • &str (a "string slice") is a borrowed view of string data that lives somewhere else: in the program itself (string literals), or inside a String.
Rust
fn main() {
    let literal: &str = "hello";                  // a borrowed view of text in the program
    let mut owned: String = String::from("hello"); // owned, growable
    owned.push_str(", world");
    owned.push('!');
    let view: &str = &owned;                       // borrow a String as &str
    println!("{literal} | {owned} | {view} | {}", owned.len());

    let built = format!("{} has {} characters", literal, literal.len());
    let joined = ["a", "b", "c"].join("-");
    let upper = owned.to_uppercase();              // methods that change text return a new String
    println!("{built} {joined} {upper}");
}

Functions that only read text take &str: they then accept both literals and &String. Functions that keep text (store it in a struct) take String. Milestone 2 explains why.

String methods

Code Gives
s.len(), s.is_empty() Length in bytes, emptiness
s.trim(), s.to_lowercase(), s.to_uppercase() Trimmed slice, new Strings
s.contains("x"), s.starts_with("x"), s.find("x") Tests, Option position
s.replace("a", "b") A new String
s.split(','), s.split_whitespace(), s.lines() Iterators over pieces
s.chars(), s.chars().rev().collect::<String>() Characters, reversed
s.parse::<i32>() A Result with the number or an error
Rust
fn main() {
    let line = "  Ada Lovelace, 1815 , mathematician ";
    let parts: Vec<&str> = line.split(',').map(|p| p.trim()).collect();
    println!("{:?}", parts);
    let year: i32 = parts[1].parse().unwrap();
    println!("{}", year + 200);
    let words: Vec<&str> = "the quick  brown fox".split_whitespace().collect();
    println!("{} words, first {}", words.len(), words[0]);
    println!("{}", "racecar".chars().rev().collect::<String>());
}

.map(|p| p.trim()) applies a closure (an inline function, lesson 5.01) to each piece; collect() gathers the results into a Vec.

Strings are UTF-8, so you cannot index them by position (s[0] does not compile): a character may take several bytes. Use chars() (lesson 3.02 explains the details).

Reading input

Rust
use std::io;

fn main() {
    let mut name = String::new();
    println!("What is your name?");
    io::stdin().read_line(&mut name).expect("could not read input");
    let name = name.trim();                 // read_line keeps the line break

    let mut age_text = String::new();
    io::stdin().read_line(&mut age_text).expect("could not read input");
    match age_text.trim().parse::<u32>() {
        Ok(age) => println!("Hello, {name}! Next year you will be {}.", age + 1),
        Err(_) => println!("Hello, {name}! That age is not a number."),
    }
}
  • read_line(&mut name) appends the line (including its \n) to name and returns a Result: reading can fail.
  • parse::<u32>() returns Ok(number) or Err(error). match handles both.
  • .expect("message") and .unwrap() take the value out of an Ok, and panic (stop the program) on an Err. They are fine in quick programs and for errors that "cannot happen"; real error handling comes in lesson 3.04.

To read every line until the input ends:

Rust
use std::io::{self, BufRead};

fn main() {
    let mut total = 0;
    for line in io::stdin().lock().lines() {
        let line = line.unwrap();
        if let Ok(n) = line.trim().parse::<i64>() {
            total += n;
        }
    }
    println!("total {total}");
}

if let Ok(n) = ... runs the block only when the pattern matches: a short match with one interesting arm.
