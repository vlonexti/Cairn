Ownership and Moves

lesson 2.011 of 5 in milestone 25 min1 practice task

The three ownership rules, the stack and the heap, how String owns heap memory and frees it when dropped, moves versus copies, the Copy trait for simple values, clone for explicit deep copies, ownership through function calls and return values, and why this replaces both garbage collection and manual free.

Who frees the memory?

Every program must give memory back when it is done with it. C and C++ make the programmer call free/delete (forgetting leaks memory; freeing twice or too early corrupts it). Java, C# and Python use a garbage collector, which costs run time. Rust takes a third way: the compiler tracks ownership and inserts the clean-up itself, exactly once, at a point it can prove is safe.

The rules

  1. Every value has exactly one owner: a variable, a struct field, a vector slot...
  2. There is only one owner at a time.
  3. When the owner goes out of scope, the value is dropped (its memory is freed).
Rust
fn main() {
    {
        let s = String::from("hello");   // s owns a heap buffer holding "hello"
        println!("{s}");
    }                                    // s goes out of scope: the buffer is freed here
    // println!("{s}");                  // error: s does not exist here
}

Stack and heap

Values with a fixed, known size (integers, bool, char, tuples of those) live on the stack and are trivially cheap to copy. A String or Vec is a small struct on the stack (a pointer, a length, a capacity) that points to a buffer on the heap, whose size can change. Copying the small struct is cheap; copying the heap buffer is not, and two owners of one buffer would both try to free it.

Moves

So, assigning a String (or Vec, or any type that owns heap data) moves ownership. The old variable can no longer be used:

Rust
let s1 = String::from("hello");
let s2 = s1;                 // the ownership moves to s2; nothing is copied on the heap
println!("{s1}");            // error[E0382]: borrow of moved value: `s1`

The compiler message explains exactly this, and points at the line where the move happened. After a move, only s2 will free the buffer, so it is freed once.

Copy types

Simple stack-only types implement the Copy trait: assignment copies them, and the original stays usable:

Rust
fn main() {
    let a = 5;
    let b = a;                       // i32 is Copy: a is still valid
    let p = (1.5, true);
    let q = p;                       // a tuple of Copy types is Copy
    println!("{a} {b} {:?} {:?}", p, q);
}

Integers, floats, bool, char, shared references &T, and tuples and arrays of Copy types are Copy. String, Vec and Box are not.

clone

To really duplicate heap data, call .clone(). It is explicit on purpose: a deep copy may be expensive, and you can see it in the code.

Rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone();             // a second, independent buffer
    println!("{s1} {s2}");
}

Ownership and functions

Passing a value to a function moves (or copies) it, just like assignment. Returning a value moves it out to the caller:

Rust
fn main() {
    let name = String::from("Ada");
    let n = 42;
    take(name);                      // name moves into the function
    // println!("{name}");           // error: value moved
    copy_it(n);                      // n is copied: still usable
    println!("{n}");

    let made = make_greeting("Grace");   // ownership moves out to `made`
    let back = give_back(made);          // in and out again
    println!("{back}");
}

fn take(s: String) {
    println!("took {s}");
}                                    // s is dropped here

fn copy_it(x: i32) {
    println!("copied {x}");
}

fn make_greeting(name: &str) -> String {
    format!("Hello, {name}!")
}

fn give_back(s: String) -> String {
    s
}

Moving values in and out of every function would be tedious. The next lesson's borrowing lets a function use a value without taking it.
