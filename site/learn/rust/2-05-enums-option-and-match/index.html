Enums, Option and match

lesson 2.055 of 5 in milestone 25 min1 practice task

Enums whose variants carry data, methods on enums, matching with destructuring and exhaustiveness, Option instead of null and its everyday methods (unwrap_or, map, and_then, ?), if let and let else, and modelling states so invalid ones cannot be represented.

Enums with data

An enum lists the possible variants of a type. Unlike enums in many languages, each Rust variant can hold its own data:

Rust
#[derive(Debug)]
enum Shape {
    Circle { radius: f64 },
    Rectangle { width: f64, height: f64 },
    Triangle(f64, f64, f64),
}

impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle { radius } => std::f64::consts::PI * radius * radius,
            Shape::Rectangle { width, height } => width * height,
            Shape::Triangle(a, b, c) => {
                let s = (a + b + c) / 2.0;                     // Heron's formula
                (s * (s - a) * (s - b) * (s - c)).sqrt()
            }
        }
    }
}

fn main() {
    let shapes = vec![
        Shape::Circle { radius: 1.0 },
        Shape::Rectangle { width: 2.0, height: 3.0 },
        Shape::Triangle(3.0, 4.0, 5.0),
    ];
    for s in &shapes {
        println!("{s:?} has area {:.2}", s.area());
    }
}

match destructures each variant, binding its fields to names. The match must be exhaustive: add a variant to Shape and every match that does not handle it stops compiling, showing you exactly where to update the code.

Option instead of null

Rust has no null. A value that may be missing has type Option<T>:

Rust
enum Option<T> {
    Some(T),
    None,
}

You must handle None before you can use the value, so "forgot to check for null" bugs cannot happen:

Rust
fn find_index(names: &[&str], target: &str) -> Option<usize> {
    for (i, name) in names.iter().enumerate() {
        if *name == target {
            return Some(i);
        }
    }
    None
}

fn main() {
    let names = ["Ada", "Grace", "Linus"];
    match find_index(&names, "Grace") {
        Some(i) => println!("found at {i}"),
        None => println!("not found"),
    }
    let i = find_index(&names, "Bob").unwrap_or(999);
    println!("{i}");
    let len = find_index(&names, "Linus").map(|i| names[i].len());     // transform if present
    println!("{len:?}");
}
Method Gives
unwrap_or(default), unwrap_or_default() The value, or a default
map(f) Some(f(v)), or None
and_then(f) Chains a step that itself returns an Option
filter(p) None unless the value passes
ok_or(err) Converts to a Result (lesson 3.04)
is_some(), is_none() Tests
unwrap(), expect("msg") The value, or a panic: use only when None is impossible

Inside a function that returns Option, the ? operator returns None early: let first = values.first()?;.

if let and let else

When only one variant matters, if let is shorter than a full match, and let ... else handles the "otherwise bail out" case:

Rust
fn parse_pair(text: &str) -> Option<(i32, i32)> {
    let Some((a, b)) = text.split_once(',') else {
        return None;                                   // let-else: must leave the function
    };
    let a = a.trim().parse().ok()?;
    let b = b.trim().parse().ok()?;
    Some((a, b))
}

fn main() {
    if let Some((x, y)) = parse_pair("3, 4") {
        println!("{x} + {y} = {}", x + y);
    }
    println!("{:?} {:?}", parse_pair("7,x"), parse_pair("nothing"));
}

Make invalid states unrepresentable

Enums let the type itself rule out impossible combinations. Instead of a struct with a status string and optional fields that only sometimes make sense, model each state:

Rust
#[derive(Debug)]
enum Order {
    Draft { items: Vec<String> },
    Paid { items: Vec<String>, amount_cents: u64 },
    Shipped { tracking: String },
}

fn describe(order: &Order) -> String {
    match order {
        Order::Draft { items } if items.is_empty() => "an empty draft".to_string(),
        Order::Draft { items } => format!("a draft with {} items", items.len()),
        Order::Paid { amount_cents, .. } => format!("paid {}.{:02}", amount_cents / 100, amount_cents % 100),
        Order::Shipped { tracking } => format!("shipped, tracking {tracking}"),
    }
}

fn main() {
    let orders = [
        Order::Draft { items: vec![] },
        Order::Paid { items: vec!["tea".into()], amount_cents: 1250 },
        Order::Shipped { tracking: "ZX81".into() },
    ];
    for o in &orders { println!("{}", describe(o)); }
}

A shipped order has a tracking number and a draft does not, by construction. if after a pattern is a guard; .. ignores the remaining fields.
