Project: A Command-Line Tool

lesson 6.055 of 5 in milestone 65 min1 practice task

Building a real command-line program in Rust - reading arguments with std::env::args and with clap, reading files or standard input, a library-plus-binary layout, one error type with exit codes, writing output efficiently, and the plan for the final project, a log summariser with filters.

The shape of a CLI program

A good command-line tool reads arguments, reads input (files or standard input), writes results to standard output and errors to standard error, and exits with code 0 on success and non-zero on failure, so that scripts can tell what happened.

Rust
use std::process::ExitCode;

fn main() -> ExitCode {
    match run(std::env::args().skip(1).collect()) {
        Ok(()) => ExitCode::SUCCESS,
        Err(e) => {
            eprintln!("error: {e}");
            ExitCode::from(2)
        }
    }
}

fn run(args: Vec<String>) -> Result<(), AppError> {
    let options = Options::parse(&args)?;
    let text = read_input(options.path.as_deref())?;
    let report = summarise(&text, &options)?;      // pure logic, easy to test
    print!("{report}");
    Ok(())
}

main stays tiny: everything that can fail returns a Result, and only main decides how to report it.

Arguments

std::env::args() gives the program name followed by the arguments as Strings. Parsing a few flags by hand is fine:

Rust
#[derive(Debug, PartialEq)]
struct Options { path: Option<String>, level: Option<String>, top: usize }

fn parse_args(args: &[&str]) -> Result<Options, String> {
    let mut opts = Options { path: None, level: None, top: 5 };
    let mut it = args.iter();
    while let Some(&arg) = it.next() {
        match arg {
            "--level" => opts.level = Some(it.next().ok_or("--level needs a value")?.to_uppercase()),
            "--top" => {
                let n = it.next().ok_or("--top needs a value")?;
                opts.top = n.parse().map_err(|_| format!("--top: '{n}' is not a number"))?;
            }
            flag if flag.starts_with("--") => return Err(format!("unknown option {flag}")),
            path => opts.path = Some(path.to_string()),
        }
    }
    Ok(opts)
}

fn main() {
    println!("{:?}", parse_args(&["app.log", "--level", "error", "--top", "3"]));
    println!("{:?}", parse_args(&["--top", "many"]));
    println!("{:?}", parse_args(&["--verbose"]));
}

For anything bigger, the clap crate generates parsing, --help and error messages from a struct:

Rust
use clap::Parser;

/// Summarise a log file.
#[derive(Parser)]
struct Args {
    /// The log file (reads standard input when left out)
    path: Option<std::path::PathBuf>,
    /// Only count lines at this level
    #[arg(long)]
    level: Option<String>,
    /// How many top sources to show
    #[arg(long, default_value_t = 5)]
    top: usize,
}

let args = Args::parse();

Input from a file or standard input

Rust
use std::io::{self, Read};

fn read_input(path: Option<&str>) -> Result<String, AppError> {
    match path {
        Some(p) => std::fs::read_to_string(p).map_err(|e| AppError::Io(p.to_string(), e)),
        None => {
            let mut text = String::new();
            io::stdin().read_to_string(&mut text).map_err(|e| AppError::Io("stdin".into(), e))?;
            Ok(text)
        }
    }
}

Reading standard input lets the tool join pipelines: cat app.log | logsum --level error.

Library plus binary

Put the logic in src/lib.rs (a library crate) and keep src/main.rs to argument handling and printing. The library's functions take text and return values, so unit tests need no files or processes, and the same code can later power a web service or a GUI.

Writing output

println! locks standard output on every call. For large outputs, lock once and use a buffered writer:

Rust
use std::io::{self, BufWriter, Write};
let stdout = io::stdout();
let mut out = BufWriter::new(stdout.lock());
for line in lines { writeln!(out, "{line}")?; }

The final project

The project for this milestone is a log summariser that reads log lines from standard input and supports command-line style options given on its first line. It combines everything in the course: parsing with Result and your own error type, enums and pattern matching for log levels, HashMap/BTreeMap for counting, iterators for the report, and a small Options struct parsed from arguments. Write the parsing and summarising as functions that take &str and return values; main only reads input and prints.
