Iterators and Adapters

lesson 5.022 of 5 in milestone 55 min1 practice task

The Iterator trait and next, iter, iter_mut and into_iter, laziness, the common adapters (map, filter, filter_map, enumerate, zip, chain, take, skip, rev, flat_map, peekable, windows), consumers (collect, sum, count, fold, any, all, find, position, min_by_key, max_by), collecting into different types including Result, and why iterator chains are as fast as loops.

The Iterator trait

An iterator produces a sequence of values, one per call to next, until it returns None:

Rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // ...and dozens of provided methods built on next
}
Rust
fn main() {
    let v = vec![10, 20, 30];
    let mut it = v.iter();
    println!("{:?} {:?} {:?} {:?}", it.next(), it.next(), it.next(), it.next());
}

A for loop calls next for you. Collections give three kinds of iterator:

Method Items The collection
iter() &T Borrowed
iter_mut() &mut T Borrowed mutably
into_iter() T Consumed

Adapters are lazy

Adapters turn one iterator into another. They do nothing until a consumer pulls values through:

Rust
fn main() {
    let words = ["apple", "Banana", "cherry", "date", "Elderberry"];
    let result: Vec<String> = words.iter()
        .filter(|w| w.len() > 4)                 // keep some
        .map(|w| w.to_lowercase())               // transform
        .enumerate()                             // add indexes
        .map(|(i, w)| format!("{i}:{w}"))
        .collect();                              // the consumer: runs the chain
    println!("{result:?}");

    let lazy = (1..).map(|n| n * n).filter(|n| n % 3 == 1);   // an infinite range: fine, nothing runs yet
    println!("{:?}", lazy.take(5).collect::<Vec<_>>());
}
Adapter Does
map(f), filter(p), filter_map(f) Transform; keep some; transform and keep the Somes
enumerate(), zip(other), chain(other) Add indexes; pair up; concatenate
take(n), skip(n), take_while(p), skip_while(p), step_by(n) Cut
rev() Backwards (for double-ended iterators)
flat_map(f), flatten() One item becomes many
peekable() Look at the next item without taking it
copied(), cloned() &T to T
inspect(f) Look at items as they pass (debugging)

Consumers

Rust
fn main() {
    let scores = [72, 95, 88, 61, 79];
    let total: i32 = scores.iter().sum();
    let count = scores.iter().filter(|&&s| s >= 75).count();
    let max = scores.iter().max();
    let best_index = scores.iter().enumerate().max_by_key(|(_, s)| **s).map(|(i, _)| i);
    let all_pass = scores.iter().all(|&s| s >= 60);
    let any_perfect = scores.iter().any(|&s| s == 100);
    let first_low = scores.iter().find(|&&s| s < 70);
    let product = scores.iter().take(2).fold(1i64, |acc, &s| acc * s as i64);
    println!("{total} {count} {max:?} {best_index:?} {all_pass} {any_perfect} {first_low:?} {product}");

    let names = ["Ada", "Grace", "Linus"];
    let ages = [36, 85, 55];
    let pairs: Vec<(&str, i32)> = names.iter().copied().zip(ages).collect();
    let by_name: std::collections::HashMap<_, _> = pairs.iter().cloned().collect();
    println!("{pairs:?} {}", by_name["Linus"]);
    let joined = names.iter().map(|n| n.to_uppercase()).collect::<Vec<_>>().join("+");
    println!("{joined}");
}

Collecting results

collect can build any collection that implements FromIterator: Vec, String, HashMap, HashSet, BTreeMap... Pick the target with a type annotation or the turbofish collect::<Vec<_>>().

It can even collect an iterator of Results into a Result of a collection, stopping at the first error:

Rust
fn main() {
    let good: Result<Vec<i32>, _> = ["1", "2", "3"].iter().map(|s| s.parse::<i32>()).collect();
    let bad: Result<Vec<i32>, _> = ["1", "x", "3"].iter().map(|s| s.parse::<i32>()).collect();
    println!("{good:?}");
    println!("{}", bad.is_err());
    let words: String = vec!["a", "b", "c"].into_iter().rev().collect();
    println!("{words}");
}

Zero-cost

Iterator chains compile to the same machine code as hand-written loops (often better, since bounds checks disappear). Prefer them when they read clearly: scores.iter().filter(...).map(...).sum() says what it computes. Use a for loop when the logic has complex early exits or side effects.
