Macros

lesson 7.011 of 5 in milestone 75 min2 practice tasks

Code that writes code - what macros can do that functions cannot, macro_rules! with fragment specifiers, repetition with $(...),*, several rules in one macro, recursion, hygiene, exporting macros, and a look at derive and procedural macros.

Why macros

You have used macros since the first lesson: println!, vec!, assert_eq!, format!. The ! marks them. A macro runs at compile time and expands into ordinary code, so it can do things a function cannot:

  • take any number of arguments (println!("{} {}", a, b));
  • take code that is not a value, such as a type, a pattern or a block;
  • check its input at compile time (println! checks that the {} match the arguments).

macro_rules!

A declarative macro is a list of rules: a pattern to match the input, and the code to produce.

Rust
macro_rules! square {
    ($x:expr) => {
        $x * $x
    };
}

fn main() {
    println!("{}", square!(7));          // 49
    println!("{}", square!(2 + 3));      // 25: $x is the whole expression (2 + 3)
}

$x:expr captures an expression and names it $x. Because an expr fragment is kept as one unit, square!(2 + 3) gives 25, not the 2 + 3 * 2 + 3 a text substitution would.

Fragment specifiers

Specifier Matches
expr an expression: a + 1, f(x)
ident a name: count, Point
ty a type: Vec<u8>, &str
pat a pattern: Some(x), 1..=5
literal a literal: 42, "hi"
block a block in braces
tt any single token tree (the most flexible)

Repetition

$( ... ),* matches the inside any number of times, separated by commas; + instead of * means one or more. In the output, $( ... )* repeats once per match:

Rust
use std::collections::HashMap;

macro_rules! map {
    ($($key:expr => $value:expr),* $(,)?) => {{
        let mut m = HashMap::new();
        $( m.insert($key, $value); )*
        m
    }};
}

fn main() {
    let ages = map! { "Ada" => 36, "Linus" => 28, };
    let mut names: Vec<_> = ages.keys().collect();
    names.sort();
    println!("{names:?} {}", ages["Ada"]);
}

$(,)? allows an optional trailing comma. The double braces {{ ... }} make the expansion a block expression, so the macro can be used where a value is expected.

Several rules and recursion

Rules are tried in order. A macro may call itself, which is how it can process its input piece by piece:

Rust
macro_rules! max_of {
    ($x:expr) => { $x };
    ($x:expr, $($rest:expr),+) => {{
        let a = $x;
        let b = max_of!($($rest),+);
        if a > b { a } else { b }
    }};
}

fn main() {
    println!("{}", max_of!(3, 9, 4, 7));    // 9
}

Generating items

Macros can produce whole functions, structs and impl blocks, which removes repetition that generics cannot:

Rust
macro_rules! unit_type {
    ($name:ident, $suffix:literal) => {
        #[derive(Debug, Clone, Copy, PartialEq, PartialOrd)]
        struct $name(f64);

        impl std::fmt::Display for $name {
            fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
                write!(f, "{}{}", self.0, $suffix)
            }
        }
    };
}

unit_type!(Metres, " m");
unit_type!(Seconds, " s");

fn main() {
    println!("{} in {}", Metres(100.0), Seconds(9.58));
}

Hygiene

Variables created inside a macro do not clash with the caller's: the a and b in max_of! are separate from any a and b where it is used. Names passed in as ident fragments do refer to the caller's names, which is how a macro can declare a variable the caller then uses.

Exporting

A macro is usable after its definition in the same file. To use it from other modules or crates, mark it #[macro_export]; it then lives at the crate root (crate::map!).

Procedural macros

#[derive(Debug)], #[derive(Serialize)] from serde, and attributes like #[tokio::main] are procedural macros: Rust functions, in a crate of their own, that receive the code as tokens and return new tokens. They are more powerful and more work to write (the syn and quote crates help). Reach for macro_rules! first; write a procedural macro when you need a derive.
