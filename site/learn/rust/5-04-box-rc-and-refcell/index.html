Box, Rc and RefCell

lesson 5.044 of 5 in milestone 55 min1 practice task

Smart pointers - Box for heap allocation and recursive types, Deref and Drop, Rc for shared ownership with reference counting, RefCell for interior mutability checked at run time, Rc<RefCell<T>> for shared mutable data, Weak references to break cycles, and when each is the right tool.

Box

Box<T> stores a value on the heap and owns it. It has the size of a pointer, which makes recursive types possible (a type that contains itself would otherwise be infinitely large):

Rust
#[derive(Debug)]
enum List {
    Cons(i32, Box<List>),
    Nil,
}

use List::{Cons, Nil};

fn sum(list: &List) -> i32 {
    match list {
        Cons(value, rest) => value + sum(rest),
        Nil => 0,
    }
}

fn main() {
    let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
    println!("{list:?} sum={}", sum(&list));
    let big = Box::new([0u8; 1000]);            // a large value on the heap instead of the stack
    println!("{}", big.len());
}

Box implements Deref, so a Box<T> can be used like a &T (*b, method calls, &Box<T> coercing to &T). When the box goes out of scope it is dropped: the Drop trait runs clean-up code, and you can implement it yourself:

Rust
struct Noisy(&'static str);

impl Drop for Noisy {
    fn drop(&mut self) {
        println!("dropping {}", self.0);
    }
}

fn main() {
    let _a = Noisy("a");
    {
        let _b = Box::new(Noisy("b"));
        println!("inner scope ends");
    }
    let c = Noisy("c");
    drop(c);                                    // drop early
    println!("main ends");
}

Rc: shared ownership

Sometimes one value genuinely has several owners: a node shared by two lists, a texture used by many sprites. Rc<T> (reference counted) keeps a count of owners and frees the value when the last one goes away:

Rust
use std::rc::Rc;

#[derive(Debug)]
struct Texture { name: String }

struct Sprite { texture: Rc<Texture>, x: i32 }

fn main() {
    let grass = Rc::new(Texture { name: "grass.png".into() });
    let sprites = vec![
        Sprite { texture: Rc::clone(&grass), x: 0 },
        Sprite { texture: Rc::clone(&grass), x: 16 },
    ];
    println!("owners: {}", Rc::strong_count(&grass));     // 3: grass and two sprites
    for s in &sprites {
        println!("{} at {}", s.texture.name, s.x);
    }
    drop(sprites);
    println!("owners: {}", Rc::strong_count(&grass));     // 1
}

Rc::clone copies the pointer and increments the count; it does not copy the texture. Rc gives shared, read-only access and works within one thread (Arc is the thread-safe version, lesson 6.02).

RefCell: interior mutability

The borrow rules are normally checked at compile time. RefCell<T> moves the check to run time: borrow() gives a shared borrow, borrow_mut() a mutable one, and breaking the rules panics instead of failing to compile. This allows changing data through a shared reference when the compiler cannot prove it is safe but you can:

Rust
use std::cell::RefCell;
use std::rc::Rc;

#[derive(Debug)]
struct Account { balance: i64 }

fn main() {
    let shared = Rc::new(RefCell::new(Account { balance: 100 }));
    let alias = Rc::clone(&shared);

    alias.borrow_mut().balance -= 30;           // change through one owner
    shared.borrow_mut().balance += 5;           // and through the other
    println!("{}", shared.borrow().balance);

    let log = RefCell::new(Vec::new());
    let record = |msg: &str| log.borrow_mut().push(msg.to_string());   // a Fn closure that still mutates
    record("start");
    record("stop");
    println!("{:?}", log.borrow());
}

Rc<RefCell<T>> is the classic combination for shared, mutable data in single-threaded code (graphs, observers, GUI state). Use it sparingly: it trades compile-time guarantees for run-time checks.

Weak: breaking cycles

Two Rcs pointing at each other never reach a count of zero: a memory leak. Weak<T> is a non-owning reference that does not keep the value alive; upgrade() returns Some(Rc) only if it still exists. Trees use Rc from parent to child and Weak from child to parent:

Rust
use std::cell::RefCell;
use std::rc::{Rc, Weak};

struct Node {
    name: String,
    parent: RefCell<Weak<Node>>,
    children: RefCell<Vec<Rc<Node>>>,
}

fn main() {
    let root = Rc::new(Node { name: "root".into(), parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) });
    let leaf = Rc::new(Node { name: "leaf".into(), parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) });
    *leaf.parent.borrow_mut() = Rc::downgrade(&root);
    root.children.borrow_mut().push(Rc::clone(&leaf));
    let parent_name = leaf.parent.borrow().upgrade().map(|p| p.name.clone());
    println!("{:?} children={} strong={} weak={}", parent_name, root.children.borrow().len(),
             Rc::strong_count(&root), Rc::weak_count(&root));
}

Choosing

Need Use
One owner, value on the heap, recursive type, trait object Box<T>
Several owners, read-only, one thread Rc<T>
Several owners, threads Arc<T>
Change data behind & in one thread RefCell<T> (or Cell<T> for Copy values)
Shared mutable data, one thread Rc<RefCell<T>>
Shared mutable data, threads Arc<Mutex<T>>
A back-reference that must not keep things alive Weak<T>
