Collections in Depth

lesson 8.033 of 5 in milestone 85 min2 practice tasks

The rest of std::collections and the slice methods that save loops - BTreeMap and BTreeSet for sorted keys and ranges, VecDeque for both ends, BinaryHeap with Reverse for priority queues, sorting by keys, dedup, retain, binary_search, windows and chunks, and choosing the right collection.

Sorted maps and sets

HashMap (lesson 3.03) has no order. BTreeMap keeps its keys sorted, so iteration is in order and you can ask for ranges:

Rust
use std::collections::BTreeMap;

fn main() {
    let mut scores = BTreeMap::new();
    for (name, s) in [("cy", 77), ("ada", 91), ("bob", 48), ("dee", 65)] {
        scores.insert(name, s);
    }
    println!("{scores:?}");                                   // sorted by name
    println!("{:?}", scores.first_key_value());
    for (name, s) in scores.range("b".."d") {
        println!("{name} {s}");
    }

    let mut events = BTreeMap::new();
    events.insert(900, "wake");
    events.insert(1230, "lunch");
    events.insert(1800, "dinner");
    let next = events.range(1000..).next();                  // the first event at or after 10:00
    println!("{next:?}");
}

BTreeSet is the sorted set. Use the B-tree types when you need order, ranges, or the smallest and largest; HashMap is usually faster otherwise.

VecDeque: a queue with two ends

A Vec is fast at the end only. VecDeque is fast at both ends, which makes it the standard queue:

Rust
use std::collections::VecDeque;

fn main() {
    let mut queue: VecDeque<&str> = VecDeque::new();
    queue.push_back("ada");
    queue.push_back("bob");
    queue.push_front("vip");
    while let Some(next) = queue.pop_front() {
        println!("serving {next}");
    }

    let mut recent = VecDeque::with_capacity(3);
    for n in 1..=5 {
        if recent.len() == 3 {
            recent.pop_front();
        }
        recent.push_back(n);
    }
    println!("{recent:?}");       // the last three: [3, 4, 5]
}

BinaryHeap: always the largest first

BinaryHeap gives back its largest item first. Wrap items in Reverse for the smallest first, which is what a priority queue of tasks or Dijkstra's algorithm needs:

Rust
use std::cmp::Reverse;
use std::collections::BinaryHeap;

fn main() {
    let mut heap = BinaryHeap::from(vec![5, 1, 8, 3]);
    heap.push(7);
    println!("{:?}", heap.pop());          // Some(8)
    println!("{:?}", heap.peek());         // Some(7)

    let mut tasks = BinaryHeap::new();
    tasks.push(Reverse((3, "write report")));
    tasks.push(Reverse((1, "fix crash")));
    tasks.push(Reverse((2, "reply to email")));
    while let Some(Reverse((priority, task))) = tasks.pop() {
        println!("{priority}: {task}");
    }
}

Tuples compare field by field, so (priority, task) orders by priority first.

Slice methods worth knowing

Most of these work on any Vec or slice:

Rust
fn main() {
    let mut words = vec!["pear", "Fig", "apple", "fig", "kiwi", "apple"];
    words.sort_by_key(|w| w.to_lowercase());
    println!("{words:?}");
    words.dedup_by_key(|w| w.to_lowercase());          // removes neighbours that are equal by the key
    println!("{words:?}");
    words.retain(|w| w.len() > 3);                      // keep only what passes
    println!("{words:?}");

    let sorted = [2, 5, 8, 13, 21];
    println!("{:?} {:?}", sorted.binary_search(&13), sorted.binary_search(&9));   // Ok(3) Err(3): where 9 would go

    let temps = [12, 14, 13, 17, 19, 18];
    let rises: Vec<i32> = temps.windows(2).map(|w| w[1] - w[0]).collect();
    println!("{rises:?}");
    for chunk in temps.chunks(4) {
        println!("{chunk:?}");
    }
    let (low, high) = temps.split_at(3);
    println!("{low:?} {high:?} max {:?}", temps.iter().max());
    println!("{:?}", temps.iter().position(|&t| t > 15));
}
  • sort_by_key and sort_by(|a, b| ...) sort in place; sort_unstable is faster when equal items may be reordered.
  • dedup removes neighbouring duplicates, so sort first to remove all duplicates.
  • binary_search on a sorted slice gives Ok(index) or Err(where it would go), which is also the place to insert to keep it sorted.
  • windows(n) gives overlapping groups, chunks(n) separate ones.

More of the entry API

Rust
use std::collections::HashMap;

fn main() {
    let text = "the cat and the hat and the bat";
    let mut positions: HashMap<&str, Vec<usize>> = HashMap::new();
    for (i, w) in text.split(' ').enumerate() {
        positions.entry(w).or_default().push(i);
    }
    let mut keys: Vec<_> = positions.keys().collect();
    keys.sort();
    for k in keys {
        println!("{k}: {:?}", positions[k]);
    }

    let mut stock = HashMap::from([("tea", 3)]);
    stock.entry("tea").and_modify(|n| *n += 5).or_insert(0);
    stock.entry("milk").and_modify(|n| *n += 5).or_insert(1);
    let mut s: Vec<_> = stock.into_iter().collect();
    s.sort();
    println!("{s:?}");
}

or_default() inserts the type's default (an empty Vec here); and_modify changes an existing value.

Choosing

need collection
a list, mostly adding at the end Vec
a queue, or adding at both ends VecDeque
look up by key, order does not matter HashMap / HashSet
keys in order, ranges, first and last BTreeMap / BTreeSet
always take the largest (or smallest) next BinaryHeap
