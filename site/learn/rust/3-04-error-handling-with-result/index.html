Error Handling with Result

lesson 3.044 of 5 in milestone 35 min1 practice task

Recoverable errors with Result<T, E> and unrecoverable ones with panic!, handling results with match, unwrap_or, map_err and and_then, propagating errors with the ? operator, writing your own error enums with Display and std::error::Error, converting errors with From so ? works across types, Box<dyn Error> for quick programs, and when to panic.

Two kinds of errors

  • Recoverable errors are expected possibilities: a file is missing, input is not a number. Functions return Result<T, E>: Ok(value) or Err(error).
  • Unrecoverable errors are bugs: an index past the end, a broken invariant. The program calls panic!, which stops the thread with a message.
Rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}

Handling a Result

Rust
fn parse_age(text: &str) -> Result<u32, String> {
    let age: u32 = text.trim().parse().map_err(|_| format!("'{text}' is not a number"))?;
    if age > 150 {
        return Err(format!("{age} is not a realistic age"));
    }
    Ok(age)
}

fn main() {
    for input in ["42", "abc", "200"] {
        match parse_age(input) {
            Ok(age) => println!("age {age}"),
            Err(message) => println!("error: {message}"),
        }
    }
    let age = parse_age("x").unwrap_or(0);
    let doubled = parse_age("21").map(|a| a * 2);
    println!("{age} {doubled:?}");
}
Method Gives
match / if let Ok(v) Full control
unwrap_or(v), unwrap_or_default(), unwrap_or_else(f) A fallback value
map(f), map_err(f) Transform the value / the error
and_then(f) Chain a step that may also fail
ok() Convert to an Option, dropping the error
unwrap(), expect("why") The value, or a panic

The ? operator

? after a Result means: if it is Err, return that error from the current function now; otherwise unwrap the Ok value. It turns error plumbing into one character:

Rust
use std::num::ParseIntError;

fn sum_line(line: &str) -> Result<i64, ParseIntError> {
    let mut total = 0;
    for part in line.split(',') {
        total += part.trim().parse::<i64>()?;      // stops at the first bad number
    }
    Ok(total)
}

fn main() {
    println!("{:?}", sum_line("1, 2, 3"));
    println!("{:?}", sum_line("1, two, 3"));
}

? works in functions returning Result (or Option), including main if it returns Result<(), E>.

Your own error type

For a library or a larger program, define an error enum that lists what can go wrong, implement Display for messages, and From so ? converts other errors into yours:

Rust
use std::fmt;
use std::num::ParseIntError;

#[derive(Debug)]
enum ConfigError {
    Missing(String),
    BadNumber { key: String, source: ParseIntError },
    OutOfRange { key: String, value: i64 },
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ConfigError::Missing(key) => write!(f, "missing setting '{key}'"),
            ConfigError::BadNumber { key, source } => write!(f, "'{key}' is not a number ({source})"),
            ConfigError::OutOfRange { key, value } => write!(f, "'{key}' = {value} is out of range"),
        }
    }
}

impl std::error::Error for ConfigError {}

fn get_port(settings: &[(&str, &str)]) -> Result<u16, ConfigError> {
    let (_, text) = settings.iter().find(|(k, _)| *k == "port")
        .ok_or_else(|| ConfigError::Missing("port".into()))?;
    let value: i64 = text.parse().map_err(|e| ConfigError::BadNumber { key: "port".into(), source: e })?;
    u16::try_from(value).map_err(|_| ConfigError::OutOfRange { key: "port".into(), value })
}

fn main() {
    for settings in [vec![("port", "8080")], vec![], vec![("port", "eighty")], vec![("port", "70000")]] {
        match get_port(&settings) {
            Ok(p) => println!("port {p}"),
            Err(e) => println!("error: {e}"),
        }
    }
}

With impl From<ParseIntError> for ConfigError, a plain text.parse()? would convert automatically. The thiserror crate generates all of this from attributes, and anyhow offers a catch-all error type for applications.

Box<dyn Error> for quick programs

When you just want ? to work with any error type, return Result<T, Box<dyn std::error::Error>>:

Rust
use std::error::Error;

fn run() -> Result<i32, Box<dyn Error>> {
    let n: i32 = "41".parse()?;          // ParseIntError converts automatically
    if n < 0 {
        return Err("negative".into());   // a &str converts too
    }
    Ok(n + 1)
}

fn main() {
    match run() {
        Ok(v) => println!("{v}"),
        Err(e) => println!("error: {e}"),
    }
}

When to panic

Panic for bugs: a condition that should be impossible if the code is correct, a violated precondition in a function documented to panic, or in tests and quick experiments. Return a Result for anything the caller or the user can cause and handle. unwrap() in production code is a promise that it can never fail; expect("reason") documents why.
