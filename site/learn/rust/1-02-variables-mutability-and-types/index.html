Variables, Mutability and Types

lesson 1.022 of 5 in milestone 15 min1 practice task

let and mut, why variables are immutable by default, shadowing, constants, the scalar types (integers of every size, floats, bool, char), type inference and annotations, integer overflow in debug and release builds, conversions with as and From, and tuples and arrays.

let and mut

Variables are immutable by default. Add mut to allow changes:

Rust
fn main() {
    let x = 5;
    // x = 6;                    // error: cannot assign twice to immutable variable
    let mut count = 0;
    count += 1;
    count += 1;
    println!("{x} {count}");
}

Immutability by default means that when you read let total = ..., you know total never changes afterwards. Mark a variable mut only when it must change.

Shadowing

A new let with the same name shadows the old variable. Unlike mut, it can change the type, which is handy for converting a value in steps:

Rust
fn main() {
    let input = "  42 ";
    let input = input.trim();              // &str
    let input: i32 = input.parse().unwrap();   // now an i32
    let input = input * 2;
    println!("{input}");
}

Constants

Rust
const MAX_PLAYERS: u32 = 4;                 // a constant: type required, known at compile time
const SECONDS_PER_DAY: u64 = 24 * 60 * 60;

fn main() {
    println!("{MAX_PLAYERS} {SECONDS_PER_DAY}");
}

Scalar types

Type Holds
i8, i16, i32, i64, i128 Signed integers (i32 is the default)
u8, u16, u32, u64, u128 Unsigned integers (0 and up)
isize, usize Pointer-sized integers; usize is used for indexes and lengths
f32, f64 Floating point (f64 is the default)
bool true or false
char One Unicode character, 4 bytes: 'a', 'é', '🦀'
Rust
fn main() {
    let a = 42;                  // inferred i32
    let b: u8 = 255;
    let big = 1_000_000_000_000i64;
    let ratio = 0.75;            // f64
    let crab = '🦀';
    let ok = a > 40 && b == 255;
    println!("{a} {b} {big} {ratio} {crab} {ok}");
    println!("{} {}", i32::MAX, u64::MAX);
    println!("{}", 7 / 2);       // 3: integer division
    println!("{}", 7.0 / 2.0);   // 3.5
    println!("{}", -7 % 3);      // -1
    println!("{}", (-7i32).rem_euclid(3));   // 2
}

Overflow

If an integer operation overflows, a debug build panics ("attempt to add with overflow"); a release build wraps around. When wrapping or saturating is what you want, say so:

Rust
fn main() {
    let x: u8 = 250;
    println!("{:?}", x.checked_add(10));     // None: would overflow
    println!("{}", x.wrapping_add(10));      // 4
    println!("{}", x.saturating_add(10));    // 255
    println!("{:?}", x.checked_add(5));      // Some(255)
}

Converting between types

Rust never converts numbers implicitly; let y: i64 = x; with x: i32 is an error. Convert explicitly:

Rust
fn main() {
    let small: i32 = 300;
    let wide: i64 = small.into();            // lossless: From / Into
    let wide2 = i64::from(small);
    let truncated = small as u8;             // as: may lose information (300 becomes 44)
    let f = small as f64 / 7.0;
    let back = 3.99_f64 as i32;              // 3: truncates toward zero
    let checked: Result<u8, _> = u8::try_from(small);   // Err: does not fit
    println!("{wide} {wide2} {truncated} {f:.3} {back} {checked:?}");
}

Prefer into() / from() for conversions that can never fail, try_from when they might, and as only when you really want truncation.

Tuples and arrays

Rust
fn main() {
    let point: (i32, f64, &str) = (3, 4.5, "label");
    let (x, y, name) = point;                 // destructuring
    println!("{x} {y} {name} {}", point.0);

    let days = ["Mon", "Tue", "Wed"];         // an array: fixed length, one type
    let zeros = [0; 5];                       // five zeros
    println!("{} {:?} {}", days[1], zeros, days.len());
    // days[10];                              // panics at run time: index out of bounds
}
