Pattern Matching in Depth

lesson 8.022 of 5 in milestone 85 min2 practice tasks

Every pattern C# can match - type, constant and relational patterns, and, or and not, property patterns with nested and extended forms, positional patterns with Deconstruct, list patterns with slices, var patterns, switch expressions that the compiler checks for completeness, and how to keep complex matches readable.

Patterns everywhere

Lesson 2.05 used is and switch with simple patterns. Patterns are a small language of their own: they appear after is, in switch statements and in switch expressions, and they combine.

Type, constant and relational patterns

C#
static string Describe(object o) => o switch
{
    null => "nothing",
    0 => "zero",
    int n when n < 0 => "a negative int",
    int and > 100 => "a big int",
    int => "an int",
    string { Length: 0 } => "an empty string",
    string s => $"text of length {s.Length}",
    _ => o.GetType().Name,
};

foreach (var x in new object?[] { null, 0, -5, 500, 7, "", "hi", 2.5 }) Console.WriteLine(Describe(x!));
  • A type pattern (int, string s) matches values of that type and can give the value a name.
  • A constant pattern (0, null, "yes") matches one value.
  • A relational pattern (> 100, <= 0) compares.
  • and, or and not combine patterns, and brackets group them: >= 'a' and <= 'z' or >= 'A' and <= 'Z'.
  • A when clause adds any extra condition.

is not null is the clearest null check in modern C#.

Property patterns

{ Property: pattern, ... } looks inside an object, and patterns nest:

C#
static string Category(Person p) => p switch
{
    { Age: < 18 } => "child",
    { Home.Country: "UK", Age: >= 65 } => "UK pensioner",
    { Home: { City: "Paris" or "Lyon" } } => "lives in a French city",
    _ => "other",
};

Console.WriteLine(Category(new("Ada", 70, new("Leeds", "UK"))));
Console.WriteLine(Category(new("Bob", 30, new("Lyon", "France"))));
Console.WriteLine(Category(new("Cy", 12, new("Rome", "Italy"))));

record Address(string City, string Country);

record Person(string Name, int Age, Address Home);

Home.Country: "UK" is the extended form of Home: { Country: "UK" }. Property patterns never match null, so they double as null checks.

Positional patterns

A type with a Deconstruct method (every positional record has one) can be matched by position:

C#
static string Where(Point p) => p switch
{
    (0, 0) => "origin",
    (0, _) => "on the y axis",
    (_, 0) => "on the x axis",
    (var x, var y) when x == y => "on the diagonal",
    (> 0, > 0) => "top right",
    _ => "somewhere else",
};

foreach (var p in new Point[] { new(0, 0), new(0, 5), new(3, 3), new(2, 7), new(-1, 4) }) Console.WriteLine(Where(p));

record Point(int X, int Y);

Tuples work the same way, which makes matching on two values at once neat:

C#
static string Rps(string a, string b) => (a, b) switch
{
    var (x, y) when x == y => "draw",
    ("rock", "scissors") or ("scissors", "paper") or ("paper", "rock") => "first wins",
    _ => "second wins",
};
Console.WriteLine(Rps("rock", "paper"));

List patterns

Lists and arrays can be matched by their elements, with .. for "any number of elements here":

C#
static string Shape(int[] xs) => xs switch
{
    [] => "empty",
    [var only] => $"one: {only}",
    [var first, .., var last] when first == last => "starts and ends the same",
    [1, 2, ..] => "starts with 1, 2",
    [.., < 0] => "ends with a negative",
    [_, _, .. var rest] => $"two and then {rest.Length} more",
};

foreach (var a in new[] { new int[0], [5], [3, 9, 3], [1, 2, 8], [4, 6, -1], [7, 8, 9, 10] }) Console.WriteLine(Shape(a));

.. var rest captures the middle part as a new array (or a slice for spans and strings).

List patterns are perfect for command lines:

C#
static string Run(string line) => line.Split(' ', StringSplitOptions.RemoveEmptyEntries) switch
{
    ["help"] => "commands: add, list",
    ["add", var item] => $"added {item}",
    ["add", var item, var qty] when int.TryParse(qty, out var n) => $"added {n} x {item}",
    ["add", ..] => "usage: add <item> [qty]",
    [] => "",
    [var cmd, ..] => $"unknown command {cmd}",
};
foreach (var l in new[] { "help", "add tea", "add tea 3", "add", "fly away" }) Console.WriteLine(Run(l));

The compiler checks switch expressions

A switch expression must cover every possible input. If it does not, the compiler warns, and at run time an unmatched value throws SwitchExpressionException. For enums and sealed hierarchies, listing every case without _ means adding a new case later gives a warning everywhere it is not handled yet.

C#
static int Seconds(Light l) => l switch
{
    Light.Red => 30,
    Light.Amber => 5,
    Light.Green => 25,
    _ => throw new ArgumentOutOfRangeException(nameof(l)),   // enums can hold other numbers too
};
Console.WriteLine(Seconds(Light.Amber));

enum Light { Red, Amber, Green }

Keeping it readable

  • Order arms from most specific to most general; the compiler reports an arm that can never be reached.
  • When a pattern gets long, move part of it into a well-named property or method (p.IsAdult).
  • Prefer a switch expression that returns a value over if/else chains that assign a variable.
