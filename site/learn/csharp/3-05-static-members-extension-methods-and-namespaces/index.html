Static Members, Extension Methods and Namespaces

lesson 3.055 of 5 in milestone 35 min1 practice task

Static fields, properties, methods and constructors, static classes, constants and readonly fields, extension methods that add methods to existing types, namespaces and using directives, file-scoped namespaces, global usings, and organising a project into files.

Static members

A static member belongs to the class itself, not to any one object. There is exactly one of it:

C#
var a = new Ticket();
var b = new Ticket();
Console.WriteLine($"{a.Number} {b.Number} {Ticket.Issued}");
Console.WriteLine(Ticket.Describe(b));

public class Ticket
{
    private static int _next = 1;             // shared by all tickets
    public static int Issued => _next - 1;

    public int Number { get; } = _next++;     // each ticket takes the next number

    public static string Describe(Ticket t) => $"ticket #{t.Number}";
}

Static methods cannot use this or instance members, since there is no object. They suit operations that need only their parameters: Math.Max, int.Parse, string.Join, factory methods like Money.FromCents(250).

A static class has only static members and cannot be instantiated: Math, Console, File. Use one for groups of helper functions.

Avoid mutable static data where you can: it is shared by the whole program (and every thread), which makes code hard to test.

const and readonly

C#
Console.WriteLine($"{Limits.MaxUsers} {Limits.StartedAt.Year > 2000} {new Circle(2).Area:F2}");

public static class Limits
{
    public const int MaxUsers = 100;                         // fixed at compile time
    public static readonly DateTime StartedAt = DateTime.Now;   // set once, at run time
}

public class Circle(double r)
{
    private readonly double _radius = r;    // can only be assigned in the declaration or constructor
    public double Area => Math.PI * _radius * _radius;
}

const works for numbers, bool, char and strings known when compiling. readonly fields can hold any value, decided when the program runs, and then never change.

Extension methods

An extension method adds a method to an existing type without changing it. It is a static method in a static class whose first parameter has this:

C#
Console.WriteLine("hello world".Capitalize());
Console.WriteLine("a long sentence that goes on".Truncate(10));
Console.WriteLine(new[] { 3, 8, 1 }.SecondLargest());

public static class StringExtensions
{
    public static string Capitalize(this string s) =>
        s.Length == 0 ? s : char.ToUpper(s[0]) + s[1..];

    public static string Truncate(this string s, int max) =>
        s.Length <= max ? s : s[..(max - 1)] + "…";
}

public static class SequenceExtensions
{
    public static int SecondLargest(this IEnumerable<int> values) =>
        values.OrderDescending().Skip(1).First();
}

All of LINQ (Where, Select, ...) is extension methods on IEnumerable<T>. They are found when their namespace is imported with using.

Namespaces

Namespaces group types and keep names from clashing: System.Collections.Generic.List<T>. A using directive lets you write the short name:

C#
// Models/Invoice.cs
namespace Billing.Models;          // file-scoped namespace: applies to the whole file

public record Invoice(string Id, decimal Total);
C#
// Program.cs
using Billing.Models;              // now Invoice can be used directly
using static System.Math;          // static members without the class name: Sqrt(2)
using Json = System.Text.Json.JsonSerializer;   // an alias

var invoice = new Invoice("INV-1", 99.5m);

Conventions:

  • The namespace follows the folder: Billing/Models/Invoice.cs holds namespace Billing.Models;.
  • One public type per file, with the file named after it.
  • Projects add global usings for common namespaces (System, System.Linq, System.Collections.Generic...) with <ImplicitUsings>enable</ImplicitUsings>, so most files need few using lines. You can add your own in one file: global using Billing.Models;.
