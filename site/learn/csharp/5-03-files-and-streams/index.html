Files and Streams

lesson 5.033 of 5 in milestone 55 min1 practice task

Reading and writing files with File's one-line helpers and their async versions, paths with Path, directories, StreamReader and StreamWriter for large files line by line, encodings, the Stream abstraction, handling IOException, and reading CSV safely.

The quick way

For small files, the File class does everything in one call:

C#
File.WriteAllText("hello.txt", "Hello\nfrom C#\n");
File.AppendAllText("hello.txt", "one more line\n");
string text = File.ReadAllText("hello.txt");
string[] lines = File.ReadAllLines("hello.txt");
Console.WriteLine($"{text.Length} characters, {lines.Length} lines, last: {lines[^1]}");

File.WriteAllLines("numbers.txt", Enumerable.Range(1, 5).Select(n => n.ToString()));
int sum = File.ReadLines("numbers.txt").Sum(int.Parse);
Console.WriteLine(sum);
Console.WriteLine(File.Exists("numbers.txt") + " " + File.Exists("missing.txt"));

ReadAllLines loads the whole file into an array; ReadLines reads it lazily, one line at a time, which works for files larger than memory. Each has an ...Async version (ReadAllTextAsync, WriteAllLinesAsync) for use with await.

Paths

Never glue paths together with + and "\\": the separator differs between Windows and Linux. Path handles it:

C#
string folder = Path.Combine("data", "2026", "march");
string file = Path.Combine(folder, "report.csv");
Console.WriteLine(file);
Console.WriteLine($"{Path.GetFileName(file)} {Path.GetExtension(file)} {Path.GetFileNameWithoutExtension(file)}");
Console.WriteLine(Path.ChangeExtension(file, ".json"));

Directory.CreateDirectory(folder);                 // creates every missing level, fine if it exists
File.WriteAllText(file, "id,total\n1,9.50\n");
foreach (string f in Directory.EnumerateFiles("data", "*.csv", SearchOption.AllDirectories))
    Console.WriteLine($"found {f.Replace('\\', '/')}");

Relative paths are relative to the current directory, which is not always the folder of your program. For files that ship with your app, use AppContext.BaseDirectory; for user data, Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData).

Streams

All file, network and memory I/O in .NET goes through streams: a sequence of bytes you read from or write to. StreamReader and StreamWriter add text on top, with an encoding (UTF-8 by default):

C#
using (var writer = new StreamWriter("log.txt"))
{
    for (int i = 1; i <= 3; i++) writer.WriteLine($"entry {i}");
}   // disposing flushes and closes the file

using var reader = new StreamReader("log.txt");
string? line;
int count = 0;
while ((line = reader.ReadLine()) != null)
{
    count++;
    Console.WriteLine($"{count}: {line}");
}

Always wrap streams in using (lesson 4.04): a writer that is not disposed may never write its last data to disk.

Other streams work the same way: FileStream for raw bytes, MemoryStream for bytes in memory, GZipStream to compress, the response stream of an HTTP request. Code written against Stream or TextReader works with all of them, which makes it easy to test with a StringReader:

C#
Console.WriteLine(CountWords(new StringReader("one two\nthree")));

static int CountWords(TextReader reader)
{
    int words = 0;
    string? line;
    while ((line = reader.ReadLine()) != null) words += line.Split(' ', StringSplitOptions.RemoveEmptyEntries).Length;
    return words;
}

When things go wrong

File operations fail for reasons outside your program: the file is missing, locked by another program, the disk is full, permission is denied. Catch the specific exceptions where you can do something useful:

C#
try
{
    string config = File.ReadAllText("settings.ini");
}
catch (FileNotFoundException)
{
    Console.WriteLine("no settings file: using defaults");
}
catch (UnauthorizedAccessException)
{
    Console.WriteLine("not allowed to read the settings");
}
catch (IOException e)
{
    Console.WriteLine($"could not read settings: {e.Message}");
}

Checking File.Exists first does not remove the need for try: the file can disappear between the check and the read.

CSV

Comma-separated files look simple, but fields can contain commas inside quotes: "Smith, Ada",36. Splitting on , breaks those. For real data use a library such as CsvHelper; for simple, known files, a small parser that understands quotes is enough (practice 5.03 builds one).

When writing numbers and dates to files, use CultureInfo.InvariantCulture, so that 9.50 does not become 9,50 on a computer set to another language.
