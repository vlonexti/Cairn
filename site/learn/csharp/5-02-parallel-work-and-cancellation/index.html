Parallel Work and Cancellation

lesson 5.022 of 5 in milestone 55 min1 practice task

Using several cores and stopping work politely - Task.Run for CPU-bound work, Parallel.For and Parallel.ForEachAsync, limiting concurrency with SemaphoreSlim, thread safety with lock, Interlocked and concurrent collections, CancellationToken and CancellationTokenSource, timeouts, and progress reporting.

CPU-bound work

async/await is about waiting. Heavy computation needs threads: Task.Run runs a function on the thread pool, which keeps a UI responsive and lets several computations run on different cores:

C#
var sw = System.Diagnostics.Stopwatch.StartNew();
Task<long>[] jobs = [Task.Run(() => SumOfPrimes(200_000)), Task.Run(() => SumOfPrimes(200_001))];
long[] results = await Task.WhenAll(jobs);
Console.WriteLine($"{results[0]} {results[0] == results[1]}");

static long SumOfPrimes(int limit)
{
    long sum = 0;
    for (int n = 2; n < limit; n++)
    {
        bool prime = true;
        for (int d = 2; d * d <= n; d++) if (n % d == 0) { prime = false; break; }
        if (prime) sum += n;
    }
    return sum;
}

For loops over data, Parallel.For and Parallel.ForEach split the work across cores:

C#
double[] values = new double[1_000_000];
Parallel.For(0, values.Length, i => values[i] = Math.Sqrt(i));
Console.WriteLine(values[999_999].ToString("F2"));

Parallelism only helps when each piece of work is independent and big enough to outweigh the cost of coordinating threads.

Shared data needs care

When several threads change the same data at the same time, updates get lost. count++ is read, add, write: two threads can read the same old value.

C#
int unsafeCount = 0, safeCount = 0, lockedCount = 0;
object gate = new();
Parallel.For(0, 100_000, _ =>
{
    unsafeCount++;                                   // a race: some increments are lost
    Interlocked.Increment(ref safeCount);            // an atomic increment
    lock (gate) { lockedCount++; }                   // only one thread at a time inside
});
Console.WriteLine($"{unsafeCount <= 100_000} {safeCount} {lockedCount}");

var words = new System.Collections.Concurrent.ConcurrentDictionary<string, int>();
Parallel.ForEach(new[] { "a", "b", "a", "c", "a" }, w => words.AddOrUpdate(w, 1, (_, n) => n + 1));
Console.WriteLine(words["a"]);
Tool Use
lock (obj) { ... } A block that only one thread runs at a time
Interlocked Atomic increments, adds and swaps of single values
ConcurrentDictionary, ConcurrentQueue, ConcurrentBag Collections that many threads may use at once
SemaphoreSlim Allow at most N at a time (also for async code)

The simplest thread safety is no shared mutable data: let each task compute its own result and combine the results at the end, as Task.WhenAll does above.

Limiting concurrency

Starting 1000 downloads at once overloads servers and your machine. Parallel.ForEachAsync runs async work with a limit:

C#
int running = 0, peak = 0;
await Parallel.ForEachAsync(Enumerable.Range(1, 12), new ParallelOptions { MaxDegreeOfParallelism = 3 }, async (n, ct) =>
{
    int now = Interlocked.Increment(ref running);
    InterlockedMax(ref peak, now);
    await Task.Delay(30, ct);
    Interlocked.Decrement(ref running);
});
Console.WriteLine($"peak {peak}");

static void InterlockedMax(ref int target, int value)
{
    int current;
    while ((current = Volatile.Read(ref target)) < value && Interlocked.CompareExchange(ref target, value, current) != current) { }
}

SemaphoreSlim does the same by hand: await sem.WaitAsync(); try { ... } finally { sem.Release(); }.

Cancellation

Long operations should be cancellable: the user closes the window, a request times out. .NET's pattern is a CancellationToken, passed down to every method that might take a while:

C#
using var cts = new CancellationTokenSource(TimeSpan.FromMilliseconds(250));   // cancels itself after 250 ms
try
{
    await CountSlowlyAsync(10, cts.Token);
}
catch (OperationCanceledException)
{
    Console.WriteLine("cancelled");
}

static async Task CountSlowlyAsync(int to, CancellationToken token)
{
    for (int i = 1; i <= to; i++)
    {
        token.ThrowIfCancellationRequested();     // for loops doing CPU work
        await Task.Delay(100, token);             // async methods take the token and stop early
        Console.WriteLine(i);
    }
}
  • The caller owns a CancellationTokenSource and calls Cancel() (or gives it a timeout).
  • The worker receives a CancellationToken, passes it on, and checks it in loops.
  • Cancellation surfaces as an OperationCanceledException; catch it where cancelling is expected.
  • Make CancellationToken cancellationToken = default the last parameter of your async methods.

Progress

IProgress<T> reports progress back to the caller (in a UI app, on the UI thread):

C#
var progress = new Progress<int>(p => Console.WriteLine($"{p}%"));
await ProcessAsync(progress);
await Task.Delay(50);   // let the last report print

static async Task ProcessAsync(IProgress<int> progress)
{
    for (int i = 1; i <= 4; i++)
    {
        await Task.Delay(20);
        progress.Report(i * 25);
    }
}
