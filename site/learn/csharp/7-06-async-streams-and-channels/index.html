Async Streams and Channels

lesson 7.066 of 6 in milestone 75 min2 practice tasks

Data that arrives over time - IAsyncEnumerable with yield return and await foreach, cancellation with [EnumeratorCancellation], System.Threading.Channels for producers and consumers, bounded channels and back-pressure, and pipelines of async stages.

Results one at a time, asynchronously

Task<List<T>> waits for all the results before returning any. When results arrive over time (pages of an API, lines of a big file, sensor readings), an async stream, IAsyncEnumerable<T>, hands each one over as soon as it exists. You write it with async plus yield return, and consume it with await foreach:

C#
await foreach (int reading in Readings(5))
    Console.WriteLine($"reading {reading}");

static async IAsyncEnumerable<int> Readings(int count)
{
    for (int i = 1; i <= count; i++)
    {
        await Task.Delay(20);         // stands in for waiting on a device or the network
        yield return i * 10;
    }
}

The consumer starts working on the first item while later ones are still on their way.

Cancellation

An async stream takes a CancellationToken through a parameter marked [EnumeratorCancellation], so WithCancellation(token) on the consumer side reaches it:

C#
using System.Runtime.CompilerServices;

using var cts = new CancellationTokenSource(TimeSpan.FromMilliseconds(120));
try
{
    await foreach (int n in Ticks().WithCancellation(cts.Token))
        Console.WriteLine($"tick {n}");
}
catch (OperationCanceledException)
{
    Console.WriteLine("stopped");
}

static async IAsyncEnumerable<int> Ticks([EnumeratorCancellation] CancellationToken token = default)
{
    for (int i = 0; ; i++)
    {
        await Task.Delay(50, token);
        yield return i;
    }
}

LINQ for async streams (Where, Select, ToListAsync...) is in the System.Linq.Async package, and is built into .NET 10.

Channels: a queue between async code

System.Threading.Channels.Channel<T> is a thread-safe queue made for async: producers await writing, consumers await reading, and nobody blocks a thread while waiting. It is the modern replacement for BlockingCollection.

C#
using System.Threading.Channels;

var channel = Channel.CreateUnbounded<string>();

var producer = Task.Run(async () =>
{
    foreach (var job in new[] { "resize", "upload", "notify" })
    {
        await channel.Writer.WriteAsync(job);
        await Task.Delay(10);
    }
    channel.Writer.Complete();                 // no more items: readers finish
});

await foreach (var job in channel.Reader.ReadAllAsync())
    Console.WriteLine($"doing {job}");

await producer;

ReadAllAsync() ends when the writer has called Complete() and the channel is empty.

Bounded channels and back-pressure

An unbounded channel grows without limit if producers are faster than consumers. A bounded channel holds at most N items; a producer writing to a full channel waits until there is room. That waiting is back-pressure: it slows the fast side down to the speed of the slow side instead of filling memory.

C#
using System.Threading.Channels;

var bounded = Channel.CreateBounded<int>(new BoundedChannelOptions(2)
{
    FullMode = BoundedChannelFullMode.Wait,    // or DropOldest, DropNewest, DropWrite
    SingleReader = true,
});
await bounded.Writer.WriteAsync(1);
await bounded.Writer.WriteAsync(2);
Console.WriteLine(bounded.Writer.TryWrite(3));   // False: full
Console.WriteLine(await bounded.Reader.ReadAsync());
Console.WriteLine(bounded.Writer.TryWrite(3));   // True: there was room again

Several consumers

Several consumers can read from the same channel; each item goes to exactly one of them. Start them with Task.WhenAll:

C#
using System.Threading.Channels;

var work = Channel.CreateBounded<int>(10);
var results = new System.Collections.Concurrent.ConcurrentBag<int>();

async Task Consumer()
{
    await foreach (int n in work.Reader.ReadAllAsync())
        results.Add(n * n);
}

var consumers = Enumerable.Range(0, 3).Select(_ => Consumer()).ToArray();
for (int i = 1; i <= 10; i++) await work.Writer.WriteAsync(i);
work.Writer.Complete();
await Task.WhenAll(consumers);
Console.WriteLine(results.Sum());    // 385

Chaining channels gives a pipeline: stage 1 reads files into channel A, stage 2 parses from A into B, stage 3 saves from B, each stage running at its own pace.
