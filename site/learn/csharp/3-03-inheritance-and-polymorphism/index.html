Inheritance and Polymorphism

lesson 3.033 of 5 in milestone 35 min1 practice task

Deriving classes with a base class, calling base constructors, virtual and override, abstract classes and members, sealed, polymorphism through base-class references, protected members, type checks with is and as, and when composition is better than inheritance.

Deriving a class

A class can inherit from one base class, getting all its members and adding or changing some:

C#
Shape[] shapes = [new Circle(1), new Rectangle(2, 3), new Square(2)];
foreach (Shape s in shapes) Console.WriteLine(s.Describe());
Console.WriteLine($"Total area: {shapes.Sum(s => s.Area()):F2}");

public abstract class Shape(string name)
{
    public string Name { get; } = name;
    public abstract double Area();                                  // every shape must provide this
    public virtual string Describe() => $"{Name} with area {Area():F2}";   // may be replaced
}

public class Circle(double radius) : Shape("circle")
{
    public double Radius { get; } = radius;
    public override double Area() => Math.PI * Radius * Radius;
}

public class Rectangle(double width, double height) : Shape("rectangle")
{
    public double Width { get; } = width;
    public double Height { get; } = height;
    public override double Area() => Width * Height;
}

public sealed class Square(double side) : Rectangle(side, side)
{
    public override string Describe() => base.Describe() + " (a square)";
}
  • : Shape("circle") names the base class and passes arguments to its constructor.
  • abstract members have no body; an abstract class cannot be created with new and makes derived classes implement them.
  • virtual members have a default that derived classes may override. In C#, methods are not virtual unless you say so.
  • base.Describe() calls the base class's version.
  • sealed stops further inheritance.

Polymorphism

A variable of the base type can hold any derived object. A call to a virtual method runs the version of the actual object: s.Area() runs Circle.Area for a circle. That is polymorphism: code written against Shape works with every shape, including ones written later.

Constructors and protected members

C#
var e = new Manager("Ada", 5000m, 3);
Console.WriteLine($"{e.Name}: {e.MonthlyCost()}");

public class Employee
{
    public string Name { get; }
    protected decimal Salary { get; }          // visible to derived classes, not outside

    public Employee(string name, decimal salary) { Name = name; Salary = salary; }
    public virtual decimal MonthlyCost() => Salary;
}

public class Manager : Employee
{
    private readonly int _reports;
    public Manager(string name, decimal salary, int reports) : base(name, salary) => _reports = reports;
    public override decimal MonthlyCost() => base.MonthlyCost() + 200m * _reports;
}

: base(name, salary) runs the base constructor first. The base class sets up its part of the object before the derived class adds its own.

Checking types

C#
object[] items = [new Circle(2), "text", new Square(1)];
foreach (var item in items)
{
    if (item is Rectangle r) Console.WriteLine($"rectangle {r.Width}x{r.Height}");
    else if (item is Shape s) Console.WriteLine($"another shape: {s.Name}");
    Shape? maybe = item as Shape;                 // null if it is not a Shape
    Console.WriteLine(maybe?.Area().ToString("F1") ?? "not a shape");
}

public abstract class Shape(string name) { public string Name { get; } = name; public abstract double Area(); }
public class Circle(double r) : Shape("circle") { public override double Area() => Math.PI * r * r; }
public class Rectangle(double w, double h) : Shape("rectangle") { public double Width => w; public double Height => h; public override double Area() => w * h; }
public class Square(double s) : Rectangle(s, s);

If you find yourself writing long chains of is checks to decide what to do, a virtual method on the base class (or a switch expression over a closed set of records) is usually cleaner.

Composition over inheritance

Inheritance means "is a": a Square is a Rectangle. It ties classes together tightly, and C# allows only one base class. When the relationship is "has a" or "uses a", composition (an object holding others) is more flexible:

C#
// Inheritance would force: class LoggingRepository : Repository
// Composition: the repository is given a logger and uses it.
public class OrderService(IOrderRepository repository, ILogger logger)
{
    public void Place(Order order) { repository.Save(order); logger.Log($"placed {order.Id}"); }
}

Interfaces (next lesson) make composition easy. Keep hierarchies shallow: one or two levels.
