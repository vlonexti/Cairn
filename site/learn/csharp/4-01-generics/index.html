Generics

lesson 4.011 of 5 in milestone 45 min1 practice task

Writing type-safe code that works for any type - generic methods and classes, type inference, constraints with where (class, struct, new(), interfaces, notnull), generic interfaces, default(T), covariance in IEnumerable and IReadOnlyList, and why generics beat object.

The problem

Without generics, a container for "anything" stores object. Every read needs a cast, mistakes show up only when the program runs, and value types get boxed (wrapped in an object) on the way in:

C#
var list = new System.Collections.ArrayList();   // the pre-generics collection
list.Add(42);
list.Add("oops");                                  // nothing stops this
int first = (int)list[0]!;                         // a cast at every read
int second = (int)list[1]!;                        // InvalidCastException at run time

Generics let you write the code once with a type parameter T, and the compiler produces a checked version for every type you use it with: List<int>, List<string>, Dictionary<string, Order>.

Generic methods

C#
int[] numbers = [4, 9, 2];
string[] words = ["pear", "fig"];
Console.WriteLine(Last(numbers));          // T inferred as int
Console.WriteLine(Last(words));            // T inferred as string
Swap(ref numbers[0], ref numbers[2]);
Console.WriteLine(string.Join(" ", numbers));
Console.WriteLine(Largest(words) + " " + Largest(numbers));

static T Last<T>(IReadOnlyList<T> items) => items[^1];

static void Swap<T>(ref T a, ref T b) => (a, b) = (b, a);

static T Largest<T>(IEnumerable<T> items) where T : IComparable<T>
{
    using var e = items.GetEnumerator();
    if (!e.MoveNext()) throw new InvalidOperationException("empty");
    T best = e.Current;
    while (e.MoveNext()) if (e.Current.CompareTo(best) > 0) best = e.Current;
    return best;
}

The compiler infers T from the arguments, so you rarely write Last<int>(...).

Constraints

where T : ... limits which types may be used, so the body can rely on what they offer:

Constraint Means
where T : IComparable<T> T implements that interface: CompareTo can be called
where T : class / struct T is a reference / value type
where T : new() T has a public parameterless constructor: new T()
where T : notnull T is not a nullable type
where T : Shape T is Shape or derives from it

Generic classes

C#
var stack = new BoundedStack<string>(2);
stack.Push("a");
stack.Push("b");
Console.WriteLine(stack.TryPush("c"));     // False: full
Console.WriteLine(stack.Pop() + stack.Peek());

var pair = new Pair<string, int>("age", 36);
Console.WriteLine(pair);
Console.WriteLine(pair.Swap());

public class BoundedStack<T>(int capacity)
{
    private readonly List<T> _items = new();
    public int Count => _items.Count;

    public bool TryPush(T item)
    {
        if (_items.Count >= capacity) return false;
        _items.Add(item);
        return true;
    }

    public void Push(T item)
    {
        if (!TryPush(item)) throw new InvalidOperationException("stack is full");
    }

    public T Pop()
    {
        T top = Peek();
        _items.RemoveAt(_items.Count - 1);
        return top;
    }

    public T Peek() => _items.Count > 0 ? _items[^1] : throw new InvalidOperationException("stack is empty");
}

public record Pair<TFirst, TSecond>(TFirst First, TSecond Second)
{
    public Pair<TSecond, TFirst> Swap() => new(Second, First);
}

Name type parameters T when there is one, and TKey, TValue, TResult and so on when there are several.

default(T)

default(T) (or just default when the type is known) is 0 for numbers, false, and null for reference types. It is the usual "nothing found" result of TryGet-style methods:

C#
var ages = new Dictionary<string, int> { ["Ada"] = 36 };
Console.WriteLine(GetOr(ages, "Bob", -1));
Console.WriteLine(FirstOrNothing(new List<string>()) ?? "(none)");

static TValue GetOr<TKey, TValue>(Dictionary<TKey, TValue> d, TKey key, TValue fallback) where TKey : notnull
    => d.TryGetValue(key, out var v) ? v : fallback;

static T? FirstOrNothing<T>(List<T> items) where T : class => items.Count > 0 ? items[0] : default;

Variance

IEnumerable<T> is covariant: an IEnumerable<Circle> can be used where an IEnumerable<Shape> is expected, because you only read from it. List<T> is not: a List<Circle> is not a List<Shape>, since someone could add a Square to it. This is why methods should accept IEnumerable<T> or IReadOnlyList<T> where they only read: callers can pass lists of more specific types.

C#
List<Circle> circles = [new(1), new(2)];
Console.WriteLine(TotalArea(circles).ToString("F2"));     // fine: IEnumerable<Shape> accepts them

static double TotalArea(IEnumerable<Shape> shapes) => shapes.Sum(s => s.Area());

public abstract record Shape { public abstract double Area(); }
public record Circle(double R) : Shape { public override double Area() => Math.PI * R * R; }
