Interfaces

lesson 3.044 of 5 in milestone 35 min1 practice task

Interfaces as contracts, implementing several interfaces, programming against interfaces instead of concrete classes, the built-in IComparable, IEquatable and IEnumerable, default interface methods, explicit implementation, and using interfaces to swap implementations and test code.

A contract

An interface lists members that a type promises to have, without saying how. A class or struct implements it by providing them all:

C#
INotifier[] channels = [new EmailNotifier("ada@example.com"), new SmsNotifier("+3161234")];
foreach (var c in channels) c.Send("Your order has shipped");
Console.WriteLine(channels.Count(c => c.IsAvailable));

public interface INotifier
{
    bool IsAvailable { get; }
    void Send(string message);
}

public class EmailNotifier(string address) : INotifier
{
    public bool IsAvailable => address.Contains('@');
    public void Send(string message) => Console.WriteLine($"email to {address}: {message}");
}

public class SmsNotifier(string number) : INotifier
{
    public bool IsAvailable => number.StartsWith('+');
    public void Send(string message) => Console.WriteLine($"sms to {number}: {message[..Math.Min(20, message.Length)]}");
}

Interface names start with I by convention. A class can inherit from one class but implement any number of interfaces: class Report : Document, IPrintable, IExportable.

Program against interfaces

Code that takes an interface works with every implementation, including ones that do not exist yet, and including fakes in tests:

C#
var clock = new FixedClock(new DateTime(2026, 3, 14, 9, 0, 0));
var greeter = new Greeter(clock);
Console.WriteLine(greeter.Greeting("Ada"));

public interface IClock { DateTime Now { get; } }
public class SystemClock : IClock { public DateTime Now => DateTime.Now; }
public class FixedClock(DateTime time) : IClock { public DateTime Now => time; }

public class Greeter(IClock clock)
{
    public string Greeting(string name) => clock.Now.Hour switch
    {
        < 12 => $"Good morning, {name}",
        < 18 => $"Good afternoon, {name}",
        _ => $"Good evening, {name}",
    };
}

Greeter does not care where the time comes from. The real program passes a SystemClock; a test passes a FixedClock and gets the same answer every time. This is the idea behind dependency injection (lesson 6.03).

Accept the most general type you need: a method that only loops over items should take IEnumerable<T>, not List<T>; one that needs indexing takes IReadOnlyList<T>.

Built-in interfaces

Interface Lets a type
IComparable<T> Be sorted: CompareTo(other)
IEquatable<T> Compare for equality efficiently: Equals(other)
IEnumerable<T> Be looped over with foreach and queried with LINQ
IDisposable Release resources with using (lesson 4.04)
IComparer<T>, IEqualityComparer<T> Be an external ordering or equality rule
C#
var versions = new List<Version3> { new(1, 10, 0), new(1, 2, 3), new(0, 9, 9) };
versions.Sort();
Console.WriteLine(string.Join(" < ", versions));

public record Version3(int Major, int Minor, int Patch) : IComparable<Version3>
{
    public int CompareTo(Version3? other)
    {
        if (other is null) return 1;
        int c = Major.CompareTo(other.Major);
        if (c != 0) return c;
        c = Minor.CompareTo(other.Minor);
        return c != 0 ? c : Patch.CompareTo(other.Patch);
    }
    public override string ToString() => $"{Major}.{Minor}.{Patch}";
}

Default methods and explicit implementation

An interface member can have a default implementation, which implementers may keep or replace. It lets you add members to an interface without breaking existing classes:

C#
ILogger log = new ConsoleLogger();
log.Info("started");
log.Log("raw message");

public interface ILogger
{
    void Log(string message);
    void Info(string message) => Log($"[info] {message}");     // default implementation
}

public class ConsoleLogger : ILogger
{
    public void Log(string message) => Console.WriteLine(message);
}

Default members are called through the interface type (ILogger log), not through the class.

When two interfaces have a member with the same name, or a member should not clutter the class's public surface, implement it explicitly: void IExportable.Export() { ... }. It is then only reachable through the interface.

Interfaces or abstract classes?

Use an interface to describe a capability that unrelated types can share (IComparable, INotifier). Use an abstract base class when types share code and state and form a real "is a" family (Shape). Interfaces are the more common choice in modern C#.
