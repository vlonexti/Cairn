Operators, Indexers and Conversions

lesson 7.011 of 6 in milestone 75 min2 practice tasks

Making your own types feel built in - overloading arithmetic and comparison operators, equality done right, indexers with this[...], Index and Range support, implicit and explicit conversion operators, and when not to overload.

Operators on your own types

A type for money, vectors or fractions reads best when a + b works on it. An operator is a public static method named operator plus the symbol:

C#
var a = new Vec2(1, 2);
var b = new Vec2(3, 4);
Console.WriteLine(a + b);          // Vec2 { X = 4, Y = 6 }
Console.WriteLine(a * 3);          // Vec2 { X = 3, Y = 6 }
Console.WriteLine(-a);             // Vec2 { X = -1, Y = -2 }

public readonly record struct Vec2(double X, double Y)
{
    public static Vec2 operator +(Vec2 l, Vec2 r) => new(l.X + r.X, l.Y + r.Y);
    public static Vec2 operator -(Vec2 l, Vec2 r) => new(l.X - r.X, l.Y - r.Y);
    public static Vec2 operator *(Vec2 v, double s) => new(v.X * s, v.Y * s);
    public static Vec2 operator *(double s, Vec2 v) => v * s;
    public static Vec2 operator -(Vec2 v) => new(-v.X, -v.Y);
}

Defining + also makes += work. Operators come in required pairs: == with !=, < with >, <= with >=.

Equality and comparison

A record (lesson 3.02) already writes ==, !=, Equals and GetHashCode from its fields. For a class you write yourself, implement IEquatable<T> and keep all four consistent:

C#
var x = new Version2(1, 4);
var y = new Version2(1, 10);
Console.WriteLine($"{x < y} {x == new Version2(1, 4)} {x.CompareTo(y)}");

public sealed class Version2 : IEquatable<Version2>, IComparable<Version2>
{
    public int Major { get; }
    public int Minor { get; }
    public Version2(int major, int minor) => (Major, Minor) = (major, minor);

    public int CompareTo(Version2? other) =>
        other is null ? 1 : (Major, Minor).CompareTo((other.Major, other.Minor));

    public bool Equals(Version2? other) => other is not null && Major == other.Major && Minor == other.Minor;
    public override bool Equals(object? obj) => Equals(obj as Version2);
    public override int GetHashCode() => HashCode.Combine(Major, Minor);

    public static bool operator ==(Version2? l, Version2? r) => l is null ? r is null : l.Equals(r);
    public static bool operator !=(Version2? l, Version2? r) => !(l == r);
    public static bool operator <(Version2 l, Version2 r) => l.CompareTo(r) < 0;
    public static bool operator >(Version2 l, Version2 r) => l.CompareTo(r) > 0;
    public static bool operator <=(Version2 l, Version2 r) => l.CompareTo(r) <= 0;
    public static bool operator >=(Version2 l, Version2 r) => l.CompareTo(r) >= 0;
}

Comparing tuples, (Major, Minor).CompareTo(...), compares field by field, which saves writing the chain by hand. Equal objects must have equal hash codes, or dictionaries and sets lose them.

Indexers

An indexer lets an object be used with square brackets, like an array or dictionary. It is a property named this with parameters:

C#
var grid = new Grid(3, 2);
grid[1, 0] = 'X';
Console.WriteLine(grid[1, 0]);
Console.WriteLine(grid);

public class Grid(int width, int height)
{
    private readonly char[] _cells = Enumerable.Repeat('.', width * height).ToArray();

    public char this[int x, int y]
    {
        get => _cells[Index(x, y)];
        set => _cells[Index(x, y)] = value;
    }

    private int Index(int x, int y) =>
        x < 0 || x >= width || y < 0 || y >= height
            ? throw new ArgumentOutOfRangeException($"({x}, {y}) is outside the grid")
            : y * width + x;

    public override string ToString() =>
        string.Join("\n", Enumerable.Range(0, height).Select(y => new string(_cells, y * width, width)));
}

public class Grid(int width, int height) is a primary constructor (C# 12): the parameters are available in the whole class body.

Index and Range

items[^1] (the last item) and items[1..3] (a slice) work on your type if it has an indexer taking int, a Count or Length, and (for ranges) a Slice(start, length) method. The compiler translates ^1 and 1..3 into those calls.

Conversion operators

implicit conversions happen automatically and must never lose information or throw. explicit ones need a cast and may do either:

C#
Celsius c = 25.0;                 // implicit: double to Celsius
double raw = c;                   // implicit back
var f = (Fahrenheit)c;            // explicit: a deliberate change of scale
Console.WriteLine($"{raw} {f.Value}");

public readonly record struct Celsius(double Value)
{
    public static implicit operator Celsius(double value) => new(value);
    public static implicit operator double(Celsius c) => c.Value;
    public static explicit operator Fahrenheit(Celsius c) => new(c.Value * 9 / 5 + 32);
}

public readonly record struct Fahrenheit(double Value);

When not to

Overload an operator only when its meaning is obvious to every reader: + on vectors and money, < on versions and dates. If you have to explain what * means for your type, a named method (Scale, Merge) is clearer.
