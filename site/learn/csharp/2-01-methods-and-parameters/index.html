Methods and Parameters

lesson 2.011 of 5 in milestone 25 min1 practice task

Writing methods with parameters and return values, expression-bodied methods, overloading, optional and named arguments, params arrays, ref, out and in parameters, local functions, recursion, and static methods in classes.

Methods

A method is a named block of code that takes parameters and may return a value. Methods live in classes; in a top-level program you can also write them directly as local functions:

C#
Console.WriteLine(Area(3, 4));
Console.WriteLine(Describe("Ada", 36));
Greet("Grace");

static double Area(double width, double height)
{
    return width * height;
}

static string Describe(string name, int age) => $"{name} ({age})";   // expression-bodied

static void Greet(string name)     // void: returns nothing
{
    Console.WriteLine($"Hello, {name}!");
}

Each parameter has a type, and so does the result: the compiler checks every call. => expression is shorthand for a body that returns one expression.

In a class, the same methods look like this; static means they belong to the class itself rather than to an object (lesson 3.05):

C#
public static class Geometry
{
    public static double Area(double width, double height) => width * height;
}
// called as Geometry.Area(3, 4)

Overloading

Several methods in a class may share a name if their parameter lists differ. The compiler picks the best match:

C#
Console.WriteLine(MathX.Max(3, 9));
Console.WriteLine(MathX.Max(2.5, 1.5));
Console.WriteLine(MathX.Max(4, 8, 6));

static class MathX
{
    public static int Max(int a, int b) => a > b ? a : b;
    public static double Max(double a, double b) => a > b ? a : b;
    public static int Max(int a, int b, int c) => Max(Max(a, b), c);
}

Local functions in a top-level program cannot be overloaded; methods in classes can.

Optional and named arguments

C#
Console.WriteLine(Format(1234.5));
Console.WriteLine(Format(1234.5, decimals: 0));
Console.WriteLine(Format(1234.5, prefix: "EUR "));

static string Format(double amount, int decimals = 2, string prefix = "")
    => prefix + amount.ToString("F" + decimals);

Parameters with default values are optional; they must come after the required ones. Named arguments (decimals: 0) make calls readable and let you skip optional parameters.

params

A params parameter accepts any number of arguments as an array:

C#
Console.WriteLine(Sum());
Console.WriteLine(Sum(1, 2, 3));
int[] values = { 10, 20 };
Console.WriteLine(Sum(values));

static int Sum(params int[] numbers)
{
    int total = 0;
    foreach (int n in numbers) total += n;
    return total;
}

ref, out and in

Arguments are normally passed by value: the method gets a copy of the variable's value (for reference types, a copy of the reference). Three keywords pass the variable itself:

C#
int a = 1, b = 2;
Swap(ref a, ref b);
Console.WriteLine($"{a} {b}");

if (TryDivide(10, 4, out double result)) Console.WriteLine(result);
if (!TryDivide(1, 0, out _)) Console.WriteLine("cannot divide by zero");

static void Swap(ref int x, ref int y) => (x, y) = (y, x);

static bool TryDivide(int x, int y, out double quotient)
{
    if (y == 0) { quotient = 0; return false; }
    quotient = (double)x / y;
    return true;
}
  • ref: the method can read and change the caller's variable.
  • out: the method must assign it; used for extra results, as in the TryParse pattern. out _ discards a result you do not need.
  • in: passed by reference but read-only, to avoid copying large structs.

For several results, a tuple is often clearer than out: static (int Min, int Max) Range(int[] xs), used as var (lo, hi) = Range(xs);.

Recursion

A method can call itself. Every recursive method needs a base case that stops:

C#
Console.WriteLine(Factorial(10));
Console.WriteLine(Gcd(84, 36));

static long Factorial(int n) => n <= 1 ? 1 : n * Factorial(n - 1);
static int Gcd(int a, int b) => b == 0 ? a : Gcd(b, a % b);

Without a base case, the calls never end and the program stops with a StackOverflowException.

Good methods

A method should do one thing that its name says. Prefer returning results over printing them: CalculateTotal that returns a number can be tested and reused; one that prints cannot. Keep reading input and printing at the edges of the program.
