Collections in Depth

lesson 7.022 of 6 in milestone 75 min2 practice tasks

Choosing the right collection - Stack, Queue and PriorityQueue, LinkedList, SortedDictionary and SortedSet, read-only views, immutable and frozen collections, concurrent collections for threads, and what each operation costs.

Beyond List and Dictionary

List<T>, Dictionary<K, V> and HashSet<T> (lessons 2.02 and 2.03) cover most needs. The others exist because some jobs are much faster or clearer with them.

Stack and Queue

A stack is last in, first out (undo history, matching brackets); a queue is first in, first out (work waiting its turn):

C#
var undo = new Stack<string>();
undo.Push("type a");
undo.Push("type b");
Console.WriteLine(undo.Pop());        // type b
Console.WriteLine(undo.Peek());       // type a (still there)

var waiting = new Queue<string>();
waiting.Enqueue("first");
waiting.Enqueue("second");
Console.WriteLine(waiting.Dequeue()); // first
Console.WriteLine(waiting.TryDequeue(out var next) ? next : "empty");

PriorityQueue

PriorityQueue<TElement, TPriority> always hands out the element with the smallest priority next. It is the heart of Dijkstra's algorithm, schedulers and "the top N" problems:

C#
var tasks = new PriorityQueue<string, int>();
tasks.Enqueue("write report", 2);
tasks.Enqueue("fix outage", 0);
tasks.Enqueue("lunch", 5);
while (tasks.TryDequeue(out var task, out int priority))
    Console.WriteLine($"{priority}: {task}");

Elements with equal priority come out in no guaranteed order. For "largest first", pass a comparer: new PriorityQueue<string, int>(Comparer<int>.Create((a, b) => b.CompareTo(a))).

LinkedList

LinkedList<T> is a doubly linked list: inserting or removing next to a node you already hold is instant, but finding the n-th item means walking. It suits "move this to the front" structures such as an LRU cache:

C#
var recent = new LinkedList<string>(["a", "b", "c"]);
var node = recent.Find("c")!;
recent.Remove(node);
recent.AddFirst(node);
Console.WriteLine(string.Join(",", recent));     // c,a,b

Sorted collections

SortedDictionary<K, V> and SortedSet<T> keep their contents in key order at all times (they are balanced trees), so iterating them is always sorted, and SortedSet can answer range questions:

C#
var scores = new SortedDictionary<string, int> { ["zoe"] = 3, ["ada"] = 9, ["max"] = 5 };
Console.WriteLine(string.Join(" ", scores.Keys));        // ada max zoe

var times = new SortedSet<int> { 30, 5, 90, 45, 12 };
Console.WriteLine(string.Join(" ", times.GetViewBetween(10, 50)));   // 12 30 45
Console.WriteLine($"{times.Min} {times.Max}");

What things cost

Collection Add Find by key or value Remove Notes
List<T> O(1) at end O(n) O(n) index O(1)
Dictionary, HashSet O(1) O(1) O(1) no order
SortedDictionary, SortedSet O(log n) O(log n) O(log n) always sorted
Stack, Queue O(1) — O(1) at the ends
PriorityQueue O(log n) — O(log n) smallest
LinkedList O(1) next to a node O(n) O(1) given the node

Read-only, immutable and frozen

  • Read-only views (list.AsReadOnly(), returning IReadOnlyList<T>) stop callers changing your collection through that reference, but you can still change it.
  • Immutable collections (System.Collections.Immutable: ImmutableList, ImmutableDictionary) never change; "adding" returns a new collection that shares most of the old one. Safe to share between threads without locks.
  • Frozen collections (FrozenDictionary, FrozenSet, .NET 8) are built once and then optimised for very fast lookups: ideal for tables loaded at start-up.
C#
using System.Collections.Frozen;
using System.Collections.Immutable;

var v1 = ImmutableList.Create(1, 2, 3);
var v2 = v1.Add(4);
Console.WriteLine($"{v1.Count} {v2.Count}");     // 3 4

var codes = new Dictionary<string, int> { ["en"] = 1, ["de"] = 2 }.ToFrozenDictionary();
Console.WriteLine(codes["de"]);

Collections for threads

Ordinary collections are not safe when several threads change them at once. System.Collections.Concurrent has versions that are: ConcurrentDictionary (with AddOrUpdate and GetOrAdd), ConcurrentQueue, ConcurrentBag, and BlockingCollection for producers and consumers (lesson 7.06 shows the modern Channel).
