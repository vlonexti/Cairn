Generic Math and Static Abstract Members

lesson 8.033 of 5 in milestone 85 min2 practice tasks

Writing one method that works for every number type - why generics could not do arithmetic before, the INumber<T> family of interfaces, T.Zero, T.One and T.CreateChecked, static abstract and static virtual interface members, defining operators in your own generic interfaces, and when generic math is worth it.

The old problem

Before C# 11, this did not compile:

C#
static T Sum<T>(IEnumerable<T> values)
{
    T total = 0;              // error: cannot convert 0 to T
    foreach (var v in values) total += v;   // error: + is not defined for T
    return total;
}

Generics could call instance methods of an interface, but numbers are added with static operators, and interfaces had no way to require those. So libraries wrote the same method once for int, once for double, once for decimal...

INumber<T>

.NET 7 added interfaces for every ability numbers have, in System.Numerics. INumber<T> gathers the common ones, and every built-in number type implements it:

C#
using System.Numerics;

static T Sum<T>(IEnumerable<T> values) where T : INumber<T>
{
    T total = T.Zero;
    foreach (var v in values) total += v;
    return total;
}

static T Average<T>(IReadOnlyCollection<T> values) where T : INumber<T>
    => Sum(values) / T.CreateChecked(values.Count);

Console.WriteLine(Sum(new[] { 1, 2, 3 }));
Console.WriteLine(Sum(new[] { 1.5, 2.25 }));
Console.WriteLine(Average(new[] { 1m, 2m, 4m }));
Console.WriteLine(Average(new[] { 1, 2, 4 }));       // 2: int division
  • T.Zero and T.One are the type's 0 and 1.
  • T.CreateChecked(x) converts any number to T, throwing OverflowException if it does not fit; CreateSaturating clamps and CreateTruncating wraps instead.
  • Operators such as +, / and < come from interfaces like IAdditionOperators that INumber<T> includes.

Smaller interfaces let you ask for exactly what you need: IAdditionOperators<T, T, T>, IComparisonOperators<T, T, bool>, IFloatingPoint<T> (adds Floor, Round), IBinaryInteger<T> (adds bit operations and PopCount).

C#
using System.Numerics;

static T Clamp<T>(T value, T min, T max) where T : INumber<T> => T.Max(min, T.Min(max, value));
static int Bits<T>(T value) where T : IBinaryInteger<T> => int.CreateChecked(T.PopCount(value));

Console.WriteLine($"{Clamp(15, 0, 10)} {Clamp(-0.5, 0.0, 1.0)} {Bits(255)} {Bits((byte)7)}");

How it works: static abstract members

Interfaces can now declare static abstract members, which every implementing type must provide, and generic code calls them through the type parameter (T.Zero):

C#
static string UnitArea<T>() where T : IShape => $"unit {T.Kind}: {T.Unit().Area():F2}";

Console.WriteLine(UnitArea<Square>());
Console.WriteLine(UnitArea<Circle>());

interface IShape
{
    static abstract string Kind { get; }
    static abstract IShape Unit();
    double Area();
}

record Square(double Side) : IShape
{
    public static string Kind => "square";
    public static IShape Unit() => new Square(1);
    public double Area() => Side * Side;
}

record Circle(double R) : IShape
{
    public static string Kind => "circle";
    public static IShape Unit() => new Circle(1);
    public double Area() => Math.PI * R * R;
}

This is something instance interfaces cannot do: ask a type for something without having an object of it. Factory methods, parsing (T.Parse, which IParsable<T> provides) and constants all fit.

static virtual members are the same but come with a default implementation that types may override.

Your own operators in a generic interface

A type can promise operators through an interface, so generic code can use them:

C#
using System.Numerics;

static T Total<T>(IEnumerable<T> items) where T : IAdditionOperators<T, T, T>, IAdditiveIdentity<T, T>
{
    T sum = T.AdditiveIdentity;
    foreach (var x in items) sum += x;
    return sum;
}

Console.WriteLine(Total(new[] { new Money(1.5m), new Money(2m) }));
Console.WriteLine(Total(new[] { 1, 2, 3 }));

readonly record struct Money(decimal Amount) :
    IAdditionOperators<Money, Money, Money>, IAdditiveIdentity<Money, Money>
{
    public static Money operator +(Money a, Money b) => new(a.Amount + b.Amount);
    public static Money AdditiveIdentity => new(0);
}

The same Total adds integers and your Money.

Parsing generically

C#
static List<T> ParseAll<T>(string csv) where T : IParsable<T>
    => csv.Split(',').Select(s => T.Parse(s.Trim(), System.Globalization.CultureInfo.InvariantCulture)).ToList();

Console.WriteLine(string.Join(" ", ParseAll<int>("1, 2, 3")));
Console.WriteLine(string.Join(" ", ParseAll<double>("1.5, 2")));
Console.WriteLine(string.Join(" ", ParseAll<DateOnly>("2026-11-20")));

When to use it

Generic math is worth it in libraries that really serve many number types: maths and statistics helpers, vectors and matrices, parsers. In application code that only ever uses decimal, plain code is simpler to read.
