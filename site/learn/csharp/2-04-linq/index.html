LINQ

lesson 2.044 of 5 in milestone 25 min1 practice task

Language Integrated Query - filtering, projecting and ordering with Where, Select, OrderBy and ThenBy, aggregates like Count, Sum, Average, Min and Max, First, Any and All, grouping with GroupBy and CountBy, ToDictionary, SelectMany, Distinct, Zip, deferred execution and query syntax.

Queries over collections

LINQ adds methods to every collection (anything that is an IEnumerable<T>) for filtering, transforming and summarising. Each takes a lambda, a small inline function written x => expression:

C#
int[] numbers = [5, 3, 8, 1, 9, 2];
var evensSquared = numbers.Where(n => n % 2 == 0).Select(n => n * n);
Console.WriteLine(string.Join(" ", evensSquared));          // 64 4
Console.WriteLine(string.Join(" ", numbers.OrderBy(n => n)));
Console.WriteLine($"{numbers.Sum()} {numbers.Average():F2} {numbers.Max()} {numbers.Count(n => n > 4)}");

using System.Linq; is needed in a project; the practice editor and new projects add it automatically.

The common methods

Method Gives
Where(x => cond) The items that match
Select(x => value) Each item transformed
OrderBy(x => key), OrderByDescending, ThenBy Sorted (stable)
First(), FirstOrDefault(), Single(), Last() One item (First throws if none)
Any(x => cond), All(x => cond), Contains(v) Tests
Count(), Sum(), Average(), Min(), Max() Aggregates
MinBy(x => key), MaxBy(x => key) The item with the smallest / largest key
Distinct(), DistinctBy(x => key) Without repeats
Take(n), Skip(n), TakeWhile, Chunk(n) Parts
GroupBy(x => key), CountBy(x => key) Groups / counts per key
ToList(), ToArray(), ToDictionary(k, v), ToHashSet() Collected results
SelectMany(x => many) Flattened
Zip(other) Pairs
Aggregate(seed, (acc, x) => ...) A general fold

Working with records

LINQ shines on lists of objects. Here, records (lesson 3.02) are short data classes:

C#
var people = new List<Person>
{
    new("Ada", "London", 36), new("Grace", "New York", 85),
    new("Linus", "Helsinki", 55), new("Alan", "London", 41),
};

var londoners = people.Where(p => p.City == "London").OrderBy(p => p.Name).Select(p => p.Name);
Console.WriteLine(string.Join(", ", londoners));

var oldest = people.MaxBy(p => p.Age);
Console.WriteLine(oldest!.Name);

foreach (var group in people.GroupBy(p => p.City).OrderByDescending(g => g.Count()))
{
    Console.WriteLine($"{group.Key}: {group.Count()} ({string.Join(", ", group.Select(p => p.Name))})");
}

var ageByName = people.ToDictionary(p => p.Name, p => p.Age);
Console.WriteLine(ageByName["Linus"]);
Console.WriteLine(people.Any(p => p.Age > 80) + " " + people.All(p => p.Age > 30));

record Person(string Name, string City, int Age);

GroupBy gives groups, each with a Key and its items. ToDictionary throws if two items have the same key.

Flattening and pairing

C#
var orders = new[] { new[] { "tea", "cake" }, new[] { "tea" }, new string[0] };
Console.WriteLine(string.Join(" ", orders.SelectMany(o => o).Distinct()));

string[] names = ["Ada", "Grace"];
int[] scores = [91, 88];
foreach (var (name, score) in names.Zip(scores)) Console.WriteLine($"{name} {score}");
Console.WriteLine(string.Join(" ", Enumerable.Range(1, 5).Select(i => i * i)));

Deferred execution

Where, Select, OrderBy and most other methods do not run when called: they build a query that runs each time you iterate over it. ToList(), Count(), Sum() and First() run it immediately.

C#
var source = new List<int> { 1, 2, 3 };
var big = source.Where(n => n > 1);      // nothing has run yet
source.Add(10);
Console.WriteLine(string.Join(" ", big)); // 2 3 10: the query sees the new item
var snapshot = big.ToList();              // run once and keep the results

If you iterate a query several times, or it is expensive, call ToList() once and reuse the list.

Query syntax

LINQ also has a SQL-like syntax, which the compiler turns into the same method calls:

C#
int[] nums = [4, 9, 1, 7];
var result = from n in nums
             where n > 3
             orderby n descending
             select n * 10;
Console.WriteLine(string.Join(" ", result));

Most C# code uses the method syntax; query syntax is sometimes clearer for joins and several from clauses.
