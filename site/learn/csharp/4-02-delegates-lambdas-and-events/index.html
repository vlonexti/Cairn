Delegates, Lambdas and Events

lesson 4.022 of 5 in milestone 45 min1 practice task

Treating methods as values - delegate types, Func and Action, lambdas and method groups, closures that capture variables, higher-order methods, multicast delegates, and events for notifications with the EventHandler pattern, subscribing and unsubscribing safely.

Methods as values

A delegate is a type for a method with a particular signature. A delegate value can be stored, passed and called. The built-in generic delegates cover almost every case:

Delegate Signature
Action No parameters, no result
Action<T1, T2> Takes T1 and T2, no result
Func<TResult> No parameters, returns TResult
Func<T1, T2, TResult> Takes T1 and T2, returns TResult (the last type is the result)
Predicate<T> Takes T, returns bool
C#
Func<int, int> square = x => x * x;               // a lambda
Func<int, int, int> add = (a, b) => a + b;
Action<string> shout = s => Console.WriteLine(s.ToUpper() + "!");
Func<string, int> parse = int.Parse;               // a method group: an existing method
Func<double> random = () => 4;                     // chosen by fair dice roll

Console.WriteLine(square(7) + add(1, 2) + parse("10") + random());
shout("hello");

A lambda (parameters) => expression or (parameters) => { statements } is an anonymous method. LINQ (lesson 2.04) is built on them.

Higher-order methods

Methods that take or return functions let you separate what to do from when or how often:

C#
Console.WriteLine(string.Join(" ", Repeat(5, i => i * 10)));
var timesThree = Multiplier(3);
Console.WriteLine(timesThree(14));
Func<int, int> incThenDouble = Compose<int, int, int>(x => x + 1, x => x * 2);
Console.WriteLine(incThenDouble(5));

static List<T> Repeat<T>(int times, Func<int, T> make)
{
    var result = new List<T>();
    for (int i = 0; i < times; i++) result.Add(make(i));
    return result;
}

static Func<int, int> Multiplier(int factor) => x => x * factor;

static Func<A, C> Compose<A, B, C>(Func<A, B> first, Func<B, C> then) => x => then(first(x));

Closures

A lambda can use variables from the code around it. It captures the variable itself, not a copy of its value:

C#
int calls = 0;
Func<int> next = () => ++calls;
next(); next();
Console.WriteLine(calls);                  // 2: the lambda changed the outer variable

var actions = new List<Action>();
foreach (var name in new[] { "a", "b", "c" }) actions.Add(() => Console.Write(name));
actions.ForEach(a => a());                 // abc: each loop iteration has its own name
Console.WriteLine();

Captured variables live as long as the lambda does. That is how Multiplier(3) above still knows factor.

Events

An event lets an object notify others that something happened, without knowing who listens. Listeners subscribe with += and unsubscribe with -=:

C#
var sensor = new TemperatureSensor();
EventHandler<double> logger = (sender, celsius) => Console.WriteLine($"log: {celsius} C");
sensor.TooHot += logger;
sensor.TooHot += (_, c) => Console.WriteLine($"ALERT: {c} C");

sensor.Report(21);
sensor.Report(31.5);
sensor.TooHot -= logger;
sensor.Report(35);

public class TemperatureSensor
{
    public double Threshold { get; init; } = 30;
    public event EventHandler<double>? TooHot;

    public void Report(double celsius)
    {
        if (celsius > Threshold) TooHot?.Invoke(this, celsius);   // ?. : nobody may be listening
    }
}
  • event means outside code can only += and -=; only the class itself can raise (invoke) it.
  • The convention is EventHandler<TArgs>: the sender and the event data.
  • A delegate can hold several methods (multicast): invoking it calls them all, in order.

Unsubscribe when a listener should stop listening and lives shorter than the object it listens to. An event holds references to its listeners, so a forgotten subscription keeps them alive (a common memory leak in desktop apps).
