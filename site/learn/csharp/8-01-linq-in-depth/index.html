LINQ in Depth

lesson 8.011 of 5 in milestone 85 min2 practice tasks

The rest of LINQ - query syntax and how it maps to methods, joining two sequences with Join and GroupJoin, flattening with SelectMany, Aggregate, Zip, Chunk and the By methods, ToLookup, set operations, and the deferred execution rules that decide when a query actually runs.

Beyond Where and Select

Lesson 2.04 introduced LINQ's everyday methods. This lesson covers the ones that combine several sequences, summarise them in custom ways, and the rule that surprises everyone: when a query runs.

The examples use these records:

C#
record Customer(int Id, string Name, string City);
record Order(int Id, int CustomerId, decimal Total);

Query syntax

C# has a second way to write queries that reads like SQL. The compiler turns it into the method calls you already know:

C#
var customers = new List<Customer> { new(1, "Ada", "London"), new(2, "Bob", "Paris"), new(3, "Cy", "London") };

var londoners =
    from c in customers
    where c.City == "London"
    orderby c.Name descending
    select c.Name;

Console.WriteLine(string.Join(", ", londoners));     // Cy, Ada
// the same as: customers.Where(c => c.City == "London").OrderByDescending(c => c.Name).Select(c => c.Name)

record Customer(int Id, string Name, string City);

Most C# code uses the method form. Query syntax shines for joins and let, which names an intermediate value.

Joining two sequences

Join pairs items from two sequences whose keys match:

C#
var customers = new List<Customer> { new(1, "Ada", "London"), new(2, "Bob", "Paris"), new(3, "Cy", "London") };
var orders = new List<Order> { new(10, 1, 25m), new(11, 2, 40m), new(12, 1, 15m) };

var lines = customers.Join(orders, c => c.Id, o => o.CustomerId, (c, o) => $"{c.Name}: order {o.Id} {o.Total}");
foreach (var line in lines) Console.WriteLine(line);

// GroupJoin keeps every customer, with the list of their orders (possibly empty)
var totals = customers.GroupJoin(orders, c => c.Id, o => o.CustomerId,
    (c, os) => new { c.Name, Count = os.Count(), Sum = os.Sum(o => o.Total) });
foreach (var t in totals) Console.WriteLine($"{t.Name}: {t.Count} orders, {t.Sum}");

record Customer(int Id, string Name, string City);
record Order(int Id, int CustomerId, decimal Total);

Join is an inner join: Cy, who has no orders, does not appear. GroupJoin is the left join: everyone appears, Cy with 0 orders.

Flattening with SelectMany

SelectMany turns each item into a sequence and joins all those sequences into one:

C#
var teams = new Dictionary<string, string[]>
{
    ["red"] = ["Ada", "Bob"],
    ["blue"] = ["Cy"],
};

var everyone = teams.SelectMany(t => t.Value, (t, player) => $"{player} ({t.Key})");
Console.WriteLine(string.Join(", ", everyone));    // Ada (red), Bob (red), Cy (blue)

var pairs = from x in new[] { 1, 2 } from y in new[] { "a", "b" } select $"{x}{y}";
Console.WriteLine(string.Join(" ", pairs));         // 1a 1b 2a 2b

Summaries of your own: Aggregate

Sum, Max and friends cover common cases. Aggregate folds a sequence with any function, starting from a seed:

C#
var words = new[] { "tea", "coffee", "milk" };
string longest = words.Aggregate((best, w) => w.Length > best.Length ? w : best);
string csv = words.Aggregate(new System.Text.StringBuilder(), (sb, w) => sb.Append(sb.Length > 0 ? "," : "").Append(w)).ToString();
int product = Enumerable.Range(1, 5).Aggregate(1, (acc, n) => acc * n);
Console.WriteLine($"{longest} | {csv} | {product}");   // coffee | tea,coffee,milk | 120

Zip, Chunk and the By methods

C#
var names = new[] { "Ada", "Bob", "Cy" };
var scores = new[] { 91, 48, 77 };

foreach (var (name, score) in names.Zip(scores)) Console.Write($"{name}={score} ");
Console.WriteLine();

foreach (var chunk in Enumerable.Range(1, 7).Chunk(3)) Console.Write($"[{string.Join(",", chunk)}] ");
Console.WriteLine();

var people = names.Zip(scores, (n, s) => (Name: n, Score: s)).ToList();
Console.WriteLine(people.MaxBy(p => p.Score).Name);                       // Ada
Console.WriteLine(string.Join(",", people.DistinctBy(p => p.Score / 50).Select(p => p.Name)));   // Ada,Bob

MaxBy, MinBy, DistinctBy, UnionBy, IntersectBy and ExceptBy compare by a key but return whole items.

Lookups and sets

ToLookup is a GroupBy that runs at once and can be indexed; a missing key gives an empty sequence instead of an exception:

C#
var words = new[] { "apple", "avocado", "banana", "cherry" };
var byLetter = words.ToLookup(w => w[0]);
Console.WriteLine(string.Join(",", byLetter['a']));     // apple,avocado
Console.WriteLine(byLetter['z'].Count());              // 0

int[] a = [1, 2, 3, 4], b = [3, 4, 5];
Console.WriteLine($"{string.Join(",", a.Union(b))} | {string.Join(",", a.Intersect(b))} | {string.Join(",", a.Except(b))}");

When does a query run?

Most LINQ methods are deferred: they build a description of the work, and nothing happens until something enumerates the result (foreach, ToList, Count, First...). Each enumeration runs the whole query again:

C#
int evaluated = 0;
var numbers = new List<int> { 1, 2, 3 };
var doubled = numbers.Select(n => { evaluated++; return n * 2; });

Console.WriteLine(evaluated);           // 0: nothing has run yet
numbers.Add(4);                         // the query sees this, because it has not run
Console.WriteLine(doubled.Sum());       // 20
Console.WriteLine(doubled.Count());     // 4: it ran again
Console.WriteLine(evaluated);           // 8

var snapshot = doubled.ToList();        // run once and keep the results
Console.WriteLine(evaluated);           // 12

Rules of thumb:

  • Call ToList() or ToArray() when you will use the results more than once, or when the source may change.
  • Methods that return a single value (Count, Sum, First, Any, ToList, ToDictionary) run at once.
  • A query over a database (Entity Framework) is translated into SQL when it runs; deferred execution is what makes that possible.
