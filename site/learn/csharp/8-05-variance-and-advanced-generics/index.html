Variance and Advanced Generics

lesson 8.055 of 5 in milestone 85 min2 practice tasks

The finer points of generics - why a List<Cat> is not a List<Animal>, covariance with out and contravariance with in, which built-in interfaces and delegates are variant, writing variant interfaces of your own, default(T), static data per closed generic type, generic caches, and constraints for enums, delegates and unmanaged types.

A puzzle

A Cat is an Animal. Is a List<Cat> a List<Animal>?

C#
List<Cat> cats = [new Cat()];
List<Animal> animals = cats;     // error
animals.Add(new Dog());          // ...because this would put a dog among the cats

No: if it were allowed, code that thinks it has a list of animals could add a dog to the list of cats. Generic types are invariant by default: List<Cat> and List<Animal> are unrelated types.

Covariance: out

IEnumerable<T> only ever gives Ts out; you cannot add to it. So treating a sequence of cats as a sequence of animals is safe, and C# allows it:

C#
IEnumerable<Cat> cats = new List<Cat> { new("Tom"), new("Kit") };
IEnumerable<Animal> animals = cats;              // fine: covariance
foreach (var a in animals) Console.WriteLine(a.Name);

Func<Cat> makeCat = () => new Cat("New");
Func<Animal> makeAnimal = makeCat;               // a function returning cats returns animals
Console.WriteLine(makeAnimal().Name);

record Animal(string Name);
record Cat(string Name) : Animal(Name);

This works because IEnumerable<T> is declared IEnumerable<out T>: the out promises T only appears in output positions (return values).

Contravariance: in

The opposite direction works for things that only take Ts in. Something that can compare any two animals can certainly compare two cats:

C#
IComparer<Animal> byName = Comparer<Animal>.Create((a, b) => string.Compare(a.Name, b.Name, StringComparison.Ordinal));
IComparer<Cat> forCats = byName;                 // fine: contravariance
var cats = new List<Cat> { new("Tom"), new("Kit") };
cats.Sort(forCats);
Console.WriteLine(string.Join(", ", cats.Select(c => c.Name)));

Action<Animal> feed = a => Console.WriteLine($"feeding {a.Name}");
Action<Cat> feedCat = feed;                      // something that feeds any animal can feed a cat
feedCat(new Cat("Tom"));

record Animal(string Name);
record Cat(string Name) : Animal(Name);

IComparer<in T> and Action<in T> are marked in: T only appears as a parameter.

Common variant types:

covariant (out) contravariant (in)
IEnumerable<T>, IReadOnlyList<T>, IReadOnlyCollection<T>, IEnumerator<T> IComparer<T>, IEqualityComparer<T>, IComparable<T>
Func<..., TResult> (the result) Action<T>, Func<T, ...> (the arguments)

Variance only works for reference types: IEnumerable<int> is not an IEnumerable<object>.

Your own variant interfaces

C#
IProducer<Animal> source = new Shelter();
IConsumer<Cat> catVet = new Vet();
catVet.Consume((Cat)source.Produce());

interface IProducer<out T> { T Produce(); }

interface IConsumer<in T> { void Consume(T item); }

class Shelter : IProducer<Cat> { public Cat Produce() => new("Rescued"); }

class Vet : IConsumer<Animal> { public void Consume(Animal a) => Console.WriteLine($"checked {a.Name}"); }

record Animal(string Name);

record Cat(string Name) : Animal(Name);

The compiler refuses out T on an interface that takes T as a parameter, and in T on one that returns it, so a variance mistake cannot slip through.

default(T)

default(T) (or just default where the type is known) gives null for reference types and zero for value types. Use it for "no value yet" in generic code, but prefer T? and TryGet patterns where you can, so callers can tell "missing" from "a real zero":

C#
static bool TryFirst<T>(IEnumerable<T> items, Func<T, bool> test, out T? found)
{
    foreach (var x in items)
        if (test(x)) { found = x; return true; }
    found = default;
    return false;
}

Console.WriteLine(TryFirst(new[] { 0, 4, 5 }, n => n > 3, out var n) ? n : -1);
Console.WriteLine(TryFirst(new[] { 1, 2 }, x => x > 3, out var m) ? m : -1);

Static data per closed type

Each "closed" generic type (Cache<int>, Cache<string>) has its own static fields. That makes a fast cache keyed by type, with no dictionary at all:

C#
Console.WriteLine(TypeInfo<int>.Name);
Console.WriteLine(TypeInfo<int>.Name);       // the static constructor ran once for int
Console.WriteLine(TypeInfo<string>.Name);    // and once for string

static class TypeInfo<T>
{
    public static readonly string Name = typeof(T).Name;
    public static readonly int Calls;
    static TypeInfo() => Console.WriteLine($"computing info for {typeof(T).Name}");
}

EqualityComparer<T>.Default and Comparer<T>.Default are built this way.

More constraints

C#
static string Names<T>() where T : struct, Enum => string.Join(",", Enum.GetNames<T>());
static int SizeOf<T>() where T : unmanaged => System.Runtime.CompilerServices.Unsafe.SizeOf<T>();

Console.WriteLine(Names<DayOfWeek>());
Console.WriteLine($"{SizeOf<int>()} {SizeOf<double>()} {SizeOf<(byte, long)>()}");
  • where T : Enum allows only enums; where T : Delegate only delegate types.
  • where T : unmanaged allows only types with no references inside (numbers, enums, and structs of them), which can be copied as raw bytes.
  • where T : allows ref struct (C# 13) lets a generic method accept Span<T>-like types.
