Project: A Complete Application

lesson 6.055 of 5 in milestone 65 min1 practice task

Designing and building a whole application from the course's parts - a budget tracker with a domain library, commands parsed from input, services behind interfaces, JSON persistence with versions, reports with LINQ, error handling at the edges, tests, and where to go next with C#.

The application

The final project is a budget tracker: record income and expenses, set monthly budgets per category, see a monthly report, undo mistakes, and save everything to a file. It is small enough to finish and has every part a real application has.

flowchart LR
  I[Input line] --> P[Command parser]

The layers

Domain (a class library in a real solution): records and the rules, no input or output.

C#
public record Transaction(int Id, DateOnly Date, decimal Amount, string Category, string Description)
{
    public bool IsExpense => Amount < 0;
}

public class Ledger
{
    private readonly List<Transaction> _transactions = new();
    private readonly Dictionary<string, decimal> _budgets = new(StringComparer.OrdinalIgnoreCase);
    private int _nextId = 1;

    public IReadOnlyList<Transaction> Transactions => _transactions;
    public Transaction Add(DateOnly date, decimal amount, string category, string description) { ... }
    public Transaction? UndoLast() { ... }
    public void SetBudget(string category, decimal monthly) { ... }
    public decimal? BudgetFor(string category) => _budgets.TryGetValue(category, out var b) ? b : null;
}

Reports: pure functions from a ledger and a month to a report record, written with LINQ, easy to test:

C#
public record CategoryLine(string Category, decimal Spent, decimal? Budget)
{
    public bool Over => Budget is decimal b && Spent > b;
}

public static MonthReport ForMonth(Ledger ledger, int year, int month)
{
    var inMonth = ledger.Transactions.Where(t => t.Date.Year == year && t.Date.Month == month).ToList();
    var byCategory = inMonth.Where(t => t.IsExpense)
        .GroupBy(t => t.Category)
        .Select(g => new CategoryLine(g.Key, -g.Sum(t => t.Amount), ledger.BudgetFor(g.Key)))
        .OrderByDescending(l => l.Spent).ThenBy(l => l.Category, StringComparer.Ordinal)
        .ToList();
    ...
}

Storage behind an interface, with a version number in the file so later versions of the app can still read old files (lesson 5.04):

C#
public interface ILedgerStore
{
    Task SaveAsync(Ledger ledger, string path);
    Task<Ledger?> LoadAsync(string path);
}

Commands: the input is parsed into a command and its arguments, and each command has a small handler that validates the arguments, calls the domain, and returns the text to show. Errors that the user can fix (a bad date, an unknown command) become messages; bugs still throw.

Building it step by step

  1. Write the domain records and Ledger with their rules. Test them.
  2. Write the report function. Test it with a ledger built in the test.
  3. Write the command loop with add, list and quit; run it by hand.
  4. Add budget, report and undo, one at a time, each with its error messages.
  5. Add save and load with JSON.
  6. Read through the code: are names clear, is each method short, is every rule in the domain rather than in the input code?

This order keeps a working program at every step: each feature is small, finished and checked before the next one starts.

Where to go next

  • Web: ASP.NET Core minimal APIs and Blazor use everything in this course (DI, configuration, async, records, JSON). dotnet new webapi is a good start.
  • Data: Entity Framework Core maps classes to database tables; Dapper runs SQL with less ceremony.
  • Desktop and mobile: WPF or Avalonia with MVVM (lesson 6.04), or .NET MAUI.
  • Games: Unity and Godot are scripted in C#.
  • Deeper C#: Span<T> and performance, source generators, System.Threading.Channels, and the Roslyn compiler APIs.
