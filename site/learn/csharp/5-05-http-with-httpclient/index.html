HTTP with HttpClient

lesson 5.055 of 5 in milestone 55 min1 practice task

Calling web APIs - one shared HttpClient, GET and POST with JSON helpers, status codes and EnsureSuccessStatusCode, headers and authentication, query strings, timeouts and cancellation, retries for transient failures, typed API clients, and testing code that uses HTTP.

HttpClient

HttpClient sends HTTP requests. The practice sandbox has no internet access, so the examples in this lesson are for reading and for running on your own computer.

C#
using System.Net.Http.Json;

using var http = new HttpClient { BaseAddress = new Uri("https://api.example.com/") };

Todo? todo = await http.GetFromJsonAsync<Todo>("todos/1");
Console.WriteLine(todo?.Title);

HttpResponseMessage response = await http.PostAsJsonAsync("todos", new Todo(0, "Learn HttpClient", false));
response.EnsureSuccessStatusCode();                      // throws HttpRequestException for 4xx and 5xx
Todo? created = await response.Content.ReadFromJsonAsync<Todo>();

record Todo(int Id, string Title, bool Done);

System.Net.Http.Json adds GetFromJsonAsync, PostAsJsonAsync and ReadFromJsonAsync, which use System.Text.Json (lesson 5.04) with web defaults (camelCase).

One client, reused

HttpClient is meant to be created once and reused. Creating one per request (using var http = new HttpClient() inside a loop) can run out of network sockets under load. In a small program, keep one in a static readonly field; in larger apps, IHttpClientFactory (lesson 6.03) manages them for you.

Status codes

A response always has a status. Check it before reading the body:

C#
using var response = await http.GetAsync($"users/{id}");
if (response.StatusCode == HttpStatusCode.NotFound) return null;
if (!response.IsSuccessStatusCode)
{
    string body = await response.Content.ReadAsStringAsync();
    throw new ApiException($"GET users/{id} failed: {(int)response.StatusCode} {body}");
}
return await response.Content.ReadFromJsonAsync<User>();
Status Meaning Retry?
200, 201, 204 Success -
400, 422 Your request was wrong No: fix it
401, 403 Not authenticated / not allowed No
404 Not found No
408, 429 Timeout / too many requests Yes, after a pause
500, 502, 503, 504 Server failure Yes, a few times

Headers, queries and authentication

C#
http.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", token);
http.DefaultRequestHeaders.UserAgent.ParseAdd("MyApp/1.0");

string query = $"search?q={Uri.EscapeDataString("tea & cake")}&page=2";
var results = await http.GetFromJsonAsync<List<Item>>(query);

Always escape values put into URLs with Uri.EscapeDataString. Keep tokens and API keys out of source code: read them from configuration or environment variables (lesson 6.03).

Timeouts and cancellation

HttpClient.Timeout defaults to 100 seconds. Pass a CancellationToken (lesson 5.02) for finer control:

C#
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
try
{
    var data = await http.GetFromJsonAsync<Report>("reports/latest", cts.Token);
}
catch (OperationCanceledException)
{
    Console.WriteLine("the server took too long");
}

Retrying

Networks fail briefly now and then. Retry only failures that may succeed later (timeouts, 429, 5xx), only a few times, and wait longer each time:

C#
static async Task<T> RetryAsync<T>(Func<Task<T>> action, int attempts = 3)
{
    for (int i = 1; ; i++)
    {
        try { return await action(); }
        catch (HttpRequestException e) when (i < attempts && IsTransient(e.StatusCode))
        {
            await Task.Delay(TimeSpan.FromMilliseconds(200 * Math.Pow(2, i - 1)));
        }
    }
}

static bool IsTransient(HttpStatusCode? code) =>
    code is null or HttpStatusCode.RequestTimeout or HttpStatusCode.TooManyRequests || (int?)code >= 500;

Libraries such as Polly (and Microsoft.Extensions.Http.Resilience) provide retries, circuit breakers and timeouts ready-made.

A typed client

Wrap an API in a class with methods named after what they do. The rest of the program then knows nothing about URLs or JSON:

C#
public interface IWeatherApi
{
    Task<Forecast?> GetForecastAsync(string city, CancellationToken ct = default);
}

public sealed class WeatherApi(HttpClient http) : IWeatherApi
{
    public Task<Forecast?> GetForecastAsync(string city, CancellationToken ct = default) =>
        http.GetFromJsonAsync<Forecast>($"forecast?city={Uri.EscapeDataString(city)}", ct);
}

Because the program depends on IWeatherApi, tests can pass a fake implementation that returns fixed data, with no network at all. This is how the practice task and project for this milestone are built: the HTTP part is an interface, and the logic around it is tested with fakes.
