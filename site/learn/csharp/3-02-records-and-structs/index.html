Records and Structs

lesson 3.022 of 5 in milestone 35 min1 practice task

Records for data with value equality, positional records, with-expressions for non-destructive changes, deconstruction, record structs; structs as small value types, copying semantics, readonly structs, and choosing between class, record and struct.

Records

A record is a class meant for data. The compiler generates a constructor, properties, ToString, and value equality: two records are equal when all their properties are equal.

C#
var a = new Point(1, 2);
var b = new Point(1, 2);
Console.WriteLine(a == b);           // True: same values
Console.WriteLine(a);                // Point { X = 1, Y = 2 }

var moved = a with { X = 5 };        // a copy with one property changed
Console.WriteLine($"{a} {moved}");

var (x, y) = moved;                  // deconstruction
Console.WriteLine(x + y);

public record Point(int X, int Y);

record Point(int X, int Y) is a positional record: the parameters become init-only properties. Records are immutable by default: instead of changing one, you make a changed copy with with.

Records can have methods, extra properties and validation like any class:

C#
var order = new Order("A-17", [new("tea", 2, 2.5m), new("cake", 1, 4m)]);
Console.WriteLine(order.Total);
Console.WriteLine(order.Lines[0]);

public record OrderLine(string Item, int Quantity, decimal Price)
{
    public decimal Total => Quantity * Price;
}

public record Order(string Id, List<OrderLine> Lines)
{
    public decimal Total => Lines.Sum(l => l.Total);
}

Value equality compares each property with Equals. A List property compares by reference, so two orders with equal but separate lists are not equal. Use records for data that is compared, copied and passed around: messages, results, settings, keys in dictionaries.

Structs

A struct is a value type: the variable holds the data itself, and assignment copies it.

C#
var p = new Vector2(3, 4);
var q = p;                     // a full copy
q.X = 100;
Console.WriteLine($"{p.X} {q.X} {p.Length}");

public struct Vector2(double x, double y)
{
    public double X = x;
    public double Y = y;
    public readonly double Length => Math.Sqrt(X * X + Y * Y);
}

Structs avoid a separate object on the heap, which matters when there are millions of them (points in a game, pixels, money amounts). Built-in examples: int, double, DateTime, TimeSpan, Guid.

Guidelines for structs:

  • Keep them small (a few fields) and immutable: readonly struct, so copies cannot surprise you.
  • Mutable structs cause bugs: changing a copy (from a list, a property or a method's parameter) does not change the original.
C#
var money = new Money(10m, "EUR");
var more = money.Add(new Money(2.5m, "EUR"));
Console.WriteLine($"{money} {more} {money == new Money(10m, "EUR")}");

public readonly record struct Money(decimal Amount, string Currency)
{
    public Money Add(Money other) =>
        other.Currency == Currency ? this with { Amount = Amount + other.Amount }
                                   : throw new InvalidOperationException("different currencies");
    public override string ToString() => $"{Amount:F2} {Currency}";
}

A record struct gives a struct the record features: value equality, ToString, with.

Choosing

Use When
class Objects with identity and behaviour that change over time: an account, a game entity, a service
record Data compared by value, usually immutable: a DTO, an event, a result
struct / readonly record struct Small values that are copied cheaply: a point, a colour, an amount of money
