IDisposable and using

lesson 4.044 of 5 in milestone 45 min1 practice task

Releasing files, connections and other resources on time - how the garbage collector works and what it does not do, IDisposable, using statements and declarations, try/finally underneath, implementing Dispose in your own classes, IAsyncDisposable, and scoped helpers built on using.

Memory versus resources

.NET has a garbage collector: objects that nothing refers to any more are freed automatically, at some point. That handles memory. But some objects hold resources the operating system gives out in limited numbers: open files, network connections, database connections, locks. Those must be released promptly and predictably, not whenever the garbage collector happens to run.

Types that hold such resources implement IDisposable, which has one method, Dispose(), that releases them.

using

A using statement calls Dispose when the block ends, even if an exception is thrown:

C#
File.WriteAllText("notes.txt", "first line\nsecond line\n");

using (var reader = new StreamReader("notes.txt"))
{
    Console.WriteLine(reader.ReadLine());
}   // reader.Dispose() runs here: the file is closed

using var writer = new StreamWriter("log.txt");   // a using declaration: disposed at the end of the scope
writer.WriteLine("started");

The compiler turns using into try / finally:

C#
var reader = new StreamReader("notes.txt");
try { Console.WriteLine(reader.ReadLine()); }
finally { reader?.Dispose(); }

Whenever you create an object that implements IDisposable, put it in a using (or make sure something else owns and disposes it). Forgetting causes files that stay locked, connection pools that run dry, and data that is never flushed to disk.

Writing a disposable class

If your class owns a disposable object, it should be disposable too, and pass the Dispose on:

C#
using (var log = new AuditLog("audit.txt"))
{
    log.Record("login ada");
    log.Record("logout ada");
}
Console.WriteLine(File.ReadAllText("audit.txt").TrimEnd());

var closed = new AuditLog("audit2.txt");
closed.Dispose();
try { closed.Record("too late"); } catch (ObjectDisposedException e) { Console.WriteLine(e.ObjectName + " is closed"); }

public sealed class AuditLog : IDisposable
{
    private readonly StreamWriter _writer;
    private bool _disposed;
    private int _count;

    public AuditLog(string path) => _writer = new StreamWriter(path);

    public void Record(string entry)
    {
        ObjectDisposedException.ThrowIf(_disposed, this);
        _writer.WriteLine($"{++_count}: {entry}");
    }

    public void Dispose()
    {
        if (_disposed) return;          // calling Dispose twice must be harmless
        _writer.WriteLine($"{_count} entries");
        _writer.Dispose();
        _disposed = true;
    }
}

Rules for Dispose:

  • It must be safe to call more than once.
  • After disposal, other methods throw ObjectDisposedException.
  • A sealed class like this needs nothing more. (The longer "dispose pattern" with a finalizer is only for classes that hold raw operating-system handles directly, which is rare.)

using for scopes

using works with anything disposable, which makes it handy for "do this, then always undo it":

C#
Console.WriteLine("before");
using (new Indent())
{
    Indent.Write("inside");
    using (new Indent()) Indent.Write("deeper");
}
Indent.Write("after");

public sealed class Indent : IDisposable
{
    private static int _level;
    public Indent() => _level++;
    public void Dispose() => _level--;
    public static void Write(string text) => Console.WriteLine(new string(' ', _level * 2) + text);
}

Timers that measure a block, locks, and temporary changes to settings are often written this way.

Async disposal

Some resources need asynchronous clean-up (flushing a network stream). They implement IAsyncDisposable and are used with await using (lesson 5.01):

C#
await using var connection = new SqlConnection(connectionString);
await connection.OpenAsync();
