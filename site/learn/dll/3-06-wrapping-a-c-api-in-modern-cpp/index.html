Wrapping a C API in Modern C++

lesson 3.066 of 6 in milestone 35 min1 practice task

A stable C interface is pleasant for the DLL and other languages, but tedious to use from C++. The answer is a thin header-only C++ wrapper on the caller's side - RAII classes that create and destroy handles, exceptions instead of result codes, std::string instead of buffers - while the DLL boundary stays pure C.

Both worlds

You now have a C interface that is safe across compilers and languages. Using it directly from C++ looks like this:

C++
xenon_world* world{ nullptr };
if (xenon_world_create(&world) != XENON_OK) { /* ... */ }
if (xenon_world_add_stone(world, 3, 4, 7) != XENON_OK) { xenon_world_destroy(world); /* ... */ }
int32_t count{ 0 };
if (xenon_world_stone_count(world, &count) != XENON_OK) { xenon_world_destroy(world); /* ... */ }
xenon_world_destroy(world);

Every early return has to remember the destroy call. C++ programmers would rather write:

C++
xenon::World world;
world.addStone(3, 4, 7);
std::cout << world.stoneCount() << '\n';

A header-only wrapper

Put a C++ wrapper in a second header, xenon.hpp, that includes xenon.h. Because it is header-only, its code compiles into the caller's module, with the caller's compiler and settings. Nothing C++ crosses the boundary: the wrapper only calls the C functions.

C++
// xenon.hpp
#pragma once
#include "xenon.h"
#include <stdexcept>
#include <string>
#include <utility>

namespace xenon
{
    class Error : public std::runtime_error
    {
    public:
        Error(int32_t code, const std::string& what) : std::runtime_error(what), m_code{ code } {}
        int32_t code() const noexcept { return m_code; }
    private:
        int32_t m_code;
    };

    inline void check(int32_t result)
    {
        if (result == XENON_OK) return;
        std::string message(static_cast<std::size_t>(xenon_last_error(nullptr, 0)), '\0');
        xenon_last_error(message.data(), static_cast<int32_t>(message.size()) + 1);
        throw Error(result, std::string(xenon_result_name(result)) + ": " + message);
    }

    class World
    {
    public:
        World() { check(xenon_world_create(&m_handle)); }
        ~World() { xenon_world_destroy(m_handle); }

        World(World&& other) noexcept : m_handle{ std::exchange(other.m_handle, nullptr) } {}
        World& operator=(World&& other) noexcept
        {
            if (this != &other) { xenon_world_destroy(m_handle); m_handle = std::exchange(other.m_handle, nullptr); }
            return *this;
        }
        World(const World&) = delete;
        World& operator=(const World&) = delete;

        void addStone(int32_t x, int32_t y, int32_t weight) { check(xenon_world_add_stone(m_handle, x, y, weight)); }
        int32_t stoneCount() const { int32_t n{ 0 }; check(xenon_world_stone_count(m_handle, &n)); return n; }

        xenon_world* get() const noexcept { return m_handle; }   // for calling C functions the wrapper lacks

    private:
        xenon_world* m_handle{ nullptr };
    };
}

The pieces:

  • RAII: the constructor creates, the destructor destroys. No path can forget.
  • Move-only: copying would mean two objects destroying the same handle. A move transfers the handle and leaves the source empty, so its destructor does nothing (xenon_world_destroy(nullptr) must be allowed, which lesson 2.05's project required).
  • Exceptions on the caller's side: check turns a result code into an exception thrown and caught entirely in the caller's module, which is perfectly safe.
  • get() keeps the escape hatch open.

A reference-counted handle

For COM-style objects (lesson 3.04), the wrapper is a smart pointer that calls AddRef and Release:

C++
template <typename T>
class RefPtr
{
public:
    RefPtr() = default;
    explicit RefPtr(T* adopt) noexcept : m_p{ adopt } {}            // takes over an existing reference
    RefPtr(const RefPtr& o) noexcept : m_p{ o.m_p } { if (m_p) m_p->AddRef(); }
    RefPtr(RefPtr&& o) noexcept : m_p{ std::exchange(o.m_p, nullptr) } {}
    ~RefPtr() { if (m_p) m_p->Release(); }
    RefPtr& operator=(RefPtr o) noexcept { std::swap(m_p, o.m_p); return *this; }
    T* operator->() const noexcept { return m_p; }
    T* get() const noexcept { return m_p; }
private:
    T* m_p{ nullptr };
};

Copying adds a reference, destroying releases one. The practice asks you to write the move-only kind for a C handle.

Common mistakes

Putting the wrapper's code in the DLL

Then C++ types cross the boundary again. Keep the wrapper header-only, compiled by the caller.

A copyable wrapper around a handle

Two copies, two destroy calls, one crash. Delete the copy operations or count references.
