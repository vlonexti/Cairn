Version Resources, Runtimes and Shipping

lesson 4.044 of 5 in milestone 45 min1 practice task

Getting a program with DLLs onto someone else's computer means three things - giving each file a version resource so people and installers can tell versions apart, making sure the Visual C++ runtime is there (or not needed), and laying out the files so the search order finds the right ones.

The version resource

Right-click any DLL in Explorer, Properties, Details: file version, product version, description, copyright. That comes from a version resource compiled into the file.

In Visual Studio, Add, Resource, Version creates one in a .rc file:

Output
VS_VERSION_INFO VERSIONINFO
 FILEVERSION 2,4,1,0
 PRODUCTVERSION 2,4,1,0
BEGIN
    BLOCK "StringFileInfo"
    BEGIN
        BLOCK "040904b0"
        BEGIN
            VALUE "CompanyName",      "Xenon"
            VALUE "FileDescription",  "Stone maths for Xenon games"
            VALUE "FileVersion",      "2.4.1.0"
            VALUE "OriginalFilename", "StoneMath.dll"
            VALUE "ProductVersion",   "2.4.1"
        END
    END
    BLOCK "VarFileInfo"
    BEGIN
        VALUE "Translation", 0x409, 1200
    END
END

The binary FILEVERSION is four 16-bit numbers, stored as two 32-bit values: dwFileVersionMS = major << 16 | minor and dwFileVersionLS = build << 16 | revision. Installers compare these numbers to decide whether a file on disk is older than the one they carry, so increase them with every release. The practice converts between the text and the two numbers.

Reading it at run time takes GetFileVersionInfoSizeW, GetFileVersionInfoW and VerQueryValueW (from version.lib), which return a VS_FIXEDFILEINFO with those two values. That is for display and diagnostics; your code's compatibility checks belong in the library's own version function (lesson 3.05).

The Visual C++ runtime

A program built with the default /MD setting needs the runtime DLLs: vcruntime140.dll, vcruntime140_1.dll, msvcp140.dll and the Universal CRT (ucrtbase.dll, part of Windows 10 and later). On a fresh machine they may be missing. Three ways to deal with it:

Approach How Notes
Redistributable installer Run vc_redist.x64.exe from your installer The standard way; shared by all programs, updated by Windows Update
App-local copy Copy the runtime DLLs next to your .exe Works without an installer; you must update them yourself
Static runtime Build everything with /MT No runtime DLLs at all, but each DLL gets its own CRT and heap (lesson 2.05)

The redistributable is the usual choice. The runtime DLLs from Visual Studio 2015 to 2022 are binary compatible: a program built with an older toolset works with the newer redistributable (never the other way round).

Never ship Debug builds

Debug builds need the debug runtimes (msvcp140d.dll, ucrtbased.dll), which you are not allowed to redistribute and which only exist where Visual Studio is installed.

Laying out the files

XenonGame\
├── XenonGame.exe
├── StoneMath.dll           your DLLs: next to the .exe, found first (lesson 4.01)
├── engine.dll
├── vcruntime140.dll        only if you ship the runtime app-locally
├── msvcp140.dll
└── plugins\
    └── fog\
        ├── fog.dll         loaded by full path (lesson 4.02)
        └── noise.dll       found with LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR

Before shipping, check the result on a clean machine (a fresh virtual machine is ideal): run dumpbin /dependents on every binary (lesson 1.06), confirm each listed DLL is either part of Windows, installed by the redistributable, or in your folder.

Side-by-side assemblies, briefly

Older Windows software uses manifests to bind a program to an exact version of a shared DLL in C:\Windows\WinSxS. You still meet them for one purpose: telling Windows to use version 6 of the common controls (modern-looking buttons) in a Win32 program. For your own DLLs, the app-local layout above is simpler and is what nearly every modern program does.

Common mistakes

Forgetting to increase the file version

An installer that compares versions may then refuse to replace an older file with yours.

Copying only some runtime DLLs

msvcp140.dll without vcruntime140_1.dll fails on machines without the redistributable. Use the installer, or copy the whole set from the Visual Studio redist folder.
