How Text Gets on the Screen

lesson 3.022 of 5 in milestone 35 min1 practice task

When a program prints "Hi", it sends the numbers 72 and 105 to the operating system. A terminal turns each number into a character, looks up its shape in a font, and the shape becomes lit pixels. The screen is just a grid of numbers too.

What "print" really sends

When a Python program runs print("Hi"), no letters travel anywhere. What leaves the program is a few bytes:

Byte 72 105 10
Hex 0x48 0x69 0x0A
Meaning in UTF-8 H i new line

print adds the new line (10) at the end by itself. These three bytes are handed to the operating system with a request: "write these bytes to my standard output". Standard output is usually connected to a window - a terminal, or the console panel in Xenon's editor.

flowchart LR
    P["Your program<br/>print('Hi')"] -->|"bytes 72 105 10"| OS["Operating system<br/>a write request"]
    OS --> T["Terminal program"]
    T -->|"look up 'H' in a font"| F["Glyph shapes"]
    F -->|"pixels"| S["Screen"]

You will see this request close up in the Assembly course: a program puts the address of its bytes and their count in two registers, puts the number 1 ("write") in another, and executes the syscall instruction. Every print in every language ends up there (lesson 5.06 follows it all the way).

From number to shape: fonts

The terminal receives 72. It knows (because it treats the bytes as UTF-8) that 72 means H. To show it, it looks up H in a font: a file of shapes, one per character, called glyphs.

Early computers used bitmap fonts: each character is a small grid of pixels, on or off. Here is a letter on a 5-wide, 7-tall grid, with each row stored as 5 bits:

Output
row   bits    shown
 1    10001   #...#
 2    10001   #...#
 3    10001   #...#
 4    11111   #####
 5    10001   #...#
 6    10001   #...#
 7    10001   #...#

The whole letter H is just seven small numbers: 17, 17, 17, 31, 17, 17, 17. Drawing it means turning each 1 into a lit pixel. You will do exactly this in this lesson's practice, and use it to print big banners in the milestone project.

Modern fonts are outline fonts (TrueType, OpenType): each glyph is described by curves, so it stays sharp at any size, and is turned into pixels when needed, with smoothing at the edges. But the idea is the same: a character number is turned into a picture.

The screen is numbers too

A screen is a grid of pixels. A 1920 × 1080 screen has 2,073,600 of them. Each pixel's colour is three numbers - red, green and blue - usually one byte each (lesson 3.04). The computer keeps the whole picture in memory, in a framebuffer, and about 60 times a second (or more) sends it to the screen.

So "printing H" ends as: a few dozen numbers in the framebuffer change from the background colour to the text colour. From your print("Hi") to the glass, it is numbers all the way.

Control characters

Some character numbers are not shown at all: they tell the terminal what to do.

Byte Name Written as Effect
10 Line feed \n Move to the start of the next line (on Linux and macOS)
13 Carriage return \r Move back to the start of this line. Windows ends lines with \r\n
9 Tab \t Jump to the next tab stop
8 Backspace \b Move back one
7 Bell \a Beep
27 Escape \x1b Starts an escape sequence: \x1b[31m makes the following text red

\r and \n come from typewriters, where "carriage return" slid the paper back to the left and "line feed" turned it up one line. Progress bars that update in place in a terminal work by printing \r and writing the line again over the old one.
