One Line of Code All the Way Down

lesson 5.066 of 6 in milestone 55 min1 practice task

Follow print("Hi") from Python down through the interpreter's bytecode, the C code of the interpreter, the C library, a system call into the operating system, the terminal, a font and the framebuffer, to lit pixels - every layer of this course in one journey.

The journey

Take one line:

Python
print("Hi")

Here is everything that happens when it runs, layer by layer. Each step points to the lesson that explained it.

flowchart TB
    A["1. Python source<br/>print('Hi')"] --> B["2. Bytecode<br/>LOAD_NAME print, LOAD_CONST 'Hi', CALL"]
    B --> C["3. The interpreter, written in C,<br/>executes each bytecode instruction"]
    C --> D["4. Text to bytes:<br/>'Hi' + newline becomes 72 105 10 (UTF-8)"]
    D --> E["5. The C library's write()<br/>puts the request in registers"]
    E --> F["6. syscall: the CPU switches<br/>into the operating system"]
    F --> G["7. The kernel passes the bytes<br/>to the terminal program"]
    G --> H["8. The terminal looks up H and i<br/>in a font"]
    H --> I["9. Pixels change in the framebuffer;<br/>the screen shows Hi"]

1. Source code

print("Hi") is just text: the bytes 70 72 69 6E 74 28 22 48 69 22 29 in a file or in the editor (3.01).

2. Bytecode

Python compiles the line to bytecode (5.03) for its virtual machine:

Output
LOAD_NAME     print
LOAD_CONST    'Hi'
CALL          1

Three instructions for an imaginary computer, like the tiny computer of 4.04.

3. The interpreter

The Python interpreter (CPython) is a program written in C (5.04), compiled to machine code for your CPU (4.05). Its core is a loop: fetch the next bytecode instruction, decode it, and run the C code for it. For CALL, it finds that print is a built-in function, itself written in C.

4. Text becomes bytes

print turns the string into bytes using UTF-8 (3.01) and adds the line ending: 72, 105, 10. Strings inside Python are objects in memory (4.03) with a length and the characters; now they are a plain row of bytes in a buffer.

5. The C library

print eventually calls the C library's write function, asking to write 3 bytes to file descriptor 1, standard output. On Linux x86-64, write comes down to a few machine instructions that set up registers:

Assembly
        mov     eax, 1          ; the number of the "write" system call
        mov     edi, 1          ; file descriptor 1: standard output
        lea     rsi, [rel buf]  ; the address of the bytes
        mov     edx, 3          ; how many bytes
        syscall                 ; into the kernel

These are the same lines the Assembly course starts with.

6. The system call

syscall is a special instruction (bytes 0F 05, 4.05). It makes the CPU switch from the program's restricted user mode into the operating system's kernel mode (6.04), and jump into the kernel's code. The program cannot touch the screen or the disk itself; it must ask.

7. The kernel

The kernel checks the request (is file descriptor 1 really open? is the address really this program's memory?) and copies the 3 bytes to wherever standard output goes: here, a terminal program, through a pipe or a pseudo-terminal device. Then it returns to Python, with the number of bytes written in register rax.

8. The terminal and the font

The terminal program reads the bytes, decodes 72 as H and 105 as i, and treats 10 as "new line" (3.02). For each character it looks up the glyph in its font and renders it to pixels at the right size, smoothing the edges.

9. Pixels

The glyph pixels are written into the window's part of the framebuffer (3.02): a few hundred numbers change from the background colour to the text colour (3.04). The graphics hardware sends the framebuffer to the screen about 60 times a second, and light comes out of the right pixels: Hi.

Billions of switches for two letters

Every step above is machine code running on the CPU: fetch, decode, execute (4.04), with the ALU built from gates (4.02), gates from transistors (1.04), working on bits (2.01). Thousands of instructions and billions of transistor switchings for two letters, in a few microseconds.

That is the point of layers: you write one line, and each layer below does its part without you having to think about it. Knowing the layers is what lets you understand the surprises: a crash, a slow program, a wrong character, a number that overflows.
