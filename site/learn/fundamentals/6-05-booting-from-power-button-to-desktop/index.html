Booting: From Power Button to Desktop

lesson 6.055 of 6 in milestone 65 min1 practice task

When the power comes on, the CPU starts running firmware from a chip on the motherboard (UEFI, once BIOS), which checks the hardware and loads a boot loader from the disk. The boot loader loads the kernel, the kernel starts its drivers and the first process, and that process starts everything else, ending with the login screen.

The chicken-and-egg problem

The operating system lives on the disk. Reading the disk needs a program. But when the power comes on, RAM is empty: there is no program yet. How does a computer start?

The answer is a chain of small programs, each loading a bigger one. This is called booting, from "pulling yourself up by your bootstraps".

1. Firmware

The CPU is built to start fetching instructions from one fixed address when it powers on. That address is wired to a small flash memory chip on the motherboard that holds the firmware: on PCs since about 2010, UEFI; before that, the BIOS (from the original IBM PC).

The firmware:

  • tests the hardware (the POST, power-on self test: is there RAM? a keyboard?);
  • sets up the essentials: memory, the clock, the CPU's settings;
  • finds a disk to boot from, in the order set in its settings;
  • loads the boot loader from that disk into RAM and jumps to it.

With Secure Boot, UEFI checks that the boot loader is digitally signed by a trusted maker before running it, so malware cannot slip in before the operating system starts.

2. The boot loader

The boot loader is a small program whose job is to find the kernel and load it. Examples: Windows Boot Manager, GRUB (Linux), and Apple's iBoot. It may show a menu to choose between operating systems. It reads the kernel file from the file system into RAM, along with a small starter set of drivers, and jumps to the kernel's first instruction.

3. The kernel starts

The kernel now takes over the machine:

  • switches the CPU into its full 64-bit mode and sets up virtual memory (6.03);
  • starts its drivers and detects devices;
  • mounts the main file system (makes the disk's files reachable);
  • starts the scheduler (6.02);
  • starts the first user-mode process.

4. The first process

On Linux the first process has PID 1: usually systemd (or the older init). Every other process on the system descends from it, through fork and execve (6.04). It starts the background services - networking, sound, printing, logging - and finally the login screen. Windows does the same with its Session Manager and Winlogon.

5. Login and desktop

You log in; the system starts your desktop (Explorer on Windows, Finder and the Dock on macOS, GNOME or KDE on Linux) and your startup apps. From power button to desktop, on a modern computer with an SSD, takes about 10 to 20 seconds.

Sleep, hibernate, shut down

What happens Starting again
Sleep RAM stays powered and keeps everything; the rest switches off Instant: everything is still in RAM
Hibernate RAM's contents are written to the disk, then the power goes off Slower: RAM is reloaded from the disk
Shut down Programs are closed, files saved, power off A full boot
Phones boot the same way

A phone has its own firmware and boot loader (with signature checks at every step, so only the maker's software can run), then a Linux kernel (Android) or Apple's XNU kernel (iOS), then the first process and the home screen.
