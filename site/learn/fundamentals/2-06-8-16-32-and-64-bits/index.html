8, 16, 32 and 64 Bits

lesson 2.066 of 6 in milestone 26 min1 practice task

The sizes you hear about - 8-bit, 16-bit, 32-bit, 64-bit - are how many bits a number takes. They decide the largest number that fits and, for a processor, how much memory it can address. 32-bit addresses reach 4 GB, which is why computers moved to 64-bit. Byte order (endianness) decides which byte of a number comes first in memory.

The usual sizes

Numbers in a program are stored in a fixed number of bits, almost always 8, 16, 32 or 64:

Bits Bytes Unsigned range Signed range Typical use
8 1 0 to 255 −128 to 127 a character, a byte of a file, one colour channel
16 2 0 to 65,535 −32,768 to 32,767 old games' scores, audio samples (CD quality)
32 4 0 to about 4.29 billion about ±2.1 billion the usual int in C, C++, Java and C#
64 8 0 to about 18.4 quintillion about ±9.2 quintillion big counts, file sizes, times, memory addresses

The pattern: n bits hold 2ⁿ values. Unsigned uses all of them for 0 and up: 0 to 2ⁿ − 1. Signed gives half to negatives: −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1.

Formula For 16 bits
Unsigned max 2ⁿ − 1 65,535
Signed min −2ⁿ⁻¹ −32,768
Signed max 2ⁿ⁻¹ − 1 32,767

In C you choose these sizes yourself (uint8_t, int32_t, int64_t); Python hides them and lets integers grow as big as memory allows, which is why 2 ** 100 just works in Python but overflows in C.

What "a 64-bit processor" means

When a processor is called 8-, 16-, 32- or 64-bit, it means its registers (the few very fast storage slots inside the CPU, lesson 4.04) hold that many bits. That decides two things:

  1. How big a number it handles in one step. A 64-bit CPU adds two 64-bit numbers in one instruction; an 8-bit CPU needs several steps for anything above 255.
  2. How much memory it can point at. Each byte of memory has a numbered address. With 32-bit addresses there are 2³² = 4,294,967,296 possible addresses: 4 GiB, and not one byte more.
Era CPU bits Example Memory it could address
1970s-80s 8 Apple II, Commodore 64, NES 64 KiB (with 16-bit addresses)
1980s 16 IBM PC's 8086 1 MiB (with tricks)
1990s-2000s 32 Windows 95 to XP PCs 4 GiB
2000s to now 64 every PC and phone today 2⁶⁴ bytes: 16 billion GiB (in practice, chips use 48 to 57 bits)

The 4 GiB ceiling is why PCs moved to 64-bit around 2005-2010: as RAM got cheaper, 4 GiB was not enough. A 32-bit version of Windows could not use more than about 4 GB of RAM no matter how much was installed.

Game consoles and "bits"

In the 1990s consoles were advertised by bits: the NES was 8-bit, the Super Nintendo and Mega Drive 16-bit, the Nintendo 64 - as the name says - 64-bit. The number was the CPU's register size, and it became a marketing word for "newer and better".

The year 2038 problem

Many systems store time as the number of seconds since 1 January 1970, in a signed 32-bit number. Its largest value, 2,147,483,647 seconds, is reached at 03:14:07 UTC on 19 January 2038. One second later it overflows to the most negative number, which reads as December 1901. Modern systems use 64-bit times, which last for 292 billion years, but old embedded devices may still fail in 2038.

Byte order: which byte comes first?

A 32-bit number takes 4 bytes in memory. Which one goes first?

0x12345678 is made of the bytes 12, 34, 56, 78:

Order Memory (lowest address first) Used by
Little-endian 78 56 34 12: lowest byte first x86 and x86-64 PCs, ARM in practice (phones, Apple-chip Macs)
Big-endian 12 34 56 78: highest byte first, as we write it network protocols ("network byte order"), some file formats, old Macs

Switch the order in the demo. The number is the same; only the arrangement of its bytes in memory changes. It matters whenever bytes go between machines or into a file: read a big-endian number as little-endian and you get nonsense. The names come from Gulliver's Travels, where two nations fought over which end of a boiled egg to crack.
