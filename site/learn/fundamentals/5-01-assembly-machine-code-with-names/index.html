Assembly: Machine Code with Names

lesson 5.011 of 6 in milestone 55 min2 practice tasks

Assembly language writes each machine instruction as a short name - mov, add, jmp - with labels instead of addresses. An assembler translates it, almost one line to one instruction, into machine code. So assembly is not binary, but it is the thinnest possible layer over it, different for every CPU family.

Is assembly just binary?

Not quite, but almost. Assembly language is machine code written so that people can read it:

Machine code (hex) Assembly Meaning
B8 2A 00 00 00 mov eax, 42 put 42 into register eax
01 D8 add eax, ebx eax = eax + ebx
C3 ret return

Each line of assembly is (nearly always) exactly one machine instruction. Nothing is added, nothing is hidden: you choose every register and every instruction yourself. The names are called mnemonics (memory aids): mov for move, jmp for jump, cmp for compare.

A program called an assembler reads the text and writes the bytes. It is a translator, but a very direct one - closer to looking words up in a dictionary than to understanding sentences.

What the assembler does for you

Besides turning names into numbers, an assembler handles the jobs that make raw machine code miserable (4.05):

  • Labels: you write loop: before an instruction and jmp loop elsewhere; the assembler works out the address. Add an instruction in the middle and it recalculates every address for you.
  • Data: message: db "Hello", 10 puts those bytes in the program and lets you refer to them by name.
  • Constants and comments: length equ 6, and anything after ; is a note for people.

Here is the tiny computer's countdown from 4.04 in an assembly language for that machine, and the numbers an assembler would produce:

Output
        LOAD  counter      ; cell 0: 106
top:    JUMPZ done         ; cell 1: 605
        SUB   one          ; cell 2: 307
        STORE counter      ; cell 3: 406
        JUMP  top          ; cell 4: 501
done:   HALT               ; cell 5: 000
counter: 3                 ; cell 6: the number 3
one:     1                 ; cell 7: the number 1

top, done, counter and one are labels; the assembler works out which cell each one names (counter is cell 6, so LOAD counter becomes 106) and puts the data right after the code. You will write exactly this assembler in this milestone's project.

Real x86-64 assembly

A complete Linux program in x86-64 assembly (NASM syntax, as the Assembly course uses) that prints a message and exits:

Assembly
        global  _start
        section .data
message: db     "Hello from assembly", 10    ; the bytes of the text, then a new line
length  equ     $ - message                   ; how many bytes that was

        section .text
_start:
        mov     eax, 1              ; system call 1: write
        mov     edi, 1              ; to standard output
        lea     rsi, [rel message]  ; these bytes
        mov     edx, length         ; this many of them
        syscall                     ; ask the operating system

        mov     eax, 60             ; system call 60: exit
        xor     edi, edi            ; with code 0
        syscall

Press Run: this is real assembly, assembled with NASM and run on a Linux machine. Every line under _start is one instruction. Notice how printing works at this level: there is no print. The program puts the number of the request (1 means "write"), where to write, the address of the bytes and their count into registers, and asks the operating system with syscall (lesson 6.04).

One assembly per CPU family

Because assembly is just machine code with names, there is a different assembly language for every instruction set: x86-64 assembly, ARM64 assembly, RISC-V assembly. The same "add two registers" is:

CPU Assembly
x86-64 add eax, ebx
ARM64 add w0, w0, w1
RISC-V add a0, a0, a1

And even for one CPU there can be several spellings (NASM, GNU, MASM syntax), all producing the same bytes.

Who writes assembly today?

Almost nobody writes whole programs in it any more - compilers (5.03) produce faster code than most people would write by hand. But assembly is still essential for:

  • understanding what a program really does: crashes, performance, security;
  • the first instructions that run when a computer starts (6.05), and parts of operating systems;
  • tight loops in video codecs, cryptography and game engines;
  • reading what a compiler made from your code.
Who wrote the first assembly language?

Kathleen Booth designed an assembly language for the ARC computer in London around 1947. In 1949 David Wheeler's "initial orders" for EDSAC (1.03) let programmers write instructions as letters and decimal numbers, which the machine translated as it loaded them.
