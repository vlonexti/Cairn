Networks and the Internet

lesson 6.066 of 6 in milestone 65 min1 practice task

Computers send data to each other in small packets, each with an address. IP addresses say where a packet goes, TCP makes delivery reliable and in order, and DNS turns names like example.com into addresses. The web is built on top - HTTP requests and responses carried by those packets - and every layer is still bits on wires and radio waves.

Bits between computers

A network sends bits from one computer to another: as voltages on copper wire, flashes of light in fibre-optic cable, or radio waves (Wi-Fi, 4G, 5G). Everything else is agreement about what those bits mean - protocols - in layers, like the rest of the computer.

Packets

Data is not sent as one long stream. It is cut into packets, usually up to about 1,500 bytes, and each packet travels on its own, with a header saying where it is going:

flowchart LR
    A["Your computer"] -->|packets| R1["Home router"] --> ISP["Internet provider"] --> R2["Routers in between"] --> S["Server"]

Packets from one message may take different routes and arrive out of order; the receiving computer puts them back together. If one link fails, packets go around it. This design, from the US ARPANET of 1969, is why the internet keeps working when parts of it break.

The layers

Layer Protocol Job
Link Ethernet, Wi-Fi Get bits to the next device on the same network
Internet IP (Internet Protocol) Get a packet from one computer to another anywhere, using IP addresses
Transport TCP, or UDP TCP: deliver everything, in order, resending what is lost. UDP: fast, no guarantees (games, video calls)
Application HTTP, HTTPS, DNS, email... What the data means

Each layer wraps the one above, like an envelope inside an envelope: an HTTP request goes inside TCP segments, inside IP packets, inside Wi-Fi frames.

Addresses

  • An IPv4 address is a 32-bit number, written as four bytes in decimal: 93.184.215.14. 32 bits is only about 4.3 billion addresses (2.06!) - not enough for every device on Earth, which is why home routers share one public address between all the devices behind them.
  • An IPv6 address is a 128-bit number, written in hex: 2606:2800:21f:cb07:6820:80da:af6b:8b2c. 2¹²⁸ is about 3.4 × 10³⁸, enough to never run out.
  • A port number (16 bits, 0 to 65,535) says which program on the computer the data is for: 443 for HTTPS, 80 for HTTP, 22 for SSH.

DNS: names to numbers

People remember names, computers need numbers. The Domain Name System (DNS) is the internet's phone book: your computer asks a DNS server "what is the address of example.com?" and gets back an IP address. Then it connects to that address.

The web

When you open a web page:

  1. DNS turns the name into an IP address.
  2. Your browser opens a TCP connection to that address, port 443, and sets up TLS encryption (the S in HTTPS: nobody in between can read or change the data).
  3. It sends an HTTP request: plain text like GET /index.html HTTP/1.1 plus some headers.
  4. The server sends an HTTP response: a status (200 OK, or 404 Not Found), headers, and the bytes of the page.
  5. The browser reads the HTML, asks for each picture, style sheet and script the same way, and draws the page.

The World Wide Web - pages, links and HTTP - was invented by Tim Berners-Lee at CERN in 1989-91, on top of an internet that had existed for twenty years.

How it all fits

That web page is text (3.01) and pictures (3.04), in files (3.05), sent by a server's operating system (6.01) through system calls (6.04), cut into packets of bits (2.01), carried by electricity, light and radio, reassembled by your kernel, handed to your browser - a process (6.02) in its own virtual memory (6.03) - whose code, compiled from C++ (5.05) into machine code (4.05), runs fetch, decode, execute (4.04) on gates (4.01) made from transistors (1.04).
