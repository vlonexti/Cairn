Machine Code

lesson 4.055 of 6 in milestone 45 min1 practice task

Machine code is a program as the CPU reads it - instructions encoded as bytes. On x86-64, mov eax, 42 is the five bytes B8 2A 00 00 00 and ret is C3. Each CPU family has its own encoding, which is why programs are built separately for each, and why nobody writes machine code by hand.

Instructions are numbers

In the tiny computer of 4.04, LOAD 10 was the number 110. Real CPUs work the same way: each instruction is encoded as bytes, and a program is a long row of them in memory. That row of bytes is machine code: the only language a CPU actually understands.

Here are some real x86-64 instructions and their bytes:

Bytes (hex) Instruction Meaning
B8 2A 00 00 00 mov eax, 42 put 42 into register eax
01 D8 add eax, ebx eax = eax + ebx
31 C0 xor eax, eax eax = eax XOR eax, which is always 0: the shortest way to set a register to zero
FF C0 inc eax eax = eax + 1
C3 ret return from a function
90 nop do nothing
0F 05 syscall ask the operating system to do something (print, open a file, exit)

Look at the first one closely:

Output
B8          2A 00 00 00
|           |
|           the number 42 (0x2A), as 4 bytes, little-endian (2.06)
"mov a 32-bit number into eax"

B8 is the operation and register; the next four bytes are the value, lowest byte first. Change 2A to 07 and the instruction puts 7 into eax instead. B9 instead of B8 means "into ecx" - the register is encoded in the low bits of the first byte.

Different CPUs, different machine code

Each CPU family has its own instruction set and its own encoding (1.05). The same idea - "return from this function" - is:

CPU family Bytes of "return"
x86 and x86-64 C3 (1 byte)
ARM64 C0 03 5F D6 (always 4 bytes)
RISC-V 67 80 00 00
6502 (Apple II, NES) 60

x86 instructions are variable length, from 1 to 15 bytes, a result of growing for 45 years since the 8086. ARM64 instructions are all exactly 4 bytes, which makes them simpler to decode. This is why a program must be built (translated to machine code) separately for each family, and why Apple had to add a translator called Rosetta when Macs moved from x86 to ARM.

Seeing machine code

Every program you have ever run is machine code. You can look at it:

  • A disassembler turns machine code bytes back into readable instructions (objdump -d on Linux, or the disassembly view of a debugger).
  • Compiler Explorer (godbolt.org, which also runs the code on this site) shows the instructions a compiler makes from C, C++, Rust and others, line by line.

A tiny C function and what it becomes:

C
int add(int a, int b)
{
    return a + b;
}
Output
add:
    8D 04 37        lea eax, [rdi + rsi]    ; eax = a + b  (a arrives in rdi, b in rsi)
    C3              ret                     ; return; the answer is in eax

Five bytes. The lea instruction is meant for working out addresses, but compilers use it as a quick way to add two registers into a third.

Why nobody writes machine code

You could write programs as raw bytes, and in the 1940s people did, setting switches or punching cards. But:

  • the numbers mean nothing to a person: B8 2A 00 00 00 is unreadable;
  • adding one instruction in the middle moves everything after it, so every jump address has to be recalculated by hand;
  • one wrong bit and the CPU does something entirely different.

The first fix, around 1947 to 1949, was to write instructions as short names and let a program translate them into the numbers. That program is an assembler, and the names are assembly language - the subject of the next milestone's first lesson, and of the Assembly course.
