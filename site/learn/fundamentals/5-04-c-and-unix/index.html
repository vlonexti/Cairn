C and Unix

lesson 5.044 of 6 in milestone 55 min1 practice task

At Bell Labs between 1969 and 1973, Ken Thompson and Dennis Ritchie built Unix and the C language together. C is close enough to the machine to write an operating system in, yet portable between computers. Unix's ideas and C's syntax shaped nearly every system and language since, including Linux, macOS, Android, Windows and C++.

The problem: operating systems in assembly

By the late 1960s, programs were written in high-level languages, but operating systems (milestone 6) were still written in assembly, because they need to control hardware directly and run as fast as possible. That meant an operating system was tied to one kind of computer forever.

Unix (1969)

At Bell Labs in 1969, Ken Thompson and Dennis Ritchie started a small operating system on a spare PDP-7 minicomputer. They called it Unix. Its ideas were simple and powerful:

  • Everything is a file: documents, devices (the keyboard, the screen, a disk) and connections are all read and written the same way.
  • Small programs that do one thing well, combined with pipes: ls | sort | head sends one program's output into the next.
  • Plain text for settings and data, so any program can read it.
  • A hierarchy of folders starting at /.

From B to C (1969-1973)

Thompson wrote a small language called B (from Martin Richards' BCPL). B had no types: everything was one machine word. On the newer PDP-11, which had bytes and different-sized numbers, that did not fit, so Dennis Ritchie extended B into C (1972), with types like char, int and pointers.

Then in 1973 they did something new: they rewrote the Unix kernel in C. An operating system written in a high-level language. To move Unix to a different computer, you only needed a C compiler for it and a small amount of assembly - and Unix spread to computers everywhere.

C
#include <stdio.h>

int main(void)
{
    printf("hello, world\n");
    return 0;
}

This program, from Kernighan and Ritchie's book The C Programming Language (1978), is why nearly every programming tutorial since starts with "hello, world".

Why C took over

C sits in a sweet spot:

Close to the machine But portable
Direct access to memory through pointers (an address is just a number, 4.03) The same C source compiles for x86, ARM, RISC-V...
No hidden costs: one line of C becomes a few instructions you can predict Readable structure: functions, if, loops, blocks
You manage memory yourself Standardised (ANSI C, 1989)

That is why C is called a "portable assembly". Today it is still the language of operating system kernels (Linux, the core of Windows and macOS), device drivers, embedded chips, databases, and the interpreters of other languages: Python's main interpreter is written in C.

The cost of C's power is that mistakes are easy and dangerous: reading past the end of an array or using freed memory is not caught, and can crash the program or open security holes. Newer languages such as Rust try to keep C's speed while catching those mistakes.

The family of Unix

flowchart TB
    U["Unix, Bell Labs (1969)"] --> BSD["BSD Unix (Berkeley, 1977)"]
    U --> SV["System V and commercial Unix"]
    BSD --> FB["FreeBSD and others"]
    BSD --> NX["NeXTSTEP (1989)"] --> MAC["macOS and iOS (2001, 2007)"]
    MIN["MINIX (1987)"] -.inspired.-> LIN["Linux (Linus Torvalds, 1991)"]
    LIN --> AND["Android (2008)"]
    LIN --> SRV["Most servers, supercomputers, Chromebooks"]

Linux, started by Linus Torvalds as a student in 1991, is a Unix-like kernel written from scratch in C. With the GNU project's tools it became a complete system, and today it runs most of the world's servers, all of the top 500 supercomputers, and (inside Android) most phones. macOS and iOS descend from BSD Unix. Windows is not Unix, but its command line, programming tools and file paths borrowed many Unix ideas, and it can run Linux programs through WSL.

C's syntax spread just as far: C++, Java, JavaScript, C#, Go and Rust all use its braces, semicolons, if (...), for and return.
