Text: ASCII and Unicode

lesson 3.011 of 5 in milestone 36 min2 practice tasks

A computer stores text as numbers - one number per character, from an agreed table. ASCII (1963) gave the 128 characters of English one byte each. Unicode gives every character of every language, and emoji, a number, and UTF-8 stores those numbers in one to four bytes while staying compatible with ASCII.

Letters are numbers

A computer has no idea what a letter is. It only stores numbers. So to store text, everyone agrees on a table: A is 65, B is 66, ... Store 72, 105 and the program that reads them, knowing they are text, shows "Hi".

That table is called a character set or encoding, and the most important one for decades was ASCII.

ASCII (1963)

ASCII (American Standard Code for Information Interchange) gives a number from 0 to 127 to every character on an English typewriter: 7 bits per character, stored in one byte.

Numbers Characters
0 to 31 Control characters, not printed: 9 is Tab, 10 is new line (\n), 13 is carriage return (\r), 7 makes a beep
32 Space
48 to 57 The digits 0 to 9
65 to 90 A to Z
97 to 122 a to z
the rest Punctuation: ! is 33, @ is 64, ~ is 126

The table has some clever touches:

  • The digits are in order, starting at 48 (0x30). So the character '7' is 55, and its digit value is 55 − 48 = 7. Every program that reads numbers from text does this subtraction.
  • Lower case is upper case + 32. A is 65 (0100 0001), a is 97 (0110 0001): they differ in exactly one bit, the one worth 32. Changing case is flipping one bit.

The character '7' is not the number 7

The text "7" is stored as the number 55. Adding the text "7" + "7" in many languages gives "77", not 14. When a program reads a number someone typed, it has to convert the characters to a number first - that is what Python's int("77") does, digit by digit.

The world has more than 128 characters

ASCII has no é, ñ, ü, no Greek, Cyrillic, Arabic, Hindi, Chinese or Japanese, no emoji. In the 1980s and 1990s, every country filled the spare numbers 128 to 255 with its own letters, in dozens of incompatible tables. A file written in one opened as nonsense in another ("mojibake": café shown as cafÃ©).

Unicode (1991)

Unicode fixes this with one enormous table that gives every character in every writing system its own number, called a code point, written U+ and hex:

Character Code point Decimal
A U+0041 65 (the same as ASCII)
é U+00E9 233
Ω U+03A9 937
я U+044F 1103
中 U+4E2D 20013
€ U+20AC 8364
😀 U+1F600 128512

There is room for over a million code points; about 150,000 are used today, and new emoji are added every year.

UTF-8: storing code points as bytes

Unicode numbers go above 255, so they need more than one byte. UTF-8 (designed in 1992 by Ken Thompson and Rob Pike) stores each code point in 1 to 4 bytes:

Code points Bytes First byte starts with
U+0000 to U+007F (ASCII) 1 0
U+0080 to U+07FF (é, Ω, я) 2 110
U+0800 to U+FFFF (中, €) 3 1110
U+10000 and up (😀) 4 11110

Every following byte starts with 10. So a program can always tell where a character begins.

UTF-8's great trick is backward compatibility: any ASCII text is already valid UTF-8, byte for byte. That is why it won: today about 98% of web pages are UTF-8, and it is the default in Python, Rust, Go and Linux.

Length is tricky

"How long is this text?" has several answers. "é😀" is 2 characters, but 6 bytes in UTF-8. Python's len() counts code points; C's strlen() counts bytes. Some "single" emoji, such as a family or a flag, are even several code points shown as one picture.
