Insertion and Selection Sort

lesson 3.011 of 5 in milestone 36 min1 practice task

The simple quadratic sorts and what they teach - selection sort, insertion sort and why it is fast on nearly sorted data, inversions as a measure of disorder, stability, sorting in place, comparators and strict weak ordering, and why real libraries still use insertion sort for small pieces.

Why study slow sorts?

std::sort is already in the library, and you will rarely write a sort for real. But sorting is the best laboratory for algorithm design: the same problem solved in a dozen ways, each showing a different idea. The simple sorts are also genuinely useful on small or nearly sorted inputs.

Every sort in this milestone puts a sequence into non-decreasing order according to a comparison, by default <.

Selection sort

Find the smallest element and swap it to the front; then find the smallest of the rest and swap it into position 1; and so on.

C++
#include <iostream>
#include <utility>
#include <vector>

void selectionSort(std::vector<int>& a)
{
    for (std::size_t i = 0; i + 1 < a.size(); ++i)
    {
        std::size_t smallest = i;
        for (std::size_t j = i + 1; j < a.size(); ++j)
            if (a[j] < a[smallest]) smallest = j;
        std::swap(a[i], a[smallest]);
    }
}

int main()
{
    std::vector<int> a{ 29, 10, 14, 37, 13 };
    selectionSort(a);
    for (int x : a) std::cout << x << ' ';
    std::cout << '\n';
}

It always makes about n²/2 comparisons, whatever the input, so it is Θ(n²). Its one virtue: it does at most n − 1 swaps, which matters only when moving elements is very expensive.

Insertion sort

Insertion sort works the way people sort a hand of cards: take the next card and slide it left past every bigger card, into its place among the already-sorted ones.

C++
#include <iostream>
#include <vector>

void insertionSort(std::vector<int>& a)
{
    for (std::size_t i = 1; i < a.size(); ++i)
    {
        int value = a[i];
        std::size_t j = i;
        while (j > 0 && a[j - 1] > value)        // shift bigger elements one place right
        {
            a[j] = a[j - 1];
            --j;
        }
        a[j] = value;
    }
}

int main()
{
    std::vector<int> a{ 5, 2, 4, 6, 1, 3 };
    insertionSort(a);
    for (int x : a) std::cout << x << ' ';
    std::cout << '\n';
}

The invariant: before step i, the elements a[0..i) are sorted. Each step inserts a[i] into that sorted prefix, so after the last step everything is sorted.

Inversions: why insertion sort is adaptive

An inversion is a pair of positions i < j with a[i] > a[j]: two elements in the wrong order relative to each other. A sorted array has 0 inversions; a reversed one has n(n−1)/2, the most possible.

Each shift in insertion sort fixes exactly one inversion, so insertion sort does n + (number of inversions) steps. That makes it:

  • O(n²) in the worst case (reversed input),
  • O(n) on sorted input,
  • very fast on nearly sorted input, where few elements are out of place.

It is adaptive: it does less work on easier inputs. Selection sort is not.

C++
#include <iostream>
#include <vector>

long long shifts = 0;

void insertionSort(std::vector<int>& a)
{
    for (std::size_t i = 1; i < a.size(); ++i)
    {
        int value = a[i];
        std::size_t j = i;
        while (j > 0 && a[j - 1] > value) { a[j] = a[j - 1]; --j; ++shifts; }
        a[j] = value;
    }
}

int main()
{
    const int n = 2000;
    std::vector<int> sorted(n), reversed(n), nearly(n);
    for (int i = 0; i < n; ++i) { sorted[i] = i; reversed[i] = n - i; nearly[i] = i; }
    for (int i = 0; i + 1 < n; i += 50) std::swap(nearly[i], nearly[i + 1]);   // a few neighbours swapped

    for (auto [name, v] : { std::pair{ "sorted", sorted }, std::pair{ "nearly sorted", nearly }, std::pair{ "reversed", reversed } })
    {
        shifts = 0;
        insertionSort(v);
        std::cout << name << ": " << shifts << " shifts\n";
    }
}

Stability

A sort is stable if elements that compare equal keep their original relative order. That matters when you sort records by one key after another: sort people by name, then stably by age, and people of the same age stay in name order.

Insertion sort is stable (it stops at an equal element, never passing it). Selection sort is not: its long-distance swaps can jump an element over an equal one. std::sort is not stable either; std::stable_sort is.

C++
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

struct Person { std::string name; int age; };

int main()
{
    std::vector<Person> people{ { "Dana", 30 }, { "Ali", 25 }, { "Cy", 30 }, { "Bo", 25 }, { "Eve", 30 } };
    std::sort(people.begin(), people.end(), [](const Person& a, const Person& b) { return a.name < b.name; });
    std::stable_sort(people.begin(), people.end(), [](const Person& a, const Person& b) { return a.age < b.age; });
    for (const auto& p : people) std::cout << p.age << ' ' << p.name << '\n';
}

In place

A sort is in place if it needs only O(1) extra memory (or O(log n) for recursion). Both simple sorts are in place. Merge sort, next lesson, is not: it needs a buffer of n elements.

Comparators and strict weak ordering

Sorting with a custom comparison needs a function less(a, b) that behaves like <:

  • irreflexive: less(a, a) is false,
  • transitive: less(a, b) and less(b, c) imply less(a, c),
  • incomparability is transitive too: if neither a < b nor b < a, the two are "equivalent", and equivalence must be transitive.

This is a strict weak ordering. Breaking it, most commonly by using <= instead of <, is undefined behaviour in std::sort: real implementations can read past the end of the array and crash. Always compare with a strict <, and compare several keys with std::tie:

C++
std::sort(v.begin(), v.end(), [](const Person& a, const Person& b) {
    return std::tie(a.age, a.name) < std::tie(b.age, b.name);     // by age, then by name
});

Small inputs: insertion sort wins

For a handful of elements, insertion sort's tiny constant factor and simple, cache-friendly loop beat the O(n log n) sorts. That is why std::sort (introsort, lesson 3.03) and Python's Timsort switch to insertion sort for pieces smaller than about 16 to 32 elements.

Summary

  • Selection sort is always Θ(n²) but makes few swaps; insertion sort is O(n + inversions).
  • Insertion sort is adaptive, stable and in place, and the best choice for tiny or nearly sorted inputs.
  • Stable sorts keep equal elements in order, which lets you sort by several keys in passes.
  • Comparators must be strict weak orderings: use <, and std::tie for several keys.
