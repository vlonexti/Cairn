Depth-First Search and Topological Order

lesson 5.022 of 5 in milestone 57 min1 practice task

Going deep first - depth-first search recursively and with an explicit stack, discovery and finish order, finding cycles in directed graphs with three colours, directed acyclic graphs, topological sorting by DFS finish times and by Kahn's algorithm, using topological order for build systems, course prerequisites and longest paths, and a pointer to strongly connected components.

Depth-first search

Depth-first search (DFS) follows one path as far as it can, then backtracks to the most recent vertex that still has an unexplored edge. It is the natural way to explore a maze by hand: keep going until a dead end, then go back to the last junction.

Recursively, DFS is a few lines:

C++
#include <iostream>
#include <vector>

void dfs(int u, const std::vector<std::vector<int>>& adj, std::vector<bool>& seen, std::vector<int>& order)
{
    seen[u] = true;
    order.push_back(u);
    for (int v : adj[u])
        if (!seen[v]) dfs(v, adj, seen, order);
}

int main()
{
    std::vector<std::vector<int>> adj{ { 1, 2 }, { 3 }, { 3, 4 }, { 5 }, { 5 }, {} };   // directed
    std::vector<bool> seen(adj.size(), false);
    std::vector<int> order;
    dfs(0, adj, seen, order);
    for (int u : order) std::cout << u << ' ';
    std::cout << '\n';
}

Like BFS it is O(V + E). It does not find shortest paths, but the structure of its exploration answers many questions BFS cannot: cycles, topological order, bridges and articulation points, strongly connected components, and backtracking search (lesson 6.05).

The recursion can go V levels deep, which overflows the stack on large graphs (a path of a million vertices). The iterative version uses an explicit stack. A simple form pushes a vertex's neighbours and marks vertices when popped; it visits in a slightly different order from the recursive one, but explores the same vertices.

Discovery and finish

Every vertex gets two moments in a DFS: when it is discovered (first entered) and when it finishes (all its descendants have been explored and the recursion returns). Finishing order is the key to the next two ideas.

Cycles in directed graphs: three colours

In an undirected graph, BFS or union-find detects cycles easily. In a directed graph, "I have seen this vertex before" is not enough: in 0 → 1, 0 → 2, 1 → 2, vertex 2 is reached twice, but there is no cycle. A cycle exists exactly when DFS finds an edge to a vertex that is still on the current path (discovered but not finished). Track three states:

  • white: not discovered yet,
  • grey: discovered, still being explored (on the recursion stack),
  • black: finished.

An edge to a grey vertex is a back edge: a cycle.

C++
#include <iostream>
#include <vector>

enum Colour { White, Grey, Black };

bool hasCycle(int u, const std::vector<std::vector<int>>& adj, std::vector<Colour>& colour)
{
    colour[u] = Grey;
    for (int v : adj[u])
    {
        if (colour[v] == Grey) return true;                       // back edge
        if (colour[v] == White && hasCycle(v, adj, colour)) return true;
    }
    colour[u] = Black;
    return false;
}

bool hasCycle(const std::vector<std::vector<int>>& adj)
{
    std::vector<Colour> colour(adj.size(), White);
    for (std::size_t u = 0; u < adj.size(); ++u)
        if (colour[u] == White && hasCycle(static_cast<int>(u), adj, colour)) return true;
    return false;
}

int main()
{
    std::cout << "diamond: " << hasCycle({ { 1, 2 }, { 2 }, {} }) << '\n';
    std::cout << "loop:    " << hasCycle({ { 1 }, { 2 }, { 0 } }) << '\n';
}

Topological order

A directed graph with no cycles is a DAG (directed acyclic graph). DAGs describe dependencies: "compile util.cpp before linking", "take Algorithms before Compilers", "put on socks before shoes". A topological order lists the vertices so that every edge points forward: u comes before v for every edge u → v. Every DAG has at least one; a graph with a cycle has none.

By DFS: a vertex finishes only after everything reachable from it has finished. So listing vertices in reverse finishing order puts every vertex before everything it points to.

By Kahn's algorithm: count each vertex's in-degree (incoming edges). Vertices with in-degree 0 have no prerequisites, so they can go first. Output one, remove its outgoing edges (decrementing the in-degrees of its neighbours), and repeat with whatever reaches in-degree 0. If vertices remain that never reach 0, the graph has a cycle.

C++
#include <iostream>
#include <queue>
#include <string>
#include <vector>

int main()
{
    std::vector<std::string> task{ "fetch", "configure", "compile", "test", "package", "docs" };
    std::vector<std::vector<int>> adj(6);
    auto before = [&](int a, int b) { adj[a].push_back(b); };
    before(0, 1); before(1, 2); before(2, 3); before(2, 4); before(3, 4); before(0, 5); before(5, 4);

    std::vector<int> indegree(6, 0);
    for (const auto& out : adj)
        for (int v : out) ++indegree[v];

    std::queue<int> ready;
    for (int u = 0; u < 6; ++u)
        if (indegree[u] == 0) ready.push(u);

    std::vector<int> order;
    while (!ready.empty())
    {
        int u = ready.front();
        ready.pop();
        order.push_back(u);
        for (int v : adj[u])
            if (--indegree[v] == 0) ready.push(v);
    }

    if (order.size() < adj.size()) std::cout << "there is a cycle\n";
    for (int u : order) std::cout << task[u] << ' ';
    std::cout << '\n';
}

Kahn's algorithm is O(V + E), easy to make iterative, and naturally reports cycles. Replacing the queue with a min-heap gives the lexicographically smallest topological order, useful when the output must be deterministic (practice 5.02).

What topological order unlocks

Processing vertices in topological order means every vertex is handled after all its predecessors. That turns several hard problems on general graphs into easy one-pass problems on DAGs:

  • Shortest and longest paths in O(V + E): relax each vertex's outgoing edges in topological order. Longest path is NP-hard in general graphs but linear in a DAG; it gives the critical path of a project plan (the minimum time to finish all tasks when independent tasks run in parallel).
  • Counting paths: the number of paths to v is the sum over its predecessors.
  • Dynamic programming (lesson 6.02) is, at heart, computing values over a DAG of subproblems in topological order.

Strongly connected components

In a directed graph, a strongly connected component is a maximal set of vertices that can all reach one another. Collapsing each one to a single vertex leaves a DAG. Kosaraju's algorithm finds them with two DFS passes (one on the graph to get finishing order, one on the reversed graph in reverse finishing order); Tarjan's does it in one. They are used to analyse web link structure, find circular dependencies, and solve 2-SAT problems.

Summary

  • DFS goes deep and backtracks; it is O(V + E) and reveals the structure of a graph.
  • Three colours detect cycles in directed graphs: an edge to a grey vertex is a back edge.
  • A DAG has a topological order: reverse DFS finishing order, or Kahn's in-degree algorithm (which also detects cycles).
  • Topological order makes shortest and longest paths, path counting and dynamic programming on DAGs linear.
  • Strongly connected components collapse a directed graph into a DAG.
