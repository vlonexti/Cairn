Choosing a Container

lesson 2.055 of 5 in milestone 26 min1 practice task

Matching the data structure to the job - the costs of the standard containers side by side, ordered versus unordered maps and sets, sorted vectors and flat maps, multisets and multimaps, problems solved by the right container (counting, grouping, first-unique, longest consecutive run), and a checklist for choosing.

The menu

Container Find Insert / erase Ordered? Notes
std::vector (unsorted) O(n) O(1) at the end, O(n) elsewhere no the default for sequences
sorted std::vector O(log n) O(n) yes fastest lookups if the data rarely changes
std::deque O(n) O(1) at both ends no queues

std::flat_map, std::flat_set (C++23) O(log n) O(n) yes sorted vectors with a map interface

Ordered or unordered?

Both kinds of map store key-value pairs. The difference is what else they can do:

  • std::map keeps keys sorted. It can iterate in order, find the smallest or largest key, and answer range questions: every key between a and b, the first key at least x (lower_bound), the key just before x. Every operation is O(log n), guaranteed.
  • std::unordered_map cannot do any of that, but its lookups are expected O(1), and in practice often several times faster.
C++
#include <iostream>
#include <map>
#include <string>

int main()
{
    std::map<int, std::string> events{ { 900, "standup" }, { 1030, "review" }, { 1200, "lunch" }, { 1500, "demo" } };

    auto next = events.lower_bound(1100);                       // the first event at or after 11:00
    std::cout << "next: " << next->first << ' ' << next->second << '\n';

    std::cout << "between 10:00 and 13:00:";
    for (auto it = events.lower_bound(1000); it != events.upper_bound(1300); ++it) std::cout << ' ' << it->second;
    std::cout << '\n';

    std::cout << "first " << events.begin()->second << ", last " << events.rbegin()->second << '\n';
}

Rule of thumb: use unordered_map for pure lookup by key, and map when order or ranges matter or when you need a guaranteed worst case.

Sorted vectors

If the data is built once and then searched many times, a sorted vector with std::lower_bound beats both maps: it is one contiguous block, uses the least memory, and binary search over it is very cache-friendly. C++23's std::flat_map wraps exactly this idea. Inserting into the middle costs O(n), so it suits data that changes rarely.

Sets and multi-containers

  • std::set / std::unordered_set: keys only, each once: "have I seen this?".
  • std::multiset / std::multimap: allow duplicate keys; count(k) and equal_range(k) find them all. A std::multiset is a sorted bag, handy for keeping a sliding window's values in order.

Problems the right container solves

Counting is the most common use of a hash map:

C++
#include <algorithm>
#include <iostream>
#include <sstream>
#include <string>
#include <unordered_map>
#include <vector>

int main()
{
    std::string text = "the cat and the dog and the bird";
    std::unordered_map<std::string, int> counts;
    std::istringstream in(text);
    for (std::string w; in >> w;) ++counts[w];                     // operator[] creates a 0 the first time

    std::vector<std::pair<std::string, int>> sorted(counts.begin(), counts.end());
    std::sort(sorted.begin(), sorted.end(), [](const auto& a, const auto& b) {
        return a.second != b.second ? a.second > b.second : a.first < b.first;
    });
    for (const auto& [word, n] : sorted) std::cout << word << ' ' << n << '\n';
}

Grouping: put each item in the bucket of its key. Anagrams share their sorted letters:

C++
#include <algorithm>
#include <iostream>
#include <map>
#include <string>
#include <vector>

int main()
{
    std::map<std::string, std::vector<std::string>> groups;          // map: groups come out in a fixed order
    for (std::string w : { "listen", "silent", "enlist", "google", "gogole", "cat", "act", "dog" })
    {
        std::string key = w;
        std::sort(key.begin(), key.end());
        groups[key].push_back(w);
    }
    for (const auto& [key, words] : groups)
    {
        for (const auto& w : words) std::cout << w << ' ';
        std::cout << '\n';
    }
}

The longest run of consecutive numbers in an unsorted list, in O(n): put everything in a hash set; a run starts at x only if x − 1 is absent; from each start, count upwards.

C++
#include <iostream>
#include <unordered_set>
#include <vector>

int longestRun(const std::vector<int>& values)
{
    std::unordered_set<int> present(values.begin(), values.end());
    int best = 0;
    for (int x : present)
    {
        if (present.count(x - 1)) continue;                         // not the start of a run
        int length = 1;
        while (present.count(x + length)) ++length;
        best = std::max(best, length);
    }
    return best;
}

int main()
{
    std::cout << longestRun({ 100, 4, 200, 1, 3, 2, 101, 102 }) << '\n';
}

Each number is counted at most once inside a run, so the whole thing is O(n), even though it has a loop inside a loop.

A checklist

  1. What operations, how often? Write them down: "insert 10⁶ times, look up 10⁸ times, never delete".
  2. Do you need order (sorted iteration, min/max, ranges, "next bigger")? Then a tree or a sorted vector.
  3. Is it only lookup by key? A hash table.
  4. Is the data mostly static? A sorted vector.
  5. Do you need the smallest or largest repeatedly? A heap.
  6. Is it small (under a few dozen elements)? A vector, searched linearly, is often the fastest of all.
  7. Measure if it matters.

Summary

  • Know the costs: vectors for sequences, hash tables for lookup, trees for order and ranges, heaps for repeated min/max.
  • Sorted vectors (and std::flat_map) are excellent for data that rarely changes.
  • Hash maps count and group; hash sets turn "is it there?" into O(1).
  • Decide from the operations you need and how often, and measure when it matters.
