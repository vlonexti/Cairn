Binary Search Trees

lesson 4.022 of 5 in milestone 47 min1 practice task

Ordered binary trees - the search-tree property, search and insert in O(height), deleting a node with zero, one or two children, minimum, maximum, floor and ceiling, successors, range queries and counting, augmenting nodes with subtree sizes for rank and select, why insertion order can make the tree degenerate, and how std::set and std::map relate.

The search-tree property

A binary search tree (BST) is a binary tree in which, for every node, all values in its left subtree are smaller and all values in its right subtree are larger. That single rule lets you find any value by walking down one path, like binary search:

  • equal: found,
  • smaller: go left,
  • larger: go right,
  • fell off the tree: not there.

Each step goes one level down, so search takes O(h), where h is the height of the tree. Insertion walks the same path and attaches a new leaf where the search fell off.

C++
#include <iostream>
#include <memory>
#include <vector>

struct Node
{
    int key;
    std::unique_ptr<Node> left, right;
};

class Bst
{
public:
    bool insert(int key)
    {
        std::unique_ptr<Node>* link = &root_;
        while (*link)
        {
            if (key == (*link)->key) return false;           // no duplicates
            link = key < (*link)->key ? &(*link)->left : &(*link)->right;
        }
        *link = std::make_unique<Node>(Node{ key, nullptr, nullptr });
        return true;
    }

    bool contains(int key) const
    {
        const Node* n = root_.get();
        while (n && n->key != key) n = key < n->key ? n->left.get() : n->right.get();
        return n != nullptr;
    }

    void inorder(const Node* n, std::vector<int>& out) const
    {
        if (!n) return;
        inorder(n->left.get(), out);
        out.push_back(n->key);
        inorder(n->right.get(), out);
    }
    std::vector<int> sorted() const { std::vector<int> out; inorder(root_.get(), out); return out; }

private:
    std::unique_ptr<Node> root_;
};

int main()
{
    Bst t;
    for (int k : { 8, 3, 10, 1, 6, 14, 4, 7, 13 }) t.insert(k);
    std::cout << "contains 6? " << t.contains(6) << ", contains 5? " << t.contains(5) << "\nin order: ";
    for (int k : t.sorted()) std::cout << k << ' ';
    std::cout << '\n';
}

The pointer-to-link trick (std::unique_ptr<Node>* link) from practice 1.04 means insertion has no special case for an empty tree: link starts at the root pointer itself.

An in-order traversal of a BST visits the keys in sorted order. So a BST can do everything a sorted array can, and also insert and delete without shifting everything.

Deleting

Deletion has three cases, depending on how many children the node has:

  1. No children: just remove it.
  2. One child: replace the node with its child.
  3. Two children: find its successor, the smallest key in its right subtree (go right once, then left as far as possible). Copy the successor's key into the node, then delete the successor from the right subtree; the successor has no left child, so that is case 1 or 2.
C++
void erase(std::unique_ptr<Node>& link, int key)
{
    if (!link) return;
    if (key < link->key) erase(link->left, key);
    else if (key > link->key) erase(link->right, key);
    else if (!link->left) link = std::move(link->right);        // cases 1 and 2
    else if (!link->right) link = std::move(link->left);
    else                                                         // case 3
    {
        Node* successor = link->right.get();
        while (successor->left) successor = successor->left.get();
        link->key = successor->key;
        erase(link->right, successor->key);
    }
}

Note link = std::move(link->right): moving a child into the very pointer that owns its parent. unique_ptr's move assignment releases the right child first, then deletes the old parent, so it is safe.

Order queries

Because a BST is ordered, it answers questions a hash table cannot, each in O(h):

Query How
minimum / maximum go left (right) until you cannot
floor(x): largest key ≤ x walk down; whenever a key ≤ x, remember it and go right; otherwise go left
ceiling(x): smallest key ≥ x the mirror image
successor of x the ceiling of x + 1, or: right once then all the way left
all keys in [lo, hi] in-order traversal that skips subtrees entirely outside the range
C++
#include <iostream>
#include <memory>
#include <optional>
#include <string>

struct Node
{
    int key;
    std::unique_ptr<Node> left, right;
};

void insert(std::unique_ptr<Node>& link, int key)
{
    if (!link) link = std::make_unique<Node>(Node{ key, nullptr, nullptr });
    else if (key < link->key) insert(link->left, key);
    else if (key > link->key) insert(link->right, key);
}

std::optional<int> floorKey(const Node* n, int x)
{
    std::optional<int> best;
    while (n)
    {
        if (n->key == x) return x;
        if (n->key < x) { best = n->key; n = n->right.get(); }    // a candidate; a closer one may be to the right
        else n = n->left.get();
    }
    return best;
}

void range(const Node* n, int lo, int hi)
{
    if (!n) return;
    if (lo < n->key) range(n->left.get(), lo, hi);                // the left side can only help if lo < key
    if (lo <= n->key && n->key <= hi) std::cout << n->key << ' ';
    if (n->key < hi) range(n->right.get(), lo, hi);
}

int main()
{
    std::unique_ptr<Node> root;
    for (int k : { 50, 30, 70, 20, 40, 60, 80, 35, 45 }) insert(root, k);
    for (int x : { 44, 50, 19, 100 })
    {
        auto f = floorKey(root.get(), x);
        std::cout << "floor(" << x << ") = " << (f ? std::to_string(*f) : "none") << '\n';
    }
    std::cout << "keys in [33, 65]: ";
    range(root.get(), 33, 65);
    std::cout << '\n';
}

The range query costs O(h + k), where k is the number of keys reported: it only descends into subtrees that can contain keys in the range.

Rank and select: augmenting the tree

Store in every node the size of its subtree, and keep it up to date on insert and delete (each changes the sizes along one path). Then two more questions become O(h):

  • rank(x): how many keys are smaller than x? Walk down; whenever you go right past a node, add the size of its left subtree plus one.
  • select(k): the k-th smallest key. At each node, compare k with the left subtree's size: go left, stop here, or go right with k reduced by the left size + 1.

This is called augmenting a data structure: adding a little information to each node so it can answer new questions. The milestone project uses it.

The catch: the shape depends on the insertion order

The height h decides everything, and it depends on the order of insertions. Keys inserted in random order give an expected height of about 3 log₂ n, which is fine. But inserting keys in sorted order makes every new key the right child of the previous one: the tree degenerates into a linked list of height n − 1, and every operation becomes O(n).

C++
#include <algorithm>
#include <iostream>
#include <memory>
#include <random>
#include <vector>

struct Node
{
    int key;
    Node* left = nullptr;
    Node* right = nullptr;
};

int main()
{
    for (bool shuffled : { false, true })
    {
        std::vector<int> keys(2000);
        for (int i = 0; i < 2000; ++i) keys[i] = i;
        if (shuffled) std::shuffle(keys.begin(), keys.end(), std::mt19937(5));

        std::vector<std::unique_ptr<Node>> pool;                 // owns the nodes, so no deep recursion when freeing
        Node* root = nullptr;
        int height = -1;
        for (int k : keys)
        {
            pool.push_back(std::make_unique<Node>(Node{ k }));
            Node** link = &root;
            int depth = 0;
            while (*link) { link = k < (*link)->key ? &(*link)->left : &(*link)->right; ++depth; }
            *link = pool.back().get();
            height = std::max(height, depth);
        }
        std::cout << (shuffled ? "random order: " : "sorted order: ") << "height " << height << " for 2000 keys\n";
    }
}

The fix is to rebalance the tree as it changes, keeping its height O(log n) no matter what. Lesson 4.03 does that with AVL trees. std::set and std::map are red-black trees, another self-balancing BST, so all their operations are guaranteed O(log n).

Summary

  • A BST keeps smaller keys to the left and larger to the right; search, insert and delete take O(h).
  • Deleting a node with two children swaps in its in-order successor.
  • BSTs answer ordered queries: min, max, floor, ceiling, successor and ranges.
  • Storing subtree sizes adds rank and select in O(h).
  • An unbalanced BST can have height n; self-balancing trees (AVL, red-black as in std::map) guarantee O(log n).
