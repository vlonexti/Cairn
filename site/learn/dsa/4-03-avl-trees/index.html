AVL Trees

lesson 4.033 of 5 in milestone 47 min1 practice task

Keeping a search tree balanced - the AVL balance condition and why it bounds the height by about 1.44 log n, storing heights in the nodes, left and right rotations, the four imbalance cases (left-left, right-right, left-right, right-left), insertion with rebalancing on the way back up, deletion, and how AVL trees compare with red-black trees, treaps and B-trees.

The balance condition

An AVL tree (Adelson-Velsky and Landis, 1962, the first self-balancing BST) is a binary search tree in which, for every node, the heights of the left and right subtrees differ by at most one. The difference is the node's balance factor:

balance(n) = height(n.left) − height(n.right) ∈ { −1, 0, +1 }

This is enough to keep the tree short. The sparsest AVL tree of height h has a subtree of height h − 1 on one side and h − 2 on the other, so the minimum number of nodes grows like the Fibonacci numbers, exponentially in h. Turned around, an AVL tree with n nodes has height at most about 1.44 log₂ n. A million keys means at most about 28 levels, guaranteed.

Rotations

When an insertion or deletion breaks the balance condition, the tree is repaired with rotations: local rearrangements of a node and its child that keep the search-tree order but change the heights.

A right rotation at node y lifts its left child x into its place:

The in-order sequence is A x B y C both before and after, so the tree is still a BST. Only three pointers change, so a rotation is O(1). A left rotation is the mirror image.

The four cases

After inserting into the subtree of node z, suppose z becomes unbalanced with balance +2 (its left side is two levels taller). Look at its left child y:

Case Shape Fix
left-left y is left-heavy (or balanced) rotate right at z
left-right y is right-heavy rotate left at y, then right at z
right-right mirror: balance −2, right child right-heavy rotate left at z
right-left mirror: right child left-heavy rotate right at the child, then left at z

The double rotations handle the "zig-zag" shape, where a single rotation would just move the imbalance to the other side.

Insertion

Insert as in an ordinary BST, then, on the way back up the path to the root, update each node's stored height and rebalance it if needed. Written recursively, the "way back up" is simply the code after the recursive call:

C++
#include <algorithm>
#include <iostream>
#include <memory>
#include <vector>

struct Node
{
    int key;
    int height = 0;
    std::unique_ptr<Node> left, right;
};

int height(const std::unique_ptr<Node>& n) { return n ? n->height : -1; }
void update(Node& n) { n.height = 1 + std::max(height(n.left), height(n.right)); }
int balance(const Node& n) { return height(n.left) - height(n.right); }

void rotateRight(std::unique_ptr<Node>& link)
{
    std::unique_ptr<Node> x = std::move(link->left);
    link->left = std::move(x->right);
    update(*link);
    x->right = std::move(link);
    update(*x);
    link = std::move(x);
}

void rotateLeft(std::unique_ptr<Node>& link)
{
    std::unique_ptr<Node> x = std::move(link->right);
    link->right = std::move(x->left);
    update(*link);
    x->left = std::move(link);
    update(*x);
    link = std::move(x);
}

void rebalance(std::unique_ptr<Node>& link)
{
    update(*link);
    if (balance(*link) > 1)
    {
        if (balance(*link->left) < 0) rotateLeft(link->left);      // left-right: make it left-left first
        rotateRight(link);
    }
    else if (balance(*link) < -1)
    {
        if (balance(*link->right) > 0) rotateRight(link->right);   // right-left: make it right-right first
        rotateLeft(link);
    }
}

void insert(std::unique_ptr<Node>& link, int key)
{
    if (!link) { link = std::make_unique<Node>(); link->key = key; return; }
    if (key < link->key) insert(link->left, key);
    else if (key > link->key) insert(link->right, key);
    else return;
    rebalance(link);
}

void inorder(const Node* n, std::vector<int>& out)
{
    if (!n) return;
    inorder(n->left.get(), out);
    out.push_back(n->key);
    inorder(n->right.get(), out);
}

int main()
{
    std::unique_ptr<Node> root;
    for (int k = 1; k <= 100000; ++k) insert(root, k);              // sorted order: the worst case for a plain BST
    std::cout << "height after 100000 sorted inserts: " << height(root) << '\n';

    std::unique_ptr<Node> small;
    for (int k : { 10, 20, 30, 25, 28, 5 }) insert(small, k);
    std::vector<int> keys;
    inorder(small.get(), keys);
    std::cout << "root " << small->key << ", keys:";
    for (int k : keys) std::cout << ' ' << k;
    std::cout << '\n';
}

The sorted insertions that made a plain BST of height 1,999 for 2,000 keys in lesson 4.02 now give height 16 for 100,000 keys: a perfect tree of that size has height 16 too.

Each insertion costs O(log n) to walk down plus O(1) work per level on the way back up: O(log n). At most one (single or double) rotation is actually needed per insertion, because after it the subtree has its old height again.

Deletion

Deletion works the same way: delete as in a BST (lesson 4.02), then rebalance every node on the path back to the root. Unlike insertion, a deletion may need a rotation at several levels, still O(log n) in total. The same rebalance function handles it; only the deciding test for the child's balance must allow 0 (a balanced child takes the single rotation).

AVL trees and their relatives

Structure Height guarantee Notes
AVL tree ≈ 1.44 log₂ n the most strictly balanced, so the fastest lookups; slightly more rotations on updates
Red-black tree ≤ 2 log₂ n colours nodes red/black with simple rules; few rotations; used by std::map, std::set, Java's TreeMap, the Linux kernel
Treap ≈ log n expected each node gets a random priority and the tree is also a heap by priority; very simple code
Skip list ≈ log n expected layered linked lists rather than a tree; used by Redis and LevelDB
B-tree log_b n nodes hold hundreds of keys, so very shallow; used by databases and file systems, where each node is a disk page

All of them give the same thing: an ordered set or map with O(log n) operations in the worst (or expected) case.

Summary

  • An AVL tree keeps every node's subtree heights within one of each other, which bounds the height by about 1.44 log₂ n.
  • Rotations restructure a node and its child in O(1) while keeping the in-order sequence.
  • Four cases (LL, RR, LR, RL) are fixed by one single or double rotation.
  • Insert and delete rebalance along the path back to the root: O(log n).
  • Red-black trees, treaps, skip lists and B-trees offer the same guarantees with different trade-offs.
