Grid Search and A*

lesson 5.055 of 5 in milestone 56 min1 practice task

Finding paths faster with a sense of direction - weighted grids, Dijkstra exploring in every direction, the A* algorithm with f = g + h, admissible and consistent heuristics (Manhattan, Chebyshev, octile, Euclidean), tie-breaking, comparing how many cells each algorithm expands, and where A* is used in games, robotics and puzzles.

Searching with a goal in mind

Dijkstra's algorithm expands vertices in order of their distance from the start, in every direction. If you only want the path to one goal, most of that work is wasted: searching for a route from Paris to Berlin, Dijkstra explores Spain just as eagerly as Germany.

A* (Hart, Nilsson and Raphael, 1968) adds a sense of direction. For each vertex n it uses:

  • g(n): the cost of the best known path from the start to n (Dijkstra's dist),
  • h(n): a heuristic, an estimate of the remaining cost from n to the goal,
  • f(n) = g(n) + h(n): the estimated cost of the best path through n.

A* is Dijkstra with the priority queue ordered by f instead of g. Vertices that are close to the start and seem close to the goal come first.

Admissible and consistent heuristics

A* finds the optimal path if h never overestimates the true remaining cost: h is admissible. If h also never drops by more than the edge cost along any edge (h(u) ≤ w(u, v) + h(v)), it is consistent, and then, as in Dijkstra, every vertex is final when popped and needs to be expanded only once.

  • h = 0 everywhere is admissible and consistent: A* becomes Dijkstra.
  • The better h estimates the true distance (without overestimating), the fewer vertices A* expands.
  • An overestimating h can make A* faster but no longer guarantees the shortest path ("weighted A*" does this deliberately).

For grids, the right heuristic depends on the moves allowed, scaled by the cheapest cost of a step:

Moves Heuristic Formula (dx, dy = distances to the goal)
4 directions Manhattan dx + dy
8 directions, diagonal costs 1 Chebyshev max(dx, dy)
8 directions, diagonal costs √2 octile max(dx, dy) + (√2 − 1)·min(dx, dy)
any direction Euclidean √(dx² + dy²)

A* on a grid

The grid below has walls (#), open cells (., cost 1 to enter) and swamp (~, cost 5 to enter). Moves go up, down, left and right, so Manhattan distance (times the cheapest step cost, 1) is admissible and consistent.

C++
#include <cstdlib>
#include <functional>
#include <iostream>
#include <queue>
#include <string>
#include <tuple>
#include <vector>

struct Result { int cost; int expanded; };

Result search(const std::vector<std::string>& grid, int sr, int sc, int gr, int gc, bool useHeuristic)
{
    int rows = static_cast<int>(grid.size()), cols = static_cast<int>(grid[0].size());
    auto h = [&](int r, int c) { return useHeuristic ? std::abs(r - gr) + std::abs(c - gc) : 0; };
    std::vector<int> g(rows * cols, 1 << 30);
    using Item = std::tuple<int, int, int>;                          // (f, -g, cell): ties prefer larger g, closer to the goal
    std::priority_queue<Item, std::vector<Item>, std::greater<Item>> open;
    g[sr * cols + sc] = 0;
    open.push({ h(sr, sc), 0, sr * cols + sc });
    int expanded = 0;
    const int dr[] = { -1, 1, 0, 0 }, dc[] = { 0, 0, -1, 1 };
    while (!open.empty())
    {
        auto [f, negG, cell] = open.top();
        open.pop();
        if (-negG > g[cell]) continue;                                // stale entry
        ++expanded;
        int r = cell / cols, c = cell % cols;
        if (r == gr && c == gc) return { g[cell], expanded };
        for (int d = 0; d < 4; ++d)
        {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr < 0 || nr >= rows || nc < 0 || nc >= cols || grid[nr][nc] == '#') continue;
            int cost = g[cell] + (grid[nr][nc] == '~' ? 5 : 1);
            int next = nr * cols + nc;
            if (cost < g[next])
            {
                g[next] = cost;
                open.push({ cost + h(nr, nc), -cost, next });
            }
        }
    }
    return { -1, expanded };
}

int main()
{
    std::vector<std::string> grid(40, std::string(60, '.'));
    for (int r = 5; r < 35; ++r) grid[r][30] = '#';                  // a wall with gaps at the top and bottom
    for (int c = 10; c < 50; ++c) grid[20][c] = '~';                 // a band of swamp
    for (bool astar : { false, true })
    {
        Result res = search(grid, 20, 2, 20, 57, astar);
        std::cout << (astar ? "A*:       " : "Dijkstra: ") << "cost " << res.cost << ", cells expanded " << res.expanded << '\n';
    }
}

Both find the same cost, but A* expands a fraction of the cells: Dijkstra floods the whole map before reaching the far side, while A* heads for the goal and only spreads out where the wall forces it to.

Tie-breaking matters on grids: many cells often share the same f. Preferring the one with the larger g (the one further along) makes A* push towards the goal instead of widening the search front. The code orders by (f, −g).

Beyond grids

  • Games: units finding their way around maps; often with precomputed navigation meshes and hierarchical search for large maps.
  • Robotics: path planning in configuration spaces.
  • Puzzles: the 15-puzzle or Rubik's cube are graphs of states; the heuristic counts misplaced tiles or adds up each tile's Manhattan distance to its home.
  • Route planning: road networks use the straight-line distance divided by the top speed as an admissible time estimate, plus "landmark" heuristics precomputed from distances to a few reference points.

When even A* is too slow or memory-hungry, variants trade optimality or memory: IDA* (iterative deepening, very little memory), jump point search (skips symmetric paths on uniform grids), and bidirectional search (searching from both ends at once).

Summary

  • A* orders the frontier by f = g + h, steering the search towards the goal.
  • With an admissible (never overestimating) heuristic it finds a shortest path; with a consistent one, each vertex is expanded once.
  • Match the heuristic to the moves: Manhattan, Chebyshev, octile or Euclidean, scaled by the cheapest step.
  • Break ties towards larger g; A* then expands far fewer vertices than Dijkstra for a single goal.
