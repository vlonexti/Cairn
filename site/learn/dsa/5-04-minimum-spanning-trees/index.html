Minimum Spanning Trees

lesson 5.044 of 5 in milestone 56 min1 practice task

Connecting everything as cheaply as possible - spanning trees, the cut property that makes greedy choices safe, Kruskal's algorithm with sorting and union-find, Prim's algorithm with a priority queue, the dense O(V^2) version of Prim for complete graphs, minimum spanning forests, and uses from network design to clustering.

The problem

A council wants to connect every village with roads, a company every office with fibre, an engineer every point of a circuit with wire. Each possible link has a cost. What is the cheapest set of links that connects everything?

The answer never contains a cycle (dropping any edge of a cycle keeps everything connected and saves money), so it is a tree that spans all vertices: a minimum spanning tree (MST). For V vertices it has exactly V − 1 edges.

Note the difference from shortest paths: an MST minimises the total cost of the network, not the distance between any particular pair. The MST route between two villages can be long.

The cut property

Split the vertices into two groups in any way (a cut). The cheapest edge crossing between the groups belongs to some minimum spanning tree. (If a spanning tree did not use it, adding it would create a cycle that crosses the cut a second time through a more expensive edge; swapping them gives a tree at least as cheap.)

This makes greedy algorithms correct: repeatedly take the cheapest edge that is safe. Kruskal and Prim differ in which cut they look at.

Kruskal's algorithm

Sort all edges by cost. Go through them cheapest first, and add an edge unless it would close a cycle. Union-find (lesson 4.05) answers "would it close a cycle?" in effectively O(1): the ends are already connected exactly when find(u) == find(v).

C++
#include <algorithm>
#include <iostream>
#include <numeric>
#include <string>
#include <tuple>
#include <vector>

struct UnionFind
{
    std::vector<int> parent, size;
    explicit UnionFind(int n) : parent(n), size(n, 1) { std::iota(parent.begin(), parent.end(), 0); }
    int find(int x) { while (parent[x] != x) x = parent[x] = parent[parent[x]]; return x; }   // path halving
    bool unite(int a, int b)
    {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (size[a] < size[b]) std::swap(a, b);
        parent[b] = a;
        size[a] += size[b];
        return true;
    }
};

int main()
{
    std::vector<std::string> town{ "Ash", "Birch", "Cedar", "Dale", "Elm" };
    std::vector<std::tuple<int, int, int>> edges{                        // (cost, a, b)
        { 7, 0, 1 }, { 5, 0, 3 }, { 8, 1, 2 }, { 9, 1, 3 }, { 7, 1, 4 }, { 5, 2, 4 }, { 15, 3, 4 }, { 6, 3, 2 } };
    std::sort(edges.begin(), edges.end());

    UnionFind uf(5);
    int total = 0;
    for (auto [cost, a, b] : edges)
        if (uf.unite(a, b))
        {
            total += cost;
            std::cout << town[a] << " - " << town[b] << " (" << cost << ")\n";
        }
    std::cout << "total " << total << '\n';
}

Sorting dominates: O(E log E). Kruskal is simple and works directly on an edge list. If the graph is not connected, it naturally produces a minimum spanning forest: one tree per component.

Prim's algorithm

Prim grows a single tree from a start vertex. At each step it adds the cheapest edge that connects the tree to a vertex outside it (the cut between "in the tree" and "not yet"). It looks just like Dijkstra, with one change: the priority of a vertex is the cost of the single edge that would attach it, not the length of a whole path.

C++
#include <functional>
#include <iostream>
#include <queue>
#include <utility>
#include <vector>

int main()
{
    int V = 5;
    std::vector<std::vector<std::pair<int, int>>> adj(V);       // (neighbour, cost)
    auto link = [&](int a, int b, int c) { adj[a].push_back({ b, c }); adj[b].push_back({ a, c }); };
    link(0, 1, 7); link(0, 3, 5); link(1, 2, 8); link(1, 3, 9); link(1, 4, 7); link(2, 4, 5); link(3, 4, 15); link(3, 2, 6);

    std::vector<bool> inTree(V, false);
    using Item = std::pair<int, int>;                            // (edge cost, vertex)
    std::priority_queue<Item, std::vector<Item>, std::greater<Item>> pq;
    pq.push({ 0, 0 });
    int total = 0, added = 0;
    while (!pq.empty() && added < V)
    {
        auto [cost, u] = pq.top();
        pq.pop();
        if (inTree[u]) continue;                                 // already attached more cheaply
        inTree[u] = true;
        total += cost;
        ++added;
        for (auto [v, c] : adj[u])
            if (!inTree[v]) pq.push({ c, v });
    }
    std::cout << "total " << total << " with " << added << " vertices\n";
}

With a binary heap, Prim is O(E log V). Both algorithms find a tree of the same total cost (the MST is unique when all edge costs differ).

Dense graphs: O(V²) Prim

When every pair of vertices can be linked, for example connecting points in the plane where any two can be wired together, E is about V²/2 and building the edge list alone is expensive. A version of Prim without a heap is then better: keep for every outside vertex the cheapest known cost to attach it, pick the minimum by scanning the array, and update the array from the new tree vertex. Each of the V steps scans V entries: O(V²), with no edge list at all. Practice 5.04 uses it.

Uses

  • Network design: roads, pipes, cables, circuit wiring.
  • Clustering: build the MST of points with distances as costs, then delete the k − 1 most expensive edges: what remains are k clusters whose closest members are as far apart as possible (single-linkage clustering).
  • Approximation: the MST gives a route at most twice the optimum for the travelling salesman problem with distances that obey the triangle inequality.
  • Image segmentation: pixels as vertices, colour differences as costs.

Summary

  • A minimum spanning tree connects all vertices with V − 1 edges of least total cost.
  • The cut property makes greedy choices safe.
  • Kruskal: sort edges, add each unless union-find says it closes a cycle; O(E log E).
  • Prim: grow one tree with a min-heap of attaching edges; O(E log V), or O(V²) without a heap on dense graphs.
  • MSTs design networks, cluster data and approximate harder problems.
