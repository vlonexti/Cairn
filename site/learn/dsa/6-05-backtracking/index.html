Backtracking

lesson 6.055 of 5 in milestone 67 min1 practice task

Searching through every possibility, cleverly - the choose, explore, unchoose pattern, generating subsets, permutations and combinations, the N-queens puzzle with constant-time safety checks, solving Sudoku, pruning dead ends early, branch and bound, and a first look at NP-complete problems, where exhaustive search is the best known exact method.

When there is no shortcut

Some problems have no known greedy rule or dynamic-programming structure: place eight queens on a chessboard so that none attacks another, fill in a Sudoku, find a subset of numbers that sums to a target. The fallback is to search: try the options one by one. Backtracking does that systematically and efficiently. It builds a solution one decision at a time, and as soon as a partial solution cannot possibly be completed, it abandons it (backtracks) and tries the next option.

Every backtracking algorithm has the same shape:

C++
void search(State& state)
{
    if (isComplete(state)) { record(state); return; }
    for (Choice c : choicesFor(state))
    {
        if (!allowed(state, c)) continue;   // prune: this choice cannot lead to a solution
        apply(state, c);                     // choose
        search(state);                       // explore
        undo(state, c);                      // unchoose
    }
}

It is a depth-first search (lesson 5.02) of a tree of partial solutions that is never built explicitly.

Subsets and permutations

Generating all subsets of n items makes one yes/no decision per item: 2ⁿ leaves. Generating all orderings (permutations) picks an unused item for each position: n! leaves.

C++
#include <iostream>
#include <vector>

void subsets(const std::vector<int>& items, std::size_t i, std::vector<int>& chosen)
{
    if (i == items.size())
    {
        std::cout << '{';
        for (std::size_t k = 0; k < chosen.size(); ++k) std::cout << (k ? "," : "") << chosen[k];
        std::cout << "} ";
        return;
    }
    subsets(items, i + 1, chosen);          // leave items[i] out
    chosen.push_back(items[i]);             // choose it
    subsets(items, i + 1, chosen);          // explore
    chosen.pop_back();                      // unchoose
}

void permutations(std::vector<int>& items, std::size_t pos)
{
    if (pos == items.size())
    {
        for (int x : items) std::cout << x;
        std::cout << ' ';
        return;
    }
    for (std::size_t i = pos; i < items.size(); ++i)
    {
        std::swap(items[pos], items[i]);    // put items[i] in position pos
        permutations(items, pos + 1);
        std::swap(items[pos], items[i]);    // undo
    }
}

int main()
{
    std::vector<int> chosen;
    subsets({ 1, 2, 3 }, 0, chosen);
    std::cout << '\n';
    std::vector<int> items{ 1, 2, 3 };
    permutations(items, 0);
    std::cout << '\n';
}

The standard library generates permutations in lexicographic order with std::next_permutation (start from a sorted range and loop while it returns true).

N queens

Place N queens on an N × N board so that no two share a row, a column or a diagonal. Place one queen per row; for each row, try every column that is not attacked. Tracking the used columns and the two kinds of diagonals in boolean arrays makes each safety check O(1): squares on the same "/" diagonal share row + col, and on the same "" diagonal share row − col.

C++
#include <iostream>
#include <vector>

int n;
std::vector<bool> column, diag1, diag2;
long long solutions = 0, nodes = 0;

void place(int row)
{
    ++nodes;
    if (row == n) { ++solutions; return; }
    for (int c = 0; c < n; ++c)
    {
        if (column[c] || diag1[row + c] || diag2[row - c + n - 1]) continue;    // attacked: prune
        column[c] = diag1[row + c] = diag2[row - c + n - 1] = true;
        place(row + 1);
        column[c] = diag1[row + c] = diag2[row - c + n - 1] = false;
    }
}

int main()
{
    for (n = 4; n <= 10; ++n)
    {
        column.assign(n, false);
        diag1.assign(2 * n, false);
        diag2.assign(2 * n, false);
        solutions = nodes = 0;
        place(0);
        std::cout << n << " queens: " << solutions << " solutions, " << nodes << " partial boards explored\n";
    }
}

There are 10¹⁰ ways to put one queen in each row of a 10 × 10 board, but pruning means only about 35,000 partial boards are ever explored.

Sudoku

A Sudoku solver is the same pattern: find an empty cell, try each digit that does not already appear in its row, column or 3 × 3 box, recurse, and undo if the recursion fails. A strong improvement is to choose the empty cell with the fewest possible digits first (the "most constrained variable" heuristic): it fails fastest when a branch is hopeless, and often has only one option. Practice 6.05 builds a solver.

Pruning and branch and bound

Backtracking is only as good as its pruning. Good pruning checks:

  • constraints as early as possible (the queen safety arrays),
  • feasibility: in subset sum with positive numbers, stop when the running total exceeds the target, or when even taking every remaining number cannot reach it,
  • symmetry: in N queens, the first queen only needs the left half of the first row (mirror the rest).

For optimisation problems, branch and bound adds a bound: keep the best complete solution found so far, and abandon any partial solution whose optimistic estimate cannot beat it. This is how exact solvers for scheduling, routing and the knapsack with huge capacities work in practice.

When search is the best we know

For many important problems (the travelling salesman, Boolean satisfiability, graph colouring, subset sum, scheduling with constraints), no polynomial-time algorithm is known. They are NP-complete: a proposed solution is easy to check, and a fast algorithm for any one of them would give fast algorithms for all of them. Whether that is possible is the famous open question P vs NP.

In practice, such problems are attacked with:

  • backtracking with strong pruning, and branch and bound,
  • dynamic programming when a parameter is small (subset sum with a small target, the travelling salesman on 20 cities with bitmask DP),
  • specialised solvers (SAT solvers, integer linear programming),
  • approximation algorithms with guarantees (the MST-based travelling-salesman tour from lesson 5.04),
  • heuristics such as local search and simulated annealing when "good enough" will do.

Summary

  • Backtracking searches the tree of partial solutions depth first: choose, explore, unchoose.
  • Subsets give 2ⁿ leaves and permutations n!; pruning is what makes search feasible.
  • Constant-time constraint checks (N queens) and choosing the most constrained variable first (Sudoku) cut the search dramatically.
  • Branch and bound prunes optimisation searches with bounds.
  • NP-complete problems have no known polynomial algorithm; search, DP on small parameters, solvers, approximations and heuristics are the tools.
