Counting and Radix Sort

lesson 3.055 of 5 in milestone 38 min1 practice task

Sorting without comparisons - counting sort for small key ranges and how prefix sums make it stable, radix sort digit by digit (least significant digit first) for integers and fixed-length strings, bucket sort for evenly spread values, when these linear-time sorts beat std::sort, and a summary of every sort in the milestone.

Escaping the lower bound

Lesson 3.02 proved that sorting by comparisons needs Ω(n log n). The sorts in this lesson never compare two elements. They use the keys as numbers or indexes, and when the keys are small integers (or can be split into small pieces), they sort in linear time.

Counting sort

If every key is an integer from 0 to k − 1, count how many times each value occurs, then write the values back in order:

C++
#include <iostream>
#include <vector>

void countingSort(std::vector<int>& a, int k)      // every value in [0, k)
{
    std::vector<int> count(k, 0);
    for (int x : a) ++count[x];
    std::size_t i = 0;
    for (int v = 0; v < k; ++v)
        while (count[v]-- > 0) a[i++] = v;
}

int main()
{
    std::vector<int> grades{ 3, 1, 4, 1, 5, 2, 0, 4, 4, 1 };
    countingSort(grades, 6);
    for (int g : grades) std::cout << g << ' ';
    std::cout << '\n';
}

That is O(n + k) time and O(k) extra space: excellent when k is small compared with n (exam scores out of 100, ages, bytes), useless when the keys can be anything up to 2³².

Stable counting sort with prefix sums

Usually the keys belong to records (sort students by grade), so you cannot just rewrite the keys: you must move whole records, and keep records with equal keys in their original order. The trick is to turn the counts into starting positions with a prefix sum:

  1. Count each key.
  2. Prefix sum: start[v] = how many keys are smaller than v = the index where the first record with key v goes.
  3. Walk the input in order, placing each record at start[key] and incrementing it.
C++
#include <iostream>
#include <string>
#include <vector>

struct Student { std::string name; int grade; };   // grade 0..5

std::vector<Student> sortByGrade(const std::vector<Student>& in)
{
    std::vector<std::size_t> start(7, 0);
    for (const auto& s : in) ++start[s.grade + 1];                 // count, shifted by one
    for (int g = 1; g < 7; ++g) start[g] += start[g - 1];          // prefix sums: start[g] = number of grades below g
    std::vector<Student> out(in.size());
    for (const auto& s : in) out[start[s.grade]++] = s;            // stable: equal grades keep their order
    return out;
}

int main()
{
    std::vector<Student> students{ { "Ana", 4 }, { "Ben", 2 }, { "Cat", 4 }, { "Dev", 5 }, { "Eli", 2 }, { "Fay", 0 } };
    for (const auto& s : sortByGrade(students)) std::cout << s.grade << ' ' << s.name << '\n';
}

Stability is not a nicety here: radix sort depends on it.

Radix sort

Radix sort handles big keys by sorting on one digit at a time with a stable counting sort. Starting from the least significant digit (LSD radix sort):

  • sort by the last digit,
  • then stably by the second-to-last,
  • ... and finally by the first.

After the pass on digit d, the keys are sorted by their last d digits, because the stable pass preserves the order of keys that agree on digit d, which earlier passes already arranged. With base 10, { 170, 45, 75, 90, 802, 24, 2, 66 } goes through:

Pass Result
ones 170 90 802 2 24 45 75 66
tens 802 2 24 45 66 170 75 90
hundreds 2 24 45 66 75 90 170 802

For 32-bit integers, computers use base 256: four passes, one per byte, each a counting sort with 256 buckets. That is O(4 · (n + 256)) = O(n):

C++
#include <chrono>
#include <cstdint>
#include <iostream>
#include <random>
#include <algorithm>
#include <vector>

void radixSort(std::vector<std::uint32_t>& a)
{
    std::vector<std::uint32_t> buffer(a.size());
    for (int shift = 0; shift < 32; shift += 8)
    {
        std::size_t start[257] = {};
        for (std::uint32_t x : a) ++start[((x >> shift) & 0xFF) + 1];
        for (int b = 1; b < 257; ++b) start[b] += start[b - 1];
        for (std::uint32_t x : a) buffer[start[(x >> shift) & 0xFF]++] = x;
        a.swap(buffer);
    }
}

int main()
{
    std::mt19937 rng(3);
    std::vector<std::uint32_t> a(2'000'000);
    for (auto& x : a) x = rng();
    auto b = a;

    auto t0 = std::chrono::steady_clock::now();
    radixSort(a);
    auto t1 = std::chrono::steady_clock::now();
    std::sort(b.begin(), b.end());
    auto t2 = std::chrono::steady_clock::now();

    using ms = std::chrono::duration<double, std::milli>;
    std::cout << "radix sort " << ms(t1 - t0).count() << " ms, std::sort " << ms(t2 - t1).count() << " ms, same result: " << (a == b) << '\n';
}

On large arrays of integers radix sort usually beats std::sort by a good margin. It needs an O(n) buffer, and it only works on keys that can be cut into digits.

  • Signed integers: flip the sign bit first (x ^ 0x80000000), so that negative numbers come first.
  • Floating-point numbers: flip all bits of negatives and only the sign bit of positives; the bit patterns then sort like the values.
  • Strings of equal length: one pass per character, from the last. Variable-length strings use MSD (most significant digit first) radix sort, which recurses into each bucket, like a trie (lesson 6.04).

Bucket sort

If the keys are spread evenly over a range, for example random doubles in [0, 1), split the range into n buckets, drop each key into its bucket (bucket = floor(key × n)), sort each small bucket with insertion sort, and concatenate. Each bucket holds about one element on average, so the expected time is O(n). With skewed data, many keys can land in one bucket and it degrades.

Summary

  • Non-comparison sorts escape Ω(n log n) by using keys as indexes.
  • Counting sort is O(n + k) for keys in [0, k); prefix sums make it stable for records.
  • LSD radix sort runs a stable counting sort per digit: O(d(n + b)), linear for fixed-size integers.
  • Bucket sort is expected O(n) on evenly spread keys.
  • Pick by the data: std::sort by default, std::stable_sort for stability, radix or counting sort for big arrays of small or fixed-size integer keys.
