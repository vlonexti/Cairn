Dynamic Arrays

lesson 1.033 of 5 in milestone 15 min1 practice task

How std::vector works inside - a contiguous block with a size and a capacity, growth by doubling and why it gives amortised O(1) push_back, the cost of inserting and erasing in the middle, building a small vector class with a rule-of-five, and what invalidates iterators.

An array that grows

A plain array has a fixed size. A dynamic array keeps its elements in one contiguous block like an array, but can grow. It tracks three things:

  • a pointer to the block,
  • its size, the number of elements in use,
  • its capacity, the number of elements the block can hold.

Reading or writing v[i] is O(1): the address is start + i × sizeof(T). Appending is O(1) while there is spare capacity. When the block is full, the array must:

  1. allocate a bigger block,
  2. move every element across,
  3. free the old block.

That step is O(n). The trick is how much bigger to make the new block.

Why doubling gives amortised O(1)

If the capacity grew by a fixed amount, say 10, every tenth push would copy everything: about n²/20 copies for n pushes, O(n) per push on average. If instead it doubles, the copies happen at sizes 1, 2, 4, 8, ..., and their total is less than 2n. Spread over n pushes, that is fewer than 2 copies each: amortised O(1).

C++
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> v;
    std::size_t lastCapacity = v.capacity();
    for (int i = 0; i < 1000; ++i)
    {
        v.push_back(i);
        if (v.capacity() != lastCapacity)
        {
            std::cout << "size " << v.size() << ": capacity " << lastCapacity << " -> " << v.capacity() << '\n';
            lastCapacity = v.capacity();
        }
    }
}

Microsoft's library grows by 1.5×, GCC's and Clang's by 2×. Any constant factor greater than 1 gives amortised O(1); smaller factors waste less memory but copy a little more often.

If you know the final size, v.reserve(n) allocates once up front and no reallocation happens at all.

Inserting and erasing in the middle

To insert at position i, every element from i onward must shift one place right; erasing shifts them left. That is O(n − i): cheap at the end, expensive at the front.

Operation Cost
v[i], v.back() O(1)
push_back, pop_back amortised O(1), O(1)
insert(v.begin() + i, x), erase(v.begin() + i) O(n − i)
insert(v.begin(), x) O(n)
find a value (unsorted) O(n)

If you only need to remove an element and do not care about order, swap it with the last element and pop: O(1).

C++
#include <iostream>
#include <vector>

void unorderedErase(std::vector<int>& v, std::size_t i)
{
    v[i] = v.back();
    v.pop_back();
}

int main()
{
    std::vector<int> v{ 10, 20, 30, 40, 50 };
    unorderedErase(v, 1);
    for (int x : v) std::cout << x << ' ';
    std::cout << '\n';
}

Building one

Here is a minimal dynamic array of ints. It owns raw memory, so it follows the rule of five: a destructor, copy constructor, copy assignment, move constructor and move assignment.

C++
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <stdexcept>
#include <utility>

class IntVector
{
public:
    IntVector() = default;
    ~IntVector() { delete[] data_; }

    IntVector(const IntVector& other) : data_(new int[other.capacity_]), size_(other.size_), capacity_(other.capacity_)
    {
        std::copy(other.data_, other.data_ + size_, data_);
    }
    IntVector& operator=(IntVector other) noexcept      // copy-and-swap handles both copy and move assignment
    {
        swap(other);
        return *this;
    }
    IntVector(IntVector&& other) noexcept
        : data_(std::exchange(other.data_, nullptr)), size_(std::exchange(other.size_, 0)), capacity_(std::exchange(other.capacity_, 0)) {}

    void push_back(int value)
    {
        if (size_ == capacity_) grow(capacity_ == 0 ? 1 : capacity_ * 2);
        data_[size_++] = value;
    }
    void pop_back() { if (size_ == 0) throw std::out_of_range("pop_back on empty"); --size_; }

    int& operator[](std::size_t i) { return data_[i]; }
    int& at(std::size_t i) { if (i >= size_) throw std::out_of_range("index"); return data_[i]; }
    std::size_t size() const { return size_; }
    std::size_t capacity() const { return capacity_; }

    void swap(IntVector& other) noexcept
    {
        std::swap(data_, other.data_);
        std::swap(size_, other.size_);
        std::swap(capacity_, other.capacity_);
    }

private:
    void grow(std::size_t newCapacity)
    {
        int* bigger = new int[newCapacity];
        std::copy(data_, data_ + size_, bigger);
        delete[] data_;
        data_ = bigger;
        capacity_ = newCapacity;
    }

    int* data_ = nullptr;
    std::size_t size_ = 0;
    std::size_t capacity_ = 0;
};

int main()
{
    IntVector v;
    for (int i = 1; i <= 10; ++i) v.push_back(i * i);
    IntVector copy = v;
    copy[0] = -1;
    std::cout << "size " << v.size() << ", capacity " << v.capacity() << ", v[0] " << v[0] << ", copy[0] " << copy[0] << '\n';
    try { v.at(10); } catch (const std::out_of_range& e) { std::cout << "at(10): " << e.what() << '\n'; }
}

The real std::vector adds a lot on top: it is a template, it constructs elements only when they are pushed (so it works for types without a default constructor), it moves rather than copies elements when it grows (if their move constructor is noexcept), and it gives iterators. The practice for this lesson builds a template version.

Iterator invalidation

Because a dynamic array moves its elements when it grows, any pointer, reference or iterator into it may dangle after a push_back, insert or reserve that reallocates. Erasing invalidates everything after the erased position.

C++
std::vector<int> v{ 1, 2, 3 };
int& first = v[0];
v.push_back(4);          // may reallocate
std::cout << first;      // undefined behaviour if it did

Keep indexes instead of pointers when the vector may grow, or reserve enough first.

Summary

  • A dynamic array is a contiguous block with a size and a capacity.
  • Growing by a constant factor makes push_back amortised O(1); reserve avoids growing at all.
  • Inserting and erasing cost O(n − i) because elements shift; swap-and-pop removes in O(1) when order does not matter.
  • Reallocation invalidates pointers, references and iterators.
