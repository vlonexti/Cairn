Fenwick and Segment Trees

lesson 4.044 of 5 in milestone 47 min1 practice task

Answering range questions on changing arrays - prefix sums and their weakness, the Fenwick (binary indexed) tree with its lowest-set-bit trick for O(log n) updates and prefix sums, segment trees for any associative operation such as minimum or maximum, building, point updates and range queries, and a first look at lazy propagation for range updates.

Range queries

Many problems ask questions about ranges of an array: the total sales between day 30 and day 90, the lowest temperature in a given hour, the number of active users between two IDs. If the array never changes, prefix sums answer range sums in O(1):

Output
prefix[i] = a[0] + a[1] + ... + a[i-1]
sum(l, r) = prefix[r + 1] - prefix[l]

Building them is O(n). But if the array changes, a single update to a[i] changes every prefix[j] with j > i: O(n) per update. With many updates and many queries mixed, we need both to be fast.

Structure Update a[i] Range sum Range min
plain array O(1) O(n) O(n)
prefix sums O(n) O(1) no
Fenwick tree O(log n) O(log n) no (only for sums and similar)
segment tree O(log n) O(log n) O(log n)

The Fenwick tree

A Fenwick tree (or binary indexed tree, Peter Fenwick, 1994) is an array t of the same size, using 1-based indexes, where t[i] stores the sum of a block of elements ending at i whose length is the lowest set bit of i:

i (binary) lowest set bit t[i] holds
1 (0001) 1 a[1]
2 (0010) 2 a[1..2]
3 (0011) 1 a[3]
4 (0100) 4 a[1..4]
6 (0110) 2 a[5..6]
8 (1000) 8 a[1..8]

The lowest set bit of i is i & -i (two's complement makes this work).

  • prefix(i): add t[i], then remove the lowest set bit (i -= i & -i) and repeat until i is 0. For i = 7 (0111): t[7] + t[6] + t[4] = a[7] + a[5..6] + a[1..4].
  • add(i, delta): add delta to t[i], then add the lowest set bit (i += i & -i) and repeat while i ≤ n: these are exactly the blocks that contain position i.

Both loops run at most log₂ n times, since each step clears or carries a bit.

C++
#include <iostream>
#include <vector>

class Fenwick
{
public:
    explicit Fenwick(int n) : t_(n + 1, 0) {}

    void add(int i, long long delta)                 // i is 1-based
    {
        for (; i < static_cast<int>(t_.size()); i += i & -i) t_[i] += delta;
    }
    long long prefix(int i) const                    // a[1] + ... + a[i]
    {
        long long s = 0;
        for (; i > 0; i -= i & -i) s += t_[i];
        return s;
    }
    long long sum(int l, int r) const { return prefix(r) - prefix(l - 1); }

private:
    std::vector<long long> t_;
};

int main()
{
    Fenwick f(10);
    int values[] = { 5, 3, 7, 9, 6, 4, 1, 2, 8, 10 };
    for (int i = 1; i <= 10; ++i) f.add(i, values[i - 1]);
    std::cout << "sum 3..6 = " << f.sum(3, 6) << '\n';      // 7 + 9 + 6 + 4
    f.add(5, 100);                                         // a[5] becomes 106
    std::cout << "after the update, sum 3..6 = " << f.sum(3, 6) << ", total = " << f.prefix(10) << '\n';
}

The whole structure is one array and two four-line loops, and it is very fast in practice. It works for any operation that can be undone (sums, XOR, counts): the range trick prefix(r) − prefix(l − 1) needs subtraction. It cannot do range minimum.

A classic use: counting inversions again. Walk the array from the right, and for each value ask the Fenwick tree how many smaller values have been seen (a prefix count), then add the value. O(n log n), the same as merge sort's method.

Segment trees

A segment tree is a binary tree over the array in which every node stores the answer for a segment: the root covers the whole array, its children cover the two halves, and so on down to single elements at the leaves. It works for any associative operation: sum, min, max, gcd, product, even "the two largest values".

Like a heap (lesson 3.04), it lives in an array: node 1 is the root and the children of node i are 2i and 2i + 1. An array of n elements needs at most 4n slots.

  • query(l, r): starting at the root, if a node's segment is inside [l, r], use its value; if it is outside, ignore it; otherwise ask both children and combine. At most about 4 log n nodes are visited.
  • update(i, value): change the leaf and recompute every node on the path up to the root: O(log n).
C++
#include <algorithm>
#include <climits>
#include <iostream>
#include <vector>

class MinTree
{
public:
    explicit MinTree(const std::vector<int>& a) : n_(static_cast<int>(a.size())), t_(4 * a.size(), INT_MAX) { build(a, 1, 0, n_ - 1); }

    int min(int l, int r) const { return query(1, 0, n_ - 1, l, r); }
    void set(int i, int value) { update(1, 0, n_ - 1, i, value); }

private:
    void build(const std::vector<int>& a, int node, int lo, int hi)
    {
        if (lo == hi) { t_[node] = a[lo]; return; }
        int mid = (lo + hi) / 2;
        build(a, 2 * node, lo, mid);
        build(a, 2 * node + 1, mid + 1, hi);
        t_[node] = std::min(t_[2 * node], t_[2 * node + 1]);
    }

    int query(int node, int lo, int hi, int l, int r) const
    {
        if (r < lo || hi < l) return INT_MAX;              // no overlap
        if (l <= lo && hi <= r) return t_[node];            // fully inside
        int mid = (lo + hi) / 2;
        return std::min(query(2 * node, lo, mid, l, r), query(2 * node + 1, mid + 1, hi, l, r));
    }

    void update(int node, int lo, int hi, int i, int value)
    {
        if (lo == hi) { t_[node] = value; return; }
        int mid = (lo + hi) / 2;
        if (i <= mid) update(2 * node, lo, mid, i, value); else update(2 * node + 1, mid + 1, hi, i, value);
        t_[node] = std::min(t_[2 * node], t_[2 * node + 1]);
    }

    int n_;
    std::vector<int> t_;
};

int main()
{
    MinTree temps({ 12, 9, 15, 7, 11, 14, 8, 10 });
    std::cout << "coldest in hours 0..2: " << temps.min(0, 2) << ", 2..6: " << temps.min(2, 6) << '\n';
    temps.set(3, 13);
    std::cout << "after correcting hour 3, coldest in 2..6: " << temps.min(2, 6) << '\n';
}

The value for "no overlap" must be the operation's identity: INT_MAX for minimum, 0 for sums, 1 for products.

Range updates and lazy propagation

What if an update changes a whole range ("add 5 to every element from 100 to 900")? Updating each leaf costs O(n). Lazy propagation stores a pending update at the highest nodes that cover the range and pushes it down to the children only when a later operation needs to look inside. Both range updates and range queries become O(log n). It is the segment tree's most powerful extension, and the stretch goal of practice 4.04.

Summary

  • Prefix sums answer static range sums in O(1) but updates cost O(n).
  • A Fenwick tree stores block sums sized by the lowest set bit: O(log n) update and prefix sum in a few lines.
  • A segment tree stores the answer for every segment of a recursive halving: O(log n) point updates and range queries for any associative operation.
  • Lazy propagation adds O(log n) range updates.
