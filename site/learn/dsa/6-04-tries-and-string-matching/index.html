Tries and String Matching

lesson 6.044 of 5 in milestone 67 min1 practice task

Data structures and algorithms for text - tries for prefix lookups and autocompletion, the cost of naive substring search, the Knuth-Morris-Pratt algorithm and its prefix function, Rabin-Karp with a rolling hash, what std::string::find and std::search do, and a glance at suffix arrays and Aho-Corasick for many patterns.

Tries

A trie (from retrieval, usually pronounced "try") is a tree that stores a set of strings by their characters. Each edge is a character, each path from the root spells a prefix, and a node is marked if the path to it is a complete word.

flowchart TB
    R(( )) -- t --> T(( ))
    T -- o --> TO((to))
    T -- e --> TE(( ))
    TE -- a --> TEA((tea))
    TE -- n --> TEN((ten))
    R -- i --> I((i))
    I -- n --> IN((in))
    IN -- n --> INN((inn))

The trie above holds "to", "tea", "ten", "i", "in" and "inn". Looking up a word of length L takes O(L), however many words are stored. And unlike a hash table, a trie answers prefix questions directly: every word starting with "te" lies in the subtree below the node for "te". That makes tries the natural structure for autocompletion, spelling suggestions, IP routing tables (longest prefix match) and word games.

C++
#include <array>
#include <iostream>
#include <memory>
#include <string>
#include <vector>

class Trie
{
public:
    void insert(const std::string& word)
    {
        Node* n = &root_;
        for (char ch : word)
        {
            auto& child = n->next[ch - 'a'];
            if (!child) child = std::make_unique<Node>();
            n = child.get();
            ++n->passing;                          // how many words go through this node
        }
        n->word = true;
    }

    bool contains(const std::string& word) const { const Node* n = walk(word); return n && n->word; }
    int countPrefix(const std::string& prefix) const { const Node* n = walk(prefix); return n ? n->passing : 0; }

    std::vector<std::string> complete(const std::string& prefix, std::size_t limit) const
    {
        std::vector<std::string> out;
        std::string current = prefix;
        if (const Node* n = walk(prefix)) collect(n, current, limit, out);
        return out;
    }

private:
    struct Node
    {
        std::array<std::unique_ptr<Node>, 26> next{};
        bool word = false;
        int passing = 0;
    };

    const Node* walk(const std::string& s) const
    {
        const Node* n = &root_;
        for (char ch : s)
        {
            n = n->next[ch - 'a'].get();
            if (!n) return nullptr;
        }
        return n;
    }

    static void collect(const Node* n, std::string& current, std::size_t limit, std::vector<std::string>& out)
    {
        if (out.size() >= limit) return;
        if (n->word) out.push_back(current);
        for (int c = 0; c < 26; ++c)                // children in alphabetical order
            if (n->next[c])
            {
                current.push_back(static_cast<char>('a' + c));
                collect(n->next[c].get(), current, limit, out);
                current.pop_back();
            }
    }

    Node root_;
};

int main()
{
    Trie t;
    for (std::string w : { "tea", "ten", "to", "inn", "in", "i", "team", "tease", "tent" }) t.insert(w);
    std::cout << "contains te? " << t.contains("te") << ", contains tea? " << t.contains("tea") << '\n';
    std::cout << "words starting with te: " << t.countPrefix("te") << '\n';
    for (const auto& w : t.complete("te", 3)) std::cout << w << ' ';
    std::cout << '\n';
}

A depth-first walk visits children in alphabetical order, so completions come out sorted. The price of a trie is memory: an array of 26 pointers per node adds up. Compact variants store children in a small sorted vector or a hash map, or merge chains of single-child nodes (a radix tree).

Finding a pattern in a text

How do you find every occurrence of a pattern P (length m) in a text T (length n)? The obvious way tries every starting position and compares character by character: O(n × m) in the worst case. Searching for aaaab in a text of a million as compares almost five characters at every one of a million positions, and the work is thrown away each time.

Knuth-Morris-Pratt

The KMP algorithm (1977) never moves backwards in the text. When a mismatch happens after matching some characters, it already knows what those characters were (they are the start of the pattern), so it can tell how much of the pattern still matches without looking at the text again.

That information is the prefix function: pi[i] is the length of the longest proper prefix of P[0..i] that is also a suffix of it. For ababaca: 0 0 1 2 3 0 1. After a mismatch with k characters matched, KMP continues as if pi[k − 1] characters matched.

C++
#include <iostream>
#include <string>
#include <vector>

std::vector<int> prefixFunction(const std::string& p)
{
    std::vector<int> pi(p.size(), 0);
    for (std::size_t i = 1, k = 0; i < p.size(); ++i)
    {
        while (k > 0 && p[i] != p[k]) k = pi[k - 1];      // fall back to a shorter border
        if (p[i] == p[k]) ++k;
        pi[i] = static_cast<int>(k);
    }
    return pi;
}

std::vector<std::size_t> kmpSearch(const std::string& text, const std::string& p)
{
    std::vector<std::size_t> found;
    if (p.empty()) return found;
    std::vector<int> pi = prefixFunction(p);
    for (std::size_t i = 0, k = 0; i < text.size(); ++i)
    {
        while (k > 0 && text[i] != p[k]) k = pi[k - 1];
        if (text[i] == p[k]) ++k;
        if (k == p.size())
        {
            found.push_back(i + 1 - p.size());
            k = pi[k - 1];                                // keep going: matches may overlap
        }
    }
    return found;
}

int main()
{
    for (int v : prefixFunction("ababaca")) std::cout << v << ' ';
    std::cout << '\n';
    for (auto pos : kmpSearch("abababcabababcab", "ababc")) std::cout << pos << ' ';
    std::cout << '\n';
    std::string big(1000000, 'a');
    big += 'b';
    std::cout << "found at " << kmpSearch(big, "aaaab")[0] << '\n';
}

The while loop inside the for loop looks quadratic, but k goes up by at most one per character and every step of the while lowers it, so the total work is O(n + m): the same amortised reasoning as the sliding-window deque in lesson 1.05.

Rabin-Karp: matching with hashes

Rabin-Karp compares hashes instead of characters. It computes the polynomial hash of the pattern and of each window of the text, sliding the window in O(1) per step with the rolling hash from practice 2.02. Only when the hashes are equal does it compare the actual characters, to rule out a collision. The expected time is O(n + m). Its strength is searching for many patterns of the same length at once (put their hashes in a hash set), and spotting repeated substrings, as plagiarism detectors do.

In the standard library

std::string::find is usually a simple, highly optimised search (often using memchr to jump to candidate first characters), fast in practice but O(n × m) in the worst case. C++17 added std::search with searcher objects, including std::boyer_moore_searcher and std::boyer_moore_horspool_searcher. Boyer-Moore compares the pattern from its last character and uses mismatches to skip ahead by up to m characters, so on ordinary text it looks at only a fraction of the characters.

C++
#include <algorithm>
#include <functional>
#include <iostream>
#include <string>

int main()
{
    std::string text = "the quick brown fox jumps over the lazy dog";
    std::string pattern = "lazy";
    auto it = std::search(text.begin(), text.end(), std::boyer_moore_searcher(pattern.begin(), pattern.end()));
    std::cout << "found at " << (it - text.begin()) << '\n';
    std::cout << "find: " << text.find("the", 1) << '\n';
}

More text structures

  • Aho-Corasick builds a trie of many patterns with KMP-like failure links and finds all of them in one pass over the text: antivirus scanners and grep -F with many words.
  • A suffix array is the sorted list of all suffixes of a text; with it, any pattern can be found by binary search in O(m log n), and it reveals repeated substrings. Suffix trees and the FM-index (behind DNA read aligners) push this further.

Summary

  • A trie stores strings character by character: O(L) lookups, prefix counts and sorted autocompletion.
  • Naive substring search is O(n × m) in the worst case.
  • KMP uses the prefix function to never re-read text: O(n + m).
  • Rabin-Karp matches rolling hashes and shines with many patterns of the same length.
  • The standard library offers find and Boyer-Moore searchers; Aho-Corasick and suffix arrays handle bigger text problems.
