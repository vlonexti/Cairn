Union-Find

lesson 4.055 of 5 in milestone 46 min1 practice task

Tracking groups that merge - the disjoint-set problem, a forest of parent pointers, find and union, union by size or rank, path compression, the nearly constant inverse-Ackermann bound, counting components and component sizes, and applications such as connectivity, image regions, percolation and (in lesson 5.04) Kruskal's algorithm.

The problem

Imagine a network of computers where cables are added one at a time, and at any moment you may be asked: "can computer 17 reach computer 42?". Or pixels in an image being merged into regions, or friends forming groups. Each case is a collection of disjoint sets that only ever merge:

  • union(a, b): merge the set containing a with the set containing b,
  • find(a): which set is a in? Two elements are connected if they have the same answer.

Searching the graph for every question is O(n) or more. Union-find (also called a disjoint-set union, DSU) answers both operations in practically constant time.

A forest of parent pointers

Each set is a tree, and each element points to its parent; a root points to itself and acts as the set's representative. find follows parent pointers up to the root. union finds both roots and makes one the parent of the other.

Here {0, 1, 2, 3} and {4, 5, 6} are two sets, with roots 0 and 4. Elements are numbered 0 to n − 1, so the parents fit in a std::vector<int>.

Two improvements

Done naively, the trees can become long chains, and find degrades to O(n). Two simple tricks fix that.

Union by size: when merging, attach the root of the smaller tree under the root of the larger one. A node's depth then grows only when its tree at least doubles in size, so no tree is deeper than log₂ n. (Union by rank, an upper bound on the height, works the same way.)

Path compression: during find, once the root is known, point every node on the way directly at the root. Later finds for any of them take one step.

With both, any sequence of m operations on n elements takes O(m · α(n)), where α is the inverse Ackermann function. It grows so slowly that α(n) ≤ 4 for any n that could ever fit in a computer: effectively constant.

C++
#include <iostream>
#include <numeric>
#include <utility>
#include <vector>

class UnionFind
{
public:
    explicit UnionFind(int n) : parent_(n), size_(n, 1), components_(n)
    {
        std::iota(parent_.begin(), parent_.end(), 0);          // everyone starts as their own root
    }

    int find(int x)
    {
        int root = x;
        while (parent_[root] != root) root = parent_[root];
        while (parent_[x] != root)                             // path compression
        {
            int next = parent_[x];
            parent_[x] = root;
            x = next;
        }
        return root;
    }

    bool unite(int a, int b)
    {
        a = find(a);
        b = find(b);
        if (a == b) return false;                               // already in the same set
        if (size_[a] < size_[b]) std::swap(a, b);               // union by size: b is the smaller tree
        parent_[b] = a;
        size_[a] += size_[b];
        --components_;
        return true;
    }

    bool connected(int a, int b) { return find(a) == find(b); }
    int sizeOf(int x) { return size_[find(x)]; }
    int components() const { return components_; }

private:
    std::vector<int> parent_, size_;
    int components_;
};

int main()
{
    UnionFind uf(10);
    std::vector<std::pair<int, int>> cables{ { 0, 1 }, { 2, 3 }, { 1, 3 }, { 5, 6 }, { 7, 8 }, { 8, 9 }, { 2, 0 } };
    for (auto [a, b] : cables)
        std::cout << "unite(" << a << ", " << b << ") " << (uf.unite(a, b) ? "merged" : "already together") << '\n';
    std::cout << "connected(0, 3)? " << uf.connected(0, 3) << ", connected(4, 5)? " << uf.connected(4, 5) << '\n';
    std::cout << uf.components() << " groups; the group of 9 has " << uf.sizeOf(9) << " members\n";
}

unite returning false when the two are already connected is useful: in a graph, it means the new edge closes a cycle.

What it can and cannot do

Union-find answers "are these connected?" and "how big is this group?" but not "how are they connected?" (the path) and it cannot split sets: there is no efficient "un-union". For paths, use graph search (lesson 5.01). If edges are removed over time, a common trick is to process the operations backwards, so removals become unions.

Applications

  • Dynamic connectivity: networks, friend groups, "are these two accounts linked?".
  • Image processing: labelling connected regions of pixels (unite each pixel with matching neighbours).
  • Percolation: in a grid of open and blocked cells, does water flow from the top to the bottom? Unite open neighbours, plus a virtual "top" and "bottom" node; it percolates when top and bottom are connected. Physicists use this to study phase transitions.
  • Kruskal's minimum spanning tree (lesson 5.04): add edges cheapest first, skipping any edge whose ends are already connected.
  • Grouping equivalences: merging accounts that share an email, or variables known to be equal in a compiler.

Summary

  • Union-find maintains disjoint sets under merging: find gives a set's root, unite links two roots.
  • Union by size (or rank) keeps trees shallow; path compression flattens them as they are used.
  • Together they make each operation O(α(n)), effectively constant.
  • It answers connectivity and group sizes, detects cycles, and powers Kruskal's algorithm, but cannot split sets or report paths.
