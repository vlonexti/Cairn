Linked Lists

lesson 1.044 of 5 in milestone 17 min1 practice task

Nodes connected by pointers - singly linked lists with push_front, insertion after a node and reversal, owning nodes with std::unique_ptr, doubly linked lists with a sentinel, the costs compared with a vector, std::list and std::forward_list, and the two-pointer techniques for finding the middle and detecting a cycle.

Nodes and links

A linked list stores each element in its own node, which also holds a pointer to the next node. The list itself only remembers the first node, the head.

flowchart LR
    head(["head"]) --> A["7 | next"] --> B["3 | next"] --> C["9 | next"] --> N(["nullptr"])

Because nodes are linked rather than adjacent, inserting or removing a node only rewires a couple of pointers: O(1) once you are at the right place. The price is that there is no list[i]: reaching the i-th node means following i links, O(i).

A singly linked list

C++
#include <iostream>

struct Node
{
    int value;
    Node* next;
};

int main()
{
    Node* head = nullptr;
    for (int x : { 9, 3, 7 })
        head = new Node{ x, head };            // push_front: O(1)

    for (Node* n = head; n != nullptr; n = n->next)
        std::cout << n->value << ' ';
    std::cout << '\n';

    // insert 5 after the node holding 3
    for (Node* n = head; n != nullptr; n = n->next)
        if (n->value == 3) { n->next = new Node{ 5, n->next }; break; }

    // reverse the list in place: O(n), O(1) extra space
    Node* previous = nullptr;
    while (head != nullptr)
    {
        Node* next = head->next;
        head->next = previous;
        previous = head;
        head = next;
    }
    head = previous;

    for (Node* n = head; n != nullptr; n = n->next)
        std::cout << n->value << ' ';
    std::cout << '\n';

    while (head != nullptr)                    // free every node
    {
        Node* next = head->next;
        delete head;
        head = next;
    }
}

Reversal is the classic linked-list exercise: walk the list once, turning each next pointer around. Draw the three pointers (previous, head, next) on paper for a three-node list and the loop becomes obvious.

Owning the nodes

Raw new and delete make it easy to leak or double-free nodes. In modern C++ each node can own the next one through a std::unique_ptr: destroying the head destroys the whole chain.

C++
#include <iostream>
#include <memory>

struct Node
{
    int value;
    std::unique_ptr<Node> next;
};

class IntList
{
public:
    void push_front(int value) { head_ = std::make_unique<Node>(Node{ value, std::move(head_) }); ++size_; }
    void pop_front() { if (head_) { head_ = std::move(head_->next); --size_; } }
    std::size_t size() const { return size_; }

    void print() const
    {
        for (const Node* n = head_.get(); n; n = n->next.get()) std::cout << n->value << ' ';
        std::cout << '\n';
    }

    ~IntList() { while (head_) head_ = std::move(head_->next); }   // iterative, so a long list cannot overflow the stack

private:
    std::unique_ptr<Node> head_;
    std::size_t size_ = 0;
};

int main()
{
    IntList list;
    for (int i = 1; i <= 5; ++i) list.push_front(i);
    list.pop_front();
    list.print();
    std::cout << "size " << list.size() << '\n';
}

The destructor matters: the default one destroys head_, which destroys its next, which destroys its next... one nested call per node. A list of a million nodes would overflow the call stack. Unlinking one node at a time in a loop avoids that.

Doubly linked lists and sentinels

A doubly linked list gives each node a prev pointer too, so you can walk backwards and remove a node knowing only its address. Implementations often add a sentinel: a dummy node that sits before the first and after the last element, making the list circular. Then there are no special cases for an empty list or for the ends: every real node always has a real prev and next.

flowchart LR
    S(["sentinel"]) <--> A["7"] <--> B["3"] <--> C["9"] <--> S
C++
#include <iostream>

struct DNode
{
    int value;
    DNode* prev;
    DNode* next;
};

void insertBefore(DNode* pos, int value)
{
    DNode* n = new DNode{ value, pos->prev, pos };
    pos->prev->next = n;
    pos->prev = n;
}

void unlink(DNode* n)
{
    n->prev->next = n->next;
    n->next->prev = n->prev;
    delete n;
}

int main()
{
    DNode sentinel{ 0, &sentinel, &sentinel };            // empty: points to itself
    for (int x : { 1, 2, 3, 4 }) insertBefore(&sentinel, x);   // push_back
    insertBefore(sentinel.next, 0);                       // push_front
    unlink(sentinel.next->next->next);                    // remove the third node (2)

    for (DNode* n = sentinel.next; n != &sentinel; n = n->next) std::cout << n->value << ' ';
    std::cout << "| backwards: ";
    for (DNode* n = sentinel.prev; n != &sentinel; n = n->prev) std::cout << n->value << ' ';
    std::cout << '\n';

    while (sentinel.next != &sentinel) unlink(sentinel.next);
}

Notice that insertBefore and unlink contain no ifs at all. That is the point of the sentinel. std::list is built this way.

Lists or vectors?

Operation std::vector linked list
index i O(1) O(i)
push/pop at the back amortised O(1) O(1) (doubly linked)
push/pop at the front O(n) O(1)
insert/erase at a known node O(n) O(1)
find a value O(n) O(n)
memory per element the element the element + 1 or 2 pointers + allocation overhead
cache behaviour excellent poor: every step can miss the cache

On paper the list wins at inserting in the middle. In practice you must first find the middle, which is O(n) pointer chasing, and a vector's O(n) shifting of contiguous memory is so fast that vectors usually win anyway. Lists win when you already hold pointers to nodes and splice them around: LRU caches (the milestone 2 project), free lists in allocators, and the ready queues of schedulers.

The standard library has std::list (doubly linked, with splice to move nodes between lists in O(1)) and std::forward_list (singly linked, the smallest).

Two-pointer techniques

Several list problems are solved by walking two pointers at different speeds.

The middle node: move slow one step and fast two steps; when fast reaches the end, slow is in the middle.

Cycle detection (Floyd's "tortoise and hare"): if a list loops back on itself, a fast pointer eventually laps the slow one and they meet. If there is no cycle, the fast pointer reaches nullptr. O(n) time, O(1) space.

C++
#include <iostream>
#include <vector>

struct Node { int value; Node* next; };

Node* middle(Node* head)
{
    Node* slow = head;
    Node* fast = head;
    while (fast && fast->next) { slow = slow->next; fast = fast->next->next; }
    return slow;
}

bool hasCycle(Node* head)
{
    Node* slow = head;
    Node* fast = head;
    while (fast && fast->next)
    {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;
    }
    return false;
}

int main()
{
    std::vector<Node> nodes(7);
    for (int i = 0; i < 7; ++i) nodes[i] = { i * 10, i + 1 < 7 ? &nodes[i + 1] : nullptr };
    std::cout << "middle " << middle(&nodes[0])->value << ", cycle " << hasCycle(&nodes[0]) << '\n';
    nodes[6].next = &nodes[2];                     // make the tail point back into the list
    std::cout << "after linking the tail back: cycle " << hasCycle(&nodes[0]) << '\n';
}

Summary

  • A linked list stores elements in nodes joined by pointers: O(1) to insert or remove at a known node, O(i) to reach position i.
  • Own nodes with std::unique_ptr and destroy long lists iteratively.
  • Doubly linked lists with a sentinel remove every special case.
  • Vectors usually beat lists in practice because of the cache; lists shine when you keep pointers to nodes and splice them.
  • Fast and slow pointers find the middle and detect cycles in O(1) space.
