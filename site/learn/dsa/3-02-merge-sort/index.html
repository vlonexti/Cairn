Merge Sort

lesson 3.022 of 5 in milestone 37 min1 practice task

Divide and conquer - merging two sorted halves in linear time, top-down merge sort and its recursion tree, the recurrence T(n) = 2T(n/2) + n and the master theorem in practice, stability and the extra buffer, bottom-up merge sort, counting inversions while merging, and the Ω(n log n) lower bound for comparison sorting.

Divide and conquer

Divide and conquer solves a problem by splitting it into smaller copies of itself, solving those recursively, and combining the answers. Merge sort is the textbook example:

  1. Divide the array into two halves.
  2. Conquer: sort each half recursively (an array of 0 or 1 elements is already sorted).
  3. Combine: merge the two sorted halves into one sorted array.

Merging

Merging two sorted sequences is easy and fast: look at the front of each, take the smaller, repeat. Each step outputs one element, so merging a total of n elements takes O(n).

C++
#include <iostream>
#include <vector>

std::vector<int> merge(const std::vector<int>& a, const std::vector<int>& b)
{
    std::vector<int> out;
    out.reserve(a.size() + b.size());
    std::size_t i = 0, j = 0;
    while (i < a.size() && j < b.size())
        out.push_back(b[j] < a[i] ? b[j++] : a[i++]);     // take from a on ties: that keeps the sort stable
    while (i < a.size()) out.push_back(a[i++]);
    while (j < b.size()) out.push_back(b[j++]);
    return out;
}

int main()
{
    for (int x : merge({ 1, 4, 9, 12 }, { 2, 3, 10 })) std::cout << x << ' ';
    std::cout << '\n';
}

Merge sort

The full sort recurses on index ranges and merges through one shared buffer, so it allocates only once:

C++
#include <iostream>
#include <vector>

void mergeSort(std::vector<int>& a, std::vector<int>& buffer, std::size_t lo, std::size_t hi)   // sorts [lo, hi)
{
    if (hi - lo < 2) return;
    std::size_t mid = lo + (hi - lo) / 2;
    mergeSort(a, buffer, lo, mid);
    mergeSort(a, buffer, mid, hi);

    std::size_t i = lo, j = mid, k = lo;
    while (i < mid && j < hi) buffer[k++] = a[j] < a[i] ? a[j++] : a[i++];
    while (i < mid) buffer[k++] = a[i++];
    while (j < hi) buffer[k++] = a[j++];
    for (k = lo; k < hi; ++k) a[k] = buffer[k];
}

void mergeSort(std::vector<int>& a)
{
    std::vector<int> buffer(a.size());
    mergeSort(a, buffer, 0, a.size());
}

int main()
{
    std::vector<int> a{ 38, 27, 43, 3, 9, 82, 10 };
    mergeSort(a);
    for (int x : a) std::cout << x << ' ';
    std::cout << '\n';
}

Why it is O(n log n)

Draw the recursion as a tree. The top level merges n elements. The next level has two merges of n/2: n in total. The level below has four merges of n/4: n again. Every level does O(n) work, and halving reaches size 1 after log₂ n levels.

flowchart TB
    A["n"] --> B["n/2"] & C["n/2"]
    B --> D["n/4"] & E["n/4"]
    C --> F["n/4"] & G["n/4"]
    D --> H["..."]
    G --> I["..."]

Total: O(n log n), in the best, average and worst case. Merge sort has no bad inputs.

The same reasoning, written as a recurrence, is T(n) = 2T(n/2) + O(n). Recurrences of the form T(n) = a·T(n/b) + O(nᵈ) are solved by the master theorem: compare a with bᵈ.

Case Result Example
a < bᵈ O(nᵈ): the top level dominates T(n) = T(n/2) + n → O(n)
a = bᵈ O(nᵈ log n): every level costs the same merge sort: a = 2, b = 2, d = 1 → O(n log n)
a > bᵈ O(n^(log_b a)): the leaves dominate T(n) = 4T(n/2) + n → O(n²)

Binary search is T(n) = T(n/2) + O(1): a = 1 = 2⁰, so O(log n).

Properties

  • Stable, if the merge takes from the left half on ties.
  • Not in place: it needs an O(n) buffer.
  • Predictable: always O(n log n), with sequential memory access that suits caches, disks and linked lists. It is the standard way to sort data too big for memory (external sorting: sort chunks, then merge them).

std::stable_sort is a merge sort. It uses a buffer if it can get one, and falls back to a slower O(n log² n) in-place merge if memory runs out.

Bottom-up merge sort

The recursion can be replaced by loops: merge runs of width 1 into runs of width 2, then 4, then 8, until one run covers everything.

C++
#include <algorithm>
#include <iostream>
#include <vector>

void bottomUpMergeSort(std::vector<int>& a)
{
    std::vector<int> buffer(a.size());
    for (std::size_t width = 1; width < a.size(); width *= 2)
    {
        for (std::size_t lo = 0; lo < a.size(); lo += 2 * width)
        {
            std::size_t mid = std::min(lo + width, a.size()), hi = std::min(lo + 2 * width, a.size());
            std::merge(a.begin() + lo, a.begin() + mid, a.begin() + mid, a.begin() + hi, buffer.begin() + lo);
        }
        a.swap(buffer);
    }
}

int main()
{
    std::vector<int> a{ 5, 1, 4, 2, 8, 0, 2, 9, 7 };
    bottomUpMergeSort(a);
    for (int x : a) std::cout << x << ' ';
    std::cout << '\n';
}

std::merge merges two sorted ranges into an output; swapping the vectors avoids copying back after each pass. Python's and Java's object sort, Timsort, is a refined bottom-up merge sort that first finds runs that are already in order, which makes it extremely fast on real-world, partly sorted data.

Counting inversions in O(n log n)

Lesson 3.01 measured disorder by counting inversions. Comparing every pair is O(n²), but merge sort can count them on the way: when the merge takes an element from the right half, that element is smaller than every element still waiting in the left half, so it forms an inversion with each of them.

C++
#include <iostream>
#include <vector>

long long sortCount(std::vector<int>& a, std::vector<int>& buf, std::size_t lo, std::size_t hi)
{
    if (hi - lo < 2) return 0;
    std::size_t mid = lo + (hi - lo) / 2;
    long long count = sortCount(a, buf, lo, mid) + sortCount(a, buf, mid, hi);
    std::size_t i = lo, j = mid, k = lo;
    while (i < mid && j < hi)
    {
        if (a[j] < a[i]) { count += static_cast<long long>(mid - i); buf[k++] = a[j++]; }
        else buf[k++] = a[i++];
    }
    while (i < mid) buf[k++] = a[i++];
    while (j < hi) buf[k++] = a[j++];
    for (k = lo; k < hi; ++k) a[k] = buf[k];
    return count;
}

int main()
{
    std::vector<int> a{ 2, 4, 1, 3, 5 };
    std::vector<int> buf(a.size());
    std::cout << sortCount(a, buf, 0, a.size()) << " inversions\n";     // (2,1), (4,1), (4,3)
}

This counts how "different" two rankings are (the Kendall tau distance), used in recommendation systems and statistics.

The lower bound: no comparison sort beats n log n

Any sort that learns about the input only by comparing elements needs Ω(n log n) comparisons in the worst case. The argument: there are n! possible orders of the input, and each comparison has two outcomes, so after c comparisons the algorithm can tell apart at most 2ᶜ orders. To distinguish all n!, it needs 2ᶜ ≥ n!, so c ≥ log₂(n!), which is about n log₂ n.

So merge sort, heapsort and (on average) quicksort are optimal among comparison sorts. Lesson 3.05 escapes the bound by not comparing at all.

Summary

  • Merge sort splits, sorts halves recursively, and merges in O(n): O(n log n) in every case.
  • The master theorem solves divide-and-conquer recurrences by comparing a with bᵈ.
  • It is stable and predictable but needs an O(n) buffer; std::stable_sort and Timsort are merge sorts.
  • Merging can count inversions in O(n log n).
  • Comparison sorting needs Ω(n log n) comparisons.
