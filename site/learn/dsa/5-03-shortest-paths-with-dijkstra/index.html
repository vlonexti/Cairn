Shortest Paths with Dijkstra

lesson 5.033 of 5 in milestone 57 min1 practice task

Shortest paths when edges have weights - why BFS no longer works, relaxation, Dijkstra's algorithm with a priority queue and lazy deletion, its O((V + E) log V) cost, rebuilding routes, why negative weights break it, Bellman-Ford and negative cycles, 0-1 BFS, and choosing the right shortest-path algorithm.

Weighted edges

On a map, roads have lengths or travel times. The route with the fewest roads is not necessarily the fastest: a motorway with three junctions can beat a single slow mountain road. BFS counts edges, so for weighted graphs we need something else.

Formally: each edge u → v has a weight w(u, v) ≥ 0, the length of a path is the sum of its weights, and we want dist[v], the length of the shortest path from a source s to every vertex v.

Relaxation

Every shortest-path algorithm is built on one operation. Keep a best-known distance dist[v] for every vertex (∞ at first, 0 for the source). Relaxing an edge u → v asks: is going through u better than what I know?

Output
if dist[u] + w(u, v) < dist[v]:
    dist[v] = dist[u] + w(u, v)
    parent[v] = u

The algorithms differ only in which edges they relax, in what order.

Dijkstra's algorithm

Edsger Dijkstra's idea (1956): always process the unfinished vertex with the smallest known distance next. With non-negative weights, that distance can never improve later, since any other route would have to go through a vertex that is already at least as far. So the vertex is finished, and we relax its outgoing edges.

A min-heap of (distance, vertex) pairs finds the smallest each time. When a distance improves, push the new pair; the old one stays in the heap and is skipped when popped because it is out of date ("lazy deletion"). This is simpler than updating entries inside the heap and just as fast in practice.

C++
#include <algorithm>
#include <functional>
#include <iostream>
#include <limits>
#include <queue>
#include <string>
#include <utility>
#include <vector>

using Graph = std::vector<std::vector<std::pair<int, long long>>>;    // (neighbour, weight)
const long long INF = std::numeric_limits<long long>::max();

std::pair<std::vector<long long>, std::vector<int>> dijkstra(const Graph& g, int source)
{
    std::vector<long long> dist(g.size(), INF);
    std::vector<int> parent(g.size(), -1);
    using Item = std::pair<long long, int>;                             // (distance, vertex)
    std::priority_queue<Item, std::vector<Item>, std::greater<Item>> pq;
    dist[source] = 0;
    pq.push({ 0, source });
    while (!pq.empty())
    {
        auto [d, u] = pq.top();
        pq.pop();
        if (d > dist[u]) continue;                                      // an out-of-date entry
        for (auto [v, w] : g[u])
            if (dist[u] + w < dist[v])
            {
                dist[v] = dist[u] + w;
                parent[v] = u;
                pq.push({ dist[v], v });
            }
    }
    return { dist, parent };
}

int main()
{
    std::vector<std::string> name{ "home", "bakery", "bridge", "park", "school" };
    Graph g(5);
    auto road = [&](int a, int b, long long minutes) { g[a].push_back({ b, minutes }); g[b].push_back({ a, minutes }); };
    road(0, 1, 4); road(0, 2, 1); road(2, 1, 2); road(1, 3, 1); road(2, 3, 5); road(3, 4, 3);

    auto [dist, parent] = dijkstra(g, 0);
    for (int v = 0; v < 5; ++v) std::cout << name[v] << ": " << dist[v] << " min\n";

    std::vector<int> route;
    for (int v = 4; v != -1; v = parent[v]) route.push_back(v);
    std::reverse(route.begin(), route.end());
    std::cout << "route to school:";
    for (int v : route) std::cout << ' ' << name[v];
    std::cout << '\n';
}

The direct road from home to the bakery takes 4 minutes, but going via the bridge takes 1 + 2 = 3: Dijkstra finds it.

Cost: each vertex is finished once, and each edge relaxed once, pushing at most one heap entry. With E heap operations of O(log E) = O(log V) each, Dijkstra runs in O((V + E) log V). For a road network of millions of junctions, that is well under a second. (Production route planners add preprocessing such as contraction hierarchies to answer queries in microseconds.)

To stop early when you only need one target, return as soon as the target is popped (not when it is first pushed: a shorter route may still turn up).

Negative weights break it

Dijkstra assumes a finished vertex can never get a shorter distance. A negative edge breaks that: with edges s → a (2), s → b (5) and b → a (−4), Dijkstra finishes a at distance 2, but s → b → a costs 1.

Negative weights appear in real problems (costs and refunds, currency exchange as log-rates, energy gained and spent). For them use Bellman-Ford: relax every edge, V − 1 times over. After pass i, every shortest path using at most i edges is correct, and a shortest path has at most V − 1 edges. It is O(VE), much slower, but it also detects negative cycles: if a V-th pass still improves something, a cycle with negative total weight exists, and "shortest" is meaningless (you could loop forever, getting cheaper).

C++
#include <iostream>
#include <limits>
#include <optional>
#include <tuple>
#include <vector>

using Edge = std::tuple<int, int, long long>;      // from, to, weight
const long long INF = std::numeric_limits<long long>::max() / 4;

std::optional<std::vector<long long>> bellmanFord(int V, const std::vector<Edge>& edges, int source)
{
    std::vector<long long> dist(V, INF);
    dist[source] = 0;
    for (int pass = 0; pass < V; ++pass)
    {
        bool changed = false;
        for (auto [u, v, w] : edges)
            if (dist[u] != INF && dist[u] + w < dist[v]) { dist[v] = dist[u] + w; changed = true; }
        if (!changed) return dist;                  // settled early
        if (pass == V - 1) return std::nullopt;     // still improving after V - 1 passes: a negative cycle
    }
    return dist;
}

int main()
{
    auto d = bellmanFord(3, { { 0, 1, 2 }, { 0, 2, 5 }, { 2, 1, -4 } }, 0);
    std::cout << "dist to 1: " << (*d)[1] << '\n';
    auto bad = bellmanFord(3, { { 0, 1, 1 }, { 1, 2, -2 }, { 2, 1, 1 } }, 0);
    std::cout << "negative cycle found? " << !bad.has_value() << '\n';
}

Special cases

  • Unweighted (all weights 1): plain BFS, O(V + E).
  • Weights 0 or 1: 0-1 BFS uses a deque, pushing 0-weight neighbours to the front and 1-weight ones to the back. O(V + E).
  • A DAG: relax in topological order (lesson 5.02), O(V + E), and negative weights are fine.
  • All pairs on a small dense graph: Floyd-Warshall, three nested loops, O(V³).
Situation Algorithm Time
unweighted BFS O(V + E)
weights 0/1 0-1 BFS O(V + E)
non-negative weights Dijkstra O((V + E) log V)
DAG, any weights topological order O(V + E)
negative weights Bellman-Ford O(VE)
all pairs, small V Floyd-Warshall O(V³)

Summary

  • Weighted shortest paths repeatedly relax edges: dist[u] + w < dist[v].
  • Dijkstra finishes vertices in order of distance with a min-heap and lazy deletion: O((V + E) log V), non-negative weights only.
  • Parent links rebuild the route; stop early when the target is popped.
  • Bellman-Ford handles negative weights in O(VE) and detects negative cycles.
  • Choose by the weights: BFS, 0-1 BFS, Dijkstra, DAG relaxation, Bellman-Ford or Floyd-Warshall.
