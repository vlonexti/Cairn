Quicksort

lesson 3.033 of 5 in milestone 37 min1 practice task

Sorting by partitioning - the Lomuto and Hoare partition schemes, quicksort's average O(n log n) and worst-case O(n²), choosing pivots at random or by median of three, three-way partitioning for many duplicates, recursing on the smaller side, introsort (std::sort), and quickselect and std::nth_element for the k-th smallest element in linear time.

Partition, then recurse

Quicksort is divide and conquer with the work done before the recursion instead of after:

  1. Choose a pivot element.
  2. Partition: rearrange the array so everything smaller than the pivot comes before it and everything larger after it. The pivot is now in its final place.
  3. Recursively sort the two sides. No combining is needed.

Partitioning is a single O(n) pass with swaps, in place. If the pivot splits the array roughly in half, the recursion is T(n) = 2T(n/2) + O(n) = O(n log n), like merge sort, but with no buffer and a very tight inner loop. In practice it is usually the fastest comparison sort.

Lomuto partition

The simplest scheme uses the last element as the pivot and grows a region of "small" elements at the front:

C++
#include <iostream>
#include <utility>
#include <vector>

// Partitions a[lo..hi] (inclusive) around a[hi]; returns the pivot's final index.
int lomuto(std::vector<int>& a, int lo, int hi)
{
    int pivot = a[hi];
    int small = lo;                                // a[lo..small) are < pivot
    for (int j = lo; j < hi; ++j)
        if (a[j] < pivot) std::swap(a[small++], a[j]);
    std::swap(a[small], a[hi]);
    return small;
}

void quickSort(std::vector<int>& a, int lo, int hi)
{
    if (lo >= hi) return;
    int p = lomuto(a, lo, hi);
    quickSort(a, lo, p - 1);
    quickSort(a, p + 1, hi);
}

int main()
{
    std::vector<int> a{ 10, 80, 30, 90, 40, 50, 70 };
    std::cout << "pivot 70 ends at index " << lomuto(a, 0, 6) << ": ";
    for (int x : a) std::cout << x << ' ';
    quickSort(a, 0, 6);
    std::cout << "\nsorted: ";
    for (int x : a) std::cout << x << ' ';
    std::cout << '\n';
}

Hoare's original scheme moves two indexes towards each other from both ends, swapping pairs that are on the wrong side. It does about three times fewer swaps than Lomuto and handles equal elements better, at the cost of trickier bounds.

The worst case and how to avoid it

If the pivot is always the smallest or largest element, one side is empty and the other has n − 1 elements: T(n) = T(n − 1) + O(n) = O(n²), and the recursion is n levels deep. With "last element as pivot", that happens on already sorted input, which is very common in practice.

Two standard fixes:

  • Random pivot: swap a randomly chosen element into the pivot position first. Then no particular input is bad; the expected time is O(n log n) for every input, and O(n²) becomes astronomically unlikely.
  • Median of three: use the median of the first, middle and last elements. Sorted and reversed inputs become best cases, and it is cheap.
C++
#include <chrono>
#include <iostream>
#include <random>
#include <utility>
#include <vector>

std::mt19937 rng(7);
long long comparisons = 0;

int partition(std::vector<int>& a, int lo, int hi, bool randomPivot)
{
    if (randomPivot) std::swap(a[std::uniform_int_distribution<int>(lo, hi)(rng)], a[hi]);
    int pivot = a[hi], small = lo;
    for (int j = lo; j < hi; ++j)
        if (++comparisons, a[j] < pivot) std::swap(a[small++], a[j]);
    std::swap(a[small], a[hi]);
    return small;
}

void quickSort(std::vector<int>& a, int lo, int hi, bool randomPivot)
{
    while (lo < hi)
    {
        int p = partition(a, lo, hi, randomPivot);
        if (p - lo < hi - p) { quickSort(a, lo, p - 1, randomPivot); lo = p + 1; }   // recurse on the smaller side,
        else { quickSort(a, p + 1, hi, randomPivot); hi = p - 1; }                   // loop on the larger one
    }
}

int main()
{
    for (bool randomPivot : { false, true })
    {
        std::vector<int> a(5000);
        for (int i = 0; i < 5000; ++i) a[i] = i;                // already sorted
        comparisons = 0;
        quickSort(a, 0, 4999, randomPivot);
        std::cout << (randomPivot ? "random pivot: " : "last element: ") << comparisons << " comparisons on sorted input\n";
    }
}

The loop at the end of quickSort is another important detail: recursing only into the smaller side and looping over the larger one keeps the recursion depth at O(log n) even in a bad case, so the stack cannot overflow.

Many duplicates: three-way partitioning

If the array contains many equal elements (say, a million values that are all 0, 1 or 2), two-way partitioning wastes time on them: Lomuto puts all equal elements on one side, which is again O(n²) when everything is equal. Three-way partitioning (Dijkstra's "Dutch national flag") splits into less than, equal to and greater than the pivot, and recurses only on the outer two parts:

C++
#include <iostream>
#include <utility>
#include <vector>

// Rearranges a[lo..hi] into < pivot, == pivot, > pivot. Returns the bounds of the middle part.
std::pair<int, int> partition3(std::vector<int>& a, int lo, int hi, int pivot)
{
    int lt = lo, i = lo, gt = hi;                 // a[lo..lt) < p, a[lt..i) == p, a(gt..hi] > p
    while (i <= gt)
    {
        if (a[i] < pivot) std::swap(a[lt++], a[i++]);
        else if (a[i] > pivot) std::swap(a[i], a[gt--]);
        else ++i;
    }
    return { lt, gt };
}

int main()
{
    std::vector<int> flags{ 2, 0, 1, 2, 1, 0, 0, 2, 1 };
    auto [lt, gt] = partition3(flags, 0, 8, 1);
    for (int x : flags) std::cout << x << ' ';
    std::cout << "| the 1s are at [" << lt << ", " << gt << "]\n";
}

With three-way partitioning, an array of all-equal elements is sorted in a single O(n) pass.

std::sort is introsort

std::sort must be O(n log n) in the worst case, which plain quicksort is not. Library implementations use introsort ("introspective sort"):

  • quicksort with a median-of-three (or similar) pivot,
  • switching to heapsort (lesson 3.04) if the recursion gets deeper than about 2 log₂ n, which only happens on adversarial inputs,
  • and finishing small pieces (under 16 or so elements) with insertion sort.

It is not stable; use std::stable_sort when that matters.

Quickselect: the k-th smallest in O(n)

To find the median, or the k-th smallest element, you do not need to sort. Partition once: if the pivot lands at index k, you are done; otherwise recurse into only the side that contains k. The expected work is n + n/2 + n/4 + ... = O(n).

C++
#include <algorithm>
#include <iostream>
#include <random>
#include <utility>
#include <vector>

int quickSelect(std::vector<int> a, int k)       // the k-th smallest, counting from 0
{
    std::mt19937 rng(1);
    int lo = 0, hi = static_cast<int>(a.size()) - 1;
    while (true)
    {
        std::swap(a[std::uniform_int_distribution<int>(lo, hi)(rng)], a[hi]);
        int pivot = a[hi], small = lo;
        for (int j = lo; j < hi; ++j)
            if (a[j] < pivot) std::swap(a[small++], a[j]);
        std::swap(a[small], a[hi]);
        if (small == k) return a[small];
        if (k < small) hi = small - 1; else lo = small + 1;
    }
}

int main()
{
    std::vector<int> a{ 9, 1, 8, 2, 7, 3, 6, 4, 5 };
    std::cout << "median " << quickSelect(a, 4) << ", smallest " << quickSelect(a, 0) << ", largest " << quickSelect(a, 8) << '\n';

    std::nth_element(a.begin(), a.begin() + 4, a.end());     // the library version
    std::cout << "nth_element: " << a[4] << '\n';
}

The standard library's std::nth_element does exactly this (with introselect's worst-case guard), and std::partial_sort sorts just the first k elements in O(n log k).

Summary

  • Quicksort partitions around a pivot, then sorts each side: O(n log n) on average, in place, very fast.
  • Bad pivots give O(n²); random or median-of-three pivots avoid it, and recursing on the smaller side bounds the stack.
  • Three-way partitioning handles many duplicates.
  • std::sort is introsort: quicksort plus heapsort as a safety net plus insertion sort for small pieces.
  • Quickselect and std::nth_element find the k-th smallest in expected O(n).
