Stacks, Queues and Deques

lesson 1.055 of 5 in milestone 17 min1 practice task

The restricted containers - stacks (last in, first out) for undo, matching brackets and evaluating expressions, queues (first in, first out) built as ring buffers, deques open at both ends, the standard adapters std::stack, std::queue and std::deque, and the monotonic-deque trick for sliding-window maximums.

Restricting a container on purpose

A stack and a queue offer fewer operations than a vector, and that is their strength: the restriction says exactly how the data will be used, and every operation is O(1).

Structure Add Remove Order
Stack push on top pop from the top last in, first out (LIFO)
Queue push at the back pop from the front first in, first out (FIFO)
Deque at either end from either end both

Stacks

A stack is a pile of plates: you only touch the top one. A std::vector makes a perfect stack (push_back, back, pop_back), and std::stack is an adapter that exposes just those operations.

Stacks appear wherever work must be undone or finished in reverse order: the call stack of a program, undo in an editor, the back button in a browser, and depth-first search (lesson 5.02).

Matching brackets is the classic example: push each opening bracket; on a closing bracket the top of the stack must be its partner.

C++
#include <iostream>
#include <stack>
#include <string>

bool balanced(const std::string& text)
{
    std::stack<char> open;
    for (char c : text)
    {
        if (c == '(' || c == '[' || c == '{') open.push(c);
        else if (c == ')' || c == ']' || c == '}')
        {
            char want = c == ')' ? '(' : c == ']' ? '[' : '{';
            if (open.empty() || open.top() != want) return false;
            open.pop();
        }
    }
    return open.empty();
}

int main()
{
    for (std::string s : { "f(a[i], {b})", "(]", "((x)", "" })
        std::cout << '"' << s << "\" " << (balanced(s) ? "balanced" : "not balanced") << '\n';
}

Evaluating expressions

How does a calculator know that 2 + 3 * 4 is 14? Edsger Dijkstra's shunting-yard algorithm uses two stacks, one of numbers and one of operators. When an operator arrives, it first applies every operator on the stack that binds at least as tightly; brackets fence off sub-expressions.

C++
#include <cctype>
#include <iostream>
#include <stack>
#include <stdexcept>
#include <string>

int precedence(char op) { return op == '+' || op == '-' ? 1 : 2; }

void apply(std::stack<long long>& values, std::stack<char>& ops)
{
    char op = ops.top(); ops.pop();
    long long b = values.top(); values.pop();
    long long a = values.top(); values.pop();
    switch (op)
    {
    case '+': values.push(a + b); break;
    case '-': values.push(a - b); break;
    case '*': values.push(a * b); break;
    case '/': if (b == 0) throw std::domain_error("division by zero"); values.push(a / b); break;
    }
}

long long evaluate(const std::string& text)
{
    std::stack<long long> values;
    std::stack<char> ops;
    for (std::size_t i = 0; i < text.size(); ++i)
    {
        char c = text[i];
        if (std::isspace(static_cast<unsigned char>(c))) continue;
        if (std::isdigit(static_cast<unsigned char>(c)))
        {
            long long n = 0;
            while (i < text.size() && std::isdigit(static_cast<unsigned char>(text[i]))) n = n * 10 + (text[i++] - '0');
            --i;
            values.push(n);
        }
        else if (c == '(') ops.push(c);
        else if (c == ')')
        {
            while (ops.top() != '(') apply(values, ops);
            ops.pop();
        }
        else
        {
            while (!ops.empty() && ops.top() != '(' && precedence(ops.top()) >= precedence(c)) apply(values, ops);
            ops.push(c);
        }
    }
    while (!ops.empty()) apply(values, ops);
    return values.top();
}

int main()
{
    for (std::string e : { "2 + 3 * 4", "(2 + 3) * 4", "100 / 10 / 5", "7 - 2 - 1", "2 * (3 + 4) * 5" })
        std::cout << e << " = " << evaluate(e) << '\n';
}

The >= makes operators of equal precedence apply left to right, so 7 - 2 - 1 is (7 - 2) - 1 = 4. This sketch trusts its input; the milestone project makes it robust, with error messages for every kind of mistake.

Queues

A queue is a line at a shop: people join at the back and leave from the front. Queues hold work in the order it arrived: print jobs, network packets, events in a game, and the frontier of breadth-first search (lesson 5.01).

A vector is a poor queue, because removing from the front is O(n). A ring buffer (circular buffer) fixes that: keep the elements in a fixed array with a head index, and let the indexes wrap around with %.

flowchart LR
    s0["0: E"] --- s1["1: F"] --- s2["2: ·"] --- s3["3: ·"] --- s4["4: B"] --- s5["5: C"] --- s6["6: D"]
    h(["head = 4"]) -.-> s4
    t(["tail = 2"]) -.-> s2

The queue above holds B, C, D, E, F in that order: the elements after the end of the array continue at the start.

C++
#include <iostream>
#include <stdexcept>
#include <vector>

class RingQueue
{
public:
    explicit RingQueue(std::size_t capacity) : slots_(capacity) {}

    void push(int value)
    {
        if (size_ == slots_.size()) throw std::length_error("queue full");
        slots_[(head_ + size_) % slots_.size()] = value;
        ++size_;
    }
    int pop()
    {
        if (size_ == 0) throw std::out_of_range("queue empty");
        int value = slots_[head_];
        head_ = (head_ + 1) % slots_.size();
        --size_;
        return value;
    }
    std::size_t size() const { return size_; }

private:
    std::vector<int> slots_;
    std::size_t head_ = 0;
    std::size_t size_ = 0;
};

int main()
{
    RingQueue q(4);
    for (int i = 1; i <= 4; ++i) q.push(i);
    std::cout << q.pop() << ' ' << q.pop() << ' ';
    q.push(5);
    q.push(6);                                      // these wrap around to the start of the array
    while (q.size() > 0) std::cout << q.pop() << ' ';
    std::cout << '\n';
}

A fixed-size ring buffer is ideal for audio samples, logs that keep the last N lines, and producer-consumer queues. To grow it, allocate a bigger array and copy the elements across in queue order, exactly like a vector (practice 1.05 does this).

Deques and the standard adapters

A deque ("deck", double-ended queue) supports push and pop at both ends in O(1), and still allows indexing. std::deque stores its elements in fixed-size blocks with a table of pointers to them, so it can grow at either end without moving existing elements.

Type What it is Underlying container
std::stack<T> push, pop, top std::deque by default; std::stack<T, std::vector<T>> is common
std::queue<T> push, pop, front, back std::deque
std::deque<T> both ends plus [i] blocks of elements

Note that pop() returns nothing in the standard adapters: read top() or front() first. This is so that a copy constructor that throws cannot lose an element.

The sliding-window maximum

Given a sequence and a window of size k, report the maximum of every window. Recomputing each one costs O(nk). A deque of indexes whose values are kept in decreasing order does it in O(n): each new value pushes out the smaller values behind it (they can never be a maximum again), and the front falls off when it leaves the window.

C++
#include <deque>
#include <iostream>
#include <vector>

std::vector<int> windowMax(const std::vector<int>& a, std::size_t k)
{
    std::deque<std::size_t> idx;            // indexes into a, values decreasing from front to back
    std::vector<int> result;
    for (std::size_t i = 0; i < a.size(); ++i)
    {
        while (!idx.empty() && a[idx.back()] <= a[i]) idx.pop_back();
        idx.push_back(i);
        if (idx.front() + k <= i) idx.pop_front();
        if (i + 1 >= k) result.push_back(a[idx.front()]);
    }
    return result;
}

int main()
{
    for (int m : windowMax({ 1, 3, -1, -3, 5, 3, 6, 7 }, 3)) std::cout << m << ' ';
    std::cout << '\n';
}

Every index enters and leaves the deque at most once, so the whole thing is O(n) even though there is a loop inside the loop. This kind of reasoning, counting the total work over the whole run rather than per iteration, is amortised analysis again.

Summary

  • Stacks are LIFO: undo, brackets, expression evaluation, depth-first search.
  • Queues are FIFO: work in arrival order, breadth-first search. Build them as ring buffers.
  • Deques are open at both ends; std::stack and std::queue are adapters over one.
  • A monotonic deque finds every sliding-window maximum in O(n).
