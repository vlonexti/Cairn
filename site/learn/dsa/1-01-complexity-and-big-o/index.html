Complexity and Big O

lesson 1.011 of 5 in milestone 18 min1 practice task

How to describe an algorithm's speed independently of the computer - counting basic steps, Big O and its relatives Omega and Theta, the common growth classes, analysing sequential, nested and halving loops, best, worst and average cases, amortised cost, and space complexity.

Why count instead of time?

A stopwatch tells you how long one program took on one computer with one input. It cannot tell you what happens when the input is a thousand times bigger, and it changes with the compiler, the processor and whatever else is running. To compare algorithms we count how the number of basic steps grows with the size of the input, called n.

A basic step is anything that takes a fixed amount of time: an arithmetic operation, a comparison, reading or writing one array element, a function call.

C++
#include <iostream>
#include <vector>

int steps = 0;

bool contains(const std::vector<int>& values, int target)
{
    for (int v : values)
    {
        ++steps;                       // one comparison per element
        if (v == target) return true;
    }
    return false;
}

bool hasDuplicate(const std::vector<int>& values)
{
    for (std::size_t i = 0; i < values.size(); ++i)
        for (std::size_t j = i + 1; j < values.size(); ++j)
        {
            ++steps;                   // one comparison per pair
            if (values[i] == values[j]) return true;
        }
    return false;
}

int main()
{
    for (int n : { 10, 100, 1000 })
    {
        std::vector<int> data(n);
        for (int i = 0; i < n; ++i) data[i] = i;

        steps = 0;
        contains(data, -1);
        int linear = steps;

        steps = 0;
        hasDuplicate(data);
        std::cout << "n = " << n << ": contains " << linear << " steps, hasDuplicate " << steps << " steps\n";
    }
}

Ten times more data means ten times more work for contains, but about a hundred times more for hasDuplicate. That growth rate is what Big O describes.

Big O

We say an algorithm is O(f(n)) if, for large enough n, its number of steps is at most some constant times f(n). Two rules make this easy to use:

  1. Drop constant factors. 3n + 5 steps is O(n). The constant depends on the machine; the growth does not.
  2. Keep only the fastest-growing term. n²/2 + 100n is O(n²): for big n, the n² part dominates everything else.

hasDuplicate does (n−1) + (n−2) + ... + 1 = n(n−1)/2 comparisons in the worst case, so it is O(n²).

Big O is an upper bound. Two relatives complete the picture:

Notation Meaning Informally
O(f) grows no faster than f "at most"
Ω(f) (Omega) grows at least as fast as f "at least"
Θ(f) (Theta) both: grows exactly like f "exactly"

In everyday use people say "O(n)" when they mean Θ(n), the tight bound. This course does the same unless the difference matters.

The common growth classes

Class Name Example n = 1,000,000
O(1) constant v[i], push_back (amortised) 1
O(log n) logarithmic binary search 20
O(n) linear scanning a vector 10⁶
O(n log n) linearithmic good sorting 2 × 10⁷
O(n²) quadratic comparing every pair 10¹²
O(2ⁿ) exponential trying every subset more than the atoms in the universe

A modern computer does very roughly 10⁸ to 10⁹ simple steps per second. So for a million items, O(n log n) finishes in a fraction of a second, while O(n²) takes many minutes. Choosing the right growth class matters far more than tuning code.

Analysing code

Sequential parts add, and the bigger one wins: an O(n) loop followed by an O(n²) loop is O(n²).

Nested loops multiply: a loop of n iterations, each doing O(n) work, is O(n²). Watch for hidden loops: std::find, v.erase(v.begin()), s.substr and copying a vector are all O(n) themselves.

Halving gives a logarithm. If each step cuts the remaining work in half, there are about log₂ n steps:

C++
#include <iostream>

int main()
{
    for (long long n : { 8LL, 1000LL, 1000000LL, 1000000000000LL })
    {
        int steps = 0;
        for (long long i = n; i > 1; i /= 2) ++steps;
        std::cout << n << " halves to 1 in " << steps << " steps\n";
    }
}

A trillion takes only 39 halvings. Logarithmic algorithms barely notice the size of their input.

Recursion: count the calls and the work per call. A function that calls itself twice on inputs of size n − 1 makes about 2ⁿ calls, which is why the naive Fibonacci in lesson 6.02 is so slow.

Best, worst and average case

The same algorithm can take different times on different inputs of the same size. contains finds the target in the first slot in the best case (O(1)) and scans everything in the worst case (O(n)). On average, if the target is equally likely to be anywhere, it looks at about half: still O(n).

  • Worst case is the usual guarantee, and the default meaning of "this algorithm is O(...)".
  • Average case matters for algorithms like quicksort and hash tables, whose worst case is rare.
  • Best case is rarely useful on its own.

Amortised cost

Some operations are usually cheap but occasionally expensive. std::vector::push_back normally writes one element, but when the vector is full it allocates a bigger block and copies everything. Because the capacity doubles, the copies over n pushes add up to less than 2n: the cost is amortised O(1) per push. Lesson 1.03 builds such a vector and counts the copies.

Amortised is not the same as average: it is a guarantee about any sequence of operations, with no luck involved.

Space complexity

Memory is analysed the same way. hasDuplicate uses O(1) extra space. Sorting a copy first and then comparing neighbours makes it O(n log n) in time but O(n) in extra space. Recursion uses stack space: a recursion n levels deep uses O(n) memory even if it allocates nothing.

Often you can trade one for the other: a hash set finds duplicates in O(n) time using O(n) space.

Summary

  • Count basic steps as a function of n; drop constants and lower-order terms.
  • O is an upper bound, Ω a lower bound, Θ both.
  • Sequential code adds, nested loops multiply, halving gives log n.
  • Worst case is the default guarantee; amortised cost averages over a sequence of operations.
  • Space is analysed the same way, and recursion depth counts.
