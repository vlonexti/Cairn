Heaps and Priority Queues

lesson 3.044 of 5 in milestone 38 min1 practice task

The binary heap - a complete tree stored in an array, sift-up and sift-down, push and pop in O(log n), building a heap in O(n), heapsort, std::priority_queue and the heap algorithms, min-heaps with std::greater, and classic uses - top k, merging k sorted lists, and the running median with two heaps.

A queue ordered by priority

A priority queue hands out its elements by priority rather than arrival order: always the largest (or smallest) next. Hospitals triage this way; operating systems schedule threads this way; Dijkstra's shortest-path algorithm (lesson 5.03) is built on one.

Implementation push pop the max
unsorted vector O(1) O(n)
sorted vector O(n) O(1)
binary heap O(log n) O(log n)

The heap property

A binary max-heap is a binary tree in which every node is at least as large as its children. So the largest element is at the root. The tree is also complete: every level is full except possibly the last, which is filled from the left.

Completeness means the tree fits perfectly in an array, level by level, with no pointers at all:

  • the root is at index 0,
  • the children of node i are at 2i + 1 and 2i + 2,
  • the parent of node i is at (i − 1) / 2.

Push: sift up

Put the new element at the end of the array (the next free spot in the bottom level), then sift it up: while it is larger than its parent, swap them. The tree has log₂ n levels, so this is O(log n).

Pop: sift down

The maximum is at the root. Move the last element into the root and shrink the array, then sift it down: while it is smaller than its larger child, swap it with that child. Again O(log n).

C++
#include <iostream>
#include <stdexcept>
#include <utility>
#include <vector>

class MaxHeap
{
public:
    void push(int value)
    {
        a_.push_back(value);
        std::size_t i = a_.size() - 1;
        while (i > 0 && a_[(i - 1) / 2] < a_[i])           // sift up
        {
            std::swap(a_[(i - 1) / 2], a_[i]);
            i = (i - 1) / 2;
        }
    }

    int pop()
    {
        if (a_.empty()) throw std::out_of_range("empty heap");
        int top = a_[0];
        a_[0] = a_.back();
        a_.pop_back();
        siftDown(0);
        return top;
    }

    bool empty() const { return a_.empty(); }

private:
    void siftDown(std::size_t i)
    {
        while (true)
        {
            std::size_t largest = i, l = 2 * i + 1, r = 2 * i + 2;
            if (l < a_.size() && a_[largest] < a_[l]) largest = l;
            if (r < a_.size() && a_[largest] < a_[r]) largest = r;
            if (largest == i) return;
            std::swap(a_[i], a_[largest]);
            i = largest;
        }
    }

    std::vector<int> a_;
};

int main()
{
    MaxHeap h;
    for (int x : { 40, 90, 10, 70, 60, 80, 50 }) h.push(x);
    while (!h.empty()) std::cout << h.pop() << ' ';
    std::cout << '\n';
}

Building a heap in O(n)

Pushing n elements one at a time costs O(n log n). But a whole array can be turned into a heap faster: sift down every non-leaf node, from the last one back to the root. Most nodes are near the bottom, where sifting down is short (half the nodes are leaves and do nothing, a quarter sift at most one level, an eighth at most two...). The total is n·(1/4 + 2/8 + 3/16 + ...) < n: O(n).

Heapsort

Build a max-heap in O(n), then repeatedly swap the root (the maximum) with the last element of the heap, shrink the heap by one, and sift the new root down. The array fills with sorted elements from the back.

Heapsort is O(n log n) in the worst case and in place, which is why introsort uses it as its safety net. It is not stable, and its jumps around the array make it slower than quicksort in practice.

C++
#include <iostream>
#include <utility>
#include <vector>

void siftDown(std::vector<int>& a, std::size_t i, std::size_t n)
{
    while (true)
    {
        std::size_t largest = i, l = 2 * i + 1, r = l + 1;
        if (l < n && a[largest] < a[l]) largest = l;
        if (r < n && a[largest] < a[r]) largest = r;
        if (largest == i) return;
        std::swap(a[i], a[largest]);
        i = largest;
    }
}

void heapSort(std::vector<int>& a)
{
    std::size_t n = a.size();
    for (std::size_t i = n / 2; i-- > 0;) siftDown(a, i, n);     // build the heap, bottom up
    for (std::size_t end = n; end > 1; --end)
    {
        std::swap(a[0], a[end - 1]);                              // the maximum goes to its final place
        siftDown(a, 0, end - 1);
    }
}

int main()
{
    std::vector<int> a{ 12, 11, 13, 5, 6, 7, 3, 99, 0 };
    heapSort(a);
    for (int x : a) std::cout << x << ' ';
    std::cout << '\n';
}

The standard library

std::priority_queue<T> is a max-heap adapter over a std::vector: push, top, pop, size. For a min-heap, pass std::greater<T> as the comparator. The raw algorithms std::make_heap, std::push_heap, std::pop_heap and std::sort_heap work on any random-access range.

C++
#include <functional>
#include <iostream>
#include <queue>
#include <string>
#include <vector>

struct Task { int priority; std::string name; };

int main()
{
    std::priority_queue<int, std::vector<int>, std::greater<int>> minHeap;
    for (int x : { 5, 1, 8, 3 }) minHeap.push(x);
    std::cout << "smallest: " << minHeap.top() << '\n';

    auto lower = [](const Task& a, const Task& b) { return a.priority < b.priority; };   // "a comes out after b"
    std::priority_queue<Task, std::vector<Task>, decltype(lower)> tasks(lower);
    tasks.push({ 2, "write report" });
    tasks.push({ 5, "fix outage" });
    tasks.push({ 1, "water plants" });
    while (!tasks.empty()) { std::cout << tasks.top().priority << ' ' << tasks.top().name << '\n'; tasks.pop(); }
}

The comparator reads backwards at first: priority_queue puts the element that is largest according to it on top, so less gives a max-heap and greater a min-heap.

Classic uses

The k largest of n items: keep a min-heap of size k. For each item, push it, and if the heap has more than k elements, pop the smallest. The heap ends up holding the k largest, in O(n log k) time and O(k) memory, which works even for a stream too big to store.

Merging k sorted lists: put the first element of each list in a min-heap, with a note of which list it came from. Repeatedly pop the smallest, output it, and push the next element from the same list. With n elements in total, that is O(n log k).

The running median: keep the smaller half of the numbers in a max-heap and the larger half in a min-heap, with sizes differing by at most one. Each new number goes into the right heap, one element moves across if the sizes get unbalanced, and the median is at the top of one or both heaps. Each step is O(log n).

C++
#include <functional>
#include <iostream>
#include <queue>
#include <vector>

int main()
{
    std::priority_queue<int> low;                                       // max-heap: the smaller half
    std::priority_queue<int, std::vector<int>, std::greater<int>> high; // min-heap: the larger half
    for (int x : { 5, 15, 1, 3, 8, 7, 9, 10 })
    {
        if (low.empty() || x <= low.top()) low.push(x); else high.push(x);
        if (low.size() > high.size() + 1) { high.push(low.top()); low.pop(); }
        else if (high.size() > low.size()) { low.push(high.top()); high.pop(); }

        double median = low.size() > high.size() ? low.top() : (low.top() + high.top()) / 2.0;
        std::cout << "after " << x << ": median " << median << '\n';
    }
}

Summary

  • A binary heap is a complete tree in an array: children of i at 2i + 1 and 2i + 2.
  • Push sifts up, pop sifts down: O(log n). Building from an array is O(n).
  • Heapsort is O(n log n) worst case and in place, but unstable and cache-unfriendly.
  • std::priority_queue is a max-heap; std::greater makes a min-heap.
  • Heaps give top-k in O(n log k), k-way merges in O(n log k), and running medians in O(log n) per number.
