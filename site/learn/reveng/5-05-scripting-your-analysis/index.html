Scripting Your Analysis

lesson 5.055 of 5 in milestone 55 min1 practice task

Automating the repetitive parts of reverse engineering - scripting Ghidra, IDA and x64dbg, Python with pefile and Capstone for batch work, generating byte signatures automatically, and keeping your findings in a form you can reuse on the next build.

Do it once by hand, then script it

Reverse engineering has a lot of repetition: renaming every function that calls a logging function after the string it logs, finding every use of a struct, re-finding fifty functions in a new build. Anything you do more than a few times is worth a script, and every serious tool has a scripting interface.

Ghidra

Ghidra runs scripts written in Java or Python (Jython, or real Python 3 with the Ghidrathon or PyGhidra extensions) from its Script Manager. A script sees the whole program database:

Python
# Rename every function that references a string beginning "[net]" after that string.
from ghidra.program.model.symbol import SourceType

for s in currentProgram.getListing().getDefinedData(True):
    text = s.getValue()
    if not isinstance(text, str) or not text.startswith("[net] "):
        continue
    for ref in getReferencesTo(s.getAddress()):
        f = getFunctionContaining(ref.getFromAddress())
        if f and f.getName().startswith("FUN_"):
            f.setName("net_" + text[6:].split()[0], SourceType.USER_DEFINED)

FUN_ is Ghidra's prefix for unnamed functions, so the check keeps names you already chose. Ghidra also has a headless mode (analyzeHeadless) that imports, analyses and runs scripts over many binaries without the user interface: the way to process a hundred builds.

IDA and x64dbg

  • IDAPython gives the same kind of access in IDA (idautils.Functions(), idc.set_name, cross-references), and IDA Free supports it in recent versions.
  • x64dbg has a simple command script language (bp, run, log, conditional commands) for automating debugging sessions, and a plugin SDK in C++ for anything bigger, such as a plugin that logs every call to a function with formatted arguments.
  • WinDbg has JavaScript extensions and its data model (dx) for querying a session like a database.

Python outside the tools

For batch work on files, plain Python with two libraries goes a long way:

Python
import pefile, capstone

pe = pefile.PE("Inventory.exe")
text = next(s for s in pe.sections if s.Name.startswith(b".text"))
code = text.get_data()
base = pe.OPTIONAL_HEADER.ImageBase + text.VirtualAddress

md = capstone.Cs(capstone.CS_ARCH_X86, capstone.CS_MODE_64)
for insn in md.disasm(code[:64], base):
    print(f"{insn.address:x}  {insn.mnemonic} {insn.op_str}")

for entry in pe.DIRECTORY_ENTRY_IMPORT:
    print(entry.dll.decode(), [imp.name.decode() for imp in entry.imports if imp.name])

pefile parses everything in milestone 1; Capstone disassembles as in lesson 5.02. Together they answer questions such as "which of these 200 builds import WinHttpOpen?" in seconds.

Generating signatures

The byte patterns of lesson 4.05 are tedious to make by hand. A signature generator automates the recipe:

  1. Start at the instruction you care about.
  2. Add whole instructions one at a time, writing their bytes into the pattern but wildcarding the bytes that change between builds: RIP-relative and branch displacements, absolute addresses.
  3. After each instruction, scan the module. When the pattern matches exactly once, stop.
  4. If it grows past a length limit before becoming unique, give up and try starting from a nearby instruction instead.

The decoder from this milestone supplies the instruction lengths and tells you which bytes are displacements. The practice writes this generator.

Keeping findings

Your understanding of a program is an asset: names, struct layouts, comments, signatures. Keep it in a form that survives:

  • Save the disassembler database and export names and types (Ghidra can export to C headers; IDA to .idc or .h).
  • Keep a text file of signatures with what each one finds, so a new build can be re-labelled by running them.
  • For your own programs, the PDB is the real answer: archive it with every build.
