Watching Behaviour from Outside

lesson 3.044 of 5 in milestone 35 min1 practice task

Learning what a program does without a debugger - Process Monitor's file and registry log and its filters, API Monitor, network captures with Wireshark, Event Tracing for Windows, and Sysmon - and reading their logs systematically.

Behaviour first

Before reading a program's code you can learn a lot by just watching it from outside: which files it opens, which registry keys it reads, which servers it talks to, which processes it starts. Behavioural analysis needs no understanding of the code, is hard for a program to notice, and often answers the question outright: "where does it keep its settings?" is answered by one Process Monitor capture.

Process Monitor

Process Monitor (Sysinternals, procmon.exe) records every file system, registry, process and thread event on the system, with the process, the path, the result and details.

A capture is enormous, so the skill is filtering (Filter > Filter...):

  • Process Name is Inventory.exe then Include: only your target.
  • Operation is WriteFile: only writes.
  • Path contains \Saves\: only one folder.
  • Result is NAME NOT FOUND: things the program looked for and did not find, which reveals optional configuration files, missing DLLs and plugins it would load if they existed.

Useful columns and tools: Path, Result, Detail (offsets and lengths of reads and writes); Tools > File Summary and Registry Summary to count accesses per path; double-click an event to see its call stack (with symbols for system DLLs), which shows the code in the program that caused it.

Logs can be saved as CSV (File > Save, Comma-Separated Values), which is the format of this lesson's practice:

Text
"Time of Day","Process Name","PID","Operation","Path","Result","Detail"
"10:14:02.1234567","Inventory.exe","4120","CreateFile","C:\Users\sam\AppData\Roaming\Inventory\config.ini","SUCCESS","Desired Access: Generic Read"

API Monitor

API Monitor (rohitab.com) logs calls to Windows API functions with their arguments and return values: every RegQueryValueExW with the key and value name, every connect with the address. It shows what Process Monitor cannot see, such as calls that do not touch files or the registry (cryptography, window messages, time).

Network captures

Wireshark captures network traffic and decodes hundreds of protocols. Filters such as ip.addr == 192.168.1.20 && tcp.port == 7777 narrow it to one conversation; Follow > TCP Stream shows the whole exchange as text or hex. For a program's own custom protocol you see only bytes, which is where lesson 6.03 picks up. Encrypted traffic (HTTPS, TLS) shows only the handshake and sizes, unless the program is yours and you can log its keys.

Event Tracing for Windows

ETW is the logging system built into Windows itself: the kernel and many components publish events (process starts, image loads, network, disk, the .NET runtime...). Tools such as Windows Performance Recorder, PerfView and logman capture them with very little overhead. Sysmon (Sysinternals) is a service that logs selected ETW-based events to the Windows event log permanently: process creation with full command lines and hashes, network connections, file creation. Security teams use it constantly, and it is a good way to watch a program over hours.

Reading logs systematically

Behaviour logs are only useful if you summarise them. A good habit for each capture:

  1. Filter to the target process (and its children: the PID of processes it started).
  2. List the distinct files written, files read, registry keys read and written, and network endpoints.
  3. Note the failures (NAME NOT FOUND, ACCESS DENIED): they show what the program expected to exist.
  4. Record the sequence of the important operations: what it reads at start-up, what it writes when you press Save.

The practice builds exactly that summary from a Process Monitor CSV.
