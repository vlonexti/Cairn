Encoding Jumps and Calls

lesson 4.022 of 5 in milestone 45 min1 practice task

How x64 encodes jumps and calls - short and near relative jumps, conditional jumps, relative calls, why the displacement counts from the end of the instruction, the 2 GB limit, and the absolute jumps used when a target is further away.

Relative, from the end

Almost every jump and call on x64 is relative: the instruction holds a signed distance, the displacement, and the target is

target = address of the next instruction + displacement

The distance is counted from the end of the jump, not its start, because by the time the processor uses it, rip already points past the instruction.

Instruction Bytes Length Displacement
jmp short EB dd 2 8-bit, −128 to +127
jmp near E9 dd dd dd dd 5 32-bit
jcc short 70+cc dd 2 8-bit
jcc near 0F 80+cc dd dd dd dd 6 32-bit
call E8 dd dd dd dd 5 32-bit

Example: a jmp at 0x1400010A0 to 0x140001200:

Text
next instruction = 0x1400010A0 + 5 = 0x1400010A5
displacement     = 0x140001200 - 0x1400010A5 = 0x15B
bytes            = E9 5B 01 00 00

Backwards jumps have negative displacements in two's complement: EB FE is a jump to itself (−2), an infinite loop; E9 00 00 00 00 jumps to the next instruction, which does nothing.

Because displacements are relative, a block of code containing only relative jumps between its own instructions can be moved anywhere and still works; a relative jump or call to outside the block points somewhere else once it is moved. That fact drives lessons 4.03 and 4.04.

The 2 GB limit

A 32-bit displacement reaches about ±2 GB. Inside one module that is plenty. But code you allocate at run time with VirtualAlloc may land anywhere in the 128 TB address space, too far for E9. Then you need an absolute jump:

Assembly
; 14 bytes: jump to the 8-byte address stored right after the instruction
FF 25 00 00 00 00          jmp qword ptr [rip+0]
xx xx xx xx xx xx xx xx    ; the absolute target address
Assembly
; 12 bytes, but it destroys rax
48 B8 xx xx xx xx xx xx xx xx    mov rax, imm64
FF E0                            jmp rax

The first form changes no registers, which is why hooking libraries use it. Alternatively, allocate your new code within 2 GB of the module (VirtualAlloc with an address hint near it), so a 5-byte E9 reaches it.

Calls through memory

Calls to imported functions are not relative calls to the function; they are indirect calls through the import address table:

Assembly
FF 15 xx xx xx xx          call qword ptr [rip+disp32]    ; the IAT slot

The displacement here gives the address of the slot, also counted from the end of the instruction (6 bytes long); the slot holds the function's address. Virtual calls are FF 50 xx / FF 90 xx xx xx xx (call qword ptr [rax+disp]) and friends.

Encoding in code

Choosing the shortest encoding that reaches:

C++
std::vector<std::uint8_t> encodeJump(std::uint64_t from, std::uint64_t to)
{
    const std::int64_t shortDisp{ static_cast<std::int64_t>(to - (from + 2)) };
    if (shortDisp >= -128 && shortDisp <= 127) return { 0xEB, static_cast<std::uint8_t>(shortDisp) };
    const std::int64_t nearDisp{ static_cast<std::int64_t>(to - (from + 5)) };
    if (nearDisp >= INT32_MIN && nearDisp <= INT32_MAX) { /* E9 + 4 bytes of nearDisp, little-endian */ }
    /* otherwise FF 25 00 00 00 00 + 8 bytes of `to` */
}

Note that the two candidate displacements are computed from different ends: from + 2 for the short form, from + 5 for the near one.
