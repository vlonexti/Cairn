Triage - First Impressions of a Binary

lesson 1.055 of 5 in milestone 16 min1 practice task

The first half hour with an unknown program - strings in ASCII and UTF-16, imports and exports, the compiler and runtime it was built with, the PDB path in its debug directory, resources, section entropy and the signs of packing - before reading any code.

Look before you read

Opening an unknown program straight in a disassembler and starting at the entry point is the slow way. A short triage first tells you what kind of program it is, what it is likely to do, and where to start reading. Everything here is static and quick.

Strings

Text in a program is often its most informative content: error messages, file names, registry keys, URLs, format strings, debug messages left in by the developers.

Windows programs store text in two encodings, and you need both:

  • ASCII / UTF-8: one byte per character, 48 65 6C 6C 6F for "Hello".
  • UTF-16LE: two bytes per character, the Windows "wide" strings used by every W function: 48 00 65 00 6C 00 6C 00 6F 00.

A strings tool scans the file for runs of printable characters (usually at least 4 or 5 long) in both forms. In a disassembler, each string becomes a landmark: find "Invalid licence file" and look at the code that refers to it, and you are in the licence check; find %s\\saves\\slot%d.dat and you have found the save code.

Imports and exports

The import table (lesson 1.04) is a summary of capabilities. Sort the imports by DLL and read the list:

DLL Suggests
ws2_32.dll, winhttp.dll, wininet.dll network
advapi32.dll (Reg*, Crypt*) registry, services, older cryptography
bcrypt.dll, ncrypt.dll cryptography
d3d11.dll, dxgi.dll, opengl32.dll graphics
user32.dll (CreateWindowEx, GetMessage) a window and a message loop
dbghelp.dll symbol handling, crash dumps

A DLL's exports are its whole public interface, often with descriptive names.

Compiler and runtime

How a program was built changes what its code looks like, so identify it early:

  • Rich header: MSVC-linked files have an undocumented block between the DOS stub and the PE header (the word Rich marks its end) listing the tool versions used.
  • Imports of the runtime: vcruntime140.dll and api-ms-win-crt-* mean Visual C++ 2015 or later; msvcrt.dll with MinGW-style names means GCC; libstdc++ names mean GCC or Clang with the GNU library.
  • Characteristic code: MSVC's __security_check_cookie calls at function ends (the /GS check from the Pointers and Memory course), its exception tables in .pdata.
  • Programs written in .NET are a different world: a tiny native stub and a large block of .NET metadata and bytecode, best opened with a .NET decompiler (ILSpy, dnSpy) instead.

The debug directory

Data directory 6 points at debug information. For MSVC builds it usually contains a CodeView record with the path of the PDB file as it was on the build machine:

Text
C:\Users\dev\source\repos\Inventory\x64\Release\Inventory.pdb

That gives you the project's name and sometimes the developer's folder layout. If the matching PDB is available (Microsoft publishes them for Windows' own DLLs on its symbol server), every tool can show real function names: always look before working without them.

Resources

The .rsrc section holds icons, dialogs, menus, string tables, version information (product name, company, version number), and sometimes whole embedded files. Resource Hacker or PE viewers list them.

Entropy and packing

Entropy measures how random a block of bytes looks, from 0 bits per byte (all the same byte) to 8 (perfectly random). Ordinary machine code sits around 5 to 6.5; text lower; compressed or encrypted data close to 8.

A section with entropy near 8, together with very few imports and an entry point outside .text, usually means the program is packed: compressed or encrypted, with a small stub that unpacks the real code at run time. Packers are used to make programs smaller and, often, to make them harder to analyse; malware uses them heavily. Static analysis of a packed file mostly sees the stub; the real code appears only in memory, after it unpacks.

Shannon entropy over a block of bytes:

H = − Σ p(b) × log₂ p(b), over the byte values b that occur, where p(b) is how often b occurs divided by the block size.

A triage checklist

  1. File type, 32 or 64 bit, .exe or .dll, native or .NET.
  2. Compiler and runtime.
  3. Sections: names, sizes, permissions, entropy. Anything writable and executable is unusual.
  4. Imports, grouped by DLL. Exports, if a DLL.
  5. Strings, both encodings, skimmed for landmarks.
  6. Debug directory and PDB path; are symbols available?
  7. Resources and version information.

Write down what you find. The next step, reading code, starts from these landmarks.
