How x64 Instructions Are Encoded

lesson 5.011 of 5 in milestone 56 min1 practice task

The layout of an x64 instruction - legacy prefixes, the REX prefix, one to three opcode bytes, the ModRM and SIB bytes that describe operands, displacements and immediates - and how to work out an instruction's length, the first job of any disassembler.

Variable length

x64 instructions are between 1 and 15 bytes long, and nothing marks where one ends: you only know an instruction's length by decoding it. That is why a disassembler that starts one byte off produces nonsense, and why the first thing any disassembler, hooking library or patch tool needs is a length decoder.

Every instruction has the same overall shape, with most parts optional:

Text
[legacy prefixes] [REX] opcode [ModRM] [SIB] [displacement] [immediate]
   0-4 bytes        0-1   1-3     0-1    0-1    0, 1, 2 or 4   0, 1, 2, 4 or 8

Prefixes

Legacy prefixes modify the instruction: 66 switches the operand size from 32 to 16 bits, F2 and F3 are the rep prefixes (and select different SSE instructions), F0 is lock, and segment overrides (64 for fs:, 65 for gs:) appear in code that reads thread-local data.

The REX prefix is a byte from 40 to 4F that must come directly before the opcode. Its low four bits are flags:

Bit Name Effect
3 (8) W 64-bit operand size
2 (4) R adds 8 to the ModRM reg field: reach r8 to r15
1 (2) X adds 8 to the SIB index field
0 (1) B adds 8 to the ModRM rm field, the SIB base field, or a register in the opcode

48 (W only) is by far the most common byte in x64 code: it turns mov eax, ecx into mov rax, rcx. 40 with no flags still matters: it changes the meaning of 8-bit registers (spl, bpl instead of ah, ch), and MSVC uses 40 53 for push rbx so the instruction is 2 bytes long.

Opcodes

Most common instructions have a one-byte opcode. Some encode a register in the opcode itself: 50+r is push r, 58+r is pop r, B8+r is mov r, imm (with REX.B selecting r8 to r15). Two-byte opcodes start with the escape byte 0F: 0F 84 is near je, 0F B6 is movzx, 0F 1F is the long nop. Three-byte opcodes start 0F 38 or 0F 3A (mostly SIMD).

ModRM

Instructions with a register or memory operand have a ModRM byte after the opcode, split into three fields:

Text
 7  6   5  4  3   2  1  0
[ mod ][  reg   ][  rm   ]
  • reg: a register operand (or, for some opcodes, an extension of the opcode: 83 /5 means "opcode 83 with reg field 5", which is sub).
  • mod and rm together describe the other operand:
mod rm Operand Extra bytes
11 any the register rm none
00 101 [rip + disp32] 4
00 100 [SIB] SIB (+4 if the SIB base is 101)
00 other [rm] none
01 100 [SIB + disp8] SIB + 1
01 other [rm + disp8] 1
10 100 [SIB + disp32] SIB + 4
10 other [rm + disp32] 4

Register numbers: 0 rax, 1 rcx, 2 rdx, 3 rbx, 4 rsp, 5 rbp, 6 rsi, 7 rdi, and 8 to 15 for r8 to r15 with a REX bit.

SIB

When rm is 100 in a memory form, a SIB byte follows, for [base + index*scale]:

Text
[ scale ][ index ][ base ]     scale: 00=1, 01=2, 10=4, 11=8

An index of 100 (without REX.X) means no index; that is how [rsp+8] is encoded, since rsp cannot be an index. A base of 101 with mod 00 means no base, disp32 instead.

A worked example

4C 8B 44 24 28:

Text
4C          REX: 0100 1100 -> W=1, R=1
8B          opcode: mov reg, r/m
44          ModRM: 01 000 100 -> mod 01 (disp8), reg 000 (+8 from R = r8), rm 100 (SIB follows)
24          SIB:   00 100 100 -> scale 1, index 100 (none), base 100 (rsp)
28          disp8: 0x28
            => mov r8, qword ptr [rsp+0x28]      (5 bytes)

Immediates

Constants embedded in the instruction come last: 1 byte for 83 /x ib and short jumps, 4 bytes for 81 /x id, C7 /0 id and E8/E9 displacements, and 8 bytes only for mov r64, imm64 (48 B8 + 8 bytes). With the 66 prefix, the 4-byte immediates of 81 and C7 become 2 bytes.

Putting it together, an instruction's length is: prefixes + REX + opcode bytes + ModRM (if any) + SIB (if any) + displacement + immediate. The practice writes exactly that for a useful subset.
