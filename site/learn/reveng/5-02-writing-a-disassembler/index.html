Writing a Disassembler

lesson 5.022 of 5 in milestone 56 min1 practice task

From bytes to text - table-driven decoding, naming registers and building memory operands, formatting immediates and branch targets, linear sweep versus recursive descent, telling code from data, and the real libraries (Zydis, Capstone) behind every tool.

Decoding and formatting

A disassembler does two jobs for each instruction:

  1. Decode: read prefixes, opcode, ModRM, SIB, displacement and immediate into a structure: which operation, which registers, which memory expression, which constant. This also gives the length.
  2. Format: turn that structure into text in a chosen syntax: mov rax, qword ptr [rcx+0x10] (Intel, as MSVC and x64dbg show it) or movq 0x10(%rcx), %rax (AT&T, as GDB and objdump show by default).

Keeping them separate pays off: analysis code (a control flow graph, a pattern generator) wants the structure, not the text.

Tables

x86 has hundreds of opcodes, so real decoders are table-driven: an array indexed by opcode byte saying what follows (ModRM or not, immediate size, operand roles) and the mnemonic. A small decoder for common instructions is a table like this:

Opcode Form Mnemonic
01 / 03 r/m, reg / reg, r/m add
29 / 2B r/m, reg / reg, r/m sub
31 / 33 r/m, reg / reg, r/m xor
39 / 3B r/m, reg / reg, r/m cmp
85 r/m, reg test
89 / 8B r/m, reg / reg, r/m mov
8D reg, m lea
83 /0 /4 /5 /7 r/m, imm8 add and sub cmp
81 /0 /4 /5 /7 r/m, imm32 the same with a 32-bit immediate
C7 /0 r/m, imm32 mov
B8+r reg, imm32 (imm64 with REX.W) mov
50+r / 58+r reg push / pop
E8 / E9 / EB rel32 / rel32 / rel8 call / jmp / jmp
70+cc / 0F 80+cc rel8 / rel32 jo jno jb jae je jne jbe ja js jns jp jnp jl jge jle jg
C3, CC, 90 none ret, int3, nop

With just these, most of a typical function decodes.

Operands

Registers depend on the operand size: with REX.W the 64-bit names (rax, ..., r15), otherwise the 32-bit ones (eax, ..., edi, r8d, ..., r15d). Registers inside a memory operand are addresses, so they always use the 64-bit names: dword ptr [rbp-0x4], never [ebp-0x4].

Memory operands are built from the ModRM and SIB fields: base, then +index*scale, then the displacement as +0x10 or -0x8, all in brackets. A size keyword in front says how many bytes are accessed: qword ptr, dword ptr, word ptr, byte ptr. lea takes no size keyword, because it accesses no memory.

Immediates for arithmetic are sign-extended: 83 C0 FF is add eax, -0x1, not add eax, 0xff.

Branch targets are shown as absolute addresses, computed from the instruction's address, its length and its displacement (lesson 4.02), because that is what a reader needs.

Linear sweep and recursive descent

How do you choose where to decode?

  • Linear sweep decodes from the start of a section to the end, each instruction right after the previous one. Simple, and it sees everything, but when it meets data inside code (a jump table, padding, a literal pool), it decodes it as nonsense instructions, and may stay out of step for a few instructions afterwards. objdump works this way.
  • Recursive descent starts at known entry points (the entry point, exports, .pdata functions) and follows the code: decode until a ret or jmp, and queue every branch and call target. It never decodes data by mistake, but misses code that is only reached indirectly (through function pointers, vtables, jump tables), unless it resolves those too. Ghidra, IDA and Binary Ninja combine this with many heuristics.

When a byte does not decode as any known instruction, a disassembler shows it as data, db 0x0f, and moves on by one byte.

Use a library for real work

A complete x86-64 decoder covers thousands of instruction forms, AVX-512, and many corner cases. For your own tools use a library:

  • Zydis: fast, thorough, C, MIT licence; decodes into a detailed structure and formats Intel or AT&T.
  • Capstone: many architectures (x86, ARM, MIPS...), C with bindings for Python and other languages, BSD licence.
  • iced (Rust and .NET): very complete, also encodes.

Writing a small one yourself, as this milestone's project does, is how you learn what those libraries give you, and how to read their output when it surprises you.
