Hooking Functions in Your Own Programs

lesson 4.044 of 5 in milestone 45 min1 practice task

Redirecting calls to a function so your code runs first - import address table hooks, inline hooks with a trampoline that still calls the original, libraries that do it safely, and using hooks for instrumentation, logging and testing in software you build.

What a hook is

A hook makes calls to a function go to your code instead, usually so your code can do something and then call the original. Inside your own software, hooks are a practical tool:

  • Instrumentation: count and time every call to an allocator or a file function without changing the call sites.
  • Logging: record the arguments of every call to a third-party library you only have as a DLL.
  • Testing: make a system function fail on purpose (CreateFileW returns "access denied") to test error handling.
  • Fixing: replace a buggy function in a library you cannot rebuild.

Profilers, debuggers, crash reporters and the Windows compatibility layer all hook functions. Everything here is about functions in your own process or programs you build.

IAT hooks

Calls to imported functions go through the import address table (lesson 1.04): call qword ptr [IAT slot]. Change the slot, and every call from that module goes to your function instead:

C++
using CreateFileWFn = HANDLE (WINAPI*)(LPCWSTR, DWORD, DWORD, LPSECURITY_ATTRIBUTES, DWORD, DWORD, HANDLE);
static CreateFileWFn realCreateFileW{ nullptr };

HANDLE WINAPI loggingCreateFileW(LPCWSTR name, DWORD access, DWORD share, LPSECURITY_ATTRIBUTES sa,
                                 DWORD disposition, DWORD flags, HANDLE templ)
{
    std::wprintf(L"opening %s\n", name);
    return realCreateFileW(name, access, share, sa, disposition, flags, templ);   // the original
}

// Find the slot for CreateFileW in this module's import table, then:
DWORD old;
VirtualProtect(slot, sizeof(void*), PAGE_READWRITE, &old);
realCreateFileW = reinterpret_cast<CreateFileWFn>(*slot);
*slot = reinterpret_cast<void*>(&loggingCreateFileW);
VirtualProtect(slot, sizeof(void*), old, &old);

IAT hooks are simple and safe: one pointer changes, no code is rewritten. Their limit is scope: they catch calls from the module whose table you changed, not calls from other DLLs, and not calls made through GetProcAddress.

Inline hooks and trampolines

An inline hook patches the first bytes of the target function itself, so every caller is caught. It is the detour of lesson 4.03 at a function's start:

Text
target function, before:          after:
  48 89 5C 24 08  mov [rsp+8],rbx   E9 xx xx xx xx   jmp yourFunction
  57              push rdi          57               push rdi
  48 83 EC 20     sub rsp,20h       48 83 EC 20      sub rsp,20h

To still call the original, you build a trampoline: a small block of executable memory holding the stolen instructions followed by a jump back to the rest of the original:

Text
trampoline:
  48 89 5C 24 08    mov [rsp+8], rbx          ; stolen bytes
  E9 xx xx xx xx    jmp target+5              ; continue the original

Your function calls the trampoline whenever it wants the original behaviour. Everything from lesson 4.03 applies: steal whole instructions, relocate RIP-relative ones, and do not overwrite a jump target. Two more problems are specific to hooking a live process:

  • Other threads may be executing the bytes you are overwriting. Suspend the other threads while you write, and check none of them is stopped inside the stolen range.
  • Distance: the trampoline must be within 2 GB for 5-byte jumps, or you need the 14-byte absolute form at the function start, which steals more bytes.

Use a library

Writing a robust inline hook engine means a full instruction-length decoder, relocation of every RIP-relative instruction form, thread handling and more. In practice use one of:

  • Microsoft Detours (MIT licence): the reference implementation, used by Microsoft's own tools.
  • MinHook (BSD licence): small, simple API (MH_CreateHook, MH_EnableHook).

Understanding what they do, as in this lesson, is what lets you debug them when a hook misbehaves.
