Branches, Loops and Switches

lesson 2.033 of 5 in milestone 25 min1 practice task

What if, else, && and ||, for and while loops and switch statements compile into, how to read a function as a graph of basic blocks, and the jump tables that big switch statements become.

Basic blocks

Inside a function, code runs straight down until a jump. A basic block is a run of instructions with one way in (its first instruction) and one way out (its last). Every disassembler shows a function as a graph of blocks joined by arrows, the control flow graph, and reading that graph is most of reading a function.

A new block starts:

  • at the function's first instruction;
  • at every jump target;
  • right after every jump or ret (the fall-through of a conditional jump, or simply code that something else jumps to).

A call does not end a block: the call returns and execution carries on.

if and else

The compiler usually inverts the condition and jumps over the "then" part:

C++
if (health <= 0) die();
else heal(5);
Assembly
    test ecx, ecx           ; health in ecx
    jg   else_part          ; NOT (health <= 0): skip the then part
    call die
    jmp  done
else_part:
    mov  ecx, 5
    call heal
done:

When you read test/cmp followed by a jump, the jump is usually the opposite of the condition in the source.

&& and ||

Short-circuit operators become a chain of jumps. if (a > 0 && b > 0) f(); jumps past f as soon as either test fails:

Assembly
    test ecx, ecx
    jle  skip
    test edx, edx
    jle  skip
    call f
skip:

|| jumps into the body as soon as one test succeeds. Two jumps to the same place mean &&; a jump into the body followed by a test of the next condition means ||.

Loops

A for or while loop has a backwards jump: a jump to an address earlier in the function. That is the quickest way to spot a loop in a listing.

C++
for (int i = 0; i < count; ++i) total += values[i];

Optimised compilers usually test once before the loop and then use a do-while shape with the test at the bottom, which saves a jump per iteration:

Assembly
    xor  eax, eax           ; total
    test edx, edx           ; count <= 0? skip the loop entirely
    jle  done
    xor  r8d, r8d           ; i
top:
    add  eax, dword ptr [rcx+r8*4]
    inc  r8
    cmp  r8, rdx
    jl   top                ; backwards: the loop
done:
    ret

Recognise the parts: initialisation before, the body, the increment, the compare and the backward jump. Optimised loops are often unrolled (the body repeated several times per jump) or vectorised (SIMD instructions handling four or eight elements at once), with a small extra loop for the leftovers.

Switch statements

A switch with a few cases becomes a chain of comparisons. A switch with many cases over a dense range of values becomes a jump table: an array of addresses indexed by the value.

Assembly
    sub  ecx, 1                     ; cases 1..5: make the index start at 0
    cmp  ecx, 4
    ja   default_case               ; unsigned: also catches values below 1
    lea  rdx, [__ImageBase]         ; the module's base address
    movsxd rcx, ecx
    mov  eax, dword ptr [rdx+rcx*4+3A40h]   ; table of 32-bit RVAs at RVA 0x3A40
    add  rax, rdx                   ; RVA + base = address of the case
    jmp  rax

MSVC stores the table as RVAs (4 bytes each) and adds the image base, so the table needs no relocations. Reading the table gives you the address of every case. The ja before it handles every value outside the table, including negative ones, with one unsigned comparison.

Conditional moves

Small ifs are often compiled without jumps at all:

Assembly
    cmp  ecx, edx
    mov  eax, edx
    cmovl eax, ecx          ; eax = (ecx < edx) ? ecx : edx   -> std::min

cmovcc and setcc (setl al: set al to 1 if less) are branch-free, so they leave the control flow graph simpler than the source was.
