Data in Machine Code

lesson 2.044 of 5 in milestone 25 min1 practice task

Recognising locals, globals, struct members, arrays and strings in disassembly - what the addressing modes reveal, how sizes and signedness show the types, floating point in xmm registers, and rebuilding a struct by collecting every offset the code uses.

Addresses tell you what the data is

Every memory operand in x64 has the form [base + index*scale + displacement], and the shape of it is a strong hint about the data being reached:

Operand Usually means
[rsp+40h], [rbp-10h] a local variable or spilled value in the current frame
[rip+1A2Bh] (shown as a name like dword_140005000) a global or a constant in the image
[rcx+18h] a member at offset 0x18 of the struct rcx points at
[rax+rdx*4] element rdx of an array of 4-byte things starting at rax
[rax+rdx*8+10h] element rdx of an array of 8-byte things that starts at offset 0x10 of a struct
[rcx+rdx] byte rdx of a buffer, or an array of 1-byte things

The scale (1, 2, 4 or 8) is the element size. A stride that is not a power of two shows up as a multiplication first: imul rdx, rdx, 1Ch then [rax+rdx] is an array of 28-byte structs.

Sizes and signedness

The size of a memory access gives the size of the field:

Access Size
byte ptr, al, movzx eax, byte ptr 1
word ptr, ax 2
dword ptr, eax 4
qword ptr, rax 8

Signedness shows in how a small value is widened and compared:

  • movsx / movsxd (sign-extend) and jl/jg mean signed: char, short, int.
  • movzx (zero-extend) and jb/ja mean unsigned: unsigned char, bool, uint16_t, sizes.

An 8-byte value that is later used as [rax+...] is a pointer. One that is passed to printf with %llu is a number.

Floating point

float and double live in xmm registers and use their own instructions:

Instruction Means
movss xmm0, dword ptr [rcx+10h] load a float
movsd xmm0, qword ptr [rcx+10h] load a double
addss, mulss, subsd, divsd ... arithmetic; ss = single (float), sd = double
comiss, ucomisd compare, then ja/jb (floating point compares use the unsigned conditions)
cvtsi2ss, cvttss2si int to float, float to int (truncating)

So a 4-byte field read with movss is a float, not an int.

Strings and constants

Code that uses a string literal loads its address with a RIP-relative lea:

Assembly
lea  rcx, [rip+2F1Ah]       ; disassemblers show: lea rcx, [aSaveFailedS]  "Save failed: %s"
call printf

That is how the strings you found in triage (lesson 1.05) lead you to code: ask the disassembler for cross-references to the string, and it lists every instruction that loads its address.

Floating-point constants also live in .rdata: mulss xmm0, dword ptr [__real@3f000000] is "multiply by 0.5" (0x3F000000 is the bits of 0.5f, readable with lesson 2.05's bit tricks from the Pointers and Memory course).

Rebuilding a struct

Without source, you reconstruct a struct by collecting every access through the same pointer. Suppose in a function where rcx is a Player* you see:

Assembly
mov  eax, dword ptr [rcx+0Ch]       ; 4 bytes at 0x0C
movss xmm0, dword ptr [rcx+10h]     ; a float at 0x10
movss xmm1, dword ptr [rcx+14h]     ; a float at 0x14
movzx edx, byte ptr [rcx+18h]       ; an unsigned byte at 0x18
mov  r8, qword ptr [rcx+20h]        ; 8 bytes at 0x20, used later as [r8+...]: a pointer

Written down as a struct, with gaps kept as padding:

C++
struct Player
{
    std::uint8_t unknown_00[0x0C];
    std::int32_t field_0C;
    float field_10;
    float field_14;          // two floats in a row: probably x, y
    std::uint8_t field_18;   // compared with 0 and 1 elsewhere: a bool
    std::uint8_t pad_19[7];
    Thing* field_20;
};

Then you rename fields as you learn what they are: field_10 and field_14 are written by the movement code, so they become x and y. Every disassembler lets you define such structs and apply them, so the listing shows [rcx+Player.x] instead of [rcx+10h]. The reconstruction grows as you read more functions that use the same struct, and its size usually comes from the new or malloc call that creates it: mov ecx, 30h; call operator new means the object is 0x30 bytes.
