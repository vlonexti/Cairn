x64 for Readers

lesson 2.011 of 5 in milestone 27 min1 practice task

The x64 you need to read compiled code rather than write it - registers and their smaller parts, the handful of instructions that make up most programs, flags and conditional jumps, and the Microsoft x64 calling convention that tells you where every argument and return value is.

Reading, not writing

Writing assembly means choosing instructions. Reading it means recognising patterns quickly, and compiled code uses a surprisingly small set of them. This lesson is a refresher aimed at reading the output of MSVC, in the Intel syntax that Visual Studio, x64dbg, WinDbg and Ghidra all show: destination first.

Assembly
mov rax, qword ptr [rcx+10h]    ; rax = the 8 bytes at rcx + 0x10

(Disassemblers write hex either as 10h or 0x10. They mean the same.)

Registers

Sixteen 64-bit general registers. Each has smaller views of its low part:

64 32 16 8 Usual role in compiled code
rax eax ax al return value, scratch
rcx ecx cx cl 1st argument, this
rdx edx dx dl 2nd argument
rbx ebx bx bl kept across calls
rsp esp sp spl stack pointer
rbp ebp bp bpl kept across calls, sometimes frame pointer
rsi, rdi esi, edi kept across calls; string copies
r8, r9 r8d, r9d r8w r8b 3rd and 4th arguments
r10, r11 scratch
r12 to r15 kept across calls

Plus rip, the instruction pointer, and sixteen 128-bit xmm0 to xmm15 registers for floating point and SIMD.

One rule catches everyone: writing a 32-bit register clears the top 32 bits of the 64-bit one. mov eax, 1 sets all of rax to 1, and xor eax, eax is the compiler's favourite way to zero rax (it is shorter than xor rax, rax). Writing 8 or 16-bit parts leaves the rest alone.

The instructions you will see most

Instruction Does
mov a, b copy
movzx, movsx, movsxd copy a small value into a bigger register, zero- or sign-extending
lea a, [expr] compute the address expression, without reading memory; also used for arithmetic: lea eax, [rcx+rcx*4] is eax = ecx * 5
add, sub, imul, neg, inc, dec arithmetic
and, or, xor, not, shl, shr, sar bits; sar is a signed shift, often division by a power of two
cmp a, b compute a - b, set the flags, keep nothing else
test a, b compute a & b, set the flags; test eax, eax asks "is eax zero (or negative)?"
jcc target jump if a condition holds (table below)
jmp target jump always
call target, ret function call and return
push, pop save and restore registers on the stack
cmovcc, setcc conditional move or set a byte from the flags, without jumping

Flags and conditional jumps

cmp and test set flags; the conditional jump that follows reads them. The jump names say whether the comparison was signed or unsigned, which tells you the type of the variables:

Signed Unsigned After cmp a, b, jumps if
jl jb a < b
jle jbe a <= b
jg ja a > b
jge jae a >= b
je / jz a == b
jne / jnz a != b

jl/jg mean the source compared ints; jb/ja mean unsigned, sizes or pointers. A bounds check written as one unsigned comparison, cmp ecx, 10; jae out_of_range, catches negative indexes too, because they look huge when unsigned.

The Microsoft x64 calling convention

Every function call on 64-bit Windows follows one convention, so you always know where the arguments are:

  • The first four arguments go in rcx, rdx, r8, r9, or in xmm0 to xmm3 if they are float or double. The position counts, not the type: in f(int a, double b, int c), a is in rcx, b in xmm1, c in r8.
  • Further arguments go on the stack. The caller always reserves 32 bytes of shadow space just above the return address for the callee to save the four register arguments in, so the 5th argument is at [rsp+28h] on entry to the function (8 for the return address, 0x20 of shadow space), the 6th at [rsp+30h], and so on.
  • The return value comes back in rax, or xmm0 for floating point.
  • rax, rcx, rdx, r8 to r11 and xmm0 to xmm5 are volatile: a call may destroy them. rbx, rbp, rdi, rsi, r12 to r15 and xmm6 to xmm15 are non-volatile: a function that uses them must save and restore them, which is exactly what its prologue's pushes are.
  • For a member function, this is the hidden first argument, in rcx.

So when you see a call, look just before it for writes to rcx, rdx, r8 and r9: those are its arguments. Just after it, a read of eax or rax is using its result.

Assembly
mov r8d, 3              ; third argument: 3
lea rdx, [rsp+40h]      ; second argument: the address of a local
mov rcx, rbx            ; first argument: whatever rbx holds
call ReadConfig
test eax, eax           ; did it return 0?
je failed
