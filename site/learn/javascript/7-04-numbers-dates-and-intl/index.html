Numbers, Dates and Intl

lesson 7.044 of 6 in milestone 75 min2 practice tasks

Getting numbers and times right - floating-point limits and Number.EPSILON, safe integers and BigInt, rounding money, the Date object and its pitfalls, ISO strings and time zones, and formatting numbers, dates, lists and plurals for any language with Intl.

Every number is a double

Ordinary JavaScript numbers are 64-bit floating point, the same as double in C. They hold integers exactly only up to 2^53 − 1, and most decimal fractions only approximately:

JavaScript
console.log(0.1 + 0.2, 0.1 + 0.2 === 0.3);                 // 0.30000000000000004 false
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON);   // true: compare with a tolerance
console.log(Number.MAX_SAFE_INTEGER, 2 ** 53 === 2 ** 53 + 1);   // 9007199254740991 true

For money, count whole cents (integers) and format at the end, as the Money class in practice 7.02 does.

Rounding

JavaScript
const x = 2.345;
console.log(Math.round(x * 100) / 100);    // 2.35 (usually; x * 100 may land just below)
console.log(x.toFixed(2));                  // "2.35": a string, for display
console.log(Math.trunc(-2.7), Math.floor(-2.7), Math.ceil(-2.2));   // -2 -3 -2

BigInt

When integers must be exact beyond 2^53 (ids, cryptography, factorials), use BigInt: write an n after the number or call BigInt(...).

JavaScript
const big = 2n ** 64n;
console.log(big, typeof big);                // 18446744073709551616n bigint
let factorial = 1n;
for (let i = 1n; i <= 25n; i++) factorial *= i;
console.log(factorial.toString());
console.log(7n / 2n);                        // 3n: BigInt division truncates

BigInts and numbers cannot be mixed in arithmetic (1n + 1 is a TypeError); convert one side with Number(...) or BigInt(...). JSON.stringify refuses BigInts, so send them as strings.

Dates

A Date is a moment in time, stored as milliseconds since 1 January 1970 UTC. It displays in the computer's local time zone unless you ask for UTC:

JavaScript
const d = new Date(Date.UTC(2026, 10, 20, 14, 30));   // months count from 0: 10 is November
console.log(d.toISOString());                         // 2026-11-20T14:30:00.000Z
console.log(d.getUTCDay());                           // 5: Friday (0 is Sunday)
const later = new Date(d.getTime() + 90 * 60 * 1000); // add 90 minutes
console.log(later.toISOString());

Pitfalls worth remembering:

  • months are 0 to 11, days of the month 1 to 31;
  • new Date("2026-11-20") is midnight UTC, but new Date("2026-11-20T00:00") is midnight local time;
  • a Date is mutable: setDate changes the object in place;
  • store and send dates as ISO strings (toISOString()), and convert to local time only when displaying.

For calendar arithmetic across time zones, the coming Temporal API (and libraries like date-fns or Luxon today) are much safer than Date.

Intl: formatting for people

Intl formats values the way each language and country expects:

JavaScript
const n = 1234567.891;
console.log(new Intl.NumberFormat("en-US").format(n));                       // 1,234,567.891
console.log(new Intl.NumberFormat("de-DE").format(n));                       // 1.234.567,891
console.log(new Intl.NumberFormat("en-US", { style: "currency", currency: "EUR" }).format(12.5));
console.log(new Intl.NumberFormat("en", { notation: "compact" }).format(n)); // 1.2M

const when = new Date(Date.UTC(2026, 10, 20, 14, 30));
console.log(new Intl.DateTimeFormat("en-GB", { dateStyle: "long", timeZone: "UTC" }).format(when));  // 20 November 2026

console.log(new Intl.ListFormat("en", { type: "conjunction" }).format(["tea", "cake", "jam"]));     // tea, cake, and jam
const plural = new Intl.PluralRules("en");
for (const count of [0, 1, 2]) console.log(count, plural.select(count));     // other one other

Intl.RelativeTimeFormat writes "3 days ago", and Intl.Collator sorts text the way a language expects (["ä", "z", "a"].sort(new Intl.Collator("de").compare)).
