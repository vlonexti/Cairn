Prototypes and this

lesson 3.022 of 5 in milestone 35 min1 practice task

How JavaScript objects really share behaviour - the prototype chain under classes, Object.create, own versus inherited properties, the four rules for this, losing this when passing methods, and fixing it with arrow functions and bind.

The prototype chain

Every object has a hidden link to another object, its prototype. When a property is not found on an object, JavaScript looks on its prototype, then that object's prototype, and so on: the prototype chain.

JavaScript
const animal = { speak() { return `${this.name} makes a sound`; } };
const dog = Object.create(animal);      // dog's prototype is animal
dog.name = "Rex";
console.log(dog.speak());               // found on animal, run with this = dog
console.log(Object.getPrototypeOf(dog) === animal);
console.log(Object.hasOwn(dog, "name"), Object.hasOwn(dog, "speak"));

Classes are built on this: methods live once on ClassName.prototype, and every instance links to it.

JavaScript
class Point { constructor(x, y) { this.x = x; this.y = y; } length() { return Math.hypot(this.x, this.y); } }
const p = new Point(3, 4);
console.log(Object.getPrototypeOf(p) === Point.prototype, Object.keys(p), p.length());

Object.keys shows only an object's own properties (x, y); length is inherited. Arrays get map from Array.prototype, and everything ends at Object.prototype, whose prototype is null.

Never add methods to built-in prototypes (Array.prototype.sum = ...): it can clash with future versions of the language and with other code.

What this is

this is decided when a function is called, not where it is written:

Call this
obj.method() obj
new Fn() the new object
fn.call(x, ...) / fn.apply(x, [...]) / a bind(x) copy x
fn() on its own undefined (in modules and classes)

Arrow functions do not have their own this; they use the this of the code around them.

Losing this

Taking a method out of its object and calling it later loses this. This happens whenever a method is passed as a callback:

JavaScript
class Timer {
  constructor() { this.ticks = 0; }
  tick() { this.ticks++; }
}
const timer = new Timer();
const f = timer.tick;
try { f(); } catch (e) { console.log(e.constructor.name, e.message); }

[1, 2, 3].forEach(() => timer.tick());    // fix 1: an arrow function calling the method
[1, 2].forEach(timer.tick.bind(timer));   // fix 2: bind makes a copy with this fixed
console.log(timer.ticks);

A third fix is a class field holding an arrow function: tick = () => { this.ticks++; };. Each instance then gets its own copy with this fixed, which is convenient for event handlers (milestone 6).

call, apply and bind

JavaScript
function introduce(greeting, punctuation) { return `${greeting}, I am ${this.name}${punctuation}`; }
const ada = { name: "Ada" };
console.log(introduce.call(ada, "Hi", "!"));
console.log(introduce.apply(ada, ["Hello", "."]));
const adaIntro = introduce.bind(ada, "Hey");
console.log(adaIntro("?"));

bind can also fix leading arguments, as "Hey" here.
