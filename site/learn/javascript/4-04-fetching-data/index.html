Fetching Data

lesson 4.044 of 5 in milestone 45 min1 practice task

Loading data over HTTP with fetch - responses and status codes, reading JSON and text, why fetch does not reject on 404, sending JSON with POST, headers, query strings with URLSearchParams, timeouts and cancelling with AbortController, and a small API client.

fetch

fetch(url) starts an HTTP request and returns a promise for a Response. Reading the body is a second step, also asynchronous:

JavaScript
const response = await fetch("https://api.example.com/users/1");
console.log(response.status, response.ok, response.headers.get("content-type"));
const user = await response.json();     // or response.text()

In this course's sandbox, programs cannot reach the internet, but fetch("name.json") reads a file of the project, with the same API. Practice tasks use that.

Check the status

fetch rejects only when the request cannot be made at all (no network, a bad URL, a blocked request). A 404 or 500 still fulfils, with response.ok false. Check it yourself:

JavaScript
async function getJSON(url) {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`${url}: HTTP ${response.status}`);
  return response.json();
}
Status Meaning
200 OK, 201 Created, 204 No Content It worked
400 Bad Request, 422 Your request was wrong; do not retry unchanged
401 Unauthorized, 403 Forbidden Not signed in / not allowed
404 Not Found No such resource
429 Too Many Requests Slow down; retry later
500, 502, 503 The server failed; retrying may help

Sending data

JavaScript
const response = await fetch("https://api.example.com/todos", {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${token}` },
  body: JSON.stringify({ title: "Learn fetch", done: false }),
});

Build query strings with URLSearchParams, which escapes values correctly:

JavaScript
const params = new URLSearchParams({ q: "tea & cake", page: 2 });
console.log(`/search?${params}`);
const url = new URL("https://example.com/search");
url.searchParams.set("q", "café");
console.log(url.href);

Timeouts and cancelling

A request can hang for a long time. An AbortController cancels it; AbortSignal.timeout(ms) makes a signal that cancels by itself:

JavaScript
try {
  const response = await fetch(url, { signal: AbortSignal.timeout(5000) });
  ...
} catch (err) {
  if (err.name === "TimeoutError" || err.name === "AbortError") console.log("gave up waiting");
  else throw err;
}

const controller = new AbortController();
searchButton.onclick = () => controller.abort();     // cancel on demand
await fetch(url, { signal: controller.signal });

A small API client

Put the details in one place, so the rest of the program just calls functions:

JavaScript
const BASE = "https://api.example.com";

async function request(path, { method = "GET", body } = {}) {
  const response = await fetch(BASE + path, {
    method,
    headers: body ? { "Content-Type": "application/json" } : {},
    body: body ? JSON.stringify(body) : undefined,
  });
  if (!response.ok) throw new Error(`${method} ${path} failed: ${response.status}`);
  return response.status === 204 ? null : response.json();
}

export const getTodos = () => request("/todos");
export const addTodo = title => request("/todos", { method: "POST", body: { title } });

Browsers and CORS

In a web page, the browser only lets you read responses from another domain if that server allows it with CORS headers. A "CORS error" is the server's setting, not a bug in your fetch call; it is fixed on the server or by calling through your own backend. Never put secret API keys in browser code: anyone can read them.
