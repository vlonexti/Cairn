Async Generators and Iteration

lesson 8.022 of 5 in milestone 85 min2 practice tasks

Data that arrives a piece at a time - async iterables and for await...of, async generator functions with async function*, paging through an API lazily, transforming async streams with small helper generators, stopping early with break and return, and the Symbol.asyncIterator protocol.

A loop that waits

Lesson 3.04 showed generators: functions that yield values one by one to a for...of loop. Lesson 4.03 showed await. Put them together and you get a loop whose values arrive over time: pages from an API, lines from a file, messages from a socket.

JavaScript
const sleep = ms => new Promise(r => setTimeout(r, ms));

async function* countdown(from) {
  for (let i = from; i > 0; i--) {
    await sleep(10);
    yield i;
  }
}

(async () => {
  for await (const n of countdown(3)) console.log(n);
  console.log("lift off");
})();

async function* declares an async generator. It can await inside, and each yield hands one value to the loop. for await...of waits for each value before running the body.

Paging through an API, lazily

Many APIs return results a page at a time with a "next" cursor. An async generator hides the pages, so the caller sees one stream of items:

JavaScript
const pages = { start: { items: [1, 2, 3], next: "p2" }, p2: { items: [4, 5], next: "p3" }, p3: { items: [6], next: null } };
let requests = 0;
async function fetchPage(cursor) {
  requests++;
  await new Promise(r => setTimeout(r, 5));
  return pages[cursor];
}

async function* allItems() {
  let cursor = "start";
  while (cursor) {
    const page = await fetchPage(cursor);
    yield* page.items;          // yield each item of the page
    cursor = page.next;
  }
}

(async () => {
  for await (const item of allItems()) {
    console.log("item", item);
    if (item === 4) break;      // stop early
  }
  console.log("requests made:", requests);
})();

Because the generator is lazy, stopping at 4 means page 3 is never requested. break (or return, or an exception) in a for await loop also tells the generator to finish, running any finally block inside it, so it can close connections.

Helpers for streams

Small async generators that take a stream and give back a changed one can be chained like array methods:

JavaScript
async function* map(source, fn) {
  for await (const x of source) yield fn(x);
}
async function* filter(source, test) {
  for await (const x of source) if (test(x)) yield x;
}
async function* take(source, n) {
  if (n <= 0) return;
  for await (const x of source) {
    yield x;
    if (--n === 0) return;
  }
}
async function toArray(source) {
  const out = [];
  for await (const x of source) out.push(x);
  return out;
}

async function* numbers() {
  for (let i = 1; ; i++) yield i;       // endless
}

(async () => {
  const result = await toArray(take(filter(map(numbers(), x => x * x), x => x % 2 === 1), 4));
  console.log(result);       // [ 1, 9, 25, 49 ]
})();

Working on an endless source is only possible because each step pulls one value at a time.

for await over ordinary promises

for await also accepts a normal array of promises, waiting for each in order:

JavaScript
const later = (v, ms) => new Promise(r => setTimeout(() => r(v), ms));
(async () => {
  for await (const v of [later("a", 30), later("b", 10)]) console.log(v);   // a, then b
})();

To handle results as they finish rather than in order, use Promise.race in a loop, or a library helper; for await keeps the order you gave.

The protocol

An object is async-iterable when it has a [Symbol.asyncIterator]() method returning an object with an async next() that resolves to { value, done }. Async generators build this for you, but you can write it by hand:

JavaScript
const ticker = {
  [Symbol.asyncIterator]() {
    let n = 0;
    return {
      async next() {
        await new Promise(r => setTimeout(r, 5));
        return n < 3 ? { value: n++, done: false } : { value: undefined, done: true };
      },
    };
  },
};
(async () => {
  for await (const t of ticker) console.log("tick", t);
})();

Node.js streams, fs.promises file handles (file.readLines()), and the browser's ReadableStream are all async-iterable.

Errors

An error thrown inside an async generator comes out of the for await loop, where an ordinary try/catch handles it:

JavaScript
async function* risky() {
  yield 1;
  throw new Error("connection lost");
}
(async () => {
  try {
    for await (const x of risky()) console.log(x);
  } catch (e) {
    console.log("caught:", e.message);
  }
})();
