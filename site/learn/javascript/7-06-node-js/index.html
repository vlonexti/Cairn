Node.js

lesson 7.066 of 6 in milestone 75 min2 practice tasks

JavaScript outside the browser - what Node.js adds, ES modules and CommonJS, reading and writing files with node:fs/promises, paths, command-line arguments and environment variables, exit codes, streams for big files, and package.json scripts.

One language, two places

The browser gives JavaScript the DOM, fetch and localStorage. Node.js runs the same language on a computer or server and gives it the operating system instead: files, processes, network sockets. Tools you already use (npm, Vite, the TypeScript compiler, ESLint) are Node programs.

JavaScript
// hello.mjs, run with:  node hello.mjs Ada
const name = process.argv[2] ?? "world";
console.log(`hello, ${name}`);

Xenon's practice sandbox imitates a small part of Node (console, process.argv, require("fs") for the project's own files). The examples marked as not runnable here are for your own machine.

Modules: two systems

ES modules CommonJS
Syntax import x from "./x.js", export const x = require("./x"), module.exports
Files .mjs, or .js with "type": "module" in package.json .cjs, or .js by default
Loading can await at the top level synchronous

New code uses ES modules (lesson 3.05). You still meet CommonJS in older packages, and import can load it.

Files

node:fs/promises has promise-based versions of every file function:

JavaScript
import { readFile, writeFile, readdir, mkdir } from "node:fs/promises";
import path from "node:path";

const text = await readFile("notes.txt", "utf8");
const words = text.split(/\s+/).filter(Boolean).length;

await mkdir("out", { recursive: true });
await writeFile(path.join("out", "count.txt"), `${words} words\n`);

for (const entry of await readdir(".", { withFileTypes: true })) {
  console.log(entry.isDirectory() ? "dir " : "file", entry.name);
}

A missing file rejects with an error whose code is "ENOENT"; check err.code to tell "not there" from other problems. node:path builds paths correctly on every system: path.join, path.basename, path.extname, path.resolve.

Arguments, environment and exit codes

JavaScript
// node tool.mjs --limit 5 input.csv
const args = process.argv.slice(2);          // [ '--limit', '5', 'input.csv' ]
const debug = process.env.DEBUG === "1";     // set with:  DEBUG=1 node tool.mjs  (PowerShell: $env:DEBUG=1)

if (args.length === 0) {
  console.error("usage: tool [--limit N] FILE");
  process.exit(2);                           // non-zero means failure to whoever started the program
}

node:util has parseArgs for real argument parsing; for anything bigger, packages such as commander do the work. Write errors to console.error (standard error) so they do not mix with the program's real output.

Streams for big files

readFile loads a whole file into memory. For a file of several gigabytes, read it as a stream, piece by piece:

JavaScript
import { createReadStream } from "node:fs";
import { createInterface } from "node:readline";

let lines = 0;
for await (const line of createInterface({ input: createReadStream("huge.log") })) {
  if (line.includes("ERROR")) lines++;
}
console.log(lines, "error lines");

for await (lesson 4.03) reads one line at a time, so memory use stays flat whatever the file size.

package.json and npm scripts

npm init -y creates a package.json describing the project: its name, dependencies, and scripts:

JSON
{
  "name": "word-tool",
  "type": "module",
  "scripts": {
    "start": "node src/main.js",
    "test": "node --test"
  },
  "dependencies": { "chalk": "^5.3.0" }
}

npm install chalk adds a dependency, npm run start runs a script, and npm test runs the test script. node --test is Node's built-in test runner: files that call test(...) from node:test with assert from node:assert/strict.

A pure core, a thin shell

Keep the logic (parsing, counting, deciding) in plain functions that take values and return values, and keep the file and process handling in a thin outer layer. The core can then be tested anywhere, including Xenon's sandbox, and the shell is small enough to check by running it.
