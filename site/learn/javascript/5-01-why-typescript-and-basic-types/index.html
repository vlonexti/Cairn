Why TypeScript and Basic Types

lesson 5.011 of 5 in milestone 55 min1 practice task

What TypeScript adds to JavaScript and what it does not change, compiling and type-checking, annotating variables, parameters and return values, type inference, arrays and tuples, any versus unknown, null and undefined under strict mode, and reading type errors.

JavaScript with types

TypeScript is JavaScript plus type annotations. A compiler (tsc) checks that values are used consistently, then removes the types and produces plain JavaScript. Types exist only while you write and check the code: at run time it is the same JavaScript as before.

TypeScript
function area(width: number, height: number): number {
  return width * height;
}

area(3, 4);        // fine
area("3", 4);      // error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
area(3);           // error TS2554: Expected 2 arguments, but got 1.

Errors like these appear as you type, before the code runs. Whole classes of bugs (a typo in a property name, a forgotten argument, a possibly-undefined value) are caught at once, and the editor can complete names because it knows each value's shape.

In this course, files ending in .ts are type-checked in the editor: problems are underlined and listed in the Problems panel. Running and checking a task executes the JavaScript that remains, so a task's tests check what the code does, and its requirements check that you wrote the types.

Annotations and inference

TypeScript
let title: string = "Dune";
let pages = 412;                     // inferred: number
const done = false;                  // inferred: the literal type false
const ratings: number[] = [5, 4];
const pair: [string, number] = ["age", 36];     // a tuple: fixed length, a type per position

function describe(name: string, age?: number): string {   // ? = optional
  return age === undefined ? name : `${name} (${age})`;
}

console.log(describe(title), describe("Ada", 36), ratings, pair);

TypeScript infers types from values, so annotate where it helps: function parameters (always), return types of exported functions, and variables that start empty (const names: string[] = []). Do not annotate what is obvious: const count: number = 0 adds nothing.

The basic types

Type Values
string, number, boolean, bigint As in JavaScript
null, undefined Only those values
T[] or Array<T> Arrays of T
[A, B] Tuples
void A function returns nothing useful
never Never happens: a function that always throws
unknown Anything, but you must check before using it
any Anything, with checking switched off

any and unknown

any turns the type checker off for that value: everything is allowed, so mistakes slip through. unknown also accepts anything, but you must narrow it (lesson 5.03) before use:

TypeScript
function lengthOf(value: unknown): number {
  if (typeof value === "string" || Array.isArray(value)) return value.length;
  return 0;
}
console.log(lengthOf("hello"), lengthOf([1, 2]), lengthOf(42));

Use unknown for data from outside: JSON.parse results, fetch responses, user input. Avoid any.

strict mode and null

With "strict": true in tsconfig.json (always use it), null and undefined are separate types. A value that may be missing must say so, and you must check before using it:

TypeScript
function firstWord(text: string | undefined): string {
  return text.split(" ")[0];      // error TS18048: 'text' is possibly 'undefined'.
}
TypeScript
function firstWord(text: string | undefined): string {
  if (text === undefined) return "";
  return text.split(" ")[0];
}
console.log(firstWord("hello world"), JSON.stringify(firstWord(undefined)));

The ! operator (text!.split(...)) tells the compiler "trust me, it is not null". Use it rarely: it is exactly the kind of claim the checker exists to verify.

Reading type errors

Type errors read from the general to the specific: the last line usually names the actual mismatch. Type 'string' is not assignable to type 'number' means a string was given where a number is required. Fix the code, not the type, unless the type is what is wrong.
