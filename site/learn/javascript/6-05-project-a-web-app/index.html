Project: A Web App

lesson 6.055 of 5 in milestone 65 min1 practice task

Putting the course together in a complete browser app - a single state object, actions and a pure update function, rendering from state with escaped HTML, event delegation, saving to localStorage with versions, and how the parts are split into modules and tested.

The plan

A small but complete app, a habit tracker: add habits, tick them off per day, see streaks, and keep everything after a reload. The structure works for most small apps:

flowchart LR
  E[User event] --> A[Action object]
  A --> U["update(state, action)"]
  U --> S[New state]
  S --> R["render(state)"]
  S --> P["save(storage, state)"]
  R --> D[DOM]
  D --> E
  • State: one plain object that describes everything on screen.
  • Actions: plain objects such as { type: "add", name: "Read" } describing what the user did.
  • update: a pure function (state, action) => newState. No DOM, no storage: easy to test.
  • render: draws the page from the state.
  • storage: saves the state after each change and loads it at start.

Modules

Text

  storage.ts   load() and save() with versions
  main.ts      wiring: events -> update -> render + save

Only main.ts touches the DOM and localStorage; the other three can be tested without a browser. The project for this milestone is exactly those pure parts.

State and actions

TypeScript
export interface Habit { id: number; name: string; days: string[] }      // days: "YYYY-MM-DD" ticked
export interface State { version: 1; habits: Habit[]; nextId: number }

export type Action =
  | { type: "add"; name: string }
  | { type: "toggle"; id: number; day: string }
  | { type: "remove"; id: number };

export function update(state: State, action: Action): State {
  switch (action.type) {
    case "add":
      return { ...state, habits: [...state.habits, { id: state.nextId, name: action.name.trim(), days: [] }], nextId: state.nextId + 1 };
    case "toggle":
      return { ...state, habits: state.habits.map(h => h.id !== action.id ? h : {
        ...h, days: h.days.includes(action.day) ? h.days.filter(d => d !== action.day) : [...h.days, action.day].sort(),
      }) };
    case "remove":
      return { ...state, habits: state.habits.filter(h => h.id !== action.id) };
  }
}

update never changes the old state; it returns a new one. That makes undo trivial (keep old states) and bugs easier to find (nothing changes behind your back).

Rendering

TypeScript
export function render(state: State, today: string): string {
  if (state.habits.length === 0) return `<p class="empty">No habits yet.</p>`;
  return `<ul>${state.habits.map(h => `
    <li data-id="${h.id}">
      <button data-action="toggle" aria-pressed="${h.days.includes(today)}">${escapeHtml(h.name)}</button>
      <span class="streak">${streak(h.days, today)} day streak</span>
      <button data-action="remove" aria-label="Remove ${escapeHtml(h.name)}">×</button>
    </li>`).join("")}</ul>`;
}

Every piece of user text goes through escapeHtml, because this string becomes innerHTML.

Wiring it up

TypeScript
import { update, type State, type Action } from "./state";
import { render } from "./view";
import { load, save } from "./storage";

let state: State = load(localStorage);
const app = document.querySelector<HTMLElement>("#app")!;
const today = () => new Date().toISOString().slice(0, 10);

function dispatch(action: Action) {
  state = update(state, action);
  save(localStorage, state);
  app.innerHTML = render(state, today());
}

document.querySelector("form")!.addEventListener("submit", e => {
  e.preventDefault();
  const input = (e.currentTarget as HTMLFormElement).elements.namedItem("name") as HTMLInputElement;
  if (input.value.trim()) dispatch({ type: "add", name: input.value });
  input.value = "";
});

app.addEventListener("click", e => {
  const button = (e.target as Element).closest<HTMLButtonElement>("button[data-action]");
  const id = Number(button?.closest("li")?.dataset.id);
  if (button?.dataset.action === "toggle") dispatch({ type: "toggle", id, day: today() });
  if (button?.dataset.action === "remove") dispatch({ type: "remove", id });
});

app.innerHTML = render(state, today());

Thirty lines of DOM code; everything else is pure and tested. Rebuilding the whole list with innerHTML is fine for a few hundred items; beyond that, update only what changed, or use a library.

Shipping it

npm run build with Vite gives a dist/ folder of static files. Any static host serves it: GitHub Pages, Netlify, Cloudflare Pages. Because the data lives in localStorage, there is no server to run.

Where to go next

  • A framework: React, Vue or Svelte. You now know what they automate: state, re-rendering, and event wiring.
  • A backend: Node with a framework such as Express or Fastify, and a database, so data follows the user across devices.
  • Testing: Vitest for the pure parts and Playwright for clicking through the real page.
