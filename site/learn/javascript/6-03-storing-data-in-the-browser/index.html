Storing Data in the Browser

lesson 6.033 of 5 in milestone 65 min1 practice task

Keeping data between visits - localStorage and sessionStorage, storing objects as JSON, handling missing, corrupt and old data with versions, storage limits and errors, cookies in brief, IndexedDB for larger data, and what never to store in the browser.

localStorage

localStorage keeps strings per site, across reloads and restarts:

JavaScript
localStorage.setItem("theme", "dark");
localStorage.getItem("theme");        // "dark"; null if missing
localStorage.removeItem("theme");
localStorage.clear();                 // everything for this site

sessionStorage has the same API but forgets when the tab closes. Both are synchronous and limited to a few megabytes per site.

Storing objects

Storage holds strings only. Objects go through JSON (lesson 2.05):

JavaScript
localStorage.setItem("todos", JSON.stringify(todos));
const todos = JSON.parse(localStorage.getItem("todos") ?? "[]");

Treat stored data as untrusted input: the user may have cleared it, another version of your app may have written it, an extension may have changed it, or it may be cut off. Reading must never crash the app:

JavaScript
function load(storage, key, fallback) {
  try {
    const text = storage.getItem(key);
    if (text === null) return fallback;
    return JSON.parse(text);
  } catch {
    return fallback;            // corrupt JSON or storage not available (private mode, blocked)
  }
}

function save(storage, key, value) {
  try {
    storage.setItem(key, JSON.stringify(value));
    return true;
  } catch {
    return false;               // full (QuotaExceededError) or blocked
  }
}

const fake = new Map();
const storage = { getItem: k => fake.get(k) ?? null, setItem: (k, v) => fake.set(k, String(v)) };
save(storage, "todos", [{ title: "tea" }]);
fake.set("broken", "{oops");
console.log(load(storage, "todos", []), load(storage, "broken", []), load(storage, "missing", []));

Passing the storage in as a parameter, instead of using localStorage directly, lets tests use a fake. The practice tasks use exactly this.

Versions

Apps change. Store a version with the data and upgrade old shapes when loading:

JavaScript
function migrate(saved) {
  let data = saved;
  if (data.version === 1) data = { version: 2, items: data.todos.map(t => ({ ...t, tags: [] })) };
  if (data.version !== 2) return { version: 2, items: [] };
  return data;
}
console.log(migrate({ version: 1, todos: [{ title: "a" }] }));

Other storage

Storage For
localStorage / sessionStorage Small settings and app state (a few MB, strings)
Cookies Small values the server must see on each request, such as a session id; set by the server with HttpOnly and Secure
IndexedDB Large or structured data, files, offline apps; asynchronous (libraries such as idb make it pleasant)
Cache API Responses for offline use, with service workers

What not to store

Anything in localStorage can be read by every script on the page, including injected ones (lesson 6.01's XSS). Never store passwords there, and be careful with access tokens; a server-set HttpOnly cookie cannot be read by JavaScript at all. Storage is per browser and per device: for data the user must not lose, save it on a server too.
