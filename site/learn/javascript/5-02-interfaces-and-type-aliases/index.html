Interfaces and Type Aliases

lesson 5.022 of 5 in milestone 55 min1 practice task

Describing the shape of objects with interfaces and type aliases, optional and readonly properties, function types, index signatures and Record, extending and intersecting types, structural typing, and excess property checks.

Describing objects

An interface names the shape of an object:

TypeScript
interface Book {
  title: string;
  author: string;
  year: number;
  tags?: string[];            // optional
  readonly isbn: string;      // cannot be reassigned
}

function cite(book: Book): string {
  return `${book.author}, ${book.title} (${book.year})`;
}

const dune: Book = { title: "Dune", author: "Frank Herbert", year: 1965, isbn: "978-0441013593" };
console.log(cite(dune));

A type alias gives a name to any type, including object shapes:

TypeScript
type Point = { x: number; y: number };
type Id = string | number;
type Pair<T> = [T, T];

const origin: Point = { x: 0, y: 0 };
const ids: Id[] = [1, "a7"];
const range: Pair<number> = [1, 10];
console.log(origin, ids, range);

For object shapes both work; a common rule is: interface for objects and classes, type for unions, tuples and everything else.

Structural typing

TypeScript compares types by their shape, not their name. Any object with the right properties fits, whatever it was declared as:

TypeScript
interface Named { name: string }
const user = { name: "Ada", age: 36 };
function hello(x: Named) { return `hello ${x.name}`; }
console.log(hello(user));     // fine: user has a name, the extra age does not matter

One exception: an object literal written directly where a type is expected may not have unknown properties (hello({ name: "Ada", agee: 36 }) is an error), because that is usually a typo.

Functions and indexes

TypeScript
type Compare<T> = (a: T, b: T) => number;
const byLength: Compare<string> = (a, b) => a.length - b.length;

interface Scores {
  [player: string]: number;    // an index signature: any string key, number values
}
const scores: Scores = { ada: 3, bob: 5 };
const lives: Record<string, number> = { ada: 2 };   // the same idea with the Record utility type

console.log(["ccc", "a", "bb"].sort(byLength), scores.bob, lives.ada);

With an index signature, reading a key that is not there gives undefined at run time even though the type says number. The compiler option noUncheckedIndexedAccess makes such reads number | undefined.

Combining types

An interface can extend others; a type alias can intersect them with &:

TypeScript
interface Entity { id: number; createdAt: string }
interface User extends Entity { name: string; email: string }

type Timestamped = { updatedAt: string };
type SavedUser = User & Timestamped;

const u: SavedUser = { id: 1, createdAt: "2026-01-01", name: "Ada", email: "ada@example.com", updatedAt: "2026-02-01" };
console.log(Object.keys(u).length);

readonly

readonly stops reassignment through that type: book.isbn = "x" is an error. readonly string[] (or ReadonlyArray<string>) has no push, sort or other changing methods, which documents that a function will not change your array:

TypeScript
function total(prices: readonly number[]): number {
  prices.push(0);            // error TS2339: Property 'push' does not exist on type 'readonly number[]'.
  return prices.reduce((a, b) => a + b, 0);
}

Like all types, readonly is checked only at compile time.
