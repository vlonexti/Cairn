Cancelling Work with AbortController

lesson 8.033 of 5 in milestone 85 min2 practice tasks

Stopping work that is no longer wanted - AbortController and AbortSignal, cancelling fetch, timeouts with AbortSignal.timeout, combining signals with AbortSignal.any, making your own async functions cancellable, cleaning up listeners, and the AbortError convention.

Work nobody is waiting for

A user types in a search box: each key starts a search, and only the last result matters. A user leaves a page while it is still loading. A request takes too long. In each case the program should stop the work, not just ignore its result: stopping saves the network, the battery and the server.

JavaScript's standard way to ask for that is a pair of objects:

  • an AbortController, held by the code that may want to cancel;
  • its AbortSignal (controller.signal), passed to the work that should stop.
JavaScript
const controller = new AbortController();
const signal = controller.signal;

signal.addEventListener("abort", () => console.log("abort event, reason:", signal.reason));
console.log(signal.aborted);     // false
controller.abort("user left");
console.log(signal.aborted);     // true

abort() can only happen once; calling it again does nothing.

Cancelling fetch

fetch accepts a signal. When it is aborted, the request stops and the promise rejects with an error whose name is "AbortError":

JavaScript
const controller = new AbortController();
const promise = fetch("/api/search?q=tea", { signal: controller.signal });
controller.abort();
try {
  await promise;
} catch (e) {
  if (e.name === "AbortError") console.log("cancelled, as asked");
  else throw e;
}

Treat AbortError differently from real failures: it is not a problem to report to the user.

Timeouts

AbortSignal.timeout(ms) gives a signal that aborts itself after a time (with a "TimeoutError"), and AbortSignal.any([...]) gives a signal that aborts when any of several does:

JavaScript
const userCancel = new AbortController();
const signal = AbortSignal.any([userCancel.signal, AbortSignal.timeout(5000)]);
const response = await fetch("/api/report", { signal });

Making your own functions cancellable

Any async function can take a signal. The two rules:

  1. Check signal.aborted (or call signal.throwIfAborted()) before starting and between steps.
  2. While waiting, listen for the abort event and stop waiting at once.
JavaScript
function sleep(ms, signal) {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) return reject(signal.reason);
    const timer = setTimeout(() => {
      signal?.removeEventListener("abort", onAbort);
      resolve();
    }, ms);
    function onAbort() {
      clearTimeout(timer);
      reject(signal.reason);
    }
    signal?.addEventListener("abort", onAbort, { once: true });
  });
}

async function slowCount(n, signal) {
  for (let i = 1; i <= n; i++) {
    signal?.throwIfAborted();
    await sleep(20, signal);
    console.log("step", i);
  }
  return "finished";
}

const controller = new AbortController();
setTimeout(() => controller.abort(new Error("stopped by the user")), 50);
slowCount(10, controller.signal).then(console.log, e => console.log("ended:", e.message));

The listener is removed when the timer finishes normally. Forgetting to remove listeners from a long-lived signal is a memory leak.

The newest search wins

Cancelling the previous request each time a new one starts:

JavaScript
let current = null;
const log = [];

function fakeSearch(text, signal) {
  return sleepValue(text.length * 15, `results for ${text}`, signal);
}
function sleepValue(ms, value, signal) {
  return new Promise((resolve, reject) => {
    const t = setTimeout(() => resolve(value), ms);
    signal.addEventListener("abort", () => { clearTimeout(t); reject(signal.reason); }, { once: true });
  });
}

async function search(text) {
  current?.abort();
  current = new AbortController();
  try {
    log.push(await fakeSearch(text, current.signal));
  } catch (e) {
    if (e.name !== "AbortError") throw e;
    log.push(`cancelled ${text}`);
  }
}

Promise.all([search("t"), search("te"), search("tea")]).then(() => console.log(log));

controller.abort() with no argument gives a DOMException named "AbortError" as the reason, which is why the check works.

Not only for async work

Event listeners accept a signal too: aborting removes every listener that was added with it, which is a tidy way to clean up a component.

JavaScript
const controller = new AbortController();
window.addEventListener("resize", onResize, { signal: controller.signal });
document.addEventListener("keydown", onKey, { signal: controller.signal });
// later, when the component goes away:
controller.abort();     // both listeners removed
