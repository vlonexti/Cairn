Getters, Setters and Symbols

lesson 7.022 of 6 in milestone 75 min2 practice tasks

Controlling properties - get and set on objects and classes, property descriptors with Object.defineProperty, freezing and sealing, Symbols as hidden keys, and the well-known symbols (Symbol.iterator, Symbol.toPrimitive, Symbol.toStringTag) that hook into the language.

Getters and setters

A getter is a function that runs when a property is read; a setter runs when it is assigned. From outside they look like plain properties:

JavaScript
class Temperature {
  #celsius = 0;

  get celsius() { return this.#celsius; }
  set celsius(value) {
    if (value < -273.15) throw new RangeError("below absolute zero");
    this.#celsius = value;
  }
  get fahrenheit() { return this.#celsius * 9 / 5 + 32; }   // read-only: no setter
}

const t = new Temperature();
t.celsius = 25;
console.log(t.fahrenheit);   // 77

They work in object literals too: { get total() { return this.a + this.b; } }. Assigning to a getter-only property is silently ignored outside strict mode and an error inside it (and modules and classes are always strict).

Property descriptors

Every property has hidden settings. Object.getOwnPropertyDescriptor shows them and Object.defineProperty sets them:

JavaScript
const config = {};
Object.defineProperty(config, "version", {
  value: "1.0",
  writable: false,      // cannot be changed
  enumerable: false,    // hidden from Object.keys and for...in
  configurable: false,  // cannot be deleted or redefined
});
console.log(config.version, Object.keys(config));          // 1.0 []
console.log(Object.getOwnPropertyDescriptor(config, "version"));

Properties made the ordinary way are writable, enumerable and configurable.

Freezing and sealing

Call New properties Delete Change values
Object.preventExtensions(o) no yes yes
Object.seal(o) no no yes
Object.freeze(o) no no no
JavaScript
"use strict";
const settings = Object.freeze({ theme: "dark", sizes: [1, 2] });
try {
  settings.theme = "light";
} catch (e) {
  console.log(e.constructor.name);    // TypeError
}
settings.sizes.push(3);              // freezing is shallow: nested objects can still change
console.log(settings.sizes);

Symbols

A Symbol is a unique value that can be used as a property key. Two symbols with the same description are still different, so a symbol key never clashes with anyone else's property:

JavaScript
const id = Symbol("id");
const user = { name: "Ada", [id]: 42 };
console.log(user[id], Object.keys(user), JSON.stringify(user));   // 42 [ 'name' ] {"name":"Ada"}
console.log(Symbol("id") === id);                                 // false

Symbol keys are skipped by Object.keys, for...in and JSON.stringify, which makes them good for attaching data to objects you do not own. Symbol.for("name") returns the same symbol everywhere for that name, when you do want sharing.

Well-known symbols

The language looks up some symbols on your objects to decide how to treat them. You met Symbol.iterator in lesson 3.04. Two more:

JavaScript
class Money {
  constructor(cents) { this.cents = cents; }

  // How the object turns into a primitive: hint is "number", "string" or "default".
  [Symbol.toPrimitive](hint) {
    return hint === "number" ? this.cents / 100 : `$${(this.cents / 100).toFixed(2)}`;
  }

  get [Symbol.toStringTag]() { return "Money"; }
}

const price = new Money(1250);
console.log(`${price}`, +price * 2, Object.prototype.toString.call(price));
// $12.50 25 [object Money]
