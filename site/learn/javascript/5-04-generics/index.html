Generics

lesson 5.044 of 5 in milestone 55 min1 practice task

Writing functions, interfaces and classes that work for any type while keeping type information - type parameters, inference of type arguments, constraints with extends, keyof and indexed access types, default type parameters, and generic containers.

Type parameters

A function that works for any type, and still knows what it returns, takes a type parameter:

TypeScript
function first<T>(items: T[]): T | undefined {
  return items[0];
}

const n = first([3, 1, 2]);          // T is number, so n is number | undefined
const s = first(["a", "b"]);         // T is string
console.log(n, s);

Without generics you would choose between first(items: any[]): any (losing the type) and one function per type. TypeScript infers T from the arguments; you can also write it: first<string>([]).

Several parameters

TypeScript
function mapValues<K extends string, A, B>(obj: Record<K, A>, f: (value: A) => B): Record<K, B> {
  const out = {} as Record<K, B>;
  for (const key of Object.keys(obj) as K[]) out[key] = f(obj[key]);
  return out;
}

const prices = { tea: 2.5, cake: 4 };
const labels = mapValues(prices, p => `${p.toFixed(2)} EUR`);   // Record<"tea" | "cake", string>
console.log(labels);

function groupBy<T, K extends string>(items: T[], key: (item: T) => K): Record<K, T[]> {
  const out = {} as Record<K, T[]>;
  for (const item of items) (out[key(item)] ??= []).push(item);
  return out;
}
console.log(groupBy(["apple", "avocado", "banana"], w => w[0]));

Constraints

T extends Something limits T to types that have certain members, so the body can use them:

TypeScript
function longest<T extends { length: number }>(a: T, b: T): T {
  return b.length > a.length ? b : a;
}
console.log(longest("tea", "coffee"), longest([1, 2], [1]));
// longest(10, 20)   // error: number has no length

keyof and indexed access

keyof T is the union of T's property names, and T[K] is the type of property K. Together they type functions that take a property name:

TypeScript
function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {
  return items.map(item => item[key]);
}

const users = [{ name: "Ada", age: 36 }, { name: "Linus", age: 55 }];
const names = pluck(users, "name");     // string[]
const ages = pluck(users, "age");       // number[]
// pluck(users, "email")                // error: "email" is not a key of the user type
console.log(names, ages);

Generic interfaces and classes

TypeScript
interface ApiResponse<T> { status: number; data: T }

class Stack<T> {
  #items: T[] = [];
  push(item: T): void { this.#items.push(item); }
  pop(): T | undefined { return this.#items.pop(); }
  peek(): T | undefined { return this.#items.at(-1); }
  get size(): number { return this.#items.length; }
}

const s = new Stack<number>();
s.push(1); s.push(2);
// s.push("3")                         // error: string is not number
const res: ApiResponse<string[]> = { status: 200, data: ["a"] };
console.log(s.pop(), s.size, res.data);

Type parameters can have defaults: interface Page<T = unknown> { items: T[]; next?: string }.

When to use generics

Use a type parameter when it connects types: the input type determines the output type, or two arguments must match. If T appears only once in a signature, it is not doing anything: function log<T>(x: T): void is just function log(x: unknown): void.
