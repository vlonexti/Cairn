Advanced TypeScript Types

lesson 7.055 of 6 in milestone 75 min2 practice tasks

Types that compute other types - keyof, typeof and indexed access, mapped types, conditional types and infer, template literal types, satisfies, user-defined type guards and assertion functions, and declaration files for JavaScript code.

Types from values and from other types

Lessons 5.01 to 5.05 wrote types by hand. TypeScript can also derive types, so they stay in step with the code automatically.

TypeScript
const defaults = { theme: "dark", fontSize: 14, showTips: true };

type Settings = typeof defaults;          // { theme: string; fontSize: number; showTips: boolean }
type SettingName = keyof Settings;        // "theme" | "fontSize" | "showTips"
type FontSize = Settings["fontSize"];     // number   (an indexed access type)

function get<K extends SettingName>(name: K): Settings[K] {
  return defaults[name];
}
const size = get("fontSize");             // number, known from the argument
console.log(size + 1);

typeof (in a type position) turns a value into its type; keyof gives the union of a type's keys; T[K] looks up the type of a property.

Mapped types

A mapped type builds a new object type by going over the keys of another:

TypeScript
type Settings = { theme: string; fontSize: number };

type Flags<T> = { [K in keyof T]: boolean };              // same keys, every value boolean
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
type Mutable<T> = { -readonly [K in keyof T]: T[K] };     // removes readonly

const changed: Flags<Settings> = { theme: true, fontSize: false };
const api: Getters<Settings> = { getTheme: () => "dark", getFontSize: () => 14 };
console.log(changed.theme, api.getFontSize());

The utility types you already use (Partial, Readonly, Pick, Record) are mapped types in the standard library.

Conditional types and infer

A conditional type chooses between two types: T extends U ? X : Y. With infer, it can pull a type out of another:

TypeScript
type IsString<T> = T extends string ? "yes" : "no";
type A = IsString<"hi">;           // "yes"

type ElementOf<T> = T extends readonly (infer E)[] ? E : never;
type B = ElementOf<number[]>;      // number

type Awaited2<T> = T extends Promise<infer V> ? V : T;
type C = Awaited2<Promise<string>>;   // string

const check: [A, B, C] = ["yes", 42, "done"];
console.log(check);

Given a union, a conditional type is applied to each member separately, which is how Exclude<T, U> removes members: type Exclude<T, U> = T extends U ? never : T;.

Template literal types

Strings can be built at the type level too:

TypeScript
type Side = "top" | "bottom";
type Edge = "left" | "right";
type Corner = `${Side}-${Edge}`;     // "top-left" | "top-right" | "bottom-left" | "bottom-right"
type EventName<T extends string> = `on${Capitalize<T>}`;

const corner: Corner = "bottom-left";
const handler: EventName<"click"> = "onClick";
console.log(corner, handler);

satisfies

satisfies checks a value against a type without widening the value's own type:

TypeScript
type Colour = "red" | "green" | "blue";
const palette = {
  red: [255, 0, 0],
  green: "#00ff00",
} satisfies Partial<Record<Colour, string | number[]>>;

console.log(palette.green.toUpperCase());   // still known to be a string
console.log(palette.red.length);            // still known to be an array

With : Partial<Record<...>> instead, both properties would have the wide type string | number[] | undefined.

Type guards and assertion functions

A function returning value is Type teaches TypeScript to narrow (lesson 5.03) with your own check:

TypeScript
type Cat = { kind: "cat"; meow(): string };
type Dog = { kind: "dog"; bark(): string };

function isCat(pet: Cat | Dog): pet is Cat {
  return pet.kind === "cat";
}

function assertDefined<T>(value: T | undefined, name: string): asserts value is T {
  if (value === undefined) throw new Error(`${name} is missing`);
}

function speak(pet: Cat | Dog): string {
  return isCat(pet) ? pet.meow() : pet.bark();   // pet is Cat, then Dog
}
console.log(speak({ kind: "dog", bark: () => "woof" }));

const port: number | undefined = 8080;
assertDefined(port, "port");
console.log(port + 1);      // number from here on

Declaration files

A plain JavaScript library has no types. A declaration file (.d.ts) describes it without any code:

TypeScript
// greet.d.ts
export function greet(name: string, options?: { shout?: boolean }): string;
export const version: string;

Most popular libraries ship their own, and the rest have community ones installed with npm install --save-dev @types/<library>.
