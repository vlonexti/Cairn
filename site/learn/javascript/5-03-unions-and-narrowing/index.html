Unions and Narrowing

lesson 5.033 of 5 in milestone 55 min1 practice task

Union types for values that can be one of several things, literal types, narrowing with typeof, instanceof, in and equality checks, discriminated unions with a kind field, exhaustive switches with never, and type guard functions for validating unknown data.

Unions

A union type A | B means "an A or a B":

TypeScript
function pad(value: string | number): string {
  if (typeof value === "number") return value.toFixed(2).padStart(8);   // here value is number
  return value.padStart(8);                                              // here value is string
}
console.log(`[${pad(3.5)}] [${pad("abc")}]`);

Inside the if, TypeScript knows value is a number; after it, a string. This is narrowing: checks you would write anyway in JavaScript teach the compiler which type you have.

Literal types limit a value to exact options:

TypeScript
type Direction = "up" | "down" | "left" | "right";
type Dice = 1 | 2 | 3 | 4 | 5 | 6;
function move(d: Direction, steps: Dice) { return `${d} ${steps}`; }
console.log(move("up", 3));
// move("north", 7)   // two errors: neither value is allowed

Ways to narrow

Check Narrows
typeof x === "string" primitives: string, number, boolean, bigint, symbol, undefined, function
x instanceof Date class instances
"radius" in shape objects that have that property
x === null, x !== undefined, if (x) removes null / undefined (careful: if (x) also removes 0 and "")
Array.isArray(x) arrays

Discriminated unions

The most useful pattern in TypeScript: each variant has a common tag property with a literal type.

TypeScript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "rect"; width: number; height: number }
  | { kind: "triangle"; base: number; height: number };

function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.radius ** 2;     // s is the circle variant here
    case "rect": return s.width * s.height;
    case "triangle": return (s.base * s.height) / 2;
    default: {
      const unreachable: never = s;                   // error if a variant is not handled
      throw new Error(`unknown shape ${JSON.stringify(unreachable)}`);
    }
  }
}

const shapes: Shape[] = [{ kind: "circle", radius: 1 }, { kind: "rect", width: 2, height: 3 }];
console.log(shapes.map(area).map(a => a.toFixed(2)));

The never line makes the switch exhaustive: if someone adds { kind: "hexagon" } to Shape and forgets area, the assignment fails to compile, pointing at the exact place to update.

Results are often modelled the same way:

TypeScript
type Result<T> = { ok: true; value: T } | { ok: false; error: string };

function parsePort(text: string): Result<number> {
  const n = Number(text);
  return Number.isInteger(n) && n > 0 && n < 65536 ? { ok: true, value: n } : { ok: false, error: `bad port "${text}"` };
}
const r = parsePort("80");
if (r.ok) console.log("port", r.value); else console.log(r.error);

Type guards

A function returning x is T is a type guard: when it returns true, the caller's value is narrowed to T. Use them to validate unknown data:

TypeScript
interface User { name: string; age: number }

function isUser(x: unknown): x is User {
  return typeof x === "object" && x !== null
    && typeof (x as User).name === "string"
    && typeof (x as User).age === "number";
}

const data: unknown = JSON.parse('{"name": "Ada", "age": 36}');
if (isUser(data)) console.log(data.name.toUpperCase(), data.age + 1);

x as User is a type assertion: it tells the compiler to treat the value as a User without any check. Inside a guard that verifies each property it is fine; elsewhere, an assertion is a claim the compiler cannot verify, so prefer narrowing.
