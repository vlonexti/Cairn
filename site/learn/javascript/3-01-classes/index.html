A class

A class describes a kind of object: the data each one holds and what it can do.

JavaScript
class Account {
  owner;                        // a public field
  #balance = 0;                 // a private field: only code inside the class can use it

  constructor(owner, opening = 0) {
    this.owner = owner;
    this.deposit(opening);
  }

  deposit(amount) {
    if (amount < 0) throw new RangeError("deposit must not be negative");
    this.#balance += amount;
    return this;                // returning this allows chaining
  }

  get balance() {               // read like a property: acc.balance
    return this.#balance;
  }

  toString() {
    return `${this.owner}: ${this.#balance.toFixed(2)}`;
  }
}

const acc = new Account("Ada", 10);
acc.deposit(5).deposit(2.5);
console.log(acc.balance, String(acc));
// acc.#balance                // SyntaxError outside the class

new Account(...) creates an object and runs constructor with this set to it. Inside methods, this is the object the method was called on.

Getters, setters and static members

JavaScript
class Temperature {
  #celsius;
  constructor(celsius) { this.#celsius = celsius; }
  get fahrenheit() { return this.#celsius * 9 / 5 + 32; }
  set fahrenheit(f) { this.#celsius = (f - 32) * 5 / 9; }
  static fromFahrenheit(f) { const t = new Temperature(0); t.fahrenheit = f; return t; }
  static #count = 0;
}

const t = Temperature.fromFahrenheit(212);
console.log(t.fahrenheit);
t.fahrenheit = 32;
console.log(t.fahrenheit);

A setter runs code when a property is assigned, which is the place to validate. Static members belong to the class itself, not to each object: Temperature.fromFahrenheit, Math.max, Number.isInteger. Static factory methods like fromFahrenheit give alternative ways to build an object.

Inheritance

extends makes a class that starts with everything of another. The child's constructor must call super(...) before using this:

JavaScript
class Shape {
  constructor(name) { this.name = name; }
  area() { return 0; }
  describe() { return `${this.name} with area ${this.area().toFixed(1)}`; }
}

class Circle extends Shape {
  constructor(r) { super("circle"); this.r = r; }
  area() { return Math.PI * this.r ** 2; }       // overrides Shape's area
}

class Square extends Shape {
  constructor(side) { super("square"); this.side = side; }
  area() { return this.side ** 2; }
  describe() { return super.describe() + " (a square)"; }   // extends the parent's version
}

const shapes = [new Circle(1), new Square(2)];
for (const s of shapes) console.log(s.describe());
console.log(shapes[0] instanceof Circle, shapes[0] instanceof Shape, shapes[0] instanceof Square);

describe in Shape calls this.area(), which runs the child's version: each object answers in its own way (polymorphism).

When to use a class

Use a class when many objects share behaviour and keep state that must stay consistent (a bank account, a game entity, a connection). For plain data, an object literal is enough; for a single operation, a function is enough. Prefer shallow hierarchies: one level of extends is common, three is usually a sign that composition (an object holding other objects) fits better.
