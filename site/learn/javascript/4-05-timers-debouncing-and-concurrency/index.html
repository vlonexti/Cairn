Timers, Debouncing and Concurrency

lesson 4.055 of 5 in milestone 45 min1 practice task

setTimeout, setInterval and clearing them, a sleep helper, debounce and throttle for noisy events, timeouts for promises, retrying with backoff, and running async work with a concurrency limit.

Timers

JavaScript
const id = setTimeout(() => console.log("never runs"), 100);
clearTimeout(id);

let ticks = 0;
const timer = setInterval(() => {
  ticks++;
  console.log("tick", ticks);
  if (ticks === 3) clearInterval(timer);
}, 20);

Delays are minimums, not exact: a timer runs when its time has passed and the event loop is free. Browsers slow timers down in background tabs.

A promise-based sleep is a one-liner:

JavaScript
const sleep = ms => new Promise(resolve => setTimeout(resolve, ms));
(async () => { console.log("waiting"); await sleep(30); console.log("done"); })();

Debounce

Some events fire many times a second: typing, scrolling, resizing. Debouncing waits until the events stop for a while, then runs once. A search box that queries a server should debounce, or it sends a request per key press.

JavaScript
function debounce(f, ms) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => f(...args), ms);
  };
}

const search = debounce(q => console.log("searching for", q), 30);
search("c"); search("ca"); search("cat");        // only "cat" is searched

Throttle

Throttling runs at most once per period, ignoring calls in between. It suits continuous updates, such as saving the position while dragging:

JavaScript
function throttle(f, ms) {
  let last = -Infinity;
  return (...args) => {
    const now = Date.now();
    if (now - last >= ms) { last = now; f(...args); }
  };
}
const log = throttle(x => console.log("ran with", x), 1000);
log(1); log(2); log(3);                         // only 1 runs

Timeouts for promises

Promise.race with a timer gives any operation a time limit:

JavaScript
function withTimeout(promise, ms) {
  let timer;
  const timeout = new Promise((_, reject) => {
    timer = setTimeout(() => reject(new Error(`timed out after ${ms} ms`)), ms);
  });
  return Promise.race([promise, timeout]).finally(() => clearTimeout(timer));
}

const slow = new Promise(r => setTimeout(() => r("slow result"), 100));
withTimeout(slow, 20).then(console.log, err => console.log(err.message));

The finally clears the timer so it does not keep the program alive after the work is done.

Retrying

Network calls fail now and then. Retry a few times with a growing wait (exponential backoff), and only for errors where retrying can help:

JavaScript
async function retry(task, { attempts = 3, delay = 100 } = {}) {
  for (let i = 1; ; i++) {
    try {
      return await task();
    } catch (err) {
      if (i >= attempts) throw err;
      await sleep(delay * 2 ** (i - 1));     // 100, 200, 400 ms...
    }
  }
}

A concurrency limit

Promise.all(items.map(work)) starts everything at once. With 1000 items, that is 1000 requests at the same moment, which servers may refuse. A pool keeps at most limit running:

JavaScript
async function mapLimit(items, limit, work) {
  const results = new Array(items.length);
  let next = 0;
  async function worker() {
    while (next < items.length) {
      const i = next++;                       // safe: only one piece of code runs at a time
      results[i] = await work(items[i], i);
    }
  }
  await Promise.all(Array.from({ length: Math.min(limit, items.length) }, worker));
  return results;
}

let running = 0, peak = 0;
const job = async n => { running++; peak = Math.max(peak, running); await new Promise(r => setTimeout(r, 10)); running--; return n * 2; };
mapLimit([1, 2, 3, 4, 5, 6, 7], 3, job).then(r => console.log(r, "peak", peak));

Results stay in input order, because each is stored at its own index.
