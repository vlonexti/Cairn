Proxy, Reflect and Weak References

lesson 7.033 of 6 in milestone 75 min2 practice tasks

Intercepting what code does to an object - Proxy with get, set, has and deleteProperty traps, Reflect for doing the default, validation and change tracking with proxies, and WeakMap, WeakSet and WeakRef for data that must not keep objects alive.

A stand-in for an object

A Proxy wraps an object (the target) and lets a handler step in whenever code reads, writes, deletes or checks a property. Each kind of operation has a trap:

JavaScript
const target = { name: "Ada" };
const logged = new Proxy(target, {
  get(obj, key, receiver) {
    console.log(`read ${String(key)}`);
    return Reflect.get(obj, key, receiver);
  },
  set(obj, key, value, receiver) {
    console.log(`write ${String(key)} = ${value}`);
    return Reflect.set(obj, key, value, receiver);
  },
});

logged.age = 36;
console.log(logged.name, target.age);

Code using logged cannot tell it is not the real object. The set trap must return true when the write succeeded.

Reflect: do the normal thing

Reflect has one function per trap that performs the default behaviour: Reflect.get, Reflect.set, Reflect.has, Reflect.deleteProperty, Reflect.ownKeys. A trap that only wants to add something (logging, checking) does its extra work and then calls the matching Reflect function, as above.

Common traps

Trap Runs for
get(target, key, receiver) p.x, p[key]
set(target, key, value, receiver) p.x = v
has(target, key) key in p
deleteProperty(target, key) delete p.x
ownKeys(target) Object.keys(p), for...in
apply(target, thisArg, args) calling p(...) when the target is a function

Validation

JavaScript
function typed(shape) {
  return new Proxy({}, {
    set(obj, key, value) {
      if (!(key in shape)) throw new TypeError(`unknown field ${String(key)}`);
      if (typeof value !== shape[key]) throw new TypeError(`${String(key)} must be a ${shape[key]}`);
      obj[key] = value;
      return true;
    },
  });
}

const user = typed({ name: "string", age: "number" });
user.name = "Ada";
try { user.age = "old"; } catch (e) { console.log(e.message); }   // age must be a number

Default values

JavaScript
const counts = new Proxy({}, {
  get: (obj, key) => (key in obj ? obj[key] : 0),
});
for (const word of "the cat the hat".split(" ")) counts[word] += 1;
console.log(counts.the, counts.cat, counts.dog);   // 2 1 0

Vue's reactivity, MobX and many test mocks are built on exactly these traps. Proxies are slower than plain objects, so keep them for the places where interception is the point.

WeakMap and WeakSet

A normal Map keeps its keys alive: as long as the map exists, the objects in it are never garbage-collected. A WeakMap holds its keys weakly: when nothing else refers to a key object, the entry disappears. Keys must be objects, and a WeakMap cannot be iterated (its contents depend on when the garbage collector runs).

Use it to attach extra data to objects you do not own, without leaking memory:

JavaScript
const clickCount = new WeakMap();

function recordClick(element) {
  clickCount.set(element, (clickCount.get(element) ?? 0) + 1);
}

const button = { id: "save" };     // stands in for a DOM element
recordClick(button);
recordClick(button);
console.log(clickCount.get(button));   // 2
// when the button is removed and forgotten, its count goes with it

A WeakSet is the same idea for "have I seen this object?", for example to avoid visiting an object twice while walking a structure with cycles.

WeakRef

A WeakRef points at an object without keeping it alive; deref() returns the object, or undefined once it has been collected. It suits caches of large objects that may be rebuilt. When collection happens is up to the engine, so never write logic that depends on it.
