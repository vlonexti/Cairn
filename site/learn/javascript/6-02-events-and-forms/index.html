Events and Forms

lesson 6.022 of 5 in milestone 65 min1 practice task

Reacting to the user - addEventListener, the event object, bubbling and event delegation, preventDefault, keyboard events, forms with submit, FormData and built-in validation, custom validation messages, and keeping handlers small.

Listening

JavaScript
const button = document.querySelector("#save");
button.addEventListener("click", event => {
  console.log("clicked", event.target);
});

The event object describes what happened: event.target (the element the event started on), event.key for keyboard events, event.clientX for the mouse. Common events: click, input (each change of a field), change (a field is committed), submit, keydown, focus, blur, DOMContentLoaded.

removeEventListener(type, sameFunction) stops listening; pass { once: true } to listen for one event only.

Bubbling and delegation

An event first runs listeners on its target, then bubbles up through each parent to document. So one listener on a list can handle clicks on every item, including items added later. This is event delegation:

JavaScript
list.addEventListener("click", event => {
  const button = event.target.closest("button[data-action]");
  if (!button || !list.contains(button)) return;
  const index = Number(button.closest("li").dataset.index);
  if (button.dataset.action === "delete") state.items.splice(index, 1);
  if (button.dataset.action === "toggle") state.items[index].done = !state.items[index].done;
  render();
});

closest(selector) walks up from the clicked element to the nearest match, so a click on an icon inside the button still finds the button. event.stopPropagation() stops bubbling; it is rarely needed and easy to misuse.

Default actions

Some events have a built-in action: a link navigates, a form submits and reloads the page, a key types a letter. event.preventDefault() cancels it:

JavaScript
form.addEventListener("submit", event => {
  event.preventDefault();               // handle the form in JavaScript instead of reloading
  ...
});

input.addEventListener("keydown", event => {
  if (event.key === "Enter" && !event.shiftKey) { event.preventDefault(); send(); }
  if (event.key === "Escape") input.value = "";
});

Forms

HTML
<form id="signup" novalidate>
  <label>Name <input name="name" required minlength="2"></label>
  <label>Email <input name="email" type="email" required></label>
  <label>Age <input name="age" type="number" min="13"></label>
  <button>Sign up</button>
  <p class="error" aria-live="polite"></p>
</form>
JavaScript
const form = document.querySelector("#signup");
form.addEventListener("submit", event => {
  event.preventDefault();
  const values = Object.fromEntries(new FormData(form));    // { name: "...", email: "...", age: "..." }
  const errors = validateSignup(values);                     // a pure function: easy to test
  form.querySelector(".error").textContent = Object.values(errors).join(" ");
  if (Object.keys(errors).length === 0) submit(values);
});
  • FormData collects every named field. All values are strings ("36", not 36): convert them yourself.
  • HTML attributes such as required, type="email" and min give built-in checks; novalidate turns off the browser's own bubbles so you can show messages your way. input.checkValidity() and input.validity still report the built-in result.
  • Always validate again on the server: anything in the browser can be bypassed.

Put the rules in a pure function like validateSignup(values) that returns errors per field. The event handler then only reads values, calls it and shows the result.

Accessibility

Use real <button> and <a> elements rather than clickable <div>s: they work with the keyboard and screen readers for free. Connect labels to fields (wrap the input in its <label>), and announce errors with aria-live so screen-reader users hear them.
