Binary Data with Typed Arrays

lesson 8.011 of 5 in milestone 85 min2 practice tasks

Working with raw bytes in JavaScript - ArrayBuffer as a block of memory, typed arrays such as Uint8Array and Float32Array as views of it, DataView for reading numbers in a chosen byte order, TextEncoder and TextDecoder for UTF-8, and parsing a binary file format.

Why bytes?

Images, sound, network packets, game save files and WebAssembly all deal in raw bytes. Ordinary arrays hold any JavaScript value and are a poor fit: each element might be a number, a string or an object. JavaScript has separate types for binary data.

ArrayBuffer and typed arrays

An ArrayBuffer is a fixed block of bytes, all zero at first. You cannot read it directly; you look at it through a view:

JavaScript
const buffer = new ArrayBuffer(8);
const bytes = new Uint8Array(buffer);
bytes[0] = 255;
bytes[1] = 256;          // wraps to 0: a Uint8 holds 0 to 255
bytes[2] = -1;           // wraps to 255
console.log(bytes, buffer.byteLength);

Each typed array has a fixed element type:

type size range
Int8Array / Uint8Array 1 byte -128..127 / 0..255
Uint8ClampedArray 1 byte 0..255, clamping instead of wrapping (for pixels)
Int16Array / Uint16Array 2 bytes
Int32Array / Uint32Array 4 bytes
Float32Array / Float64Array 4 / 8 bytes floating point
BigInt64Array / BigUint64Array 8 bytes BigInt values

Typed arrays have most array methods (map, filter, reduce, slice, indexOf, fill), but a fixed length: there is no push.

JavaScript
const scores = Float32Array.from([1.5, 2.25, 3]);
console.log(scores.map(x => x * 2), scores.reduce((a, b) => a + b, 0));
const clamped = new Uint8ClampedArray([300, -20, 128.6]);
console.log(clamped);       // Uint8ClampedArray(3) [ 255, 0, 129 ]

Several views of the same bytes

Two views over one buffer share the memory:

JavaScript
const buffer = new ArrayBuffer(4);
const asInt = new Uint32Array(buffer);
const asBytes = new Uint8Array(buffer);
asInt[0] = 0x11223344;
console.log([...asBytes].map(b => b.toString(16)));   // [ '44', '33', '22', '11' ] on a little-endian machine

The order of those bytes depends on the computer. That is fine inside one program, but not for files or networks, which need a fixed order.

DataView: numbers in a chosen byte order

DataView reads and writes numbers of any size at any byte offset, with the byte order you choose (true means little-endian):

JavaScript
const view = new DataView(new ArrayBuffer(12));
view.setUint16(0, 7, true);
view.setUint32(2, 1_000_000, true);
view.setFloat32(6, 1.5, true);
view.setUint16(10, 0x1234, false);      // big-endian

const hex = [...new Uint8Array(view.buffer)].map(b => b.toString(16).padStart(2, "0")).join(" ");
console.log(hex);
console.log(view.getUint16(0, true), view.getUint32(2, true), view.getFloat32(6, true), view.getUint16(10, false).toString(16));

Reading past the end throws a RangeError, so a broken file cannot make you read random memory.

Text and bytes

TextEncoder turns a string into UTF-8 bytes, and TextDecoder turns bytes back into a string:

JavaScript
const bytes = new TextEncoder().encode("café");
console.log(bytes, bytes.length);
console.log(new TextDecoder().decode(bytes));
console.log(new TextDecoder("utf-8", { fatal: false }).decode(new Uint8Array([0xff, 0x41])));

"café".length is 4 but its UTF-8 form has 5 bytes, because é takes two.

Parsing a small format

A record format: a 4-byte magic "XNSV", a 2-byte count, then for each record a 1-byte name length, the name, and a 4-byte score, all little-endian.

JavaScript
function parse(buffer) {
  const view = new DataView(buffer);
  const magic = new TextDecoder().decode(new Uint8Array(buffer, 0, 4));
  if (magic !== "XNSV") throw new Error("not a save file");
  const count = view.getUint16(4, true);
  const records = [];
  let pos = 6;
  for (let i = 0; i < count; i++) {
    const len = view.getUint8(pos);
    const name = new TextDecoder().decode(new Uint8Array(buffer, pos + 1, len));
    const score = view.getUint32(pos + 1 + len, true);
    records.push({ name, score });
    pos += 1 + len + 4;
  }
  return records;
}

// build a file to test with
const enc = new TextEncoder();
const parts = [enc.encode("XNSV"), new Uint8Array([2, 0])];
for (const [name, score] of [["ada", 1500], ["bob", 80]]) {
  const n = enc.encode(name);
  const s = new Uint8Array(4);
  new DataView(s.buffer).setUint32(0, score, true);
  parts.push(new Uint8Array([n.length]), n, s);
}
const total = parts.reduce((a, p) => a + p.length, 0);
const file = new Uint8Array(total);
let at = 0;
for (const p of parts) { file.set(p, at); at += p.length; }
console.log(parse(file.buffer));

new Uint8Array(buffer, offset, length) is a view of part of the buffer without copying, and set copies one typed array into another at a position.

Where these appear

  • fetch(url).then(r => r.arrayBuffer()) and File.arrayBuffer() give an ArrayBuffer.
  • A canvas's getImageData().data is a Uint8ClampedArray of RGBA pixels.
  • In Node.js, Buffer is a subclass of Uint8Array with extra methods.
