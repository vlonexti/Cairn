Tooling

lesson 6.044 of 5 in milestone 65 min1 practice task

The tools around a JavaScript project - Node and npm, package.json and scripts, installing packages and semantic version ranges, the lock file, a dev server and bundler with Vite, TypeScript's tsconfig, ESLint and Prettier, testing with Vitest, and building for production.

Node and npm

Node.js runs JavaScript outside the browser: build tools, servers, scripts. It comes with npm, the package manager. A project is a folder with a package.json:

Terminal
npm init -y                      # create package.json
npm install date-fns             # a dependency your code imports
npm install -D vitest typescript # a devDependency: only needed while developing
npm run test                     # run a script from package.json
npx tsc --version                # run a tool installed in the project
JSON
{
  "name": "shopping-list",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "test": "vitest run",
    "lint": "eslint ."
  },
  "dependencies": { "date-fns": "^4.1.0" },
  "devDependencies": { "typescript": "~5.6.0", "vite": "^6.0.0", "vitest": "^2.1.0" }
}

"type": "module" makes .js files ES modules (lesson 3.05).

Versions

Packages use semantic versioning: MAJOR.MINOR.PATCH. A patch fixes bugs, a minor version adds features, a major version may break existing code.

Range Allows
4.1.0 exactly 4.1.0
^4.1.0 4.1.0 up to, not including, 5.0.0 (the npm default)
~4.1.0 4.1.0 up to, not including, 4.2.0
>=4.1.0 anything from 4.1.0

Below 1.0.0, a caret is stricter: ^0.3.2 allows up to, not including, 0.4.0, because every 0.x minor may break things.

npm install writes package-lock.json with the exact version of every package. Commit it, so everyone (and the build server) installs the same versions; use npm ci to install exactly what it says. Never commit node_modules; add it to .gitignore.

Vite

A bundler with a dev server makes browser development fast: it serves your files, reloads the page as you save, handles TypeScript and npm imports, and produces optimised files for production.

Terminal
npm create vite@latest my-app -- --template vanilla-ts
cd my-app
npm install
npm run dev       # http://localhost:5173, reloads on save
npm run build     # optimised files in dist/, ready for any static host

TypeScript configuration

tsconfig.json controls the compiler. A good starting point:

JSON
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noEmit": true,
    "lib": ["ES2022", "DOM"]
  },
  "include": ["src"]
}

With Vite, the bundler removes the types and tsc --noEmit (in the build script) only checks them.

Linting, formatting and tests

  • ESLint finds likely bugs: unused variables, missing await, comparisons that are always false. npx eslint .
  • Prettier formats code the same way for everyone, ending arguments about style. Run it on save in your editor.
  • Vitest (or Jest) runs tests written like this course's: test("adds", () => { expect(add(2, 3)).toBe(5); }). Pure functions, which this course has encouraged throughout, are the easiest to test.

Security of dependencies

Every package can run code on your machine when installed and in your users' browsers when bundled. Prefer few, well-known packages; read what a small package does before adding it; run npm audit for known vulnerabilities; and update regularly.
