The DOM

lesson 6.011 of 5 in milestone 65 min1 practice task

How a web page is a tree of objects - loading scripts, finding elements with querySelector, reading and changing text, attributes, classes and styles, creating and removing elements, why textContent is safe and innerHTML is not, and rendering a list from data.

The page as objects

When a browser loads HTML, it builds the DOM (Document Object Model): a tree of objects, one per element, that JavaScript can read and change. Changing the DOM changes the page immediately.

HTML
<!doctype html>
<html>
  <body>
    <h1 id="title">Shopping</h1>
    <ul class="items"></ul>
    <script type="module" src="main.js"></script>
  </body>
</html>

type="module" makes main.js an ES module (lesson 3.05). Module scripts run after the HTML has been parsed, so every element above already exists.

The DOM code in this milestone runs in a browser, not in the practice sandbox, which has no page. The practice tasks therefore test the logic behind the page (building HTML, validating forms, managing state), which is where most bugs live.

Finding elements

JavaScript
const title = document.querySelector("#title");          // the first match of a CSS selector, or null
const list = document.querySelector(".items");
const buttons = document.querySelectorAll("button.delete");   // all matches (a static NodeList)
const field = document.getElementById("email");

for (const b of buttons) b.disabled = true;

querySelector takes any CSS selector: "#id", ".class", "form input[name=email]", "li:first-child". It returns null when nothing matches, so a misspelled selector shows up as Cannot read properties of null.

Changing elements

JavaScript
title.textContent = "Groceries";                 // replace the text
title.classList.add("highlight");                 // classes: add, remove, toggle, contains
title.classList.toggle("done", isDone);
title.style.color = "tomato";                     // inline style (prefer classes)
title.setAttribute("aria-live", "polite");
title.dataset.count = "3";                        // data-count="3"
const link = document.querySelector("a");
link.href = "/help";

Prefer toggling classes and keeping the looks in CSS: el.classList.toggle("hidden", !visible) is easier to maintain than setting styles from JavaScript.

Creating and removing

JavaScript
const item = document.createElement("li");
item.textContent = "Milk";
item.className = "item";
list.append(item);                // also: prepend, before, after
item.remove();
list.replaceChildren();           // remove all children

textContent versus innerHTML

innerHTML parses a string as HTML. That is convenient, and dangerous with any text that comes from users:

JavaScript
const name = '<img src=x onerror="alert(document.cookie)">';
greeting.innerHTML = `Hello ${name}`;    // runs the attacker's code: cross-site scripting (XSS)
greeting.textContent = `Hello ${name}`;  // shows the text exactly as typed: safe

Use textContent and createElement for user data. If you do build HTML strings, escape the text first:

JavaScript
function escapeHtml(text) {
  return String(text)
    .replaceAll("&", "&amp;")
    .replaceAll("<", "&lt;")
    .replaceAll(">", "&gt;")
    .replaceAll('"', "&quot;")
    .replaceAll("'", "&#39;");
}
console.log(escapeHtml('<img src=x onerror="alert(1)">'));

& must be replaced first, or the & of each replacement would be escaped again.

Rendering from data

Keep the data in JavaScript and draw the page from it, instead of reading values back out of the page:

JavaScript
const state = { items: [{ name: "Milk", done: false }, { name: "Eggs", done: true }] };

function render() {
  list.replaceChildren(...state.items.map((item, i) => {
    const li = document.createElement("li");
    li.textContent = item.name;
    li.classList.toggle("done", item.done);
    li.dataset.index = String(i);
    return li;
  }));
}
render();

After any change to state, call render() again. This state, then render loop is the idea behind React, Vue and Svelte; those libraries make the re-rendering efficient.
