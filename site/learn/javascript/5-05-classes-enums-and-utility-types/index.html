Classes, Enums and Utility Types

lesson 5.055 of 5 in milestone 55 min1 practice task

Typed classes with access modifiers, parameter properties, implements and abstract classes, enums and why unions of literals are often better, as const, and the built-in utility types Partial, Required, Pick, Omit, Readonly, Record, ReturnType and Awaited.

Typed classes

TypeScript
interface Account {
  readonly id: string;
  balance(): number;
  deposit(amount: number): void;
}

class SavingsAccount implements Account {
  #cents = 0;
  constructor(public readonly id: string, private rate: number) {}   // parameter properties

  balance(): number { return this.#cents / 100; }
  deposit(amount: number): void {
    if (amount <= 0) throw new RangeError("amount must be positive");
    this.#cents += Math.round(amount * 100);
  }
  addInterest(): void { this.#cents += Math.round(this.#cents * this.rate); }
}

const acc = new SavingsAccount("S-1", 0.02);
acc.deposit(100);
acc.addInterest();
console.log(acc.id, acc.balance());
  • public readonly id: string in the constructor's parameters declares and assigns the property: a parameter property.
  • private and protected are checked only by the compiler; #private fields are private at run time too. Prefer # for real privacy.
  • implements Account makes the compiler check that the class has everything the interface promises.

Abstract classes

An abstract class cannot be created with new; it provides shared code and declares methods that subclasses must write:

TypeScript
abstract class Report {
  abstract rows(): string[][];
  render(): string { return this.rows().map(r => r.join(" | ")).join("\n"); }
}

class SalesReport extends Report {
  rows() { return [["tea", "12"], ["cake", "7"]]; }
}
console.log(new SalesReport().render());

Enums, or unions of literals

An enum names a set of constants and, unlike most TypeScript, produces real JavaScript:

TypeScript
enum Level { Debug, Info, Warn, Error }
console.log(Level.Warn, Level[Level.Warn]);     // 2 "Warn"

enum Color { Red = "red", Green = "green" }
console.log(Color.Red);

Many codebases prefer a union of string literals, which is plain JavaScript values, needs no import, and reads clearly in JSON and logs:

TypeScript
const LEVELS = ["debug", "info", "warn", "error"] as const;
type LevelName = typeof LEVELS[number];          // "debug" | "info" | "warn" | "error"

function atLeast(level: LevelName, min: LevelName): boolean {
  return LEVELS.indexOf(level) >= LEVELS.indexOf(min);
}
console.log(atLeast("error", "warn"), atLeast("debug", "info"));

as const makes the array readonly with literal element types, so the list of values and the type come from one place.

Utility types

TypeScript includes generic types that transform other types:

Utility Result
Partial<T> All properties optional: for updates
Required<T> All properties required
Readonly<T> All properties readonly
Pick<T, "a" | "b"> Only those properties
Omit<T, "a"> All but those properties
Record<K, V> An object with keys K and values V
ReturnType<typeof f> What function f returns
Awaited<P> What a promise resolves to
NonNullable<T> T without null and undefined
TypeScript
interface Todo { id: number; title: string; done: boolean; notes?: string }

type NewTodo = Omit<Todo, "id">;                  // what a client sends
type TodoUpdate = Partial<Omit<Todo, "id">>;      // any subset of fields
type TodoSummary = Pick<Todo, "id" | "title">;

function update(todo: Todo, changes: TodoUpdate): Todo {
  return { ...todo, ...changes };
}

const t: Todo = { id: 1, title: "Learn TS", done: false };
const summary: TodoSummary = { id: t.id, title: t.title };
console.log(update(t, { done: true }), summary);

Deriving types from one source (Todo) means a change to it flows everywhere automatically.
