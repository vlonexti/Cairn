Promises

lesson 4.022 of 5 in milestone 45 min1 practice task

A promise as a value that arrives later - its three states, creating one with new Promise, chaining then and catch, returning promises from then, finally, wrapping callback APIs, and combining promises with Promise.all, allSettled, race and any.

A value that arrives later

A promise stands for the result of an operation that has not finished. It is in one of three states:

  • pending: still working;
  • fulfilled: finished with a value;
  • rejected: failed with an error (a reason).

Once fulfilled or rejected, it is settled and never changes again.

JavaScript
const wait = ms => new Promise(resolve => setTimeout(resolve, ms));

function delayedSquare(n) {
  return new Promise((resolve, reject) => {
    if (typeof n !== "number") { reject(new TypeError("not a number")); return; }
    setTimeout(() => resolve(n * n), 10);
  });
}

delayedSquare(4).then(v => console.log("value", v));
delayedSquare("x").catch(err => console.log("error", err.message));
wait(20).then(() => console.log("20 ms later"));

The function given to new Promise (the executor) runs immediately and calls resolve(value) or reject(error) when done.

Chaining

then(f) returns a new promise for whatever f returns. If f returns a promise, the chain waits for it. That makes sequences flat:

JavaScript
const step = (label, ms) => new Promise(r => setTimeout(() => { console.log(label); r(label.length); }, ms));

step("load user", 10)
  .then(n => step("load orders", 10).then(() => n))
  .then(n => { console.log("first label had", n, "letters"); return n * 2; })
  .then(doubled => console.log("doubled", doubled))
  .catch(err => console.log("something failed:", err.message))
  .finally(() => console.log("done either way"));

A catch at the end handles a rejection from any step above it, like a try around the whole chain. A throw inside a then callback rejects the chain too. finally runs whatever happened, without changing the result.

Always end a chain with catch (or await it inside try): an unhandled rejection prints a warning in the browser and stops a Node program.

Wrapping callback APIs

JavaScript
function loadUser(id, cb) { setTimeout(() => (id > 0 ? cb(null, { id }) : cb(new Error("bad id"))), 5); }

const loadUserAsync = id => new Promise((resolve, reject) => {
  loadUser(id, (err, user) => (err ? reject(err) : resolve(user)));
});

loadUserAsync(3).then(u => console.log("user", u.id));

Node's util.promisify does this for any error-first function.

Many promises at once

Combinator Fulfils when Rejects when
Promise.all(list) all fulfil: with an array of values in list order any rejects (the first error)
Promise.allSettled(list) all settle: with { status, value } or { status, reason } for each never
Promise.race(list) the first one settles, with its value the first one to settle rejects
Promise.any(list) the first one fulfils all reject (AggregateError)
JavaScript
const after = (ms, v, fail = false) => new Promise((res, rej) => setTimeout(() => (fail ? rej(new Error(v)) : res(v)), ms));

Promise.all([after(30, "a"), after(10, "b")]).then(v => console.log("all", v));
Promise.allSettled([after(5, "ok"), after(5, "bad", true)]).then(r => console.log(r.map(x => x.status)));
Promise.race([after(20, "slow"), after(5, "fast")]).then(v => console.log("race", v));

Promise.all runs the operations at the same time: three 100 ms requests take about 100 ms, not 300.

Promise.resolve(v) and Promise.reject(e) make already-settled promises, useful in tests and for returning a promise from a function that sometimes has the answer ready.
