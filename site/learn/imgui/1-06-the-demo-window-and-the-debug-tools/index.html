The Demo Window and the Debug Tools

lesson 1.066 of 6 in milestone 15 min1 practice task

Dear ImGui ships its best documentation as a program - ShowDemoWindow shows every widget with the code beside it. It also ships tools for finding your own bugs - the Metrics window, the ID Stack tool, the Item Picker and debug logs. This lesson shows how to use them all.

ShowDemoWindow

C++
ImGui::ShowDemoWindow();

One call opens a window that demonstrates almost every feature of ImGui: widgets, layout, tables, popups, drag and drop, styling, fonts. It is the real documentation: when you want to know how to do something, find it in the demo window, then open imgui_demo.cpp and search for the label you saw. The code you need is right there.

The demo's "Tools" menu (top of the window) opens the other tools below.

Keep imgui_demo.cpp in every project during development; it costs nothing until called. Leave the call out of shipping builds (lesson 6.03).

The style editor

C++
ImGui::ShowStyleEditor();

Every size, rounding and colour of the current style, editable live. Tune a style here, then click "Export" to copy the C++ code that sets it (lesson 4.05).

The Metrics/Debugger window

C++
ImGui::ShowMetricsWindow();

It shows ImGui's own state: every window with its position, size and draw list (how many vertices, how many draw commands), the active and hovered widget IDs, the ID stack, the font atlas, tables' internal state, and more. Hover a draw command and it highlights what it draws. Use it when:

  • the interface is slow (which window has thousands of vertices?);
  • something is drawn but you cannot see why (where is its clip rectangle?);
  • a window behaves oddly (what are its flags and size constraints?).

The ID Stack tool

C++
ImGui::ShowIDStackToolWindow();

Hover any widget: it shows the ID stack for it, level by level - the window's seed, every PushID, the label - and the final ID. The fastest way to understand why two widgets clash (lesson 1.05).

The Item Picker

In the Metrics window, Tools, Item Picker: click any widget in your program, and ImGui stops in the debugger inside the code that drew it. When you have a complex tool and cannot find which of fifty functions draws a misbehaving checkbox, this finds it in one click.

Debug log

The Metrics window has a Debug Log section that records what ImGui does in categories you choose: focus changes, popups, navigation, I/O events, docking. Turn on "I/O" and you see every mouse and keyboard event the back end feeds in, which answers "is ImGui even receiving my input?".

Assertions are your friends

ImGui uses IM_ASSERT heavily: unmatched Begin/End, PushID/PopID, calls outside a frame, bad parameters. In a Debug build the debugger stops on the exact line, with a comment in the source explaining the rule you broke. Read the comment above the assert; it nearly always says what to do. You can route assertions to your own handler by defining IM_ASSERT in imconfig.h.

Common mistakes

Guessing instead of looking

When a widget misbehaves, the ID Stack tool, the Metrics window and the Item Picker usually find the cause in seconds.

Disabling assertions to make a crash go away

The assert is reporting a real mistake that will cause worse problems later. Fix the pairing or the call order instead.
