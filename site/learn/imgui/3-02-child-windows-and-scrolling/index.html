Child Windows and Scrolling

lesson 3.022 of 5 in milestone 35 min1 practice task

A child window is a scrolling region inside a window - a list that scrolls while the buttons below it stay put, or a two-pane layout. This lesson covers BeginChild, sizing children to fill space, scrolling from code, auto-scrolling logs, and clipping so a list of a hundred thousand items costs nothing.

BeginChild

C++
ImGui::BeginChild("stones", ImVec2(0, 200), ImGuiChildFlags_Borders);   // full width, 200 high, with a border
for (const Stone& s : stones) ImGui::Text("%s", s.name.c_str());
ImGui::EndChild();                                                       // ALWAYS, like End
if (ImGui::Button("Add")) addStone();                                    // stays below, not scrolled

BeginChild/EndChild follow the window rule: EndChild is always called, whatever BeginChild returned.

Sizes: 0 means "fill what is available", a positive number is a fixed size, a negative number means "fill, minus this much". So "a list that fills the window except for one row of buttons below it" is:

C++
const float footer = ImGui::GetFrameHeightWithSpacing();      // the height of one row of buttons
ImGui::BeginChild("list", ImVec2(0, -footer), ImGuiChildFlags_Borders);
// ...
ImGui::EndChild();
ImGui::Button("Add");

Two panes side by side

C++
ImGui::BeginChild("left", ImVec2(200, 0), ImGuiChildFlags_Borders | ImGuiChildFlags_ResizeX);  // resizable
drawLevelList();
ImGui::EndChild();
ImGui::SameLine();
ImGui::BeginChild("right");                      // takes the rest
drawLevelDetails();
ImGui::EndChild();

ImGuiChildFlags_ResizeX adds a handle on the child's right edge the user can drag. (Before version 1.90 the second argument of BeginChild was a bool border; the flags replaced it.)

Scrolling from code

C++
ImGui::SetScrollHereY(0.5f);           // scroll so the current cursor position is in the middle
ImGui::SetScrollY(0.0f);               // to the top
float y = ImGui::GetScrollY(), maxY = ImGui::GetScrollMaxY();

A log window wants to follow new lines, but only if the user has not scrolled up to read something:

C++
const bool atBottom = ImGui::GetScrollY() >= ImGui::GetScrollMaxY();   // measure BEFORE adding lines
for (const auto& line : log) ImGui::TextUnformatted(line.c_str());
if (atBottom) ImGui::SetScrollHereY(1.0f);                              // keep following

Clipping long lists

Drawing 100,000 lines every frame is slow even if only 30 are visible. ImGuiListClipper works out which items are on screen, so you only draw those, while the scroll bar still behaves as if all of them were there:

C++
ImGuiListClipper clipper;
clipper.Begin((int)lines.size());                  // all items have the same height
while (clipper.Step())
    for (int i = clipper.DisplayStart; i < clipper.DisplayEnd; ++i)
        ImGui::TextUnformatted(lines[i].c_str());

The idea is simple arithmetic: with each item h pixels high, the scroll position y and the visible height H, the first visible item is floor(y / h) and the last is ceil((y + H) / h). The clipper reserves empty space for the items above and below so the scroll bar is right. The practice writes this calculation.

Clipping needs every item to have the same height. For variable heights, keep a prefix sum of heights and binary-search it, or group items into rows of equal height.

Common mistakes

Calling EndChild only when BeginChild returned true

Like End, EndChild is always called.

Auto-scroll that fights the user

Check whether you were at the bottom before adding lines, and only follow then.

Drawing every line of a huge log

Use ImGuiListClipper; the cost then depends on the window height, not the log length.
