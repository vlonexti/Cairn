Tables

lesson 3.033 of 5 in milestone 35 min1 practice task

Tables are ImGui's most capable layout tool - columns that resize, reorder, hide and sort, frozen header rows, scrolling with clipping, and alternate row backgrounds. This lesson builds an entity table step by step and explains sorting specs, the part most people find confusing.

A basic table

C++
if (ImGui::BeginTable("entities", 3, ImGuiTableFlags_Borders | ImGuiTableFlags_RowBg))
{
    ImGui::TableSetupColumn("Name");
    ImGui::TableSetupColumn("HP", ImGuiTableColumnFlags_WidthFixed, 60.0f);
    ImGui::TableSetupColumn("Position");
    ImGui::TableHeadersRow();

    for (const Entity& e : entities)
    {
        ImGui::TableNextRow();
        ImGui::TableNextColumn(); ImGui::TextUnformatted(e.name.c_str());
        ImGui::TableNextColumn(); ImGui::Text("%d", e.hp);
        ImGui::TableNextColumn(); ImGui::Text("%.1f, %.1f", e.x, e.y);
    }
    ImGui::EndTable();                    // only if BeginTable returned true
}

BeginTable returns false when the table is clipped (scrolled out of view); then you skip it and do not call EndTable (lesson 1.04's second rule). Inside, any widget can go in any cell.

Useful flags

Flag Effect
Resizable Drag column borders to resize
Reorderable Drag headers to reorder columns
Hideable Right-click the header to hide columns
Sortable Click headers to sort (see below)
ScrollY (with an outer size) The table scrolls; combine with TableSetupScrollFreeze(0, 1) to keep the header row visible
RowBg Alternate row colours
SizingFixedFit, SizingStretchProp... How column widths are chosen

The table remembers widths, order, visibility and sort per table ID, and saves them in imgui.ini (lesson 4.06).

Scrolling a large table

C++
const ImVec2 outer(0, ImGui::GetTextLineHeightWithSpacing() * 15);   // 15 rows high
if (ImGui::BeginTable("big", 3, ImGuiTableFlags_ScrollY | ImGuiTableFlags_RowBg, outer))
{
    ImGui::TableSetupScrollFreeze(0, 1);        // keep the first row (headers) visible
    /* TableSetupColumn x3, TableHeadersRow */
    ImGuiListClipper clipper;
    clipper.Begin((int)rows.size());
    while (clipper.Step())
        for (int i = clipper.DisplayStart; i < clipper.DisplayEnd; ++i) { /* TableNextRow, cells for rows[i] */ }
    ImGui::EndTable();
}

Sorting

With ImGuiTableFlags_Sortable, clicking a header changes the table's sort specs. ImGui does not sort your data: it tells you what the user asked for, and you sort.

C++
if (ImGuiTableSortSpecs* specs = ImGui::TableGetSortSpecs())
{
    if (specs->SpecsDirty)                       // the user changed the sort (or first frame)
    {
        std::sort(entities.begin(), entities.end(), [&](const Entity& a, const Entity& b) {
            for (int n = 0; n < specs->SpecsCount; ++n)
            {
                const ImGuiTableColumnSortSpecs& s = specs->Specs[n];   // ColumnIndex, SortDirection
                int cmp = compareColumn(a, b, s.ColumnIndex);           // -1, 0 or 1
                if (cmp != 0) return s.SortDirection == ImGuiSortDirection_Ascending ? cmp < 0 : cmp > 0;
            }
            return false;
        });
        specs->SpecsDirty = false;
    }
}

Call this after TableSetupColumn/TableHeadersRow and before the rows. Key points:

  • Sort only when SpecsDirty, not every frame.
  • With ImGuiTableFlags_SortMulti, Shift-clicking adds secondary sort columns: Specs[0] is the primary key, Specs[1] breaks its ties, and so on. The loop above handles any number.
  • Give each column a stable meaning with TableSetupColumn("Name", flags, width, userId) and compare by ColumnUserID if the columns can be reordered or hidden.

The practice writes this multi-key comparison.

Common mistakes

Sorting every frame

Sort when SpecsDirty is set, then clear it.

Expecting ImGui to sort the data

It only reports what the user clicked. Your data, your sort.
