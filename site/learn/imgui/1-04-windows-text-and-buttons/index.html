Windows, Text and Buttons

lesson 1.044 of 6 in milestone 15 min1 practice task

The first real interface - windows with Begin and End, every way of showing text, and buttons. Along the way you learn ImGui's rules for Begin/End pairs, what the boolean returned by Begin means, and how to open and close a window from code.

A window

C++
ImGui::Begin("Stones");          // a window titled "Stones"; created the first time, remembered afterwards
ImGui::Text("Hello from Xenon");
ImGui::End();                    // ALWAYS called, whatever Begin returned

The first time, ImGui creates the window with a default size and position; you can move and resize it, and it remembers (lesson 4.06 saves that to disk). Two Begin("Stones") calls in the same frame append to the same window, which is handy: different systems can add to one "Debug" window.

Begin returns false when the window is collapsed (folded by its title-bar arrow) or entirely clipped. You may skip its contents then, to save time, but End must still be called:

C++
if (ImGui::Begin("Stones"))
{
    expensiveStoneList();        // skipped while the window is collapsed
}
ImGui::End();

Begin/End is a different rule from most pairs in ImGui. For nearly everything else that starts with Begin (BeginMenu, BeginTable, BeginPopup, BeginCombo...), you call the matching End only if Begin returned true. Lesson 4.01 comes back to this; it is the most common beginner bug.

A closable window

Pass a pointer to a bool and the window gets a close button that sets it to false:

C++
static bool showStones = true;
if (showStones)
{
    if (ImGui::Begin("Stones", &showStones))
        ImGui::Text("Close me with the x");
    ImGui::End();
}

From code, set showStones = true again (from a menu item, a key) to reopen it.

Size and position

C++
ImGui::SetNextWindowPos(ImVec2(20, 20), ImGuiCond_FirstUseEver);
ImGui::SetNextWindowSize(ImVec2(320, 240), ImGuiCond_FirstUseEver);
ImGui::Begin("Stones");

SetNextWindow... applies to the next Begin. The condition says when: ImGuiCond_FirstUseEver only if the window has never been seen (not even in imgui.ini), ImGuiCond_Once once per run, ImGuiCond_Always every frame (the user can then no longer move it). Use FirstUseEver for defaults.

Window flags change behaviour: ImGuiWindowFlags_NoResize, NoMove, NoCollapse, AlwaysAutoResize (fits its content), NoTitleBar, MenuBar (lesson 4.01), and more, combined with |.

Text

Function Shows
ImGui::Text("Score %d", score) printf-style formatted text
ImGui::TextUnformatted(text) Text as is, fastest, no % processing; takes a begin and optional end pointer
ImGui::TextColored(ImVec4(1, 0.6f, 0.2f, 1), "Warning") Coloured text
ImGui::TextDisabled("(none)") Greyed-out text
ImGui::TextWrapped("long text...") Wraps at the window's edge
ImGui::BulletText("item") A bullet point
ImGui::LabelText("Label", "%d", value) Value with a label on the right, aligned like other widgets
ImGui::SeparatorText("Section") A separator line with a title

Text uses printf formatting: never pass user-provided text as the format string (Text(name)), because a % in it reads garbage. Use TextUnformatted(name) or Text("%s", name).

Buttons

C++
if (ImGui::Button("Add stone"))               // true on the frame it was clicked (mouse released over it)
    stones.push_back(Stone{});

if (ImGui::Button("Clear", ImVec2(120, 0)))   // width 120, default height
    stones.clear();

ImGui::SmallButton("x");                       // no frame padding, for inline buttons
ImGui::ArrowButton("##left", ImGuiDir_Left);   // an arrow, no visible label

A button counts as clicked when the mouse is pressed and released over it. Pressing, dragging away and releasing elsewhere does not click it. Lesson 1.05's practice and the next lessons look at how that works.

Common mistakes

Calling End only when Begin returned true

For windows, End is always called. For most other Begin functions, it is only called if Begin returned true. Learn the two rules.

Text(userString)

A % in the string crashes or prints garbage. Use TextUnformatted.
