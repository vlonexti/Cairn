Trees and Selection

lesson 3.044 of 5 in milestone 35 min2 practice tasks

A scene hierarchy, a file browser and an asset list all need a tree and a selection that behaves like every other program - click to select, Ctrl+click to add, Shift+click for a range. This lesson covers TreeNode and its flags, building a tree from your data, and implementing multi-selection properly.

Tree nodes

C++
if (ImGui::TreeNode("Level"))            // true while open
{
    ImGui::Text("child item");
    if (ImGui::TreeNode("Props")) { ImGui::Text("rock"); ImGui::TreePop(); }
    ImGui::TreePop();                    // only if TreeNode returned true
}

ImGui remembers whether each node is open by its ID (lesson 1.05), so two nodes with the same label in the same place open and close together. In a loop, use PushID or the TreeNode(ptr_id, fmt, ...) overload, which takes a pointer as the ID and a separate display text.

TreeNodeEx and its flags

C++
ImGuiTreeNodeFlags flags = ImGuiTreeNodeFlags_OpenOnArrow       // click the arrow to open, the label to select
                         | ImGuiTreeNodeFlags_OpenOnDoubleClick
                         | ImGuiTreeNodeFlags_SpanAvailWidth;   // the whole row is clickable
if (node.children.empty()) flags |= ImGuiTreeNodeFlags_Leaf | ImGuiTreeNodeFlags_NoTreePushOnOpen;
if (isSelected(node.id))  flags |= ImGuiTreeNodeFlags_Selected;

const bool open = ImGui::TreeNodeEx((void*)(intptr_t)node.id, flags, "%s", node.name.c_str());
if (ImGui::IsItemClicked() && !ImGui::IsItemToggledOpen())   // clicked the label, not the arrow
    select(node.id);
  • Leaf draws no arrow; with NoTreePushOnOpen you also skip TreePop for it.
  • DefaultOpen opens a node the first time it is seen.
  • ImGui::SetNextItemOpen(true) opens the next node from code: "reveal the selected object in the tree".

Building a tree from your data

Scene data is usually a flat list where each object knows its parent. Draw it recursively:

C++
void drawNode(const Scene& scene, int id)
{
    const Object& o = scene.objects[id];
    ImGuiTreeNodeFlags flags = ImGuiTreeNodeFlags_OpenOnArrow | ImGuiTreeNodeFlags_SpanAvailWidth;
    if (o.children.empty()) flags |= ImGuiTreeNodeFlags_Leaf | ImGuiTreeNodeFlags_NoTreePushOnOpen;
    const bool open = ImGui::TreeNodeEx((void*)(intptr_t)id, flags, "%s", o.name.c_str());
    if (open && !o.children.empty())
    {
        for (int child : o.children) drawNode(scene, child);
        ImGui::TreePop();
    }
}

The practice builds the "children of each node" lists from parent links and produces the order rows appear in, which is also what Shift+click ranges need.

Selection that behaves

Users expect:

Action Result
Click Select only this item; it becomes the anchor
Ctrl+click Toggle this item, keep the others; it becomes the anchor
Shift+click Select every item between the anchor and this one, in display order, replacing the selection
Ctrl+Shift+click Add that range to the existing selection

The anchor is the last item clicked without Shift. Ranges are measured in display order: the order rows appear on screen, which for a tree is depth-first over the open nodes. Store the selection as a set of stable IDs, never as row positions, so it survives sorting and filtering.

Dear ImGui 1.91 added a full multi-select API (BeginMultiSelect/EndMultiSelect) that handles these rules, box-selection and keyboard navigation for you; writing the rules yourself once, as the practice does, makes it much easier to use well.

Common mistakes

Selecting when the arrow was clicked

Check IsItemToggledOpen so opening a node does not also select it.

Storing the selection as row numbers

Rows change when the list is sorted, filtered or a node opens. Store IDs.
