Sliders, Drags and Checkboxes

lesson 2.011 of 5 in milestone 25 min1 practice task

Most tool interfaces are numbers and switches. This lesson covers checkboxes, radio buttons, sliders and drags for floats, integers and vectors, how a slider maps the mouse to a value, logarithmic sliders, format strings, and how to know when a value changed or finished changing.

Checkboxes and radio buttons

C++
ImGui::Checkbox("God mode", &settings.godMode);              // bool*

static int difficulty = 1;
ImGui::RadioButton("Easy", &difficulty, 0);  ImGui::SameLine();
ImGui::RadioButton("Normal", &difficulty, 1); ImGui::SameLine();
ImGui::RadioButton("Hard", &difficulty, 2);                  // sets difficulty to 2 when chosen

ImGui::CheckboxFlags("Collides", &body.flags, FLAG_COLLIDES); // one bit of an integer

All of them return true on the frame the value changed.

Sliders

C++
ImGui::SliderFloat("Speed", &player.speed, 0.0f, 20.0f);                  // drag the grab across the width
ImGui::SliderFloat("Gravity", &world.gravity, 0.0f, 30.0f, "%.2f m/s^2"); // a format for the shown value
ImGui::SliderInt("Lives", &player.lives, 0, 9);
ImGui::SliderFloat3("Position", &player.pos.x, -100.0f, 100.0f);          // three sliders for x, y, z
ImGui::SliderAngle("Heading", &player.headingRadians);                    // stored in radians, shown in degrees

A slider maps the mouse's position across its width to a value between min and max. With the grab's width taken out of the track, the mapping is simply linear:

Output
t     = (mouseX - trackStart) / trackWidth          clamped to 0..1
value = min + t * (max - min)

and back again to place the grab: t = (value - min) / (max - min). For integer sliders the value is rounded to the nearest whole number. The practice writes both directions.

Ctrl+click (or double-click) on a slider turns it into a text field so you can type an exact value. By default a typed value can go outside the range; pass ImGuiSliderFlags_AlwaysClamp to prevent that.

Logarithmic sliders

For values that span orders of magnitude (a light's intensity from 0.01 to 1000), a linear slider puts nearly all its width on the large numbers. ImGuiSliderFlags_Logarithmic maps the position to the logarithm of the value instead, so 0.01 to 0.1 gets as much room as 100 to 1000:

C++
ImGui::SliderFloat("Intensity", &light.intensity, 0.01f, 1000.0f, "%.3f", ImGuiSliderFlags_Logarithmic);

Drags

A drag changes the value by dragging horizontally, with no fixed track, so it suits values without natural limits:

C++
ImGui::DragFloat("Mass", &body.mass, 0.1f);                    // 0.1 per pixel dragged
ImGui::DragFloat("Radius", &body.radius, 0.05f, 0.0f, 50.0f);  // with optional limits
ImGui::DragInt("Count", &spawner.count, 1.0f, 0, 1000);
ImGui::DragFloat3("Scale", &obj.scale.x, 0.01f);
ImGui::DragFloatRange2("Spawn delay", &spawner.minDelay, &spawner.maxDelay, 0.05f, 0.0f, 10.0f);

Holding Shift while dragging moves faster, Alt slower. Drags are the most common number widget in professional tools because they take little space and work for any range.

Knowing when a value changed

Every widget returns true when it changed the value this frame. Tools often need more:

C++
if (ImGui::DragFloat("Height", &terrain.height, 0.1f))
    terrain.rebuildPreview();                 // every frame during the drag

if (ImGui::IsItemDeactivatedAfterEdit())      // the drag ended and the value had changed
    undo.record("Change height");             // record ONE undo step for the whole drag (lesson 5.04)

if (ImGui::IsItemActive()) { /* being dragged right now */ }

The IsItem... functions ask about the widget just drawn: IsItemHovered, IsItemActive, IsItemActivated (started this frame), IsItemEdited, IsItemDeactivatedAfterEdit.

Format strings

The format argument is printf-style and controls only what is shown: "%.0f" rounds the display, "%d px" adds a unit, "%.1f%%" shows a percent sign (%%). The stored value keeps its full precision.

Common mistakes

A slider with min greater than or equal to max

It cannot map anything. ImGui asserts in debug builds.

Recording an undo step on every frame of a drag

One drag would create sixty undo steps a second. Use IsItemDeactivatedAfterEdit.
