Docking and Multiple Viewports

lesson 4.044 of 6 in milestone 45 min1 practice task

With the docking branch, windows snap into each other as tabs and splits - the layout of every modern editor - and with multiple viewports they can leave the main window and become real operating-system windows. This lesson turns both on, builds a dockspace over the whole screen, creates a default layout from code, and explains how dock nodes split space.

Turning it on

Docking lives on Dear ImGui's docking branch (lesson 1.02). Enable it once after creating the context:

C++
ImGuiIO& io = ImGui::GetIO();
io.ConfigFlags |= ImGuiConfigFlags_DockingEnable;
io.ConfigFlags |= ImGuiConfigFlags_ViewportsEnable;      // optional: windows may leave the main window

Now drag any window by its title bar onto another: a docking overlay appears with targets for "as a tab", "split left", "split right", "split top", "split bottom". Hold Shift while dragging to dock only when you want to (set io.ConfigDockingWithShift = true).

A dockspace over the whole screen

Editors fill the application window with one big dockspace that other windows dock into:

C++
ImGui::NewFrame();
ImGui::DockSpaceOverViewport(0, ImGui::GetMainViewport(), ImGuiDockNodeFlags_PassthruCentralNode);
drawMenuBar();          // a main menu bar sits above the dockspace
drawSceneWindow();
drawInspector();
drawLog();

ImGuiDockNodeFlags_PassthruCentralNode leaves the empty central area transparent, so your 3D scene drawn behind ImGui shows through it and receives clicks there.

How docking splits space

A dockspace is a tree of dock nodes. Each node is either a leaf, holding one or more windows as tabs, or a split, holding two child nodes side by side (horizontal) or one above the other (vertical) with a ratio:

root (split left/right, ratio 0.2)
├── left: [Scene tree]                          20% of the width
└── right (split top/bottom, ratio 0.75)
    ├── top: [Viewport] [Game]                  tabs, 75% of the height
    └── bottom: [Log] [Profiler]                tabs, 25%

Every node's rectangle is computed from its parent's: the first child gets ratio of the size along the split axis, the second gets the rest. The practice computes these rectangles, which is exactly the arithmetic ImGui does every frame.

A default layout from code

The first time a user opens your editor, it should not be a pile of floating windows. The DockBuilder API (in imgui_internal.h) builds a layout:

C++
#include "imgui_internal.h"

void buildDefaultLayout(ImGuiID dockspace)
{
    ImGui::DockBuilderRemoveNode(dockspace);
    ImGui::DockBuilderAddNode(dockspace, ImGuiDockNodeFlags_DockSpace);
    ImGui::DockBuilderSetNodeSize(dockspace, ImGui::GetMainViewport()->Size);

    ImGuiID left, right;
    ImGui::DockBuilderSplitNode(dockspace, ImGuiDir_Left, 0.2f, &left, &right);
    ImGuiID bottom, centre;
    ImGui::DockBuilderSplitNode(right, ImGuiDir_Down, 0.25f, &bottom, &centre);

    ImGui::DockBuilderDockWindow("Scene", left);
    ImGui::DockBuilderDockWindow("Viewport", centre);
    ImGui::DockBuilderDockWindow("Log", bottom);
    ImGui::DockBuilderFinish(dockspace);
}

Call it when the dockspace has no saved layout yet (ImGui::DockBuilderGetNode(id) == nullptr before the first DockSpace call), and from a "Reset layout" menu item. After that, imgui.ini remembers whatever the user arranged (lesson 4.06).

Multiple viewports

With ViewportsEnable, dragging a window outside the application window turns it into a real operating-system window, so tools can spread over several monitors. Your loop needs two more calls after rendering the main window:

C++
ImGui::Render();
ImGui_ImplDX11_RenderDrawData(ImGui::GetDrawData());
if (io.ConfigFlags & ImGuiConfigFlags_ViewportsEnable)
{
    ImGui::UpdatePlatformWindows();          // create, move, resize OS windows
    ImGui::RenderPlatformWindowsDefault();   // render and present each one
}
g_swapChain->Present(1, 0);

Coordinates then become desktop coordinates rather than window coordinates, which matters if you place windows yourself: use ImGui::GetMainViewport()->Pos as the origin.

Common mistakes

Using docking functions on the master branch

They do not exist there. Use the docking branch, as most tools do.

Rebuilding the default layout every frame

The user's arrangement is wiped every frame. Build it only when there is none, or on request.
