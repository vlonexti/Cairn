Setting Up ImGui with Win32 and DirectX 11

lesson 1.022 of 6 in milestone 15 min1 practice task

Dear ImGui is a handful of source files you add to your project, plus a platform back end (input and windows) and a renderer back end (drawing). This lesson builds the standard Win32 + DirectX 11 program step by step, the same set-up as ImGui's own example.

What you download

Get Dear ImGui from its GitHub repository (ocornut/imgui). Use a release tag; for docking and multiple viewports (lesson 4.04), use the docking branch, which most tools do. You need:

Files What they are
imgui.cpp, imgui_draw.cpp, imgui_tables.cpp, imgui_widgets.cpp, imgui_demo.cpp The library itself
imgui.h, imconfig.h, imgui_internal.h, imstb_*.h Its headers
backends/imgui_impl_win32.cpp/.h Platform back end: Win32 window messages to ImGui input
backends/imgui_impl_dx11.cpp/.h Renderer back end: ImGui's triangles to Direct3D 11

ImGui has no build system of its own on purpose: add these .cpp files to your Visual Studio project like your own. Then link d3d11.lib and d3dcompiler.lib (and dxgi.lib).

The shape of the program

C++
#include "imgui.h"
#include "imgui_impl_win32.h"
#include "imgui_impl_dx11.h"
#include <d3d11.h>

// Forward-declared in imgui_impl_win32.h behind an #if: declare it yourself.
extern IMGUI_IMPL_API LRESULT ImGui_ImplWin32_WndProcHandler(HWND hWnd, UINT msg, WPARAM wParam, LPARAM lParam);

LRESULT CALLBACK WndProc(HWND hwnd, UINT msg, WPARAM wParam, LPARAM lParam)
{
    if (ImGui_ImplWin32_WndProcHandler(hwnd, msg, wParam, lParam)) return true;   // ImGui sees input first
    switch (msg)
    {
    case WM_SIZE:    /* resize the swap chain buffers (see ImGui's example) */ return 0;
    case WM_DESTROY: PostQuitMessage(0); return 0;
    }
    return DefWindowProcW(hwnd, msg, wParam, lParam);
}

int WINAPI wWinMain(HINSTANCE instance, HINSTANCE, PWSTR, int)
{
    // 1. A window and a Direct3D 11 device and swap chain (ordinary Win32 and D3D11 code).
    HWND hwnd = createWindow(instance, WndProc);
    createDeviceAndSwapChain(hwnd);              // fills g_device, g_context, g_swapChain, g_renderTarget

    // 2. ImGui itself.
    IMGUI_CHECKVERSION();
    ImGui::CreateContext();
    ImGuiIO& io = ImGui::GetIO();
    io.ConfigFlags |= ImGuiConfigFlags_NavEnableKeyboard;   // arrow keys and Tab move between widgets
    ImGui::StyleColorsDark();

    // 3. The two back ends.
    ImGui_ImplWin32_Init(hwnd);
    ImGui_ImplDX11_Init(g_device, g_context);

    // 4. The loop (lesson 1.03).
    bool running = true;
    while (running)
    {
        MSG msg;
        while (PeekMessageW(&msg, nullptr, 0, 0, PM_REMOVE))
        {
            TranslateMessage(&msg);
            DispatchMessageW(&msg);
            if (msg.message == WM_QUIT) running = false;
        }
        if (!running) break;

        ImGui_ImplDX11_NewFrame();
        ImGui_ImplWin32_NewFrame();
        ImGui::NewFrame();

        ImGui::ShowDemoWindow();                 // every widget ImGui has, to explore (lesson 1.06)

        ImGui::Render();
        const float clear[4] = { 0.1f, 0.1f, 0.12f, 1.0f };
        g_context->OMSetRenderTargets(1, &g_renderTarget, nullptr);
        g_context->ClearRenderTargetView(g_renderTarget, clear);
        ImGui_ImplDX11_RenderDrawData(ImGui::GetDrawData());
        g_swapChain->Present(1, 0);              // 1 = wait for vertical sync
    }

    // 5. Shut down in reverse order.
    ImGui_ImplDX11_Shutdown();
    ImGui_ImplWin32_Shutdown();
    ImGui::DestroyContext();
    destroyDeviceAndWindow();
    return 0;
}

The parts that are not ImGui (creating the window, the device, the swap chain, resizing) are copied almost word for word from examples/example_win32_directx11/main.cpp in the ImGui repository. Start from that file; it is the reference everyone uses.

What each piece does

  • ImGui_ImplWin32_WndProcHandler turns Windows messages (mouse moves, clicks, keys, characters, focus) into ImGui input. It must run first in your window procedure.
  • ImGui::CreateContext makes the one object that holds all of ImGui's state. Most programs have exactly one.
  • ImGui_ImplWin32_Init and ImGui_ImplDX11_Init connect the context to the window and to the device. The DirectX back end creates its own shaders, a font texture and buffers.
  • In the loop, the two back ends' NewFrame calls feed ImGui the window size, time and input, then ImGui::NewFrame starts recording widgets.
  • ImGui::Render finishes the frame and produces draw data: lists of triangles, textures and clipping rectangles. The renderer back end draws them over your scene.

In a game that already has a renderer

In a real game, step 1 already exists. You add steps 2 and 3 after your device is created, call the three NewFrame functions at the start of your frame, and call ImGui::Render plus ImGui_ImplDX11_RenderDrawData after your scene is drawn, so ImGui appears on top. Lesson 2.05 deals with sharing the mouse and keyboard between ImGui and the game.

Common mistakes

Not forwarding window messages

Without ImGui_ImplWin32_WndProcHandler first in the window procedure, windows draw but nothing reacts to the mouse.

Forgetting the extern declaration

imgui_impl_win32.h hides ImGui_ImplWin32_WndProcHandler behind an #if 0. Declare it yourself, as above.

Mismatched versions of imgui.h and the back ends

Back ends must come from the same version of ImGui. IMGUI_CHECKVERSION() catches a header and a .cpp from different versions.
