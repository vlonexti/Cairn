A Log Window with Filters

lesson 5.022 of 4 in milestone 55 min2 practice tasks

Every engine prints far more log lines than anyone can read. A good log window lets you filter by severity and by text, follows new lines without fighting the user, colours errors, and copes with a million lines. This lesson builds one with ImGuiTextFilter, a level filter and the list clipper.

The data

Keep log entries as data, not one big string, so they can be filtered:

C++
enum class Level { Trace, Info, Warning, Error };
struct LogEntry { double time; Level level; std::string category; std::string text; };

class Log
{
public:
    void add(Level level, std::string category, std::string text);
    const std::vector<LogEntry>& entries() const;
    void clear();
private:
    std::vector<LogEntry> m_entries;      // or a ring buffer with a maximum size
    std::mutex m_mutex;                   // other threads log too
};

Log calls come from many threads (loading, audio, networking). Protect the container with a mutex, or have each thread push into a lock-free queue that the UI thread drains once per frame.

ImGuiTextFilter

ImGui ships a small text filter with a useful syntax:

C++
static ImGuiTextFilter filter;
filter.Draw("Filter (\"inc,-exc\")", 240.0f);
for (const LogEntry& e : log.entries())
    if (filter.PassFilter(e.text.c_str()))
        ImGui::TextUnformatted(e.text.c_str());

The filter text is a comma-separated list of words:

  • texture shows lines containing "texture";
  • texture,shader shows lines containing either;
  • -vsync hides lines containing "vsync";
  • -missing,texture shows texture lines except those containing "missing".

The terms are checked in order, and the first one that matches the line decides: an exclusion that matches hides the line, an inclusion that matches shows it. So order matters: with texture,-missing, a line "texture missing" matches texture first and is shown. Put exclusions first. Spaces around terms are ignored and matching ignores case. If no term matches, the line passes only if the filter has no inclusions at all. The practice reimplements these exact rules.

Severity and category

Add check boxes for levels and a combo for categories, and combine them with the text filter:

C++
static bool showLevel[4] = { false, true, true, true };    // hide Trace by default
ImGui::Checkbox("Info", &showLevel[1]); ImGui::SameLine();
ImGui::Checkbox("Warnings", &showLevel[2]); ImGui::SameLine();
ImGui::Checkbox("Errors", &showLevel[3]);

Each line then passes if its level is shown, its category matches, and the text filter passes.

Drawing a million lines

Filtering every line every frame is fine for thousands, not for millions. Keep a list of the indexes of matching entries, rebuild it only when the filter changes, and append to it as new entries arrive (checking only the new ones). Then draw it with the clipper (lesson 3.02):

C++
ImGuiListClipper clipper;
clipper.Begin((int)visible.size());
while (clipper.Step())
    for (int row = clipper.DisplayStart; row < clipper.DisplayEnd; ++row)
    {
        const LogEntry& e = entries[visible[row]];
        ImGui::PushStyleColor(ImGuiCol_Text, colourFor(e.level));
        ImGui::TextUnformatted(e.text.c_str());
        ImGui::PopStyleColor();
    }

Follow new lines only when the user was at the bottom (lesson 3.02), and offer "Copy" (ImGui::SetClipboardText) and "Clear" buttons.

Common mistakes

Logging from other threads into a vector without a lock

Two threads pushing at once corrupt it. Lock, or queue and drain on the UI thread.

Filtering the whole log every frame

Rebuild the visible index list only when the filter changes; append for new lines.
