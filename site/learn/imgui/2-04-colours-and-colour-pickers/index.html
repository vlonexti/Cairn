Colours and Colour Pickers

lesson 2.044 of 5 in milestone 25 min1 practice task

ImGui works with colours in two forms - four floats from 0 to 1 (ImVec4) and one packed 32-bit integer (ImU32, built with IM_COL32). This lesson covers the colour widgets, converting between the forms and to HSV, and why packed colours store their bytes in the order they do.

Colour widgets

C++
ImGui::ColorEdit3("Fog colour", &fog.color.x);        // float[3]: r, g, b from 0 to 1
ImGui::ColorEdit4("Tint", &sprite.tint.x);            // float[4]: with alpha
ImGui::ColorPicker4("Sky", &sky.x);                   // the big picker with a hue wheel or square
ImGui::ColorButton("##swatch", ImVec4(0.9f, 0.6f, 0.2f, 1.0f));   // a clickable swatch

ColorEdit shows the colour as numbers with a swatch; click the swatch for a picker popup. Flags choose the details: ImGuiColorEditFlags_NoAlpha, DisplayHex, DisplayHSV, PickerHueWheel, Float (0..1 numbers instead of 0..255), HDR (values above 1).

Two forms of colour

ImVec4: four floats, red, green, blue, alpha, each from 0 to 1. Widgets and styles use this form.

ImU32: four bytes packed into one 32-bit unsigned integer. Draw lists use this form, because millions of vertices each carry a colour and four bytes are much smaller than four floats. The macro builds one:

C++
ImU32 gold = IM_COL32(240, 180, 70, 255);    // r, g, b, a from 0 to 255
draw->AddRectFilled(min, max, gold);

With ImGui's default settings, IM_COL32(r, g, b, a) is

Output
(a << 24) | (b << 16) | (g << 8) | r

Red is in the lowest byte. Written in memory on a little-endian PC (lesson 1.02 of the gamedev course), the bytes are in the order R, G, B, A, which is exactly the vertex format the GPU reads. That is why it looks "backwards" as a hexadecimal number: opaque red is 0xFF0000FF.

Converting between them:

C++
ImVec4 v = ImGui::ColorConvertU32ToFloat4(gold);
ImU32  u = ImGui::ColorConvertFloat4ToU32(ImVec4(1, 0.5f, 0, 1));   // rounds to the nearest of 0..255
ImU32  w = ImGui::GetColorU32(ImGuiCol_Text);                       // a style colour, with the current alpha

HSV

Hue, saturation, value is a friendlier space for adjusting colours: change the hue to cycle through the rainbow while keeping brightness; lower the saturation to grey something out.

C++
float h, s, v;
ImGui::ColorConvertRGBtoHSV(c.x, c.y, c.z, h, s, v);   // all in 0..1, hue too
h = std::fmod(h + 0.1f, 1.0f);                          // shift the hue
ImGui::ColorConvertHSVtoRGB(h, s, v, c.x, c.y, c.z);

A classic tool trick is to give each item a distinct colour from its index: hue = i * 0.618034f modulo 1 (the golden ratio spreads them evenly), saturation 0.6, value 0.9. The practice writes the conversions.

Hexadecimal colour codes

Artists often paste colours as #F0B446 or #F0B446CC. Parsing them into an ImVec4 is a small, useful function, which the practice also has you write.

Common mistakes

Building an ImU32 by hand in the wrong byte order

0xF0B446FF is not gold with full alpha in ImGui's layout. Use IM_COL32 or ColorConvertFloat4ToU32.

Passing 0-255 values to ColorEdit

ColorEdit edits floats from 0 to 1. Convert when your data stores bytes.
