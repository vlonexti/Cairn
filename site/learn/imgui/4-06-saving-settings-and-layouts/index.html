Saving Settings and Layouts

lesson 4.066 of 6 in milestone 45 min1 practice task

ImGui saves window positions, sizes, docking and table layouts to imgui.ini by itself. This lesson explains that file, how to move it, how to store your own tool's settings in the same file with a settings handler, and how to save and restore named layouts.

imgui.ini

By default ImGui writes imgui.ini in the working directory a few seconds after something changes, and reads it at start-up:

INI
[Window][Stones]
Pos=60,40
Size=320,260
Collapsed=0
DockId=0x00000002,0

[Table][0x8A4C2B11,4]
Column 0  Weight=1.0000 Visible=1 Order=0 Sort=0v
Column 1  Width=60 Visible=1 Order=1

[Docking][Data]
DockSpace     ID=0x3BC79352 Window=0x4647B76E Pos=0,19 Size=1280,701 Split=X
  DockNode    ID=0x00000001 Parent=0x3BC79352 SizeRef=256,701 Selected=0x8B1D2D3A
  DockNode    ID=0x00000002 Parent=0x3BC79352 SizeRef=1022,701 CentralNode=1

It is a simple text format: [Type][Name] section headers, then Key=Value lines.

Where it goes

The working directory is a bad place: it changes with how the program is started. Put it in the user's settings folder:

C++
static std::string iniPath = settingsFolder() + "\\xenon_editor_imgui.ini";   // e.g. under %APPDATA%
io.IniFilename = iniPath.c_str();          // the string must outlive ImGui: keep it static or global
io.IniSavingRate = 2.0f;                   // seconds of quiet before saving

Set io.IniFilename = nullptr to turn saving off, and save or load yourself with ImGui::SaveIniSettingsToMemory() and ImGui::LoadIniSettingsFromMemory(text), for example to keep the layout inside your own project file.

Your own settings in the same file

A settings handler lets your tool save its own data as more sections of imgui.ini, so window layout and tool settings live and load together:

C++
ImGuiSettingsHandler handler;
handler.TypeName = "XenonEditor";
handler.TypeHash = ImHashStr("XenonEditor");
handler.ReadOpenFn = [](ImGuiContext*, ImGuiSettingsHandler*, const char* name) -> void* {
    return std::strcmp(name, "Options") == 0 ? &g_options : nullptr;     // which object receives the lines
};
handler.ReadLineFn = [](ImGuiContext*, ImGuiSettingsHandler*, void* entry, const char* line) {
    auto* o = static_cast<Options*>(entry);
    int v;
    if (std::sscanf(line, "GridSize=%d", &v) == 1) o->gridSize = v;
    else if (std::sscanf(line, "Snap=%d", &v) == 1) o->snap = v != 0;
};
handler.WriteAllFn = [](ImGuiContext*, ImGuiSettingsHandler* h, ImGuiTextBuffer* out) {
    out->appendf("[%s][Options]\n", h->TypeName);
    out->appendf("GridSize=%d\nSnap=%d\n\n", g_options.gridSize, g_options.snap ? 1 : 0);
};
ImGui::AddSettingsHandler(&handler);      // before the first NewFrame (the ini is read then)

When your settings change, call ImGui::MarkIniSettingsDirty() so ImGui saves soon.

Because the format is so simple, reading and writing it yourself is easy too. The practice writes a small reader that turns the file into sections of key-value pairs, and a writer that puts them back, keeping sections it does not understand untouched.

Named layouts

Editors often let users save layouts by name: "Level design", "Animation", "Debugging". With SaveIniSettingsToMemory and LoadIniSettingsFromMemory, a layout is just a string:

C++
layouts["Animation"] = ImGui::SaveIniSettingsToMemory();      // save the current arrangement
ImGui::LoadIniSettingsFromMemory(layouts["Animation"].c_str()); // switch to it (at the start of a frame)

Common mistakes

A temporary string for io.IniFilename

ImGui keeps the pointer. A temporary dies and ImGui reads freed memory. Keep it in a static or global.

Adding a settings handler after the first frame

The ini file has already been read, so your section is ignored. Add handlers before the first NewFrame.
