The Frame and the Draw Data

lesson 1.033 of 6 in milestone 15 min2 practice tasks

Every ImGui frame follows the same steps - input in, widgets described, draw data out. This lesson looks inside them, explains what draw data is, and covers the timing questions every tool runs into - frame rate, delta time, and only drawing when something changed.

Inside a frame

graph LR
  A[Back ends' NewFrame: size, time, input] --> B[ImGui::NewFrame]
  B --> C[Your code: Begin, widgets, End]
  C --> D[ImGui::Render]
  D --> E[Draw data]
  E --> F[Renderer back end draws it]
  • Input in. The platform back end sets io.DisplaySize, io.DeltaTime, and queues input events (mouse position, buttons, keys, characters).
  • NewFrame. ImGui processes the events, decides which window is under the mouse, which widget is hovered, and clears last frame's draw lists.
  • Your code. Each widget function does three things at once: it lays itself out (takes space from the window's cursor), handles input (was it clicked?), and adds shapes to the window's draw list. It returns the result immediately.
  • Render. ImGui sorts windows by depth and collects every window's draw list into one ImDrawData.
  • Draw. The back end uploads vertices and indices to the GPU and issues one draw call per command.

You can call widget functions anywhere between NewFrame and Render: in your game's update, in each system's own debug function, in a loop over entities. They all add to the same frame.

Draw data

C++
ImDrawData* data = ImGui::GetDrawData();
for (int n = 0; n < data->CmdListsCount; ++n)
{
    const ImDrawList* list = data->CmdLists[n];        // one per window, roughly
    // list->VtxBuffer: vertices (position, texture coordinate, colour)
    // list->IdxBuffer: triangle indices
    for (const ImDrawCmd& cmd : list->CmdBuffer)
    {
        // cmd.ClipRect: scissor rectangle; cmd.TextureId: which texture; cmd.ElemCount: how many indices
    }
}

Everything ImGui draws, including text, is textured triangles. Text uses a font atlas: one texture containing every glyph, built at start-up (lesson 4.05). That is why ImGui is so portable: a back end only needs to draw coloured, textured triangles with scissor rectangles.

You rarely touch draw data yourself, but it helps to know that ImGui::GetWindowDrawList() gives you the current window's draw list, so you can add your own lines, circles and text (useful for graphs and minimaps):

C++
ImDrawList* draw = ImGui::GetWindowDrawList();
ImVec2 p = ImGui::GetCursorScreenPos();
draw->AddCircleFilled(ImVec2(p.x + 20, p.y + 20), 12.0f, IM_COL32(240, 180, 70, 255));
ImGui::Dummy(ImVec2(40, 40));     // reserve the space so the next widget goes below

Delta time and frame rate

ImGui needs to know how much time passed since the last frame (io.DeltaTime) for double-click detection, key repeat, blinking cursors and animations. The Win32 back end measures it with QueryPerformanceCounter. Your own code can read it too:

C++
ImGuiIO& io = ImGui::GetIO();
ImGui::Text("%.1f FPS (%.2f ms)", io.Framerate, 1000.0f / io.Framerate);

io.Framerate is an average over the last 60 frames or so, so the number does not jump around.

Tools that sleep

A game redraws every frame anyway. A standalone tool (a level editor, an asset browser) does not need to burn a CPU core redrawing an unchanged screen at 144 Hz. Common approaches:

  • V-sync: Present(1, 0) waits for the display, capping the frame rate at its refresh rate.
  • Wait for input when idle: if nothing is animating, block in MsgWaitForMultipleObjects or WaitMessage until a message arrives, then draw a few frames (ImGui sometimes needs one or two extra frames to settle a layout).
  • Minimised: when IsIconic(hwnd) is true, sleep instead of drawing.

The practice for this lesson has you write the "how many frames should I still draw?" logic a sleeping tool uses.

Common mistakes

Calling widget functions before NewFrame or after Render

ImGui asserts. Every widget call belongs between the two.

Assuming one frame is enough after input

Some layouts settle over two frames (a window measuring its content). Draw a couple more frames after the last input.
