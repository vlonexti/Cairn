Drag and Drop

lesson 4.033 of 6 in milestone 45 min2 practice tasks

Dragging an asset onto a slot, reordering a list, moving an object to another parent in a tree - ImGui's drag and drop works between any two items with a typed payload. This lesson covers sources, targets, payload types, reordering a list by dragging, and re-parenting in a tree without creating loops.

Source and target

Any item can be a drag source and any item a drop target. They talk through a payload: a small block of bytes with a type name.

C++
// The source: an asset in the browser
ImGui::Selectable(asset.name.c_str());
if (ImGui::BeginDragDropSource())
{
    ImGui::SetDragDropPayload("ASSET", &asset.id, sizeof(asset.id));   // copied by ImGui
    ImGui::Text("%s", asset.name.c_str());                              // drawn under the mouse while dragging
    ImGui::EndDragDropSource();
}

// The target: a texture slot in the inspector
ImGui::Button(material.texture.empty() ? "(drop a texture)" : material.texture.c_str(), ImVec2(-FLT_MIN, 0));
if (ImGui::BeginDragDropTarget())
{
    if (const ImGuiPayload* p = ImGui::AcceptDragDropPayload("ASSET"))  // non-null on the frame of the drop
    {
        const int id = *static_cast<const int*>(p->Data);
        material.texture = assets.byId(id).name;
    }
    ImGui::EndDragDropTarget();
}

Both Begin... functions follow the "End only if Begin returned true" rule. The type string (up to 32 characters) lets a target accept only what it understands: a texture slot accepts "ASSET", ignores "ENTITY". While dragging, matching targets highlight automatically.

The payload is copied, so pass small, stable things: an id, an index, never a pointer to something that may move or be deleted during the drag.

Reordering a list

A list where each row is both a source and a target can be reordered by dragging:

C++
for (int i = 0; i < (int)layers.size(); ++i)
{
    ImGui::PushID(i);
    ImGui::Selectable(layers[i].name.c_str());
    if (ImGui::BeginDragDropSource()) { ImGui::SetDragDropPayload("LAYER", &i, sizeof(i)); ImGui::Text("%s", layers[i].name.c_str()); ImGui::EndDragDropSource(); }
    if (ImGui::BeginDragDropTarget())
    {
        if (const ImGuiPayload* p = ImGui::AcceptDragDropPayload("LAYER"))
            pendingMove = { *static_cast<const int*>(p->Data), i };     // apply after the loop
        ImGui::EndDragDropTarget();
    }
    ImGui::PopID();
}
if (pendingMove) { moveItem(layers, pendingMove->from, pendingMove->to); pendingMove.reset(); }

Apply the move after the loop: changing the vector while iterating over it would skip or repeat rows. "Move item from from to to" means: take the item out, and insert it so it ends up at index to. The practice writes moveItem.

Re-parenting in a tree

Dropping a tree node on another node makes it a child of that node. One rule protects the data: a node may not be dropped onto itself or onto any of its own descendants, which would make a loop (the node would become its own ancestor) and detach that whole branch from the tree. Check the ancestry before accepting:

C++
bool isAncestor(const Scene& s, int maybeAncestor, int node)   // walk up the parent links

ImGui can help the user too: AcceptDragDropPayload with ImGuiDragDropFlags_AcceptBeforeDelivery lets you peek at the payload while hovering and show a "not allowed" cursor or tooltip before the drop. The practice implements the re-parenting rule.

Dragging from outside

The Win32 back end does not deliver files dragged from Explorer as ImGui payloads. Handle WM_DROPFILES (after DragAcceptFiles(hwnd, TRUE)) in your window procedure, and act on the files directly, for example importing them into the asset browser.

Common mistakes

A pointer in the payload

The data may move or be deleted during the drag. Use ids or indexes.

Changing a container while drawing it

Record the move and apply it after the loop.

Allowing a node to become its own descendant

Check ancestry before re-parenting, or part of the tree disappears into a loop.
