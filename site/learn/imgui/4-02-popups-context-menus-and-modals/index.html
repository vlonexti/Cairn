Popups, Context Menus and Modals

lesson 4.022 of 6 in milestone 45 min1 practice task

Popups are small windows that appear on request and close when you click elsewhere - right-click menus, pickers, confirmations. This lesson explains ImGui's popup model (open by ID, draw every frame while open), context menus on items and windows, modal dialogs that block the rest of the interface, and the classic "unsaved changes" confirmation.

Opening and drawing are separate

A popup has an ID, like a widget. You open it once, in reaction to something, and you draw it every frame with BeginPopup, which returns true only while it is open:

C++
if (ImGui::Button("Pick a stone")) ImGui::OpenPopup("stone picker");     // once, on click

if (ImGui::BeginPopup("stone picker"))                                     // every frame
{
    for (const char* s : { "Granite", "Basalt", "Slate" })
        if (ImGui::Selectable(s)) chosen = s;                              // a Selectable closes the popup
    ImGui::EndPopup();                                                     // only if BeginPopup returned true
}

The popup closes by itself when the user clicks outside it, presses Escape, or clicks a Selectable/MenuItem inside it. Close it from code with ImGui::CloseCurrentPopup() inside the popup.

Both calls must be made with the same ID stack: an OpenPopup inside a PushID(i) opens a popup that BeginPopup can only find inside the same PushID(i). This is the most common popup bug, and a direct consequence of lesson 1.05.

Context menus

Right-click menus have shortcuts that do the opening for you:

C++
ImGui::Selectable(stone.name.c_str());
if (ImGui::BeginPopupContextItem())                   // right-click on the item just drawn
{
    if (ImGui::MenuItem("Rename")) startRename(stone);
    if (ImGui::MenuItem("Delete")) deleteStone(stone);
    ImGui::EndPopup();
}

if (ImGui::BeginPopupContextWindow(nullptr, ImGuiPopupFlags_MouseButtonRight | ImGuiPopupFlags_NoOpenOverItems))
{                                                      // right-click on empty space in the window
    if (ImGui::MenuItem("Add stone")) addStone();
    ImGui::EndPopup();
}

Modals

A modal popup blocks interaction with everything behind it until it is closed, and dims the background. Use it for decisions that must be made before continuing:

C++
if (wantsToQuit && level.dirty) ImGui::OpenPopup("Unsaved changes");

ImGui::SetNextWindowPos(ImGui::GetMainViewport()->GetCenter(), ImGuiCond_Appearing, ImVec2(0.5f, 0.5f));
if (ImGui::BeginPopupModal("Unsaved changes", nullptr, ImGuiWindowFlags_AlwaysAutoResize))
{
    ImGui::Text("Save changes to %s before quitting?", level.name.c_str());
    if (ImGui::Button("Save", ImVec2(100, 0)))       { save(); quit(); ImGui::CloseCurrentPopup(); }
    ImGui::SameLine();
    if (ImGui::Button("Don't save", ImVec2(100, 0))) { quit(); ImGui::CloseCurrentPopup(); }
    ImGui::SameLine();
    if (ImGui::Button("Cancel", ImVec2(100, 0)))     { wantsToQuit = false; ImGui::CloseCurrentPopup(); }
    ImGui::EndPopup();
}

SetNextWindowPos with the pivot (0.5, 0.5) and ImGuiCond_Appearing centres the dialog each time it appears. Passing a bool* as the second argument gives the modal a close button.

The unsaved-changes flow

"Quit", "New level" and "Open level" all have the same shape: if there are unsaved changes, ask first; then do the action only if the user saved or chose not to. A small state machine keeps it correct: remember the pending action, open the modal, and when a button is pressed run (or drop) the pending action. The practice builds it.

Common mistakes

OpenPopup and BeginPopup under different ID stacks

The popup is opened but never found. Call both at the same PushID level.

Calling OpenPopup every frame

The popup reopens and resets constantly. Open it once, in response to an event.

Using a modal for information

Modals interrupt. Use them for decisions only; show information in a tooltip or a log.
