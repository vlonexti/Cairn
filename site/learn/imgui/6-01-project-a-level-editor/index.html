The viewport: from screen to tiles and back

The viewport needs a camera: a pan offset (where the map's origin is on screen) and a zoom (pixels per tile).

C++
struct Camera { ImVec2 pan{ 0, 0 }; float zoom{ 32.0f }; };   // zoom = pixels per tile

ImVec2 tileToScreen(const Camera& c, ImVec2 origin, float tx, float ty)
{
    return ImVec2(origin.x + c.pan.x + tx * c.zoom, origin.y + c.pan.y + ty * c.zoom);
}
// and the reverse, screenToTile, for the mouse

Zooming around the mouse feels right only if the tile under the mouse stays under the mouse: remember which tile it is before changing the zoom, then adjust the pan so it is back under the cursor. The practice writes these functions; they are the same maths any 2D editor or map view uses.

Drawing only what is visible matters for big maps: compute the visible range of tiles from the viewport rectangle (lesson 3.02's clipper idea in 2D) and loop over just those.

C++
ImGui::Begin("Viewport");
const ImVec2 origin = ImGui::GetCursorScreenPos();
const ImVec2 size = ImGui::GetContentRegionAvail();
ImGui::InvisibleButton("canvas", size, ImGuiButtonFlags_MouseButtonLeft | ImGuiButtonFlags_MouseButtonMiddle);
const bool hovered = ImGui::IsItemHovered();
ImDrawList* dl = ImGui::GetWindowDrawList();
dl->PushClipRect(origin, ImVec2(origin.x + size.x, origin.y + size.y), true);
// draw visible tiles, the grid, the hovered tile's outline, the rectangle tool's preview
dl->PopClipRect();
if (hovered && ImGui::IsMouseDragging(ImGuiMouseButton_Middle)) camera.pan += ImGui::GetIO().MouseDelta;
if (hovered && ImGui::GetIO().MouseWheel != 0) zoomAround(camera, ImGui::GetMousePos(), ImGui::GetIO().MouseWheel);
ImGui::End();

InvisibleButton covering the canvas gives you hover, active and clicks for the whole area, and stops the window from being dragged when you paint.

Tools and undo

Each tool turns mouse input into changes to tiles:

  • Paint and Erase: while the left button is held, set the tile under the mouse. Collect every tile changed during the stroke, with its old value, and record one undo step when the button is released (lesson 5.04's "one drag, one step").
  • Rectangle: show a preview while dragging; on release, fill the rectangle as one step.
  • Flood fill: replace the connected region of the clicked tile's kind with the new kind, as one step. Use an explicit stack or queue, not recursion: a large region would overflow the call stack.

The file format

A readable text format makes levels easy to diff in version control:

Output
xenon-level 1
size 40 24
palette . grass, # stone, ~ water
tiles
........................................
...####.........~~~~~...................

One character per tile, rows top to bottom, with a version number on the first line (lesson 3.05) so a future editor can read old files. The project at the end of this milestone has you write the editor's core: map, tools, undo and file format.

Order to build in

  1. Host, docking, menu, empty windows: it runs.
  2. Map data, the viewport drawing it, pan and zoom.
  3. Paint and erase with the palette, then undo for them.
  4. Save and load, the dirty flag in the title, the unsaved-changes guard.
  5. Rectangle and flood fill.
  6. Inspector, log, settings.
