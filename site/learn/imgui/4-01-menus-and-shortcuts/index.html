Menus and Shortcuts

lesson 4.011 of 6 in milestone 45 min1 practice task

A main menu bar turns a pile of windows into an application - File, Edit, View, Tools. This lesson covers menu bars in the main viewport and in windows, menu items with checkmarks and shortcut text, the Begin/End rule for menus, and wiring the shortcuts so they actually work.

The main menu bar

C++
if (ImGui::BeginMainMenuBar())                       // across the top of the screen
{
    if (ImGui::BeginMenu("File"))
    {
        if (ImGui::MenuItem("New level", "Ctrl+N")) newLevel();
        if (ImGui::MenuItem("Open...", "Ctrl+O"))   openDialog();
        if (ImGui::MenuItem("Save", "Ctrl+S", false, level.dirty)) save();   // disabled when nothing changed
        ImGui::Separator();
        if (ImGui::MenuItem("Quit", "Alt+F4")) running = false;
        ImGui::EndMenu();
    }
    if (ImGui::BeginMenu("View"))
    {
        ImGui::MenuItem("Stones", nullptr, &showStones);    // a checkmark bound to a bool
        ImGui::MenuItem("Log", nullptr, &showLog);
        ImGui::EndMenu();
    }
    ImGui::EndMainMenuBar();
}

This is the pair rule you met in lesson 1.04: BeginMainMenuBar/EndMainMenuBar and BeginMenu/EndMenu are only ended if their Begin returned true. A closed menu returns false, so its EndMenu is skipped.

MenuItem has two useful forms:

  • MenuItem(label, shortcut, selected, enabled) returns true when clicked; selected draws a checkmark, enabled = false greys it out.
  • MenuItem(label, shortcut, bool* selected) toggles the bool when clicked: the standard "show window" switch.

Menus can nest: a BeginMenu inside another opens a sub-menu.

A menu bar inside a window

C++
ImGui::Begin("Level editor", nullptr, ImGuiWindowFlags_MenuBar);
if (ImGui::BeginMenuBar())
{
    if (ImGui::BeginMenu("Edit")) { /* ... */ ImGui::EndMenu(); }
    ImGui::EndMenuBar();
}
// window contents
ImGui::End();

Shortcut text is only text

The second argument of MenuItem ("Ctrl+S") is only displayed. Clicking the menu item works; pressing Ctrl+S does nothing unless you also check the keys. Do that once, outside the menu code, so the shortcut works even when the menu is closed:

C++
if (ImGui::Shortcut(ImGuiMod_Ctrl | ImGuiKey_S, ImGuiInputFlags_RouteGlobal)) save();

A tidy approach is a table of commands: each has a name, a shortcut, an "is it available" check and an action. The menu draws from the table, the shortcut handler checks the table, and a command palette (Ctrl+Shift+P, like editors have) can list it too. The practice builds that table, including detecting two commands that claim the same shortcut.

Keyboard navigation in menus

With ImGuiConfigFlags_NavEnableKeyboard, pressing Alt focuses the menu bar, arrow keys move through it, Enter activates and Escape closes, the way desktop applications behave.

Common mistakes

Calling EndMenu when BeginMenu returned false

ImGui asserts. EndMenu goes inside the if.

Expecting the shortcut text to work by itself

It is a label. Check the keys with Shortcut or IsKeyPressed.

Two commands on the same shortcut

Only one will ever run, depending on which is checked first. Detect clashes when you build the command table.
