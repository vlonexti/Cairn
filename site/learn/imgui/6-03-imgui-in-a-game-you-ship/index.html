ImGui in a Game You Ship

lesson 6.033 of 3 in milestone 65 min

Dear ImGui is a development tool first. Before a game ships, decide what happens to the debug interface - compile it out, hide it behind a key, or keep a few tools for players - and check what it costs. This lesson covers build switches, performance, security and licensing.

Three choices

Choice When How
Compile it out Most shipped games A build switch removes every debug window and the ImGui calls
Hidden behind a key or a flag Games tested by others, early access Present but not drawn until a debug key or a command-line flag
Keep some tools for players Modding tools, level editors shipped with the game Treated as real product UI: styled, tested, translated

A build switch

Give your project a configuration flag, say XENON_DEV_TOOLS, defined in Debug and in an internal "Development" configuration, and not in Shipping:

C++
#if XENON_DEV_TOOLS
    drawDebugWindows();
    ImGui::ShowMetricsWindow(&showMetrics);
#endif

Keep tool code in its own files (debug_ui/*.cpp) so the shipping build can leave whole files out. If the game uses ImGui for nothing else, the shipping build need not link ImGui at all, which also removes the font atlas and its texture memory.

What it costs

Measure before guessing:

  • CPU: building the UI runs your code every frame. Debug windows that loop over every entity are the usual culprits; use the clipper and only build windows that are open (lesson 1.04's Begin return value).
  • GPU: usually tiny, a few draw calls. Watch for thousands of custom draw-list primitives.
  • Memory: the font atlas (a few megabytes with large fonts and icon fonts), plus vertex buffers.
  • Input: if a debug window has keyboard focus, the game must not react to keys (lesson 2.05). In a shipping build with hidden tools, make sure nothing can grab focus while hidden.

The Metrics window (lesson 1.06) shows vertex counts per window.

Security and cheating

Debug tools that edit memory, spawn items or teleport are cheats in a multiplayer game. In anything online:

  • compile them out of client builds, rather than hiding them;
  • never trust the client: the server decides what is allowed, whatever the client's interface can do.

Licensing

Dear ImGui is under the MIT licence: free to use in commercial games, provided the licence text is included with the software (usually in an "open source licences" screen or file). The same goes for ImPlot and most companion libraries; check each one's licence. Fonts have their own licences (Font Awesome Free and most Google Fonts allow embedding with attribution).

Checklist

  • Shipping configuration builds without XENON_DEV_TOOLS and runs.
  • No debug window can be opened in a shipping build by any key combination.
  • Debug-only assets (tool fonts, icon fonts) are not in the shipping package.
  • Licence texts for every library and font are included.
  • For a game with shipped tools: those windows are styled, scale with the display, work with a controller if the game does, and are translated.
