Practice Targets You Compile Yourself

lesson 9.1010 of 10 in milestone 96 min

The best way to learn reverse engineering is on programs whose source you can check afterwards. This lesson gives a graded series of practice targets to write, build without symbols, and analyse with the chapter's tools, from a single function to a small game with classes and a file format, along with how to set up the builds and how to check your answers.

The routine

For each target:

  1. Write it, or have a friend write it so you do not know the answers.
  2. Build it Release, x64, and move the .pdb out of the folder.
  3. Analyse it statically in Ghidra and dynamically in x64dbg or Visual Studio, writing down your conclusions: names, types, what each function does, the format of any file.
  4. Check against the source. For each mistake, find which evidence misled you.
  5. Load the PDB into Ghidra and compare the two views.

Repeat a target with /Od (unoptimised) for an easier version, and with /O2 /GL (whole-program optimisation, more inlining) for a harder one.

Level 1: single functions

Write a program with half a dozen small functions and call them from main with values read from std::cin, so the optimiser cannot fold everything into constants:

  • int clamp(int v, int lo, int hi)
  • unsigned popcount(unsigned x) (count set bits with a loop)
  • int sumSquares(const int* a, int n)
  • bool isPalindrome(const char* s)
  • float lerp(float a, float b, float t)

Goal: name each function and give its signature from the assembly alone. Watch for cmov in clamp, the loop in popcount (or the popcnt instruction, if the compiler uses it), vectorisation in sumSquares, and xmm registers in lerp.

Level 2: control flow

  • A switch on a command letter with eight cases (find the jump table, lesson 7.07).
  • A state machine with an enum and a loop.
  • A function with early returns and &&/|| conditions.

Goal: reconstruct the control flow as C++ that behaves identically, and test it against the original with the same inputs.

Level 3: data structures

  • A struct with mixed members (int, float, bool, pointer, char[16]) passed to several functions.
  • A singly linked list built from user input and walked.
  • A std::vector<Item> with push_back and a loop.

Goal: rebuild the structs (lesson 9.09), including size and padding, and recognise the standard library's inlined code (vector growth, lesson 3.07).

Level 4: classes

  • A small hierarchy with virtual functions: Shape with area() and name(), three derived classes, a vector of std::unique_ptr<Shape>.

Goal: find every vtable and its RTTI name (lesson 9.06), match each slot to a function, identify constructors and destructors, and draw the hierarchy. Then rebuild with /GR- and do it again without the names.

Level 5: a file format

Write a program that saves and loads a simple binary file: a header with a magic number and version, a count, then records of mixed fields, little-endian (lesson 2.06's practice). Analyse the program and a file it wrote.

Goal: write a specification of the format (offsets, sizes, meanings) good enough that someone could write a compatible reader, and then write that reader yourself. This is exactly what interoperability work looks like.

Level 6: a small game

Take the game you will build in chapter 11 (or any small game of your own), build it without symbols, and pick a feature: how damage is calculated, how a level file is loaded, how the save format works.

Goal: document the feature completely from the binary, as if you had never seen the source.

Other sources of practice

  • Open-source programs: build one in Release without symbols and analyse it; the source is there to check you.
  • Capture-the-flag competitions often include reverse engineering challenges, made and published for exactly this purpose.
  • Crackme collections: small programs published by their authors as reverse engineering exercises. Use ones explicitly offered for practice, run unfamiliar binaries only inside a virtual machine (lesson 15.08), and treat downloaded executables as untrusted.

Common mistakes

Starting with something too big

Each level should take an evening or two. If a target takes weeks, step back a level.

Not checking your answers

The value of self-made targets is the answer key. Use it, and learn from each mistake.

Running downloaded practice binaries on your main machine

Use a virtual machine for anything you did not build yourself.
