Watch, Locals, Memory and Registers Windows

lesson 4.088 of 10 in milestone 47 min

The debugger's windows show a paused program's state at every level, from C++ expressions down to CPU registers and machine instructions. This lesson covers the tricks that make them far more useful: format specifiers, pseudo-variables, viewing arrays through pointers, the Registers and Disassembly windows, and how they connect to everything in chapters 1 to 3.

Locals, Autos and Watch

Window Shows
Locals Every local variable in the current frame
Autos Variables used on the current and previous line, plus the return value of a function you just stepped over
Watch 1-4 Any expressions you type, kept up to date as you step
QuickWatch (Shift+F9) One expression, in a dialog, for a quick look
DataTips Hover over a variable in the editor; pin it to keep it on screen

The Watch window evaluates nearly any C++ expression: player.health * 2, enemies.size(), &grid[3][4], *target, levels[current].name, even function calls (careful: a call runs real code and can change state).

Format specifiers

Add a comma and a specifier after an expression to change how it is shown:

Expression Shows
health,x In hexadecimal
flags,b In binary
ptr,10 or ptr,[10] The 10 elements starting at ptr, as an array
name,s A char* as a string; ,su for a UTF-16 wchar_t*; ,s8 for UTF-8
value,d In decimal
obj,! The raw structure, ignoring any custom visualiser
ptr,na A pointer without the "address and then the value" decoration
hr,hr An HRESULT decoded into its name
err,wm A Windows error code as its message, such as "The system cannot find the file specified."

,10 is the one you will use most: a raw int* scores shows only the first element, and scores,10 shows ten. For a std::vector, the debugger already shows all elements, using a visualiser that understands the type.

Pseudo-variables

The Watch window understands some names that are not in your code:

Name Value
$err The thread's current GetLastError() value. Use $err,hr to see its meaning (chapter 5)
$ReturnValue The value the function you just stepped out of returned
$tid, $pid Current thread and process id
@rsp, @rip, @rax, ... (or $rsp) A CPU register's value

*(int*)(@rsp + 0x28) reads an int at an offset from the stack pointer: useful when reading an optimised function whose locals have no names.

The Memory window, revisited

Lesson 2.11 covered reading bytes. Two more tricks:

  • Drag a variable from the editor or from Locals into the Memory window to jump to its address.
  • Edit in place: click a byte and type new hex digits. The program continues with the change. This is a quick way to test how code reacts to an unusual value without changing the source.

The Registers window

Debug → Windows → Registers (Ctrl+Alt+G) shows the CPU's registers for the current thread at the current instruction:

Output
RAX = 0000000000000041 RBX = 0000000000000000 RCX = 000000F3A1AFF6C8
RDX = 0000000000000032 RSI = 0000000000000000 RDI = 0000000000000000
R8  = 0000000000000000 R9  = 0000000000000000 R10 = 0000000000000000
RIP = 00007FF6E1A2185E RSP = 000000F3A1AFF6A0 RBP = 0000000000000000
EFL = 00000246
  • RIP is the instruction pointer: the address of the next instruction (the program counter from lesson 1.01).
  • RSP is the stack pointer (lesson 1.05).
  • RCX, RDX, R8, R9 hold the first four arguments at the start of a function, and RAX holds a function's return value just after it returns (lesson 2.01).
  • EFL is the flags register; right-click to show individual flags such as ZF (zero) and CF (carry), which chapter 7 explains.

Values that changed in the last step are shown in red, just as in Locals.

The Disassembly window

Debug → Windows → Disassembly (Ctrl+Alt+D), or right-click → Go To Disassembly, shows the machine instructions the compiler produced, interleaved with your source lines:

Output
    player.health -= amount;
00007FF6E1A21859  mov   rax,qword ptr [player]
00007FF6E1A2185E  mov   ecx,dword ptr [rax]
00007FF6E1A21860  sub   ecx,dword ptr [amount]
00007FF6E1A21863  mov   rax,qword ptr [player]
00007FF6E1A21868  mov   dword ptr [rax],ecx

In this window, F10 and F11 step one instruction at a time instead of one line, and the Registers window changes with every step. This is the bridge between C++ and the machine: one line of source became five instructions, each of them a simple step like the tiny computer's. Right-click options let you show code bytes (the actual numbers, as in lesson 1.04), hide source lines, and show symbol names.

Chapter 7 teaches how to read all of this. For now, step through a simple function in the Disassembly window with the Registers window open and watch RIP move along by each instruction's size.

Common mistakes

Watch expressions that call functions

They run real code every time the window updates. A function with side effects changes your program while you look at it.

Reading a raw pointer to an array

scores shows one element. Use scores,10.

[!warning] Trusting $err much later GetLastError is overwritten by later API calls. Check it straight after the call that failed.

  1. How do you see 20 elements of an int* data in the Watch window?
    • Type data,20
    • Type data[20]

    Type data,20 The ,N format specifier shows N elements starting at the pointer.

  2. Which register holds the address of the next instruction to run?
    • RSP
    • RIP
    • RAX
    Show the answer

    RIP RIP is the instruction pointer; RSP is the stack pointer.

  3. You just stepped out of a function. Where can you see what it returned?
    • In $ReturnValue, or the Autos window
    • In RIP
    • Only by adding a print statement
    Show the answer

    In $ReturnValue, or the Autos window The debugger records the return value as you step out or over a call.

  4. What does F10 do while the Disassembly window has focus?

    • Steps one source line
    • Continues to the next breakpoint
    Show the answer

    Steps one machine instruction In the Disassembly window, stepping is per instruction.
