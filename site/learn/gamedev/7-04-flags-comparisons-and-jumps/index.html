Flags, Comparisons and Jumps

lesson 7.044 of 11 in milestone 75 min1 practice task

Every if, loop and switch in C++ becomes a comparison that sets the flags and a conditional jump that reads them. This lesson covers cmp and test, the family of jcc jumps and which ones mean signed or unsigned, and the branch-free alternatives setcc and cmov.

cmp and test

Lesson 7.03 showed that arithmetic sets the flags. Two instructions exist only to set them:

Instruction Computes Keeps Used for
cmp a, b a − b Only the flags; a is unchanged Comparing two values
test a, b a AND b Only the flags Checking for zero (test eax, eax) or particular bits

test eax, eax is the idiom for "is eax zero?": ANDing a value with itself gives the value, so ZF is set exactly when it is zero, and SF when it is negative.

Conditional jumps

A conditional jump goes to a label if a condition on the flags holds, and otherwise falls through to the next instruction. The condition names come in signed and unsigned versions, because "less than" means different things for signed and unsigned numbers (lesson 1.02):

After cmp a, b, jump if... Signed Unsigned Flags tested
a == b je / jz je / jz ZF = 1
a != b jne / jnz jne / jnz ZF = 0
a < b jl jb ("below") SF ≠ OF / CF = 1
a <= b jle jbe ZF = 1 or SF ≠ OF / CF = 1 or ZF = 1
a > b jg ja ("above") ZF = 0 and SF = OF / CF = 0 and ZF = 0
a >= b jge jae SF = OF / CF = 0
always jmp jmp none

So the jump tells you the type: jl/jg after a cmp means the compiler treated the values as signed; jb/ja means unsigned (or pointers, or sizes). When reverse engineering, that is often your first clue to a variable's type.

An if, compiled

C++
int clampHealth(int h)
{
    if (h > 100) h = 100;
    return h;
}
Assembly
clampHealth PROC
    cmp   ecx, 100        ; compare h with 100
    jle   keep            ; if h <= 100, skip the assignment
    mov   ecx, 100
keep:
    mov   eax, ecx        ; return h
    ret
clampHealth ENDP

Notice the inverted condition: C++ says "if h > 100, do this", and the compiler writes "if h <= 100, jump over this". That inversion is so common that reading compiled code, you learn to flip conditions automatically.

Branch-free versions: setcc and cmov

A jump that the processor cannot predict is expensive: modern CPUs guess which way each branch goes and start working ahead, and a wrong guess throws that work away (10 to 20 cycles). For simple choices, compilers often avoid the jump entirely:

Instruction Effect
setl al (and sete, setg, setb ...) al = 1 if the condition holds, else 0: a bool result
cmovg eax, edx (and every other condition) eax = edx if the condition holds; otherwise eax is unchanged
Assembly
; return a > b;            ; return a > b ? a : b;   (std::max)
cmp   ecx, edx             mov   eax, edx
setg  al                   cmp   ecx, edx
ret                        cmovg eax, ecx
                           ret

Common mistakes

Reading the jump as the C++ condition

Compilers usually jump around the body, so the jump's condition is the opposite of the if.

[!warning] Mixing up jl and jb jl is signed less-than, jb unsigned. For -1 against 1, jl jumps (−1 < 1) and jb does not (0xFFFFFFFF is above 1).

Forgetting what set the flags

A conditional jump uses whatever instruction last set the flags, which is not always the line right above it.

Knowledge check

quizIn Xenon your best score is kept.
  1. What does test eax, eax followed by jz done do?
    • Jumps to done if eax is zero
    • Jumps if eax is not zero
    • Compares eax with zero and stores the result
    Show the answer

    Jumps to done if eax is zero AND of a value with itself is zero only when the value is zero, setting ZF.

  2. After cmp ecx, edx, the compiler uses ja. What does that suggest about ecx and edx?
    • They are being compared as unsigned values
    • They are being compared as signed values
    • They are floats
    Show the answer

    They are being compared as unsigned values ja/jb are the unsigned conditions; jg/jl the signed ones.

  3. The C++ says if (x == 0) { ... }. Which jump is the compiler most likely to emit before the body?
    • jne, to skip the body when x is not zero
    • je
    • jmp
    Show the answer

    jne, to skip the body when x is not zero The jump goes around the body, so its condition is inverted.

  4. Why do compilers sometimes use cmov instead of a jump?
    • To avoid the cost of a branch the processor might predict wrongly
    • Because cmov is shorter than mov
    • Because jumps cannot be conditional
    Show the answer

    To avoid the cost of a branch the processor might predict wrongly A mispredicted branch costs many cycles; a conditional move never mispredicts.
