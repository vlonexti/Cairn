Installing the Windows Driver Kit

lesson 16.011 of 10 in milestone 165 min

Drivers are built with the Windows Driver Kit (WDK), an extension to Visual Studio that adds kernel headers and libraries, driver project templates, signing, deployment and analysis tools. This lesson installs matching versions of Visual Studio, the SDK and the WDK on the host, creates the chapter's driver project, and explains what is different about building kernel code.

What the WDK adds

Part What it is for
Kernel headers (ntddk.h, wdm.h, wdf.h) Declarations of kernel functions and structures
Kernel libraries ntoskrnl.lib, hal.lib, the KMDF libraries
Project templates Empty WDM driver, KMDF driver, UMDF driver, and more
Build settings The kernel environment: no C runtime, /kernel mode, special linker options
Signing Test-signs the driver automatically on build (lesson 16.09)
Tools Debugging tools (WinDbg, kdnet), Driver Verifier helpers, static analysis (Code Analysis for drivers), InfVerif for installation files

Installing

The WDK must match your Visual Studio and Windows SDK versions exactly. Microsoft's "Download the Windows Driver Kit" page lists the current combination; follow its steps in order:

  1. Visual Studio 2022 with the Desktop development with C++ workload (lesson 1.07). In Individual components, add the MSVC Spectre-mitigated libraries for x64 (driver projects require them) and the Windows SDK version the WDK page names.
  2. The Windows SDK of the matching version, if not installed by step 1.
  3. The WDK installer of the same version. At its end, let it install the Windows Driver Kit Visual Studio extension.

Everything is installed on the host. The VM (lesson 15.08) only runs the result.

The chapter's project

In Visual Studio: File → New → Project, search for Kernel Mode Driver, Empty (KMDF) or Empty WDM Driver, and name it XenonEcho. This chapter uses a minimal WDM-style software driver first (lessons 16.02 to 16.07), because seeing the IRPs directly makes the I/O model of lesson 15.05 concrete; lesson 16.10 notes what KMDF would take care of for you.

Project settings to check (Configuration All, Platform x64):

Setting Value Why
Driver Settings → Target OS Version Windows 10 or later The oldest Windows the driver supports
C/C++ → Warning level Level 4, warnings as errors Kernel code deserves every warning
Driver Signing → Sign Mode Test Sign Signs the .sys with a test certificate on build (lesson 16.09)
Inf2Cat / Stampinf Off for a software-only driver loaded with sc No installation package needed for this chapter's driver

Add a second project to the solution, an ordinary Console App called EchoClient, for the user-mode program that talks to the driver (lesson 16.06).

What is different about kernel builds

  • No C runtime and no C++ standard library. There is no printf, std::vector or new by default. Kernel code uses kernel functions: ExAllocatePool2 for memory (lesson 15.04), RtlCopyMemory, RtlStringCbPrintfA, KdPrint for debug output.
  • C++ is allowed, carefully. Classes, templates, RAII and constexpr work. Exceptions and RTTI are off; global objects with constructors are not supported without extra work; anything that allocates must use the pools.
  • Stack is small: 12 KB to 24 KB on x64 kernel threads, versus 1 MB in user mode (lesson 2.01). Large locals and deep recursion are not acceptable.
  • Every function's IRQL matters (lesson 15.06): document and assert it.
  • Static analysis is part of the build: run Analyze → Run Code Analysis with the driver rules; it understands IRQL annotations and catches real bugs.

The output of a build is XenonEcho.sys (a PE file like a DLL, lesson 9.02), its .pdb, and with test signing a test certificate (.cer).

Common mistakes

Mismatched Visual Studio, SDK and WDK versions

Install the exact combination Microsoft's download page lists.

Missing Spectre-mitigated libraries

Driver builds fail with an error naming them; add them in the Visual Studio installer.

Reaching for the standard library

It is not available in the kernel. Use the kernel's functions.
