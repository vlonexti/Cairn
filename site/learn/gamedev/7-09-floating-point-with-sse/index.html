Floating Point with SSE

lesson 7.099 of 11 in milestone 75 min

x64 code does floating-point maths in the 16 xmm registers with SSE instructions. Scalar instructions like addss work on one float; packed ones like addps work on four at once, the start of SIMD. This lesson reads typical game maths in assembly: loading constants, arithmetic, comparisons, conversions between ints and floats, and a first look at vectorised code.

The xmm registers

Each xmm0 to xmm15 register is 128 bits wide: room for four floats or two doubles. (Newer processors extend them to 256-bit ymm and 512-bit zmm registers with AVX; the ideas are the same.)

For ordinary scalar maths the compiler uses only the lowest lane:

Output
xmm0:  [ float 3 | float 2 | float 1 | float 0 ]     <- scalar code uses lane 0 only
        127                               31   0

Instruction names end in a suffix saying what they work on:

Suffix Means Example
ss Scalar Single: one float addss xmm0, xmm1
sd Scalar Double: one double mulsd xmm0, xmm2
ps Packed Single: four floats addps xmm0, xmm1
pd Packed Double: two doubles subpd xmm3, xmm4

Everyday float code

C++
float speedAfterFriction(float speed, float friction, float dt)
{
    return speed * (1.0f - friction * dt);
}
Assembly
speedAfterFriction PROC
    mulss  xmm1, xmm2                          ; friction * dt
    movss  xmm3, dword ptr [__real@3f800000]   ; load the constant 1.0f
    subss  xmm3, xmm1                          ; 1.0f - friction*dt
    mulss  xmm0, xmm3                          ; speed * (...)
    ret                                        ; result in xmm0
speedAfterFriction ENDP
  • Arguments arrive in xmm0, xmm1, xmm2 by position (lesson 7.06); the result leaves in xmm0.
  • There are no float immediates: constants live in read-only data and are loaded from memory. MSVC names them after their bits, so __real@3f800000 is 1.0f (lesson 2.11's table). Reading those names tells you the constants directly.
  • movss loads and stores one float; movaps/movups move all 128 bits (aligned or unaligned).

Conversions and comparisons

Instruction Does C++
cvtsi2ss xmm0, eax int to float static_cast<float>(i)
cvttss2si eax, xmm0 float to int, truncating towards zero static_cast<int>(f)
cvtss2sd xmm0, xmm0 float to double passing a float to printf
comiss xmm0, xmm1 / ucomiss compare, setting ZF, CF (and PF) a < b
sqrtss, minss, maxss square root, minimum, maximum std::sqrt, std::min
xorps xmm0, xmm0 zero the register 0.0f

Float comparisons set the flags like an unsigned integer compare, so they are followed by ja, jb, jae, jbe, not jg/jl. Comparisons involving NaN ("not a number") are "unordered" and set the parity flag, which is why you sometimes see an extra jp after them.

SIMD: four at once

The packed instructions do the same operation on every lane in one go. Adding two arrays of floats four elements per instruction is up to four times the work per instruction:

Assembly
top:
    movups xmm0, [rcx+rax]       ; load 4 floats from a
    movups xmm1, [rdx+rax]       ; load 4 floats from b
    addps  xmm0, xmm1            ; 4 additions in one instruction
    movups [r8+rax], xmm0        ; store 4 results
    add    rax, 16               ; advance by 4 floats
    cmp    rax, r9
    jb     top

Optimising compilers produce loops like this automatically from plain C++ (auto-vectorisation) when the loop is simple enough: no dependencies between iterations, no function calls in the body, data laid out contiguously. That last condition is a big part of why engines store data as structures of arrays (all x values together, all y values together) rather than arrays of structures for the hottest loops. You can also write SIMD by hand with intrinsics (_mm_add_ps and friends from <immintrin.h>), which map one-to-one onto these instructions.

Precision and determinism

float has about 7 significant decimal digits; double about 16. Results can differ with optimisation settings (the compiler may reorder a + b + c only under /fp:fast, which is not the default) and between processors for some library functions. For lockstep multiplayer games and replays, which need bit-identical results everywhere, programs keep the default /fp:precise, avoid /fp:fast, and sometimes use fixed-point integers for game logic instead.

Common mistakes

Expecting float arguments in rcx/rdx

Floating-point arguments use the xmm register of their position.

[!warning] Reading a float comparison's ja as unsigned integers After comiss, ja/jb are simply "greater"/"less" for floats.

Converting with truncation when rounding was meant

static_cast<int>(2.9f) is 2. Use std::lround to round.
