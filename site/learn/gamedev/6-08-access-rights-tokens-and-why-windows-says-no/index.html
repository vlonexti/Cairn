Access Rights, Tokens and Why Windows Says No

lesson 6.088 of 9 in milestone 66 min1 practice task

"Access is denied" (error 5) is Windows checking rights. Every process carries a token saying who it runs as; every securable object has a security descriptor saying who may do what; and every handle is opened for specific access rights. This lesson explains the check, integrity levels and UAC, protected processes, and the principle of asking for no more than you need.

The check behind every handle

When a program opens an object (a file, a process, a registry key, an event), it asks for specific rights, and Windows decides there and then:

    T["Your process's token<br/>user, groups, privileges,<br/>integrity level"] --> C{"Access check"}
    D["The object's security descriptor<br/>owner, list of who may do what"] --> C
    R["Rights you asked for<br/>e.g. GENERIC_READ"] --> C
    C -->|"allowed"| H["A handle with exactly those rights"]
    C -->|"denied"| E["ERROR_ACCESS_DENIED (5)"]
  • The token is attached to every process when it starts, inherited from the user who logged in. It lists the user, their groups (Administrators, Users...), their privileges, and an integrity level.
  • The security descriptor of an object holds an access control list (ACL): entries such as "Users: read", "Administrators: full control".
  • The access mask is the set of rights requested, as bits: for a file FILE_READ_DATA, FILE_WRITE_DATA, DELETE...; for a process PROCESS_QUERY_LIMITED_INFORMATION, PROCESS_TERMINATE, PROCESS_VM_READ...

The check happens once, when the handle is opened. The handle then carries the granted rights, and every later use is checked against them only: a file handle opened for reading cannot be used to write, whatever the user's rights.

Ask for what you need

The most common cause of error 5 in a program's own code is asking for more than it needs: GENERIC_ALL, PROCESS_ALL_ACCESS, KEY_ALL_ACCESS. A normal user may be allowed to read a file but not change it, and a request for all access then fails, though a request for read access would have succeeded. The fix is also the security principle of least privilege: request exactly the rights the code uses.

C++
// Fails for files the user may only read:
HANDLE f{ CreateFileW(path, GENERIC_READ | GENERIC_WRITE, ...) };
// Succeeds, and documents what the code does:
HANDLE f{ CreateFileW(path, GENERIC_READ, FILE_SHARE_READ, ...) };

Integrity levels and UAC

Each token and each object also has an integrity level: Low, Medium, High or System. A process cannot write to objects at a higher integrity level than its own, whatever the ACL says.

Level Typical processes
Low Sandboxed browser tabs
Medium Everything a user normally runs, including games
High Programs run "as administrator"
System Windows services

With User Account Control (UAC), even an administrator's programs normally run at Medium, with the administrator group switched off in their token. "Run as administrator" (and the consent prompt) starts a process with the elevated High-integrity token. This is why a game should never need elevation: it runs at Medium, writes to the user's folders (lesson 5.04), and can be compromised without giving the attacker the whole machine.

Protected processes

Some processes are protected (Protected Process Light, PPL): Windows' own security components, antivirus engines, and some anti-cheat services. Even an administrator cannot open them for anything beyond limited query rights, cannot read their memory, inject code into them or debug them; only code signed with specific certificates may run inside them. This is a deliberate wall: it keeps malware from tampering with security software, and it is enforced by the kernel itself.

The practical lesson for tool builders: when Windows refuses access to something, that is usually the system working as designed. The tools in this course work on processes you start yourself, at the same integrity level, where the rights are yours.

Privileges

Separate from object rights, a token holds privileges: system-wide abilities such as SeShutdownPrivilege (shut down the machine), SeLoadDriverPrivilege (load kernel drivers) and SeDebugPrivilege (open any non-protected process regardless of its security descriptor). Administrators' elevated tokens contain several privileges, disabled until a program explicitly enables them with AdjustTokenPrivileges. Normal programs never need them; development tools like debuggers do, which is why Visual Studio asks to restart elevated when you try to attach to a process running as administrator.

Common mistakes

Asking for all access

Request the specific rights the code uses. It succeeds more often and limits damage if the program is compromised.

"It works as administrator, so let's always run elevated"

Find which right is missing instead. Games and tools should run as a normal user.

Assuming error 5 means a bug in the parameters

It is a security decision. Check which rights you requested, the object's ACL, and the integrity levels.
