Programs, Processes and Modules

lesson 6.011 of 9 in milestone 65 min1 practice task

A program is a file; a process is a running instance of one, with its own address space, threads and handles; a module is an executable or DLL loaded into a process. This lesson makes the distinction concrete by starting a child process, waiting for it, reading its exit code, and passing it a command line.

Three words, three things

Is Example
Program A file on disk C:\Games\Dungeon\dungeon.exe
Process A running instance: an address space, one or more threads, a handle table, a security token Two copies of dungeon.exe running are two processes
Module An .exe or .dll mapped into a process dungeon.exe, kernel32.dll, plugin.dll inside one process

A process does not run code by itself. Threads run code; the process is the container that gives them memory and resources. Every process starts with one thread and may create more (lesson 6.05). When the last thread ends, or any thread calls ExitProcess, the process ends and Windows frees everything it held.

Starting another program

Games start other processes more often than you might think: a crash reporter, a launcher starting the game, an updater, a level editor launching the game to test a level. The function is CreateProcessW:

C++
#include <windows.h>
#include <iostream>
#include <string>

int main()
{
    std::wstring commandLine{ L"cmd.exe /c exit 7" };      // must be writable: CreateProcessW may modify it

    STARTUPINFOW startup{};
    startup.cb = sizeof(startup);
    PROCESS_INFORMATION info{};

    if (!CreateProcessW(nullptr, commandLine.data(), nullptr, nullptr, FALSE, CREATE_NO_WINDOW,
                        nullptr, nullptr, &startup, &info))
    {
        std::cout << "CreateProcessW failed: " << GetLastError() << '\n';
        return 1;
    }

    WaitForSingleObject(info.hProcess, INFINITE);            // a process handle is signalled when it ends
    DWORD exitCode{ 0 };
    GetExitCodeProcess(info.hProcess, &exitCode);
    std::cout << "the child exited with code " << exitCode << '\n';

    CloseHandle(info.hThread);                                // CreateProcessW gives you two handles:
    CloseHandle(info.hProcess);                               // close both
    return 0;
}
Output
the child exited with code 7

The pieces:

  • The command line is one string, not an array: the program name followed by its arguments. The new process splits it into argv itself. Arguments containing spaces must be quoted: L"\"C:\\My Games\\editor.exe\" --level \"forest 2\"".
  • PROCESS_INFORMATION returns a handle to the new process, a handle to its first thread, and both ids. You own both handles and must close them, even if you do not need them.
  • Waiting. A process handle is a kernel object that becomes signalled when the process ends, so WaitForSingleObject waits for it. The exit code is whatever the child returned from main or passed to ExitProcess.

Exit code 0 conventionally means success; anything else is an error number the program chose. Windows itself uses some large values: 0xC0000005 (3221225477) means the child crashed with an access violation.

Process ids and handles

A process has a process id (PID), a number unique among running processes, shown in Task Manager. A PID is not a handle: to do anything with a process you hold only the id of, you must open a handle to it with OpenProcess, asking for specific access rights, which Windows may refuse (lesson 6.08).

C++
#include <windows.h>
#include <iostream>

int main()
{
    const DWORD myId{ GetCurrentProcessId() };
    HANDLE me{ OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION, FALSE, myId) };
    wchar_t path[MAX_PATH]{};
    DWORD size{ MAX_PATH };
    const bool ok{ me && QueryFullProcessImageNameW(me, 0, path, &size) };
    std::cout << "opened myself and read my image name: " << (ok ? "yes" : "no") << '\n';
    if (me) CloseHandle(me);
    return 0;
}
Output
opened myself and read my image name: yes

GetCurrentProcess() returns a pseudo-handle, the special value -1, meaning "the current process", which never needs closing.

Modules inside a process

Every process has at least one module, its .exe, and nearly always dozens of DLLs. Each module occupies its own range of the address space, starting at its HMODULE (lesson 5.08). Visual Studio's Modules window lists them while debugging; lesson 6.07 lists them from code.

Common mistakes

Passing a string literal as the command line

CreateProcessW may write into the buffer, so a literal crashes. Use a std::wstring or a wchar_t array.

[!warning] Forgetting info.hThread Two handles come back, and both leak if not closed.

Unquoted paths with spaces

C:\My Games\editor.exe is read as the program C:\My with arguments. Quote the program name and any argument containing spaces.

Confusing a PID with a handle

A PID identifies a process; to act on it you need a handle from OpenProcess.

  3. A child process's exit code is 3221225477 (0xC0000005). What happened?
    • It crashed with an access violation
    • It succeeded
    • It was closed by the user
    Show the answer

    It crashed with an access violation 0xC0000005 is the status code for an access violation.

  4. What is the difference between a process id and a process handle?

    • They are the same number
    • Handles are only for threads
    Show the answer

    The id names the process system-wide; a handle is a per-process reference with specific rights, obtained from OpenProcess or CreateProcessW Windows checks rights when the handle is opened.
