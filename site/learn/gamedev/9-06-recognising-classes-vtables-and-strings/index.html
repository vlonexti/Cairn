Recognising Classes, Vtables and Strings

lesson 9.066 of 10 in milestone 95 min1 practice task

C++ programs leave distinctive traces even without symbols: vtables in read-only data list each polymorphic class's virtual functions, RTTI records often hold class names outright, constructors write vptrs, and strings reveal messages, file names and formats. This lesson shows how to find and use each, and how a strings-style scan works.

Vtables

Lesson 3.05 showed that each class with virtual functions has a vtable, an array of function pointers, in .rdata, and each object stores a pointer to it at offset 0. In a stripped program, vtables are among the most useful structures you can find:

  • Each vtable is a list of one class's virtual functions, in declaration order.
  • Classes related by inheritance have vtables with the same layout: slot 3 is the same virtual function (overridden or not) in every one.
  • A vtable entry pointing at the same function as the base class's entry means that function was not overridden.

How to find them: in Ghidra, look in .rdata for runs of 8-byte values that are all addresses of functions in .text. Ghidra's analysis usually labels them vftable when RTTI is present.

Constructors and destructors

A constructor can be recognised by what it does with the vptr:

Assembly
Goblin_ctor:
    mov   [rsp+8], rcx
    sub   rsp, 28h
    call  Entity_ctor                        ; base class constructor first
    lea   rax, [Goblin_vftable]              ; then store this class's vtable...
    mov   rcx, [rsp+30h]
    mov   [rcx], rax                         ; ...into offset 0 of the object
    mov   dword ptr [rcx+18h], 10            ; initialise members
    ...

The pattern "call another constructor, then store a vtable address into [this], then initialise members" identifies a constructor, its base class's constructor, and its vtable all at once. Destructors do the reverse: store their own vtable, destroy members, then call the base destructor. Every place a vtable's address is written is a constructor or destructor of that class.

RTTI: class names for free

Unless a program is compiled with /GR-, MSVC stores run-time type information for each polymorphic class, used by dynamic_cast and typeid. Just before each vtable sits a pointer to a "complete object locator", which leads to a type descriptor containing the class's decorated name as a string:

Output
.?AVGoblin@@
.?AVEntity@@
.?AV?$vector@HV?$allocator@H@std@@@std@@

.?AV means "a class", and the rest is the class name in MSVC's name-mangling format (lesson 4.02); undname or Ghidra demangles them. A class hierarchy descriptor also lists each class's base classes, so RTTI can recover the whole inheritance tree. Searching a stripped program's strings for .?AV often lists every polymorphic class it has.

Strings

Programs are full of text: messages, log lines, file names, registry keys, format strings, URLs, error descriptions, command names. They survive compilation unchanged (lesson 2.03's .rdata), and each one is a label for the code that uses it:

String found Suggests
"Failed to open save file %s" The function using it loads saves; the %s argument is the path
"config.ini", "Settings" Configuration loading
"Assertion failed: %s, file %s, line %d" The program's assert handler (lesson 8.03)
"kernel32.dll", "VirtualAlloc" A function loaded at run time with GetProcAddress (lesson 9.03)
"%d/%d", "HP" Interface drawing

Remember both encodings (lesson 2.08): Windows programs often store UTF-16 strings, which look like H.P. with zero bytes between the letters in a byte view. Tools search for both. The classic tool is strings (in Microsoft's Sysinternals suite): it scans any file for runs of printable characters of at least some minimum length. The practice task writes one.

Common mistakes

Assuming RTTI is always there

Programs built with /GR- have none; vtables still exist but are unnamed.

[!warning] Treating every run of addresses in .rdata as a vtable Jump tables and other pointer arrays look similar. A vtable is referenced by constructors that store it into objects.

Searching only for ASCII strings

Windows programs use UTF-16 heavily. Search both forms.
