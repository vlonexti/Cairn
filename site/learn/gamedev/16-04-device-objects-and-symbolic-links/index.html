Device Objects and Symbolic Links

lesson 16.044 of 10 in milestone 165 min1 practice task

For a user program to talk to a driver, the driver needs a device object to receive requests and a symbolic link that gives it a name user mode can open. This lesson creates both in DriverEntry, removes them in unload, controls who may open the device with a security descriptor, and adds the create and close dispatch routines that make opening and closing work.

The device object

C++
UNICODE_STRING kDeviceName = RTL_CONSTANT_STRING(L"\\Device\\XenonEcho");
UNICODE_STRING kLinkName   = RTL_CONSTANT_STRING(L"\\??\\XenonEcho");

PDEVICE_OBJECT device{ nullptr };
NTSTATUS status{ IoCreateDevice(
    driver,                       // the owning driver
    sizeof(EchoState),            // extra bytes for the driver's per-device state (the device extension)
    &kDeviceName,                 // its name in the object namespace
    FILE_DEVICE_UNKNOWN,          // device type: also used in the IOCTL codes (lesson 16.05)
    FILE_DEVICE_SECURE_OPEN,      // apply the device's security to every open, including of sub-paths
    FALSE,                        // not exclusive: several handles may be open at once
    &device) };
  • The device appears as \Device\XenonEcho in the object namespace (lesson 15.03), visible in WinObj.
  • The device extension is a block of non-paged memory attached to the device, sized by the second argument, where the driver keeps its state (static_cast<EchoState*>(device->DeviceExtension)). Keeping state there instead of in globals keeps the driver ready for more than one device.
  • UNICODE_STRING is the kernel's string type: a length in bytes, a maximum length, and a pointer to UTF-16 characters that are not necessarily zero-terminated. Always use the length.

The symbolic link

Device names under \Device are not reachable from the Win32 API directly. A symbolic link in the \?? directory (lesson 15.03) gives the device a DOS device name:

C++
status = IoCreateSymbolicLink(&kLinkName, &kDeviceName);

From user mode, the device is then opened as \\.\XenonEcho (lesson 16.06). In unload, the link is deleted (IoDeleteSymbolicLink) before the device (IoDeleteDevice), the reverse of creation (lesson 16.03).

Create and close

Opening the device sends an IRP_MJ_CREATE to the driver, and closing the last handle sends IRP_MJ_CLOSE (after IRP_MJ_CLEANUP). A driver that does not handle them gets the default, which fails the request, so even a minimal driver handles them:

C++
NTSTATUS EchoCreateClose(PDEVICE_OBJECT, PIRP irp)
{
    irp->IoStatus.Status = STATUS_SUCCESS;
    irp->IoStatus.Information = 0;
    IoCompleteRequest(irp, IO_NO_INCREMENT);
    return STATUS_SUCCESS;
}

// in DriverEntry:
driver->MajorFunction[IRP_MJ_CREATE] = EchoCreateClose;
driver->MajorFunction[IRP_MJ_CLOSE]  = EchoCreateClose;

Every dispatch routine follows this shape: fill in IoStatus (the status, and in Information how many bytes were transferred), complete the IRP exactly once (lesson 15.05), and return the same status.

Who may open it

By default a device created with IoCreateDevice gets the security of its device type, which for many types lets any user open it. That is rarely what a driver wants: every request a user can send is code the kernel will run on their behalf. Choose deliberately:

  • IoCreateDeviceSecure (from wdmsec.h) takes an SDDL string describing the security descriptor. For example SDDL_DEVOBJ_SYS_ALL_ADM_ALL allows only SYSTEM and administrators; a custom string can add specific users or groups.
  • Each IOCTL can also require read or write access to the handle (lesson 16.05), so a user with read access cannot perform write operations.

For the lab's echo driver, administrators only is the right default.

Common mistakes

[!warning] Treating UNICODE_STRING as zero-terminated Always use its Length (in bytes).

Deleting the device before the link

Delete in reverse order of creation.

Leaving the device open to every user

Use IoCreateDeviceSecure with an SDDL string that allows only who needs access.

Not handling create and close

Opening the device then fails with "invalid device request".
