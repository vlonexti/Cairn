Structs, Arrays and Pointers in Assembly

lesson 7.088 of 11 in milestone 75 min1 practice task

In assembly there are no types, only addresses and sizes. A struct member is a fixed offset from a pointer; an array element is base plus index times size; a pointer chain is a series of loads. This lesson shows how each C++ data access compiles, and how to work backwards from the offsets and sizes in disassembly to the data structures behind them.

Members are offsets

C++
struct Monster
{
    int id;          // +0
    float x, y;      // +4, +8
    int health;      // +12
    Monster* target; // +16
};

void hurt(Monster* m, int amount)
{
    m->health -= amount;
    if (m->health <= 0) m->target = nullptr;
}
Assembly
hurt PROC
    sub   dword ptr [rcx+0Ch], edx      ; m->health -= amount     (offset 12, 4 bytes)
    jg    alive
    mov   qword ptr [rcx+10h], 0        ; m->target = nullptr     (offset 16, 8 bytes)
alive:
    ret
hurt ENDP

Every member access is [pointer + offset] with a size. Reading this cold, with no source, you could still say: the first argument points at a structure; at offset 0xC there is a 4-byte integer that is compared with zero; at offset 0x10 an 8-byte value that is set to zero, probably a pointer. That is how chapter 9 rebuilds unknown structs.

sub also set the flags, so the compiler used them directly for the <= 0 test with jg: no separate cmp. Optimisers do this whenever they can.

Arrays of structs

An element of an array of structs is base + index × sizeof(struct) + member offset. When the size is 1, 2, 4 or 8 the scale does it; otherwise the index is multiplied first:

C++
struct Particle { float x, y, vx, vy, life; };    // 20 bytes

float lifeOf(const Particle* particles, int i) { return particles[i].life; }
Assembly
    movsxd rax, edx                        ; i, widened to 64 bits
    lea    rax, [rax+rax*4]                ; i * 5
    movss  xmm0, dword ptr [rcx+rax*4+10h] ; particles + i*20 + 16: the life member
    ret

i * 5 * 4 = i * 20 (the struct size) plus 0x10 (the offset of life). When you see an index multiplied by an odd constant, divide to get the element size.

Pointer chains

world->player->inventory->gold (lesson 3.02) is one load per arrow:

Assembly
mov   rax, qword ptr [rcx+18h]    ; world->player       (player is at offset 0x18 in World)
mov   rax, qword ptr [rax+40h]    ; ->inventory         (inventory at 0x40 in Player)
mov   eax, dword ptr [rax+8]      ; ->gold              (gold at 8 in Inventory)

Each qword load produces the address for the next. A run of dependent 8-byte loads like this is a pointer chain, and its offsets are the layouts of each struct in turn.

Objects with virtual functions

A virtual call (lesson 3.05) has its own fingerprint:

Assembly
mov   rax, qword ptr [rcx]         ; load the vptr from offset 0
call  qword ptr [rax+18h]          ; call slot 3 of the vtable (0x18 / 8)

A load from offset 0 of an object followed by an indirect call through that value plus an offset: a virtual call. The offset divided by 8 is the slot number.

Working backwards: a reading table

You see Probably
dword ptr [rcx+N] A 4-byte member (int, float, enum) at offset N of the struct rcx points to
qword ptr [rcx+N] then used as an address A pointer member at offset N
movss / movsd with a memory operand A float / double member
movzx eax, byte ptr [rcx+N], then test al, al A bool member
[rcx+rdx*4], [rcx+rdx*8] An array of 4- or 8-byte elements
imul rdx, rdx, 38h then [rcx+rdx] An array of 56-byte structs
mov rax, [rcx] then call [rax+N] A virtual call, slot N/8
lea rcx, [rdi+20h] then call Passing the address of a member (or base subobject) at offset 0x20

Common mistakes

Assuming the same register means the same object

Registers are reused constantly. Track what each one holds at each point.

Forgetting padding when guessing a layout

A 4-byte member at offset 0 followed by an 8-byte one at offset 8 means padding at 4 to 7, not a hidden member (lesson 2.05).

[!warning] Reading lea as a load lea rcx, [rdi+20h] takes an address; it does not read the member.

Knowledge check

quizIn Xenon your best score is kept.
  1. mov eax, dword ptr [rcx+0Ch] with rcx holding a struct pointer. What is being read?
    • A 4-byte member at offset 12
    • The 12th element of an array
    • A pointer at offset 12
    Show the answer

    A 4-byte member at offset 12 dword ptr is 4 bytes; +0Ch is the member's offset.

  2. Code computes lea rax, [rax+rax*2] and then reads [rcx+rax*8]. What is the element size?
    • 24 bytes
    • 8 bytes
    • 3 bytes
    Show the answer

    24 bytes The index is multiplied by 3, then scaled by 8.

  3. What does mov rax, [rcx] followed by call qword ptr [rax+10h] indicate?
    • A virtual call to slot 2 of the object's vtable
    • A call to a function at address rcx + 16
    • Reading an array
    Show the answer

    A virtual call to slot 2 of the object's vtable The first load fetches the vptr; 0x10 / 8 = slot 2.
