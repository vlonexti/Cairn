A User-Mode Client

lesson 16.066 of 10 in milestone 165 min1 practice task

The other half of the driver is an ordinary program: it opens the device by its symbolic link with CreateFileW, sends commands with DeviceIoControl, and reports errors clearly. This lesson writes the echo driver's client using chapter 5's handles and errors, wraps the protocol in a small class, and covers the details that trip people up: buffer sizes, ERROR_MORE_DATA, and the driver not being loaded.

Opening the device

C++
#include <windows.h>
#include <cstdio>
#include "echo_ioctl.h"          // shared with the driver (lesson 16.05)

UniqueHandle openEcho()          // lesson 5.01's RAII handle
{
    HANDLE h{ CreateFileW(L"\\\\.\\XenonEcho",          // the symbolic link, as \\.\XenonEcho
                          GENERIC_READ | GENERIC_WRITE,  // the access our IOCTLs require (lesson 16.05)
                          0, nullptr, OPEN_EXISTING, 0, nullptr) };
    return UniqueHandle{ h };    // treats INVALID_HANDLE_VALUE as empty
}

If the driver is not loaded, CreateFileW fails with error 2 (ERROR_FILE_NOT_FOUND: there is no such name); if the device's security does not allow this user, error 5 (ERROR_ACCESS_DENIED, lesson 16.04). A good client reports these in plain words: "The XenonEcho driver is not loaded: run sc start XenonEcho in the lab VM."

Sending a command

C++
bool ping(HANDLE device)
{
    DWORD returned{ 0 };
    return DeviceIoControl(device, IOCTL_ECHO_PING, nullptr, 0, nullptr, 0, &returned, nullptr) != FALSE;
}

std::optional<EchoStats> stats(HANDLE device)
{
    EchoStats s{};
    DWORD returned{ 0 };
    if (!DeviceIoControl(device, IOCTL_ECHO_STATS, nullptr, 0, &s, sizeof(s), &returned, nullptr)) return std::nullopt;
    if (returned != sizeof(s)) return std::nullopt;           // never trust the length blindly, even from our own driver
    return s;
}

DeviceIoControl takes the control code, an input buffer and its size, an output buffer and its size, and returns how many bytes the driver put in the output (the IRP's Information, lesson 16.05). The driver's NTSTATUS becomes a Win32 error for GetLastError (lesson 5.02): STATUS_BUFFER_TOO_SMALL arrives as ERROR_INSUFFICIENT_BUFFER, STATUS_INVALID_DEVICE_REQUEST as ERROR_INVALID_FUNCTION.

Echo, with a variable size

C++
std::optional<std::string> echo(HANDLE device, const std::string& text)
{
    std::string reply(text.size(), '\0');
    DWORD returned{ 0 };
    if (!DeviceIoControl(device, IOCTL_ECHO_ECHO,
                         const_cast<char*>(text.data()), static_cast<DWORD>(text.size()),
                         reply.data(), static_cast<DWORD>(reply.size()), &returned, nullptr))
        return std::nullopt;
    reply.resize(returned);
    return reply;
}

The protocol is the client and driver's shared contract, exactly like lesson 13.03's plugin API: a shared header, explicit sizes, versions if it will change (lesson 12.06), and validation on both sides. The practice task builds a versioned message format for requests and replies with careful parsing.

A small client program

C++
int wmain()
{
    UniqueHandle device{ openEcho() };
    if (!device)
    {
        const DWORD error{ GetLastError() };
        if (error == ERROR_FILE_NOT_FOUND) std::wprintf(L"XenonEcho is not loaded (sc start XenonEcho, in the lab VM)\n");
        else std::wprintf(L"could not open XenonEcho: error %lu\n", error);
        return 1;
    }
    std::wprintf(L"ping: %s\n", ping(device.get()) ? L"ok" : L"failed");
    if (auto reply{ echo(device.get(), "hello, kernel") }) std::printf("echo: %s\n", reply->c_str());
    if (auto s{ stats(device.get()) }) std::printf("requests %llu, bytes echoed %llu\n", s->requests, s->bytesEchoed);
    return 0;
}

Run it in the VM with the driver loaded, under the kernel debugger with a breakpoint in EchoDeviceControl, and you can follow one request from DeviceIoControl in user mode, through the system call (lesson 15.02), to your dispatch routine and back.

Common mistakes

Opening the device with less access than the IOCTL requires

The request fails with access denied before reaching the driver.

Ignoring the returned byte count

Use it to size the result, and check it is what you expected.

Cryptic errors

Translate the common cases (not loaded, access denied) into instructions the user can follow.
