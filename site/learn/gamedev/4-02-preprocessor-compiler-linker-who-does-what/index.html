Preprocessor, Compiler, Linker: Who Does What

lesson 4.022 of 10 in milestone 47 min1 practice task

Lesson 1.04 introduced the four build stages. This lesson goes deeper into the rules that decide which file needs what: declarations versus definitions, headers and include guards, the one definition rule, inline and static, and how the linker matches symbols between object files. These rules explain almost every "already defined" and "unresolved" error you will meet.

Declarations and definitions

C++ separates saying something exists from saying what it is.

Declaration: "this exists" Definition: "here it is"
Function int addBonus(int score); int addBonus(int score) { return score + 50; }
Global variable extern int g_highScore; int g_highScore{ 0 };
Class class Player; (a forward declaration) class Player { int health; };

A declaration is enough to use a function: the compiler only needs to know its name, parameters and return type to generate a call. The call's target address is left for the linker. A definition is what produces machine code or storage.

Headers carry declarations

Each .cpp file is compiled alone (it becomes one translation unit). For main.cpp to call a function defined in score.cpp, main.cpp needs its declaration. A header file is simply a convenient way to paste the same declarations into every file that needs them:

C++
// score.h
#pragma once
int addBonus(int score);         // declaration

// score.cpp
#include "score.h"
int addBonus(int score) { return score + 50; }   // the one definition

// main.cpp
#include "score.h"
int main() { return addBonus(10); }              // a call, resolved by the linker

#pragma once stops a header from being pasted twice into the same translation unit, which would otherwise repeat its class definitions and fail. The older, portable form is an include guard:

C++
#ifndef SCORE_H
#define SCORE_H
int addBonus(int score);
#endif

The one definition rule

The one definition rule (ODR) says, roughly:

  • every function and global variable that is used must be defined exactly once in the whole program;
  • a class, an inline function or a template may be defined in every translation unit that uses it, but all those definitions must be identical.

That second point is why class definitions and templates live in headers, and why ordinary function bodies do not. Break the first point and the linker complains:

Situation Linker error
A function is declared and called, but defined nowhere LNK2019: unresolved external symbol
A function body written in a header included by two .cpp files LNK2005: already defined in main.obj
A global int g_score{ 0 }; in a header LNK2005 as well

Ways to make a definition safe in a header

Keyword Effect Use for
inline "Identical definitions may appear in many files; keep one" Small functions in headers; inline variables (C++17) for header constants
static (at namespace scope) "Private to this translation unit": each file gets its own separate copy Helpers used only in one .cpp
Unnamed namespace { ... } Same as static, for everything inside Several file-private helpers
constexpr variable Implicitly inline (since C++17) for static data members; namespace-scope constexpr variables are internal to each file Compile-time constants

Templates and functions defined inside a class body are implicitly inline, which is why they can live in headers.

Symbols: what the linker actually matches

Each object file contains a symbol table: names it defines and names it needs. C++ names are mangled into strings that encode the namespace, parameter types and more, so that overloads get different symbols:

Output
int addBonus(int)            ?addBonus@@YAHH@Z
int addBonus(float)          ?addBonus@@YAHM@Z
void Player::heal(int)       ?heal@Player@@QEAAXH@Z

The linker matches these strings exactly. So a declaration that differs from its definition in any detail (a const, a parameter type, a namespace) produces a different symbol, and the result is LNK2019 even though "the function is right there". The error message shows the mangled name and a readable version; compare it carefully with your definition.

extern "C" turns mangling off, giving the plain name addBonus. That is how C++ code exposes functions to C, and how DLLs usually export functions so other languages and GetProcAddress (lesson 4.05) can find them by a simple name. You can see an object file's symbols with:

Terminal
dumpbin /symbols score.obj
dumpbin /exports plugin.dll
undname "?addBonus@@YAHH@Z"

Order of the stages, once more

flowchart LR
    A["a.cpp"] --> PA["preprocess"] --> CA["compile"] --> OA["a.obj<br/>defines: addBonus<br/>needs: printf"]
    B["main.cpp"] --> PB["preprocess"] --> CB["compile"] --> OB["main.obj<br/>defines: main<br/>needs: addBonus"]
    OA --> L["link"]
    OB --> L
    LIB["libraries"] --> L
    L --> E["game.exe"]

Changing a.cpp recompiles only a.obj, then re-links. Changing a header recompiles every .cpp that includes it, directly or indirectly. That is why large projects keep headers small, use forward declarations where they can, and avoid including heavy headers in other headers.

Common mistakes

A declaration that does not quite match its definition

void heal(int) declared, void heal(long) defined: two different symbols, and an unresolved external. Copy declarations from definitions exactly.

Globals defined in headers

Declare extern int g_score; in the header and define it in one .cpp, or use inline int g_score{ 0 };.

Including a header to get a type you only point to

If a header only uses Player* or Player&, a forward declaration class Player; is enough, and saves recompiling when player.h changes.

Knowledge check

quizIn Xenon your best score is kept.
  1. Which is a definition, not just a declaration?
    • int addBonus(int score);
    • extern int g_lives;
    • int g_lives{ 3 };
    Show the answer

    int g_lives{ 3 }; It creates the variable's storage. The others only announce that something exists elsewhere.

  2. Two .cpp files include a header containing int square(int x) { return x * x; }. What happens?
    • The linker reports that square is already defined
    • It compiles and links fine
    • The compiler reports a syntax error
    Show the answer

    The linker reports that square is already defined Each file gets a definition, breaking the one definition rule. Marking it inline fixes it.

  3. Why does a declaration void heal(int) not link to a definition void heal(unsigned)?
    • The parameter types are part of the mangled symbol, so they are two different symbols
    • The linker ignores parameters
    • unsigned cannot be used in definitions
    Show the answer

    The parameter types are part of the mangled symbol, so they are two different symbols C++ symbols encode the parameter types so that overloads can coexist.

  4. What does extern "C" change?
    • It turns off name mangling, so the symbol is the plain function name
    • It makes the function run faster
    • It makes the function private to one file
    Show the answer

    It turns off name mangling, so the symbol is the plain function name Plain names are what C code, other languages and GetProcAddress expect.
