The Console API

lesson 5.099 of 9 in milestone 55 min1 practice task

The console window is more than a place for std::cout. With the console API and virtual terminal sequences you can move the cursor, use colours, hide the cursor, read individual key presses and redraw a whole screen without flicker: enough for a text-mode game or a live tool display. This lesson covers both the classic API and the modern escape sequences.

Handles to the console

A console program has three standard handles, fetched with GetStdHandle:

Handle For
STD_INPUT_HANDLE Keyboard and mouse input
STD_OUTPUT_HANDLE Text output
STD_ERROR_HANDLE Error output

They are like file handles (lesson 5.01): WriteFile works on the output handle. But the console also has its own functions that understand it as a grid of character cells with colours and a cursor.

Run these in a real console

The examples in this lesson need a real console window. The course website captures program output instead of showing a console, so build and run them in Visual Studio.

Colours and positions, the classic way

C++
#include <windows.h>
#include <iostream>

int main()
{
    HANDLE out{ GetStdHandle(STD_OUTPUT_HANDLE) };

    SetConsoleTextAttribute(out, FOREGROUND_GREEN | FOREGROUND_INTENSITY);
    std::cout << "HP 87/100\n";
    SetConsoleTextAttribute(out, FOREGROUND_RED | FOREGROUND_INTENSITY);
    std::cout << "Poisoned\n";
    SetConsoleTextAttribute(out, FOREGROUND_RED | FOREGROUND_GREEN | FOREGROUND_BLUE);   // back to grey

    SetConsoleCursorPosition(out, COORD{ 20, 0 });   // column 20, row 0
    std::cout << "Gold 1250";
    SetConsoleCursorPosition(out, COORD{ 0, 3 });
    return 0;
}

Colours are 4 bits each for text and background (16 colours); positions are a COORD of column and row, counted from 0.

Virtual terminal sequences

Modern Windows consoles (and Windows Terminal) also understand the same escape sequences used by Linux and macOS terminals: special strings starting with the ESC character (\x1b) that the terminal interprets instead of printing. They are often simpler than the API, work across platforms, and support 24-bit colour. Turn them on once:

C++
HANDLE out{ GetStdHandle(STD_OUTPUT_HANDLE) };
DWORD mode{ 0 };
GetConsoleMode(out, &mode);
SetConsoleMode(out, mode | ENABLE_VIRTUAL_TERMINAL_PROCESSING);
SetConsoleOutputCP(CP_UTF8);     // and print UTF-8 correctly (lesson 5.03)
Sequence Effect
\x1b[H Cursor to the top-left
\x1b[row;colH Cursor to a position, counted from 1
\x1b[2J Clear the screen
\x1b[31m ... \x1b[37m Text colour: red, green, yellow, blue, magenta, cyan, white (30 is black)
\x1b[1m Bold / bright
\x1b[38;2;r;g;bm Any 24-bit text colour
\x1b[0m Reset all colours and styles
\x1b[?25l / \x1b[?25h Hide / show the cursor
C++
std::cout << "\x1b[2J\x1b[?25l";                               // clear, hide cursor
std::cout << "\x1b[1;1H\x1b[32mHP 87/100\x1b[0m";              // green, top-left
std::cout << "\x1b[1;21H\x1b[38;2;255;200;60mGold 1250\x1b[0m"; // gold-coloured, column 21

Drawing a whole screen without flicker

Clearing and reprinting the screen every frame flickers, for the same reason as lesson 5.06: the user sees the empty screen in between. The text-mode version of double buffering is to build the entire frame as one string and write it in a single call, starting with "cursor home" rather than "clear":

C++
std::string frame{ "\x1b[H" };                   // home, not clear: overwrite in place
for (int y{ 0 }; y < height; ++y)
{
    for (int x{ 0 }; x < width; ++x) frame += (x == px && y == py) ? '@' : map[y][x];
    frame += '\n';
}
WriteConsoleA(out, frame.data(), static_cast<DWORD>(frame.size()), nullptr, nullptr);

One write per frame means the console updates all at once.

Reading keys without Enter

std::cin waits for a whole line. A game needs individual key presses as they happen. ReadConsoleInputW returns input records, one per event, and GetNumberOfConsoleInputEvents says whether any are waiting, so a loop never blocks:

C++
HANDLE in{ GetStdHandle(STD_INPUT_HANDLE) };
DWORD waiting{ 0 };
GetNumberOfConsoleInputEvents(in, &waiting);
while (waiting-- > 0)
{
    INPUT_RECORD record{};
    DWORD read{ 0 };
    ReadConsoleInputW(in, &record, 1, &read);
    if (record.EventType == KEY_EVENT && record.Event.KeyEvent.bKeyDown)
        handleKey(record.Event.KeyEvent.wVirtualKeyCode);   // the same virtual-key codes as lesson 5.07
}

Put the three pieces together (an input loop, game state, a whole-frame string) and you have a complete text-mode game engine in under a hundred lines. Many classic roguelike games are exactly this.

A console for a windowed game

A game built for the Windows subsystem (lesson 5.06) has no console, which makes std::cout logging disappear. During development you can give it one:

C++
AllocConsole();                                   // create a console window for this process
FILE* stream{ nullptr };
freopen_s(&stream, "CONOUT$", "w", stdout);       // point stdout at it

Chapter 11's debug console uses a different approach, drawing text inside the game itself, but AllocConsole is the quickest way to get logging into a windowed program.

Common mistakes

Escape sequences printing as garbage

Enable ENABLE_VIRTUAL_TERMINAL_PROCESSING first. Older consoles may not support it at all.

Counting rows and columns from 0 in escape sequences

\x1b[1;1H is the top-left. The COORD API counts from 0; escape sequences count from 1.

Clearing the screen every frame

Home the cursor and overwrite instead, writing the whole frame in one call.

[!warning] Using std::cin for game input It waits for Enter. Read input records instead.
