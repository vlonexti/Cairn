Strings on Windows: ANSI, UTF-16 and UTF-8

lesson 5.033 of 9 in milestone 56 min1 practice task

Most Windows API functions that take text exist twice: an A version for 8-bit "ANSI" strings and a W version for UTF-16 "wide" strings. Windows works in UTF-16 internally; the rest of the world, and most libraries, use UTF-8. This lesson explains the A/W split, why the course always calls the W functions, and how to convert between UTF-8 and UTF-16 at the edges of your program.

Two versions of everything

Look up CreateFile in the documentation and you find CreateFileA and CreateFileW. The same goes for MessageBox, LoadLibrary, GetModuleFileName and hundreds of others.

Version Strings are C++ type Literal
A ("ANSI") 8-bit, in the system's current code page char*, std::string "text"
W ("wide") UTF-16 wchar_t*, std::wstring L"text"

The plain name CreateFile is a macro that becomes CreateFileW when the project defines UNICODE (Visual Studio's default, "Use Unicode Character Set") and CreateFileA otherwise. The TCHAR type and TEXT("...") macro follow the same switch. They exist for code that once had to build both ways; new code does not need them.

The W versions are the real ones. Windows has stored and processed text as UTF-16 since Windows NT. An A function converts your string to UTF-16 using the current code page (a table, such as Windows-1252 for Western Europe), calls the W function, and converts any results back. Characters that do not exist in that code page are lost, typically turned into ?. A player named Zoë or Сергей, or a save folder under a user name with such letters, breaks A-function code on many machines.

So the rule for this course: call the W functions explicitly (CreateFileW, MessageBoxW), with std::wstring or L"..." strings.

But the rest of the program uses UTF-8

Files, network protocols, JSON, most cross-platform libraries and your own source code use UTF-8 (lesson 2.08). So programs keep text as UTF-8 internally and convert to UTF-16 only when calling Windows. The conversion functions are MultiByteToWideChar and WideCharToMultiByte, using the two-call pattern from lesson 5.02:

C++
#include <windows.h>
#include <iostream>
#include <string>

std::wstring widen(const std::string& utf8)
{
    if (utf8.empty()) return {};
    const int needed{ MultiByteToWideChar(CP_UTF8, MB_ERR_INVALID_CHARS, utf8.data(), static_cast<int>(utf8.size()), nullptr, 0) };
    std::wstring out(static_cast<std::size_t>(needed), L'\0');
    MultiByteToWideChar(CP_UTF8, MB_ERR_INVALID_CHARS, utf8.data(), static_cast<int>(utf8.size()), out.data(), needed);
    return out;
}

std::string narrow(const std::wstring& utf16)
{
    if (utf16.empty()) return {};
    const int needed{ WideCharToMultiByte(CP_UTF8, 0, utf16.data(), static_cast<int>(utf16.size()), nullptr, 0, nullptr, nullptr) };
    std::string out(static_cast<std::size_t>(needed), '\0');
    WideCharToMultiByte(CP_UTF8, 0, utf16.data(), static_cast<int>(utf16.size()), out.data(), needed, nullptr, nullptr);
    return out;
}

int main()
{
    const std::string name{ "Zo\xC3\xAB" };          // "Zoë" in UTF-8: 4 bytes
    const std::wstring wide{ widen(name) };            // 3 UTF-16 units
    std::cout << name.size() << " UTF-8 bytes, " << wide.size() << " UTF-16 units\n";
    std::cout << "round trip ok: " << (narrow(wide) == name) << '\n';
    return 0;
}
Output
4 UTF-8 bytes, 3 UTF-16 units
round trip ok: 1

These two small functions are worth keeping in your engine library. With them, the pattern is: UTF-8 everywhere in your code, widen() right before a W call, narrow() on anything Windows gives back.

How UTF-8 and UTF-16 encode a character

Knowing the encodings lets you recognise text in memory and write conversions yourself, which is this lesson's practice task.

UTF-8 uses 1 to 4 bytes per code point. The first byte's high bits say how many bytes follow:

Code points Bytes Pattern
U+0000 to U+007F 1 0xxxxxxx
U+0080 to U+07FF 2 110xxxxx 10xxxxxx
U+0800 to U+FFFF 3 1110xxxx 10xxxxxx 10xxxxxx
U+10000 to U+10FFFF 4 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx

ë is U+00EB, binary 000 1110 1011. In the 2-byte pattern that is 110 00011 10 101011 = C3 AB, the two bytes in the example.

UTF-16 uses one 16-bit unit for code points up to U+FFFF. Anything above (most emoji, some rare scripts) is split into two units called a surrogate pair: subtract 0x10000, put the top 10 bits in a unit 0xD800 + top, and the bottom 10 bits in 0xDC00 + bottom. So even in UTF-16, one character can take two units.

Telling Windows to use UTF-8

Since Windows 10 version 1903, an application can declare in its manifest that its A functions should use UTF-8 as the code page (<activeCodePage>UTF-8</activeCodePage>). That makes A functions safe for any text. It is a reasonable option for new programs, but calling W functions works on every version and makes the intent obvious, so the course sticks with W.

The console is a separate matter: to print UTF-8 correctly in a console window, call SetConsoleOutputCP(CP_UTF8) at start-up (lesson 5.09).

Common mistakes

Calling A functions with UTF-8

Without the UTF-8 manifest, A functions interpret bytes in the current code page, garbling everything that is not ASCII.

[!warning] Casting between char* and wchar_t* (LPCWSTR)"file.txt" compiles, and passes bytes that Windows reads as nonsense UTF-16. Convert with widen, or use L"..." literals.

[!warning] Counting characters with size() UTF-8 bytes and UTF-16 units are not characters. std::wstring{ L"😀" }.size() is 2.

[!warning] Mixing std::cout and std::wcout Using both on the same stream in one program leads to missing output. Pick one, or convert and use std::cout throughout.
