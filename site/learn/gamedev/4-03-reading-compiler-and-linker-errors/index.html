Reading Compiler and Linker Errors

lesson 4.033 of 10 in milestone 48 min

Build errors look intimidating because one mistake can produce a screen of messages. This lesson gives a method (find the first error, read its code, go to its line, ignore the cascade), and a field guide to the MSVC errors and warnings you will meet most often, with what each usually means.

The method

  1. Use the Output window, not just the Error List. The Error List sorts and groups messages; the Output window (View → Output, "Show output from: Build") shows them in the order they happened, with the full text and the "see declaration of..." notes that follow each one.
  2. Fix the first error first. One missing ; or } makes the compiler misread everything after it, producing dozens of follow-on errors that vanish once the first is fixed. Rebuild after each fix.
  3. Read the code. C codes come from the compiler, LNK codes from the linker. Warnings are C4xxx. Searching for the code (for example "C2664") finds Microsoft's page explaining it.
  4. Go to the line, then look just before it. The compiler reports where it noticed the problem, which is often the line after the real mistake.
  5. Read the types in the message slowly. Most of a long message is the names of the types involved. The interesting part is usually "cannot convert from X to Y".

A worked example

C++
#include <string>
#include <vector>

struct Item { std::string name; int weight; };

int totalWeight(const std::vector<Item>& items)
{
    int total{ 0 }
    for (const Item& item : items)
        total += item.weight;
    return total;
}

MSVC reports:

Output
main.cpp(8,19): error C2143: syntax error: missing ';' before 'for'
main.cpp(10,9): error C2065: 'item': undeclared identifier
main.cpp(10,9): error C2228: left of '.weight' must have class/struct/union

Three errors, one mistake. The first one names the real problem: int total{ 0 } on line 7 is missing its ;, which the compiler only noticed on reaching for on line 8. Because it then misread the for, it never declared item, so lines 10's errors are just a cascade. Add the semicolon and all three disappear.

Compiler errors you will see most

Code Message (shortened) Usually means
C2143 syntax error: missing ';' before ... A missing ;, ) or } just before the reported spot
C2065 undeclared identifier A typo, a missing #include, or a name used before its declaration
C3861 identifier not found Same, for a function call
C2039 is not a member of Typo in a member name, or the wrong type
C2664 cannot convert argument N from X to Y The argument has the wrong type; read X and Y carefully (const? pointer vs reference?)
C2440 cannot convert from X to Y An assignment or initialisation with the wrong type
C2662 cannot convert 'this' pointer from const X to X& Calling a non-const member function on a const object: make the function const
C2280 attempting to reference a deleted function Copying something that cannot be copied, such as a std::unique_ptr; use std::move or a reference
C2027 use of undefined type Only a forward declaration is visible where the full class is needed: include its header
C2011 type redefinition A header included twice without #pragma once
C1083 cannot open include file Wrong file name, or the folder is missing from Additional Include Directories

Linker errors

Code Usually means
LNK2019 Unresolved external symbol: declared and used, never defined in anything linked. Missing .cpp in the project, missing library in Linker → Input, or a declaration that does not match its definition exactly (lesson 4.02).
LNK2001 Also unresolved, usually for a variable or a virtual function's vtable: a class with a virtual function declared but never defined
LNK1120 "N unresolved externals": a summary; fix the LNK2019s above it
LNK2005 Already defined: a function or global defined in a header included by several .cpp files
LNK1104 Cannot open file: often the .exe is still running and locked, or a library path is wrong
LNK1168 Cannot open X.exe for writing: the program is still running. Close it.

A linker error message contains the symbol, mangled and readable. The readable form tells you exactly which function and which overload is missing.

Warnings worth treating as errors

Warnings point at code that compiles but is probably wrong. At warning level 4 these are the most valuable:

Warning Meaning
C4700 Uninitialised local variable used
C4701 Potentially uninitialised local variable used
C4172 Returning the address of a local variable
C4244 Conversion that may lose data, such as double to int
C4267 size_t to int conversion, possible loss of data
C4018 / C4389 Signed and unsigned comparison
C4715 Not all control paths return a value
C4996 Using a function marked unsafe or deprecated, such as strcpy

Turning on Treat Warnings As Errors (/WX) keeps the list at zero, which is the only way warnings stay useful: once there are fifty of them, nobody reads the fifty-first.

Template errors

Errors inside templates (including the standard library) can run to dozens of lines, because the compiler reports the whole chain of instantiations. Read them from the bottom of the "see reference to..." chain, where the template was first used from your code: that is the line to look at. The usual causes are passing a type that lacks something the template needs (no < for std::sort, not copyable for std::vector::push_back).

Common mistakes

Fixing errors from the bottom of the list

Later errors are often caused by earlier ones. Fix the first and rebuild.

Trusting the reported line exactly

Look at the line before, especially for missing semicolons and braces.

Ignoring warnings

C4700, C4172 and C4715 are bugs the compiler has already found for you.

  1. A build shows 40 errors. What should you do first?
    • Fix the first error in the Output window and rebuild
    • Fix the error that appears most often
    • Start from the last error
    Show the answer

    Fix the first error in the Output window and rebuild Most of the rest are probably a cascade from the first.

  2. error C2280: attempting to reference a deleted function appears when pushing a std::unique_ptr into a vector. What is the fix?
    • Move it in: v.push_back(std::move(ptr));
    • Make the pointer const
    • Use new instead
    Show the answer

    Move it in: v.push_back(std::move(ptr)); unique_ptr cannot be copied; its copy constructor is deleted. It can be moved.

  3. LNK1168: cannot open game.exe for writing. What is the most likely cause?
    • A missing library
    • The program is still running from the last build
    • A syntax error in main
    Show the answer

    The program is still running from the last build Windows will not let the linker overwrite an executable that is running.

  4. Which warning tells you a function can end without returning a value?
    • C4244
    • C4715
    • C4996
    Show the answer

    C4715 Falling off the end of a non-void function is undefined behaviour.
