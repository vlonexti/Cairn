Plugins as DLLs

lesson 13.044 of 8 in milestone 135 min

With the interface designed, Delve can load plugins: find each enabled mod's DLL, load it safely, call its entry point, validate what it returns, order plugins by their dependencies, call them each frame, and unload them cleanly. This lesson writes the plugin manager, and adds hot reloading of your own plugins during development.

Loading one plugin

C++
using EntryFn = int (*)(DelvePluginApi*);

std::optional<LoadedPlugin> loadPlugin(const std::filesystem::path& dll, const DelveHostApi& host)
{
    // Load by full path, searching only the plugin's own folder and the system for its dependencies (lesson 5.08).
    HMODULE module{ LoadLibraryExW(dll.c_str(), nullptr,
                                   LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_DEFAULT_DIRS) };
    if (!module) { logError("could not load ", dll, ": error ", GetLastError()); return std::nullopt; }

    auto entry{ reinterpret_cast<EntryFn>(GetProcAddress(module, "delvePluginEntry")) };
    DelvePluginApi api{};
    api.size = sizeof(api);                               // tell the plugin how big our table is
    if (!entry || entry(&api) != 0 || !validatePlugin(api, DELVE_API_VERSION_MAJOR, DELVE_API_VERSION_MINOR).empty())
    {
        logError(dll, " is not a valid Delve plugin");
        FreeLibrary(module);
        return std::nullopt;
    }
    if (api.init(&host) != 0) { logError(api.name, " failed to initialise"); FreeLibrary(module); return std::nullopt; }
    return LoadedPlugin{ module, api };
}

Each step can fail, and each failure is logged with the plugin's path or name and leaves the game running without it. validatePlugin is lesson 13.03's practice task.

Load order with dependencies

Mods declare what they require (lesson 13.01's manifest). A plugin must be initialised after everything it requires, and shut down before them. Finding such an order is a topological sort: repeatedly take a mod whose requirements are all already placed. If at some point no mod can be placed, the requirements form a cycle (A requires B, B requires A), and those mods cannot be loaded. The practice task implements it, preferring the player's chosen order where the dependencies allow.

Calling plugins

C++
void PluginManager::update(double dt)
{
    for (LoadedPlugin& p : m_plugins)                   // in load order
        if (p.api.update) p.api.update(dt);
}

void PluginManager::shutdown()
{
    for (auto it{ m_plugins.rbegin() }; it != m_plugins.rend(); ++it)   // reverse order
    {
        it->api.shutdown();
        FreeLibrary(it->module);                       // after this, no pointer into the DLL may be used
    }
    m_plugins.clear();
}

Shutting down in reverse order mirrors lesson 2.04's destructor order: a plugin may depend on those loaded before it. Before FreeLibrary, the game must forget every callback the plugin registered (event handlers, console commands), or a later event would call into unloaded code (lesson 4.05).

Hot reloading your own plugins

During development, rebuilding a plugin and reloading it without restarting the game makes iteration fast:

  1. Watch the plugin's DLL file for changes (lesson 10.06's ReadDirectoryChangesW).
  2. Copy the new DLL to a temporary name and load the copy, because Windows locks a loaded DLL file and the compiler could not overwrite it otherwise. (The PDB has the same problem; give each build a unique PDB name.)
  3. Call the old plugin's shutdown, remove its callbacks, FreeLibrary it, then init the new one.
  4. State that must survive the reload (a debug tool's settings) is saved by shutdown and restored by init, or kept on the game's side.

Hot reloading is for your own development builds; players restart the game to update mods.

Common mistakes

Loading plugins by bare name

Use full paths and restricted search flags, so a plugin's dependencies cannot be hijacked (lesson 5.08).

Keeping callbacks after unloading

Unregister everything a plugin registered before FreeLibrary.

Shutting down in load order

Shut down in reverse, so dependents go before what they depend on.
