Setting Up Visual Studio for This Course

lesson 1.077 of 8 in milestone 18 min

The examples on this site run in your browser, but from chapter 4 on you will build real Windows programs, step through them in a debugger and read their memory. That takes Visual Studio on your own PC. This lesson installs it with the right parts, creates a console project, and sets the options the course assumes.

Why Visual Studio

Visual Studio is Microsoft's development environment for Windows. It brings together the three tools this course leans on most:

  • the MSVC compiler and linker, which produce the same kind of code as the Windows programs you will study,
  • the Windows SDK, the headers and libraries for the Windows API,
  • the Visual Studio debugger, which can pause a program, show its memory and registers, and step through its machine code.

The Community edition is free for individual learners. It runs on Windows 10 and 11. The examples on this site use the same compiler, so code that runs here behaves the same way there.

Visual Studio, not Visual Studio Code

Visual Studio Code is a separate, lighter editor. It can be set up for C++, but its debugger and project system are not what this course describes. Install Visual Studio (the purple icon).

Installing

  1. Download the Visual Studio Community installer from Microsoft's website: visualstudio.microsoft.com.
  2. Run it. When it asks which workloads to install, tick Desktop development with C++.
  3. On the right, under Installation details, make sure these are ticked. Most are on by default:
    • MSVC v143 (or newer) x64/x86 build tools
    • Windows 11 SDK (the newest listed; it also builds programs for Windows 10)
    • C++ AddressSanitizer (used in chapter 2)
    • C++ CMake tools for Windows (optional)
  4. Press Install. It needs several gigabytes and some time.

Later chapters add more: chapter 16 installs the Windows Driver Kit, and says exactly which version to match. Nothing else is needed now.

Creating a project

  1. Start Visual Studio and choose Create a new project.
  2. Pick Console App with the C++ tag. Not "Empty Project" and not a C# one.
  3. Name it, for example chapter01, choose a folder, and tick Place solution and project in the same directory to keep the folders simple.
  4. Press Create.

Visual Studio opens chapter01.cpp with a "Hello World" program in it. Press Ctrl+F5 (Start Without Debugging). A console window opens and shows the output, and stays open until you press a key.

A project builds one program or library. A solution groups projects that belong together; chapter 4 uses this to build a game and a DLL side by side.

Settings the course assumes

Open the project's properties: right-click the project in Solution Explorer and choose Properties. At the top, set Configuration to All Configurations and Platform to x64, so the changes apply to both Debug and Release builds.

Where Setting Value Why
General C++ Language Standard ISO C++20 Standard (/std:c++20) or newer The course uses std::format, std::span and other C++20 features
C/C++ → General Warning Level Level 4 (/W4) More warnings catch more mistakes
C/C++ → General Treat Warnings As Errors Yes (/WX), optional Stops warnings from piling up unread
Advanced Character Set Use Unicode Character Set The default; chapter 5 explains what it changes

And in the toolbar at the top of the window, make sure the platform box says x64, not x86. Everything in this course assumes 64-bit programs: 8-byte pointers, the x64 registers, the x64 calling convention.

Debug and Release

The toolbar's configuration box switches between two ways of building the same code.

Debug Release
Optimisation Off On (/O2)
Code matches the source line by line Yes Not closely: code is merged, reordered or removed
Extra checks Uninitialised stack memory filled with 0xCC, heap checks, iterator checks None
Speed Slow Fast
Use it for Writing and debugging Measuring performance, and shipping

Most of this course uses Debug. Chapter 4 compares the two in detail, and chapter 7 reads optimised Release code on purpose.

[!tip] The 0xCC pattern In a Debug build, uninitialised local variables are filled with the byte 0xCC. If a variable shows up as -858993460 (which is 0xCCCCCCCC) in the debugger, you have read it before giving it a value. You will meet this pattern in the next lesson.

Where the output goes

After a build, the program is in a folder named after the platform and configuration:

Output
chapter01\
    chapter01.cpp
    chapter01.vcxproj
    x64\
        Debug\
            chapter01.exe      the program
            chapter01.pdb      its debug symbols
        Release\
            chapter01.exe

You can run the .exe from there by double-clicking it, but a console program closes its window as soon as it finishes. Run it from a terminal instead: open Tools → Command Line → Developer PowerShell, then:

Terminal
cd x64\Debug
.\chapter01.exe

The Developer PowerShell also has the compiler on its path, so you can try the build stages from lesson 1.04 by hand:

Terminal
cl /EHsc /std:c++20 /c main.cpp      # compile only: makes main.obj
cl /EHsc /std:c++20 /FA main.cpp     # compile and link, and also write main.asm
dumpbin /disasm main.obj             # show the machine code inside the object file

Common mistakes

Building for x86

A 32-bit build has 4-byte pointers and a different calling convention, and nothing in chapters 6, 7 or 9 will match. Check the platform box says x64.

Changing settings for one configuration only

If Debug builds work and Release builds fail with odd errors, a setting was probably changed with only Debug selected. Use All Configurations when setting project-wide options.

Picking the wrong project template

"Console App" under C++ is the one. Templates for C#, or a "Windows Desktop Application", start from different code.
