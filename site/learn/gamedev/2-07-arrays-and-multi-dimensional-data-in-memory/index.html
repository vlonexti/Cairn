Arrays and Multi-Dimensional Data in Memory

lesson 2.077 of 11 in milestone 26 min1 practice task

An array is the simplest data structure there is: elements side by side, with no gaps and no bookkeeping. Element i is at the start address plus i times the element size. Two-dimensional data such as a tile map is stored the same way, one row after another. This lesson shows the arithmetic, why the order you loop in matters for speed, and how games store grids.

Side by side, nothing else

C++
#include <iostream>

int main()
{
    int scores[5]{ 10, 20, 30, 40, 50 };
    std::cout << "sizeof(scores) = " << sizeof(scores) << '\n';
    for (int i{ 0 }; i < 5; ++i)
        std::cout << "scores[" << i << "] is " << (reinterpret_cast<char*>(&scores[i]) - reinterpret_cast<char*>(&scores[0])) << " bytes from the start\n";
    return 0;
}
Output
sizeof(scores) = 20
scores[0] is 0 bytes from the start
scores[1] is 4 bytes from the start
scores[2] is 8 bytes from the start
scores[3] is 12 bytes from the start
scores[4] is 16 bytes from the start

Twenty bytes for five 4-byte ints: an array holds nothing but its elements. It does not store its own length, and nothing at run time stops you reading scores[5] or scores[-1]. The compiler turns scores[i] into exactly the arithmetic from lesson 1.03:

address of scores[i] = address of scores[0] + i × sizeof(int)

That is a multiplication and an addition, which is why indexing an array is as fast as memory access gets.

Arrays of structs

The same rule holds for any element type. An array of Pickup from lesson 2.05 places each struct right after the previous one, padding included, which is exactly why a struct's size is rounded up: so that pickups[1] starts properly aligned.

pickups[0]                 pickups[1]                 pickups[2]
┌──────────────────────────┬──────────────────────────┬──────────
│ 24 bytes                 │ 24 bytes                 │ ...
└──────────────────────────┴──────────────────────────┴──────────
 +0                         +24                        +48

std::array<T, N> is a plain array wrapped in a struct: same bytes, but it knows its size, can be copied and returned, and checks bounds in Debug builds with .at(). std::vector<T> keeps its elements in exactly the same side-by-side form, in a heap block (lesson 3.07). Everything in this lesson applies to all three.

Two dimensions: rows one after another

Memory is one-dimensional. A grid has to be flattened. C++ stores a two-dimensional array row by row (called row-major order): all of row 0, then all of row 1, and so on.

C++
#include <iostream>

int main()
{
    char map[3][4]{
        { '#', '#', '#', '#' },
        { '#', '.', '.', '#' },
        { '#', '#', '#', '#' },
    };
    const char* flat{ &map[0][0] };
    for (int i{ 0 }; i < 12; ++i) std::cout << flat[i];
    std::cout << '\n';
    std::cout << "map[1][2] is element " << (&map[1][2] - flat) << " of the flat run\n";
    return 0;
}
Output
#####..#####
map[1][2] is element 6 of the flat run

The formula, with width the number of columns:

index of (row, column) = row × width + column

Games almost always store maps this way on purpose, as one flat std::vector of size width × height, with a small function for the index. The size can then be chosen at run time, the whole map is one allocation, and saving it is one write.

C++
#include <iostream>
#include <vector>

struct TileMap
{
    int width{ 0 };
    int height{ 0 };
    std::vector<char> tiles;

    TileMap(int w, int h, char fill) : width{ w }, height{ h }, tiles(static_cast<std::size_t>(w * h), fill) {}

    char& at(int x, int y) { return tiles[static_cast<std::size_t>(y * width + x)]; }
    bool inside(int x, int y) const { return x >= 0 && y >= 0 && x < width && y < height; }
};

int main()
{
    TileMap map{ 6, 3, '.' };
    map.at(0, 0) = '@';
    map.at(5, 2) = '>';
    for (int y{ 0 }; y < map.height; ++y)
    {
        for (int x{ 0 }; x < map.width; ++x) std::cout << map.at(x, y);
        std::cout << '\n';
    }
    return 0;
}
Output
@.....
......
.....>

Notice (x, y) in the interface and y * width + x inside: x is the column, y the row. Mixing these up is the most common grid bug there is.

Loop order and the cache

The processor does not fetch single bytes from main memory. It fetches 64-byte blocks, called cache lines, and keeps recently used ones in small, very fast memories called caches. Reading the next byte along is almost free, because it arrived with the line. Jumping far away means waiting for a new line, which can take a hundred times longer than a cache hit.

So the order in which you visit a grid matters:

C++
// Fast: walks memory in order, using every byte of each cache line.
for (int y{ 0 }; y < height; ++y)
    for (int x{ 0 }; x < width; ++x)
        total += map.at(x, y);

// Slow for big maps: jumps a whole row ahead every step.
for (int x{ 0 }; x < width; ++x)
    for (int y{ 0 }; y < height; ++y)
        total += map.at(x, y);

Both visit every tile once and give the same answer. On a 4000 × 4000 map, the first is typically several times faster. The rule: make the innermost loop walk along the last index, so it moves through memory in order. Chapter 17 measures effects like this properly.

Arrays decay to pointers

Passing a plain array to a function passes only the address of its first element. The size is lost:

C++
void printAll(int scores[])      // really: int* scores
{
    // sizeof(scores) here is 8, the size of a pointer, not of the array.
}

That is the root of many overruns: the function has no idea where the array ends. Pass a std::span<int> (C++20), which carries the pointer and the length together, or pass a std::vector or std::array by reference.

Common mistakes

Swapping x and y

With y * width + x, x must be less than width and y less than height. Writing x * width + y works only for square maps and scrambles everything else.

Off-by-one at the edges

A map width wide has columns 0 to width - 1. Looking at a neighbour at x + 1 from the last column reads into the next row, not off the map. Check with an inside function first.

Looping column by column over big grids

Put the row loop outside and the column loop inside.

Expecting a function to know an array's size

A plain array passed to a function becomes a pointer. Use std::span, std::array or std::vector.

  1. An array of double starts at address 0x1000. Where is element 3?
    • 0x1003
    • 0x100C
    • 0x1018
    Show the answer

    0x1018 3 × 8 bytes = 24 = 0x18, so element 3 is at 0x1000 + 0x18.

  2. A tile map is 10 wide and stored row-major. Which index holds the tile at x = 3, y = 2?
    • 23
    • 32
    • 5
    Show the answer

    23 2 × 10 + 3 = 23.

  3. Which loop order is faster for a large row-major grid?
    • Rows in the outer loop, columns in the inner loop
    • Columns in the outer loop, rows in the inner loop
    • Both are always the same speed
    Show the answer

    Rows in the outer loop, columns in the inner loop The inner loop should walk through memory in order, so each cache line fetched is fully used.

  4. Inside void f(int a[]), what is sizeof(a) on x64?
    • The size of the whole array
    • 8, the size of a pointer
    • 4, the size of one int
    Show the answer

    8, the size of a pointer An array parameter is really a pointer. The length is not passed.
