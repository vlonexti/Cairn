The Microsoft x64 Calling Convention

lesson 7.066 of 11 in milestone 75 min1 practice task

A calling convention is the agreement between a caller and the function it calls: where arguments go, where the result comes back, which registers survive the call and who cleans up the stack. On 64-bit Windows there is one convention for everything. Knowing it lets you read any function's arguments in the debugger, follow calls in disassembly, and write assembly that C++ can call.

Why a convention is needed

The compiler that builds a caller and the compiler that built the function might be different programs, years apart: your game calling CreateFileW in kernel32.dll, a plugin calling the engine, C++ calling assembly. They only work together if both follow the same rules. On x64 Windows those rules are the Microsoft x64 calling convention, and every compiler targeting Windows follows it.

Arguments

The first four arguments go in registers, the rest on the stack:

Argument Integer or pointer Floating point
1st rcx xmm0
2nd rdx xmm1
3rd r8 xmm2
4th r9 xmm3
5th and later On the stack, at [rsp+28h], [rsp+30h], ... at the moment of the call

The position decides the register, not the type: in f(int a, float b, int c), a is in rcx, b in xmm1 (second position), and c in r8.

  • A member function's hidden this is the first argument: it is in rcx, and the visible arguments shift along by one.
  • Structs of 1, 2, 4 or 8 bytes are passed in a register as if they were an integer. Any other size is copied by the caller to memory, and a pointer to the copy is passed.

Return values

  • Integers, pointers, and structs of 1, 2, 4 or 8 bytes come back in rax.
  • float and double come back in xmm0.
  • Larger structs: the caller passes a hidden pointer (in rcx, moving the other arguments along) to space it has reserved, the function fills it in, and returns that pointer in rax.

Shadow space

The caller always reserves 32 bytes of shadow space (home space) on the stack just above the return address, even if the function takes fewer than four arguments (lesson 2.01). The function may store its register arguments there. Debug builds do exactly that, which is why the debugger can show a function's arguments even after the registers have been reused.

Output
 at the moment the function starts:
 [rsp+28h]   5th argument (if any)
 [rsp+20h]   shadow space for r9
 [rsp+18h]   shadow space for r8
 [rsp+10h]   shadow space for rdx
 [rsp+8]     shadow space for rcx
 [rsp]       return address

Volatile and non-volatile registers

Volatile: the function may destroy them Non-volatile: the function must preserve them
rax, rcx, rdx, r8, r9, r10, r11 rbx, rbp, rdi, rsi, r12, r13, r14, r15, rsp
xmm0 to xmm5 xmm6 to xmm15

A caller that needs a volatile register's value after a call must save it somewhere first. A function that wants to use a non-volatile register must save and restore it (lesson 7.05's push rbx / pop rbx).

Reading a call in disassembly

C++
float applyDamage(Player& p, int amount, float armour, bool critical);
...
applyDamage(hero, 40, 0.25f, true);
Assembly
mov   r9b, 1                          ; 4th: critical = true (in r9)
movss xmm2, dword ptr [__real@3e800000] ; 3rd: armour = 0.25f (3rd position: xmm2)
mov   edx, 40                         ; 2nd: amount (rdx)
lea   rcx, [hero]                     ; 1st: &hero (a reference is a pointer, in rcx)
call  applyDamage
movss dword ptr [result], xmm0        ; the float result comes back in xmm0

Arguments are often loaded in an order unrelated to the C++ order; what matters is which register each ends up in. 0x3e800000 is the bit pattern of 0.25 (lesson 2.11).

Variadic functions

For printf and other functions with ..., floating-point values among the first four arguments are passed in both the integer register and the xmm register for their position, because the callee cannot know which one to look at.

Common mistakes

[!warning] Mapping the 2nd argument to xmm0 because it is the first float Registers follow the argument's position. The 2nd argument, float or not, uses the 2nd slot: rdx or xmm1.

[!warning] Forgetting this In a member function, rcx is this and the first visible argument is in rdx.

Calling a function with less than 32 bytes reserved

Hand-written assembly must reserve shadow space before every call, even to functions with no arguments.

Knowledge check

  1. Where is the third argument of void f(int a, int b, int c, int d, int e)?
    • r8
    • rdx
    • On the stack
    Show the answer

    r8 rcx, rdx, r8, r9 for the first four; the fifth goes on the stack.

  2. Where is y in void g(int x, double y)?
    • xmm1, because it is the second argument
    • xmm0, because it is the first floating-point argument
    • rdx
    Show the answer

    xmm1, because it is the second argument The position decides the register.

  3. In player.heal(25), which register holds 25?
    • rdx, because this takes rcx
    • rcx
    • r8
    Show the answer

    rdx, because this takes rcx The hidden this is the first argument.

  4. A function changes rbx and r10. Which must it restore before returning?
    • Only rbx
    • Only r10
    • Both
    Show the answer

    Only rbx rbx is non-volatile; r10 is volatile and may be destroyed.
