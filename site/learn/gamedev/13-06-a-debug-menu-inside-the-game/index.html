A Debug Menu Inside the Game

lesson 13.066 of 8 in milestone 135 min1 practice task

A console is fast for people who remember commands; a debug menu drawn over the game is faster for everyone else: checkboxes for god mode and map reveal, sliders for monster speed, buttons to spawn things, live graphs. This lesson registers tweakable variables in one place, draws them with Dear ImGui (previewing chapter 14), and lets plugins add their own sections.

Tweakables

Game feel comes from dozens of numbers: player move time, monster sight range, screen shake strength, drop chances. Changing them by editing code and rebuilding is slow. A tweakable is a variable registered once with a name, a range and a description, which the debug menu (and console, and save of settings) can then show and change while the game runs:

C++
float g_moveSlideSeconds{ 0.12f };
int   g_sightRange{ 8 };
bool  g_godMode{ false };

void registerTweakables(Tweakables& t)
{
    t.addFloat("player.slide",   &g_moveSlideSeconds, 0.0f, 0.5f, "Seconds to slide between tiles");
    t.addInt  ("monster.sight",  &g_sightRange, 1, 30, "Tiles at which monsters notice the player");
    t.addBool ("cheat.god",      &g_godMode, "Player takes no damage");
}

The registry stores, for each name, a pointer to the variable, its type and its limits. Everything else is built on that table:

  • the debug menu draws a slider or checkbox per entry, grouped by the part of the name before the dot;
  • the console gets set monster.sight 12 and get player.slide for free (lesson 11.07);
  • values can be saved to tweaks.ini and loaded at start-up (lesson 10.08), so a good setting found while playing survives.

Setting from text must parse, range-check and clamp, which is exactly the part worth testing: the practice task builds the registry's core.

Drawing it with Dear ImGui

Dear ImGui draws interfaces in immediate mode: every frame, the code that draws the menu simply calls one function per widget, and the function returns whether the user changed it. There is no separate interface state to keep in sync. Chapter 14 covers it fully; here is enough for a menu:

C++
void drawDebugMenu(Tweakables& t, Game& game)
{
    ImGui::Begin("Debug");
    if (ImGui::CollapsingHeader("Cheats"))
    {
        ImGui::Checkbox("God mode", &g_godMode);
        if (ImGui::Button("Reveal map")) game.revealMap();
        if (ImGui::Button("Full health")) game.player.health = game.player.maxHealth;
    }
    if (ImGui::CollapsingHeader("Tweakables"))
        for (Tweakable& tw : t.all()) tw.drawWidget();   // SliderFloat / SliderInt / Checkbox by type
    if (ImGui::CollapsingHeader("Performance"))
        ImGui::PlotLines("Frame ms", frameHistory.data(), frameHistory.size());
    ImGui::End();
}

ImGui is added with vcpkg (imgui[sdl2-binding,sdl2-renderer-binding], lesson 4.06), initialised once with the SDL window and renderer, and drawn last each frame, on top of the game. The menu opens with F1; while it has the mouse or keyboard focus, the game ignores that input (ImGui::GetIO().WantCaptureMouse and WantCaptureKeyboard).

Plugin sections

Plugins (lesson 13.04) can add their own sections: the host API gains addDebugSection(name, drawFunction, user), the game calls each registered draw function inside the menu, and unregisters it when the plugin unloads. A plugin author then gets a place for their own debugging tools without touching the game.

Keep it out of release builds

Like the console's cheat commands (lesson 11.07), the menu and every tweakable that changes gameplay are compiled only into development builds. Tweakables that are really player settings (volume, shake) move to the real settings screen instead.

Common mistakes

Tweaking values that are cached elsewhere

If a system copied g_sightRange at start-up, changing it does nothing. Read tweakables where they are used.

No limits on tweakables

A slider from 0 to a billion is useless and a typed value out of range can break the game. Give every tweakable a sensible range, and clamp.

The game reacting to clicks meant for the menu

Check ImGui's capture flags before passing input to the game.
