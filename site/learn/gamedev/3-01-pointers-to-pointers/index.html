Pointers to Pointers

lesson 3.011 of 10 in milestone 35 min1 practice task

A pointer is a variable, so it has an address too, and a pointer can hold that address. A pointer to a pointer lets a function change which object another pointer points at, and it is how arrays of pointers, command-line arguments and many Windows API "out" parameters work.

A pointer is just another variable

Lesson 1.03 showed that a pointer is a variable holding an address. Like every variable, the pointer itself lives somewhere in memory and has an address of its own. Nothing stops you storing that address in another variable:

C++
#include <iostream>

int main()
{
    int gold{ 250 };
    int* p{ &gold };       // p holds the address of gold
    int** pp{ &p };        // pp holds the address of p

    std::cout << "gold = " << gold << '\n';
    std::cout << "*p   = " << *p << '\n';
    std::cout << "**pp = " << **pp << '\n';

    **pp = 300;            // follow pp to p, follow p to gold, write there
    std::cout << "gold = " << gold << '\n';
    return 0;
}
Output
gold = 250
*p   = 250
**pp = 250
gold = 300

Read the types from the right: int** is a pointer to (a pointer to an int). Each * in an expression follows one arrow.

flowchart LR
    PP["pp<br/>holds &p"] -->|"*pp"| P["p<br/>holds &gold"]
    P -->|"*p, or **pp"| G["gold<br/>250"]
Expression Type Means
pp int** The address of p
*pp int* The value of p: the address of gold
**pp int The value of gold

In memory, all three are just numbers in boxes: pp's 8 bytes hold p's address, p's 8 bytes hold gold's address, and gold's 4 bytes hold 250.

Why you would want one: changing someone else's pointer

A function receives copies of its arguments. Pass it a pointer and it can change the thing pointed at, but not the caller's pointer itself. To change the caller's pointer, the function needs that pointer's address.

C++
#include <iostream>

struct Enemy { const char* name; int health; };

// Makes *target point at the weakest living enemy, or nullptr if none are alive.
void pickWeakest(Enemy* enemies, int count, Enemy** target)
{
    *target = nullptr;
    for (int i{ 0 }; i < count; ++i)
    {
        Enemy* e{ &enemies[i] };
        if (e->health > 0 && (*target == nullptr || e->health < (*target)->health))
            *target = e;
    }
}

int main()
{
    Enemy pack[]{ { "wolf", 30 }, { "bat", 0 }, { "rat", 12 } };
    Enemy* aim{ nullptr };
    pickWeakest(pack, 3, &aim);
    std::cout << "aiming at the " << aim->name << '\n';
    return 0;
}
Output
aiming at the rat

pickWeakest writes into *target, which is the caller's aim. This "out parameter" style is everywhere in C and in the Windows API, where functions return an error code and hand back the object they created through a pointer to your pointer. Chapter 5 is full of calls like this:

C++
// The function writes the new object's address into iface.
IUnknown* iface{ nullptr };
HRESULT hr{ CreateSomething(IID_PPV_ARGS(&iface)) };

In modern C++ code you would more often return the pointer, or pass Enemy*& (a reference to a pointer, lesson 3.03). But you need to read the ** form fluently.

Arrays of pointers

The other common use is an array whose elements are pointers. main can receive the program's command-line arguments that way:

C++
#include <iostream>

int main(int argc, char** argv)
{
    // argv points at an array of argc pointers, each pointing at one argument's characters.
    std::cout << "argc = " << argc << '\n';
    for (int i{ 1 }; i < argc; ++i)
        std::cout << "argument " << i << ": " << argv[i] << '\n';
    return 0;
}

Run with game.exe --level 3, argv[0] is the program's path, argv[1] points at "--level" and argv[2] at "3". argv[1][2] is 'l': index into the array of pointers, then into the characters.

argv ──▶ ┌─────────┐
         │ argv[0] │──▶ "C:\games\game.exe"
         ├─────────┤
         │ argv[1] │──▶ "--level"
         ├─────────┤
         │ argv[2] │──▶ "3"
         ├─────────┤
         │ nullptr │
         └─────────┘

Arrays of pointers also let you sort or reorder large objects cheaply: shuffle 8-byte pointers instead of copying the objects.

Pointer arithmetic still works one level down

argv + 1 moves along the array of pointers by one pointer (8 bytes). *(argv + 1) + 2 moves along the characters of the second argument by two characters. Each level has its own element size, and pointer arithmetic always uses the size of the thing pointed at.

Common mistakes

Passing the pointer when the function needs its address

pickWeakest(pack, 3, aim) does not compile, which is good. With void* parameters it might, and then the function writes over the wrong thing. Match the number of *s.

[!warning] Forgetting the parentheses in (*target)->health *target->health means *(target->health), which is something else entirely.

Following a null pointer at either level

Check pp before *pp, and *pp before **pp.
