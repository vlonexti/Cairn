A Live Stats Panel for Your Game

lesson 12.055 of 7 in milestone 125 min1 practice task

With Delve publishing its telemetry, a separate tool can show it live: frame times with a graph, the floor, the player's health and position, how many monsters are alive. This lesson builds that tool as a console program (chapter 14 gives it a graphical interface): finding running copies of the game, reading snapshots on a timer, keeping a history for graphs, and coping when the game starts, stops or restarts.

Every value comes from one consistent snapshot (lesson 12.04). The graph shows the last 60 frame times, scaled so the slowest is the tallest bar, and the spike in it is exactly the kind of stutter lesson 8.08 warned about, now visible while playing.

Finding the game

The telemetry block's name includes the game's process id (lesson 12.04), so the tool:

  1. Lists processes named delve.exe (lesson 6.07's snapshot).
  2. For each, tries OpenFileMappingW(FILE_MAP_READ, FALSE, L"Local\\Delve.Telemetry.<pid>").
  3. Maps the first that opens and checks magic, version and size before reading anything else (lesson 12.06 covers what to do with versions it does not know).

If several copies are running, it can show a list to choose from.

The read loop

C++
while (running)
{
    TelemetryV1 snap{};
    if (!connected) tryConnect();
    else if (!readSnapshot(block, snap)) showStatus("busy");          // retries exhausted (lesson 12.04)
    else if (snap.frame == lastFrame) staleFor += interval;           // the game is paused, or frozen
    else { staleFor = 0; lastFrame = snap.frame; history.push(snap.frameMs); draw(snap, history); }

    if (connected && !processStillRunning(pid)) disconnect();         // the game exited: start looking again
    Sleep(100);                                                       // 10 updates a second is plenty for people
}

Three states matter and should be shown clearly:

State Detect Show
Connected and live The frame number advances The values
Connected but stale The frame number has not changed for a second "paused or not responding", values greyed out
Not connected No mapping found, or the process exited "waiting for Delve...", and keep looking

Checking whether the process is still running uses a process handle opened with SYNCHRONIZE and WaitForSingleObject(handle, 0) (lesson 6.01: a process handle is signalled when it exits). The mapping itself stays valid while the tool has it open, even after the game exits, so the frame counter alone cannot tell "exited" from "frozen".

Drawing in the console

Lesson 5.09's techniques do the drawing: enable virtual terminal sequences, build the whole screen into one string starting with "cursor home", and write it in one call so it never flickers. The bars use the Unicode block characters ▁▂▃▄▅▆▇█, written in UTF-8 after SetConsoleOutputCP(CP_UTF8). The practice task computes the statistics and the bar characters from the history.

Common mistakes

Treating an unchanged frame number as "the game exited"

It also means paused or frozen. Check the process handle separately.

Reading as fast as possible

People cannot read 1,000 updates a second, and it wastes a core. 10 to 30 per second is plenty.

Crashing when the game restarts

Unmap, close and go back to searching; the new copy has a new process id and a new block.
