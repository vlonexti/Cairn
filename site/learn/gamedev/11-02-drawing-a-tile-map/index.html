Drawing a Tile Map

lesson 11.022 of 8 in milestone 115 min1 practice task

Delve's world is a grid of tiles stored in a flat array (lesson 2.07) and loaded from a plain text file (lesson 10.08), where each character is a tile and special characters mark where the player and monsters start. This lesson writes the level format, the loader with validation, and the renderer that draws the visible part of the map around a camera.

The level format

Levels are text files that anyone can edit in Notepad:

Output
# data/levels/01.txt: the first floor
##########
#@...#..g#
#....#...#
#..k.+...#
#....#..>#
##########
Character Meaning
# Wall
. Floor
+ Door (closed; opens when walked into)
> Stairs down to the next level
@ Player start (floor underneath)
g, k, t A goblin, kobold or troll start (floor underneath)

Lines starting with # followed by a space are comments. Every map row must be the same width.

The tile map

C++
// tilemap.h
#pragma once
#include <string>
#include <vector>

enum class Tile : unsigned char { Floor, Wall, Door, Stairs };

struct Spawn { char kind; int x; int y; };

class TileMap
{
public:
    int width() const { return m_width; }
    int height() const { return m_height; }
    bool inside(int x, int y) const { return x >= 0 && y >= 0 && x < m_width && y < m_height; }
    Tile at(int x, int y) const { return inside(x, y) ? m_tiles[static_cast<size_t>(y * m_width + x)] : Tile::Wall; }
    void set(int x, int y, Tile t) { if (inside(x, y)) m_tiles[static_cast<size_t>(y * m_width + x)] = t; }
    bool walkable(int x, int y) const { const Tile t{ at(x, y) }; return t == Tile::Floor || t == Tile::Stairs; }

    int m_width{ 0 }, m_height{ 0 };
    std::vector<Tile> m_tiles;                  // row-major: index = y * width + x
};

Note at returns Wall outside the map: anything that asks about a tile beyond the edge gets a sensible answer instead of an out-of-bounds read, which removes a whole class of bugs (lesson 2.09) from the movement and AI code.

Loading with validation

Loading follows lesson 10.08's rules: read line by line, skip comments, and report problems with a line number. The practice task writes parseLevel, which turns the text into a TileMap, the player's start and a list of monster spawns, and rejects levels that are ragged, have no player or several players, or contain unknown characters.

Drawing it

Each tile is drawn as a 32-pixel square. Lesson 10.04's camera keeps the player in the middle of the screen, and culling skips tiles that are off screen:

C++
// render.cpp
#include <SDL.h>
#include "tilemap.h"

constexpr int kTile{ 32 };

void drawMap(SDL_Renderer* r, const TileMap& map, float cameraX, float cameraY, int screenW, int screenH)
{
    // Which tiles can be on screen? Only loop over those (culling, lesson 10.04).
    const int firstX{ std::max(0, static_cast<int>((cameraX - screenW / 2.0f) / kTile)) };
    const int firstY{ std::max(0, static_cast<int>((cameraY - screenH / 2.0f) / kTile)) };
    const int lastX{ std::min(map.width() - 1, static_cast<int>((cameraX + screenW / 2.0f) / kTile)) };
    const int lastY{ std::min(map.height() - 1, static_cast<int>((cameraY + screenH / 2.0f) / kTile)) };

    for (int y{ firstY }; y <= lastY; ++y)                 // rows outside, columns inside (lesson 2.07)
    {
        for (int x{ firstX }; x <= lastX; ++x)
        {
            switch (map.at(x, y))
            {
            case Tile::Wall:   SDL_SetRenderDrawColor(r, 58, 63, 72, 255); break;
            case Tile::Floor:  SDL_SetRenderDrawColor(r, 26, 29, 35, 255); break;
            case Tile::Door:   SDL_SetRenderDrawColor(r, 140, 98, 57, 255); break;
            case Tile::Stairs: SDL_SetRenderDrawColor(r, 240, 198, 116, 255); break;
            }
            const SDL_Rect cell{ static_cast<int>(x * kTile - cameraX + screenW / 2.0f),
                                 static_cast<int>(y * kTile - cameraY + screenH / 2.0f), kTile - 1, kTile - 1 };
            SDL_RenderFillRect(r, &cell);
        }
    }
}

Coloured squares are enough to play with. To use artwork, load one tile sheet image with SDL_image (vcpkg add port sdl2-image) into an SDL_Texture, and draw each tile with SDL_RenderCopy from the right part of the sheet: one texture shared by every tile, which is lesson 10.04's batching in practice.

Common mistakes

[!warning] Indexing with x * height + y Row-major storage is y * width + x (lesson 2.07).

Trusting level files

Validate shape and characters on load, with line numbers in the messages.

Drawing every tile of a huge map

Loop only over the tiles that can be on screen.

  3. How does the renderer avoid drawing off-screen tiles?
