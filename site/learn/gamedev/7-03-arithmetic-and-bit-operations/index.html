Arithmetic and Bit Operations

lesson 7.033 of 11 in milestone 77 min1 practice task

The arithmetic instructions (add, sub, imul, inc, dec, neg, div) and the bit instructions (and, or, xor, not, shl, shr, sar) are the processor's whole calculator. This lesson covers each, the flags they set as a side effect, and the tricks compilers use, such as replacing division by a constant with multiplication.

The two-operand pattern

x64 arithmetic usually has two operands, and the result replaces the first:

Instruction Effect C++
add a, b a = a + b a += b
sub a, b a = a - b a -= b
imul a, b a = a × b (signed, keeps the low bits) a *= b
imul a, b, 7 a = b × 7 (three-operand form) a = b * 7
inc a / dec a a = a ± 1 ++a / --a
neg a a = -a a = -a

There is no separate instruction for unsigned multiplication of the kind C++ needs: since the low bits of a product are the same either way (two's complement again), imul serves both.

The flags

Most arithmetic and logic instructions also set bits in the flags register describing their result. Four matter most:

Flag Set when the result...
ZF (zero) is zero
SF (sign) has its top bit set: negative, read as signed
CF (carry) did not fit as an unsigned number (a carry out of, or borrow into, the top bit)
OF (overflow) did not fit as a signed number

Watch them change. The first add overflows as signed (127 + 1 in a byte), the second as unsigned:

Interactive demo. This part of the lesson is a working model you can step through in Xenon. Try it in Xenon
  • 127 + 1 in a byte is 0x80: SF set (negative as signed), OF set (signed overflow), CF clear (128 fits unsigned).
  • 255 + 1 is 0 with a carry out: ZF and CF set (unsigned overflow), OF clear.
  • 5 - 5 is 0: ZF set.

The processor does not know whether your bytes are signed or unsigned. It computes the bits once and reports both kinds of overflow; the next instruction decides which flags it cares about. Lesson 7.04 uses this for comparisons.

Division

div (unsigned) and idiv (signed) are the odd ones out. They divide the double-width value in rdx:rax (or edx:eax) by the operand, putting the quotient in rax and the remainder in rdx:

Assembly
mov   eax, ecx        ; the number to divide
cdq                   ; sign-extend eax into edx:eax
idiv  r8d             ; eax = quotient, edx = remainder

Division is slow: tens of cycles, against one for an add. Dividing by zero, or INT_MIN / -1, raises an exception (integer divide by zero, code 0xC0000094). So compilers avoid div whenever they can:

C++ What the compiler emits
x / 8 (unsigned) shr eax, 3
x % 8 (unsigned) and eax, 7
x / 10 (unsigned) A multiplication by a "magic" constant (0xCCCCCCCD) and a shift
x / 8 (signed) A shift plus a small correction so negative numbers round towards zero

When you see a strange large constant multiplied and then shifted in compiler output, it is almost always division by a constant.

Bit operations

Instruction Effect Typical use
and a, b Keep bits set in both Masking: x & 0xFF, testing flags
or a, b Set bits set in either Combining flags
xor a, b Flip bits set in b Toggling; xor eax, eax sets eax to zero
not a Flip every bit ~x
shl a, n Shift left by n: multiply by 2ⁿ x << n
shr a, n Shift right, filling with zeros: unsigned divide by 2ⁿ x >> n for unsigned
sar a, n Shift right, copying the sign bit x >> n for signed

xor eax, eax deserves a mention because it is everywhere: XOR of anything with itself is zero, and the instruction is shorter than mov eax, 0. Whenever you see it, read "eax = 0".

Bit tricks are everywhere in game and systems code: packing flags into one integer, extracting fields (lesson 5.07's lParam), hashing (lesson 3.08), rounding up to alignment (lesson 2.02's arena).

Common mistakes

Reading CF as "the result was negative"

CF is unsigned overflow. "Negative" is SF.

[!warning] Assuming shr and sar are interchangeable For negative numbers they differ: sar keeps the sign, shr makes the number large and positive.

[!warning] Forgetting that div uses rdx Code that divides must set up rdx first (cdq, cqo, or xor edx, edx), and the remainder overwrites it.

Knowledge check

quizIn Xenon your best score is kept.
  1. After mov al, 200 then add al, 100, which flag tells you the unsigned result did not fit?
    • CF
    • OF
    • ZF
    Show the answer

    CF 300 does not fit in a byte; the carry out of the top bit sets CF.

  2. What does xor ecx, ecx do?
    • Sets ecx to zero
    • Flips every bit of ecx
    • Leaves ecx unchanged
    Show the answer

    Sets ecx to zero Any value XOR itself is 0. It is the usual way to zero a register.

  3. A compiler turned n / 16 into shr eax, 4. What does that tell you about n?
    • It is unsigned (for a signed value, a correction for negative numbers would be needed)
    • It is a float
    • It is always zero
    Show the answer

    It is unsigned (for a signed value, a correction for negative numbers would be needed) A logical right shift divides an unsigned number by a power of two.

  4. Which instruction shifts right while keeping the sign of a negative number?
    • shr
    • sar
    • shl
    Show the answer

    sar Arithmetic shift right copies the sign bit into the new top bits.
