Registers and the Shape of an Instruction

lesson 7.011 of 11 in milestone 77 min1 practice task

x64 assembly is the text form of the machine code your C++ becomes. This chapter teaches you to read it, and occasionally to write it. It starts with the registers, the processor's handful of built-in variables, their 64, 32, 16 and 8-bit names, and the shape every instruction follows: an operation and its operands.

Why learn to read assembly

You will rarely write assembly. You will read it often:

  • in the debugger's Disassembly window, when a crash happens in code without source, or in optimised code where the source view no longer matches what runs (lesson 4.10);
  • in compiler output, to see what your C++ really costs (lesson 7.11);
  • in reverse engineering, where it is all there is (chapter 9).

The tiny computer of lesson 1.01 had one register and seven instructions. An x64 processor has the same ideas on a larger scale.

The general-purpose registers

x64 has sixteen 64-bit general-purpose registers. Each is a variable built into the processor: reading and writing them takes no memory access at all.

Register Traditional role In the Windows calling convention (lesson 7.06)
rax Accumulator Return value
rbx Base Must be preserved by functions
rcx Counter 1st integer argument
rdx Data 2nd integer argument
rsi Source index Must be preserved
rdi Destination index Must be preserved
rbp Base pointer Must be preserved; sometimes the frame pointer
rsp Stack pointer The top of the stack (lesson 1.05)
r8, r9 3rd and 4th integer arguments
r10, r11 Scratch
r12 to r15 Must be preserved

There are also special registers: rip (the instruction pointer, the program counter of lesson 1.01), rflags (the flags, lesson 7.04), and sixteen 128-bit xmm registers for floating point (lesson 7.09).

So an int (4 bytes) usually lives in an e register, a char or bool in an 8-bit one, a pointer or long long in a full r register.

One rule surprises everyone once: writing a 32-bit register clears the upper 32 bits of the 64-bit register. Writing 8 or 16 bits leaves the rest unchanged. Compilers rely on this constantly: mov eax, 1 is a shorter instruction than mov rax, 1 and has the same effect.

The shape of an instruction

Each line of assembly is one instruction: an operation (the mnemonic) and up to two or three operands. In the syntax Microsoft's tools use (Intel syntax), the destination comes first:

Assembly
mov   eax, 5          ; eax = 5
add   eax, ecx        ; eax = eax + ecx
mov   [rsp+8], eax    ; the 4 bytes at address rsp+8 = eax

An operand is one of three kinds:

Kind Example Means
Register ecx The value in a register
Immediate 5, 0FFh, -1 A constant stored inside the instruction itself (lesson 1.04 saw 0x32 inside an lea)
Memory [rsp+8], dword ptr [rcx] The value at an address, worked out from registers and constants

Most instructions allow at most one memory operand: there is no "add memory to memory". Values are brought into registers, worked on, and written back, just like the tiny computer's LOAD, ADD, STORE.

  • After mov al, 7 and mov ax, 300, only the low bits change: rax was all ones (-1), and its upper bytes stay ones.

  • ret ends the function, and whoever called it finds its answer in rax.
Two syntaxes

Microsoft's tools and most Windows debuggers use Intel syntax (destination first, mov eax, 5). Linux tools default to AT&T syntax (movl $5, %eax: source first, % before registers, $ before constants). They are the same instructions written differently. This course uses Intel syntax throughout.

Common mistakes

Reading operands in the wrong order

In Intel syntax, mov a, b copies b into a. The destination is first.

Forgetting that writing a 32-bit register zeroes the top half

mov eax, -1 leaves rax as 0x00000000FFFFFFFF, not -1.

Expecting two memory operands

add [a], [b] does not exist. One side must be a register or a constant.
