Setting Up Dear ImGui

lesson 14.022 of 6 in milestone 145 min

Dear ImGui is a small, widely used C++ library for immediate-mode interfaces. It does not draw anything itself: back ends connect it to a platform (for windows and input) and a renderer (for drawing). This lesson sets it up with vcpkg and the SDL2 back ends used by Delve, explains the per-frame calls, fonts and DPI scaling, and builds a standalone tool application for chapter 12's tools.

How ImGui is put together

flowchart LR
    Y["Your code<br/>ImGui::Button, SliderFloat ..."] --> C["ImGui core<br/>layout, ids, state;<br/>produces draw lists of triangles"]
    P["Platform back end<br/>imgui_impl_sdl2<br/>(input, window size, clipboard)"] --> C
    C --> R["Renderer back end<br/>imgui_impl_sdlrenderer2<br/>(or DirectX 11, OpenGL, Vulkan ...)"]
    R --> S["Screen"]

The core turns widget calls into draw lists (triangles, textures, clip rectangles); a renderer back end submits them with whatever graphics API the program uses (lesson 10.04). Back ends exist for SDL, Win32, GLFW, DirectX 9 to 12, OpenGL, Vulkan, Metal and more, so ImGui fits into almost any engine.

Installing

In the project's vcpkg.json (lesson 4.06):

Terminal
vcpkg add port imgui[sdl2-binding,sdl2-renderer-binding]

The features in brackets build the SDL2 platform back end and the SDL renderer back end along with the core.

The setup and the frame

C++
#define SDL_MAIN_HANDLED
#include <SDL.h>
#include <imgui.h>
#include <imgui_impl_sdl2.h>
#include <imgui_impl_sdlrenderer2.h>

int main()
{
    SDL_Init(SDL_INIT_VIDEO);
    SDL_Window* window{ SDL_CreateWindow("Delve Tools", SDL_WINDOWPOS_CENTERED, SDL_WINDOWPOS_CENTERED, 1280, 800,
                                         SDL_WINDOW_RESIZABLE | SDL_WINDOW_ALLOW_HIGHDPI) };
    SDL_Renderer* renderer{ SDL_CreateRenderer(window, -1, SDL_RENDERER_ACCELERATED | SDL_RENDERER_PRESENTVSYNC) };

    IMGUI_CHECKVERSION();
    ImGui::CreateContext();
    ImGuiIO& io{ ImGui::GetIO() };
    io.ConfigFlags |= ImGuiConfigFlags_NavEnableKeyboard;      // keyboard navigation
    ImGui::StyleColorsDark();
    ImGui_ImplSDL2_InitForSDLRenderer(window, renderer);
    ImGui_ImplSDLRenderer2_Init(renderer);

    bool running{ true };
    while (running)
    {
        SDL_Event e;
        while (SDL_PollEvent(&e))
        {
            ImGui_ImplSDL2_ProcessEvent(&e);                       // ImGui sees every event first
            if (e.type == SDL_QUIT) running = false;
        }

        ImGui_ImplSDLRenderer2_NewFrame();                         // 1. start the frame
        ImGui_ImplSDL2_NewFrame();
        ImGui::NewFrame();

        ImGui::ShowDemoWindow();                                   // 2. describe the interface
        ImGui::Begin("Hello");
        ImGui::Text("Frame time %.2f ms", 1000.0f / io.Framerate);
        ImGui::End();

        ImGui::Render();                                           // 3. build the draw lists
        SDL_SetRenderDrawColor(renderer, 18, 20, 26, 255);
        SDL_RenderClear(renderer);
        ImGui_ImplSDLRenderer2_RenderDrawData(ImGui::GetDrawData(), renderer);   // 4. draw them
        SDL_RenderPresent(renderer);
    }

    ImGui_ImplSDLRenderer2_Shutdown();                             // shut down in reverse order
    ImGui_ImplSDL2_Shutdown();
    ImGui::DestroyContext();
    SDL_DestroyRenderer(renderer);
    SDL_DestroyWindow(window);
    SDL_Quit();
}

Every ImGui program has these four steps per frame: new frame, describe, render, draw. In a game (lesson 13.06) the same steps run after the game has drawn its own frame, so the interface sits on top.

The demo window

ImGui::ShowDemoWindow() shows every widget ImGui has, each with a short explanation. Its source, imgui_demo.cpp, is the best reference there is: when you want a widget, find it in the demo window, then find the code that drew it. Keep the demo one menu click away in every tool you write.

Fonts and DPI

ImGui's built-in font is small and sharp at 100% display scaling. On high-DPI screens (laptops at 150%, 4K monitors) load a proper font at a size scaled for the display:

C++
const float scale{ dpiScaleForWindow(window) };       // e.g. from SDL_GetDisplayDPI / 96
io.Fonts->AddFontFromFileTTF("fonts/Inter-Regular.ttf", 16.0f * scale);
ImGui::GetStyle().ScaleAllSizes(scale);

Include the font file with the tool, under its own licence (Inter, for example, uses the SIL Open Font License).

Input sharing

ImGui_ImplSDL2_ProcessEvent gives ImGui every event. In a game, check io.WantCaptureMouse and io.WantCaptureKeyboard before the game uses an event (lesson 13.06); in a standalone tool, ImGui is the whole interface and there is nothing to share.

Common mistakes

Forgetting one of the four frame steps

Missing NewFrame or Render produces assertion failures or nothing on screen.

Calling ImGui functions outside a frame

Widget calls are only valid between NewFrame and Render.

Blurry or tiny text on high-DPI screens

Load a real font at a scaled size and scale the style.
