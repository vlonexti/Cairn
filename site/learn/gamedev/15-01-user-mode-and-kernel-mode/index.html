User Mode and Kernel Mode

lesson 15.011 of 8 in milestone 155 min

Lesson 1.06 introduced the kernel as the part of Windows with full control of the hardware. This chapter looks inside. It starts with the boundary itself: the processor's privilege levels, what runs in kernel mode (the kernel, the HAL, drivers), how kernel memory is shared by all processes, and why code running there must be held to a far higher standard than anything in user mode.

Two privilege levels

x64 processors have hardware privilege levels, called rings. Windows uses two:

Ring Mode What runs there What it can do
0 Kernel mode The Windows kernel, the hardware abstraction layer, device drivers Everything: any memory, any instruction, the hardware
3 User mode Every application, including games and most services Only its own address space; privileged instructions fault; hardware only through the kernel

The processor itself enforces the difference. In ring 3, instructions that control the hardware (disabling interrupts, loading page tables, talking to devices directly) cause an exception, and pages marked "supervisor only" in the page tables (lesson 6.02) cannot be touched. The only way up is a controlled gate: the system call (lesson 15.02).

  • ntoskrnl.exe holds the executive (the managers this chapter covers: objects, memory, I/O, processes, security) and the kernel proper (scheduling, interrupts, low-level synchronisation).
  • hal.dll, the hardware abstraction layer, hides differences between motherboards and interrupt controllers.
  • Drivers (.sys files) are kernel modules: PE files like DLLs (lesson 9.02), loaded into kernel space, extending the kernel with support for devices and file systems.
  • win32k.sys is the kernel side of windows and graphics (lesson 5.05's messages are partly managed here).

One kernel address space, shared by everything

Lesson 6.02 showed each process's private lower half of the address space. The upper half is kernel space, and it is the same in every process: the kernel, every driver, and the kernel's data (the pools, lesson 15.04) are mapped at the same kernel addresses whichever process is running. Pages there are marked supervisor-only, so user code cannot touch them, but all kernel-mode code can touch all of it.

That sharing is the key to the rest of this chapter:

  • A driver's global variable is one variable for the whole machine, not per process.
  • A driver writing through a bad pointer can corrupt the kernel, other drivers, or any process's data, because there is no boundary between kernel components.
  • There is no "this driver crashed, the rest carries on". An unhandled fault in kernel mode means the system cannot know what else is damaged, so Windows stops the machine with a bug check (the blue screen, lesson 15.07).

The standard kernel code is held to

In user mode, a crash ends one process and the operating system cleans up (lesson 1.06). In kernel mode:

User mode Kernel mode
A crash ends the process A crash stops the whole machine
A leak is freed when the process exits A leak lasts until reboot
Bad pointers fault in your own space Bad pointers can silently corrupt anything
Many runtime libraries and C++ features available A restricted environment: no standard library, careful exceptions, limited stack (lesson 16.02)
Debug with Visual Studio on the same machine Debug from a second machine or a VM's host (lesson 15.08)

That is why the rest of this course treats kernel work as something done only in a virtual machine, only with drivers you write for learning, with testing tools turned on, and why production drivers go through extensive testing and Microsoft's signing requirements (lesson 16.09).

Common mistakes

Thinking a driver is "like a DLL that runs as administrator"

It runs in ring 0 with the whole kernel's memory reachable. The rules, and the consequences of mistakes, are different.

Assuming kernel globals are per process

Kernel space is shared; a driver's globals are machine-wide.

Experimenting with kernel code on your main PC

Use a virtual machine you can restore (lesson 15.08).
