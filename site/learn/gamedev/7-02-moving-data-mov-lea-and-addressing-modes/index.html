Moving Data: mov, lea and Addressing Modes

lesson 7.022 of 11 in milestone 75 min1 practice task

Most instructions in real code just move data: between registers, from memory into a register, from a register back to memory. This lesson covers mov and its widening relatives movzx and movsx, the addressing modes that let one instruction compute an address like base + index × scale + offset, and lea, which does that arithmetic without touching memory at all.

mov

mov destination, source copies a value. It never changes the source and never sets the flags.

Assembly
mov   eax, 10                  ; constant into a register
mov   ecx, eax                 ; register to register
mov   eax, dword ptr [rcx]     ; 4 bytes from memory at the address in rcx, into eax
mov   qword ptr [rsp+20h], rax ; 8 bytes from rax into memory at rsp+0x20
mov   byte ptr [rdx], 1        ; the constant 1 into one byte of memory

The size comes from the register (eax is 4 bytes, rax 8). When there is no register to tell it (a constant stored to memory), the size is written out: byte ptr, word ptr (2), dword ptr (4), qword ptr (8). Disassemblers show the ptr sizes on every memory operand, which is a gift when reading code: dword ptr [rcx+8] tells you there is a 4-byte value 8 bytes into whatever rcx points at.

Widening: movzx and movsx

Loading a 1-byte char or 2-byte short into a 32-bit register needs to fill the extra bits, and how depends on whether the type is signed:

Instruction Fills the new upper bits with For
movzx eax, byte ptr [rcx] Zeros (zero extension) unsigned char, bool, std::uint16_t
movsx eax, byte ptr [rcx] Copies of the sign bit (sign extension) signed char, short
movsxd rax, ecx Sign extension from 32 to 64 bits int to long long or to an index

The byte 0xFF becomes 255 with movzx and -1 with movsx. This is two's complement from lesson 1.02, done by hardware.

Addressing modes

A memory operand can compute its address from up to four parts:

Output
[ base + index × scale + displacement ]
   reg    reg    1,2,4,8   constant
Form Typical C++
[rcx] *p
[rcx+8] p->member at offset 8 (lesson 2.06)
[rcx+rdx*4] array[i] for 4-byte elements: base address rcx, index rdx
[rcx+rdx*8+10h] p->items[i] where items is an array of 8-byte values at offset 0x10
[rip+1234h] A global variable, relative to the instruction (lesson 6.09)

The scale can only be 1, 2, 4 or 8: exactly the sizes of char, short, int/float and pointers/double. Indexing arrays of those types costs no extra instructions at all.

lea: the address calculator

lea ("load effective address") computes the address of a memory operand and puts the address itself into the destination, without reading memory:

Assembly
lea   rax, [rcx+rdx*4]      ; rax = rcx + rdx*4         (&array[i])
lea   rax, [rcx+10h]        ; rax = rcx + 16            (&p->member)
lea   rcx, [rip+1F2Ah]      ; rcx = the address of a global or string literal

Because the address hardware can add two registers, scale one of them and add a constant in a single step, compilers also use lea for plain arithmetic that has nothing to do with addresses:

C++ Compiled
x + 50 (into a different register) lea eax, [rcx+32h] (lesson 1.04's example)
a + b lea eax, [rcx+rdx]
x * 5 lea eax, [rcx+rcx*4]
x * 9 + 3 lea eax, [rcx+rcx*8+3]

When you see lea in compiler output, ask whether it is computing a pointer or just doing quick arithmetic. Both are common.

Common mistakes

[!warning] Confusing mov rax, [rcx] with lea rax, [rcx] mov reads the 8 bytes at the address; lea puts the address itself in rax. One is *p, the other is p.

[!warning] Reading [rcx+rdx*4] as "rcx plus rdx plus 4" The *4 scales the index: it is element rdx of an array of 4-byte values.

[!warning] Assuming mov sets flags It does not. A comparison needs cmp or test.

Knowledge check

quizIn Xenon your best score is kept.
  1. What does mov eax, dword ptr [rcx+8] do?
    • Copies the 4 bytes at address rcx+8 into eax
    • Sets eax to rcx+8
    • Adds 8 to the value at rcx
    Show the answer

    Copies the 4 bytes at address rcx+8 into eax The brackets read memory; lea would compute the address instead.

  2. The byte at [rdx] is 0xFE. What does movsx eax, byte ptr [rdx] put in eax?
    • -2
    • 254
    • 0xFE000000
    Show the answer

    -2 Sign extension copies the top bit, so 0xFE as a signed byte, -2, stays -2.

  3. Which C++ expression is [rcx+rdx*8] most likely to come from?
    • p[i] where p points at 8-byte values such as pointers or doubles
    • p + i + 8
    • p->member at offset 8
    Show the answer

    p[i] where p points at 8-byte values such as pointers or doubles Base, index and a scale equal to the element size: array indexing.

  4. Why might a compiler emit lea eax, [rcx+rcx*2]?
    • To compute x * 3 in one instruction
    • To read memory at x * 3
    • To compare x with 3
    Show the answer

    To compute x * 3 in one instruction lea does arithmetic with the address hardware and never touches memory.
