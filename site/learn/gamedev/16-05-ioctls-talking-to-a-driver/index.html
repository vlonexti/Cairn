IOCTLs: Talking to a Driver

lesson 16.055 of 10 in milestone 165 min1 practice task

Reads and writes move bytes; most driver interfaces need commands: "echo this", "give me your statistics", "reset". Those are I/O control codes (IOCTLs), sent with DeviceIoControl and received as IRP_MJ_DEVICE_CONTROL. This lesson explains how a control code packs device type, function, buffering method and required access into 32 bits, and writes the driver's dispatch routine for the echo driver's commands.

Control codes

An IOCTL is a 32-bit number built by the CTL_CODE macro from four fields:

 31        16 15  14 13                 2 1    0
┌────────────┬──────┬────────────────────┬──────┐
│ DeviceType │Access│     Function       │Method│
│  (16 bits) │ (2)  │     (12 bits)      │ (2)  │
└────────────┴──────┴────────────────────┴──────┘
Field Meaning
DeviceType The device's type, as passed to IoCreateDevice. Values below 0x8000 are reserved for Microsoft; your own drivers use 0x8000 and up
Function Which command. Values 0x800 and up are for vendors
Method How buffers are passed: METHOD_BUFFERED (0), METHOD_IN_DIRECT (1), METHOD_OUT_DIRECT (2), METHOD_NEITHER (3); lesson 16.07
Access The access the caller's handle must have: FILE_ANY_ACCESS (0), FILE_READ_ACCESS (1), FILE_WRITE_ACCESS (2), or both (3)
C++
// echo_ioctl.h: shared by the driver and the client, like lesson 13.03's plugin header.
#define ECHO_DEVICE_TYPE 0x8001
#define IOCTL_ECHO_PING   CTL_CODE(ECHO_DEVICE_TYPE, 0x800, METHOD_BUFFERED, FILE_ANY_ACCESS)
#define IOCTL_ECHO_ECHO   CTL_CODE(ECHO_DEVICE_TYPE, 0x801, METHOD_BUFFERED, FILE_READ_ACCESS | FILE_WRITE_ACCESS)
#define IOCTL_ECHO_STATS  CTL_CODE(ECHO_DEVICE_TYPE, 0x802, METHOD_BUFFERED, FILE_READ_ACCESS)

struct EchoStats { unsigned long long requests; unsigned long long bytesEchoed; };

The access bits are enforced by the I/O manager before the driver ever sees the request: a handle opened without write access cannot send IOCTL_ECHO_ECHO. Choosing them carefully is part of the driver's security (lesson 16.04). The practice task encodes and decodes these codes.

The dispatch routine

C++
NTSTATUS EchoDeviceControl(PDEVICE_OBJECT device, PIRP irp)
{
    auto* state{ static_cast<EchoState*>(device->DeviceExtension) };
    const PIO_STACK_LOCATION stack{ IoGetCurrentIrpStackLocation(irp) };
    const auto& p{ stack->Parameters.DeviceIoControl };
    NTSTATUS status{ STATUS_INVALID_DEVICE_REQUEST };
    ULONG_PTR information{ 0 };

    switch (p.IoControlCode)
    {
    case IOCTL_ECHO_PING:
        status = STATUS_SUCCESS;
        break;

    case IOCTL_ECHO_STATS:
        if (p.OutputBufferLength < sizeof(EchoStats)) { status = STATUS_BUFFER_TOO_SMALL; break; }
        // METHOD_BUFFERED: the I/O manager gave us one system buffer for input and output (lesson 16.07).
        *static_cast<EchoStats*>(irp->AssociatedIrp.SystemBuffer) = state->stats;
        information = sizeof(EchoStats);
        status = STATUS_SUCCESS;
        break;

    case IOCTL_ECHO_ECHO:
        status = EchoEcho(state, irp, p, information);     // lesson 16.07 writes this, carefully
        break;
    }

    irp->IoStatus.Status = status;
    irp->IoStatus.Information = information;            // how many bytes to copy back to the caller
    IoCompleteRequest(irp, IO_NO_INCREMENT);
    return status;
}

// in DriverEntry:
driver->MajorFunction[IRP_MJ_DEVICE_CONTROL] = EchoDeviceControl;
  • Unknown codes fall through to STATUS_INVALID_DEVICE_REQUEST. Never assume a code is one you know.
  • Every length is checked before any buffer is touched (lesson 16.07 is entirely about this).
  • Information tells the I/O manager how many bytes of the output to copy back for METHOD_BUFFERED; it must never exceed the output length.
  • Updating state->stats from several processors at once needs synchronisation: interlocked operations (InterlockedIncrement64) or a lock (lesson 15.06).

Common mistakes

[!warning] Function numbers below 0x800 or device types below 0x8000 Those ranges are reserved for Microsoft.

[!warning] FILE_ANY_ACCESS for commands that change state Require the access the operation needs, so read-only handles cannot perform it.

Trusting the control code

Handle only codes you define; everything else returns STATUS_INVALID_DEVICE_REQUEST.
