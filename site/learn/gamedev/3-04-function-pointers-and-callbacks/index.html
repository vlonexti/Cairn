Function Pointers and Callbacks

lesson 3.044 of 10 in milestone 36 min1 practice task

Functions live in memory too, so they have addresses, and a variable can hold one. A function pointer lets code decide at run time which function to call: the basis of callbacks, command tables, state machines and plugin systems. This lesson covers raw function pointers, std::function and lambdas, and what each costs.

A function has an address

Lesson 1.04 showed that a function is a run of machine-code bytes in the .text section. Calling it means jumping to its first byte. That address can be stored in a variable, passed around and called later.

C++
#include <iostream>

int doubleIt(int x) { return x * 2; }
int squareIt(int x) { return x * x; }

int main()
{
    int (*op)(int){ &doubleIt };      // op is a pointer to a function taking int and returning int
    std::cout << op(7) << '\n';

    op = &squareIt;                    // aim it at a different function
    std::cout << op(7) << '\n';

    std::cout << "doubleIt lives at " << reinterpret_cast<void*>(&doubleIt) << '\n';
    return 0;
}
Output (yours will differ)
14
49
doubleIt lives at 00007FF6E1A21082

The declaration syntax is awkward. Read int (*op)(int) as "op is a pointer to a function that takes an int and returns an int". A type alias makes it readable:

C++
using UnaryOp = int (*)(int);
UnaryOp op{ &doubleIt };

In assembly, a normal call is call doubleIt, with the address fixed when the program is linked. A call through a pointer is call rax (or call qword ptr [...]): the address is read from a register or memory at run time. That small difference is what makes everything in this lesson possible.

Callbacks: letting the caller decide

A callback is a function you pass to other code for it to call. The standard library's algorithms are built on them, and so are event systems.

C++
#include <iostream>
#include <vector>

struct Enemy { const char* name; int health; bool flying; };

// Calls visit for every enemy that matches.
void forEachEnemy(const std::vector<Enemy>& enemies, bool (*matches)(const Enemy&), void (*visit)(const Enemy&))
{
    for (const Enemy& e : enemies)
        if (matches(e)) visit(e);
}

bool isFlying(const Enemy& e) { return e.flying; }
void printName(const Enemy& e) { std::cout << e.name << '\n'; }

int main()
{
    std::vector<Enemy> enemies{ { "bat", 8, true }, { "rat", 5, false }, { "wasp", 3, true } };
    forEachEnemy(enemies, &isFlying, &printName);
    return 0;
}
Output
bat
wasp

forEachEnemy knows nothing about flying or printing. The caller supplies both decisions.

Command tables

A table of function pointers maps names or numbers to actions. Debug consoles, input bindings, network message handlers and bytecode interpreters all work this way.

C++
#include <iostream>
#include <map>
#include <string>
#include <utility>
#include <vector>

struct Game { int gold{ 0 }; int health{ 100 }; };

void giveGold(Game& g, int n) { g.gold += n; }
void heal(Game& g, int n) { g.health += n; }
void hurt(Game& g, int n) { g.health -= n; }

int main()
{
    using Command = void (*)(Game&, int);
    const std::map<std::string, Command> commands{ { "gold", &giveGold }, { "heal", &heal }, { "hurt", &hurt } };

    Game game;
    const std::vector<std::pair<std::string, int>> typed{ { "gold", 50 }, { "hurt", 30 }, { "heal", 5 } };
    for (const auto& [name, amount] : typed)
    {
        const auto found{ commands.find(name) };
        if (found != commands.end()) found->second(game, amount);
    }
    std::cout << "gold " << game.gold << ", health " << game.health << '\n';
    return 0;
}
Output
gold 50, health 75

Adding a command means adding one line to the table. Chapter 11 builds the game's debug console exactly like this, and chapter 13 uses the same idea for plugins: a plugin is, at heart, a table of function pointers the game calls.

Lambdas and std::function

Raw function pointers can only point at plain functions. They cannot carry extra data, such as "only enemies within 10 metres of this position". C++ has two tools for that.

A lambda is an unnamed function written in place. A lambda that captures nothing converts to a plain function pointer. One that captures variables is an object holding copies of (or references to) them, with an operator().

std::function<Signature> holds any callable: a function pointer, a lambda with captures, or an object with operator().

C++
#include <functional>
#include <iostream>
#include <vector>

int main()
{
    std::vector<std::function<void()>> onLevelEnd;
    int score{ 0 };

    onLevelEnd.push_back([] { std::cout << "save the game\n"; });
    onLevelEnd.push_back([&score] { score += 100; std::cout << "bonus, score now " << score << '\n'; });

    for (const auto& callback : onLevelEnd) callback();
    return 0;
}
Output
save the game
bonus, score now 100
Tool Can carry data Cost of a call Typical use
Function pointer No One indirect call C APIs, Windows callbacks, plugin tables
Template parameter taking a lambda Yes Often none: the compiler can inline it std::sort, algorithms
std::function Yes An indirect call, and possibly a heap allocation when created Stored callbacks, event lists

The Windows API uses plain function pointers for its callbacks, because it is a C interface. A window's message handler (chapter 5) is a function pointer you give to Windows, and Windows calls it for every message.

Common mistakes

Capturing by reference in a callback that outlives the scope

[&score] stores a reference to score. If the callback runs after the function holding score has returned, it writes into a dead frame (lesson 2.04). Capture by value, or make sure the data outlives the callback.

Calling a null function pointer

It jumps to address 0 and crashes. Check optional callbacks before calling them.

[!warning] Using std::function in the hottest loops Each call is indirect and cannot be inlined. For per-element work in a tight loop, pass the lambda as a template parameter instead.
