Strings in Memory: C Strings, std::string and Encodings

lesson 2.088 of 11 in milestone 27 min1 practice task

Text in memory is a run of numbers, one or more per character. A C string is a char array ending in a zero byte. std::string keeps its own length and stores short text inside the object itself. And which numbers stand for which characters depends on the encoding: ASCII, UTF-8, or the UTF-16 that Windows uses internally.

Characters are numbers

A char is a one-byte number. When text is printed, each number is looked up in a table to find the character to draw. The original table is ASCII, which covers English letters, digits and punctuation in the values 0 to 127:

Character Decimal Hex
'0' to '9' 48 to 57 0x30 to 0x39
'A' to 'Z' 65 to 90 0x41 to 0x5A
'a' to 'z' 97 to 122 0x61 to 0x7A
space 32 0x20
newline '\n' 10 0x0A
the terminator '\0' 0 0x00

A few patterns are worth knowing because they turn up in code all the time: '7' - '0' is 7, which converts a digit character to its value; and upper and lower case letters differ by exactly 32 (0x20), a single bit.

C++
#include <iostream>

int main()
{
    const char digit{ '7' };
    std::cout << digit - '0' << '\n';                    // 55 - 48
    std::cout << static_cast<char>('g' - 32) << '\n';    // lower to upper case
    std::cout << static_cast<int>('A') << ' ' << static_cast<int>('a') << '\n';
    return 0;
}
Output
7
G
65 97

C strings: up to the zero

C, and the Windows API, represent text as a C string: a pointer to the first character of a char array, with the end marked by a byte holding 0. Nothing records the length; functions like strlen find it by walking along until they reach the zero.

C++
#include <cstring>
#include <iostream>

int main()
{
    const char name[]{ "Rook" };              // 5 bytes: R o o k \0
    std::cout << sizeof(name) << ' ' << std::strlen(name) << '\n';
    for (unsigned char c : name) std::cout << std::hex << static_cast<int>(c) << ' ';
    std::cout << '\n';
    return 0;
}
Output
5 4
52 6f 6f 6b 0

sizeof counts the array, terminator included. strlen counts the characters before it. The difference of one is behind countless bugs:

  • Copying a 10-character name into a char[10] leaves no room for the terminator. The next function to read it walks off the end until it happens to find a zero.
  • Forgetting the terminator at all, for example after copying bytes with memcpy, has the same effect.
  • strcpy and strcat write until they hit the source's terminator, however small the destination. They are a classic source of buffer overruns, which is why MSVC warns about them and offers strcpy_s and friends, which take the destination size.

std::string: length, capacity and a small buffer

std::string fixes these problems by storing the length itself and managing its memory. On 64-bit MSVC a std::string object is 32 bytes in a Release build:

std::string (Release x64, 32 bytes)
┌──────────────────────────────────────┐
│ 16 bytes: either the characters      │  short text lives right here
│           themselves (up to 15), or  │
│           a pointer to a heap block  │  long text lives on the heap
├──────────────────────────────────────┤
│ 8 bytes: size (characters in use)    │
├──────────────────────────────────────┤
│ 8 bytes: capacity (room available)   │
└──────────────────────────────────────┘

(Debug builds add 8 more bytes for iterator checking, so sizeof differs between configurations.)

The interesting part is the small string optimisation (SSO). Strings of up to 15 characters are stored directly inside the object, with no heap allocation at all. Longer strings get a heap block, and the first 8 of those 16 bytes hold a pointer to it.

C++
#include <iostream>
#include <string>

int main()
{
    std::string shortName{ "Rook" };
    std::string longName{ "Rook the Unbreakable of the Northern Wastes" };
    std::cout << shortName.size() << " chars, capacity " << shortName.capacity() << '\n';
    std::cout << longName.size() << " chars, capacity " << longName.capacity() << '\n';

    const auto* object{ reinterpret_cast<const char*>(&shortName) };
    const char* text{ shortName.data() };
    std::cout << "short text is inside the object: " << (text >= object && text < object + sizeof(shortName)) << '\n';
    return 0;
}
Output
4 chars, capacity 15
43 chars, capacity 47
short text is inside the object: 1

For games this matters: short names, tags and keys cost no allocation, and long text does. A std::string still keeps a zero after its characters, so c_str() can hand it straight to C-style functions.

std::string_view is a pointer and a length, 16 bytes, with no ownership. It is ideal for passing text to a function that only reads it, provided the text outlives the view (lesson 2.04).

Encodings: beyond ASCII

ASCII has no room for é, ß, Ж, 日 or emoji. Modern text uses Unicode, which gives every character a number called a code point (é is U+00E9, 日 is U+65E5). An encoding decides how those numbers become bytes.

Encoding Unit ASCII text Used by
UTF-8 1 to 4 bytes per character Identical to ASCII Files, the web, most libraries, Linux
UTF-16 2 or 4 bytes per character Every character takes 2 bytes Windows internally, wchar_t on Windows
C++
#include <iostream>
#include <string>

int main()
{
    std::string utf8{ "caf\xC3\xA9" };      // "café" in UTF-8: é is two bytes
    std::wstring utf16{ L"café" };       // the same text in UTF-16
    std::cout << "UTF-8 bytes:  " << utf8.size() << '\n';
    std::cout << "UTF-16 units: " << utf16.size() << " (" << utf16.size() * sizeof(wchar_t) << " bytes)\n";
    std::cout << "sizeof(wchar_t) = " << sizeof(wchar_t) << '\n';
    return 0;
}
Output
UTF-8 bytes:  5
UTF-16 units: 4 (8 bytes)
sizeof(wchar_t) = 2

Two consequences for low-level work:

  • size() is not the number of characters once text is not plain ASCII. "café" is 4 characters but 5 UTF-8 bytes.
  • In memory, UTF-16 text looks spaced out. L"Rook" is 52 00 6F 00 6F 00 6B 00 00 00: every ASCII letter followed by a zero byte. When you search memory for text, search for both forms. Visual Studio's Memory window can show bytes as ANSI or Unicode text; right-click to switch.

Chapter 5 deals with the Windows side: most Windows API functions come in an A version taking narrow strings and a W version taking UTF-16, and the course uses the W versions with conversions at the edges.

Common mistakes

Forgetting room for the terminator

A C string of n characters needs n + 1 bytes.

[!warning] Using strcpy into a fixed buffer Use std::string, or strcpy_s / strncpy_s with the destination size, and make sure the result is terminated.

[!warning] Treating size() as a character count It counts bytes (or UTF-16 units). For player-facing text, use a Unicode-aware library when the count matters.

[!warning] Keeping c_str() after changing the string Appending can move the characters to a new heap block, or out of the small buffer. Get the pointer again after any change.
