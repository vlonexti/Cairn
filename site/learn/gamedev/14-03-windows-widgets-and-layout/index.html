Windows, Widgets and Layout

lesson 14.033 of 6 in milestone 145 min1 practice task

This lesson covers the ImGui toolkit you will use in every tool: windows and child regions, the common widgets (text, buttons, checkboxes, sliders, inputs, combos), how ImGui lays widgets out (top to bottom by default, SameLine to go across, groups, columns of fixed width), ids in loops, and disabling widgets.

Windows

C++
ImGui::SetNextWindowSize({ 420, 300 }, ImGuiCond_FirstUseEver);   // only the first time ever; afterwards the user's size is kept
if (ImGui::Begin("Monsters", &m_showMonsters))                       // the bool adds a close button
{
    // ... widgets ...
}
ImGui::End();                                                        // always call End, even if Begin returned false

Begin returns false when the window is collapsed or hidden, so you can skip describing its contents, but End must still be called. Child windows (BeginChild/EndChild) create scrolling regions inside a window: a log view, a list that scrolls while buttons stay put.

The everyday widgets

Widget Call Changes
Text Text("HP %d", hp), TextColored, TextWrapped, TextDisabled Nothing
Button if (Button("Heal")) ... Returns true on click
Checkbox Checkbox("God mode", &god) Toggles a bool
Slider SliderInt("Sight", &sight, 1, 30), SliderFloat Drag to set a value in a range
Drag DragFloat("Speed", &speed, 0.05f) Drag to change without fixed limits
Input InputInt("Gold", &gold), InputText("Name", buf, sizeof buf) Typed values
Combo Combo("Kind", &index, kinds, count) Picks one from a list
Colour ColorEdit3("Tint", rgb) Edits a colour
Separator, spacing Separator(), Spacing(), SeparatorText("Combat") Visual grouping

Every widget that edits a value returns true on the frame the value changed, which is when to apply side effects (save a setting, send a command to the game):

C++
if (ImGui::SliderInt("Sight range", &m_sight, 1, 30))
    sendToGame("set monster.sight " + std::to_string(m_sight));   // only when it actually changed

Layout

ImGui places widgets top to bottom, each on its own line, at the window's full width minus padding. To change that:

Need Call
Next widget on the same line SameLine()
A fixed width for the next widget SetNextItemWidth(120), or PushItemWidth/PopItemWidth for several
Fill the remaining width SetNextItemWidth(-FLT_MIN)
Treat several widgets as one block BeginGroup() / EndGroup()
Indent Indent() / Unindent()
Align text with framed widgets on the same line AlignTextToFramePadding()
Columns A table (lesson 14.04) with no borders
C++
ImGui::AlignTextToFramePadding();
ImGui::Text("Floor");
ImGui::SameLine(80);                              // continue at x = 80, so rows line up
ImGui::SetNextItemWidth(120);
ImGui::InputInt("##floor", &m_floor);             // ## hides the label but keeps an id
ImGui::SameLine();
if (ImGui::Button("Go")) sendToGame("goto " + std::to_string(m_floor));

This layout model is simple: a cursor moves down (or right, after SameLine), and each widget advances it by its size plus spacing. The practice task implements a version of it.

Ids in loops

As lesson 14.01 warned, widgets in a loop need distinct ids:

C++
for (const MonsterInfo& m : snapshot.monsters)
{
    ImGui::PushID(m.id);                          // every widget inside gets an id including m.id
    ImGui::Text("%s  (%d, %d)  hp %d", m.kind, m.x, m.y, m.hp);
    ImGui::SameLine();
    if (ImGui::SmallButton("kill")) sendToGame("kill " + std::to_string(m.id));
    ImGui::PopID();
}

Disabling

BeginDisabled(condition) / EndDisabled() greys out and blocks the widgets between them: for example, the commands that need a connection to the game, while the tool is not connected (lesson 12.05).

Common mistakes

[!warning] Skipping End when Begin returns false Begin and End must always be paired.

Applying side effects every frame

Act on the frame a widget returns true, not every frame.

Labels used as both text and id in loops

PushID per item, or ## suffixes.
