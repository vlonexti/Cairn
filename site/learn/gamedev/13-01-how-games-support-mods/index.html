How Games Support Mods

lesson 13.011 of 8 in milestone 135 min

Many of the most loved games owe much of their life to mods: changes and additions made by players. Games that support modding on purpose provide layers for it: replaceable data and assets, scripting, plugin APIs and official editors. This lesson surveys those layers, how mods are found and loaded in order, how conflicts arise, and the responsibilities that come with letting other people's code run inside your game.

Layers of modding

Layer What modders change Example Risk to the game
Data Numbers and definitions: items, monsters, levels A monsters.ini with tougher trolls Low: data is validated on load
Assets Textures, models, sounds, text A new tile set or translation Low
Scripts Behaviour, through an embedded language (lesson 10.08) A new boss fight in Lua Medium: limited by the API the game exposes
Plugins Native code (DLLs) through a plugin API A new rendering effect or game system High: native code can do anything the game can
Official tools Whole levels and campaigns, in the developers' editor Map editors, mod kits Low to medium

Delve will support the first four in this chapter: data and asset overrides (lesson 13.02), and a plugin API for DLLs (13.03, 13.04), with scripting as an extension of lesson 10.08.

Mods as a folder with a manifest

Each mod is a folder with a small description, its manifest:

Output
mods\
    tougher-trolls\
        mod.ini             name, version, author, which game versions it supports
        data\monsters.ini   overrides the base game's file
    lantern-light\
        mod.ini
        plugin.dll          native code (lesson 13.04)
        textures\light.png
INI
; mod.ini
name = Lantern light
version = 1.2.0
author = Ada
game = 1.0, 1.1
requires = tougher-trolls

The game reads every manifest at start-up, shows a list where players enable mods and choose their order, and refuses mods for incompatible game versions with a clear message, rather than loading them and crashing.

Load order and conflicts

When two mods change the same thing, one has to win. Games resolve this with a load order: mods later in the list override earlier ones, and the base game is first.

flowchart LR
    B["Base game<br/>data/monsters.ini"] --> M1["Mod 1: tougher-trolls<br/>data/monsters.ini"]
    M1 --> M2["Mod 2: easy-mode<br/>data/monsters.ini"]
    M2 --> R["What the game uses:<br/>easy-mode's file wins"]

Whole-file replacement means the last mod's file wins completely and the earlier mod's changes vanish: a conflict. Smarter games merge at the level of individual entries, so tougher-trolls can change troll health and easy-mode change goblin damage without fighting (lesson 13.02's practice task). Dependencies (requires) add ordering constraints: a mod must load after the mods it builds on (lesson 13.04's practice task sorts them).

Responsibilities

Supporting mods means letting other people's work run inside your game, for your players. That brings duties:

  • Stability: a broken mod should fail clearly ("mod X failed to load: ..."), not crash the game or corrupt saves. Lesson 13.07 covers isolation.
  • Safety: native plugins can do anything, so players should only install them from sources they trust, and the game should make it obvious when native code is involved. Data and script mods are much safer, which is why many games restrict mods to them.
  • Saves: record which mods (and versions) a save was made with, and warn when loading it without them.
  • Online play: anything affecting other players must be controlled by the server, and mods that change gameplay usually belong only in single-player or in servers that opt in. Modding games you did not make is governed by their licence and community rules.

Common mistakes

Loading every mod without checking versions

Read the manifest and refuse incompatible mods with a clear message.

Silent conflicts

Show which mods change the same files or entries, so players can fix their load order.

Letting mods corrupt saves

Record the mod list in each save, and warn before loading it with different mods.
