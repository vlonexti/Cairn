A Complete Tool Window

lesson 14.066 of 6 in milestone 145 min1 practice task

This lesson assembles the chapter into one application: Delve Inspector, a tool with a docked layout that connects to a running copy of Delve and shows its live stats, monsters, a memory view of the telemetry block and a command panel, with a command palette, settings that persist, and the hardening from chapter 12. It is the template for the tools in chapter 18's capstones.

With ImGui's docking (enable ImGuiConfigFlags_DockingEnable; the vcpkg port's docking-experimental feature on versions where docking lives on its own branch), each panel is an ordinary Begin/End window that the user can dock, undock, tab and rearrange, and the arrangement is saved with the layout (lesson 14.05).

Three layers, as chapter 12 recommended: a thin platform layer that talks to the game, a model of pure, tested logic, and views that only draw the model and send user actions back. Each view is a function a few dozen lines long.

The frame

C++
void Inspector::frame()
{
    m_connection.poll();                                       // reconnect if needed; read a snapshot at most every 100 ms
    if (auto snap{ m_connection.latest() }) m_model.update(*snap);

    ImGui::DockSpaceOverViewport();
    drawMenuBar();
    drawOverview();       // reads m_model only
    drawFrameTimes();
    drawMonsters();
    drawHexView();
    drawCommandPalette(); // Ctrl+P
    if (m_showDemo) ImGui::ShowDemoWindow(&m_showDemo);
}

Commands ("heal", "god", "goto 3") go to the game through its command pipe (lesson 12.01) as console lines (lesson 11.07), never by writing into the game's memory: the game stays in charge of its own state, and the tool works with any build that understands the commands.

The command palette

Tools grow many commands. A command palette (Ctrl+P, as in many editors) lists them all, filtered as you type by fuzzy matching: typing gt3 finds "Goto floor 3". Matching characters in order, with bonuses for matches at the start of words, ranks useful results first. The practice task implements the scoring.

Finishing touches

  • Status bar: connection state, game version, telemetry version (lesson 12.06), last error.
  • Keyboard shortcuts for common actions, shown in menus.
  • Logging of the tool's own actions and errors to a file (lesson 8.03).
  • Hardening: the six failure modes of lesson 12.07, rehearsed.
  • Packaging: like lesson 11.08, a Release build with its DLLs, licences (ImGui's MIT licence, SDL's zlib) and a readme.

Common mistakes

Views that compute

Keep logic in the model, where it can be tested; views only draw and forward actions.

Tools that write into the game's memory

Send commands through the game's interface and let it change its own state.

A tool with no status

Always show whether it is connected, to what, and whether the data is current.
