Memory, Addresses and Pointers

lesson 1.033 of 8 in milestone 116 min3 practice tasks

Memory is one long row of numbered bytes. A variable is a few of those bytes with a name, its address is the number of its first byte, and a pointer is a variable whose value is an address.

One long row of bytes

Put the last two lessons together. Memory is a row of cells, each cell is one byte, and every byte has a number. That number is the byte's address.

Addresses are just counting: byte 0, byte 1, byte 2, and so on up to however much memory there is. On a 64-bit system an address is a 64-bit number, and it is always written in hexadecimal, for the reasons the last lesson gave. An address looks like 0x00B3F9A0.

There is nothing more to an address than that. It is the position of a byte in the row.

Variables are named groups of bytes

When you write int score{ 1200 }; the compiler picks four neighbouring bytes of memory, decides that those bytes are score, and puts the bits for 1200 in them. From then on, wherever your code says score, the compiled program uses those four bytes.

The demonstration below shows five variables and the bytes they occupy. The table lists each variable; the grid underneath is the same memory in address order.

Work through these:

  • Click score in the table. Its four bytes light up in the grid. Its address is the address of the first of them.
  • Change score to 255, then 256, then 65536. Watch the bytes: 255 fills the first byte, and 256 needs the second. The first byte is the lowest one, which is the little-endian order from the last lesson.
  • Change score to -1. Every byte becomes FF. That is two's complement, also from the last lesson.
  • Change grade to B. One byte changes, from 41 to 42. A char is a small number that happens to be displayed as a letter.
  • Look at the bytes of ratio. A double uses a different scheme, called floating point, so its bytes do not resemble the number at all. The type tells the program how to read them.

Everything in a running program is stored this way. A game's health, gold and position are groups of bytes like these, at some address.

Sizes, alignment and padding

The grid has some cells marked ··. Those are padding: bytes that belong to no variable.

Processors read a 4-byte value fastest when its address is a multiple of 4, and an 8-byte value when its address is a multiple of 8. This is called alignment. To keep every variable aligned, the compiler leaves unused bytes in front of any variable that would otherwise start at an awkward address.

Press Packed tight in the demonstration to see the same variables with no padding, then switch back. Packing saves a few bytes and makes every read of ratio and lives slower, which is why compilers do not do it unless told to.

The clearest place to see padding from C++ is a struct, because the members of a struct are stored in the order you write them.

C++
#include <iostream>

struct Loose
{
    char grade;     // 1 byte, then 3 bytes of padding so score is aligned
    int score;      // 4 bytes
    char rank;      // 1 byte, then 3 bytes of padding at the end
};

struct Tidy
{
    int score;      // 4 bytes
    char grade;     // 1 byte
    char rank;      // 1 byte, then 2 bytes of padding at the end
};

int main()
{
    std::cout << "Loose: " << sizeof(Loose) << " bytes\n";
    std::cout << "Tidy:  " << sizeof(Tidy) << " bytes\n";
    return 0;
}
Output
Loose: 12 bytes
Tidy:  8 bytes

Both structs hold the same three members, six bytes of real data. The order alone makes one of them half as big again as the other. A game with a hundred thousand objects notices that difference.

Local variables are not promised an order

The demonstration lays variables out in the order they are declared, the way a struct does. For ordinary local variables the compiler may choose any order it likes, and an optimising compiler may not store a variable in memory at all, keeping it in a register instead. The rules about size and alignment hold either way.

Asking where a variable is

The & operator, placed in front of a variable, gives its address.

C++
#include <iostream>

int main()
{
    int score{ 1200 };
    int lives{ 3 };
    std::cout << "score is at " << &score << '\n';
    std::cout << "lives is at " << &lives << '\n';
    return 0;
}
Output
score is at 000000A3D54FF9A4
lives is at 000000A3D54FF9A0

Run it and you will get different numbers from the ones shown here. Run it again and you will probably get different numbers again. That is expected, and the reason is at the end of this lesson. What stays the same is the distance between the two addresses.

Pointers: variables that hold addresses

An address is a number, so it can be stored in a variable. A variable that holds an address is called a pointer.

C++
int score{ 1200 };
int* p{ &score };    // p holds the address of score

Read int* as "address of an int". Two things about p matter, and beginners often blur them:

You write It means
p The address stored in p
*p The int that lives at that address
&p The address of p itself, because p is a variable and lives somewhere too

Putting * in front of a pointer is called dereferencing it: go to the address and use what is there. *p = 50; does not change p. It changes score.

The demonstration has an array of four int values and a pointer p. Click a box to aim p at it.

  • Click values[2]. The value of p changes to that box's address, and *p becomes 30.
  • Press *p += 1. The number in the box goes up. The array was changed through the pointer, without its name being used.
  • Type a number next to *p = and press Write.

Moving a pointer

Press p++ in the demonstration and look at the address. It goes up by 4, not by 1.

Adding one to a pointer moves it forward by one element, not one byte. An int is four bytes, so p + 1 is the address four bytes further on, which is where the next int in an array lives. The compiler does the multiplication for you, using the type the pointer points at. This is called pointer arithmetic.

An array is nothing more than its elements stored one after another with no gaps, so walking a pointer along it reaches each element in turn.

C++
#include <iostream>

int main()
{
    int values[4]{ 10, 20, 30, 40 };
    int* p{ values };                 // an array's name turns into the address of its first element

    std::cout << *p << '\n';          // 10
    ++p;                              // forward one int, which is 4 bytes
    std::cout << *p << '\n';          // 20
    *p = 99;                          // write through the pointer
    std::cout << values[1] << '\n';   // the array changed
    std::cout << *(p + 2) << '\n';    // two ints further on: values[3]
    return 0;
}
Output
10
20
99
40

In fact values[i] is defined by the language to mean *(values + i). Square brackets are pointer arithmetic with a friendlier spelling.

Addresses you must not use

Keep pressing p++ until p goes past the last box.

Nothing stops a pointer from holding an address that is outside the array. The pointer is only a number. What you must not do is dereference it there. The memory after the array belongs to something else, or to nothing, and reading or writing it is undefined behaviour: the program might crash, might quietly damage another variable, or might seem to work until the day it does not.

Now press p = nullptr, then *p += 1.

nullptr is the address 0, used by convention to mean "this pointer is not aimed at anything". The operating system makes sure nothing ever lives at address 0, so dereferencing a null pointer stops the program at once with an access violation. That is the most common crash in C and C++ programs, and it is the friendly one, because it happens immediately and at the line that is wrong.

Give every pointer a value when you create it

A pointer that was never given a value holds whatever bytes happened to be there, which is an address to nowhere in particular. Start every pointer either at a real object or at nullptr, and check for nullptr before using a pointer that might be empty.

Where memory comes from

A running program's memory is divided into regions with different jobs. You will study each in chapter 2; for now it is enough to know that they exist.

Region What lives there How long it lasts
Code The program's instructions The whole run
Static data Global variables and constants The whole run
Stack Local variables of functions that are currently running Until the function returns
Heap Memory the program asks for while it runs, with new or containers such as std::vector Until the program gives it back

A pointer can hold an address in any of these regions. Much of the skill in low-level programming is knowing which region an address belongs to, and therefore how long it stays valid.

Why addresses change between runs

You saw that &score prints a different address each time the program runs. Two things cause that.

First, the stack and the heap are handed out by the operating system while the program runs, and what a program gets depends on what happened before.

Second, Windows deliberately loads programs at a different place in memory on each run. This is a security feature called address space layout randomisation, and chapter 6 explains it.

What does not change is the layout. Inside a struct, score is always the same number of bytes from the start. Inside a program, a given global variable is always the same number of bytes from where the program was loaded. So low-level code and debugging tools describe locations as a base address plus an offset: find where the thing starts this time, then add a distance that never changes. You will use that idea constantly later in the course.

Common mistakes

[!warning] Confusing p with *p p is an address. *p is the value at that address. p = 5; tries to aim the pointer at address 5, which is almost never what was meant. *p = 5; stores 5 in the thing it points at.

Using a pointer that was never set

An uninitialised pointer holds leftover bytes. Dereferencing it reads or writes some unrelated part of memory. Always initialise pointers.

Keeping the address of a local variable after its function returns

A local variable's bytes are reused as soon as the function ends. A pointer to them still holds the old address, but what is there now is something else. This is called a dangling pointer.

Going one step too far

An array of four elements has indexes 0 to 3. values[4] and *(p + 4) are outside it. Off-by-one mistakes with pointers do not produce an error message, only wrong behaviour.

Assuming a layout instead of checking it

Padding means the size of a struct is often more than the sum of its members, and members are not always where you would guess. Use sizeof and, later in the course, offsetof rather than adding up sizes in your head.

quizIn Xenon your best score is kept.
  1. What is the address of a variable?
    • The value stored in it
    • The position in memory of its first byte
    • The number of bytes it takes up
    Show the answer

    The position in memory of its first byte Memory is a numbered row of bytes. A variable occupies one or more of them, and its address is the number of the first.

  2. An int is at address 0x1000. int* p points at it. What address is p + 1?
    • 0x1001
    • 0x1004
    • 0x1008
    Show the answer

    0x1004 Adding one to a pointer moves it by one element. An int is four bytes, so the next int starts four bytes further on.

  3. After int score{ 7 }; int* p{ &score }; *p = 20; what is true?
    • p now holds 20
    • score is now 20
    • score is still 7, because only a copy changed
    Show the answer

    score is now 20 *p means "the int that p points at", which is score itself. Nothing was copied. p still holds the address of score.

  4. A struct has a char, then an int, then a char. Why is sizeof 12 and not 6?
    • Every member is rounded up to 4 bytes
    • Padding is added so the int starts at a multiple of 4, and so the whole struct is a multiple of 4
    • The compiler reserves space for future members
    Show the answer

    Padding is added so the int starts at a multiple of 4, and so the whole struct is a multiple of 4 The int needs to be aligned, so three unused bytes follow the first char. Three more follow the last char so that the next struct in an array would also be aligned.

  5. What happens when a program dereferences a null pointer on Windows?
    • It reads the value 0
    • Nothing, the statement is skipped
    • The operating system stops the program with an access violation
    Show the answer

    The operating system stops the program with an access violation Nothing is ever placed at address 0, precisely so that this mistake is caught the moment it happens.

  6. The same program prints a different address for the same variable each time it runs. Why?
    • The compiler is rebuilt each time
    • The operating system places the program and its stack at different addresses on each run
    • The variable's value is different each time
    Show the answer

    The operating system places the program and its stack at different addresses on each run Addresses are assigned at run time and Windows randomises them on purpose. The distances between things inside the program stay the same, which is why locations are described as a base plus an offset.
