A Memory Viewer

lesson 12.022 of 7 in milestone 125 min1 practice task

A hex viewer that shows raw memory with addresses, bytes and text is one of the most useful debugging tools there is, and the Memory window of lesson 2.11 is one. This lesson builds one for your own process and for a process your tool launched: reading with ReadProcessMemory, coping with pages that cannot be read, and formatting the classic three-column view.

The classic layout

Output
Address           00 01 02 03 04 05 06 07  08 09 0A 0B 0C 0D 0E 0F   Text
0000020E6C8F5E30  52 6F 6F 6B 00 00 00 00  00 00 00 00 00 00 00 00   Rook............
0000020E6C8F5E40  0E 00 00 00 14 00 00 00  00 00 80 3F ?? ?? ?? ??   ...........?....

Three columns: the address of the row, sixteen bytes in hex, and the same bytes as text (printable characters as themselves, everything else as a dot). Bytes that could not be read are shown as ??, which a good viewer must handle because memory can be freed, never committed, or protected (lesson 6.03).

Reading your own process safely

In your own process you can read memory directly through a pointer, but only if it is committed and readable; touching anything else crashes the viewer. Ask first with VirtualQuery (lesson 6.04):

C++
bool readable(const void* address, size_t size)
{
    MEMORY_BASIC_INFORMATION info{};
    if (!VirtualQuery(address, &info, sizeof(info))) return false;
    if (info.State != MEM_COMMIT) return false;
    if (info.Protect & (PAGE_NOACCESS | PAGE_GUARD)) return false;
    const auto end{ static_cast<const char*>(info.BaseAddress) + info.RegionSize };
    return static_cast<const char*>(address) + size <= end;     // a longer read may cross into the next region
}

Even this has a gap: another thread could free the memory between the check and the read. In a viewer for your own process that is acceptable; in a tool that must never crash, read through ReadProcessMemory on the current process, which returns failure instead of faulting.

Reading another process you started

For a process the tool launched itself (and so has full rights to, lesson 6.08), ReadProcessMemory copies bytes from its address space:

C++
SIZE_T got{ 0 };
std::vector<unsigned char> buffer(256);
const BOOL ok{ ReadProcessMemory(child, reinterpret_cast<LPCVOID>(address), buffer.data(), buffer.size(), &got) };
  • The handle needs PROCESS_VM_READ (and PROCESS_QUERY_INFORMATION for VirtualQueryEx). A process you created with CreateProcessW comes with a full-access handle.
  • If any page in the range is unreadable, the call fails and got reports how much was copied, which may be less than asked. A robust viewer reads page by page (4,096 bytes, lesson 6.02), so one bad page only blanks its own part.
  • VirtualQueryEx(child, ...) is VirtualQuery for another process, and tells you in advance which pages are readable.

Formatting

The practice task writes the formatter: given a starting address, the bytes, and which of them were readable, produce the three-column lines. Separating reading (the platform part) from formatting (pure logic) means the formatter can be tested without any process at all, as every practice task in this course has done.

Making it useful

Features that turn a hex dump into a tool:

  • Follow a pointer: click 8 bytes that look like an address (lesson 2.11) and jump there.
  • Interpretations: show the selected bytes as int, float, double, and as a pointer, side by side.
  • Highlight changes: re-read every 100 ms and colour bytes that changed (Visual Studio's Memory window does this when stepping).
  • Bookmarks and type overlays: apply a struct layout (lesson 9.09) so offsets show member names.

Chapter 14 gives the viewer a proper interface with Dear ImGui; chapter 18's first capstone completes it.

Common mistakes

Reading a whole range in one call

One unreadable page fails the whole read. Read page by page.

Showing stale data as current

Mark the time of the last successful read, and show unreadable bytes as ??, never as zeros.

Asking for more access than reading needs

A viewer needs PROCESS_VM_READ and query rights only.
