A Debug Console

lesson 11.077 of 8 in milestone 115 min1 practice task

Every serious game has a hidden console for its developers: press a key, type god, give potion 5 or goto 3, and test anything without playing up to it. This lesson builds Delve's console from lesson 3.04's command table: text input, a command registry with help text, argument parsing, history, output, and a rule that keeps it out of the shipped game.

Why a console

Testing the troll on floor 5 by playing through floors 1 to 4 every time wastes hours. A debug console lets developers and testers change the game's state directly:

Command Effect
help List every command with a one-line description
god Toggle invulnerability
give potion 5 Add items to the inventory
heal Restore full health
goto 3 Jump to floor 3
spawn troll Spawn a monster next to the player
reveal Show the whole map
seed 1234 Re-seed the random generator, to reproduce a bug
save / load Save and load immediately

Chapter 13 extends the same idea into an in-game debug menu, and chapter 14 gives tools a full interface; the console is the simplest and most flexible form.

The registry

Lesson 3.04's command table becomes a registry where each command has a name, a short help text and a function that receives the arguments:

C++
using Args = std::vector<std::string>;
using Handler = std::function<std::string(Game&, const Args&)>;   // returns a line to print

struct Command { std::string help; Handler run; };

class Console
{
public:
    void add(std::string name, std::string help, Handler run) { m_commands[std::move(name)] = { std::move(help), std::move(run) }; }

    std::string execute(Game& game, const std::string& line)
    {
        const Args words{ splitCommandLine(line) };              // lesson 6.01's practice task: quotes allowed
        if (words.empty()) return "";
        const auto found{ m_commands.find(words[0]) };
        if (found == m_commands.end()) return "unknown command: " + words[0] + " (try help)";
        return found->second.run(game, Args(words.begin() + 1, words.end()));
    }
private:
    std::map<std::string, Command> m_commands;                   // sorted, so help lists them alphabetically
};

Registering a command is one line wherever the feature lives:

C++
console.add("give", "give ITEM [COUNT]: add items to the inventory", [](Game& g, const Args& a) {
    if (a.empty()) return std::string{ "usage: give ITEM [COUNT]" };
    const int count{ a.size() > 1 ? std::atoi(a[1].c_str()) : 1 };
    const int left{ g.player.inventory.add(a[0], count) };
    return "gave " + std::to_string(count - left) + " " + a[0];
});

Each command validates its own arguments and returns a message, so mistakes produce a helpful line instead of a crash.

Text input with SDL

The console opens with the backquote key (`, below Escape). While it is open:

  • SDL's SDL_StartTextInput delivers typed characters as SDL_TEXTINPUT events, already in UTF-8 and respecting the keyboard layout (lesson 5.07's WM_CHAR, through SDL).
  • Backspace, Enter, Escape and the arrow keys come through as normal key events.
  • Game controls are ignored, so typing w does not move the player.

The console draws a dark band over the top third of the screen with the last lines of output (from lesson 8.03's ring buffer) and the input line.

History

Pressing Up recalls the previous command, as in a terminal. The history is a list of past commands and a cursor; the practice task implements its exact behaviour, including the detail that typing a new line and pressing Up then Down restores what you were typing.

Keeping it out of the shipped game

The console is a cheat menu. In a single-player game that may be fine to leave reachable, but at least the game-changing commands should be compiled only into development builds:

C++
#ifndef DELVE_SHIPPING
    registerDebugCommands(console);     // god, give, goto, spawn ...
#endif

with DELVE_SHIPPING defined in a separate Shipping configuration (lesson 4.01). In multiplayer games, anything that changes shared state must also be refused by the server: a client-side console can only ever be trusted for the client's own view.

Common mistakes

Commands that crash on bad arguments

Every handler checks its arguments and returns a usage message.

Typing in the console also moves the player

While the console is open, route keys to it only.

Shipping cheat commands by accident

Compile them out of shipping builds.
