A First Win32 Application

lesson 5.066 of 9 in milestone 55 min

Put the last lesson together into a complete windowed program: wWinMain, registering a class, creating a window, a game-style loop, and drawing a moving square with GDI using a back buffer so it does not flicker. About 120 lines of plain Windows API, and every one explained.

The project

In Visual Studio, create a new Windows Desktop Application project (not Console App), or change an existing project's Linker → System → SubSystem to Windows (/SUBSYSTEM:WINDOWS). A Windows-subsystem program has no console, and starts at wWinMain instead of main.

This program cannot run on the course website, which runs console programs only. Build it in Visual Studio.

The whole program

C++
#include <windows.h>

// ---------- the game state ----------
struct Game
{
    float x{ 100.0f }, y{ 100.0f };   // square position, in pixels
    float vx{ 180.0f }, vy{ 120.0f }; // velocity, in pixels per second
    int width{ 640 }, height{ 360 };  // client area size
};
static Game g_game;

// ---------- drawing ----------
static void render(HWND hwnd)
{
    HDC screen{ GetDC(hwnd) };

    // Draw into an off-screen bitmap first, then copy it to the window in one go: no flicker.
    HDC back{ CreateCompatibleDC(screen) };
    HBITMAP bitmap{ CreateCompatibleBitmap(screen, g_game.width, g_game.height) };
    HGDIOBJ oldBitmap{ SelectObject(back, bitmap) };

    RECT all{ 0, 0, g_game.width, g_game.height };
    HBRUSH background{ CreateSolidBrush(RGB(18, 20, 26)) };
    FillRect(back, &all, background);
    DeleteObject(background);

    RECT square{ static_cast<LONG>(g_game.x), static_cast<LONG>(g_game.y), static_cast<LONG>(g_game.x) + 40, static_cast<LONG>(g_game.y) + 40 };
    HBRUSH teal{ CreateSolidBrush(RGB(95, 211, 196)) };
    FillRect(back, &square, teal);
    DeleteObject(teal);

    BitBlt(screen, 0, 0, g_game.width, g_game.height, back, 0, 0, SRCCOPY);

    SelectObject(back, oldBitmap);    // put the original back before deleting
    DeleteObject(bitmap);
    DeleteDC(back);
    ReleaseDC(hwnd, screen);
}

// ---------- updating ----------
static void update(float dt)
{
    g_game.x += g_game.vx * dt;
    g_game.y += g_game.vy * dt;
    if (g_game.x < 0 || g_game.x + 40 > g_game.width) g_game.vx = -g_game.vx;     // bounce
    if (g_game.y < 0 || g_game.y + 40 > g_game.height) g_game.vy = -g_game.vy;
}

// ---------- messages ----------
static LRESULT CALLBACK WindowProc(HWND hwnd, UINT message, WPARAM wParam, LPARAM lParam)
{
    switch (message)
    {
    case WM_SIZE:
        g_game.width = LOWORD(lParam);
        g_game.height = HIWORD(lParam);
        return 0;
    case WM_KEYDOWN:
        if (wParam == VK_ESCAPE) DestroyWindow(hwnd);
        return 0;
    case WM_ERASEBKGND:
        return 1;                     // we paint everything ourselves: skip the default erase (less flicker)
    case WM_DESTROY:
        PostQuitMessage(0);
        return 0;
    }
    return DefWindowProcW(hwnd, message, wParam, lParam);
}

// ---------- start-up and the loop ----------
int WINAPI wWinMain(HINSTANCE instance, HINSTANCE, PWSTR, int showCommand)
{
    WNDCLASSEXW wc{};
    wc.cbSize = sizeof(wc);
    wc.lpfnWndProc = WindowProc;                       // the callback
    wc.hInstance = instance;                           // this program's module
    wc.hCursor = LoadCursorW(nullptr, IDC_ARROW);
    wc.lpszClassName = L"XenonWindow";
    if (!RegisterClassExW(&wc)) return 1;

    RECT size{ 0, 0, 640, 360 };                       // the client area we want...
    AdjustWindowRect(&size, WS_OVERLAPPEDWINDOW, FALSE); // ...grown to include borders and title bar
    HWND hwnd{ CreateWindowExW(0, wc.lpszClassName, L"Bouncing square", WS_OVERLAPPEDWINDOW,
        CW_USEDEFAULT, CW_USEDEFAULT, size.right - size.left, size.bottom - size.top,
        nullptr, nullptr, instance, nullptr) };
    if (!hwnd) return 1;
    ShowWindow(hwnd, showCommand);

    LARGE_INTEGER frequency{}, previous{}, now{};
    QueryPerformanceFrequency(&frequency);             // ticks per second of the high-resolution clock
    QueryPerformanceCounter(&previous);

    bool running{ true };
    while (running)
    {
        MSG msg{};
        while (PeekMessageW(&msg, nullptr, 0, 0, PM_REMOVE))
        {
            if (msg.message == WM_QUIT) running = false;
            TranslateMessage(&msg);
            DispatchMessageW(&msg);
        }
        if (!running) break;

        QueryPerformanceCounter(&now);
        const float dt{ static_cast<float>(now.QuadPart - previous.QuadPart) / static_cast<float>(frequency.QuadPart) };
        previous = now;

        update(dt);
        render(hwnd);
        Sleep(1);                                       // be polite to the CPU; chapter 10 does timing properly
    }
    return 0;
}

Walking through it

Start-up. wWinMain receives the program's HINSTANCE (the address its .exe was loaded at, lesson 4.05's HMODULE) and how the window should first appear. It fills in a WNDCLASSEXW, registers it, and creates one window of that class. AdjustWindowRect matters: the size passed to CreateWindowExW includes the title bar and borders, so without it the drawable client area would be smaller than 640 by 360.

Time. QueryPerformanceCounter reads a high-resolution clock, typically ticking 10 million times a second. The difference between two readings, divided by the frequency, is the elapsed time in seconds. Moving by velocity × dt makes the square move at the same speed on a fast PC and a slow one, a theme chapter 10 develops.

Drawing. GDI (the Graphics Device Interface) is Windows' original 2D drawing API. It is slow by modern standards but simple and always available. Every GDI object you create (CreateSolidBrush, CreateCompatibleBitmap, CreateCompatibleDC) must be deleted, and an object selected into a device context must be deselected before it is deleted: that is the oldBitmap dance. Handle leaks here show up in Task Manager's GDI objects column and eventually stop the program drawing at all.

Double buffering. Drawing the background and then the square directly onto the window would briefly show the empty background each frame: flicker. Drawing both into an off-screen bitmap and copying it to the window with one BitBlt means the window only ever shows complete frames.

What a real game does differently

This program is the skeleton every Windows game has underneath. Real games replace the GDI drawing with a GPU API (Direct3D, Vulkan or OpenGL) and usually use a library such as SDL to create the window and read input, which chapter 11 does. But the window class, the message loop and the timing are the same ideas, and when something goes wrong at that level (a window that will not close, input that stops, a frame-rate collapse when the window is dragged) this is the code you will be debugging.

Common mistakes

Building as a console application

The linker complains that main is missing. Set SubSystem to Windows, or create the project from the Windows Desktop Application template.

Creating GDI objects every frame without deleting them

The program runs out of GDI handles (10,000 per process by default) and stops drawing. Delete each one, or create them once at start-up.

Sizing the window instead of the client area

Use AdjustWindowRect so the drawable area is the size you intended.
