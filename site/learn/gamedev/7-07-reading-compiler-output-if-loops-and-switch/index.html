Reading Compiler Output: if, Loops and switch

lesson 7.077 of 11 in milestone 75 min

Control flow in C++ compiles into a small set of recognisable shapes built from comparisons and jumps. This lesson teaches you to recognise them: if and if/else, while and for loops (and how compilers rotate them), short-circuit && and ||, and the jump table a switch becomes. Recognising shapes is how you read disassembly quickly.

The method

When reading compiled code, do not try to understand each instruction in isolation. Look for the shape:

  1. Find the jumps. Each conditional jump is a decision; each backward jump (to a lower address) is a loop.
  2. Group the instructions between jumps into basic blocks: straight runs with one way in and one way out.
  3. Draw the blocks and the arrows between them. The picture is the control flow, and it maps back to if, while and switch.

Disassemblers such as Ghidra and IDA draw this graph for you (chapter 9). With practice you see it directly in the listing.

if and if/else

C++
int grade(int score)
{
    if (score >= 50) return 1;
    return 0;
}
Assembly
    cmp   ecx, 50
    jl    fail            ; inverted: skip the "then" part when score < 50
    mov   eax, 1
    ret
fail:
    xor   eax, eax
    ret

With an else, the "then" block ends with an unconditional jmp over the "else" block to the code after both:

flowchart TB
    A["cmp ...<br/>jcc else"] -->|"condition false"| E["else block"]
    A -->|"condition true (fall through)"| T["then block<br/>jmp end"]
    T --> J["end"]
    E --> J

(Optimisers often replace small if/else assignments with cmov, lesson 7.04, so there may be no jump at all.)

Loops

A while loop literally compiled would test at the top and jump back to the test at the bottom: two jumps per iteration. Compilers rotate loops instead: test once before entering, then test again at the bottom with a single backward jump.

C++
int sum(const int* values, int count)
{
    int total{ 0 };
    for (int i{ 0 }; i < count; ++i) total += values[i];
    return total;
}
Assembly
    xor   eax, eax              ; total = 0
    test  edx, edx              ; count <= 0?  then skip the loop entirely
    jle   done
    xor   r8d, r8d              ; i = 0
top:
    add   eax, [rcx+r8*4]       ; total += values[i]
    inc   r8d                   ; ++i
    cmp   r8d, edx              ; i < count?
    jl    top                   ; backward jump: the loop
done:
    ret

The backward jump to top is the signature of a loop. The block before it is the guard that skips the loop when it would run zero times. Step through it with three values:

In optimised builds, loops may also be unrolled (the body repeated several times per jump) or vectorised (processing four or eight elements per instruction, lesson 7.11), which changes the shape but not the backward jump.

&& and ||

C++ guarantees short-circuit evaluation: in a && b, b is not evaluated if a is false. That becomes a chain of jumps, each able to skip straight to the outcome:

C++
if (enemy != nullptr && enemy->health > 0) attack(enemy);
Assembly
    test  rcx, rcx              ; enemy == nullptr?
    je    skip                  ; then the whole condition is false
    cmp   dword ptr [rcx+8], 0  ; enemy->health > 0?
    jle   skip
    call  attack
skip:

Two conditional jumps to the same label is the shape of &&. For ||, the first test jumps to the "true" block instead.

switch and jump tables

A switch over a few cases compiles to a chain of comparisons. Over many dense cases (values close together), the compiler builds a jump table: an array of addresses, one per case, and jumps through it with a single indexed jump.

C++
const char* stateName(int state)
{
    switch (state)
    {
    case 0: return "idle";
    case 1: return "walking";
    case 2: return "running";
    case 3: return "jumping";
    case 4: return "falling";
    default: return "?";
    }
}
Assembly
    cmp   ecx, 4
    ja    default_case          ; unsigned compare: also catches negative values!
    movsxd rax, ecx
    lea   rdx, [__ImageBase]
    mov   eax, [rdx+rax*4+table_rva]   ; read the case's offset from the table
    add   rax, rdx
    jmp   rax                    ; jump to that case

Three things to recognise:

  • One unsigned comparison (ja) checks the range: a negative value, seen as unsigned, is huge, so it also goes to default. One check covers both ends.
  • An indexed load from a table, scaled by 4 or 8.
  • An indirect jump (jmp rax).

Sparse cases (1, 100, 5000) get a chain of comparisons or a binary search instead.

Common mistakes

[!warning] Reading every jump as an if Backward jumps are loops; a jmp at the end of a block is usually the "skip the else" jump.

Expecting the loop test at the top

Rotated loops test at the bottom, with a guard before the loop.

Missing the range check before a jump table

The cmp and ja before it tell you the number of cases.

    To skip the loop entirely when it should run zero times The bottom test decides whether to go round again; the guard handles the zero-iteration case.

  3. Two conditional jumps lead to the same label just before a call. What C++ is this likely to be?

    • if (a || b) call();

    if (a && b) call(); Either condition failing skips the call.

  4. Why does a jump table's range check use ja instead of jg?
