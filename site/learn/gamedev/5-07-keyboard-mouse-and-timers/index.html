Keyboard, Mouse and Timers

lesson 5.077 of 9 in milestone 57 min1 practice task

Input arrives as messages whose details are packed into wParam and lParam. This lesson unpacks them: virtual-key codes, the bits of a key message, typed characters, mouse coordinates and buttons, and when to read the keyboard's current state instead. It ends with timers and the high-resolution clock that games use for timing.

Keys: messages and virtual-key codes

When a key goes down, the window with keyboard focus receives WM_KEYDOWN; when it comes up, WM_KEYUP. (Alt combinations and F10 arrive as WM_SYSKEYDOWN and WM_SYSKEYUP instead.) wParam holds a virtual-key code: a number for the key, independent of keyboard layout.

Key Code
Letters 'A' to 'Z' (0x41 to 0x5A): the upper-case letter, whatever the shift state
Digits (top row) '0' to '9' (0x30 to 0x39)
Arrows VK_LEFT, VK_UP, VK_RIGHT, VK_DOWN
Space, Enter, Escape, Tab VK_SPACE, VK_RETURN, VK_ESCAPE, VK_TAB
Shift, Ctrl, Alt VK_SHIFT, VK_CONTROL, VK_MENU (or VK_LSHIFT, VK_RCONTROL... for one side)
F1 to F12 VK_F1 to VK_F12

The bits in lParam

A key message's lParam packs several facts into 32 bits:

 31   30   29   28..25  24   23..16          15..0
┌────┬────┬────┬───────┬────┬───────────────┬────────────────┐
│ up │was │alt │       │ext │ scan code (8) │ repeat count   │
│    │down│    │       │    │               │ (16)           │
└────┴────┴────┴───────┴────┴───────────────┴────────────────┘
Bits Meaning
0 to 15 Repeat count: how many auto-repeats this message stands for
16 to 23 Scan code: the physical key's position, independent of layout
24 Extended key (right-hand Ctrl and Alt, the arrow block)
30 Previous state: 1 if the key was already down before this message
31 Transition: 0 for key down, 1 for key up

Bit 30 is the useful one for games. Holding a key generates a stream of WM_KEYDOWN messages (auto-repeat). If "jump" should happen once per press, ignore messages where bit 30 is set:

C++
case WM_KEYDOWN:
{
    const bool repeat{ (lParam & (1 << 30)) != 0 };
    if (wParam == VK_SPACE && !repeat) jump();
    return 0;
}

Reading bit fields like this, with shifts and masks, is exactly lesson 1.02's material applied, and you will do it constantly in low-level code. The practice task is a set of these decoders.

Typed text: WM_CHAR

For text entry (a player name, a chat box, a debug console) do not use WM_KEYDOWN: it knows nothing about Shift, Caps Lock, dead keys or the user's keyboard layout. TranslateMessage in the message loop turns key presses into WM_CHAR messages whose wParam is the actual UTF-16 character typed, 'a', 'A', 'é' or 'Ж' as appropriate.

Use Message
Game controls (move, jump, fire) WM_KEYDOWN / WM_KEYUP, or the current state
Typing text WM_CHAR

Polling the current state

Sometimes you want to ask "is W held down right now?" rather than track every message. GetAsyncKeyState(vk) answers: its top bit (0x8000) is set when the key is currently down.

C++
if (GetAsyncKeyState('W') & 0x8000) player.y -= speed * dt;

Games often combine both: messages for discrete events (a press that toggles a menu), and either polling or a key-state array kept up to date from the messages for continuous movement. GetAsyncKeyState reports keys even when your window is not focused, so check focus (WM_ACTIVATE) before acting on it.

The mouse

Mouse messages put the cursor position, in client-area coordinates, in lParam: x in the low 16 bits, y in the high 16 bits, both signed (they can be negative when the mouse is captured and dragged outside the window).

C++
#include <windowsx.h>   // GET_X_LPARAM, GET_Y_LPARAM

case WM_MOUSEMOVE:
{
    const int x{ GET_X_LPARAM(lParam) };
    const int y{ GET_Y_LPARAM(lParam) };
    const bool leftHeld{ (wParam & MK_LBUTTON) != 0 };
    aimAt(x, y, leftHeld);
    return 0;
}

Do not use LOWORD and HIWORD for coordinates: they are unsigned, so -1 becomes 65535. GET_X_LPARAM casts to short first.

Message Meaning
WM_MOUSEMOVE The cursor moved
WM_LBUTTONDOWN / UP, WM_RBUTTON..., WM_MBUTTON... Buttons
WM_MOUSEWHEEL Wheel turned: amount in the high word of wParam, in multiples of WHEEL_DELTA (120)
wParam flags MK_LBUTTON, MK_RBUTTON, MK_SHIFT, MK_CONTROL: what is held during the message

For first-person camera controls, cursor positions are the wrong tool: the cursor stops at the screen edge. Games use raw input (RegisterRawInputDevices and WM_INPUT), which reports the mouse's actual movement without acceleration or edge limits.

Timers and clocks

SetTimer(hwnd, id, milliseconds, nullptr) posts WM_TIMER every so often. It is fine for "autosave every five minutes" or blinking a cursor. It is not precise: messages only arrive when the queue is checked, and the default resolution is about 15.6 ms.

For anything to do with frame timing, use the high-resolution performance counter, as lesson 5.06 did:

C++
#include <windows.h>
#include <iostream>

int main()
{
    LARGE_INTEGER frequency{}, start{}, end{};
    QueryPerformanceFrequency(&frequency);
    QueryPerformanceCounter(&start);

    volatile double sink{ 0 };
    for (int i{ 0 }; i < 1'000'000; ++i) sink = sink + i * 0.5;   // something to time

    QueryPerformanceCounter(&end);
    const double ms{ 1000.0 * static_cast<double>(end.QuadPart - start.QuadPart) / static_cast<double>(frequency.QuadPart) };
    std::cout << "frequency is " << (frequency.QuadPart > 0 ? "positive" : "zero") << ", took " << (ms >= 0 ? "a measurable" : "a negative") << " time\n";
    return 0;
}
Output
frequency is positive, took a measurable time

(The example prints words instead of numbers because the actual times differ on every machine.) std::chrono::steady_clock uses the same counter on Windows and is the portable choice.

Common mistakes

[!warning] Using WM_KEYDOWN for text input It ignores Shift, layout and accents. Use WM_CHAR.

Acting on every auto-repeat

Check bit 30 of lParam for one-shot actions.

[!warning] LOWORD(lParam) for mouse coordinates Negative coordinates become huge positive numbers. Use GET_X_LPARAM and GET_Y_LPARAM.

[!warning] Timing frames with SetTimer or GetTickCount Both are too coarse. Use QueryPerformanceCounter or std::chrono::steady_clock.
