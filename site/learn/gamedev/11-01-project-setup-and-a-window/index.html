Project Setup and a Window

lesson 11.011 of 8 in milestone 115 min

This chapter builds a complete small game, a top-down dungeon crawler called Delve, using the ideas from chapters 1 to 10. It starts here: a Visual Studio project with SDL2 from vcpkg, a window and renderer, and the fixed-time-step game loop from lesson 10.02. By the end of the chapter you will have a game with a map, a player, monsters, items, levels, saves and a debug console.

What we are building

Delve is a top-down, tile-based dungeon crawler:

  • a map made of tiles (walls, floor, doors, stairs) loaded from text files;
  • a player moved with the keyboard, one tile at a time;
  • monsters that hunt the player with breadth-first search (lesson 3.09);
  • health, items and an inventory;
  • several levels, saving and loading;
  • an in-game debug console;
  • and a packaged Release build you can give to a friend.

It is small enough to finish and large enough to need everything from chapters 1 to 10. Later chapters use it as their test subject: chapter 12 builds tools that inspect it, chapter 13 adds mods to it, and chapter 14 gives those tools an interface.

Why SDL2

SDL2 (Simple DirectMedia Layer) is a widely used, open-source C library that handles the platform-specific parts of a game: creating a window, a hardware-accelerated 2D renderer, keyboard, mouse and gamepad input, audio, and timing. It runs on Windows, Linux, macOS and consoles. Underneath, on Windows, it does exactly what chapter 5 did by hand (a window class, a message loop, Direct3D for drawing), so we can concentrate on the game.

A window and a loop

C++
// main.cpp
#define SDL_MAIN_HANDLED                     // we write our own main; SDL must not replace it
#include <SDL.h>
#include <algorithm>
#include <cstdio>

int main()
{
    if (SDL_Init(SDL_INIT_VIDEO | SDL_INIT_EVENTS) != 0)
    {
        std::fprintf(stderr, "SDL_Init failed: %s\n", SDL_GetError());
        return 1;
    }

    SDL_Window* window{ SDL_CreateWindow("Delve", SDL_WINDOWPOS_CENTERED, SDL_WINDOWPOS_CENTERED,
                                         960, 640, SDL_WINDOW_RESIZABLE) };
    SDL_Renderer* renderer{ SDL_CreateRenderer(window, -1, SDL_RENDERER_ACCELERATED | SDL_RENDERER_PRESENTVSYNC) };
    if (!window || !renderer)
    {
        std::fprintf(stderr, "could not create the window: %s\n", SDL_GetError());
        return 1;
    }

    const double step{ 1.0 / 60.0 };         // fixed simulation step (lesson 10.02)
    double accumulator{ 0.0 };
    Uint64 previous{ SDL_GetPerformanceCounter() };
    const double frequency{ static_cast<double>(SDL_GetPerformanceFrequency()) };
    float boxX{ 100.0f };

    bool running{ true };
    while (running)
    {
        // 1. Input: drain every waiting event (lesson 5.05's PeekMessage loop, done by SDL).
        SDL_Event event;
        while (SDL_PollEvent(&event))
        {
            if (event.type == SDL_QUIT) running = false;
            if (event.type == SDL_KEYDOWN && event.key.keysym.sym == SDLK_ESCAPE) running = false;
        }

        // 2. Update in fixed steps.
        const Uint64 now{ SDL_GetPerformanceCounter() };
        accumulator += std::min((now - previous) / frequency, 0.25);
        previous = now;
        while (accumulator >= step)
        {
            boxX += 120.0f * static_cast<float>(step);      // 120 pixels per second
            if (boxX > 900.0f) boxX = 0.0f;
            accumulator -= step;
        }

        // 3. Render.
        SDL_SetRenderDrawColor(renderer, 18, 20, 26, 255);
        SDL_RenderClear(renderer);
        SDL_Rect box{ static_cast<int>(boxX), 300, 40, 40 };
        SDL_SetRenderDrawColor(renderer, 95, 211, 196, 255);
        SDL_RenderFillRect(renderer, &box);
        SDL_RenderPresent(renderer);          // swap buffers (lesson 10.04); waits for vsync
    }

    SDL_DestroyRenderer(renderer);            // shut down in reverse order of creation
    SDL_DestroyWindow(window);
    SDL_Quit();
    return 0;
}

Build and run: a dark window with a teal box sliding across it. Every concept is from earlier lessons: the event loop is lesson 5.05's, the fixed step and accumulator lesson 10.02's, the clear-draw-present cycle lesson 10.04's double buffering.

Structuring for growth

Before adding features, split the game state from the platform code. main.cpp will only own the window, the loop and timing; a Game class owns everything else:

C++
// game.h
#pragma once
#include "input.h"
struct SDL_Renderer;

class Game
{
public:
    bool load(const char* firstLevel);
    void update(const InputState& input, double dt);   // fixed step: game rules only
    void render(SDL_Renderer* renderer) const;          // drawing only: never changes state
    bool wantsToQuit() const { return m_quit; }
private:
    bool m_quit{ false };
    // map, entities, inventory ... added in the next lessons
};

The division follows lesson 10.01: update changes state, render only reads it. Keeping SDL out of Game::update also means the game's rules can be unit-tested without a window (chapter 17), which is how this chapter's practice tasks work: they test the game's logic pieces on their own.

Common mistakes

[!warning] Forgetting SDL_MAIN_HANDLED Without it, SDL renames main and expects its SDL2main library to provide the real entry point, and the link fails.

The DLL is missing at run time

vcpkg copies SDL2.dll next to the exe. If you move the exe, move the DLL with it (lesson 11.08 packages both).

Drawing in the update loop

Keep update and render separate, as lesson 10.01 explained.
