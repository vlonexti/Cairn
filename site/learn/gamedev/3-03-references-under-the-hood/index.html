References Under the Hood

lesson 3.033 of 10 in milestone 35 min1 practice task

A reference looks like a second name for an object, and in the language that is exactly what it is. In the machine, a reference that has to be stored or passed is an address, the same as a pointer. This lesson shows both views, the rules that make references safer than pointers, and the ways they can still dangle.

Two views of the same thing

In C++, a reference is an alias: another name for an existing object.

C++
#include <iostream>

void heal(int& health, int amount)
{
    health += amount;          // changes the caller's variable
}

int main()
{
    int hp{ 40 };
    int& alias{ hp };          // alias is another name for hp
    alias -= 10;
    heal(hp, 25);
    std::cout << hp << '\n';
    std::cout << (&alias == &hp) << '\n';   // same object, same address
    return 0;
}
Output
55
1

Now look at what the compiler generates. These two functions compile to identical machine code:

C++
void healRef(int& health, int amount) { health += amount; }
void healPtr(int* health, int amount) { *health += amount; }
Assembly
healRef PROC                      ; healPtr is exactly the same
    add DWORD PTR [rcx], edx      ; add amount (edx) to the int at the address in rcx
    ret 0
healRef ENDP

The caller passes the address of hp in rcx in both cases. At the machine level, a reference parameter is a pointer. The difference is entirely in the rules the compiler enforces at the source level.

The rules that make references safer

Pointer Reference
Can be null Yes No: must be bound to an object when created
Can be changed to refer to something else Yes No: bound once, for life
Needs * or -> to reach the object Yes No: used like the object itself
Can do arithmetic Yes No
Can be stored in containers Yes No (use std::reference_wrapper)

Each rule removes a way to go wrong. A function taking Player& never needs to check for null, and its body reads like normal code. That is why modern C++ uses references for "must be there" parameters and pointers only where "might be absent" or "can be re-aimed" is part of the meaning.

C++
void applyDamage(Player& target, int amount);       // there is always a target
Enemy* findNearest(const Vec2& from);               // there might be none: nullptr

const references: reading without copying

Passing a large object by value copies it. Passing it by const reference passes 8 bytes (an address) and promises not to change it:

C++
#include <iostream>
#include <string>
#include <vector>

struct Level
{
    std::string name;
    std::vector<int> tiles;
};

int countWalls(const Level& level)       // no copy of a possibly huge vector
{
    int walls{ 0 };
    for (int t : level.tiles) if (t == 1) ++walls;
    return walls;
}

int main()
{
    Level cave{ "cave", { 1, 1, 0, 0, 1, 0 } };
    std::cout << countWalls(cave) << '\n';
    return 0;
}
Output
3

The rule of thumb: pass small, cheap-to-copy types (int, float, a small Vec2) by value, and everything else by const&, unless the function needs its own copy.

A const& can also bind to a temporary, which it then keeps alive (lesson 2.04). That is why countWalls(Level{ "tmp", { 1 } }) works.

When a reference takes no space at all

When a reference is a local alias inside one function, the compiler usually does not store it anywhere. int& alias{ hp }; just tells the compiler that alias means hp, and it generates code using hp's location directly. Only references that must cross a boundary (parameters, return values, members) become stored addresses.

A reference member makes the object hold an 8-byte address:

C++
#include <iostream>

struct Camera
{
    const float& targetX;     // follows something else's x position
    float offset;
};

int main()
{
    float playerX{ 10.0f };
    Camera cam{ playerX, -2.0f };
    playerX = 15.0f;
    std::cout << cam.targetX + cam.offset << '\n';
    std::cout << sizeof(Camera) << '\n';
    return 0;
}
Output
13
16

Sixteen bytes: an 8-byte address, a 4-byte float, 4 bytes of padding. Reference members also make the class impossible to assign (a reference cannot be re-bound), which is usually more trouble than it is worth. Prefer a pointer member for "refers to something owned elsewhere".

References can dangle too

A reference is an address with no null check needed, but it is still an address, and the object can die before the reference does:

C++
const std::string& badName()
{
    std::string name{ "Ghost" };
    return name;                  // the local dies; the caller gets a dangling reference
}

MSVC warns about this one (C4172). It cannot warn about the subtler cases: a reference into a std::vector that later grows, or a reference member to an object destroyed first. The rules from lesson 2.04 apply to references exactly as they do to pointers.

Common mistakes

Returning a reference to a local

Return by value. Copies of return values are usually optimised away completely.

Thinking references are free in every case

Passing an int by const int& passes an address and makes the function read through it. For small types, pass by value.

Reference members in classes that need to be copied or assigned

Use a pointer, or std::reference_wrapper, instead.
