Recognising Functions, Loops and Branches

lesson 9.055 of 10 in milestone 96 min1 practice task

Disassemblers find most functions automatically, but understanding a function means recognising its parts: where it starts and ends, what its arguments and result are, and how its control flow maps to if, loops and switch. This lesson turns chapter 7's patterns into a reading routine for unknown functions, and covers the cases where automatic analysis gets function boundaries wrong.

Where functions start and end

A disassembler finds functions by following calls from known starting points (the entry point, exports, the .pdata unwind table from lesson 8.02, which lists most functions' start and end RVAs on x64). Signs of a function start:

  • it is the target of call instructions;
  • it begins with a typical prologue: saving non-volatile registers (push rbx, mov [rsp+8], rbx), sub rsp, N;
  • it is listed in .pdata;
  • it follows padding bytes (CC or 90) after the previous function's ret.

Signs of an end: ret after an epilogue, or a jmp to another function (a tail call, lesson 7.11).

Automatic analysis goes wrong when code is only reached through pointers (a vtable, a callback table, a jump table it did not decode), or when data sits in a code section. Ghidra then shows bytes that are not disassembled; pressing D (disassemble) and F (create function) at a likely start fixes it.

A reading routine

For each unknown function:

  1. Signature first. Which of rcx, rdx, r8, r9, xmm0 to xmm3 are read before being written? Those are the arguments (lesson 7.06). Is rax/eax/xmm0 set just before every ret? That is a result. eax set but only al used by callers suggests a bool.
  2. Calls next. Which functions does it call, and are any of them imports (named for you) or functions you already named? Calls often explain more than everything else together.
  3. Constants and strings. Format strings, error messages, magic numbers (0x5A4D is "MZ"; 0x3F800000 is 1.0f).
  4. Control flow. Draw or view the graph: loops are back edges, decisions are diamonds, switch is a jump table (lesson 7.07).
  5. Memory accesses. Offsets from argument registers are struct members (lesson 7.08).
  6. Name it, even provisionally ("probably_load_config"), and move on. Refine later.

Loops in the graph

A loop shows up in a function graph as an arrow going back up to a block that dominates it (one that every path into the loop passes through). Its parts:

flowchart TB
    G["guard: count == 0?"] -->|"no"| B["loop body<br/>(the block the back edge targets)"]
    G -->|"yes"| X["after the loop"]
    B --> T["increment, compare"]
    T -->|"back edge: go round again"| B
    T -->|"done"| X

Recognising the induction variable (the register incremented each time round and compared against a limit) tells you what the loop iterates over; the memory accesses that use it tell you the array and its element size.

The practice task finds loops from a list of jumps, the first step automatic tools perform.

Branches that are not ifs

Not every conditional jump is an if in the source:

Pattern Source
A compare and jump straight after a call, to an error path if (!ok) return error; or an exception-free error check
test rax, rax / je after a call returning a pointer A null check
A jump to a block that calls a function with a string like "Assertion failed" An assert
cmp against a value, then a call to a function that never returns (abort, a throw helper) A bounds check or failed precondition
Several jumps to one block that sets the same return value Early returns merged by the compiler

When there are no symbols for library code

Functions from the C and C++ runtime are compiled into your program. Without a PDB, they look like any other unknown function. Ghidra's Function ID analyser recognises many by their bytes, and recognising the common ones by behaviour saves a lot of time: memcpy/memset (byte loops or rep movsb/rep stosb), strlen (a loop looking for a zero byte), operator new (calls malloc, throws on failure), std::string constructors (lesson 2.08's small buffer: compares a length with 15).

Common mistakes

Assuming the disassembler found every function

Code reached only through pointers may be missing. Look for undisassembled bytes in code sections.

Reading every register as an argument

Only registers read before being written in the function's first block are arguments.

Spending hours inside runtime library code

Recognise it, name it, and move on to the program's own logic.

Knowledge check

quizIn Xenon your best score is kept.
  1. How can you tell which registers are a function's arguments?
    • They are argument registers (rcx, rdx, r8, r9, xmm0-xmm3) read before being written
    • They are the registers used most in the function
    • They are always all four
    Show the answer

    They are argument registers (rcx, rdx, r8, r9, xmm0-xmm3) read before being written Unused argument registers are simply never read.

  2. What marks a loop in a function graph?
    • A back edge: an arrow from a later block back up to an earlier one that dominates it
    • Any conditional jump
    • A call instruction
    Show the answer

    A back edge: an arrow from a later block back up to an earlier one that dominates it The target of the back edge is the loop's head.

  3. test rax, rax / je error straight after a call. What is it probably?
    • A null check on the pointer the call returned
    • A loop
    • A switch
    Show the answer

    A null check on the pointer the call returned Functions returning pointers use null to signal failure.
